# 营销内容体系

## 1. 内容不是功能翻译

营销内容的最小因果链：

```text
熟悉场景
→ 原有做法
→ 损失或矛盾
→ 装得清改变的一个环节
→ 证据
→ 适用边界
→ 下一步
```

不得从“功能名 + 卖点 + CTA”直接开始。

## 2. 内容层级

### L1 行业认同

让装企老板确认“你懂我这行”。不出现产品名也可以成立。

### L2 场景理解

把一个具体对象、角色和触发事件讲清楚，例如报价改版、材料未到场、应收逾期。

### L3 机制解释

说明装得清如何承接事实、状态、责任和回读，不夸大效果。

### L4 证据与比较

展示实际操作、单据、流程、页面或授权案例；比较旧做法和新做法、App 与 Web、适用与不适用。

### L5 行动与承接

引导预约演示、试用一个真实项目、收藏教程或进入入驻路径，不制造虚假紧迫感。

## 3. 内容形式差异

| 形式 | 首要任务 | 关键约束 |
| --- | --- | --- |
| 短视频 | 2 秒停留、看懂一个问题、建立信任 | 一个冲突、一个证据、一个 CTA |
| 图文 | 搜索、收藏、转发、场景理解 | 标题和封面先服务问题，不先露产品 |
| 官网场景页 | 搜索承接、比较、行动 | 每段有事实映射和边界小字 |
| 销售材料 | 面对面诊断、答疑 | 不替客户做决定，先问业务条件 |
| 使用前后对比 | 理解变化和边界 | 只展示可验证的任务变化，不编效果数字 |

## 4. 内容矩阵维度

```text
角色 × 场景 × 客户阶段 × 端 × 渠道 × 形式 × 证据状态
```

角色：Boss、StoreManager、Finance、Designer、Marketer、Pm、Owner。

客户阶段：陌生、认同、场景理解、比较、试用、入驻、持续使用、复盘。

端：App 高频快捷、Web 深度复杂、双端同源。

## 5. 一个场景的裂变方式

同一场景可以生成：

1. 老板痛点短视频。
2. 角色一天工作图文。
3. 旧做法 vs 新做法对比。
4. App 快速处理 vs Web 深度对账说明。
5. 真实业务案例（需授权）。
6. 使用教程联动 brief。
7. FAQ 和异议处理卡。

裂变不等于复制；不同形式必须保持同一事实与边界。

## 6. 内容质量判断

- 删除装得清品牌名后，问题仍然成立吗？
- 老板能否用一句自己的话复述损失？
- 内容是否只讲了一个主要问题？
- 产品是否在价值兑现后出现，而不是开场就出现？
- 证据是否可见、可追溯、未越权？
- 边界是否写清楚？
- CTA 是否与用户当前阶段匹配？
- 使用内容是否已经存在或明确需要联动？

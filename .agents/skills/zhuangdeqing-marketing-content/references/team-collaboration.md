# 团队协作与交接

## 1. RACI

| 工作 | 业务智能体 | 营销内容 | 使用内容 | 营销执行 | 产品研发/UI |
| --- | --- | --- | --- | --- | --- |
| 业务事实 | A/R | C | C | I | C |
| 对外价值主张 | C | A/R | C | C | I |
| 入驻/操作教程 | A/C | C | R | I | C |
| 渠道选题与发布 | C | R | C | A/R | I |
| 业务适配与兼容 | A/C | C | R | I | C |
| 产品缺口 | A | C | R | I | R |

## 2. 交接包

营销内容交给渠道执行时必须包含：

- 内容目标、受众和客户阶段。
- 场景与老板原话。
- 事实 ID、成熟度、证据和边界。
- 3 个可选钩子或叙事角度。
- 只允许展示的产品链路。
- 必须联动但尚需生产的使用内容。
- 不可说清单。

使用内容交给营销内容时至少包含：

- 真实操作步骤和 App/Web 分工。
- 入驻前置条件。
- 异常、无权限和兼容路径。
- 哪些步骤不能对外演示。

## 3. 冲突处理

- 产品事实冲突 → 业务智能体。
- 使用步骤冲突 → 使用内容智能体 + 当前产品证据。
- 对外表达与页面不一致 → 停止发布，登记 `MC-GAP-*`。
- 产品缺口 → `T05/issue`，不得用内容话术掩盖。

# 主链驱动交互模型

## 1. 设计目标

装得清要让企业“装得清、看得清”：使用者沿客户、房屋、合同、项目和工地理解业务，不靠记忆一级模块或寻找散落功能。

## 2. 四个锚点与一条事实链

```text
客户锚点：线索、负责人、跟进、房屋、机会
房屋锚点：量房、设计、报价、合同、项目
合同锚点：报价快照、签约基线与签约价调整、变更、收款节点
项目/工地锚点：阶段、任务、动态、材料、验收、整改
账务事实链：报价快照 -> 合同基线 -> 应收/应付 -> 收付 -> 成本 -> 结算/利润
```

任何一级模块页面都应能回到锚点，任何锚点视图都应能展开完整事实链；不得让用户在不同菜单中手工拼装同一项目。

## 3. 系统的下一动作

每个对象页首屏优先回答：

1. 现在处于什么业务状态？
2. 当前由谁负责，多久未推进，是否逾期？
3. 下一步最合理的业务动作是什么？
4. 为什么不能继续，缺哪个前置事实或权限？
5. 完成后会写回哪些对象、状态、金额或通知？

“下一步”必须由后端正式状态、前置条件和权限推导；前端不得自行猜测状态机或绕过服务端校验。若需要新增“推荐动作/阻断原因/下一责任人”等业务字段，先走业务咨询和正式设计。


## 4. App 现场快捷视图

App 聚焦高频、现场、即时动作：

- 今日待办、待跟进、待量房、待报价、待开工、待验收、待整改。
- 拍照、上传、定位/时间留证、语音/文本动态、扫码和确认。
- 一句话结果优先；使用同一对象、状态、金额和权限，不单独形成移动口径。

## 5. 信息层级与交互规则

- 首屏只有一个主行动；次要动作降级为描边、文字或更多菜单。
- 状态、责任人、时间、金额/风险、下一动作按任务重要性排序。
- 表单按业务阶段分组，不一次铺满大型 ERP 全字段；低频专业字段按需展开。
- 错误必须说明“发生了什么、为什么、如何恢复、谁负责”，不能只弹“操作失败”。
- 列表用于定位，详情用于推进；不要要求用户从列表跳多个菜单才能完成同一业务动作。
- 页面切换后回到原业务上下文，保留租户、项目、房屋、筛选项和操作进度。

## 6. 多机型与多分辨率验收

### App

- 至少 375、390、430 宽逻辑像素，覆盖安全区、状态栏、底部手势区。
- 检查长企业名、长中文、金额、日期、空状态、加载、失败、键盘弹起和横竖屏边界。
- 禁止文字截断无提示、卡片互相覆盖、按钮跳出安全区、横向滚动和浮层遮挡主操作。


视觉问题必须提供设备、分辨率、角色、页面、截图和具体溢出/遮挡证据。

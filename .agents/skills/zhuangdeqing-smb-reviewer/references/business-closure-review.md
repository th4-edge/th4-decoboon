# 业务强闭环与金额口径审查

## 审查目标

不是证明“页面能打开”，而是证明同一业务事实在全链路中只有一套来源、一套状态和一套计算口径，并且任何异常都不会造成重复收入、重复成本或假利润。

## 主链

```text
客户 -> 房屋 -> 量房 -> 设计 -> 报价版本 -> 客户决策 -> 合同
-> 项目 -> 合同变更 -> 任务/材料计划 -> 采购 -> 到货
-> 实际成本/应付 -> 应收/收款、应付/付款 -> 结算 -> 利润 -> 报表
```

报价确认和合同变更都是链路上的“基线事件”。基线之后只能新增变更事实，不能静默覆盖已确认事实。

## 真相与派生

| 事实 | 真相来源 | 不得作为真相 |
| --- | --- | --- |
| 报价价格 | 已发布报价版本及其不可变快照 | 当前目录价格、页面缓存、前端重算 |
| 合同金额 | 生效合同基线 + 已批准变更 | 实时报价、未审批变更、前端合计 |
| 项目范围 | 合同基线和已批准变更派生的任务/材料计划 | 施工人员口头描述、无来源任务 |
| 实际材料成本 | 实际到货数量 × 采购执行价 | 计划采购金额、库存数量、重复入库 |
| 应收/实收 | 应收计划、收款与核销事实 | 合同金额直接当作已收 |
| 应付/实付 | 应付单、付款与核销事实 | 采购计划、供应商账面口头余额 |
| 项目利润 | 完整收入减完整成本 | 0 成本伪算、未确认变更、单端页面汇总 |
| 统计指标 | 业务对象状态和统一时间字段 | 各角色报表各自算法 |

## 逐段不变量

### 1. 报价与成本

必须核对：

```text
lineNetAmount = 行原价 - 行折扣 + 受控附加项
subtotal      = Σ lineNetAmount
totalAmount   = subtotal - 整单折扣 + 管理费 + 设计费 + 税金
totalCost     = Σ 可追溯成本组件
grossProfit   = totalAmount - totalCost
```

- 所有汇总由服务端计算，前端不得直接写 `subtotal/totalAmount/totalCost/grossProfit`。
- 已发布版本和已接受版本不可被当前目录价格反向改变。
- 成本缺失时必须 `costComplete=false`，`grossProfit/grossMargin=null`，前端显示“成本未完整”。
- 报价接受率使用 `MET-001`，不得使用“接受数 ÷ 全部报价”的旧分母。
- 直接签约只能生成 `DirectContract` 基线报价，不得建立无报价项目旁路。

### 2. 合同、签约和项目

- 合同和项目必须绑定有效报价版本。
- 只有允许的合同状态可以签约、生效和创建项目。
- 项目创建必须幂等，同一合同不能因重复点击产生多个项目。
- 合同、项目及其派生对象必须继承企业、门店、团队和负责人。
- 合同金额、报价金额、已确认产值和实收金额必须分别保存，不能用其中一个覆盖另一个。

### 3. 合同变更与增减项

- 只有客户确认/审批通过的变更可以影响执行。
- 重复确认必须返回原结果，不能重复生成任务、材料、应收或成本。
- 确认事务内应按正式口径更新合同总额、项目预算、任务、材料计划、应收预测和成本。
- 原报价行、原合同行保持可追溯；变更通过 `change_item` 或等价关系回指来源。
- 已开始、已采购、已收款后的变更必须保留既成事实并生成差异，不能物理抹除。
- 必须核对“合同差额、任务差额、材料差额、应收差额、成本差额”五账一致。

### 4. 材料采购与到货

- 采购必须来源于项目材料计划；供应商必须属于当前企业且有效。
- 默认路径为供应商直送工地；只有明确选择入仓才产生库存和领料。
- 直送工地不得产生库存，但到货必须产生实际成本和应付。
- 部分到货按实际到货数量形成成本，不能按整单计划数量提前累计。
- 采购执行价与标准采购成本必须分开保存和授权。
- 退换货、短少、破损和扣款必须按方向冲减，不能再次累计采购成本。

### 5. 财务核销与结算

- 收款金额必须大于 0 且不得超过当前应收余额。
- 付款金额必须大于 0 且不得超过当前应付余额或本次选择的待核销合计。
- 收款与应收更新、付款与应付更新、资金台账写入必须处于同一事务。
- 台账是不可变事实。错误通过调整、冲销或反向业务处理，不物理删除。
- 项目结算关闭必须具备正式要求，通常包括完工/验收、应收清零和应付清零。
- 一笔记账只能来自一个明确业务来源，重复消息、重复点击和重试不得重复入账。

### 6. 项目成本与利润

必须分别说明：

```text
报价预计利润
施工过程动态利润
结算最终利润
```

三者不是同一个对外数字。预计成本、实际成本和变更成本必须能追溯到行或来源单据。任何一个应计成本缺失，利润和毛利率都必须返回空值，不允许按 0 计算。

### 7. 统计与报表

每个指标至少固定：

```text
统计对象 | 分子 | 分母 | 状态范围 | 时间字段 | 组织范围
排除项 | 缺失值 | 更新频率 | 展示精度 | 对外边界
```

设计师、门店、团队、BOSS 报表使用同一指标口径；角色差异只影响数据范围或视图，不能改变公式。

## 对账检查方法

1. 选择一笔真实业务并记录所有对象主键。
2. 从源头单据向下追踪到任务、材料、成本、应收应付和台账。
3. 从汇总金额反向抽样到来源行。
4. 核对保存、状态变化、金额变化和审计时间。
5. 重放提交、回调、审批和到货动作，验证幂等。
6. 补造缺失成本、跨期、退换货、部分到货、超额收款等边界。
7. 比较所有角色的报表结果，确认只有可见范围不同，没有公式不同。
8. 检查错误后恢复：撤销、冲销、回退和旁路是否产生幽灵数据。

## 必须补充的反向用例

- 报价未发布、已替代、已拒绝时不得直接签约。
- 重复接受报价、重复签约、重复创建项目。
- 变更未审批、重复审批、已采购后的取消和替换。
- 采购无来源、跨企业供应商、超计划到货、部分到货、退换货。
- 收款/付款超额、重复通知、并发核销、余额为负。
- 缺标准成本、缺人工成本、缺变更成本时仍显示利润。
- 审批中、已关闭、已结算对象被更新。
- 导出或报表与详情金额不一致。

## 输出格式

使用一张“业务事实对账表”：

```text
主链节点 | 源对象/源字段 | 目标对象/计算 | 公式 | 状态前置
事务范围 | 幂等键 | 审计留痕 | 反向用例 | 结论/证据
```

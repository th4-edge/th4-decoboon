# 专业产品、业务、交互、UX/UI 融合评审

## 1. 为什么需要这层门禁

装得清页面不是作品集，也不是“设计概念展示”。

一个页面必须同时回答：

```text
谁在什么职责下
  -> 遇到什么业务事件
  -> 使用什么业务对象
  -> 完成什么动作
  -> 系统给出什么反馈和恢复路径
  -> 结果如何被回读和继续流转
```

如果页面只能解释“我设计得很高级”，不能解释业务任务，它就没有通过专业评审。

## 2. 五层融合模型

### P1 角色与职责

- 页面服务于哪个角色？
- 该角色的职责和考核结果是什么？
- 页面是替角色做判断，还是替角色完成操作？
- 角色不需要的能力是否被放进页面？

### P2 业务流程

- 触发事件是什么？
- 前置条件是什么？
- 中间有哪些状态、例外和失败路径？
- 完成动作后进入什么状态，交给谁？

### P3 业务对象与动作

- 页面围绕哪个业务对象：客户、房屋、项目、合同、报价、应收、应付、任务、验收？
- 对象的唯一身份如何保持？
- 当前允许动作是什么？为什么是这一个主行动？
- 动作完成后需要回读什么？

### P4 交互与 UX

- 用户从进入页面到完成任务需要几步？
- 比现有流程少做了什么？
- 是否减少搜索、重复输入、切换页面和记忆负担？
- 失败时是否保留输入和上下文？
- 长内容、大量选项、极端值如何处理？
- 是否支持键盘、批量、筛选、分页和连续处理？

### P5 视觉与 UI

- 视觉是否服务于信息层级，而不是成为信息本身？
- 是否有清晰的对象身份、状态、行动和反馈？
- 是否只有一个主行动？
- 是否使用统一 Token 和现有组件？
- 是否有过度卡片、药丸标签、装饰图形或说明性微文案？

## 3. 工作台公式

```text
工作台 =
  当前角色职责
  + 业务数据 / 待办
  + 当前对象与状态
  + 唯一主行动
  + 完成后的交接
```

工作台不是：

- KPI 卡片集合；
- 图表墙；
- 功能菜单首页；
- 设计说明页；
- 作品集封面。

## 4. 内容经济原则

产品界面里只保留帮助用户完成任务的内容。

应删除或移出产品界面：

- 解释设计理念的长句；
- 解释“我们的原则”“数据诚实”“状态完整”等设计说明；
- 每个标题下的泛化副标题；
- 重复的“演示数据”“原型说明”；
- 为评审者准备的标签、图例和状态切换；
- 没有业务动作的装饰性说明。

需要说明的口径、边界和设计过程，放到 README、验收报告或帮助文档，而不是占据核心工作面。

## 5. AI 味检测

以下任一项出现，应视为“AI 味过重”并回退修正：

- 每个模块都做成独立圆角卡片；
- 每个卡片都有小图标、副标题、状态 pill；
- 大量英文小标题或 `BOSS OPERATING COCKPIT` 之类装饰性 eyebrow；
- 首屏有大而空的结论卡、装饰圆环或光效；
- 4 个通用 KPI 卡片是绝对主角；
- 图表、表格、风险列表、说明卡全部同权重平铺；
- 为了“有生命感”加入无业务含义的动画、发光点或演示切换；
- 为展示而存在的 2.5D/3D；
- 文案像设计稿讲解，而不是业务操作提示；
- 每个状态都用彩色标签；
- 看起来像模板，而不是某个真实岗位的工作台。

## 6. 2.5D/3D 价值证明

使用 2.5D/3D 前必须写出：

```text
它比 2D 多解决了什么？
是否减少定位、比较或操作步骤？
是否绑定真实对象和状态？
是否有 2D/列表替代？
是否不阻塞首屏结论？
```

如果答案只是“更酷”“更有空间感”“更像数字孪生”，则移除 2.5D/3D，改为表格、流程图或 2.5D 平面图。

2.5D/3D 是加分设计，不是页面默认负担。

## 7. 专业评审十问

1. 这个页面存在的业务理由是什么？
2. 角色职责和结果指标是什么？
3. 业务对象和当前状态是什么？
4. 用户进入后第一步做什么？
5. 页面是否减少了操作步骤或判断成本？
6. 唯一主行动是什么？完成后谁接手？
7. 哪些信息应该折叠、弱化或移出页面？
8. 长内容、空、失败、无权限和极端值怎么处理？
9. 页面是否依赖真实业务数据，而不是装饰或假场景？
10. 不用 2.5D/3D 是否也能完成任务？如果能，为什么还要用？

## 8. 评审输出

```text
角色 / 职责 / 结果指标：
触发事件：
业务对象 / 状态：
任务链：进入 -> 判断 -> 操作 -> 反馈 -> 回读 -> 交接
唯一主行动：
页面减少的成本：
应删除的说明性内容：
AI 味风险：
2.5D/3D 价值证明或移除结论：
状态与异常：
结论：PASS / CONDITIONAL / BLOCK
```

## 9. 参考来源

- HAWK 供应链工作台：User Personas / Duty Driven / Object Oriented；
- 途牛商旅 B 端全案：效率思维、最短路径、克制视觉；
- B端产品设计高频笔记：功能性 > 表现力，业务流程优先；
- B端工作台方法：工作台 = 掌握进展 + 进入工作状态；
- B端内容过多方法：极限值、截断、折行、抽屉、渐进披露；
- 智慧车站/智慧工厂：角色分层、功能优先、视觉服务于功能；

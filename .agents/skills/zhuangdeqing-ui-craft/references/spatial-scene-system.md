# 2.5D / 3D 空间场景系统

## 1. 核心判断

2.5D / 3D 不是“更高级的卡片”，也不是装饰层。

在装得清中，空间场景只有在能够回答以下至少一个问题时才允许使用：

1. **在哪里**：问题发生在哪个房间、楼层、门店或项目区域？
2. **处于什么阶段**：该空间当前处于设计、施工、材料、验收还是整改阶段？
3. **彼此如何连接**：门店、项目、空间、任务、材料和验收之间是什么关系？
4. **风险集中在哪**：哪个空间最需要今天处理？

如果 3D 不能比表格、流程图或平面图更快回答以上问题，就应使用 2D。

## 2. 场景选择矩阵

| 业务问题 | 首选表达 | 是否适合 3D |
|---|---|---|
| 经营 KPI、金额、利润、回款 | 指标卡 / 表格 / 趋势图 | 不适合 |
| 项目阶段、待办、权限、审批 | 状态头 / 表格 / 行动队列 | 不适合 |
| 户型与房间状态 | 2.5D 平面图 / 3D 户型 | 适合 |
| 施工阶段与空间定位 | 2.5D 空间图层 | 适合 |
| 材料计划与房间归属 | 2.5D 房间 + 清单 | 适合 |
| 整改、验收与证据定位 | 2.5D 空间标记 + 证据卡 | 适合 |
| 多门店经营对比 | 表格 / 地图 / 2.5D 门店沙盘 | 视数据真实空间关系而定 |
| 设备或工地监控 | 2.5D/3D 场景 + 状态层 | 适合，但必须提供列表替代 |
| 长文本、表单、配置、财务明细 | 表格 / 表单 / 抽屉 | 不适合 |

## 3. 2.5D 与 3D 的分工

### 2.5D 默认优先

2.5D 适合企业工作台中的大多数空间表达：

- 固定视角；
- 低认知成本；
- 不依赖 WebGL；
- 可快速降级为平面图；
- 能同时展示空间关系和数据标签；
- 在 1024 和低性能设备上更稳定。

### 3D 的适用条件

只有在以下条件同时满足时才使用 3D：

1. 用户需要理解真实的深度、层高、体块或设备空间关系；
2. 视角旋转或缩放会产生新的业务判断；
3. 有真实或明确标注为概念模型的空间数据；
4. 有 2D 列表/平面图替代；
5. 有静态 fallback 和性能预算。

不得为了“看起来像数字孪生”而给 KPI、表格或流程强行套 3D。

## 4. 空间场景壳

一个合格的装得清空间场景由五部分组成：

```text
场景上下文条
  -> 空间画布
  -> 选中对象检查器
  -> 图例 / 状态说明
  -> 2D 替代视图
```

### 场景上下文条

必须显示：

- 项目 / 门店 / 空间名称；
- 当前图层：空间、施工、材料、验收、风险；
- 数据更新时间；
- 视角切换：2.5D / 3D / 列表；
- 重置视角。

### 空间画布

- 只保留当前业务图层；
- 每个可交互空间必须有唯一业务对象 ID；
- 空间颜色必须对应业务状态，不只做材质装饰；
- 默认不自动旋转；
- 不叠加大面积 bloom、玻璃反射或霓虹光；
- 空间标签优先直接标注，不依赖悬浮才可看见。

### 选中检查器

点击或键盘选中空间后，检查器必须显示：

- 空间名称与当前阶段；
- 状态、进度、风险；
- 责任人；
- 下一步动作；
- 数据时间与来源；
- 对应任务、材料、验收或证据入口。

### 图例 / 状态说明

必须用文字 + 图标 + 颜色共同表达：

- 正常；
- 需关注；
- 阻断/延期；
- 未开始；
- 数据暂不可确认。

### 2D 替代视图

每个 3D 场景必须有：

- 2.5D 平面图或列表；
- 完整键盘路径；
- 状态文本；
- 同样的对象选择与动作入口。

3D 可以是增强层，不能是唯一入口。

## 5. 数据契约

每个空间对象至少应具备：

```text
businessId
label
spaceType
stage
status
progress
riskLevel
owner
updatedAt
source
```

如果模型没有真实空间数据：

- 使用 2.5D 示意图；
- 明确标记“概念模型/演示数据”；
- 不得声称是 CAD/BIM/数字孪生精确映射；
- 不得用随机 3D 物体伪装真实项目事实。

## 6. 交互规则

- 单击选择空间，更新检查器，不直接跳走；
- 双击或“进入空间”打开工作面；
- 键盘 `Tab` 遍历空间，`Enter` 选择；
- `Esc` 退出当前选择或关闭检查器；
- 视角切换不得丢失选中对象；
- 不自动旋转；如提供旋转，必须明确按钮并保存视角；
- 动效时长服从 Token，默认 200ms 左右；
- `prefers-reduced-motion` 下使用静态切换。

## 7. 视觉规则

- 场景壳使用现有中性 Token；
- 家庭空间使用温暖中性材质，不使用默认赛博深色；
- 品牌青绿只用于选中、主行动和关键路径；
- 橙色/红色只用于风险与阻断；
- 3D 材质不能替代状态标签；
- 一个屏幕最多一个主动 3D 场景；
- 2.5D/3D 场景内的装饰性物体必须有明确信息目的。

## 8. 装得清适用场景

### 项目空间风险

用 2.5D 户型图展示房间、阶段、风险、责任人和下一步，点击房间查看任务与证据。

### 设计空间与材料

用 2.5D/3D 房间展示设计区域、主材归属、待选材料和方案版本；点击区域查看报价与材料事实。

### 施工与验收

用房间图层展示施工阶段、待验收、整改、证据和责任人；颜色对应状态，不用 3D 物体混淆事实。

### 多门店经营沙盘

只有在门店确实存在空间关系或区域对比需求时使用 2.5D 门店沙盘；否则表格优先。

## 9. 反模式

- 给 KPI、金额、利润套 3D 模型；
- 为了视觉冲击加入无数据含义的 3D 物体；
- 使用默认深色霓虹“数字孪生”风格替代企业工作台；
- 没有 2D 替代视图；
- 鼠标才能操作；
- 自动旋转或持续漂浮；
- 用 3D 场景掩盖加载、错误或数据缺失；
- 把概念模型说成 CAD/BIM 精确模型；
- 在 1024 或低性能设备上没有静态 fallback。

## 10. 验收

- 场景能回答“在哪里、什么阶段、风险在哪、下一步做什么”；
- 每个空间对象有业务 ID 和事实来源；
- 有 2.5D/列表替代；
- 键盘可遍历和选择；
- 不自动旋转；
- 1024 无横向溢出；
- 无 WebGL/资源加载失败时的恢复路径；
- 3D 不阻塞首屏业务结论。

# 站酷视觉学习闭环

## 1. 闭环目标

不是“多看几张图”，而是形成可复用的视觉判断：

```text
浏览器搜索
  -> 选择同类高赞作品
  -> 提取真实界面图
  -> Qwen2.5-VL 读图
  -> 人工/主模型反思
  -> 对照当前页面
  -> 提炼视觉规则
  -> 修改页面
  -> 再渲染与复评
```

## 2. 搜索与选样

优先搜索与当前页面同类的词：

- B端产品设计
- B端工作台
- SaaS后台
- 后台管理系统
- 业务流程设计
- 表单/表格设计
- 设计复盘
- UX设计案例

选样标准：

1. 点赞量不是唯一标准，但作为初始排序；
2. 必须有真实界面截图，不只是封面、海报或作品集包装；
3. 优先选择同时展示业务过程、信息架构和最终界面的作品；
4. 同一轮至少选 3 个不同风格/产品的样本；
5. 记录作品链接、点赞、页面截图和图片路径。

## 3. 视觉读图

使用本地视觉桥：

```bash
python3 .agents/skills/zhuangdeqing-ui-craft/scripts/vision_review.py \
  --preset reference-study \
  --num-ctx 16384 \
  --max-image-side 1280 \
  --image <参考图1> \
  --image <参考图2> \
  --output <分析文件>
```

重点看：

- 信息层级的真实结构，而不是装饰；
- 页面密度与留白分布；
- 字阶、字重和对齐；
- 主色、辅助色、语义色的比例；
- 表格、列表、卡片、侧栏、抽屉的职责；
- 交互暗示和状态反馈；
- 2.5D/3D 是否承担空间定位，还是纯装饰。

## 4. 对照当前页面

顺序必须是参考图在前、当前页面在后：

```bash
python3 .agents/skills/zhuangdeqing-ui-craft/scripts/vision_review.py \
  --preset reference-compare \
  --num-ctx 16384 \
  --max-image-side 1280 \
  --image <参考图> \
  --image <当前页面截图> \
  --output <对比文件>
```

对比后必须人工/主模型过滤：

- 接受：能改善层级、密度、对齐、色彩比例、组件职责的建议；
- 拒绝：为了“更丰富”增加辅助色、装饰图形、说明性文案或 2.5D/3D；
- 拒绝：把作品集封面、营销页或 App 化布局直接搬入企业工作台；
- 拒绝：不符合装得清业务对象、任务链和 Token 规范的结论。

## 6. 本轮站酷学习结论（2026-10-28）

### 参考 A：华为站点勘测 Pad 端 B 端项目

- 3D 模型与右侧属性栏一一对应，3D 不是装饰，而是空间定位和设备编辑入口；
- 触控区、常驻属性栏和任务流程共同服务现场录入效率；
- 3D 只适合项目、设备、空间、材料、验收等真实空间页面，不适合 BOSS 驾驶舱。

### 参考 B：Beework SaaS 协同办公

- 信息架构先于视觉，模块通过预设和工作台组织；
- 卡片/模块化适合表达可组合能力，但过多等权卡片会让工作台变成 App 首页；
- 视觉语言简洁，但装得清仍需保持更高信息密度和角色任务导向。

### 参考 C：高赞 UI 作品集

- 排版、留白、字重对比和单色系统值得学习；
- 大幅封面、作品集叙事、装饰性视觉和营销式 Hero 不适合日常工作台；
- 视觉高级感来自秩序和细节，不来自增加颜色、阴影或 3D。

### 对当前 BOSS 驾驶舱的判断

- v2 已经去掉无业务价值的 2.5D 模块，并把右侧提醒合并到待办面板，卡片数量更合理；
- 当前页面信息密度较高，但 BOSS 驾驶舱需要同时支持结果、趋势和待办，密度是业务需求，不应为了“空气感”牺牲可扫描性；
- 后续需要继续观察：
  - 待办中的对象名称是否足够具体；
  - 结果区与图表之间的视觉节奏；
  - 1024 下是否仍然过长；
  - 右侧待办与主区的视觉权重是否平衡。

## 7. 硬规则

1. 不把 Qwen 的泛化建议直接当设计结论。
2. 不因为“更高级”增加装饰。
3. 不因为“更丰富”增加辅助色。
4. 不因为“更直观”强上 2.5D/3D。
5. 视觉学习必须落到页面改动或规范更新，否则不算学习完成。
6. 每次学习保留参考链接、图片、视觉分析文件、对比文件和修正证据。

## 8. 2026-10-28 持续学习第一轮

学习链接：

- DRG/DIP 智能管理系统
- 直播后台管理系统 2.0
- 信息层级设计方法
- 设计师掌握前端框架

新增规则：

1. 高密度后台用模块分组、页签、筛选、状态和图表共同建立层级，不靠放大卡片。
2. 工作台优先组织“实时数据 + 当前任务 + 时间/阶段结构”。
3. 同类型动作保持同一种视觉语法；一屏只有一个最强焦点。
4. 表格标题可两行，但只在内容确有必要时；常规列表保持可扫描行高。
5. 状态使用文字 + 颜色 + 图标，不能只靠颜色。
6. 设计必须服从现有组件库、盒子模型、响应式和 Token 可实现性。
7. 方法文章中的字阶是讲解示例，不得直接覆盖装得清冻结字阶。

持续学习证据：`output/playwright/zcool-long-study/learning-log.md`。

## 9. 2026-10-28 持续学习第二轮

学习来源：设计师掌握前端框架的实用手册。

新增规则：

1. 设计稿必须能映射到盒子模型和现有布局体系，禁止依赖绝对定位做主要结构。
2. 优先复用现有组件和 Token；新增组件必须证明现有组件无法满足。
3. 复杂渐变、重阴影、毛玻璃、复杂背景和复杂过渡必须做实现风险评估。
4. 1440/1280/1024 的响应式策略在设计阶段冻结。
5. 设计交付必须包含间距、字阶、颜色、状态和交互的可实现映射，不把猜测留给前端。

## 10. 2026-10-28 持续学习第三轮

学习角度：配色比例、字阶、信息密度、组件一致性。

新增规则：

1. 参考作品的品牌色覆盖超过 10% 时，只转译强调位置，不转译覆盖面积。
2. 装得清品牌色优先用于主按钮、当前导航、选中页签、关键图表和当前对象标记。
3. 不用阴影或增加对比色弥补层级；先检查字阶、字重、位置、留白和边框。
4. 配色判断必须结合真实页面面积统计，不能只凭视觉模型描述。
5. 工作台的密度服务于扫描效率，不为“空气感”牺牲关键数据可读性。

## 11. 2026-10-28 持续学习第四轮

学习角度：表格、列表、筛选与行操作。

新增规则：

1. 可点击行必须同时提供可见动作入口，避免隐藏交互。
2. 表格操作列放在稳定位置，默认右侧。
3. 高密度表格使用低背景噪音、清晰表头和稳定行高，不用高饱和底色区分行。
4. 两行标题只在内容确有必要时使用。
5. 视觉模型结论必须与 DOM/OCR 对照，冲突时以真实页面结构为准。

## 12. 2026-10-28 持续学习第五轮

学习角度：排版节奏、字阶与组件一致性。

新增规则：

1. 视觉模型只能判断协调感，不能可靠发现 1–3px 的 Token 漂移。
2. 每轮视觉评审必须同时读取 DOM 计算样式，检查字号、字重、圆角、按钮高度、表格行高。
3. 可见字号必须来自冻结字阶；发现 17/21/24 等非体系字号时回退到最近 Token。
4. 圆角必须收敛到固定梯度；发现 6px 等非体系值时回退到 4/8/12/16/pill。
5. 视觉、DOM、截图、Token 四种证据缺一不可。

## 13. 2026-10-28 持续学习第六轮

学习角度：工作台首屏视觉重心与行动路径。

新增规则：

1. 视觉模型提出“主行动不突出”时，先用 DOM 验证主行动数量、位置和可见性。
2. 只有真实用户任务测试找不到主行动，才调整尺寸、位置或文案。
3. 不为通过视觉模型评审而增加阴影、颜色块或额外卡片。
4. 首屏优先形成“判断 → 结果 → 证据 → 待办”的阅读链。

## 14. 2026-10-28 持续学习第七轮

学习角度：组件一致性与交互目标尺寸。

新增规则：

1. 文字按钮可以保持 12px 视觉字号，但点击热区不得小于 24×24px。
2. 组件一致性审计必须读取 DOM 尺寸、圆角、阴影和主按钮数量。
3. 视觉模型提出“卡片更丰富、标签更多”时默认拒绝，除非业务状态确有必要。
4. 低层级文字动作必须与高层级按钮共享可访问的点击目标标准。

## 15. 2026-10-28 持续学习第八轮

学习角度：响应式与单列工作台顺序。

新增规则：

1. 单列布局下，若角色主任务是处理事项，待办/风险队列应排到数据图表之前。
2. 响应式顺序必须用 DOM 几何验证，不能只依据视觉模型主观描述。
3. 窄屏优先保证第一任务可达，再保证完整图表可见。

## 16. 2026-10-28 持续学习第十轮

学习角度：七态状态页视觉。

新增规则：

1. 状态区分必须依靠独立标题、原因、恢复路径和按钮，不只靠图标或颜色。
2. 状态页评审必须核对 DOM 中的真实按钮与文案，不能依赖视觉模型记忆。
3. 数据可信文案不得为了简短删除；保留“暂不可确认”和恢复路径。
4. 加载态保持页面结构，不使用空白闪烁。

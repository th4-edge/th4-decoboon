# 装得清 Web 视觉系统执行规范

本文件把站酷高赞 B 端研究和装得清现有 Token 转成可执行的视觉规则。若本文件与 Web 仓库 `src/styles/tokens.scss` 冲突，以 `tokens.scss` 为准并回改本文件。

## 1. 核心原则

装得清的视觉高级感来自：

1. 大面积中性色；
2. 单一品牌强调色；
3. 明确的内容层级；
4. 克制的阴影和边界；
5. 编辑级排版；
6. 高数据墨水比；
7. 语义状态一致。

不得用多套强调色、装饰性渐变、循环动画或复杂材质制造“高级感”。

## 2. 色彩策略

### 2.1 色彩角色

| 角色 | 用途 | 约束 |
|---|---|---|
| 画布色 | 页面背景 | 页面主体使用中性浅色 |
| 内容面色 | 卡片、表格、工作面 | 比画布更亮，保持干净 |
| 文字色 | 标题、正文、辅助信息 | 至少三级层级 |
| 品牌色 | 主操作、选中态、关键强调 | 一个页面只允许一个品牌行动色 |
| 信息色 | 链接、提示、系统信息 | 不与品牌主行动争夺 |
| 警告色 | 风险、逾期、异常 | 必须配文字和图标 |
| 成功色 | 完成、通过 | 必须配文字和图标 |
| 危险色 | 阻断、删除、驳回 | 必须配文字和图标 |

### 2.2 当前 Token 映射

来自 Web 仓库 `src/styles/tokens.scss`：

```scss
$brand-500: #2f7d5a;
$brand-600: #26654a;
$brand-700: #1d4e39;
$brand-50:  #eef6f1;

$ink-950: #1a1a17;
$ink-600: #66665f;
$ink-400: #b8b8b0;

$surface-50: #fafaf8;
$surface-100: #f5f5f2;
$surface-0: #ffffff;
$line-200: #ebebe6;

$success-500: #22a06b;
$warning-500: #e8a020;
$danger-500: #e5484d;
$info-500: #3b7de8;
```

使用规则：

- 主行动、当前选中、关键业务强调使用 `$brand-*`；
- 正文使用 `$ink-950`，说明使用 `$ink-600`，禁用/辅助使用 `$ink-400`；
- 页面背景使用 `$surface-50`，卡片使用 `$surface-0`，次级填充使用 `$surface-100`；
- 分隔优先使用 `$line-200`，不要用重阴影替代；
- 成功/警告/危险/信息必须使用现有语义色；
- 新增颜色前必须说明现有 Token 为什么不够，并更新 Token 真源，不得在页面写裸值。

### 2.3 比例建议

- 中性色：主体面积的 75%–90%；
- 文字和边界：约 10%–20%；
- 品牌强调：不超过 10%；
- 警告/危险等强语义色：只占局部，不作为大面积背景。

这里的比例是视觉预算，不是机械像素分配；判断标准是主行动和关键事实是否清楚。

## 3. 表面层级

最多使用四级表面：

1. **Canvas**：页面画布；
2. **Surface**：内容卡、表格容器、工作面；
3. **Raised**：当前选中、浮起的工作面；
4. **Overlay**：抽屉、弹窗、菜单。

约束：

- 一级内容面优先用边框和留白区分；
- 阴影只用于浮层或需要脱离文档流的工作面；
- 不得所有卡片都使用阴影；
- 不得叠加重边框 + 重阴影 + 强背景色；
- 抽屉和弹窗不得叠加出现。

## 4. 排版

使用冻结字阶；正文最小 13px，辅助信息最小 12px。当前 Token：

- Hero/展示数字：44px；
- Display：28px；
- H1：20px；
- Title：18px；
- Card title：16px；
- Body：14px；
- Body small：13px；
- Caption：12px；
- KPI：32px。

规则：

- 页面标题不等于视觉结论；不要把标题做得比结论更重要；
- 数字使用等宽数字；
- 金额、数量、百分比、日期右对齐或按列对齐；
- 一个区块最多使用三个层级：结论/标签 → 内容 → 说明；
- 长名称必须截断并提供完整提示；
- 使用中文标点和完整业务词，不使用内部英文对象名或技术字段；
- 英文只用于业务确有的品牌、产品、URL 或不可翻译的专有名词。

## 5. 间距与网格

- 8px 为基础单位；
- 4px 只用于图标与文字、标签与数字等局部微调；
- 页面区块之间优先 24/32px；
- 卡片内边距优先 16/24px；
- 表格行高应保持可扫描，不为“空气感”牺牲密度；
- 工作台三栏布局必须保证对象身份、当前工作面、行动栏同时可见；
- 1024 宽度必须无整页横向溢出，必要时折叠次要信息而不是压缩正文。

## 6. 卡片与容器

卡片只用来承载一个可识别的业务单元或工作任务。

必须：

- 有明确标题或对象身份；
- 只保留一个主要结论或动作；
- 说明数据更新时间或来源；
- 有空、加载、失败和权限边界。

不得：

- 把页面做成卡片墙；
- 用卡片代替表格中的结构关系；
- 卡片内再嵌套多层卡片；
- 用装饰图标填补无内容区域；
- 将营销文案放入业务卡。

## 7. 表格

表格必须优先于卡片列表承载结构化、可比较数据。

- 表头服务列解释，不为装饰；
- 金额、数量、日期、编号使用等宽数字并对齐；
- 主操作在稳定位置，次要操作降级；
- 筛选区默认只露常用条件，高级筛选折叠；
- 批量操作必须显示选中数量、影响范围和清除选择；
- 空结果与真实空数据区分；
- 分页必须显示总数、当前页和每页条数；
- 不得通过横向滚动隐藏关键结论；
- 行内状态使用文字 + 颜色 + 图标/形状。

## 7.1 表格行操作补充

- 可点击行必须同时提供可见操作入口，不能只依赖整行点击。
- 操作列放在稳定位置，默认右侧。
- 行高优先服务扫读，常规表格建议 40–44px；两行标题只在确有必要时使用。
- 不使用高饱和整行背景区分状态；状态由标签、文字和图标表达。

## 8. 图表

图表必须服务于一个业务结论。

- 图表标题包含结论或直接在上方提供结论带；
- 先选择要表达的关系，再选择图形；
- 删除装饰性背景、渐变、3D、冗余网格线；
- 需要比较时优先直接标注；
- 数据系列颜色必须有业务含义，不使用彩虹色装饰；
- 同一图表最多一个主要视觉焦点；
- 图例、轴、提示信息必须完整但克制；
- 数据不完整时显示“暂不可确认”，不绘制伪完整曲线/饼图；
- 图表下钻必须回到同一对象和同一口径。

## 9. 状态色与图标

状态必须同时具备：

1. 文字；
2. 颜色；
3. 图标/形状；
4. 稳定位置。

不得使用：

- 纯红/绿点代表全部状态；
- 仅靠颜色区分成功和失败；
- 没有文字说明的警告色块；
- 把品牌色当作成功色或危险色。

## 10. 动效

当前 Token：

```scss
$transition-fast: 120ms cubic-bezier(.4, 0, .2, 1);
$transition-base: 200ms cubic-bezier(.4, 0, .2, 1);
$motion-enter-fast: 320ms;
$motion-enter-base: 520ms;
$motion-ease-out: cubic-bezier(.22, .61, .36, 1);
```

允许：

- 工作面切换；
- 抽屉/弹窗进入退出；
- 状态变化；
- 保存、复制、提交完成的反馈；
- 数据刷新和更新时间提示。

禁止：

- 无限循环装饰；
- 与业务状态无关的漂浮/闪烁/呼吸；
- 阻塞操作的动画；
- 通过动画掩盖加载或失败；
- 不响应 `prefers-reduced-motion`。

## 11. 视觉学习补充规则（2026-10-28）

- 高密度页面优先用分组、页签和状态组织信息，不用放大卡片。
- 同类型动作保持同一种视觉语法；一屏只有一个最强焦点。
- 状态必须文字 + 颜色 + 图标；不得只用红黄绿点。
- 表格行高优先服务扫描效率，标题可两行但不得让普通列表失去节奏。
- 方法文章中的示例字号不得覆盖项目冻结字阶。
- 设计必须能在现有组件库、盒子模型、响应式和 Token 体系中稳定落地。

## 12. 参考页配色转译

- 参考作品品牌色覆盖超过 10% 时，只学习其强调位置，不照搬覆盖面积。
- 品牌色优先用于主按钮、当前导航、选中页签、关键图表和当前对象标记。
- 阴影和对比色不能用来弥补层级；先检查字阶、字重、位置、留白和边框。
- 配色评审同时参考真实截图的主色面积统计，不只依赖视觉模型主观描述。

## 13. 字阶与组件几何审计

- 可见字号必须来自冻结字阶；发现 17px、21px、24px 等非体系值时回退到最近 Token。
- 圆角必须收敛到 4/8/12/16/pill；发现 6px 等非体系值时回退。
- 每轮评审必须读取 DOM 计算样式，检查字号、字重、圆角、按钮高度、表格行高。
- 视觉模型、DOM 计算样式、真实截图和 Token 四种证据必须联合使用。

## 14. 交互目标尺寸

- 所有可点击按钮、文字动作和图标按钮的最小热区不得小于 24×24px。
- 表格行操作、页脚文字动作和面板二级动作也必须满足该标准。
- 视觉字号可以保持 12px，但通过 padding/min-height 扩大命中区域。
- 每轮 DOM 审计必须检查交互目标尺寸。

## 15. 响应式顺序

- 单列布局下，若角色主任务是处理事项，待办/风险队列优先于数据图表。
- 1440 保持主数据 + 右待办双栏；1024 单列时先待办后图表。
- 响应式顺序必须用 DOM 几何坐标验证，不能只依赖视觉模型判断。
- 窄屏优先保证第一任务可达，再保证完整图表展示。

## 16. 设计到代码可行性

- 主要布局必须能由网格、Flex、Grid 和正常文档流表达，不得依赖大量绝对定位。
- 间距、尺寸、边框、内边距必须遵循盒子模型和 8pt 节奏。
- 优先使用现有组件和 Token；新增组件、材质和复杂效果必须说明实现方案。
- 复杂渐变、重阴影、毛玻璃、复杂背景和长链过渡默认不进入工作台。
- 1440/1280/1024 的响应式与折叠策略必须在设计阶段冻结。
- 设计交付必须能直接映射到前端 Token、组件、状态和交互，不把还原风险留给开发临场猜测。

## 17. 反模式清单

发现任一项即退回：

- 大面积渐变或品牌色铺底；
- 多套高饱和强调色；
- 页面首屏像官网 Hero；
- 所有内容都做成卡片；
- 表格数据用彩色背景区分；
- 图表颜色无业务语义；
- 12px 以下正文；
- 非 Token 间距和字号；
- 仅 hover 才显示关键操作；
- 阴影过重或层级不清；
- 状态只靠颜色；
- 无意义的插画或 3D 图标。

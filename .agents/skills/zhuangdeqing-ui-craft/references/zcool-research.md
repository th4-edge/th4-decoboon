## 2. 高赞 B 端样本的共同点

### 2.1 浅中性画布，而不是深色“炫技”

高赞 B 端作品的页面主体通常采用：

- 大面积白色或极浅冷灰/暖灰画布；
- 深色正文；
- 低对比度边框和分隔线；
- 一个明确的高饱和强调色；
- 状态色只用于状态，不用于装饰。

抽样调色板中最常见的底层色接近：

- `#F7FAFD`、`#FAFBFC`、`#FFFFFF`、`#F1F5FE`
- 深色文字接近 `#17181B`、`#201F29`、`#1D191A`

这说明“高级感”主要来自**低噪音底色、清晰层级和留白**，不是黑色大屏、霓虹光效或复杂渐变。

### 2.2 单一强调色承担行动和数据重点

高赞样本常用蓝、绿或青绿作为行动/数据重点；同一页面通常不会同时使用多套高饱和主色。

站酷样本的强调色常见：

- 蓝色系：`#3392E7`、`#2C5BF7`、`#4182EB`
- 青绿系：`#30D7AF`、`#23A2B1`
- 用于显示“高亮/提醒”的少量绿色和橙色

对装得清的转译：

- **品牌绿色是唯一主行动色**；
- 蓝色作为信息/链接色，不与绿色争夺主行动；
- 橙色/红色只承担警告、风险和阻断；
- 不在一个页面同时使用品牌绿、蓝、紫、黄作为并列主色。

### 2.3 表格是系统，不是“表格组件”

《数据表格设计》将企业表格拆成：

- 标题；
- 筛选区域；
- 操作按钮区；
- 表头；
- 表体；
- 底栏；
- 搜索、筛选、批量操作、分页。

其可转译原则：

- 筛选区服务快速定位，不是装饰；
- 主操作放在稳定、可预期的一侧，次要操作降级；
- 表头必须解释列含义，表头筛选不宜无差别使用；
- 金额、数量、日期和编号必须可纵向比较；
- 分页、总数、每页条数和当前位置必须完整；
- 批量操作必须明确选中范围和影响对象；
- 空表、无结果和加载中不能使用同一种视觉状态。

### 2.4 图表必须先有结论

《数据可视化 - 图表》强调：

- 图表标题应尽量包含结论，不只描述主题；
- 删除不必要的背景填充、渐变、三维效果和网格线；
- 淡化和统一必要非数据元素；
- 去除不必要的数据系列，避免信息过载；
- 用标签、颜色对比和简单文字强调最重要的数据。

转译为装得清规范：

- 图表上方必须有一句业务结论；
- 图表不能替代结论带；
- 同一图表不超过一个主要叙事焦点；
- 图表颜色使用语义/业务含义，不做彩虹色装饰；
- 默认减少网格线、背景和三维效果；
- 图表缺失或口径不完整时，不绘制伪完整图形。

### 2.5 设计系统 = 可用组件，不只是文档

《设计系统/组件库全面知识整合》强调：

- 设计系统是清晰、规范、可复用的组件库；
- 设计规范的重点是指导，设计系统的重点是可用；
- 需要统一颜色、字体、图层样式、图标、栅格和组件；
- 原子化设计可降低设计、开发和走查成本。

这要求 UI Craft 智能体：

- 优先复用 Token 和现有组件；
- 新增组件必须说明为什么现有组件无法满足；
- 新组件必须定义状态、尺寸、内容、交互和可访问性；
- 页面不得自造第二套按钮、卡片、状态标签、抽屉或空态。

### 2.6 好 B 端工作台先解决路径，再解决漂亮

《B端项目整理-后台系统》中的改进表述包括：

- 核心功能前置，降低用户查找负荷；
- 首页布局重构，缩短路径；
- 活跃功能前置，模块合理分割布局；
- 增加可视化信息，帮助快速获取结果；
- 重塑导航架构，降低认知成本和决策难度；
- 信息分类梳理，所见即所得；
- 锚点切换，帮助用户在一个页面完成长表单。

对应装得清：

- 先决定“谁在什么时候处理什么”，再决定卡片和图表；
- 首屏优先展示当前对象、当前状态和下一步；
- 不要用多级菜单掩盖主链；
- 长表单允许分段、锚点和上下文预览；
- 详情、抽屉和全屏工作面必须保留对象身份和返回上下文。

## 3. 高赞样本中的“展示层陷阱”

很多高赞作品是作品集包装，不是日常生产界面。必须区分：

| 展示层手法 | 是否适合装得清工作台 |
|---|---|
| 超大封面标题、项目叙事长图 | 不适合生产页，可用于设计说明/汇报 |
| 3D 图标、插画、强材质光效 | 少量可用于品牌页，不进入高频工作台 |
| 深色大屏、霓虹光、星河流光 | 不作为默认工作台语言 |
| 大面积渐变、玻璃拟态 | 不作为主要层级手段 |
| 多色图表、装饰性数据图表 | 禁止替代结论 |
| 过度留白的作品集卡片 | 可参考节奏，不能牺牲信息密度和操作效率 |
| 原型动效和鼠标悬浮展示 | 只保留有业务含义的反馈 |

核心反思：

> 站酷高赞作品证明“视觉工艺”很重要，但装得清要追求的是 **workbench craft（工作台工艺）**，不是 **portfolio craft（作品集工艺）**。前者的目标是每天更快做对事，后者的目标是让人停留和赞叹。

## 4. 对装得清的直接转译

### 保留

- 浅中性画布和克制的表面层级；
- 单一品牌强调色；
- 清晰的三层信息和排版节奏；
- 表格、图表、卡片的高数据墨水比；
- 设计系统、Token、组件复用；
- 核心功能前置、导航收敛、上下文连续；
- 轻量但有意义的反馈动效。

### 调整

- 站酷样本的蓝色强调 → 装得清使用品牌青绿 `#2F7D5A` 作为主行动色；
- 站酷样本的展示型大标题 → 工作台使用编辑级标题，不抢业务结论；
- 站酷样本的封面式大图 → 生产页面只保留业务对象和必要证据；
- 站酷样本的多色数据图 → 装得清按业务语义和 Token 控制色彩；
- 站酷样本的卡片作品集节奏 → 工作台用队列、对象工作面和行动栏组织信息。

### 禁止照搬

- 具体作品的构图、配色组合、插画、3D 图标、品牌标识；
- 需要长时间停留欣赏但降低操作效率的展示方式；
- 未验证的行业数据、案例文案或产品能力描述；
- 以“大屏感”替代经营判断；
- 用高饱和色块制造视觉冲击而破坏状态语义。

## 5. 设计结论

装得清的高质感不来自“更多视觉”，而来自：

1. 更少但更准确的视觉层级；
2. 更少但更明确的强调色；
3. 更少但更有业务含义的图表；
4. 更少但更可靠的交互反馈；
5. 更少但更完整的状态覆盖；
6. 更少但更连续的工作流。

设计判断的最终问题不是“像不像站酷高赞作品”，而是：

> 一个装企老板、店长、设计师或财务，在真实业务压力下，是否更快看懂了、更少点错了、更愿意每天打开？

## 2. 最重要的发现

### 2.1 3D 场景真正有价值的地方是“空间定位”

智能建筑和智慧园区样本反复出现同一模式：

- 3D 场景负责回答“在哪里”；
- 数据标签负责回答“是什么状态”；
- 右侧或场景内的检查器负责回答“下一步做什么”；
- 平面列表负责兜底和批量操作。

《智能建筑可视化系统》强调将楼宇数据与 3D 场景融合，通过重点区域呈现、设备运行状态和空间定位缩短研判路径。它不是把 KPI 做成 3D，而是让空间成为导航和定位层。

### 2.2 3D 交互不能只靠“看起来立体”

《100个关于3D交互动效的探索》提出从“界面”走向“界体”：

- 空间感知；
- 虚实互动；
- 全息构建；
- 仿真融合；
- 色彩、字体和动效共同服务空间理解。

对装得清的启发：

- 如果 3D 只是平面卡片贴了一个立体图标，它是装饰；
- 如果 3D 能帮助用户找到房间、阶段、风险或证据，它才是交互；
- 手机/桌面 ERP 仍然需要清晰的流程、信息层级和操作路径。

### 2.3 高赞 3D 大屏多为深色，但不能直接搬进装得清

调色板分析显示：

- 数字孪生/工厂/设备类样本平均亮度约 21–40，常使用深色背景与青色、蓝色光效；
- 3D UI、B端作品集、智能家居类样本则出现大量白色/浅灰和单色蓝绿强调；
- 2.5D 方法类内容以白色画布为主，强调结构、透视和元素关系。

结论：

- 装得清不应默认使用深色霓虹“数字孪生”大屏；
- 工作台外壳保持浅中性，3D 场景作为内嵌的“空间窗口”；
- 家庭空间材质使用温暖中性色，风险/选中仍由 Token 语义色表达；
- 不使用大面积 bloom、玻璃拟态和强反射掩盖信息。

### 2.4 2.5D 比 3D 更适合大多数企业工作台

2.5D 样本强调：

- 先分析结构，再勾勒线稿；
- 确定光源与支撑点；
- 模块化拆解；
- 处理元素关系与前后层级；
- 复用视觉资源。

这些原则更适合装得清的：

- 业主户型/空间关系；
- 项目阶段与风险层；
- 材料与空间归属；
- 门店/项目关系图；
- 经营流转示意图。

2.5D 在 1024、低性能设备和键盘操作下更稳定，应作为默认空间表达；3D 是增强，不是默认。

### 2.5 功能按钮可以继承业务场景的形状和动作

《数字孪生-智能工厂设计思路分享》把冲压、焊装、涂装工作区特性融入按钮和动效。对装得清的启发：

- 户型场景中的“进入房间”可以继承空间位置；
- 施工场景中的“查看工序”可以继承房间与阶段；
- 验收场景中的“查看证据”可以定位到空间与照片；
- 但按钮不能因为像机械臂/设备而牺牲可读性、尺寸和一致性。

### 2.6 智能工地样本强调监控，但不能只做监控

智慧工地样本的价值点包括：

- 实时监控；
- 报警录像；
- 环境监测；
- 人员与设备管理；
- 发现问题后的处理闭环。

对装得清的启发：

- 空间场景必须连接任务、责任人和下一步；
- 不能只做一个漂亮的监控大屏；
- 业主、设计师、项目经理和老板看到的空间层不同，但同源事实必须一致。

## 3. 对装得清的具体转译

### 推荐使用 2.5D/3D 的页面

1. 项目空间风险：户型平面 + 房间阶段 + 风险 + 责任人 + 证据。
2. 设计与材料：房间区域 + 方案版本 + 主材归属 + 待选材料。
3. 施工与验收：房间 + 工序 + 待验收 + 整改 + 现场照片。
4. 多门店经营沙盘：只有真实空间分布或区域比较有价值时使用。

### 不推荐使用 2.5D/3D 的页面

- 财务金额、成本、利润；
- 客户列表、合同列表、审批表单；
- 权限配置；
- 长文本和复杂表格；
- 普通任务队列。

## 4. 反思

站酷上的 3D 作品非常容易让人“第一眼惊艳”，但企业产品的评价标准不是停留时长，而是：

- 是否更快找到问题；
- 是否更少点错；
- 是否更容易理解空间与阶段的关系；
- 是否能在低性能、键盘和 1024 宽度下继续工作；
- 是否在 3D 失效时仍能通过 2D 完成同一任务。

因此：

> 3D 在装得清里不应该是“页面主角”，而应该是“空间导航层”和“业务状态图层”。

## 5. 以后设计时的固定动作

1. 先问：这个业务问题是否真的需要空间感知？
2. 能用 2.5D 回答的，不默认上 3D。
3. 3D 必须绑定真实对象、状态和下一步。
4. 每个 3D 场景必须有列表/2.5D fallback。
5. 不得自动旋转、循环漂浮、用装饰物遮挡关键数据。
6. 1024 必须可退化为静态 2.5D。
7. 不用深色霓虹大屏替代浅色企业工作台。
8. 不用“数字孪生”称呼概念模型；概念模型必须明确标注。

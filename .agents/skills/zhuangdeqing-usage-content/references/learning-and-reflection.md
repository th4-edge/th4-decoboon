# 使用内容学习与反思

## 1. 反馈来源

- 入驻清单完成情况。
- 客服工单和高频问题。
- 培训提问与现场演示卡点。
- 页面失败、无权限、状态冲突和兼容记录。
- 真实用户操作路径。
- 营销内容带来的用户预期与实际使用差异。

## 2. 每个学习卡判断

```text

场景：

现有产品是否有缺口：

```

## 3. 分流

- 内容缺失或表述不清 → 修改使用内容。
- 页面结构与用户习惯冲突 → 先核验现有路径，不轻易大改。
- 业务事实无法表达 → `T05_REQUIRED`。
- 产品状态/权限/金额错误 → 研发问题。
- 客户自身流程不支持 → `UNSUPPORTED` 或定制边界。

## 4. 反思纪律

- 不因为一个客户问题就改全量教程。
- 不在聊天里沉淀兼容结论，写入兼容台账。
- 客户临时做法不得升级为正式业务规则。
- 产品修复后标记旧教程 `stale` 并复核。

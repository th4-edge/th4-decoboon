# 使用内容体系

## 1. 使用内容的起点

使用内容不是功能说明，而是帮助用户完成当前任务：

```text
谁在什么场景
→ 想完成什么
→ 从现有哪里进入
→ 最小动作是什么
→ 系统如何反馈
→ 下一步去哪里
→ 失败如何恢复
```

## 2. 内容层级

### 入驻前

- 装得清适合什么装企。
- 需要准备哪些基础资料。
- 哪些内容可以后补。
- 哪些高风险口径不能猜。

### 入驻首日

- 企业、门店、人员。
- 客户、房屋、项目基础档案。
- 当前业务如何承接。
- 第一个真实任务。

### 入驻首周

- 客户跟进。
- 设计报价合同。
- 项目开工与现场留痕。
- 收付款与成本完整性。
- 负责人如何查看经营事实。

### 日常使用

- App 高频快捷任务。
- Web 深度比较、批量和对账。
- 通知、搜索、返回和深链。
- 异常、冲突和恢复。

## 3. App / Web 分工

| 任务 | App | Web |
| --- | --- | --- |
| 即时查看今天要处理什么 | 主场景 | 辅助 |
| 现场拍照、日报、节点留证 | 主场景 | 辅助/回看 |
| 轻量确认、跟进、回读 | 主场景 | 支持 |
| 跨项目比较、批量处理 | 不强行承载 | 主场景 |
| 财务对账、复杂筛选 | 摘要和快速处理 | 主场景 |
| 模板、组织、权限治理 | 查看/轻量操作 | 主场景 |

同一任务在两端的状态、金额和权限必须一致；差异只允许出现在交互形式和设备能力。

## 4. 使用内容质量判断

- 用户是否需要先理解模块名才能开始？
- 是否告诉他“为什么现在做”？
- 是否直接进入当前对象，不重复搜索？
- 是否说明完成后发生什么？
- 失败后是否保留输入和上下文？
- 是否区分真实空、筛选空、接口失败和无权限？
- 是否明确 App/Web 哪个更合适？
- 是否把线下事实误写成系统事实？

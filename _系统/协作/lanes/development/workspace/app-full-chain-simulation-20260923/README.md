## 4. 已验证的闭环

1. 选材 `PendingConfirm -> Confirmed` 后，原合同材料计划绑定 `selection_id`，状态推进为 `ReadyToOrder`。
2. 材料采购 `Approved -> Ordered` 后，采购单、应付和材料计划状态同步；应付到达账期回填前 `due_date` 为空。
3. 材料到场后，采购单变为 `Received`、材料计划变为 `Arrived`、应付回填 `receipt_date/due_date`，金额与采购金额一致。
4. 变更 `Pending -> Approved -> CustomerConfirmed` 后，合同当前金额、项目合同额和已确认变更金额严格一致。
5. 项目 43/44 的材料 Quantity 变更把计划数量从 30 调整到 27，证明增减项能回写材料计划。
6. App 实际读取接口已校验：材料计划工作台、选材分项、项目采购、合同变更列表均能返回真实数据。

## 5. 本次发现并修复的阻断缺陷

执行“材料下单”时发现：`project/purchase/order` 创建应付时写入 `dueDate=null`，但 `Payable.dueDate` 与数据库列为 `NOT NULL`，导致事务失败。

修复口径按 `DEC-MP-01`：下单即形成应付，到场确认后按供应商账期回填到期日。

- `Payable.dueDate` 改为可空。
- 新增迁移 `docs/design/migrations/55-应付账期到场回填.sql`。
- 同步更新空库基线 `01-空库基线.sql`。
- 本地应用迁移后，项目 37 重试下单并到场，应付成功回填为 `2026-10-23`。

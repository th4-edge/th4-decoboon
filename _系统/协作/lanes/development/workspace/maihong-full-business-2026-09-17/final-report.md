# 麦鸿装饰全业务实测总结

## 结论

本轮从空库开始，完成了“企业注册 -> 岗位体系 -> 麦鸿报价库导入 -> 客户 -> 量房 -> 设计 -> 报价 -> 合同 -> 项目 -> 施工任务 -> 阶段验收 -> 采购 -> 收货 -> 库存 -> 应付 -> 付款 -> 应收 -> 回款”的完整链路。

系统主流程已经能够闭环，且多岗位数据范围基本按职责生效。但当前还不能直接宣称“签单即算清”，核心原因是报价库没有真实成本价，导致利润指标失真；同时 5980 基础版试用并不包含供应链、财务和经营分析模块，无法单独支撑完整经营闭环。

## 已完成验证

- 557 条麦鸿报价成功导入并生成正确编号。
- 客户、房屋、量房、设计、报价、合同、项目、任务、验收、库存、应付、收付款数据全部贯通。
- 项目最终 100% 完工，5 个阶段验收完成。
- 供应商 1 家，采购单 1 张，到货 120㎡，应付 8,160 元已核销。
- 客户回款 27,072.85 元，待收 63,169.98 元。
- 本地全量测试：90 tests，0 failures，0 errors。
- App：先前小程序构建和分包校验通过；本轮关键页面在开发者工具中复验通过。

## 必须优先解决

1. 成本价模型和利润口径：先确保每个报价分项有可追溯采购成本，再做经营利润展示。
2. 基础版试用权益：明确是否提供供应链、财务和经营分析只读/限额能力。
3. 报价数据预校验：把单位、零价格、重复名称、公式型项目和缺失成本作为导入阻断或警告。
4. 协作关系模型：从单 owner 权限升级为客户/房屋协作成员，避免为设计师、业务员、项目经理不断打补丁。
5. 状态一致性：阶段验收、任务完成、项目完工必须严格按阶段归属推进，不能由全项目任务完成统一回写。
6. 写操作幂等：创建采购、付款、收款等接口必须支持幂等键，避免响应异常后的重试形成重复单据。
7. 真实业主端：补做独立业主微信账号的邀请、方案确认、验收确认和工地查看闭环。

## 1. 用户现象

BOSS 按首页“开始使用装得清”引导完成成本价格和供应商维护后，返回首页仍看到引导未完成。

## 2. 已确认根因

1. 供应商步骤在 `OnboardingChecklist.vue` 中写死 `done: false`，无论供应商是否已维护，都不会显示完成。
2. 引导数据只在组件挂载时加载一次；从报价项目库、供应商协作等子页面返回首页时，没有重新读取业务数据，旧状态会继续显示。
3. 引导方案没有把“必做/可选”与“完成谓词”冻结为可执行字段。当前必做项是报价项目、成本价、第一个客户；供应商和成员邀请为可选，但用户看到供应商步骤时容易理解为必须完成该步骤后才能结束引导。

## 3. 已完成修复

- App 首页引导改为读取真实供应商数据。
- 供应商步骤完成条件暂定为：`status=active`、`type=supplier`、至少一个关联品牌。
- 首页每次 `onShow` 时调用引导组件 `reload()`，覆盖从成本/供应商页面返回的场景。
- App `npm run type-check` 已通过。

## 4. 过程反思

### 产品规划

- 已有候选包写了“卡片由真实数据推导”和状态来源，但没有形成逐步状态契约：负责人、是否必做、完成谓词、计数口径、空态、错误态和刷新触发条件。
- 验收标准只覆盖“能看到卡片”，没有覆盖“完成业务动作 -> 返回首页 -> 状态变完成”的状态迁移。
- “供应商和品牌关系”与“供应商主数据已创建”没有在验收层明确区分。

### 开发实现

- 在生产组件中留下 `done: false` 占位，表明页面壳先于数据契约落地，且没有显式阻断或 TODO 门禁。
- 只实现首次挂载加载，没有检查 Tab 页面返回、子页面返回和会话重新显示的生命周期。
- 类型检查、构建检查只能证明代码可编译，不能证明业务动作后状态收敛。

### 验收设计

- 缺少可完成型引导的状态迁移用例，尤其是“动作成功 -> 页面返回 -> 进度刷新”的跨页面回归。
- 缺少“可选步骤完成后不改变必做分母”“必做步骤未完成时下一步指向正确对象”的独立验证。

## 5. 防复发要求

1. 每个引导/进度步骤必须冻结以下字段：`key / label / required / source_provider / completion_predicate / count / refresh_triggers / next_action`。
2. 生产代码禁止用 `done: false`、静态布尔值或演示数据作为完成状态；必须由领域 API 返回的真实对象派生。
3. 所有会因用户新增、编辑、删除而变化的进度项，必须在页面重新显示时刷新，或在跨页写入后使缓存失效。
4. 必做与可选必须同时体现在文案、分母、下一步和验收用例中；可选步骤完成后不得改变必做分母。
5. 验收必须覆盖：初始态、动作成功返回后的完成态、动作失败/接口异常、可选步骤完成、必做步骤未完成、重复进入页面。
6. 任何“完成状态”不得以接口 `success=true` 代替；必须核对对应领域对象的真实状态和页面展示。

## 6. 待产品冻结

- 供应商步骤究竟以“新增有效供应商”还是“有效供应商 + 至少一个关联品牌”为完成谓词。
- 首页当前 3 个必做项是否与《新手企业操作引导手册》的 6 步路径完全一致；如果不一致，应以一个冻结状态表作为唯一实现依据。

## 3. 缺陷清单

### P0-01 开发环境 API 地址错误导致登录网络异常

- 现象：本地登录固定报“网络异常”，请求绕过 Vite 代理访问 80 端口。
- 根因：`.env.development` 配置 `VITE_API_BASE=http://127.0.0.1/api/`。
- 影响：本地开发环境无法登录，阻断全部联调。
- 状态：本次走查中已修复为 `/api/`。
- 优化：保留 `VITE_DEV_PROXY_TARGET=http://127.0.0.1:8090`，新增启动前自动校验 API 基址和代理连通性。

### P0-02 量房日期格式不兼容，错误信息不可读

- 现象：客户详情“约定量房”选择时间后提交失败，提示“未定义错误信息:{0}”。
- 根因：前端提交 `YYYY-MM-DD HH:mm:ss`，后端接口需要 ISO `YYYY-MM-DDTHH:mm:ss`。
- 影响：用户无法通过 Web 完成量房预约，且错误提示无业务含义。
- 优化：统一 Web 时间序列化格式；后端补参数解析兼容和可读参数校验消息。

### P0-03 “量房管理”与客户量房状态使用两套数据模型

- 现象：客户详情显示已约定量房，但“量房管理”页面没有记录。
- 根因：`customer/customer/measure` 只写客户预约字段；量房管理读取独立 `Measure` 实体，Web 没有创建该实体的入口。
- 影响：业务人员认为已预约，执行人员看不到量房任务；无法管理到场、完成、照片和尺寸结论。
- 优化：约定量房时原子创建 Measure，或明确拆分“预约量房”和“量房记录”，并提供从预约直接进入录入的强逻辑视图。

### P0-04 Boss 无法兼任设计师，单角色模型阻断小企业流程

- 现象：企业只有 Boss 时“指定设计师”为空，系统无法继续设计流程。
- 影响：小型装企老板常同时负责经营和设计，当前模型强制必须新增第二个 Designer 员工。
- 优化：支持一员工多岗位/临时兼任；至少允许 Boss 以“本人设计师”身份承接方案，或在项目级配置设计负责人而不要求 EmployeeRole 必须是 Designer。

### P0-05 任务验收动作缺失，阶段验收无法自然推进

- 现象：任务提交完成后变成“待验收”，但 Web 没有“任务验收通过/确认完成”动作；阶段验收要求所有任务 Done，形成死锁。
- 影响：施工任务无法闭环，阶段验收只能通过接口绕过。
- 优化：项目详情和任务管理增加“验收任务”动作及权限矩阵；待验收任务的入口应在项目详情和待办中心高亮。

### P0-06 开工缺少强前置校验

- 现象：项目经理为 `-`、开工日期为 `-`、计划完工为 `-` 时仍可直接阶段开工，项目进入施工中。
- 影响：责任无人、工期未定即可开工，后续履约和统计基础失真。
- 优化：增加开工交底/条件核验页，至少强制项目经理、计划工期、施工计划、量房完成和客户确认；未通过不得开工。

### P0-07 通用“编辑”按钮大量调用创建接口，存在重复数据风险

- 现象：项目、报价、合同、跟进、合同变更等页面均显示“编辑”，但对应表单仍是创建语义。
- 典型位置：项目列表“编辑”打开“已接受报价 + 项目名称”的立项表单，而不是项目资料编辑。
- 影响：用户以为在修改，实际可能重复创建项目、合同或跟进记录。
- 优化：资源定义增加 `editable/createOnly` 语义；创建型动作只显示“查看/重新发起”，编辑必须绑定 update Provider 和旧实体主键。

### P1-01 路由只带 propertyId 时显示内部编号

- 现象：从客户详情进入量房管理后，装修房屋筛选框显示 `226014853528027136`。
- 根因：实体选项依赖 customerId，但路由只带 propertyId，未按主键反查标签。
- 优化：实体选择器支持已选 ID 的按主键回填；不要向业务人员暴露内部 ID。

### P1-02 依赖选择器提示与服务端状态不一致

- 现象：所属项目已预填，但施工阶段仍提示“请先选择项目，再选择施工阶段”。
- 影响：用户误以为上游没有选择，重复操作。
- 优化：已满足依赖时显示“请选择施工阶段”；依赖未满足时再显示前置条件。本次已修正通用提示逻辑，待复验。

### P1-03 设计分项默认关联“综合”，丢失区域归类

- 现象：方案已有“客餐厅”区域，新增行默认仍是“综合”。
- 影响：区域施工范围和报价分组失真。
- 优化：新增行继承当前选中区域；从 Excel 粘贴时校验区域名称，未匹配时要求人工确认。

### P1-04 项目详情是只读陈列，不是履约指挥台

- 现象：任务清单、现场动态、阶段验收只展示结果，不能在当前项目上下文直接开始、验收、补证据。
- 影响：项目经理被频繁跳转到其他资源页并重新选择项目。
- 优化：将项目详情升级为项目指挥台：待办、风险、阶段、任务、材料、验收、变更均可在项目上下文内直接推进。

### P1-05 合同生命周期缺少独立强视图

- 现象：合同只在报价详情内显示一小段金额摘要，状态直接出现 `pendingSign`、`signed`，没有合同条款、回款节点、签署材料、变更历史和履约责任视图。
- 优化：增加合同履约台，同时统一合同状态中文映射。

### P1-06 验收缺少证据与整改闭环

- 现象：阶段验收只有结论和文字说明，没有照片/视频、问题清单、责任人和整改截止时间；无任务证据也可提交验收。
- 优化：验收表单增加证据文件、问题项、整改责任、复查记录；按业务规则限制无证据提交。

### P1-07 消息角色文案错误，时间格式不统一

- 现象：老板执行指定设计师后，消息写“店长已指定设计师”。
- 现象：消息中量房时间显示 `2026-09-19T10:00`，Web 页面其他位置显示空格格式。
- 优化：消息使用实际角色和操作人；全系统统一日期时间格式化和时区处理。

### P1-08 客户、合同和项目状态快照不同步

- 现象：客户详情阶段与房屋状态、项目状态并非同一语义：已指定设计师后客户仍显示“待量房”，房屋显示“量房中”，项目最终显示“待验收”。
- 优化：区分线索阶段、预约量房阶段、量房执行阶段、设计阶段、项目履约阶段，禁止一个字符串承担多种生命周期。

## 4. 缺少的强逻辑视图

1. **客户作战台**：今日待跟进、逾期、预约量房、待指派设计、待报价集中处理，而不是只看列表。
2. **量房执行台**：预约、出发、到场、量房完成、照片、尺寸、原始结构和设计交底。
3. **设计确认台**：诉求确认、方案版本对比、客户选择、设计冻结和报价前置条件。
4. **合同履约台**：合同条款、签署材料、回款计划、变更、开票和生效条件。
5. **开工准备台**：项目经理、施工计划、材料、现场条件、客户交底和风险确认。
6. **项目指挥台**：任务状态、证据、风险、材料、验收、变更和财务在项目上下文内联动推进。
7. **验收闭环台**：任务验收、阶段验收、问题整改、客户确认、整改复查和项目关闭。
8. **角色待办中心**：按角色展示“下一步动作”，而不是依赖用户记忆菜单和对象编号。

## 5. 建议优先级

### P0

- 修复量房模型分裂和 Web 量房写入失败。
- 增加任务验收动作，解除验收死锁。
- 增加开工前置校验。
- 移除创建型表单上的伪编辑入口。
- 支持 Boss 兼任设计师或项目设计负责人。

### P1

- 项目指挥台、合同履约台、验收闭环台。
- 设计分项区域继承和 Excel 粘贴校验。
- 日期时间、状态字典、消息文案和状态快照统一。
- entity 选择器按 ID 回填和依赖提示修正。

### P2

- 待办中心、工作台行动建议、批量录入体验和响应式细节。

## 6. 结论

系统已经具备从客户到报价、合同、项目、施工任务、验收和应收的主链路能力，但目前的 Web 更像“多个资源页 + 部分聚合详情”，还不是稳定的家装履约操作系统。最需要补的不是更多页面，而是把关键业务节点做成有强校验、强责任、强证据、强下一步动作的视图。

## 7. 本轮修复落地状态

- 开发环境 API 地址改为同源 `/api/`，登录恢复。
- 预约量房现在会创建 `Measure(Scheduled)`，量房结果会更新同一条记录为 `Completed`，不再分裂客户预约字段和量房记录。

- 创建型资源页不再显示伪编辑入口；客户、设计方案、报价项目库和项目配置使用真实更新能力。
- 项目详情升级为项目指挥台，增加履约入口、开工准备清单和任务动作。

- 新增验收闭环工作台 `/projects/acceptance`，展示任务验收、阶段验收、业主确认和整改状态。

- Boss 可作为设计负责人被指派，解决单账号小企业无法推进设计流程的问题。

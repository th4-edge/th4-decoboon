## 1. 两个真实场景

### 场景 A：新成立 15 人单店装企

1. 使用人：BOSS。
2. 触发事件：企业注册后首次进入 App 首页。
3. 当前动作：系统读取企业真实报价项目、标准成本、客户与房屋事实。
4. 系统下一步：必做项未完成时指向当前首个未完成步骤；客户无房屋时客户步骤不得完成。
5. 异常处理：任一必做数据源失败时显示“状态暂不可确认”，不展示伪完成或旧状态。

### 场景 B：存量装企新增项目经理

1. 使用人：项目经理。
2. 触发事件：接受邀请并首次进入 App 首页。
3. 当前动作：系统按本人项目责任范围计算岗位首任务。
4. 系统下一步：有负责项目时指向 PM 工作台；无项目但存在待接单项目时提示接单；完全无责任项目时显示等待项目分配。
5. 异常处理：只返回本人及当前项目参与范围，不展示企业其他项目明细或其他员工责任数据。

### 场景 C：业主接受邀请

1. 使用人：业主客户。
2. 触发事件：接受邀请后进入首页。
3. 当前动作：系统只读取当前微信身份的有效项目授权。
4. 系统下一步：有授权项目时指向“我的家/项目动态”；无授权或授权撤销时显示等待有效邀请。
5. 异常处理：不展示企业内部成本、成员、客户和项目经营数据。

## 2. 冻结状态字段

每个步骤返回 `key / label / description / required / sourceProvider / completionPredicate / status / count / action / actionLabel`。

- `status=done`：真实领域对象满足完成谓词。
- `status=todo`：真实领域对象已确认未完成。
- `status=waiting`：当前角色尚无责任对象，等待分配或邀请。
- `status=unknown`：数据源异常，暂不可确认。
- 不使用 `done: true/false`、前端本地阅读标记或接口成功状态代替领域事实。

## 3. Boss 必做谓词

| key | required | completion_predicate |
| --- | --- | --- |
| `catalog` | 是 | 当前企业至少存在 1 个 active 报价项目 |
| `cost` | 是 | 当前企业至少存在 1 个 active 且 `costPrice > 0` 的报价项目 |
| `customer` | 是 | 当前企业至少存在 1 个客户，且该客户至少关联 1 套房屋 |
| `partner` | 否 | 至少 1 个 active 材料供应商，且至少关联 1 个非空品牌 |
| `member` | 否 | 当前企业至少 1 个非 Boss 的 active 成员 |

必做分母固定为 3；可选步骤不进入分子或分母，不阻塞首次入驻完成。

## 4. 角色岗位首任务

- 店长/团队长：本门店/团队存在客户责任事实。
- 业务员：本人至少 1 个客户且该客户至少 1 套房屋。
- 设计师：本人至少被分配 1 套房屋。
- 项目经理：本人至少负责 1 个项目；无负责项目但存在未分配项目时提示接单。
- 履约专员：本人至少参与 1 个项目。
- 财务：当前企业至少存在 1 条应收或应付事实。
- 业主客户：当前微信身份至少有 1 条有效项目授权。

店长、团队长的最终业务必做谓词仍以产品后续冻结为准；本轮只用于岗位引导，不作为验收通过或业务权限门禁。

## 5. 验证计划

- 后端：Boss 客户无房屋不完成、补齐房屋完成、删除回退由真实查询结果决定；必做源异常为 unknown；可选源异常不阻塞必做完成；员工角色范围计数；业主仅计有效授权；路由需登录。
- App：首页 `onShow` 和下拉刷新重新读取；加载、空、错误、未知、可重试状态可见；按钮跳转使用集中路由。

## 6. 实施结果

- 后端新增 `statistic/onboarding/report` 受保护聚合路由，服务端按真实领域对象推导 Boss 三件套、可选步骤和 8 类员工/业主岗位首任务。

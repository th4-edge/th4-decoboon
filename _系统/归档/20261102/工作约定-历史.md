# 工作约定（省 Token 执行口径）

> 本文件是同一话题的**唯一入口**：续做同一话题时先读本文件，不再重读大 worklog、rules.md 全文或历史对话。
> 约定自 2026-09-24 起生效，适用于用户直接发起的开发/UI 迭代任务。

## 试运营单人模式（当前最高优先级）

- 端到端流程以 `docs/operations/试运营单人轻量协作与发版规范.md` 为准。
- 默认只读 AGENTS、轻量规范和本文件近期改动；不预读完整 lane/worklog/shared。
- L1 小修复只跑定向测试和构建；L2/L3 或用户要求才跑全量测试。
- 不强制 lane、独立验收、RC tag；tag 按天、周或批次创建。
- 每次任务最多追加一行近期改动，不写重复交接包。
- 默认预算：L0 最多 3 个文件/100 行；L1 最多 8 个文件，一次定向测试 + 一次构建，工具输出只看关键行。
- 权限、金额、成本、支付、跨租户、DDL 和数据删除仍保留安全底线。

## 1. 执行约定

| 约定 | 要求 |
| --- | --- |
| 最小补丁 | 改代码只做定点替换（脚本内读改写，只打印 diff），禁止整文件重写、禁止把完整文件贴进对话 |
| 定向读取 | 先 `grep -n` 定位行号，再只读相关 30–80 行；不整文件读、不重复读同一文件 |
| 视觉先证据 | UI/排版问题先要用户截图或明确期望；同一问题最多推测一轮，不连续试错 |
| 一轮一次验证 | 批次收尾统一跑 `type-check + build:mp-weixin + check:subpackages`；后端只在逻辑改动时跑定向测试，全量测试留给里程碑 |
| 不扩大范围 | 口径、权限、架构级联先问；跨模块统一改动必须显式确认 |
| 工作台动作隔离 | 工作台内的动作只能是单职责抽屉/小表单；禁止把完整业务页面组件塞进抽屉或中栏复用。若需求要求“直接执行动作”，必须先冻结动作字段和完成条件，再实现，不得以复用旧页面代替交互设计。 |
| 记录从简 | 每轮只在本文件「近期改动」追加**一行**，不写重复文档 |
| 输出从简 | 回复正文 ≤ 一屏，工具输出只取需要的行（`grep`/`tail`），不 dump 全量日志或编译产物 |

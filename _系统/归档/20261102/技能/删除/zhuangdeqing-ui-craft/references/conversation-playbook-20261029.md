# 装得清 Web UI 对话沉淀 · 工作台设计判断手册

> 状态：`working_playbook`。来自 2026-10-29 多轮登录页、品牌主题、壳层、账号菜单、消息通知、内部编号清理与设计页面观察。
>
> 定位：这是 UI Craft 的判断辅助，不替代业务事实、页面源码、Token 或真实渲染证据。
>
> 结论：装得清要追求 **workbench craft（工作台工艺）**，不是 portfolio craft（作品集工艺）。

## 1. 第一性判断

任何页面先回答：

```text
角色是谁
→ 当前职责和结果是什么
→ 哪个业务对象进入视野
→ 对象现在是什么状态
→ 当前唯一合法动作是什么
→ 做完后反馈什么
→ 需要回读什么
→ 交给谁继续
```

如果这条任务链答不出来，不许用卡片、图表、动效或品牌视觉补答案。

## 2. 十条页面铁律

1. **任务先于布局**：先冻结对象、状态和下一步，再决定是列表、队列、详情、表单还是流程页。
2. **首屏先给结论**：当前发生了什么、影响什么、下一步做什么，比页面标题和说明更重要。
3. **一个页面只有一个主行动**：其他动作降为次级按钮、文字动作、行内动作或“更多”。
4. **同一事实只讲一次**：状态、金额、数量、负责人和下一步不得在 Hero、指标卡、侧栏和底部重复。
5. **用对象识别，不用系统编号识别**：名称、地址、客户、方案版本、状态、金额、日期和责任人优先；内部 ID 和系统编号默认不展示。
6. **页面服务于连续工作**：筛选、选中对象、页签、滚动、未保存草稿和返回路径必须恢复。
7. **未知必须显式**：缺字段、读取失败、无权限、来源不完整显示“暂不可确认”和恢复路径。
8. **高密度不做卡片墙**：结构化比较用表格/列表，顺序用轨道，证据用折叠区，风险用队列。
9. **动效只表达变化**：状态变化、页面连续性、保存反馈和操作反馈可以动；循环呼吸、装饰光点和自动播放不允许。
10. **构建成功不是页面完成**：真实浏览器三档渲染、截图、两轮批判和边界状态才算交付证据。

## 3. 视觉气质

### 保留

- 暖中性或低噪浅画布；
- 白色内容面；
- 单一企业品牌强调色；
- 清晰文字层级；
- 8pt 间距节奏；
- 细边框、轻阴影；
- 高数据墨水比；
- 表格、队列和对象工作面；
- 适度留白，不用空白掩盖信息结构问题。

### 拒绝

- 大面积渐变、玻璃拟态和光效；
- 多套高饱和主色并列；
- 英文 eyebrow、泛化副标题和设计宣言；
- 所有模块都做成圆角卡片；
- 每个卡片都有图标、副标题和状态 pill；
- 为了“高级”把信息折叠到找不到；
- 用大而空的 KPI 卡片代替结论和动作；
- 用 2.5D/3D 给非空间问题制造空间感。

## 4. 登录与登录后的连续性

已形成的可复用模式：

- 登录页：企业身份 → 项目主线 → 单一登录行动；
- 企业品牌色：一个基色派生浅色、主色、深色、焦点、可读前景；
- 登录后：页面切换使用一次性 `page-shift`，不是每页重新做入场表演；
- 账号菜单：身份摘要 + 图标菜单 + 未读提示；
- 消息通知：单列表处置队列，不是“筛选卡 + 列表卡”；
- 页面头部：`PageHeader` 统一标题、摘要和操作区；
- 业务状态：文字、颜色、图标/形状同时表达。

## 5. 动效判断

允许：

- 登录页品牌落位；
- 项目主线一次性绘制；
- 页面切换 320ms 淡入/上移；
- 保存成功、状态变化、行选中和抽屉连续性；
- 输入聚焦、按钮按压和 loading。

禁止：

- 无限巡游光点；
- 鼠标跟随大面积柔光；
- 自动呼吸、漂浮或闪烁；
- 只靠动画制造“有数据”；
- 动画阻挡输入或延迟主行动；
- 忽略 `prefers-reduced-motion`。

## 6. 编号与信息可信

已由业务规则 `DEC-095` / `BR-060` 固化：

- 员工编号、企业编号、客户编号默认不展示；
- 报价、合同、项目、方案、费用、凭证、邀请编号默认不展示；
- 搜索提示不得要求用户记忆编号；
- 编号保留在数据、接口、权限、审计、二维码和法定打印载体；
- 统一社会信用代码、法定证照号码、发票法定号码是例外；
- UI 用名称、地址、角色、状态、金额、日期和责任人识别对象。

## 7. 页面母型选择

| 页面任务 | 母型 | 不应该 |
| --- | --- | --- |
| 看经营结论 | 结论带 + 风险/机会 + 行动队列 | KPI 卡片墙 |
| 处理今天事项 | 左队列 + 中工作面 + 右状态/下一步 | 通用首页快捷入口 |
| 推进单个对象 | 身份条 + 当前工作面 + 动作栏 + 历史 | 多个 Hero 并列 |
| 比较多个记录 | 筛选 + 表格 + 批量动作 + 分页 | 卡片瀑布流 |
| 新建/变更/确认 | 上下文头 + 分区表单 + 结果确认 + 失败恢复 | 一屏堆满全部字段 |
| 跟踪流程 | 阶段轨道 + 当前节点 + 阻断原因 + 下一动作 | 自动播放流程图 |
| 看空间关系 | 2.5D/2D 场景 + 检查器 + 列表替代 | 装饰性 3D |

## 8. 页面实现前的冻结问题

1. 页面类型是什么？
2. 目标角色是谁，当前职责是什么？
3. 用户打开页面时的第一个问题是什么？
4. 三秒结论是什么？
5. 唯一主行动是什么？
6. 这个页面减少了哪一步、哪一次判断或哪一类错误？
7. 哪些内容属于证据、说明或审计，应折叠或移出？
8. 加载、空、失败、无权限、长内容、极端值怎么表达？
9. 页面刷新、返回和操作完成后如何恢复上下文？
10. 哪些事实来自服务端，哪些只是 UI 派生，前端是否在偷偷重算？

## 9. 现有门禁

```text
npm run check:ai-flavor:self-test
npm run check:ai-flavor
npm run check:identifier-exposure:self-test
npm run check:identifier-exposure
npm run check:brand-theme
npm run check:client-copy
```

门禁是低噪音回归防线，不是视觉验收。仍必须：

- 1440×900、1280×800、1024×768 真实截图；
- 至少两轮批判与修正；
- DOM 几何、焦点、七类和极端值证据；
- 视觉模型只作预检，最后由用户或更强视觉评审确认。

## 10. 当前最重要的工作台判断

1. 不要重做全部页面；先把当前高频对象工作面收干净。
2. 一个页面只服务一个核心对象和一个主行动。
3. “入口多”不等于工作台清楚；入口应根据当前状态和职责出现。
4. 复杂页面优先减少重复信息，不是增加新的管理模块。
5. 先做真实数据、真实状态、真实交接；视觉 polish 最后做。
6. 页面要像员工每天使用的工具，而不是 AI 生成的管理后台。

# 装得清 Web 体验宪法 v1.0

本文件是装得清 Web 的体验北极星和交付基线。所有页面设计、改造、评审和验收均以此为准。

## 1. 定位

装得清 Web 是面向企业日常经营和生产协作的**商业级企业工作台**，不是营销官网、品牌展示页或演示大屏。

工作台必须优先回答：

1. 当前发生了什么？
2. 这对业务有什么影响？
3. 下一步应该做什么？

## 2. 气质

- **克制的高级感**：通过信息秩序、层级、留白、排版和一致性体现专业度；不得依赖大面积渐变、重阴影、玻璃拟态、装饰插画或奢华视觉制造高级感。
- **工具感**：用户必须快速识别可操作对象、操作结果和恢复路径；功能区域不得被品牌口号或装饰性内容占据。
- **低噪活性**：默认安静，只在业务状态变化、用户操作、数据更新或风险出现时提供有意义反馈；不得用持续闪烁或循环动画表达活性。

## 3. 首屏与层级

### EXP-001 三秒结论

首屏必须在三秒内呈现：

- 当前状态或关键事实；
- 业务影响或风险；
- 建议的下一步动作。

不得要求用户阅读多个图表、卡片或表格后才能自行推断结论。

### EXP-002 三层信息结构

| 层级 | 内容 | 展示规则 |
|---|---|---|
| L1 结论层 | 结果、风险、待决策事项 | 首屏直接可见 |
| L2 解释层 | 关键依据、异常原因、影响范围 | 摘要或一次展开可见 |
| L3 明细层 | 完整记录、历史、审计、技术字段 | 抽屉、详情页或次级页签 |

不得将三层信息以同等视觉权重铺满首屏。

### EXP-003 单一主行动

每个页面必须确定唯一主行动：

- 主行动视觉权重明显高于其他动作；
- 同一视口不得出现两个同等级主按钮；
- 次要动作使用次级按钮、文字按钮、行内操作或“更多”；
- 破坏性动作不得使用主行动样式，且必须提供影响说明和确认。

### EXP-004 渐进披露

- 首屏只展示结论、关键事实和主行动；
- 证据、历史和解释进入一次展开或上下文抽屉；
- 高级筛选、技术字段和审计信息默认折叠；
- 低频字段不得堆入首屏。

## 4. 视觉系统

- **Token 一致性**：颜色、字号、字重、行高、间距、圆角、阴影、边框和动效参数必须来自统一 Token，不得硬编码。
- **表面层级**：通过画布、内容面、浮层和覆盖层建立清晰层级，不得给所有卡片同时增加阴影、边框和背景色。
- **编辑级排版**：正文 ≥ 13px，辅助信息 ≥ 12px；标题、正文、标签、数字和说明使用固定字阶；长文本定义换行、截断和展开规则。
- **8pt 节奏**：间距以 8px 为基础，4px 只用于局部微间距。
- **等宽数字**：金额、数量、日期和编号使用等宽数字，便于纵向比较。
- **语义色**：成功、警告、风险、信息、中性使用稳定语义色，并同时提供文字和图标；不得仅靠颜色表达状态。
- **数据墨水比**：每个视觉元素都服务信息表达；减少无意义网格线、装饰色块、重复标签和无数据含义的图标。
- **可访问性**：正文、关键数字、按钮和状态标签满足 WCAG AA；焦点始终可见。

## 5. 交互

- **可发现性**：可点击、可编辑、可展开、可拖拽元素必须具备明确可供性，并定义默认、hover、active、focus、disabled、loading 状态。
- **即时反馈**：点击、聚焦或提交后 100ms 内出现可视反馈；超过 300ms 展示加载指示；超过 1 秒使用骨架屏、进度或明确处理中状态。
- **长任务**：超过 3 秒必须提供阶段、进度或持续活动、可取消路径、完成结果和失败恢复。
- **可逆操作**：非破坏性操作优先支持撤销；删除、作废、覆盖、批量变更必须确认并说明影响范围。
- **失败恢复**：说明原因、保留输入、提供重试/返回/替代路径，不得只显示“系统异常”或空白页。
- **焦点管理**：弹窗、抽屉、菜单和页面切换正确管理焦点，关闭后返回触发元素，不得用 `outline: none` 移除焦点提示。
- **任务连续性**：保留筛选、分页、滚动、选中项、未提交草稿、当前页签和对象上下文。

## 6. 动效与生命感

- 动效只服务空间连续性、状态变化、操作反馈、数据更新。
- 不得使用持续旋转、呼吸灯、漂浮、闪烁、背景流光等循环装饰动画。
- 动效使用统一时长和缓动 Token，不得阻塞操作或延迟关键信息。
- 尊重系统“减少动态效果”设置。
- 生命感来自真实业务状态：数据更新时间、新增/变更/风险/待处理数量、状态流转、责任人和下一步。
- 所有数据必须显示更新时间或新鲜度；过期、刷新失败或来源不可确认时显示“暂不可确认”。

## 7. 七类状态

| 状态 | 必须表达的内容 |
|---|---|
| 正常态 | 当前结论、关键事实、主行动、数据更新时间 |
| 加载态 | 保持结构稳定的骨架或进度提示，不得空白闪烁 |
| 空态 | 区分真实无数据、筛选无结果、尚未创建，并提供恢复动作 |
| 失败态 | 原因、影响范围、重试入口、替代路径 |
| 无权限态 | 权限边界、当前角色限制、申请或联系路径 |
| 长内容态 | 截断、展开、换行、分页或虚拟滚动，不得横向溢出 |
| 极端值态 | null、0、负数、超大金额、超长名称、大量条目的格式化与降级 |

不得用骨架屏伪装空态，不得用空数组或 0 伪装未知数据。

## 8. 数据可信

- 金额、成本、利润、状态、统计和关键业务数字必须可追溯到来源、口径和更新时间。
- 字段缺失、接口失败或业务记录不存在时显示“暂不可确认”并给出恢复路径。
- App、Web、Admin 对同一业务对象必须使用同一状态、权限、金额和统计口径。
- 无权限不得伪装为空数据。

## 9. 验收

### ACC-001 三秒结论

未查看明细的用户进入页面后，必须能复述当前发生了什么、有什么影响、下一步做什么。

### ACC-002 单一主行动

同一视口不得出现两个同等级主按钮，所有次要动作必须明确降级。

### ACC-003 状态完整

七类状态必须全部具备设计说明和实现证据；缺一不得通过。

### ACC-004 任务连续

列表筛选后进入详情再返回、编辑取消、刷新恢复、批量操作后选中状态和结果必须可核验。

### ACC-005 可访问性

键盘路径、焦点可见、语义标签、对比度和减少动效达到 WCAG AA 基础要求。

### ACC-006 同源同口径

同一对象在 App、Web、Admin 的状态、权限、金额、统计和更新时间完成对账。

### ACC-007 真实渲染

页面交付必须提供 1440×900、1280×800、1024×768 三档真实浏览器截图。类型检查、构建、接口成功和代码阅读不得替代渲染验收。

## 10. 禁止项

- 营销官网式首屏、口号和装饰插画占据功能空间；
- 同一页面多个主行动；
- 图表墙替代经营结论；
- 循环动画制造生命感；
- 0、默认值或空数组伪装未知数据；
- 仅靠颜色表达状态；
- 非 Token 颜色、间距、字号、圆角或阴影；
- 失败时只显示“系统异常”；
- 破坏性操作无确认、无影响说明；
- 禁用焦点轮廓或牺牲键盘可用性。

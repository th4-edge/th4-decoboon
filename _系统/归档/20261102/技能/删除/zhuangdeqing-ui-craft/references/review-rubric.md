# 装得清 UI Craft 评审量规

## 1. 评分方式

每个维度 0–4 分：

- **0 — 失败**：缺失或明显违反，用户无法完成任务。
- **1 — 不合格**：存在关键问题，需要重做。
- **2 — 待修正**：基本成立，但细节和状态不完整。
- **3 — 合格**：满足规范，可以进入下一门禁。
- **4 — 优秀**：不仅满足规范，还形成可复用的装得清页面语法。

任一维度低于 3 分，不得交付。主链页面平均必须 ≥ 3.5 分。

评分必须有截图、DOM、交互或状态证据；没有证据的评分视为无效。

截图存在不等于视觉评审完成。视觉维度必须由具备图像输入能力的模型或人工评审实际查看截图后评分；OCR、色板统计和 DOM 几何只能作为辅助证据。若当前主模型是 text-only，使用 `scripts/vision_review.py` 调用本地视觉模型，并保存模型名、图片路径和原始输出。3B 视觉模型只能作为预检；若没有视觉桥或更强视觉模型/人工复核，必须标记 `VISUAL_REVIEW_UNAVAILABLE`，不得宣称视觉维度通过。

## 2. 八个维度

### Q1 — 三秒结论

检查：

- 首屏是否直接说明当前发生了什么；
- 是否说明影响或风险；
- 是否说明下一步；
- 是否在 3 秒内可复述。

一票否决：

- 首屏只有标题、筛选器和图表；
- 需要读完多个卡片才知道结论；
- 结论与页面状态不一致；
- 用营销文案代替业务结论。

### Q2 — 三层信息与单一主行动

检查：

- L1 结论 / L2 解释 / L3 明细是否清楚；
- 首屏是否只保留关键事实；
- 是否只有一个视觉最重的主行动；
- 次要动作是否降级；
- 破坏性动作是否进入安全门。

一票否决：

- 同一视口两个同等级主按钮；
- 信息全部同权重；
- 主行动随屏幕变化而漂移；
- 操作结果和下一步不可见。

### Q3 — 视觉系统与质感

检查：

- 是否只使用 Token；
- 是否存在中性画布 + 白色内容面 + 单一品牌强调色；
- 字阶、行高、间距、圆角、阴影是否一致；
- 金额、数量、日期是否使用等宽数字；
- 表格和图表是否降噪；
- 是否存在作品集式大图、重渐变、玻璃拟态、3D 图标等不适当元素。

一票否决：

- 硬编码视觉值；
- 多套高饱和强调色；
- 页面像官网或作品集；
- 12px 以下正文；
- 阴影/边框/背景叠加造成层级混乱。

### Q4 — 交互反馈

检查：

- 可点击元素是否有默认、hover、active、focus、disabled、loading 状态；
- 点击后 100ms 内是否有反馈；
- 长任务是否有阶段/进度/取消；
- 成功是否说明影响和回读结果；
- 非破坏性操作是否支持撤销；
- 破坏性操作是否有确认与影响说明。

一票否决：

- 按钮点击无反馈；
- 提交中可重复点击；
- 失败后输入丢失；
- 高风险动作无确认；
- 关键操作只在 hover 时出现。

### Q5 — 七类状态完整

检查：

- 正常、加载、空、失败、无权限、长内容、极端值是否全部覆盖；
- 真实空、筛选空、未创建、数据源不可用是否区分；
- 无权限是否说明原因和路径；
- 极端值是否验证 null、0、负数、超大金额、长名称和大量条目。

一票否决：

- 用骨架屏充当空态；
- 用空数组或 0 伪装未知；
- 失败只显示“系统异常”；
- 无权限伪装为空数据。

### Q6 — 任务连续性

检查：

- 列表筛选后进入详情再返回是否保留筛选、分页和滚动；
- 编辑取消是否保留原上下文；
- 刷新/深链接是否恢复对象、子对象、工作面；
- 批量操作后选中状态和结果是否可核验；
- 完成后是否提供明确去向，而不是自动切对象。

一票否决：

- 返回后筛选和选中丢失；
- 刷新后需要重新搜索对象；
- 动作成功后只更新局部卡片，不回读必要范围；
- 自动切换到下一个对象。

### Q7 — 可访问性

检查：

- 全部关键路径可键盘完成；
- 焦点可见；
- 弹层焦点陷阱和归还正确；
- 图标按钮有可读名称；
- 表格有语义表头；
- 图表有文字摘要；
- 对比度达到 AA；
- prefers-reduced-motion 生效。

一票否决：

- `outline: none`；
- 只用颜色表达状态；
- 不可键盘操作的唯一主行动；
- 图表无文字摘要；
- 弹层关闭后焦点丢失。

### Q8 — 同源同口径与真实渲染

检查：

- App、Web、Admin 的状态、权限、金额、统计和更新时间是否同源；
- 正式字段缺失时是否显示“暂不可确认”；
- 是否提供 1440×900、1280×800、1024×768 真实截图；
- 是否有 1024 横向溢出；
- 是否有 Console 未处理错误；
- 构建、类型检查和接口 200 是否被错误当作视觉完成。

一票否决：

- 前端自算业务状态或金额；
- 同对象跨端口径不一致；
- 无三档真实截图；
- 用“构建成功”代替页面验收。

## 3. 产品真实性与 AI 味附加门禁

专业 UI 评审必须先于视觉喜好。以下任一失败即 BLOCK：

- 无法说清角色、职责、结果指标和任务链；
- 页面没有真实业务对象，只有 KPI、图表和卡片；
- 首屏不是当前对象/待办/决策，而是模板化数据看板；
- 页面没有减少用户步骤、判断成本或错误；
- 核心文案在解释设计理念、口径原则或“数据诚实”，而不是指导操作；
- 每个模块都是独立卡片，且都有图标、副标题和状态 pill；
- 出现英文 eyebrow、装饰圆环、呼吸点、无业务含义的 2.5D/3D；
- 只为评审者存在的“演示数据”“状态预览”等控件占据产品界面；
- 长内容、选项多、大量按钮和极端值没有交互规则；
- 页面通过视觉看起来“高级”，但用真实角色任务走不通。

专业评审十问见 `product-ux-review.md`。

## 4. 2.5D/3D 空间场景附加门禁

若页面使用 2.5D/3D，除 Q1–Q8 外必须满足：

- 场景回答“在哪里、什么阶段、风险在哪、下一步做什么”；
- 每个可交互空间绑定业务 ID、状态、责任人和来源；
- 有 2.5D/列表替代，3D 不是唯一路径；
- 键盘可遍历和选择空间；
- 不自动旋转，不循环漂浮；
- 1024 可静态降级且无横向溢出；
- 颜色/材质不替代状态文字；
- 不把概念模型说成 CAD/BIM 精确模型。

命中以下任一项即 FAIL：

- 给 KPI/金额/表格强行套 3D；
- 3D 没有业务对象映射；
- 没有 2D fallback；
- 自动旋转或装饰性漂浮；
- 用深色霓虹大屏替代企业工作台；
- 3D 加载失败后没有恢复路径。

## 5. 交付报告模板

```text
页面 / 批次：
页面类型：
目标角色：
使用场景：
唯一主行动：
三秒结论：
三层信息：
Token 与组件复用：
七类状态证据：
交互闭环证据：
任务连续性证据：
同源同口径对账：
三档渲染证据：
批判轮次 1：问题 → 修正 → 证据
批判轮次 2：问题 → 修正 → 证据
Q1–Q8 评分：
未解决项与原因：
最终结论：PASS / CONDITIONAL / BLOCK
```

## 6. 结论口径

- **PASS**：Q1–Q8 均 ≥ 3，主链平均 ≥ 3.5，且无未解决 P0/P1。
- **CONDITIONAL**：不存在 P0，但有明确 P1/P2 或未覆盖场景；不得对外说“完成”。
- **BLOCK**：任一维度 < 3，或命中一票否决，或没有真实渲染证据。

## 7. 批判循环要求

至少两轮：

1. 第一轮：按 Q1–Q8 逐项批判，列出最重要的问题；
2. 修正：优先改信息层级、状态、交互和可访问性，不先加装饰；
3. 第二轮：重新渲染并复核，确认没有因修正引入新问题；
4. 如仍有未解决问题，必须说明为什么不修，不得隐藏。

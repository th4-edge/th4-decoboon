# 装得清工作台页面母型与交互模式

本文件定义可复用的页面构图和交互模式。优先复用现有组件和项目规范，不为了“与众不同”发明新母型。

## 0. 工作台真实性

工作台首先是角色进入工作状态、掌握进展并继续处理的页面，不是 KPI 卡片集合。

```text
角色 -> 职责 -> 结果指标 -> 业务对象 -> 状态 -> 动作 -> 反馈 -> 回读 -> 交接
```

常用模块应围绕：

- 当前业务结论；
- 待办和风险；
- 当前对象与状态；
- 唯一主行动；
- 常用入口；
- 通知与帮助。

首屏应先出现“我今天要处理什么”，而不是“我有哪些图表”。如果一个模块既不能帮助判断，也不能触达动作，应折叠、弱化或移出页面。

## 1. 页面类型选择

### 1.1 决策页 / 经营驾驶舱

适用：老板、店长、财务负责人需要判断经营状态。

首屏顺序：

1. 页面标题与时间范围；
2. 三秒结论：经营结果、主要风险、待决策事项；
3. 关键事实：收入、回款、成本完整性、项目风险、待办；
4. 唯一主行动；
5. 风险/机会队列；
6. 可展开证据和明细。

禁止：

- 先放图表墙；
- 先放欢迎语或插画；
- 同一屏幕多个强主按钮；
- 用伪实时数字制造活性。

### 1.2 行动队列

适用：员工进入后需要处理“今天轮到我做的事”。

推荐结构：

- 左：队列与筛选；
- 中：当前对象工作面；
- 右：状态引导、下一步、责任人、阻断原因。

规则：

- 队列选中状态必须明显；
- 中栏保留客户/项目/单据身份；
- 右栏只放当前合法动作；
- 完成一个对象后不自动切换，由用户显式继续；
- 返回时恢复筛选、滚动和选中对象；
- 空队列说明“当前没有轮到你的事项”，不要伪装加载。

### 1.3 对象详情工作台

适用：客户、房屋、项目、合同、报价、工地、财务单据。

首屏顺序：

1. 对象身份条：名称、编号、状态、负责人；
2. 当前阶段/状态头；
3. 当前工作面：用户此刻最需要处理的业务块；
4. 唯一主行动 + 次要动作；
5. 关键事实摘要；
6. 历史、审计、附件、技术字段折叠。

规则：

- 对象身份条跨页面保持稳定；
- 不得用多个 Hero 竞争；
- 当前工作面优先于完整信息清单；
- 右侧动作栏必须表达“为什么现在做”和“做完去哪”；
- 高风险动作进入安全门。

### 1.4 专业列表

适用：客户、项目、报价、合同、财务流水、材料等批量处理场景。

结构：

1. 页面标题 + 数据范围 + 更新时间；
2. 常用筛选；
3. 操作区；
4. 表格；
5. 批量动作；
6. 分页和底栏统计。

规则：

- 列表不是 CRUD 入口，必须服务业务任务；
- 列必须按用户决策价值排序；
- 金额、数量、日期、编号使用等宽数字；
- 行点击进入对象工作面，不能先跳到一个无上下文详情页；
- 批量操作必须显示选中范围和影响；
- 无数据、无结果、加载失败和无权限必须区分。

### 1.5 事务表单 / 单据

适用：新建、变更、确认、收款、付款、验收、审批、退款。

结构：

1. 业务上下文头；
2. 表单分区；
3. 关键结果预览；
4. 风险/影响说明；
5. 主行动；
6. 提交中、成功、失败、冲突和恢复。

规则：

- 先展示“为什么做、影响谁、做完进入什么状态”；
- 长表单使用锚点或分段，不把 30 个字段一次铺满；
- 对象选择器必须保留业务上下文；
- 失败不丢输入；
- 破坏性动作必须确认；
- 提交成功后按业务要求回读，不得只关闭抽屉。

### 1.6 空间场景页

适用：项目户型、施工阶段、材料归属、验收证据、门店/园区空间。

推荐结构：

- 场景上下文条：项目/空间、当前图层、更新时间；
- 2.5D/3D 场景画布；
- 场景内直接标签；
- 选中对象检查器；
- 图层与状态图例；
- 2D 平面图/列表替代。

规则：

- 场景必须绑定真实业务对象 ID；
- 点击空间先更新检查器，不直接跳走；
- 每个空间必须有状态、责任人、下一步和数据来源；
- 3D 不得自动旋转，不得成为唯一入口；
- 1024 与低性能设备必须可退化为静态 2.5D/列表；
- 详细规则见 `spatial-scene-system.md`。

### 1.7 流程跟踪页

适用：签约、施工阶段、验收、整改、回款计划。

结构：

- 阶段轨道；
- 当前节点；
- 进入条件与完成条件；
- 责任人；
- 阻断原因；
- 下一动作；
- 历史和证据。

规则：

- 状态名必须来自服务端；
- 不得前端推导完成度；
- 逾期、阻塞、待确认必须文字化；
- 上游未完成不得把下游显示为可操作。

## 2. 页面首屏信息带

每个非纯列表页面必须优先设计一个“结论带”。

推荐结构：

```text
对象身份 / 页面上下文
一句话结论（当前发生了什么）
影响/风险（为什么重要）
唯一主行动（下一步）
更新时间/来源（数据是否可信）
```

如果页面没有结论，说明页面还不该进入视觉设计。

## 3. 筛选与搜索

- 默认展示高频筛选；
- 高级筛选放入“筛选”抽屉或折叠区；
- 搜索必须明确搜索属性；
- 筛选结果必须显示当前条件与清除入口；
- 无结果必须保留筛选条件并给出放宽条件建议；
- 搜索和筛选条件进入 URL/任务上下文；
- 不允许前端在本地对全量业务数据做假分页。

## 4. 表格模式

### 4.1 列设计

优先级：

1. 对象身份；
2. 当前状态；
3. 对决策最重要的金额/数量/时间；
4. 责任人或下一动作；
5. 次要信息和操作。

规则：

- 金额右对齐，数量右对齐，状态和负责人左对齐；
- 长文本列必须定义截断与展开；
- 主要标识列不能因横向滚动完全消失；
- 操作列稳定且不堆叠过多按钮；
- 菜单操作不得隐藏唯一合法的主行动。

### 4.2 行状态

- hover 只做轻微背景变化；
- selected 使用品牌淡色 + 可见边界/勾选；
- disabled 同时降低对比并解释原因；
- 风险行不能用整行红色背景；使用局部状态标记 + 说明；
- 行内动作必须有可访问名称。

## 5. 图表模式

### 5.1 选择流程

1. 先写一句结论；
2. 判断关系：趋势、比较、占比、分布、相关、排名；
3. 再选择图形；
4. 删除非必要网格、背景、图例和标签；
5. 对最重要数据做直接标注；
6. 提供来源、时间范围和口径。

### 5.2 工作台默认图表

- 趋势：折线图，避免面积堆叠；
- 排名：横向条形图；
- 结构占比：环图/堆叠条，类别不超过 5–7；
- 阶段流转：漏斗或阶段轨道；
- 异常：表格/行动队列优先于图表。

## 6. 状态设计

### 正常态

- 结论清楚；
- 主行动可用；
- 数据更新时间可见；
- 关键数字有口径。

### 加载态

- 保持布局稳定的骨架；
- 需要长加载时说明当前阶段；
- 不使用无限旋转作为唯一反馈。

### 空态

必须区分：

- 真实没有业务数据；
- 筛选无结果；
- 尚未创建；
- 数据源不可用；
- 当前角色无权限。

真实空态要给出创建/返回/去处理路径；筛选空态提供清除筛选。

### 失败态

必须包含：

- 简短原因；
- 影响范围；
- 重试；
- 返回或替代路径；
- 保留输入和上下文。

### 无权限态

必须说明：

- 当前角色为什么看不到；
- 谁可以处理；
- 申请/联系路径；
- 不使用“暂无数据”掩盖。

### 长内容

- 标题截断并 Tooltip；
- 长文本分区或展开；
- 长列表分页/虚拟滚动；
- 不使用横向溢出隐藏关键事实。

### 极端值

必须验证：

- null；
- 0；
- 负数；
- 超大金额；
- 百分比 0/100；
- 超长名称；
- 大量条目；
- 缺少单位和时间。

## 7. 交互反馈

- 点击 100ms 内出现按压/加载/选中反馈；
- 保存成功显示影响对象和回读结果；
- 非破坏性动作优先撤销；
- 失败保留输入；
- 同步按钮防重复提交；
- 批量动作先确认范围和数量；
- 高风险动作必须安全门；
- Toast 只用于轻量反馈，不承载关键结果；
- 关键结果进入页面内结果区或持久提示。

## 8. 动效

允许的动效：

- 页面/工作面切换的空间连续；
- 抽屉、菜单、浮层进入退出；
- 行选中、状态变化、保存成功；
- 数据刷新提示；
- 进度变化。

禁止：

- 循环呼吸灯；
- 没有任何状态变化的漂浮；
- 每个卡片独立入场；
- 为了展示而延迟内容；
- 动效替代错误说明；
- 忽略 reduced-motion。

## 9. 可访问性

- 所有交互元素可用键盘访问；
- 焦点可见；
- 弹层焦点陷阱正确，关闭后归还焦点；
- 图标按钮有可读名称；
- 状态不只靠颜色；
- 表格有语义表头；
- 图表有文字摘要；
- 对比度达到 AA；
- 支持减少动效。

## 11. 页面完成定义

- 页面类型和唯一主行动已冻结；
- 首屏满足三秒结论和三层结构；
- 七类状态全部覆盖；
- 交互闭环、失败恢复和任务连续性完成；
- Token、排版、间距、语义色和数字格式合规；
- 键盘、焦点、对比度和 reduced-motion 通过；
- 真实浏览器三档截图已提交；
- App/Web/Admin 同源同口径对账完成。

# 关门准则

## 1. PASS

- 计划范围内所有必测用例已执行；
- P0 全部 `PASS` 且无开放 P0；
- P1 无开放阻断缺陷；
- 每条 `PASS` 有满足等级的证据；
- 页面、Provider、DB/汇总对账完成；
- App/Web/Owner 声明范围完成同源验证；
- 未覆盖项为零或已明确不在计划范围。

## 2. CONDITIONAL_PASS

- 无开放 P0；
- 存在已登记、已由用户或授权主体接受的 P1/P2 残余风险；
- 未覆盖项不影响本次声明的业务结论；
- 报告明确限制和复验时间。

## 3. FAIL

- 任一 P0 失败或开放；
- 核心主链无法完成；
- 核心金额、成本、利润、权限或状态不一致；
- 证据显示页面事实与服务端事实冲突且未解决。

## 4. BLOCKED

- oracle lock、用例、环境、账号、业主身份、授权或关键依赖不可用；
- 无法在本轮结束前得到可判定结果；
- 不能把 `BLOCKED` 计为 `PASS`。

## 5. 报告纪律

必须列明：

```text
执行了什么
没有执行什么
什么通过、什么失败、什么不能确认
证据在哪里
缺陷由谁修复、如何复验
是否满足计划退出条件
```

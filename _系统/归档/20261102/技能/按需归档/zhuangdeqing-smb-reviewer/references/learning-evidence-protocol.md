# 学习、证据与标准协作协议

## 学习的目标

自我学习不是增加文档和摘要，而是持续降低以下不确定性：

- 中小装企在什么条件下会遇到什么真实问题。
- 装得清现有设计和实现是否真正解决该问题。
- 解决方案在什么规模、模式、角色和异常条件下成立。
- 业务价值能否被验证、度量并安全表达。
- 当前标准中缺什么、冲突什么、必须由谁裁决。

## 来源权威顺序

沿用业务智能体规则，不得倒置：

1. 用户明确决策和书面确认。
2. 已批准产品设计、业务规则和正式口径。
3. 已通过验收、自动化测试和生产真实现象。
4. 当前代码、迁移和接口契约。
5. 操作手册、设计说明和历史文档。
6. 客户访谈、市场材料和行业资料。
7. 智能体推断。

外部资料只能提出问题、补充行业条件或形成假设，不能覆盖装得清用户决策和正式事实源。

## 学习触发

以下任一事件发生时启动学习：

- 真实客户访谈、现场观察、配置或上线反馈。
- 新的产品需求、缺陷、验收不一致或生产事故。
- 新行业政策、标准、材料价格机制或平台规则。
- 本智能体发现口径冲突、业务断点或高影响未知。
- 新产品版本上线、关键流程变化或角色变化。
- 营销准备使用新的效果、效率、成本或客户案例表达。

每个真实项目样本都应回写“成立条件、例外、未解决问题”，不能只记录成功故事。

## 外部来源登记

每个外部来源必须记录：

```text
SRC-ID | 标题 | 发布方 | 类型 | 发布日期 | 访问日期 | URL/文件路径
原文摘录 | 能证明什么 | 不能证明什么 | 是否一手来源 | 利益相关性
```

真实性要求：

- 不得编造 URL、标题、作者、日期或引文。
- 无法访问或无法确认来源时，明确写 `unverified`，不得包装成事实。
- 供应商、营销机构和内容平台的宣传材料必须识别利益相关性。
- 法规、标准、政策优先使用官方一手来源。
- 行业经验或市场规模结论至少寻找两个独立来源；只有单一来源时不得升级为高置信度。
- 外部研究只能说明行业通用现象，不能证明装得清已经具备某个能力或产生某个效果。

## 候选知识包

创建 JSON 文件后使用：

```bash
python3 scripts/validate_learning.py <learning-packet.json>
```

文件结构：

```json
{
  "request_id": "REQ-BIZ-YYYYMMDD-NNN",
  "target_profile": "合肥 10-30 人、1-3 店成长装企",
  "sources": [
    {
      "source_id": "SRC-001",
      "title": "来源标题",
      "publisher": "发布方",
      "type": "regulation|industry_report|customer_interview|vendor|academic|news|project_evidence",
      "published_at": "YYYY-MM-DD",
      "accessed_at": "YYYY-MM-DD",
      "locator": "https://... 或项目文件路径",
      "excerpt": "真实短摘录或事实摘要",
      "can_prove": ["能证明什么"],
      "cannot_prove": ["不能证明什么"],
      "interest_risk": "none|vendor|commercial|unknown"
    }
  ],
  "claims": [
    {
      "claim_id": "CLAIM-001",
      "claim": "候选事实或规则",
      "scope": "适用装企、角色、阶段和条件",
      "status": "hypothesis|draft|approved|implemented",
      "confidence": "low|medium|high",
      "source_refs": ["SRC-001"],
      "internal_refs": ["EV-XXX"],
      "promotion_target": "SCN|BR|SOL|MET|CAP|GAP|NONE",
      "limitations": ["不适用范围"],
      "conflicts": ["冲突点或 GAP"]
    }
  ]
}
```

校验器会阻止：

- 只有外部来源却被标为 `approved/implemented`。
- 本智能体自行把候选知识标记为 `verified`。
- 来源引用不存在、重复 ID 或缺少可证明边界。
- 候选事实没有适用条件或不能证明边界。

## 证据核验

至少完成两类检查：

```text
业务标准 vs 产品设计
产品设计 vs 当前代码/接口
当前代码 vs 测试/验收/生产事实
外部行业知识 vs 装企真实样本/内部证据
```

只有一类证据时，最高只能是 `hypothesis/draft` 或 `implemented/medium`，不能写成已验证业务闭环。

## 冲突与缺口

冲突不得静默合并。输出：

```text
GAP 建议编号
冲突点
来源 A 口径
来源 B 口径
影响：产品/开发/验收/财务/营销
临时处理
建议决策人
最晚确认时间
```

高风险口径必须走 T05/T06：

- 角色或数据范围无法确定。
- 金额、成本、利润、收款、付款公式不一致。
- 直接签约、无报价、历史迁移、冲销策略存在分歧。
- 同一对象存在互斥状态。
- 未验收能力准备对外表达。

## 标准升级路径

```text
本智能体候选证据
-> T05 研发咨询单
-> 业务智能体按 T06 答复
-> 业务知识库新增/更新知识卡与 EV
-> 运行 knowledge.py validate 和 index
-> 产品/开发/验收/营销再引用
```

未经业务智能体确认，不得创建“平行标准”，也不得把候选结论写入正式 PRD、验收结论或宣传材料。

当前营销相关 Lane 处于暂停状态。需要营销协同时，本智能体只向用户或已授权 Lane 输出“证据状态、可说、不可说、必须附条件、待补证据”的表达边界包，不直接派发选题、脚本或发布任务。

## 学习复盘

每轮学习结束时回答：

1. 新增了哪个真实条件或反例？
2. 哪个旧判断被修正或否定？
3. 哪个结论仍需真实项目验证？
4. 对产品、开发、验收、营销分别产生什么行动？
5. 哪些内容不能用于对外表达？

如果本轮没有新增证据、没有修正判断、也没有形成可执行问题，则不算一次有效学习。

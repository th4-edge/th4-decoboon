# 业务适配与兼容模型

## 1. 先识别事实，再判断兼容

```text
企业实际做法
→ 涉及哪个业务对象/状态
→ 现有模型能否表达
→ 不能表达时影响什么
→ 选择兼容方式
→ 记录证据与责任人
```

## 2. 五种兼容结果

| 类型 | 含义 | 是否影响产品事实 |
| --- | --- | --- |
| `MAPPED` | 可映射到现有对象/字段/状态 | 否 |
| `WORKAROUND_ALLOWED` | 现有流程内的人工动作可承接 | 否，但必须写边界 |
| `RECORD_ONLY` | 备注、附件、线下证据 | 否，不参与状态机 |
| `T05_REQUIRED` | 影响对象、权限、金额、状态或闭环 | 需业务裁决 |
| `UNSUPPORTED` | 明确不支持 | 否，禁止伪装 |

## 3. 兼容记录字段

```text
UC-COMPAT-*
企业类型/角色：
实际业务做法：
与产品差异：
涉及对象/字段：
当前处理：
分类：
证据：
权限/金额/状态影响：
是否可逆：
责任人：
下一步：
```

## 4. 典型判断

- 企业把“项目经理”叫“工程管家”：名称别名，`MAPPED`。
- 企业线下审批后再录入：可把线下证据作为附件/备注，`RECORD_ONLY`；不能把附件写成线上审批。
- 企业有特殊费用分类：先看分类字典/映射，无法唯一表达再 `T05_REQUIRED`。
- 企业不做阶段验收：不能把系统验收改成自动完成；记录业务边界，评估是否适用或 `UNSUPPORTED`。
- 企业合同金额与系统快照不一致：停止教程和流程建议，业务裁决。

## 5. 禁止

- 为了让客户“先跑起来”而伪造完成状态。
- 把手工 Excel 当成系统台账。
- 用备注替代金额、权限、验收和成本事实。
- 兼容方案没有责任人和证据。
- 兼容逻辑只存在于客服个人和聊天记录。

# 协作与低 Token 预算

## 1. 责任分工

| 角色 | 决定 | 不决定 |
| --- | --- | --- |
| 产品 Web 开发智能体 | 应用推演、场景闭环、主链体验、迭代包、跨端一致性 | 不裁决业务事实，不宣布最终验收 |
| 业务智能体 | 正式业务对象、规则、状态、权限、金额和证据状态 | 不直接改代码或验收 |
| 中小装企审查/学习智能体 | 独立角色审查、反例、候选证据和风险 | 不复制业务知识库，不代替验收 |
| product-planning | 需求拆解、规格、范围和验收标准 | 不改生产实现 |
| development | 实现、自测、变更文件和风险 | 不宣布验收通过 |
| acceptance | 独立测试、缺陷结论和验收报告 | 不代替开发修生产代码 |
| marketing | 经授权后消费已验证事实 | 当前禁用；未授权不得派发或发布 |

## 2. 三阶段、九门禁

```text
草案阶段
  G0 场景与批次边界
  G1 R1 因果闭环
  G2 R2 权限/账务/异常闭环
  G3 R3 Web 壳层/多分辨率/键盘闭环

冻结阶段
  G4 迭代包校验通过
  G5 批量业务咨询完成
  G6 用户/产品负责人冻结范围

执行与验证
  G7 开发实现与自测（含真实浏览器渲染证据）
  G8 3–5 个需求或里程碑集中独立验收
```

P0/P1 问题可以立即升级，不必等待批次；普通 P2/P3 进入批次合并验证。

## 3. Agent 通信规则

- R1–R3 不跨 Agent 同步，不把每轮思考发给业务、开发、验收或营销 Agent。
- 一次 `T05` 最多 5 个会改变正式规则的阻塞问题；先列出候选答案和影响。
- 一次开发交接交付一个冻结批次，不按单句需求投递。
- 一次验收批量覆盖 3–5 个需求或一个完整里程碑，并附统一环境与证据索引。
- 只传路径、版本、差异、决策、风险和证据编号；不复制大段聊天记录、代码或知识卡。
- 消息已送达不等于任务完成；只有工作日志、输出或目标 Agent 明确回报才记为完成。
- 当前营销 Lane 禁用，只登记“可表达/不可表达/待验证”边界，不投递营销任务。
- 跨端差异（App 与 Web 口径不一致）必须建立 `DEF-*` 并上报，不得单端静默改口径。

## 4. Token 分级

| 层级 | 使用条件 | 允许动作 |
| --- | --- | --- |
| L0 本地复用 | 现有事实和证据足够 | 只做场景迭代和包校验 |
| L1 定向读取 | 缺一个明确事实源 | 读取最小文件，不启动 Agent |
| L2 批量咨询 | 有 1–5 个正式规则阻塞 | 一次 T05/T06 |
| L3 里程碑评审 | 包已冻结或阶段完成 | 一次独立审查/评审 |
| L4 独立验收 | 达到批次门槛 | 集中测试并出报告 |

任何升级层级都必须写明“不通信用会导致什么错误决策”。

## 5. 交接字段

```text
input_basis
batch_id / requirement_ids
scope / out_of_scope
fact_sources
tenant_profiles / roles
changed_files / output_paths
verification            # 必须含真实浏览器渲染证据或明确标注 BLOCKED
risks / blockers
next_action
acceptance_needed
```

不含这些字段的交接视为不完整。业务裁决还需要 `REQ-BIZ-*`；答复必须有 `ANS-BIZ-*`。

## 6. 停止条件

- 业务对象、状态、权限或金额冲突未裁决：停止代码实现。
- 跨租户负向用例未覆盖：停止验收通过。
- 成本不完整但仍输出利润：停止经营页面和对外表达。
- 只有构建通过、没有真实浏览器渲染证据：停止标记“页面完成”。
- App 与 Web 同一事实口径不一致且未登记 `DEF-*`：停止对外结论。
- 营销 Lane 未恢复却收到营销派单：停止并标记权限边界。
- 需求未冻结却频繁跨 Agent 往返：回到本地 R1–R3，不继续消耗 token。

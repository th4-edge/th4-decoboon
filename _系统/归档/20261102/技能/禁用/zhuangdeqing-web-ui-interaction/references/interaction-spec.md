# 交互规范（Web）

## 1. 交互四原则

1. **可预测**：同样的元素在任何页面行为一致；不发明新交互模式。
2. **即时反馈**：任何操作必须在 100ms 内给出可见响应。
3. **可恢复**：任何失败都能说清原因并给出下一步；破坏性操作可撤销或有确认。
4. **不阻塞**：局部失败不拖垮整页；长任务不冻结界面。

## 2. 七类状态（缺一不可）

每个页面、每个数据区块都必须设计以下状态，不允许只做"正常态"：

| 状态 | 设计要点 |
| --- | --- |
| 正常 | 数据完整、层级清晰、主行动明确 |
| 加载 | 骨架屏或占位块，尺寸与真实内容一致，避免布局跳动 |
| 失败 | 说明原因 + 重试按钮 + 保留其他已成功区块，文案为"暂不可确认" |
| 真实为空 | 说明业务含义 + 明确的下一步入口，不得只写"暂无数据" |
| 无权限 | 说明属于什么范围、如何申请，不泄露对象细节 |
| 会话过期 | 明确提示并引导重新登录，尽量保留原上下文 |
| 长内容 / 极端值 | 超长中文、超长金额、超大数量、超多列的处理方案 |

补充：大数据量必须有分页或虚拟滚动；慢请求必须有进度或可取消。

## 3. 反馈时序

| 时长 | 用户感受 | 必须有 |
| --- | --- | --- |
| 0–100ms | 即时 | 按钮按下态、选中态、hover 变化 |
| 100ms–1s | 稍等 | 按钮 loading、局部 spinner |
| 1s–10s | 等待 | 进度提示或骨架，明确"正在处理" |
| > 10s | 长任务 | 转后台 + 结果通知，不阻塞界面 |
| 失败 | — | 原因 + 影响范围 + 恢复动作 |

禁止：点击后无任何反馈超过 300ms；重复提交不拦截；成功后无确认反馈。

## 4. 表单交互

- **标签位置**：短表单标签在左（右对齐，宽 80–120px）；长表单标签在上（左对齐）。同一表单不得混用。
- **必填标记**：使用红色星号在标签前/后统一位置；可选字段不标记，必要时写明"选填"。
- **校验时机**：失焦时校验该字段；提交时校验全部；**禁止在用户输入过程中实时报错**（除非是格式即时提示）。
- **错误位置**：紧贴字段下方，12px 字号，危险色；同时给字段加危险边框。禁止只在顶部汇总。
- **分组**：超过 7 个字段必须分组，组标题 14px/600，组间距 ≥ 24px。
- **列宽**：单列表单首列宽度不超过 640px；双列表单每列 ≥ 280px。
- **提交按钮**：放在表单底部左侧或右下角，位置在整个系统内一致；提交中禁用并显示 loading。
- **敏感字段**：脱敏值不得回填到输入框；留空表示保持原值，需在界面上说明。
- **离开确认**：有未保存修改时离开必须提示。

## 5. 表格交互

- 表头固定；行高 40–44px；斑马纹仅在列数 > 8 时使用。
- 列策略：核心列（对象名、状态、金额、下一步）必须常显；次要列在 1280 以下隐藏或折叠。
- 长文本列设置最大宽度并省略，鼠标悬停显示完整内容。
- 数字列右对齐、等宽数字；状态列使用 `StatusTag`；操作列固定在右侧。
- 排序：可排序列表头必须有方向图标，且明确是服务端排序还是前端排序。
- 筛选：筛选项超过 3 个时收进"筛选"抽屉；必须有"已选条件"回显与一键清除。
- 分页：默认 20 条；必须显示总数与当前范围；切换筛选后回到第 1 页。
- 批量选择：表头全选 + 行选择；选中后出现批量操作条，显示"已选 N 项"。
- 空态：区分"无数据"与"筛选无结果"，后者必须提供清除筛选入口。

## 6. 抽屉、模态与页面

| 场景 | 选择 | 尺寸 |
| --- | --- | --- |
| 单职责动作（确认、快速编辑、审批） | 抽屉 | 宽 400–480px |
| 中等表单（≤ 12 字段） | 抽屉 | 宽 560–720px |
| 复杂编辑、多步骤、需要上下文 | 独立页面 | 整页 |
| 破坏性确认、强阻塞决策 | 模态 | 宽 400–480px |
| 对象查看（不离开当前列表） | 抽屉 | 宽 640–840px |

规则：

- 抽屉只承载**单职责**动作，禁止把完整业务页面塞进抽屉。
- 抽屉必须有标题、关闭按钮、`Esc` 关闭、点击遮罩行为明确（表单类不关闭）。
- 抽屉打开时焦点移入，关闭后焦点归还触发元素。
- 模态最多用于确认；禁止模态套模态。
- 抽屉宽度不得超过视口的 80%。

## 7. 破坏性操作分级

| 级别 | 例子 | 处理 |
| --- | --- | --- |
| 低 | 移除单个标签、取消选择 | 直接执行 + 可撤销提示 |
| 中 | 删除单条记录、停用配置 | 二次确认（说明影响） |
| 高 | 批量删除、批量改价、权限变更、收款/付款、验收确认、签约 | 二次确认 + 影响范围 + 输入确认词或强提示 + 审计留痕 |

规则：

- 破坏性按钮不得使用品牌主色，使用危险色或次要样式。
- 确认弹窗必须说明"会发生什么"，不是只问"确定吗"。
- 批量操作必须显示影响数量与范围。

## 8. 键盘与焦点

- `Tab` 顺序必须符合视觉顺序。
- `Esc` 关闭当前浮层；`Enter` 提交当前表单（多行输入除外）。
- 快捷键（可选，但必须成体系）：`/` 聚焦搜索、`Esc` 关闭浮层、`Ctrl/Cmd + Enter` 提交。
- 焦点必须可见（`:focus-visible`）；**禁止 `outline: none`**。
- 焦点陷阱只用于模态与抽屉；关闭后必须归还焦点。

## 9. 动效

| 场景 | 时长 | 缓动 |
| --- | --- | --- |
| hover / 按下 | 120ms | `cubic-bezier(.4,0,.2,1)` |
| 抽屉、弹层进出 | 200ms | 同上 |
| 数据刷新 | 150–200ms | 同上 |

规则：

- 禁止 `transition: all`；必须写明确属性。
- 禁止超过 300ms 的装饰动画。
- 禁止弹跳、旋转、缩放等娱乐化动效。
- 必须尊重 `prefers-reduced-motion: reduce`。

## 10. 提示与通知选择

| 类型 | 使用场景 |
| --- | --- |
| 行内提示 | 字段级错误、区块级说明，紧贴相关内容 |
| 轻提示 toast/message | 操作成功、低风险失败的即时反馈 |
| 通知条 alert | 需要持续可见的警告或系统状态 |
| 模态 | 必须打断用户的决策或确认 |
| 页面级错误 | 整个页面不可用时 |

规则：

- 成功提示 2–3 秒自动消失；错误提示不自动消失或延长至 5 秒以上。
- 同一时刻只允许一个全局通知；连续操作合并提示。
- 禁止用 toast 承载需要用户决策的信息。

## 11. 加载与骨架

- 首屏加载用骨架屏，形状与最终内容一致。
- 局部刷新用区块级 loading，不阻塞整页。
- 按钮 loading 期间禁用重复点击。
- 禁止全屏遮罩 loading（除登录、初始化等确实全页阻塞场景）。

## 12. 错误与恢复

错误文案必须回答四件事：

```text
发生了什么？（如"客户列表加载失败"）
为什么？（如"当前网络不可用"或"服务暂时不可用"）
怎么恢复？（如"重试"按钮）
还有什么可用？（如"其他区块仍可查看"）
```

禁止：

- 只显示"操作失败"、"系统错误"、"网络异常"等无信息量文案。
- 把加载失败显示成空数据。
- 把权限拒绝显示成"无数据"。
- 用一个全局错误覆盖其他已成功加载的内容。

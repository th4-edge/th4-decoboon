## 已确认教训

### LESSON-001 可完成型引导必须绑定真实状态并覆盖返回刷新

- 日期：2026-09-18
- 来源：`REQ-20260918-ONBOARDING-DEFECT-001`、`FIX-004`、`ECD-008`
- 教训：界面上的“完成”不是文案或占位状态，而是业务对象事实在页面上的投影。任何引导、进度、待办或节点完成状态，都必须明确来源、完成谓词、必做/可选口径和刷新触发条件。
- 本次根因：
  - 供应商步骤写死 `done: false`；
  - 引导只在首次挂载时取数，返回首页不刷新；
  - 方案验收只检查卡片存在，没有检查“动作后状态收敛”。
- 流程反思：产品和验收讨论了“显示什么”，开发实现了“页面能打开”，但没有共同冻结“什么事实使状态改变”以及“用户回到页面后如何看到改变”。
- 防复发规则：
  1. 任何可完成状态必须有真实领域数据来源，禁止静态占位布尔值。
  2. 必做与可选必须在分母、文案、下一步和测试中一致。
  3. 状态依赖的页面重新显示时必须刷新，或通过写入失效机制保证收敛。
  4. 验收必须至少覆盖：初始未完成、动作成功返回、动作失败、可选完成、重复进入。
- 适用范围：首次入驻、实施清单、任务进度、资料完整度、节点完成度、审批进度、质量检查清单。

## 候选教训

- **候选 LESSON-002 工作台动作隔离**
  - 现象：量房工作台点击“录入量房”后，将完整 `MeasurementWorkbenchView` 放入抽屉，用户仍然看到原管理页和二次操作。
  - 根因：把“复用现有功能”误当成“满足工作台交互”，没有按已冻结的动作职责重新设计单职责表单。
  - 防复发：工作台动作必须是一动作一抽屉；禁止引用完整业务页面组件；完成前必须核对动作字段、入口上下文、保存结果和返回状态。

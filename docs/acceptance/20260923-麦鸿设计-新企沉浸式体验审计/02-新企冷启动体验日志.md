# 新企冷启动体验日志

## 体验总览

以一个刚完成企业注册、第一次进入麦鸿设计工作台的新用户视角，希望先确认“我在哪个企业、我是什么角色、今天先做什么”。

## S01-onboarding-001 登录页

- 页面：`pages/auth/login`
- 第一印象：品牌、平台定位和微信登录入口清晰；“项目经营 / 现场留证 / 验收闭环”三个价值点可见。
- 观察到：页面没有账号密码入口，普通员工和业主都统一走微信身份。
- 结论：可理解，但实际微信登录依赖开发者工具登录态、授权手机号和后端 `code2session`。本次用开发令牌进入，真实微信授权未验证。

## S01-onboarding-002 创建企业

- 页面：`pages/auth/enterprise`
- 页面内容：负责人姓名、企业全称、企业简称、门店名称、企业地址。
- 判断：注册字段少，适合快速开始；但没有提示企业地址是否可后补，也没有显示“创建后先配置什么”。
- 结论：`PARTIAL`。页面可见，未能用独立新微信身份完成真实注册。

## S01-onboarding-003 企业信息与成员

- 页面：`subpackages/company/pages/info`、`members`
- 页面观察到：企业名为麦鸿设计，但企业地址为空；7 名员工均显示“未分配团队”。
- 价值判断：企业/门店/岗位字段有明确展示，成员管理具备交接、停用、注销入口。
- 疑惑：一个刚入驻企业如果没有团队体系，是否需要强制分配团队；页面只显示“未分配团队”，没有解释这对权限、客户或项目有没有影响。
- 结论：`PASS` 可见，`DOC_GAP` 存在。

## S01-onboarding-004 邀请员工

- 页面：`subpackages/company/pages/invite`
- 页面内容：姓名、手机号、默认门店、岗位、生成邀请。
- 价值判断：能把岗位和归属一起约束，比只发一个群二维码更有治理能力。
- 未测：未实际生成或发送邀请。
- 结论：`NOT_TESTED` 写入与接手流程。

## S01-onboarding-005 邀请业主

- 页面：`subpackages/project/pages/invite`
- 页面内容：说明业主仅可见本项目进度、动态与验收，并列明“生成邀请 → 微信授权手机号 → 我的家 → 阶段验收确认”的四步闭环。
- 价值判断：权限边界和业主价值表达清楚，适合作为一线员工向业主解释的材料。
- 未测：未生成邀请、未发送、未用独立业主微信进入。

## S01-onboarding-006 无 token 打开接受页

- 页面：`pages/invite/accept`
- 实际结果：页面长期显示“正在加载邀请…”，没有提示缺少 token、无效邀请、过期邀请或返回入口。
- 结论：`FAIL`，见 `XA-20260923-004`。

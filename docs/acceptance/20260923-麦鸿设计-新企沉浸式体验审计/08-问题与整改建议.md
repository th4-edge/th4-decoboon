## XA-20260923-001 业务员后续业务可见性断裂

- 最小复现：以黄贤杰进入客户 `程曦（演示41）` 的业务流转页。
- 期望：页面文案承诺“业务员只读查看后续推进”，应看到设计与项目状态。
- 实际：报价 3 份、合同 1 份可见；设计方案 0、项目与工地 0。
- Provider 核验：业务员对同一客户的设计和项目分页均返回 0，报价返回 3。
- 影响：业务员无法确认设计和项目是否已推进，仍可能依赖微信群或线下询问，削弱销售到履约的协同价值。
- 建议：明确业务员对设计和项目的只读数据范围；若业务上允许查看，修正服务端可见性；若不允许，修改页面文案和入口，避免承诺与实际不符。
- 正向验收：业务员能看到本客户已转项目的设计和项目，且只读无编辑入口。
- 反向验收：业务员不能看到其他客户或其他企业项目。
- 责任建议：业务规则裁决 + 后端数据范围修复 + App 文案/入口同步。

## XA-20260923-002 设计师被客户详情 404 阻断设计列表

- 最小复现：以谢玲玲打开客户 `程曦（演示41）` 的主房设计列表。
- 期望：显示 1 条诉求、1 个设计和区域/分项。
- 实际：页面显示诉求 0、方案 0，客户为 `—`、待量房。
- Provider 核验：`design/scheme/page` 返回 1、`quote/designer/page` 返回 3、`project/project/page` 返回 1，但 `customer/customer/info` 返回 404。
- 根因线索：设计列表页把客户、诉求、方案、报价、项目、房屋并列放入一个 `Promise.all`，任一失败后没有设置任何列表数据，最终落到空状态。
- 影响：设计师无法从正常客户入口进入已存在的方案和报价，直接影响设计到报价的主工作流。
- 建议：先修复设计师访问其负责客户详情的服务端数据范围；同时将列表页改为分区加载或使用 `allSettled`，明确区分“无数据”和“加载失败”。
- 正向验收：设计师负责客户的详情可读，设计列表显示已有设计。
- 反向验收：设计师不能访问非本人负责、非参与项目的客户。
- 责任建议：业务规则确认 + 后端权限修复 + App 错误态改造。

## XA-20260923-003 项目状态“竣工验收”与当前阶段矛盾

- 最小复现：项目列表或项目经理首页打开“麦鸿演示项目 41”。
- 期望：当前处于开工交底阶段、等待阶段验收时，项目状态应显示“待验收”或“阶段待验收”。
- 实际：项目状态显示“竣工验收”，同一卡片又显示当前阶段“开工交底 0%”，项目详情显示“阶段 0/8”。
- 影响：负责人和项目经理可能误以为项目已到最终竣工验收，影响任务判断和外部沟通。
- 建议：区分“项目级最终竣工验收”和“施工阶段验收”；`Accepting` 统一显示“待验收/阶段待验收”，只有最终完工验收才使用“竣工验收”，或改为“待验收（当前阶段：开工交底）”。
- 正向验收：首阶段待验收显示阶段语义，最终竣工阶段才显示竣工验收。
- 反向验收：项目状态和当前阶段不得同时表达相互矛盾的含义。
- 责任建议：业务口径确认 + App 状态映射修复 + 报表文案统一。

## XA-20260923-004 邀请接受页缺少无效 token 处理

- 最小复现：不携带邀请 token 打开 `pages/invite/accept`。
- 期望：提示“邀请参数缺失/已失效，请联系邀请人”，并提供返回入口。
- 实际：长期显示“正在加载邀请…”。
- 影响：员工不知道是网络慢、邀请坏了还是自己操作错误，无法自助恢复。
- 建议：在 `onLoad` 对缺失 token、无效 token、过期 token 分别提供明确错误态和返回/重试入口。
- 正向验收：无 token 立即提示并返回；有效 token 正常显示邀请信息。
- 反向验收：无效 token 不进入企业；过期 token 不重复使用。

## XA-20260923-005 入驻基础配置缺少状态地图

- 现象：企业地址为空、所有员工未分配团队，页面没有明确提示这些配置是否阻断业务。
- 影响：新企业完成账号创建后不知道还要配置哪些组织与业务基础数据。
- 建议：在负责人首页或企业设置增加“入驻就绪清单”：企业资料、门店、成员、角色、团队/负责人、报价库、付款/施工计划模板。每项显示是否影响业务和下一步入口。
- 正向验收：新负责人能按清单完成基础配置，不需要实施人员口述。
- 反向验收：不强制所有企业建立团队，若团队非必需，应明确显示“可选”。

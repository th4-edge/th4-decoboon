# 企业协同价值评估

| 维度 | 结论 | 置信度 | 证据 |
|---|---|---|---|
| V1 一次录入、全链复用 | PASS。客户、房屋、设计、报价、合同、项目、材料、财务能沿同一对象链传递 | 高 | 计数与金额对账 |
| V2 跨角色协同与交接 | PASS/ PARTIAL。业务员到店长、设计师、PM、财务链路可见；业主会话缺失 | 中高 | 角色页面和交接记录 |
| V3 责任与状态闭环 | PARTIAL。阶段和验收状态可追踪，但默认任务负责人错误 | 高 | PM 截图、DB |
| V4 经营控制力 | PASS。Boss/店长/财务/设计师/PM 指标可互相对平；成本不完整时 Boss 毛利为空 | 高 | 角色统计 JSON |
| V5 业主协同体验 | NOT_TESTED/BLOCKED。只能确认接口模拟数据和员工页只读呈现 | 高 | 环境与接口检查 |
| V6 新企业上手与效率 | PARTIAL。报价库初始化存在脚本缺陷；菜单和引导整体可理解 | 中 | 导入日志、角色截图 |
| V7 数据范围、安全与可追溯 | FAIL。设计师/PM 数据隔离有效，但业务员可直接调用设计新增接口 | 高 | negative-permission-checks.json |

## 综合判断

- 真正有效：客户档案、设计报价、项目履约、选材采购、应收应付之间的对象关系基本连续，角色看板不是纯展示壳。
- 最大风险：服务端角色权限比页面权限弱，业务员可越过产品功能边界写入设计数据。
- 第二风险：默认施工任务把“经营 owner/房屋负责人”当成“任务负责人”，造成 PM 工作台上的责任人错误。
- 尚不能证明：业主端真实确认体验、真机媒体上传、弱网恢复、跨门店边界。

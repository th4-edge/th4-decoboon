## 3. 页面观察

当前测试项目关键数据：

```text
当前合同金额：128000 元
客户未收工程款：100000 元
当前未付款：42000 元
接管前已发生成本：120000 元
```

提交前核对弹窗正确展示：

```text
当前合同金额：128000 元
客户未收工程款：100000 元
当前未付款：42000 元
接管前已发生成本：120000 元
成本状态：只知道总额
```

并明确提示：

> 请确认以上是接管日尚未结清的余额和已发生成本，不是历史累计收款、历史累计付款或未来预算。

## 4. 本次确认到的改进效果

- 用户不需要理解“应收未收”这个专业字段，页面直接使用“客户未收工程款”，并列出尾款、客户欠款等叫法；
- 用户可以按公式填写，不再容易把累计已收误填成未收余额；
- “接管前已发生成本”明确说明包含已付和未付，并专门说明不等于当前未付款；
- 无余额可以一键明确为 0，不会因为留空造成“待确认”；
- 金额明显冲突时页面立即警告，而不是提交后才失败；
- 提交前统一展示四项金额和成本状态，减少误提交。

## 5. 问题

### XA-20260926-001 项目状态枚举映射错误（已修复）

- 用户看到：承接项目列表持续提示“待补齐：项目状态”。
- 根因：小程序发送 `ongoing`，后端枚举值为 `Ongoing`，保存时未完成映射。
- 修复：`carryoverApi.save` 增加项目状态和成本状态映射。
- 修复结果：本地记录 `229350346068066304` 已保存为 `Ongoing`，并生成来源为 `Carryover` 的正式项目 `229353590450290688`。
- 严重度：P1。
- 状态：已修复，待 acceptance 复核。

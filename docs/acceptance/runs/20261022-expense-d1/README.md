## 1. 验收范围

- 费用分类初始化与启用状态；
- 企业费用/员工报销草稿；
- 附件上传、版本冻结、提交、撤回、退回、重提、拒绝、审批；
- 项目/企业归属；未归属门店仅 BOSS/总部财务；
- BOSS/店长/总部财务/门店财务/普通员工数据范围；
- App/Web 同对象、同状态、同金额和同异常恢复；
- D1 不得产生应付、付款、流水或凭证。

## 2. 环境与数据

- 环境：隔离测试库或本地 H2/MySQL 测试库；不得直接使用生产真实员工和财务数据。
- 企业 A：默认总店 + 普通门店；BOSS、店长、总部财务、门店财务、普通员工各至少 1 人。
- 企业 B：BOSS + 普通员工，用于跨租户。
- 项目：企业 A 本店项目 1 个，项目 owner/manager 为测试普通员工或店长。
- 费用分类：至少 1 个内置启用分类和 1 个停用分类。

## 3. 角色与身份

| 角色 | 主要验收动作 |
| --- | --- |
| 普通员工 | 创建本人草稿、附件、提交、撤回、退回重提、查看本人 |
| BOSS | 全企业查看、审批、退回、拒绝、一人企业自审 |
| 店长 | 本店查看、审批、退回、拒绝；不得自批本人报销 |
| 总部财务 | 全企业查看、票据复核退回、不得业务审批、不得自付 |
| 门店财务 | 本店查看、复核退回、不得跨店、不得业务审批 |
| 企业 B 员工 | 不得读取或操作企业 A 费用 |

## 4. 验收步骤

### ACC-EXP-01 内置分类与停用校验

1. 普通员工打开费用分类；
2. 检查分类自动初始化、名称、说明、排序；
3. 新建费用选择停用分类。

期望：内置分类幂等补齐；停用分类不可选/提交被拒；历史分类仍可回读。

### ACC-EXP-02 员工报销闭环

1. 普通员工创建 `Reimbursement` 草稿；
2. 上传发票/收据附件；
3. 提交；
4. 店长审批通过；
5. 再次读取详情。

期望：状态 `Submitted → Approved`；版本=1；附件、提交人、归属员工和审批人可追溯；D1 无应付/付款/流水/凭证。

### ACC-EXP-03 退回重提版本

1. 员工提交；
2. BOSS 或财务退回并填写原因；
3. 员工修改附件后重提；
4. 读取版本历史/详情。

期望：状态 `Submitted → Returned → Submitted`；版本=2；旧版本快照保留；审批意见为退回原因。

### ACC-EXP-04 店长本人报销防自批

1. 店长提交本人报销；
2. 店长尝试审批。

期望：审批被拒；BOSS 审批成功后 `selfApproved=false`。

### ACC-EXP-05 财务复核权限

1. 普通员工提交；
2. 财务退回；
3. 员工重提；
4. 财务尝试审批；
5. 财务提交本人报销并尝试退回/付款。

期望：财务可退回补充；不可业务审批；不可退回自己的费用；D1 不涉及付款。

### ACC-EXP-06 项目/企业归属

1. 项目费用选择项目；
2. 企业费用清空项目；
3. 提交后尝试改项目；
4. BOSS/总部财务尝试 `storeId=0` 未归属门店；
5. 店长/门店财务/普通员工尝试 `storeId=0`。

期望：项目费用取项目门店；企业费用不进入项目成本；提交后归属不可改；未归属门店仅企业范围可提交。

### ACC-EXP-07 附件与草稿边界

1. 创建无附件草稿；
2. 直接提交；
3. 补充附件后提交；
4. 上传失败/重复提交。

期望：草稿允许无附件；提交必须至少一份证据；重复提交幂等；失败显示“暂不可确认”。

### ACC-EXP-08 数据范围与跨端

1. 普通员工 A 提交；
2. 普通员工 B/其他门店/其他企业读取；
3. App/Web 分别打开列表、详情、审批；
4. 断网或接口失败重试。

期望：越权 403/404；App/Web 同状态、同金额、同动作和同下一步；失败不显示本地成功。

## 5. 阻断条件

- D1 生成 `Payable`、`Payment`、`Ledger` 或 `VoucherRecord`；
- 财务可审批或给自己付款；
- 店长可自批本人报销；
- 提交后仍可改金额/归属/附件；
- 仅一端可完成强制动作；
- 跨企业/跨店可读取；
- 真实页面或独立验收证据缺失。

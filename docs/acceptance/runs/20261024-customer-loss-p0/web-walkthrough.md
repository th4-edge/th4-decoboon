# 客户流失 Web 真实页面走查

日期：2026-10-24  
环境：本地 dev API `8091` + 独立 Web Vite `8082`  
身份：张伟 / Designer / 安徽昭青网络科技  
数据：临时客户“流失验收客户”及两套房屋，走查后已完整清理

## 走查结果

| 步骤 | 操作 | 期望 | 实际 | 结论 |
| --- | --- | --- | --- | --- |
| W-01 | 待我量房选择房屋B，打开“标记流失” | 抽屉展示范围、阶段、原因 | 范围默认本次房屋，阶段默认待我量房 | PASS |
| W-02 | 选择“选择了其他装修公司”并确认 | 房屋B退出队列，房屋A保留 | 临时客户仅剩房屋A，页面显示“部分房屋已流失” | PASS |
| W-03 | 再选择房屋A并标记流失 | 客户整体流失，退出全部活跃队列 | 临时客户两套房屋全部消失，待量房仅剩其他客户 | PASS |
| W-04 | 打开“我的客户” | 客户仍可在已流失阶段查询 | 已流失计数1，客户卡片显示“已流失/查看流失原因” | PASS |
| W-05 | 打开客户360 | 流失阶段、原因、房屋和操作人可见 | 显示“待我量房 / 选择了其他装修公司 / 验收小区A / 张伟” | PASS |
| W-06 | 恢复最新流失记录 | 仍有其他房屋流失时客户保持Lost | 页面继续显示已流失，并切换到剩余房屋的流失信息 | PASS |
| W-07 | 恢复最后一条流失记录 | 抽屉关闭，客户恢复到待首联 | 页面显示待首联、标记流失入口，恢复抽屉未复开 | PASS |
| W-08 | 返回待量房 | 两套房屋重新进入队列 | 两套房屋均重新显示 | PASS |

## 截图证据

- `web-partial-loss.png`：单房流失后客户仍活跃，页面显示部分房屋已流失。
- `web-whole-loss-removed.png`：客户整体流失后退出待量房队列。
- `web-restored.png`：恢复后客户回到待首联，恢复抽屉已关闭。

## 发现并修复

- 修复 `CustomerHeroCard` 中流失抽屉被放入默认插槽、实际未渲染的问题；已移至 `ObjectHeroCard` 外。
- 修复恢复成功后父页面立即刷新导致抽屉内容从“恢复”切换为“标记流失”的瞬态问题；抽屉现固定本次打开模式，并先关闭再通知父页面刷新。
- 客户360补充“标记流失/恢复客户”入口。

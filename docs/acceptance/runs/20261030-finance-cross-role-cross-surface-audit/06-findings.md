## 阻断问题

### 1. App 财务汇总伪 0

同一条应收记录在列表中真实存在，但 App 顶部显示应收、已收、待收、逾期均为 0。收款和付款页同样出现“列表有 18/19 笔，顶部为 0 笔”。这直接违反 `BR-055` 的失败态规则。

### 2. 台账来源不守恒

- 有效收款：18 笔，¥13,477.14。
- 收款台账：¥14,225.87；同一收款 `235520577220116480` 对应 2 条台账，多 ¥748.73。
- 业务付款：19 笔，¥9,500。
- 付款台账：¥9,000；付款 `999200000000000907` 缺台账，少 ¥500。
- 台账净现金流 ¥-14,574.13；按有效收付款 + 手工支出的期望值 ¥-15,822.86；偏差 +¥1,248.73。

该项属于数据/幂等或历史修复缺口。当前不能宣称“财务台账准确”。

### 3. 手工应收/应付类型违反业务规则

`BR-055` 规定手工应收只允许“其他应收”，手工应付只允许“其他应付/费用支出”。当前 Web 和 App 都暴露首期款、进度款、尾款、质保金、材料款、工资、项目款、供应商款等类型；对应后端 Save 也未见手工来源类型校验。该问题是业务事实生成门禁缺口，不只是文案问题。

### 4. 失败态仍显示 0

项目账本、费用、凭证页面在接口失败时仍显示 `0`；错误码为 `undefinedErrorCode`，页面没有说明数据不可确认的原因。Web/App 对失败态的表达也不一致。

### 5. 页面能力表达不一致

- Web 在已收清应收上仍显示“登记收款”，App 隐藏。
- 店长菜单写“资金台账（只读）”，页面却有写动作。
- Boss 访问 `/finance/quotes` 被 403，Finance 可访问；需确认 Boss 的报价项目库主入口。

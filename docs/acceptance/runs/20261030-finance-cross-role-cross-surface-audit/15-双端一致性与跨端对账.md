## 3. 根因证据

- App：`src/subpackages/finance/pages/receivables.vue:53-70`、`receipts.vue:38-46`、`payments.vue:46-54` 使用 `financeApi.summary()` 的财务首页汇总字段；Web 对应页面使用应收/收款/付款部门报告。
- Web：`FinanceReceivablesView.vue:229` 只按 `canWrite` 展示“登记收款”，未判断 `outstandingAmount > 0`。
- App：`receivables.vue` 仅在 `item.outstandingAmount > 0` 时显示“登记收款”。
- `BR-055 §4`：接口失败显示暂不可确认，不得用 0、空数组或旧值伪装成功；App/Web 同角色能力必须一致。

## 4. 跨端效率结论

| 工作 | 更适合端 | 证据 |
| --- | --- | --- |
| 收付款对账、批量筛选、全公司下钻 | Web | Web 可一次呈现 73 笔与四维汇总 |
| 现场快速查看本店流水 | App | App 可按本店加载 20 笔台账 |
| 手工应收/应付录入 | 当前两端均不成立 | 类型门禁违反 `BR-055`，先修复再评效率 |
| 项目成本核算 | Web | App 只适合摘要，当前预算/项目页均因环境阻断 |

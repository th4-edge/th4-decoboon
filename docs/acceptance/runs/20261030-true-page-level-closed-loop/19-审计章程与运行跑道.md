# 审计章程与运行跑道

## 核心目标

证明昭青科技的一名真实岗位人员，能否只用 Web 或小程序当前可见的页面操作，把一条装修项目从客户建档推进到项目、材料、施工、验收和财务闭环，并在角色交接后保持同状态、同金额、同成本和同权限。

## 页面动作硬门禁

1. 新客户必须从页面“新增客户”进入。
2. 房屋、量房、设计、报价、合同、项目、材料、施工、验收、收付必须由页面按钮或页面表单推进。
3. Provider/API/DB 只做回查，不用于创建或补终态。
4. 页面未提供入口、提交失败或前置阻断时，记录缺陷并停止该分支。
5. 每次提交后刷新并重新读取页面；不以点击动作或成功 toast 代替回读。
6. 角色切换必须使用对应账号并核验企业、门店、角色。
7. 业主确认不能由员工或 AI 代替。

## 本轮业务主线

```text
Boss/业务员：客户建档 → 房屋 → 跟进/预约量房
→ Designer：完成量房 → 方案 → 报价提交/客户决策登记
→ Boss：合同签署/生效 → 项目生成
→ Designer：主材选材并交付
→ Finance：材料下单 → 应付 → 付款
→ PM：到货/施工任务 → 日报/节点留证
→ PM：阶段验收提交
→ 业主：确认/驳回（真实身份页面）
→ Finance：收款/付款 → 台账 → 项目结算
→ Boss/店长：跨端回读与经营对账
```

## 停止条件

- 任何一步只能靠接口/数据库才能继续；
- 正常角色看不到应有入口；
- 金额、状态、合同快照、成本或权限出现不可解释差异；
- 需要真实外发、支付、电子签或真实业主身份；
- 出现跨租户、越权或数据破坏风险。

## 结论边界

只有页面端到端、角色交接、金额/状态/权限三方对账、负向门禁、幂等/并发和顺序扰动均通过，才可标记 `COMPLETED`。否则按事实标 `PARTIAL`、`BLOCKED` 或 `NOT_TESTED`。

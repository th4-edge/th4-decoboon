## 1. 审计目标

对比套餐报价与自定义设计报价从报价草稿到项目创建的完整业务链，确认：

- 金额、成本、折扣和税金是否一致；
- 客户接受、合同签约、合同生效和项目创建门禁是否成立；
- 合同行、项目任务、材料计划和应收是否完整承接报价范围；
- App 页面是否准确表达报价结构和下游事实。

## 3. 正向主链结果

两条报价均实际执行：

```text
报价草稿/已提交
→ 客户接受
→ 合同待签约
→ 合同已签约
→ 合同已生效
→ 自动创建唯一项目
→ 生成付款计划、施工阶段、任务/材料计划和应收
```

| 核对项 | 套餐报价 | 自定义报价 | 结论 |
| --- | --- | --- | --- |
| 报价金额 | 11,340.00 | 15,103.75 | 一致进入合同 |
| 报价成本 | 106.80 | 10,109.00 | 一致进入项目成本 |
| 成本状态 | 成本完整 | 成本完整 | 通过 |
| 合同当前金额 | 11,340.00 | 15,103.75 | 与报价一致 |
| 项目合同金额 | 11,340.00 | 15,103.75 | 与合同一致 |
| 项目成本 | 106.80 | 10,109.00 | 与报价一致 |
| 应收金额 | 11,340.00 | 15,103.75 | 与合同一致 |
| 付款节点 | 3 | 3 | 一致 |
| 施工阶段 | 8 | 8 | 一致 |
| 合同行数 | 4 | 6 | 按报价生成 |
| 项目任务数 | 4 | 3 | 仅施工行生成任务 |
| 材料计划数 | 0 | 1 | 仅主材行生成材料计划 |

结论：**报价 → 客户接受 → 合同 → 合同生效 → 项目**状态主链可通过。

## 4. 缺陷与断点

### P0-01 定制、综合等项目未进入履约执行

自定义报价包含：

| 类型 | 行数 | 销售金额 | 成本 |
| --- | ---: | ---: | ---: |
| 施工 | 3 | 1,821.60 | 1,269.00 |
| 主材 | 1 | 5,040.00 | 3,600.00 |
| 定制 | 1 | 8,160.00 | 5,160.00 |
| 综合 | 1 | 120.00 | 80.00 |

实际项目只生成：

- 3 条施工任务，成本 1,269.00；
- 1 条主材材料计划，成本 3,600.00；
- 定制 5,160.00 和综合 80.00 **没有任务、材料计划、交付计划或安装/制造对象**。

即项目签约成本 10,109.00 中，有 **5,240.00（约 51.8%）没有进入履约执行对象**。同时 `安装收尾`、`竣工保洁验收` 被自动判定为“本项不涉及”，项目可以在定制和综合项目没有执行载体的情况下继续推进。

代码根因：`ProjectContext` 在生成任务/材料计划时只处理 `Construction` 和 `Material`，其余四种类型被忽略。

### P1-02 套餐报价把面积折算误显示为“调整增减”

套餐标准面积 100㎡、套餐牌价 10,000，客户计价面积 120㎡，没有扣减、升级、替换或增项。

正确套餐基准金额：

```text
10,000 × 120 / 100 = 12,000
```

但 App 显示：

```text
套餐基准价 1万
调整增减 +¥2,000
```

该 +2,000 实际只是面积比例从 1.0 变成 1.2，不是客户调整。  
根因：前端用 `报价分项合计 - 套餐标准面积牌价` 计算调整额，没有使用“面积折算后的套餐基准金额”。

### P1-03 自定义报价面积为 0，但房屋和项目面积为 110㎡

- 自定义报价接口返回 `area=0.00`；
- App 报价详情显示 `0㎡`；
- 同一房屋面积为 110㎡；
- 创建后的项目面积为 110㎡。

根因：自定义报价直接复制 `Design.area`，而完成方案校验允许无区域方案保留已有面积 0；没有回退到房屋实测面积或阻断生成。

### P1-04 合同明细分组合计与合同当前金额缺少折前/折后解释

- 套餐合同明细合计 12,000.00，合同当前金额 11,340.00；
- 自定义合同明细合计 15,141.60，合同当前金额 15,103.75。

差异来自折扣和税金，但合同页把明细合计直接显示为“合同范围合计”，没有同时显示“折前合计、优惠、税金、合同金额”的勾稽关系，容易被理解为金额对不上。

### P2-05 合同履约事实暴露内部报价/合同编号

合同页的签约依据事实节点显示 `Q1793529627095`、`C1793607048785` 等内部编号，不符合 `DEC-095`“业务界面不展示系统内部编号”的要求。

### P2-06 套餐无设计方案被表达成“来源事实暂不可确认”

套餐报价合法地没有设计方案来源，但合同页显示“无设计方案来源”后仍出现“来源事实暂不可确认”。应明确表达为“套餐报价，无设计方案来源”，不能与来源缺失/未知混淆。

## 5. 边界门禁结果

| 反向场景 | 实际结果 | 结论 |
| --- | --- | --- |
| 使用历史套餐版本新建报价 | 409：该套餐不是当前发布版本 | PASS |

## 7. 结论

- `报价 → 合同 → 项目`状态主链：**可运行**。
- 报价、合同、项目之间的金额和成本快照：**基础一致**。
- 非施工/主材履约闭环：**未闭环，P0 阻断**。
- 套餐报价调整额展示：**错误，P1**。
- 自定义报价面积：**不一致，P1**。
- 合同金额勾稽和内部编号展示：**待优化，P1/P2**。

当前不得判定为“业务通过”或“可交付客户使用”。

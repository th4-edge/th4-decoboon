### 2.4 旧库增量升级完整性

`10-设计转化域迁移.sql` 仍写着：

> 新增列和表由 Hibernate ddl-auto=update 自动补齐；生产环境若关闭自动建表，请使用 schema diff 导出以下对象后再发布。

生产配置强制 `ddl-auto=validate`。该迁移只明确修改了 3 个列，未在版本化脚本中创建所需的 design 表、报价列、任务列和材料计划列。

结论：空库基线可支持新库，但旧库增量升级仍不完整，**FAIL**。

## 3. 安全回滚模板复核

`rollback-safe.sh.template` 检查结果：

- 使用 `set -Eeuo pipefail`。
- 必需变量使用 `: "${VAR:?}"`。
- 恢复数据库不能等于源数据库。
- 恢复根目录拒绝 `/`、`/tmp`、`/Users`、`/var` 等危险路径。
- 恢复目录必须位于 `RESTORE_ROOT/<RELEASE_ID>`。
- 已存在恢复目录直接拒绝。
- 恢复前校验数据库、文件和 `SHA256SUMS`。
- 只恢复到新库和新目录，不执行删除。
- 不包含 `rm -rf`。

安全 dry-run：

```text
rollback_same_db_exit=2
恢复库不能等于当前生产库

rollback_dangerous_root_exit=2
拒绝使用危险恢复根目录: /
```

结论：原 `DEF-PP05-001` 已关闭。

剩余风险：

- 危险根目录只做字符串匹配，没有对 `RESTORE_ROOT` 做 `realpath` 规范化；`/var/..` 等变体尚未被明确拒绝。
- `tar -xzf` 未显式拒绝带 `../` 的归档成员；生产备份应由可信流程生成。

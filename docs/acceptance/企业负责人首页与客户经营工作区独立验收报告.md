## 4. 缺陷

### DEF-BOSS-CUSTOMER-001 · P1 · 门店筛选下指标跨店泄漏

- 复现夹具：A 店有一个客户；B 店有一个客户，B 店客户当天有跟进且当天签约；查询 `storeId=A店`。
- 实际：A 店视角的有效跟进日增为 1，签约客户为 1。
- 预期：应均为 0，因为跟进和合同属于 B 店客户。
- 根因：`CustomerOverviewContext.report` 只对 `customers` 做门店过滤，传递给 `metrics` 的 `follows` 和 `contracts` 仍是全企业数据；`activeCustomerIds` 和 `signedCustomers` 未与当前客户集合求交。
- 证据：`_系统/协作/lanes/acceptance/workspace/boss-customer-workspace/probe.log`
- 影响：BOSS 门店切换后指标与列表口径不一致，可能严重误导经营判断。
- 责任 lane：development。

### DEF-BOSS-CUSTOMER-002 · P2 · 今天 00:00 被同时计入昨日和今日

- 复现夹具：客户 `createTime = 今天 00:00:00`。
- 实际：新增客户周期 `today=1, yesterday=1`。
- 预期：`today=1, yesterday=0`。
- 根因：`inRange(value,start,end)` 使用 `!value.isAfter(end)`，结束时间为 `todayStart` 时包含结束点；昨日窗口 `[yesterdayStart, todayStart]` 与今天窗口重叠一个瞬间。
- 同类影响：客户创建、跟进记录、到访、量房、交设计等使用相同 `inRange` 的活动统计。
- 证据：`probe.log`
- 影响：日增和昨日会重复计数午夜边界事实。
- 建议：周期窗口统一改为 `[start, end)`，只有“至当前时刻”的窗口才使用当前时间作为闭区间。
- 责任 lane：development。

### DEF-BOSS-CUSTOMER-003 · P2 风险 · 底部固定栏可能遮挡最后一张卡

- 静态证据：BOSS 页面根节点 `height:100vh; overflow:hidden`；内部客户滚动区仅 `padding-bottom:24rpx`；固定 TabBar 高度至少约 `92rpx + safe-bottom`，悬浮按钮还位于 TabBar 上方。
- 风险：最后一张客户卡、分页 footer 或登记按钮可能被固定 TabBar/FAB 遮挡，无法完全滚动到可点击区域。
- 状态：`UNVERIFIED`，需开发者工具/真机确认后才能升级为确定缺陷。
- 证据：`src/pages/customer/list.vue` 的 `.cl--boss`、`.cl__customer-scroll` 与 `JzTabBar.vue` / `JzFloatAdd.vue`。

# 客户经营「预约量房客户」指标卡独立验收报告

## 0. 结论

企业负责人「客户经营」第四张指标卡已从 `riskCustomer` 切换为 `measureCustomer`：

- 指标值按本月 `Measure.scheduledAt` 去重客户统计；
- `scheduledAt` 为空时兼容 `Measure.measureTime`；
- `Cancelled` 量房记录不参与预约客户统计；
- 日增、昨日、近7日增、月增均按预约时间统计去重客户；
- 副文案为“本月完成 X 户 · 待派单 Y 户”；
- 风险客户不再占用第四张指标卡，但客户风险等级和负责人分组风险数仍保留。

后端定向测试、独立性/窗口边界测试、App type-check 与 release build 均通过。当前环境无法用真实业务数据执行 App 页面视觉验收，因此最终状态为 **CONDITIONAL**，视觉部分标记 `BLOCKED_EXTERNAL`。

## 2. 测试更新

`CustomerOverviewContextTest` 已从旧 `riskCustomer` 断言更新为 `measureCustomer`，并增加以下夹具：

- 同一客户多条预约记录，验证客户去重；
- `scheduledAt` 为空但 `measureTime` 有值，验证历史兼容；
- `Cancelled` 预约与有效预约并存，验证取消记录排除；
- 今天、昨天、近7日、本月四个时间窗口；
- 本月已完成客户；
- 本月未完成且未指派设计的待派单客户；
- 负责人分组风险数。

旧断言：

```text
newCustomer / activeFollow / signedCustomer / riskCustomer
```

新断言：

```text
newCustomer / activeFollow / signedCustomer / measureCustomer
```

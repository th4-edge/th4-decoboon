## 4. 缺陷清单

> 严重级别：P1 影响主流程数据加载；P2 影响特定页面可用性；P3 影响健壮性/体验。

### DEF-MP-BOSS-001｜P1｜企业负责人进入「设计师列表/设计调度」数据全部失败

- **现象**：Boss 打开 `subpackages/team/pages/designers`，页面提示"设计调度数据加载失败"，待指派设计师、设计师绩效卡片均为 0。
- **后端日志**：`2026-09-16 06:26:27 statistic/store/report处理失败:当前账号无权执行该操作`
- **最小化复现**：Boss token → `POST /api/statistic/store/report` → `{"success":false,"errorCode":{"code":"403","message":"当前账号无权执行该操作"}}`
- **根因**：`src/subpackages/team/pages/designers.vue` 中 `refresh()` 只区分两类角色：
  `isTeamLeader.value ? statisticApi.teamLeader() : statisticApi.storeManager()`
  企业负责人落入 `else` 分支调用**店长专属**接口；后端 `statistic/store/report` 使用 `tenantContext.requireRole(employee, EmployeeRole.StoreManager)` 正确拒绝。
- **性质**：前端角色分支不完整 + 前后端契约覆盖缺口（Boss 未纳入该页调用矩阵）。
- **影响**：Boss 无法查看设计师调度与设计师绩效，页面数据静默为 0，容易被误读为"无数据"。
- **建议**：为该页补 Boss 分支（复用 `statistic/boss/dashboard` 或新增企业级设计调度视图），或对无权限角色隐藏页面入口；同时补充"角色 × Provider"契约用例。

### DEF-MP-BOSS-002｜P1｜企业负责人查看自己的成员详情被拒，页面无内容

- **现象**：Boss 从成员列表进入自己的成员详情 `subpackages/company/pages/member-detail?empId=<自己>`，页面无任何内容，仅 toast"员工详情加载失败"。
- **后端日志**：`06:26:40`、`06:27:01` 共 3 次 `company/member/info处理失败:不能操作自己的员工记录`
- **最小化复现**：Boss token → `POST /api/company/member/info {"empId":1789402550555064838}` → `400 不能操作自己的员工记录`
- **根因**：`MembershipContext.memberInfo(current, empId)` 将"查看详情"与"变更类操作"共用同一条自我保护规则；读接口不应被写保护规则拦截。前端 `member-detail.vue` 对自己这一行仍提供详情入口。
- **性质**：后端权限规则粒度缺陷（读/写未分离）。
- **影响**：企业负责人（以及任何成员的"自己"记录）无法查看详情；只有 1 名成员的企业中该页 100% 不可用。
- **建议**：`member/info` 允许查询本人（或在企业范围内允许 Boss 查询任意成员），仅对 `update/suspend/resign/handover` 保留"不能操作自己"；前端对自己隐藏"交接/离职"等写操作入口。

### DEF-MP-BOSS-003｜P2｜已锁定方案的「设计洽谈」页进入即失败，无法查看已有洽谈记录

- **现象**：进入 `subpackages/design/pages/talk?designId=<designId>` 时页面提示"会按当前方案、诉求和报价重新生成全部页面。"，无洽谈内容。
- **后端日志**：`06:28:24 design/talk/build处理失败:该房屋已有客户确认报价或唯一项目，设计方案已锁定；调整请发起合同变更单`
- **最小化复现**：Boss token → `POST /api/design/talk/build {"designId":225672867549806592}` → `400 设计方案已锁定`
- **根因**：`talk.vue` 的 `load()` 在"只有 designId、没有 talkId"时直接调用 `designApi.buildTalk()`（重建），而服务端对已锁定方案正确拒绝；前端未先按 design 查询已有洽谈记录，也未对锁定态降级为只读查看。
- **性质**：前端状态分支缺陷（把"查看"实现为"重建"）。
- **影响**：已签约/已锁定客户无法通过小程序查看历史洽谈 PPT，只能新建时使用。
- **建议**：进入页面先查询已有洽谈记录；仅对未锁定方案提供"重新生成"；锁定态改为只读展示 + 引导入口。

### DEF-MP-BOSS-004｜P3｜参数异常时页面未捕获异常，出现空白页

- **现象**：巡检期间捕获 1 次 `[装得清] 未处理异常 {}`；`plan-edit` 以非 projectId 参数进入时，后端同时返回 `project/project/info`、`project/stage/page` 两条"项目不存在或无权访问"，页面空白无提示。
- **证据**：`route-sweep-result.json` 的 `events`；后端日志 `06:29:20` 两条 400。
- **根因**：`plan-edit.vue` / `task/edit.vue` / `report/edit.vue` 的 `onLoad` 直接调用 `load()`，未捕获 Promise 异常；页面本身也没有错误态 UI。
- **性质**：前端健壮性缺陷（非后端错误）。
- **建议**：页面加载统一 `try/catch + 错误态占位 + 返回入口`；对缺参场景前置校验并给出可操作提示。

## 6. 结论

- **功能结论**：`PASS WITH DEFECTS`。企业负责人主链路（客户 → 跟进 → 量房 → 设计 → 报价 → 合同 → 项目）与 57 个页面可正常访问与渲染；3 个页面存在功能性缺陷，1 项健壮性缺陷。
- **服务端结论**：真实环境下后端业务校验、状态机与数据权限**未发现放行类安全问题**；`company/member/info` 存在读权限规则过严问题。
- **放行建议**：`DEF-MP-BOSS-002` 修复前，不建议对外声明"企业负责人可管理成员详情"；`DEF-MP-BOSS-001/003` 应在小程序正式提审前修复。

1. 非 Boss 角色（店长/团队长/顾问/设计师/项目经理/履约/财务）本轮未做小程序真实回归。
2. 业主端（客户）小程序闭环未覆盖。

5. 项目执行段（任务开工、日报提交、阶段验收、客户确认、收付款）仅在小程序只读页面与既有数据上验证，未在本轮新建项目上跑完写闭环。

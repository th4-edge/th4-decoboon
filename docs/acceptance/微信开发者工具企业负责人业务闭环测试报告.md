## 2. 本轮在真机操作中发现并修复的缺陷

| 编号 | 现象（真机操作发现） | 根因 | 修复 |
| --- | --- | --- | --- |
| MP-01 | 排期页在选择「客餐厅/主卧」等既有区域时，工艺库整片为空，设计师无法排期 | 合同施工行带入的区域是自由文本（客餐厅/主卧），不在 SpaceType 枚举内；原 `lib` 过滤直接用枚举 id 判断，全部被过滤 | `zoneOptions = 系统区域枚举 ∪ 既有任务区域名`；自由文本区域不做 `zoneIds` 过滤 |
| MP-02 | 既有任务的「已下发」标记不出现，同一工艺可再次下发 | ① 既有任务 `catalogId` 取自 `catalogItem.itemId`（前端未回退）；② 区域键用枚举 id（LivingRoom）与后端存的区域名（客厅/客餐厅）对不上 | `normalizeTask.catalogId` 回退 `catalogItem.itemId`；去重键统一用**区域名**；后端同步提供唯一性拦截（400） |
| MP-03 | 未指定项目经理时工地详情没有任何提示，且点「开始施工阶段」无任何反馈 | 页面无未指派提示；`startNextStage` 无 try/catch，后端 400 被静默吞掉 | 增加警示条 + 开工按钮改为「先指定项目经理才能开工」；补 `toastError` 提示 |
| MP-04 | 找不到切换设计师/项目经理的入口 | 成员页只读、无指派入口 | 新增「工地岗位」区 + 员工选择弹层（按角色过滤，仅 Boss/本门店店长可操作）+ 工地详情入口 |
| MP-05 | 验收横幅固定显示「泥瓦工程」 | 文案硬编码 | 改为真实阶段名 |
| MP-06 | 任务编辑保存失败时页面卡在 loading | `hideLoading()` 不在 finally | 补 try/catch + 保证 hideLoading |

> MP-01/MP-02 是本轮**真机操作才发现**的问题（接口级测试覆盖不到），已修复并复验（厨房区域出现「已下发」标记）。

## 6. 复现方式

```bash
# 1) 以本机 IP 构建小程序（dev 模式，指向本地后端）
cd 前端代码/th4-decoboon-app
VITE_API_BASE=http://$(ipconfig getifaddr en0):8090/api/ npx uni build -p mp-weixin --mode development
# 确保 dist/build/mp-weixin/project.config.json 含 miniprogramRoot=./ 且 setting.urlCheck=false

# 2) 用开发者工具打开并开启自动化端口
"/Applications/wechatwebdevtools.app/Contents/MacOS/cli" auto --project "$PWD/dist/build/mp-weixin" --auto-port 9420

# 3) 连接并驱动（miniprogram-automator，node 22）
node /tmp/mp-lib.js  # 公共封装：connect/sleep/texts/errors
```

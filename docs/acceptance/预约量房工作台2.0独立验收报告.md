## 0. 结论

预约量房工作台 2.0 的主要结构已经落地，且没有引入“接单/拒单/上门中”等新状态：

- 七个派生状态与现有 `MeasureStatus` 事实组合一致；
- 全企业看板与业务员分组使用不同状态源，顶部结构不随当前分组切换；
- 待派单、未预约、已预约、逾期、已完成、待交设计条件均已加入；
- 主按钮与联系客户、改约、查看预约、查看量房记录路径已接入；
- 最新 UI 返工的“返回经营概览”“日期维度 2×2”“异常待办 2×2”静态实现正确；
- App type-check / release build / 分包检查通过。

但独立探针发现以下阻断问题：

1. `todayCount` 漏计今天已完成但 `scheduledAt` 属于今天的量房；
2. `periods.today` 使用 `[今天 00:00, 当前时刻)`，漏计今天尚未到时的预约；
3. 全企业日期窗口仍先按 `ACTIVE_PRE_MEASURE` 截断客户池，已签约客户的历史量房事件丢失；
4. App 逾期筛选仍使用 84 小时，后端和业务口径为 4 小时；
5. 人员绩效考核页选择月份/门店时，业务员量房业绩没有使用对应筛选；
6. 业务员角色的“我的量房”入口声明了能力，但权限矩阵没有授予 `view:measure-workbench`，核心目标角色无法从首页进入。

因此本轮不能判定通过，`final_status = BLOCK`。

## 4. 确认缺陷

### DEF-MEASURE-WS-001 · P1 · 全企业日期窗口截断已签约客户事件

- 复现：Signed 客户存在今天的预约和完成量房事实。
- 实际：客户/房屋/量房事实不在 report items、items 为空，today periods 也为 0。
- 预期：全企业经营日期窗口按 Measure 事件统计，不因客户当前状态为 Signed/Serving/Finished 而丢失历史事实。
- 根因：`Report.call` 先按 `ACTIVE_PRE_MEASURE` 过滤客户，再以过滤后的 items 计算 periods。
- 证据：`workspace2-acceptance.log`；`workspace2-results.json`。

### DEF-MEASURE-WS-003 · P1 · App 逾期筛选阈值仍为 84 小时

- 位置：`measure-workbench.vue` 的 `overdue()`。
- 实际：`84 * 3600 * 1000`。
- 预期：4 小时，与后端 `OVERDUE_HOURS = 4L` 及产品口径一致。
- 影响：已预约未完成、未指派设计的任务在 4–84 小时之间不会进入 App 的逾期筛选，和顶部逾期计数不一致。
- 证据：`workspace2-static-audit.json`。

### DEF-MEASURE-WS-004 · P2 · 人员绩效页量房业绩未跟随月份/门店筛选

- 位置：`assessment.vue` 的 `load()`。
- 实际：`workbenchApi.bossMeasure()` 使用空参数。
- 预期：月份和门店筛选应传入量房业绩数据源，或由服务端按相同 cohort 返回。
- 影响：切换月份或门店后，业务员量房日期窗口、预约率、完成率、逾期率和待指派仍为另一范围事实。
- 证据：`workspace2-static-audit.json`。

### DEF-MEASURE-WS-005 · P1 · 今日预约自然日口径不完整

- 位置：`Report.isToday()` 和 `Report.periods()`。
- 实际：
  - `isToday` 要求 `completedAt == null`，今天完成但今天预约的量房不计入 `todayCount`；
  - `periods.today` 结束点是 `now`，今天尚未到时的预约不计入 `today.scheduledCount`。
- 预期：今日预约按今天的全部 `scheduledAt` 且未取消统计，不因尚未上门或已经完成而变化。
- 独立探针：预期 `todayCount=2`、`today.scheduledCount=2`，实际均为 `1`。
- 证据：`workspace2-acceptance.log`。

### DEF-MEASURE-WS-006 · P1 · 业务员无法进入我的量房

- 位置：`roles/catalog.ts` 与 `roles/permission.ts`。
- 实际：业务员的 action 声明了 `view:measure-workbench`，但权限矩阵未授予该能力；首页过滤后入口消失。
- 影响：产品要求业务员本人客户和量房推进，但业务员无法从首页进入预约量房工作台。
- 风险：直接访问时页面标题为“我的预约量房”，但当前入口、立即派单权限与角色行为没有形成完整可操作闭环。
- 证据：`workspace2-static-audit.json`。

## 4. 已确认缺陷

### DEF-MEASURE-WS-001 · P1 · 全企业日期增量丢失已签约客户事件

- 复现：客户当前为 `Signed`，今天存在预约和完成量房事实。
- 实际：`today.scheduledCount=0`、`today.completedCount=0`。
- 预期：均为 1。
- 根因：`Report.call` 先按 `ACTIVE_PRE_MEASURE` 过滤客户，再以过滤后的 items 计算 periods。签约、履约、完工客户的历史 Measure 不再进入增量。
- 影响：全企业预约量房和完成量房趋势失真，也会污染人员绩效考核页的日期窗口。
- 证据：`/Users/zhangwei/FutureFiles/安徽昭青/家装装修/装客宝/后端代码/th4-decoboon/_系统/协作/lanes/acceptance/workspace/boss-measure-workspace/latest-probe.log`

### DEF-MEASURE-WS-003 · P1 · App 逾期筛选仍使用 84 小时

- 位置：`measure-workbench.vue` 的客户端 `overdue()`。
- 实际：`84 * 3600 * 1000`。
- 预期：`4 * 3600 * 1000`。
- 影响：未指派且预约超过 4 小时但未超过 84 小时的任务，不会进入 App「逾期」筛选和条件计数；后端 `overdue4hCount` 与前端不一致。
- 证据：源码静态检查；后端常量为 `OVERDUE_HOURS = 4L`。

### DEF-MEASURE-WS-004 · P2 · 人员绩效页的量房业绩没有使用当前月份/门店筛选

- `onMonthChange` 将 `month` 传给 `statisticApi.performance`，但 `workbenchApi.bossMeasure()` 使用空参数。
- `storeId` 同样只传给绩效接口，没有传给量房业绩接口。
- 因此：
  - 切换月份不会改变业务员量房日期窗口和量房指标；
  - BOSS 选择门店后，量房业绩仍可能包含其他门店；
  - 该区块与页面上的月份/门店筛选语义不一致。
- 影响：人员绩效考核中的量房业绩可能被错误用于评估，属于职责迁移后的数据范围缺陷。
- 证据：`subpackages/statistic/pages/assessment.vue` 的 `load()` 与 `measureGroups`。

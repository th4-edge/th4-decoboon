## 4. 缺陷与阻断

### DEF-PROJ37-001（P0）影像节点留证接口 100% 失败

- 现象：`project/task-node/save` 对 Start/Conceal/Finish 全部返回 `undefinedErrorCode 未定义错误信息:{0}`。
- 日志根因（`logs/log_error.log` 2026-09-23 02:23:43）：
  `Cannot invoke "String.equalsIgnoreCase(String)" because the return value of "com.th4.edge.decoboon.project.configure.TaskNodeKey.getValue()" is null`
- 定位：`TaskNodeKey implements Enumerable<String>` 只重写了 `getName()`，未实现 `getValue()`；`tasknodes/save.support.Save#parseKey` 使用 `item.getValue().equalsIgnoreCase(value)` 触发 NPE。
- 影响：**「施工进行 / 隐蔽工程 / 施工完成」影像节点留证在真实链路完全不可用**，`SCN-003` 的核心动作不可执行；连带隐蔽任务无法按规则完成（隐蔽未确认不得完工）。
- 建议：`TaskNodeKey` 按 `EmployeeRole` 模式实现 `getValue()`（返回 `name()`），或 `parseKey` 改用 `item.name()` 比较；补单元测试覆盖三个节点键。

### DEF-PROJ37-002（P1）收款重复提交不幂等

- 现象：同一 `finance/receipt/save` 请求重复提交，返回 `400 收款金额不能超过应收余额`，而非返回首次收款事实。
- 根因：`receipts/save.support.Save#call` 中「应收余额校验」位于「幂等键查找 + sameBusiness 判定」之前，重复请求在幂等分支前即被拦截。
- 影响：网络重试/用户重复点击会被误判为超额，客户端无法拿到原始收款 ID，可能诱发人工改单或重复录入。
- 建议：把幂等键查找与 `sameBusiness` 判定提前到余额校验之前（键不同再走余额校验），并补「重复提交返回原收款、不重复核销、不重复记账」测试。

### DEF-PROJ37-003（P1）无施工任务的阶段开工后被回退为「未开始」

- 现象：`project/stage/update` 开工「开工交底」返回成功，但随后任意刷新（任务推进触发的 `refreshProject`）把该阶段状态写回 `Todo`；库中可见 `actual_start` 已写入而 `status=Todo`。
- 根因：`ProjectContext.refreshProject` 以阶段内任务进度推导阶段状态，空任务阶段 `progress=0` → 落入 `else { Todo }` 分支，覆盖了「已开工」事实。
- 影响：交底、竣工保洁等无施工行的阶段无法稳定保持施工中状态，页面与事实不一致；与 G-03（阶段权重/进度口径）同源。
- 建议：`refreshProject` 不得回退已开工阶段（区分「未开工」与「已开工但无任务进度」），具体口径待 `REQ-BIZ-20260923-001` G-03 裁决后实现。

### DEF-PROJ37-004（P1）取消任务计入验收门禁且 `Cancelled → Done` 无校验

- 现象：项目 37「木作吊顶」阶段含 1 条 `Cancelled` 任务；`project/acceptance/save` 要求阶段内**所有**任务 `Done`，因此必须先把该取消任务通过 `project/task/update` 改为 `Done` 才能提交验收（本次为继续验证即如此操作，验证后已回滚该任务为 `Cancelled`）。
- 根因：`ProjectContext.submitAcceptance` 的 `unfinished` 判定包含 `Cancelled`；`tasks/update` 无状态迁移白名单，允许 `Cancelled → Done`。
- 影响：真实减项/取消场景要么被迫造假（取消改成完成），要么永远无法提交阶段验收。
- 建议：业务先裁决 G-07（取消任务是否参与验收门禁），研发补状态迁移白名单与相应验收用例。

### BLOCKED-OWNER-SESSION（外部阻断）业主驳回/复验/确认无法真实执行

- 原因：业主身份只能通过微信小程序授权（`auth/session/login` 换取 `Credentials` + `identity/customer-invite/accept` 建立 `CustomerAccess`），本地/离线环境无真实微信主体与 AppSecret，无法取得业主 token；未使用任何伪造/旁路手段（不接受伪造 token 的做法）。

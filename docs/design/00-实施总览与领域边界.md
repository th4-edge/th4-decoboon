# 装得清后端实施总览与领域边界

> 版本：v1.0 · 2026-09-11  
> 上游依据：`th4-bim` 源码、`saas` 数据库、`rules.md`、装得清小程序业务设计  
> 当前实现范围：BIM 工艺、材料、统一家装材料库、设计转化报价，以及由其驱动的项目施工闭环

## 1. 事实源与目标

| 内容 | 上游事实源 | 本系统目标 |
| --- | --- | --- |
| 工程分类、施工项、工艺价格 | `th4-bim` 的 `bim_construct_*` | 原字段、原表名迁入，作为报价和施工计划主数据 |
| 材料品牌、系列、规格、材料价格 | `th4-bim` 的 `bim_material_*` | 作为材料计划、选材和成本核算主数据 |
| 施工、主材、软装、电器、综合和定制的统一选材目录 | `catalog_item` | 企业负责人/材料员统一维护价格、规格、公式和工艺，设计师只能选库 |
| 装修空间、整装套餐、套餐分项、增值项 | `th4-bim` 的 `bim_pack_*` | 作为客户报价模板，并实例化为 Quote |
| 客户、项目、施工阶段、施工项、材料计划、验收 | 装得清小程序 Mock 状态机 | 后端强业务闭环 Provider 实现 |
| 数据同步 | `saas` 数据库 | 同步到本系统 `decoboon` 数据库的 `bim_*` 表 |

## 2. 业务链路

```text
BIM 工程/材料/套餐主数据
        ↓
统一家装材料库（企业维护）
        ↓
诉求 → 设计方案 → 区域尺寸 → 施工/材料分项
        ↓
设计报价（服务端公式汇算，保存区域与分项快照）
        ↓
谈单 PPT → 客户确认/接受
        ↓
Project（项目）
        ↓
ProjectStage（按工程分类生成阶段）
        ↓
ProjectTask（按套餐施工项生成任务）
        ↓
MaterialPlan（按套餐材料生成材料计划）
        ↓
Task 节点推进 + MaterialPlan 到场
        ↓
Acceptance（阶段/项目验收）
        ↓
Project 进度与状态刷新
```

## 3. 多租户边界

装得清是 SaaS 平台，所有业务实体都必须包含企业归属：

```java
@Note("所属企业")
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "com_id", nullable = false)
private Company company;
```

约束：

- BIM 工艺、材料、套餐按企业复制，企业之间使用独立主键空间。
- 统一材料库同样按企业隔离，只有企业负责人、采购员或仓管可以维护。
- 客户、报价、报价明细、项目、阶段、施工任务、材料计划和验收单都必须直接保存 `company`。
- 子实体即使可以通过父实体推导企业，也必须冗余保存 `company`，便于强隔离和审计。
- Provider 的当前企业只能从 `@User Employee` 重新加载后的登录员工取得；前端 `companyId` 只能作为候选值，不能作为权限依据。
- 有个人、团队或门店归属的实体必须接入 `@DataPermission`：框架通用 CRUD 由 `DataScopeRequestFilter`、`DataPermissionCrudAspect` 自动处理，自定义 Provider 使用 `DataScopeSpecification`。分页请求不能只把企业条件交给框架查询。
- 完整的数据权限设计、查询闭环、测试矩阵和接入步骤见 `docs/design/07-数据权限设计规范.md`。
- 数据库同步脚本从 `saas.oa_company` 同步租户，并将 BIM 基准数据复制到每个企业。

## 4. 代码边界

所有装得清业务代码直接放在 `com.th4.edge.decoboon` 总包的业务域下：

```text
com.th4.edge.decoboon
├── bim
├── customer
├── trade
└── project
```
不再存在 `clue` 中间包，Provider 路由也不再带 `decoboon/` 前缀。

所有 Provider 路由保持框架约定：

```text
bim/{对象}/{能力}
trade/{对象}/{能力}
project/{对象}/{能力}
```

禁止事项：

- 不新增 Controller、DTO、VO、Request 包装类。
- 不把 BIM 的 `Price/Upgrade/Spec` 等值对象改成裸字段组合。
- 不在实体里写报价、进度计算等业务逻辑。
- 不直接修改源 `saas` 数据库。
- 不把平台订阅账务与企业项目账务混在一起。

## 5. 当前代码分层

```text
bim
├── configure     空间类型、计量单位
├── cost          价格、增值项和价格计算上下文
├── construct     工程分类、施工项
├── material      材料分类、品牌、系列、规格、材料
├── catalog       施工、主材、软装、电器、综合、定制统一目录
└── pack          套餐空间、套餐分项、套餐、差价规则

trade
└── quote         客户报价实例和报价明细

project
├── project       项目主档、阶段、施工任务、材料计划、验收
└── context       项目生成、任务推进、进度刷新等强业务上下文
```

## 6. 状态机总览

| 对象 | 状态链 |
| --- | --- |
| Quote | `Draft → Submitted → Accepted → Converted`；`Submitted → Rejected` |
| Project | `Preparing → Ongoing → Accepting → Finished → Settled`；`Ongoing → Suspended` |
| ProjectStage | `Todo → Doing → Accepting → Done` |
| ProjectTask | `Todo → Doing → Accepting → Done` |
| MaterialPlan | `Planned → Requested → Ordered → Arrived → Closed` |
| Acceptance | `Pending → Confirmed`；`Pending → Rejected` |

## 7. 交付顺序

1. BIM 主数据结构与同步。
2. BIM 工艺/材料/套餐只读 Provider。
3. Quote 创建、价格和成本快照。
4. Quote 接受后生成 Project/Stage/Task/MaterialPlan。
5. Task 推进、材料状态更新、项目进度刷新。
6. Acceptance 确认并关闭阶段/项目。

## 8. 验收口径

- 能从 `saas` 同步出 11 个工程分类、182 个施工项、317 个材料和 2 个套餐。
- 能通过 BIM 主数据创建客户报价，金额和成本来自套餐与面积。
- 客户接受报价后能自动生成项目、阶段、施工项和材料计划。
- 施工任务完成后，阶段和项目进度能自动刷新。
- 验收确认后，阶段状态可以闭环。
- 所有接口均通过 Provider，且不出现 DTO/VO/Controller。

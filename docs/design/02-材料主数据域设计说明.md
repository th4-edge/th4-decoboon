# 材料主数据域设计说明

> 对应代码：`com.th4.edge.decoboon.bim.material`、`com.th4.edge.decoboon.bim.catalog`  
> 对应数据表：`bim_material_category`、`bim_material_brand`、`bim_material_series`、`bim_material_material`、`bim_catalog_item`  
> 租户约束：全部材料主数据实体包含 `Company company`

## 1. 领域定位

材料主数据域回答“有哪些材料、属于什么品类和品牌、规格是什么、如何计价、适用于哪些空间”。

它是材料计划、材料到场、项目材料成本和客户选材的共同来源，不代表某项目的实际库存或采购事实。

## 2. 模型层级

```text
Category 主材大类
  └─ Brand 品牌
      └─ Series 品牌系列
          └─ Spec 规格
              └─ Material 材料分项
```

`Material` 同时保留 `category`、`brand`、`series` 对象关联，避免跨层查询时丢失归属。

## 4. 材料价格计算

沿用 `th4-bim` 的统一价格值对象：

```text
Part：数量 × (材料基价 + 人工基价)
Total：数量 × 总包基价
Cost：数量 × 成本价
```

材料计划的计算方式：

```text
项目材料需求量 = 标准面积 × 项目面积折算系数 × (1 + 损耗率)
```

首批实现先保存标准面积和项目面积折算结果，损耗率由 Category 提供，后续在采购和领用环节再进行实际差异核算。

## 6. 数据隔离与序列化

- 材料成本、采购参考价属于企业内部数据。
- 客户选材接口只返回品牌、系列、规格、公开图片和报价。
- 材料主数据属于纯企业级数据，不虚构负责人字段；所有查询仍必须强制当前 `Company`。
- 成本字段通过 `@ServiceProperties` 按 Provider URI 做响应过滤，不能替代数据权限。
- 关联对象使用 `LAZY`，列表页不应无控制地展开完整品牌/系列/规格对象。

## 8. 统一家装材料库

旧 `bim_material_*` 和 `bim_construct_*` 记录经统一目录层汇集为 `CatalogItem`，与软装、电器、综合和全屋定制共用同一套选材协议。设计师不再维护名称、品牌、规格、单价和公式，只提交库内项目及工程量。

| 路由 | 能力 | 说明 |
| --- | --- | --- |
| `catalog/item/tree` | 分类树 | 返回类型下的左侧分类，以及按分类归组的品牌和规格，不返回项目明细 |
| `catalog/item/page` | 分页 | 按类型、分类、品牌、规格、关键词查询，默认 30 条、最多 100 条 |
| `catalog/item/save` | 保存 | 仅企业负责人、采购员、仓管可新增 |
| `catalog/item/update` | 更新 | 按项目 ID + 企业 ID 定位，禁止跨企业更新 |

`CatalogItem` 的计价模式固定为材料+人工、仅材料、仅人工、固定总价四类，公式由服务端生成并随项目返回。列表页不返回图片集合，避免大目录逐条附加懒加载查询。

### 8.1 选择交互

```text
顶部类型（施工/主材/软装/电器/综合/定制）
→ 左侧分类
→ 顶部品牌/规格筛选
→ 关键词搜索
→ 分页加载 30 条
→ 可跨分类勾选多个项目
→ 确认后逐项填写工程量
→ 回填名称、品牌、规格、单位、价格和公式
```

分步条件均传给服务端，不能把 500+ 条材料一次性加载到小程序。软装和电器暂无真实基准数据时，页面显示空状态并由企业维护人员补录。

新增分项时，分项类型只在材料库选择器顶部出现一次，分项弹层不再重复设置类型。所选项目可以属于不同分项类型，保存时仍逐条提交、逐条按企业公式汇算。

### 8.2 维护权限

- `Boss`、`Purchaser`、`Warehouse` 可维护统一材料库。
- `Designer`、`Marketer`、`Pm` 等其他角色只能查看和选库。
- 前端菜单、路由页面和服务端 Provider 三层都要校验，服务端查询继续强制当前企业。

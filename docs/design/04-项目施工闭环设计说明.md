# 项目施工闭环设计说明

> 对应代码：`com.th4.edge.decoboon.project`  
> 上游：Quote、BIM Construction、BIM Material、GiftItem  
> 目标：让报价能够落地为阶段、施工项、材料计划和验收事实  
> 租户约束：项目、阶段、任务、材料计划和验收单全部包含 `Company company`

## 1. 闭环目标

```text
Quote Accepted
→ Project Preparing
→ 生成 ProjectStage
→ 生成 ProjectTask
→ 生成 MaterialPlan
→ Task 开工/完成
→ 材料到场/关闭
→ Acceptance 提交/确认
→ ProjectStage Done
→ Project 进度刷新
→ Project Finished
```

## 3. 汇合规则

```text
阶段进度 = 阶段任务完成率的加权平均
项目进度 = 阶段权重 × 阶段进度
项目成本 = 任务成本 + 材料计划成本
```

规则：

- `weight` 来自阶段内施工项成本或标准权重。
- 任一施工任务变更后，必须重新计算所属阶段和项目。
- 所有阶段 Done 且验收确认后，项目才能 Finished。
- `Project.progress` 是派生缓存，前端不得直接修改。

## 4. 状态推进

### ProjectTask

```text
Todo → Doing → Accepting → Done
Doing → Todo（重新排期）
Todo/Doing → Cancelled
```

推进规则：

- `Doing`：写 `actualStart`。
- `Accepting`：提交完工，任务进度记为 90%。
- `Done`：确认完成，进度记为 100%，写 `actualEnd`。
- 每次状态变化都刷新阶段/项目。

### MaterialPlan

```text
Planned → Requested → Ordered → Arrived → Closed
```

材料可直送工地或由仓库领用；首批实现以计划状态和到场时间为主，后续扩展采购单、库存和应付。

### Acceptance

```text
Pending → Confirmed
Pending → Rejected
Rejected → Pending（整改后重新提交）
```

## 6. 事务边界

- Quote 接受 → 项目生成：一个事务。
- 任务状态变化 → 阶段/项目进度刷新：一个事务。
- 材料状态变化 → 项目成本刷新：一个事务。
- 验收确认 → 阶段完成 → 项目进度刷新：一个事务。
- 通知、统计刷新可以异步，但不能丢失业务事实。

## 7. 权限

| 角色 | 项目 | 任务 | 材料 | 验收 |
| --- | --- | --- | --- | --- |
| Boss | 全量 | 查看/推进 | 查看 | 查看 |
| Designer | 参与项目 | 查看/协助 | 查看 | 提交/查看 |
| PM | 参与项目 | 推进 | 计划/到场 | 提交 |
| Purchaser | 查看关联项目 | 查看 | 状态推进 | – |
| Customer | 绑定项目 | 只读 | 公开材料 | 确认/驳回 |

服务端必须按 `Company + ProjectMember/项目负责人` 做数据隔离。

### 7.1 四级数据权限闭环

项目域存在 `designer/manager` 多负责人，不能在没有业务定义的情况下直接把其中一个字段硬编码为 `owner`。接入统一拦截器前必须先确定项目主责人、门店和团队归属快照。

- page/list/count：项目实体确定权限字段后标注 `@DataPermission`，通过统一拦截器追加条件。
- info/update/delete：优先使用框架通用 `service/*` 让 `DataPermissionCrudAspect` 自动保护；自定义 Provider 使用 `DataScopeSpecification`，禁止 `findById` 后判断。
- 跨域读取 Customer、Quote 时，目标实体也必须通过对应数据范围查询。
- 项目成员、协同人员属于项目级功能权限，不能替代企业、门店、团队、本人四级数据范围。
- 具体规范见 `docs/design/07-数据权限设计规范.md`。

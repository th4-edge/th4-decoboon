# 08 财务域业务闭环设计

## 1. 定位与角色

财务域以 `Project` 为经营核算单元，管理客户应收、客户实收、供应商/班组应付、实际付款、工人工资、项目材料和项目结算。平台订阅费不属于该域。

| 角色 | 数据范围 | 可执行动作 |
| --- | --- | --- |
| 老板 Boss | 当前企业全部项目与企业费用 | 查看、记账、建应收/应付、收付款、确认/关闭结算 |
| 财务 Finance | 当前企业全部项目与企业费用 | 查看、记账、建应收/应付、收付款、确认/关闭结算 |
| 门店店长 StoreManager | 当前门店项目与门店费用 | 只读查看 |
| 其他员工 | 无财务读权限 | 不可访问财务 Provider |

财务页面可见性只是体验层控制；所有 Provider 均重新加载登录员工并校验角色、企业和项目归属。

## 2. 领域对象

| 对象 | 职责 |
| --- | --- |
| `Receivable` | 合同节点应收：首期款、进度款、尾款、质保金、其他 |
| `Receipt` | 客户实际收款，并核销一个应收节点 |
| `Payable` | 材料款、工人工资、项目款、供应商款、费用支出等付款义务 |
| `Payment` | 向供应商、班组或工人实际付款，并核销应付 |
| `Ledger` | 不可变资金流水，来源为收款、付款、手工记账或调整 |
| `Settlement` | 项目收入、成本、利润与关闭快照 |

每个业务实体都包含 `company/store/team/owner`。企业字段来自登录员工，门店、团队和负责人优先继承项目客户归属快照，禁止信任前端传入的组织字段。

## 3. 状态机

### 3.1 应收

```text
待收 Pending
  ├─ 收到部分金额 -> 部分收款 Partial
  ├─ 累计金额 >= 应收金额 -> 已收清 Received
  └─ 到期未收 -> 已逾期 Overdue
```

金额调整不得低于已收金额。收款金额不得大于当前应收余额。已形成的收款不物理删除，错误业务使用调整/冲销流水。

### 3.2 应付

```text
待付款 Pending
  ├─ 付出部分金额 -> 部分付款 Partial
  ├─ 累计金额 >= 应付金额 -> 已付清 Paid
  └─ 到期未付或加急 -> 逾期/风险 Overdue
```

金额调整不得低于已付金额。付款金额不得大于当前应付余额。

### 3.3 项目结算

```text
Draft 待确认
  -> Confirmed 已确认（验收阶段或已完工）
  -> Closed 已关闭（应收全部收清、应付全部付清）
```

关闭结算时同步项目状态为 `Settled`。任一条件不满足时服务端拒绝，不能通过前端绕过。

## 4. 核心闭环

### 4.1 合同节点首款与工程回款

1. 财务按合同建立 `Receivable`，首期款可关联“签订合同”节点。
2. 到达约定日期仍未收清时，应收自动呈现为逾期。
3. 收款登记必须选择具体应收节点，金额不得超过余额。
4. `Receipt` 保存与应收余额更新在同一事务内完成。
5. 同一事务生成 `Ledger(Income, Receipt, customer)`。
6. 项目账本由应收、实收和流水实时汇总，不手工修改项目已收金额。

### 4.2 材料款

1. 材料计划保留采购计划与成本来源，不直接修改资金余额。
2. 财务或采购转应付时建立 `Payable(type=Material)`，可关联 `MaterialPlan`。
3. 实际付款建立 `Payment`，核销应付并生成 `Ledger(Expense, Payment)`。
4. 项目账本按材料款、工人工资、项目款、其他成本四类归集。

### 4.3 工人工资

1. 建立 `Payable(type=Salary)`，记录工人姓名、工资周期、应付金额和约定付款日。
2. 安排付款后核销工资应付，生成支出流水。
3. 工资页复用应付能力，但默认按工资类型过滤，便于财务快速处理待发工资。

### 4.4 项目款

1. 项目班组、分包或项目经理费用建立 `Payable(type=Project)`。
2. 可关联项目与来源单号，明确成本归属。
3. 付款核销后进入项目成本和结算利润。

### 4.5 手工记账与审计

手工记账只能新增 `Ledger(Source=Manual)`，不允许更新或删除。银行手续费、办公费用、其他收入等无法直接归入收付款单时使用手工记账；能追溯业务合同的金额必须走对应应收/应付闭环。

## 5. Provider 路由

| 路由 | 能力 |
| --- | --- |
| `finance/summary/report` | 企业财务工作台汇总 |
| `finance/project/page` | 项目财务账本分页 |
| `finance/project/report` | 单项目财务全景 |
| `finance/receivable/page|save|update` | 应收计划 |
| `finance/receipt/page|save` | 客户收款与应收核销 |
| `finance/payable/page|save|update` | 应付计划 |
| `finance/payment/page|save` | 付款与应付核销 |
| `finance/ledger/page|save` | 台账查询与手工记账 |
| `finance/settlement/page|save|update` | 项目结算生成、确认、关闭 |

## 6. 小程序页面

| 页面 | 主要视图 |
| --- | --- |
| 财务工作台 | 现金余额、待收/逾期、本月收支、资金闭环、风险待办、最近流水 |
| 应收计划 | 首期款/进度款/尾款、账期、已收/待收、快捷收款 |
| 收款记录 | 收款核销明细、账户、经办人、凭证 |
| 应付账款 | 材料款、项目款、供应商款、工资分类视图 |
| 工人工资 | 应付页按工资类型进入，展示工人、周期、待发金额 |
| 付款记录 | 付款核销、账户、转账流水、凭证 |
| 资金台账 | 收入/支出过滤、账户、来源、项目、往来对象 |
| 项目账本 | 多项目合同、回款、成本、利润与风险排序 |
| 项目财务 | 应收回款、应付付款、项目流水、成本构成、结算条件 |

## 7. 强制校验与测试清单

- 老板、财务可写；店长只读；普通员工访问被拒绝。
- 跨企业 `projectId/payableId/receivableId` 必须按“不存在或无权访问”处理。
- 收款/付款金额必须大于 0 且不能超过余额。
- 调整应收/应付金额不能低于已收/已付金额。
- 收款与应收更新、付款与应付更新、流水生成必须同事务。
- 结算关闭必须具备“应收清零 + 应付清零 + 完工/验收”三项条件。
- 列表和汇总必须按当前企业/门店范围过滤，不返回其他企业财务数据。

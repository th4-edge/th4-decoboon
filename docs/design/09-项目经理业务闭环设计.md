# 项目经理业务闭环设计说明

> 对应后端：`com.th4.edge.decoboon.project`、`com.th4.edge.decoboon.statistic`
> 对应小程序：`th4-decoboon-app`
> 适用角色：`EmployeeRole.Pm`，项目经理
> 核心原则：项目经理只进入“本人作为 `Project.manager` 的项目域”，不按客户负责人或报价创建人套用 `Self` 权限。

## 1. 角色定位与权限边界

项目经理负责报价转项目后的施工履约，不负责获客、客户归属调整和报价编辑。

| 维度 | 项目经理能力 | 数据来源与边界 |
| --- | --- | --- |
| 项目/工地 | 查看、管理阶段与任务、查看动态、成员、验收 | `Project.manager = 当前员工` |
| 客户 | 只读查看 | 本人负责项目关联的去重客户 |
| 报价 | 只读查看 | 本人负责项目的来源 `Quote` |
| 计划 | 查看并调整施工排期 | `ProjectAccessContext.requirePlanEditor` 允许 Boss/Designer/Pm |
| 任务 | 新增、调整、开工、完工、节点留证 | 任务所属项目必须对当前 PM 可见 |
| 现场动态 | 发布日报、图片、问题、材料/进度动态 | 作者固定为当前员工，企业固定为登录员工企业 |
| 验收 | 提交阶段验收、查看确认/驳回 | 阶段所属项目必须对当前 PM 可见 |
| 材料 | 查看风险、推进计划状态 | 仅 Boss/Pm/Purchaser 可推进，项目范围强校验 |
| 消息通知 | 查看、标记已读 | 通知接收人固定为当前员工 |
| 业绩 | 查看本人项目履约与交付指标 | `statistic/pm/report`，只汇总本人负责项目 |

### 1.1 四条强制安全规则

1. 前端传入的 `managerId/companyId/projectId/customerId/quoteId` 只能作为候选值，服务端必须重新校验。
2. 项目经理访问客户、报价、跟进时，不能使用 `findById` 后判断；统一通过 `ProjectManagerAccessContext` 从本人负责项目反向校验。
3. 项目经理访问阶段、任务、日报、验收、材料时，统一通过 `ProjectAccessContext.requireVisible` 校验企业及项目参与关系。
4. 无权限对象统一返回“资源不存在或无权访问”语义，避免泄露其他企业/项目是否存在。

## 2. 邀请注册闭环

```text
企业负责人登录
→ 邀请项目经理（role=Pm）
→ 生成一次性邀请 token
→ 项目经理打开邀请页
→ 填写姓名与密码
→ user/accept 创建 Employee，继承邀请人的 Company/Store/Team
→ 项目经理登录
→ session.role = pm
→ 进入项目经理工作台
```

约束：

- `user/invite` 仅 Boss、StoreManager、TeamLeader 可调用，且只允许邀请其范围内的角色。
- 被邀请人必须通过邀请 token 与手机号完成注册，前端不得直接创建 PM。
- `user/accept` 后角色固定使用邀请记录中的 `Pm`，不接受前端覆盖。
- 项目经理归属企业与门店固定复制邀请人快照，不能通过注册参数扩权。

## 4. 项目经理专用接口

### 4.1 履约报告

`statistic/pm/report`

返回内容：

- 项目数量、待开工、施工中、待验收、停工、完工、逾期、临期项目数。
- 待办、施工中、待验收、逾期任务数。
- 今日动态、近 7 天动态、待确认验收、驳回验收数。
- 材料风险、材料延迟数。
- 关联客户数、来源报价数、合同额、完成交付额。
- 平均进度、准时交付率、验收通过率、未读通知数。
- 风险优先项目、近 3 天任务、验收提醒、材料风险、现场动态、客户和报价摘要。

### 4.2 关联客户只读接口

- `project/manager/customer/page`
- `project/manager/customer/info`
- `project/manager/customer-follow/page`

实现规则：

```text
managedProjects(PM)
→ Project.customer 去重
→ 命中 customerId 才允许返回详情/跟进
```

### 4.3 来源报价只读接口

- `project/manager/quote/page`
- `project/manager/quote/info`

实现规则：

```text
managedProjects(PM)
→ Project.quote 去重
→ 命中 quoteId 才允许返回详情与明细
```

### 4.4 计划、任务与材料

- 计划编辑：`ProjectAccessContext.requirePlanEditor` 允许 Boss、Designer、Pm。
- 任务推进：Boss、Pm 可改变任务状态，任务所属项目必须可见。
- 材料推进：Boss、Pm、Purchaser 可改变材料计划状态，材料所属项目必须可见。
- 材料分页取消前端 `companyId` 依赖，由登录员工解析项目范围。

## 5. 履约业务闭环

```text
企业负责人立项并指派项目经理
→ 项目经理工作台出现负责项目
→ 客户/来源报价进入只读业务视图
→ 项目经理核对施工计划和任务
→ 阶段开工
→ 任务施工与节点留证
→ 发布现场动态/施工日报
→ 材料到场状态推进
→ 阶段任务完成
→ 提交阶段验收
→ 业主确认或驳回整改
→ 项目进度刷新
→ 项目完工/结算
→ 履约业绩沉淀
```

## 6. 消息与通知闭环

项目经理消息刷新只读取：

- 当前 PM 负责项目。
- 当前 PM 项目关联客户。
- 当前 PM 项目内逾期任务和进度提醒。
- 平台创建且接收人为当前 PM 的系统通知。

不再把设计师负责项目或业务员个人客户混入 PM 消息范围。

## 7. 前后端验证清单

- PM 邀请令牌只能接受一次，接受后的角色为 `Pm`。
- Boss 可以邀请 PM，普通 PM 不能邀请企业成员。
- PM 项目列表只返回 `manager=当前员工` 的项目。
- PM 客户列表/详情只返回本人负责项目关联客户。
- PM 报价列表/详情只返回本人负责项目来源报价。
- 伪造其他企业的 `customerId/quoteId/projectId` 必须返回无权限。
- PM 可以调整计划、推进任务、提交验收和推进材料状态。
- Boss 调用 `statistic/pm/report` 返回 `403`。
- PM 调用履约报告只汇总本人项目，不返回企业全量经营数据。
- 小程序 `vue-tsc --noEmit` 与 `uni build -p mp-weixin` 必须通过。
- 后端 `mvn -DskipTests package` 必须通过。

# 设计转化域设计说明

> 对应代码：`com.th4.edge.decoboon.design`、`com.th4.edge.decoboon.trade.quote`  
> 上游：客户、量房/房屋信息、CAD、BIM 施工与主材主数据  
> 下游：设计报价、谈单 PPT、项目施工任务、材料计划  
> 核心目标：把设计师与客户的沟通成果变成可复用的数据和可解释的报价，而不是只留一份 Excel。

## 1. 业务定位

中小家装公司的报价通常按“房屋区域 × 施工/材料分项”展开，再按区域逐项确认。设计与报价一旦交付，企业又担心客户跳过设计师直接比价，因此真正需要经营的不是一张静态价格表，而是客户能感知的专业过程：

```text
量房与勘测
→ 记录客户诉求/排斥点
→ 至少形成 2 套设计方案
→ 每套方案按区域配置尺寸与施工/材料分项
→ 后端按公式自动汇算设计报价
→ 汇总成谈单 PPT
→ 到店讲解并确认方案
→ 接受报价后生成项目
```

因此，本域不是简单的“报价单管理”，而是完整的设计转化事实链：

- **诉求点**：客户明确表达的要求、偏好和排斥项。
- **设计方案**：同一客户、同一房屋下的版本化空间设计方案。
- **方案区域**：主卧、次卧、北卧、厨房、卫生间、阳台、客厅、餐厅、走道等。
- **设计分项**：区域内实际发生的施工分项或材料分项。
- **设计报价**：对设计分项进行公式计算后冻结的商务快照。
- **谈单 PPT**：把诉求、量房问题、方案、材料、投入和讲解顺序组织成页面。

## 2. 关键设计结论

1. **方案与报价分离**：方案可以调整，已生成报价必须保持快照；方案变化后重新生成报价版本。
2. **报价快照不依赖套餐**：当前设计转化流程不读取 `GiftPack`，套餐报价只作为旧流程兼容。
3. **区域是报价的必要维度**：客户视图保留“区域 → 施工/材料分项”结构。
4. **项目经理视图改变结构而不是修改数据**：同一批报价快照按施工分类汇总，不重复保存一套金额。
5. **金额只能由服务端计算**：前端可以提交单价、数量和计价方式，不能直接提交分项金额或报价总额。
6. **谈单门槛是业务规则**：同一客户至少两套达到“待谈单/已讲解/客户选中”的方案，才允许生成谈单 PPT。
7. **所有实体带企业归属和组织快照**：设计、区域、分项、诉求、谈单均保存 `company/store/team/owner`，不能把前端传入归属直接落库。

## 3. 领域模型

### 3.1 客户诉求 Requirement

用于设计师在电话、到店或量房沟通中随时记录：

| 字段 | 说明 |
| --- | --- |
| `kind` | `Demand` 诉求 / `Reject` 排斥点 |
| `category` | 功能、风格、材料、预算、工期、质量、其他 |
| `priority` | 高、中、低 |
| `type/spaceName` | 空间类型及客户口语区域名，如“北卧” |
| `title/detail` | 诉求标题和客户原始描述 |
| `response` | 设计师/方案的回应 |
| `status` | 待确认、已确认、已落地 |
| `customer` | 客户对象关联 |
| `company/store/team/owner` | 企业、门店、团队、负责设计师快照 |

谈单 PPT 中的“装修要求”“户型问题解析”直接读取该实体，不另做文案副本。

设计师端入口：

- 工作台快捷入口“客户诉求”进入诉求中心，先选择负责客户，再查看或新增诉求。
- 客户详情“客户诉求与设计转化”卡片提供“记录诉求”按钮，进入后自动打开录入表单。
- 设计转化页保留“记录客户诉求”入口，并展示已记录的诉求数量和摘要。
- 新增诉求统一记录类型（诉求/排斥点）、分类、优先级、区域、客户原话和沟通来源。

### 3.2 设计方案 Design

同一客户可有多套版本，至少两套可谈单：

- `designId/no/name/version/status`
- `customer/owner/company/store/team`
- `style/layout/area/description`
- `coverUrl/cadUrl/originalPlanUrl/demolitionUrl/masonryUrl/optimizationUrl`
- `sitePhotos/surveyPhotos`

状态流转：

```text
Draft（设计编辑）
→ Ready（待谈单）
→ Presented（已讲解）
→ Selected（客户选中）
→ Archived（归档）

Draft/Ready → Archived
```

只有 `Ready/Presented/Selected` 计入“至少两套方案”的谈单门槛。

### 3.3 方案区域 Space

每个区域保存实际尺寸：

- `type`：卧室、厨房、客厅、餐厅、卫生间、阳台等
- `name`：主卧、次卧、北卧、客餐厅、生活阳台等业务名称
- `length/width/height`
- `area/perimeter`
- `sort/remark/images`

面积与周长由后端根据长宽计算：

```text
area = length × width
perimeter = (length + width) × 2
```

区域面积之和回写 `Design.area`，不能以前端汇总值为准。

### 3.4 设计分项 DesignItem

一个设计分项只属于一个设计方案，可以关联区域，也可以作为综合项目不关联区域。

| 字段 | 说明 |
| --- | --- |
| `type` | 综合、施工、主材、全屋定制、电器、软装家具 |
| `category` | 拆除、水电、瓦工、木工、油漆、瓷砖、木门、卫浴等 |
| `catalogItem` | 必选（兼容旧数据时可在迁移期使用 BIM 施工/主材来源） |
| `construction/material` | 旧 BIM 来源兼容字段，仅由统一目录迁移使用 |
| `name/brand/spec/unit/quantity` | 报价明细快照基础字段 |
| `materialPrice/manualPrice/costPrice` | 材料价、人工价、成本价 |
| `pricingMode` | 材料+人工、仅材料、仅人工、固定总价 |
| `amount/cost/formula` | 服务端计算结果与公式说明 |
| `space/design` | 所属区域和方案 |
| `company/store/team/owner` | 权限归属快照 |

### 3.5 统一家装材料库 CatalogItem

施工、主材、软装、电器、综合和全屋定制统一从 `catalog_item` 选择。设计师只提交 `catalogItemId + quantity + space`，服务端加载有效的库内项目并复制名称、品牌、规格、单位、材料价、人工价、成本价、计价模式、公式和工艺。前端手工任意录入名称或价格会被拒绝。

选材界面按以下顺序分步加载，避免一次拉取全部主材：

```text
类型 → 左侧分类 → 顶部品牌/规格 → 关键词 → 服务端分页
```

新增分项支持跨分类、跨类型勾选多个库内项目；确认后每个项目单独填写工程量，保存时逐条调用服务端并分别按公式汇算。分项类型只在材料库顶部选择一次，分项弹层不再重复设置类型。

企业负责人、采购员或仓管维护库内项目和公式；设计师角色只能查看和选择。旧 BIM 施工/主材记录在首次访问目录时幂等迁移，已有设计分项继续兼容显示并可在编辑时切换为统一目录项目。

## 4. 自动汇算规则

### 4.1 分项金额

```text
材料+人工：quantity × (materialPrice + manualPrice)
仅材料：   quantity × materialPrice
仅人工：   quantity × manualPrice
固定总价： materialPrice + manualPrice
```

### 4.2 分项成本

```text
cost = quantity × costPrice
```

### 4.3 报价汇总

```text
subtotal = Σ 所有分项金额
discounted = subtotal × discount
taxAmount = discounted × 5%
amount = discounted + taxAmount
cost = Σ 所有分项成本
```

`subtotal/discount/taxAmount/amount/cost` 全部由后端写入，前端不能直接指定。新增报价时复制设计分项为 `QuoteItem` 快照，后续 BIM 主数据或设计分项变化不会改动历史报价。

### 4.4 区域结构与项目经理结构

同一批 `QuoteItem` 可以生成两个读视图：

```text
客户/设计师视图：区域 → 分项 → 数量/单价/金额
项目经理视图：  施工分类 → 施工分项 → 数量/金额
```

项目经理视图不重新计算金额，也不把区域拆成多条独立报价，只按 `category + type` 汇总。这样客户看到“按房间解释钱花在哪”，项目经理看到“按拆除/水电/瓦工等组织施工”。

## 5. 谈单 PPT

系统同时保留结构化页面并生成可下载 `.pptx`。服务端先把每页写入 `TalkSection`，再按 16:9 版式导出标题、副标题、正文和图片，最终文件地址写回 `Talk.outputUrl`。页面结构参照《谈单PPT模板.pptx》：

```text
封面
设计目录
小区景观
装修诉求
现场照片
现场勘测
量房质量报告
原始结构图
户型问题解析
拆改图 / 砌筑图 / 优化图
区域设计（每个区域一页）
软装设计
材料搭配
电器配置
装修投入
省钱方案
结束页
```

生成规则：

- 装修诉求页只展示客户真实说过的诉求和排斥点，并带上优先级。
- 量房报告页读取区域长宽高、面积和周长。
- 区域设计页按区域展示分项及金额，把设计动作和报价对应起来。
- 装修投入页展示分项合计、折扣、税金和报价合计，并注明正式金额以签字报价单为准。
- 省钱方案页从金额最高分项中提取重点投入项，帮助设计师把价格解释成价值取舍。
- 导出文件失败不丢失业务数据，页面内容仍保留在 `TalkSection` 中，后续可重新生成。
- 导出文件地址保存在 `Talk.outputUrl`，由 `th4.edge.framework.upload-dir` 和 `upload-url-prefix` 决定落盘目录与访问地址。

## 7. 权限与数据范围

- 诉求、方案、区域、分项、报价、谈单页均标注 `@DataPermission`。
- 保存时 `company` 固定取当前登录员工企业，`store/team` 从服务端确认后的负责人复制。
- 非 BOSS 不能通过 `ownerId` 把方案转交他人；BOSS 只能指定当前企业员工。
- 跨域读取客户和方案必须使用 `DataScopeSpecification`，禁止 `findById` 后判断权限。
- 设计师/顾问默认 `Self`，门店店长 `Store`，团队负责人 `Team`，BOSS `Company`。
- 项目经理访问报价时仍通过项目来源报价校验，并使用施工分项汇总视图，不扩大为全企业报价权限。
- 统一材料库属于企业级主数据：所有角色可按企业读取，只有 `Boss/Purchaser/Warehouse` 可维护；设计师直连维护页面会被前端拦截，伪造保存请求会被服务端返回 403。

## 8. 数据迁移与兼容

旧套餐报价继续可用；设计报价通过新增的 `Quote.design` 表达。已有生产库上线前需执行 `docs/design/migrations/10-设计转化域迁移.sql`，重点把 `gift_id/mod_id/const_id` 从旧流程的强制非空调整为按来源类型可空。新建环境可直接由 JPA 更新表结构。

## 9. 项目生成衔接

设计报价被客户接受后，项目按以下规则展开：

- `QuoteItem.type = Construction`：生成 `ProjectTask`，按 `category/modular` 归入施工阶段。
- `QuoteItem.type = Material`：生成 `MaterialPlan`。
- `QuoteItem.space`：写入任务 `zone`，供项目经理定位施工区域。
- 阶段权重按施工成本计算，项目金额仍以报价快照为准。

这样客户确认的是“按区域解释的方案报价”，项目经理执行的是“按施工分项组织的工作包”，两端共享同一份报价事实。

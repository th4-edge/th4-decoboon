# 装得清报价体系重构总设计

> 版本：v1.0 · 2026-09-13  
> 重构原则：不迁移旧报价表，不保留 `com.th4.edge.design` 导入实现，不从旧字段做兼容。可以删除原报价结果、设计分项和套餐实例，按目标模型重新建设。  
> 业务目标：同时支持套餐报价、自定义报价和套餐+自定义混合报价，并让六类家装业务统一进入项目施工、增减项、供应商、成本和账务体系。

## 1. 重构范围

> 实施结果：已完成 `com.th4.edge.design` 删除，已建立 `com.th4.edge.decoboon.catalog / pack / quote`，真实导入项目库 537 条，套餐模板 1 条，已通过设计师账号生成套餐报价和自定义报价。

本次重构覆盖：

```text
家装项目分类与可售项目库
套餐模板
套餐报价
自定义报价
套餐扣减、升级、替换和增项
报价版本与客户确认
项目合同基线
项目执行
增减项
供应商和成本
应收、应付和台账
```

本次明确不做：

- 不迁移旧 `Quotation`、`PackQuote`、`ConstructionQuote`、`MaterialQuote` 数据。
- 不兼容旧 `com.th4.edge.dr.*` 包结构。
- 不把旧 `bim.construct.Construction`、`bim.material.Material` 继续作为新报价主数据。
- 不保留“施工报价表、主材报价表、套餐报价表、扣减报价表”各自保存金额的实现。
- 不允许旧前端接口反向限制新领域模型。

## 2. 导入代码的问题

当前导入的 `src/main/java/com/th4/edge/design` 有 76 个 Java 文件，但所有文件仍然声明为：

```text
com.th4.edge.dr.design.*
```

同时依赖不存在或不属于当前工程的：

```text
com.th4.edge.dr.bim.*
com.th4.edge.dr.market.*
com.th4.edge.dr.oa.*
com.th4.edge.dr.account.*
```

这不是普通编译错误，而是整套报价设计来自另一个工程边界。继续修包名只会把错误结构带进装得清。

更严重的是领域模型问题：

```text
Quotation
  ├─ PackQuote
  ├─ PackMeasureQuote
  ├─ PackItemDeductQuote
  ├─ ConstructionQuote
  ├─ MaterialQuote
  ├─ UpgradeQuote
  └─ QuoteTemplate
```

它把“报价来源”和“报价事实”混在一起：

- 套餐是一套报价表。
- 施工是一套报价表。
- 主材是一套报价表。
- 扣减又是一套报价表。
- 升级又是一套报价表。
- `Quotation` 自己再保存套餐金额、施工金额、主材金额、扣减金额、其他金额、设计费、管理费和税金。

最终结果是同一个报价行可能出现多个版本、空值或重复计算，项目、供应商和财务无法确定唯一事实来源。

## 3. 重构后的总体结论

套餐报价和自定义报价共用一套报价内核：

```text
                套餐模板
                   ↓
客户房屋 + 套餐模板 ─────→ 套餐生成策略
                                  ↓
                         统一 Quote / QuoteVersion
                                  ↑
客户房屋 + 区域测量 ─────→ 自定义生成策略
                                  ↑
             套餐扣减 / 升级 / 替换 / 增项
```

套餐报价和自定义报价的区别只在**报价行的生成方式和初始数量**，不在最终数据结构。

无论是套餐、施工、主材、软装、定制、电器还是综合项目，最终都统一成为：

```text
QuoteVersion
  └─ QuoteSection
       └─ QuoteLine
            ├─ ItemType
            ├─ SellableItem / ItemVariant
            ├─ Space
            ├─ Quantity
            ├─ Price Components
            ├─ Cost Components
            ├─ Formula
            └─ Snapshot
```

## 4. 领域边界

### 4.1 项目库域 Catalog

回答：“企业能卖什么、怎么计价、如何施工或供应？”

```text
ItemCategory
SellableItem
ItemVariant
ConstructionItemDetail
MaterialItemDetail
SoftFurnitureItemDetail
CustomFurnitureItemDetail
ApplianceItemDetail
GeneralItemDetail
```

六类业务共享一个 `SellableItem` 根，类型特有字段放在各自明细实体，完整设计见 `docs/design/11-家装核心业务对象标准化设计.md`。

### 4.2 套餐模板域 Pack

回答：“企业经营的标准套餐包含什么、按什么规则带入报价？”

```text
PackageTemplate
PackageSection
PackageLine
PackageRule
PackageOption
PackageUpgradeRule
```

套餐是报价模板，不是客户报价事实。套餐被修改，不应直接改变历史报价。

### 4.3 报价域 Quote

回答：“这个客户、这套房子现在具体报了多少钱？”

```text
Quote
QuoteVersion
QuoteSection
QuoteLine
QuoteLineComponent
QuoteAdjustment
QuoteSummary
QuoteApproval
```

报价保存的是客户确认时的完整快照，不保存对当前商品库价格的实时引用。

### 4.4 设计域 Design

回答：“设计师准备如何设计这个房子？”

```text
DesignScheme
DesignSpace
DesignSelection
DesignRequirement
DesignMaterialBoard
```

设计选择可以修改；进入报价后生成快照。设计与报价分开保存，避免报价变动反向污染设计方案。

### 4.5 项目域 Project

回答：“合同确认后具体要施工、采购、交付和安装什么？”

```text
Project
ProjectBaseline
ProjectStage
ProjectTask
MaterialPlan
PurchaseOrder
DeliveryPlan
InstallationTask
ManufacturingOrder
Expense
```

项目执行只能引用已确认报价或已批准变更，不能重新读取当前目录价格。

### 4.6 变更域 Change

回答：“确认报价之后，多做了、少做了、换品牌了或调价了多少钱？”

```text
ChangeOrder
ChangeOrderItem
ChangeApproval
ChangeProjection
```

增减项必须独立记录，不能覆盖已确认报价。

### 4.7 合作方域 Partner

回答：“谁提供材料、服务、劳务、生产或安装？”

```text
Partner
PartnerItem
PartnerPrice
PartnerContract
```

供应商、工厂、劳务班组、安装队、物流商和服务商统一使用 `Partner` 模型。

### 4.8 财务域 Finance

回答：“客户应收多少、供应商应付多少、项目实际利润多少？”

```text
Receivable
Receipt
Payable
Payment
Ledger
ProjectCost
ProjectProfit
```

财务以合同、变更单、采购单、工单和费用单为来源，不从实时目录直接计算。

## 5. 套餐与自定义报价的统一模型

### 5.1 Quote

`Quote` 是报价聚合根，负责客户、房屋、设计、状态和业务归属。

```text
Quote
├─ quoteId
├─ quoteNo
├─ title
├─ company
├─ store
├─ team
├─ owner
├─ customer
├─ building
├─ designScheme
├─ mode                 Package/Custom/Hybrid
├─ status               Draft/Calculated/Published/Accepted/Rejected/Contracted
├─ currentVersion      当前版本
├─ packageTemplate     可选，套餐路线使用
└─ versions            报价版本集合
```

一个 `Quote` 可以有多个版本，但只有一个当前版本。

### 5.2 QuoteVersion

`QuoteVersion` 是不可变报价版本。

```text
QuoteVersion
├─ quote
├─ versionNo
├─ sourceMode           Package/Custom/Hybrid
├─ packageSnapshot      套餐快照，可空
├─ area
├─ spaceSnapshot        房屋和区域快照
├─ subtotal
├─ discountAmount
├─ discountRate
├─ managementFee
├─ designFee
├─ taxAmount
├─ totalAmount
├─ totalCost
├─ grossProfit
├─ formulaVersion
├─ publishedAt
└─ acceptedAt
```

所有汇总金额由报价行计算生成，禁止前端直接写入。

### 5.3 QuoteSection

用于组织和展示报价，不参与金额计算。

```text
QuoteSection
├─ quoteVersion
├─ type                按空间/施工/主材/软装/定制/电器/综合/套餐分组
├─ name
├─ sort
└─ lines
```

客户视图可以按空间分组，项目经理视图可以按施工阶段分组，财务视图可以按成本类型或供应商分组。结构是视图，不改变报价行事实。

### 5.4 QuoteLine

所有报价来源最终统一成 `QuoteLine`。

```text
QuoteLine
├─ lineNo
├─ quoteVersion
├─ section
├─ itemType             施工/主材/软装/定制/电器/综合
├─ item                 SellableItem，保存来源引用
├─ variant              ItemVariant，可空
├─ packageLine          套餐来源行，可空
├─ parentLine           套餐替换/升级关系，可空
├─ space                施工或交付区域，可空
├─ sourceMode           Package/Custom/Hybrid
├─ lineRole             Base/Option/Upgrade/Add/Deduct/Replace/Gift
├─ nameSnapshot
├─ brandSnapshot
├─ modelSnapshot
├─ specSnapshot
├─ unitSnapshot
├─ quantity
├─ quantityBasis
├─ formulaSnapshot
├─ taxRateSnapshot
├─ saleAmount
├─ costAmount
├─ discountAmount
├─ netAmount
├─ included            是否包含在套餐基线内
├─ sort
└─ remark
```

`QuoteLine` 不允许按业务类型拆成 `ConstructionQuote`、`MaterialQuote` 等多套实体。类型差异通过 `itemType`、`SellableItem` 类型明细和组件表达。

### 5.5 QuoteLineComponent

报价行的金额由组件组成，而不是只保存一个材料和人工。

```text
QuoteLineComponent
├─ quoteLine
├─ componentType       Material/Labor/Auxiliary/Machine/Freight/Installation/Service/Tax/Other
├─ componentName
├─ quantity
├─ unitPrice
├─ saleAmount
├─ costAmount
├─ supplier
├─ priceSource
└─ formula
```

六类业务的组件差异：

| 类型 | 常见销售组件 | 常见成本组件 |
| --- | --- | --- |
| 施工 | 人工、辅材、机械、措施 | 班组、工资、辅材、机械 |
| 主材 | 材料、安装、运输 | 采购、损耗、运费、安装 |
| 软装 | 家具、物流、安装 | 商品、物流、安装 |
| 定制 | 柜体、门板、台面、五金、安装 | 板材、五金、工厂、安装 |
| 电器 | 设备、附件、配送、安装 | 设备、附件、物流、安装 |
| 综合 | 服务费、管理费、设计费 | 费用、人力、外部服务 |

### 5.6 QuoteAdjustment

套餐扣减、升级、替换、赠送和自定义增项统一使用报价调整。

```text
QuoteAdjustment
├─ quoteVersion
├─ sourceLine           被调整的套餐或报价行
├─ replacementLine      替换后的报价行
├─ adjustmentType       Include/Exclude/Deduct/Upgrade/Replace/Gift/Add
├─ reason
├─ deltaAmount
├─ deltaCost
├─ customerConfirmRequired
└─ status
```

套餐扣减不再单独建立 `PackItemDeductQuote` 表，避免扣减金额脱离被扣减分项。

## 6. 两条报价路线

### 6.1 套餐报价路线

目标：快速形成标准报价，同时允许设计师按房屋实际情况扣减、升级和增补。

```text
选择客户和房屋
  → 选择套餐模板
  → 录入建筑面积/实测面积
  → 系统按套餐规则生成基础报价行
  → 设计师确认套餐包含项
  → 处理扣减项
  → 处理升级和替换项
  → 追加自定义施工/主材/软装/电器/综合项
  → 服务端重新计算
  → 生成报价版本
  → 客户确认
```

套餐生成规则至少包括：

- 套餐标准面积。
- 项目包含数量或折算数量。
- 超出面积加价。
- 未包含面积的扣除。
- 可选项目和升级项目。
- 项目是否允许扣减。
- 项目是否允许替换。
- 替换后的差价计算。
- 最低保留金额。

套餐路线关键约束：

- 套餐模板只能生成报价草稿，不能直接成为合同。
- 套餐基础行、扣减行、升级行必须可以追溯到套餐来源。
- 最终报价只保存 `QuoteLine` 和 `QuoteAdjustment` 快照。
- 套餐模板更新不影响已完成报价版本。

### 6.2 自定义报价路线

目标：按实际空间和设计选择逐项生成报价。

```text
选择客户和房屋
  → 量房并建立 DesignSpace
  → 选择施工/主材/软装/定制/电器/综合项目
  → 为每个项目填写空间和工程量
  → 系统按企业公式计算组件
  → 可选升级项和替换项
  → 生成报价版本
  → 客户确认
```

自定义路线不走套餐模板，但仍使用同一套：

- `SellableItem`。
- `PriceBook`。
- `FormulaRule`。
- `QuoteLine`。
- `QuoteLineComponent`。
- 报价汇总和版本机制。

### 6.3 混合报价路线

混合报价是最常见的真实业务。

```text
套餐基础
  + 套餐升级
  + 套餐替换
  - 套餐扣减
  + 自定义施工项
  + 自定义主材项
  + 软装家具
  + 全屋定制
  + 电器设备
  + 综合费用
  = 最终报价版本
```

混合报价最终仍然只是一份 `Quote`、一个 `QuoteVersion` 和一组统一 `QuoteLine`，不能拆成套餐报价单、施工报价单、主材报价单三份单据。

## 7. 计价与成本路线

### 7.1 销售价计算

```text
lineSaleAmount =
    materialSale
  + laborSale
  + auxiliarySale
  + machineSale
  + freightSale
  + installationSale
  + serviceSale
  + otherSale

lineNetAmount = lineSaleAmount - lineDiscountAmount
```

套餐折算、数量换算、损耗、最低计费量和取整由 `FormulaRule` 统一计算。

### 7.2 成本计算

```text
lineCostAmount =
    materialCost
  + laborCost
  + auxiliaryCost
  + machineCost
  + freightCost
  + installationCost
  + productionCost
  + outsourcingCost
  + otherCost
```

成本来源可以是：

- 企业成本本。
- 供应商报价。
- 劳务班组价格。
- 工厂定制价格。
- 项目实际采购价。
- 财务手工调整。

设计报价只保存预计成本或确认成本，实际成本由项目执行单据形成。

### 7.3 报价汇总

```text
subtotal       = Σ lineNetAmount
discountAmount = Σ lineDiscountAmount + 整单折扣
managementFee  = 受控公式
designFee      = 受控公式或 GeneralItem
taxAmount      = 按税务规则计算
totalAmount    = subtotal - 整单折扣 + 管理费 + 设计费 + 税金
totalCost      = Σ lineCostAmount
grossProfit    = totalAmount - totalCost
```

`Quotation` 不应再保存 `packQuoteAmount/materialQuoteAmount/constructionQuoteAmount/deductAmount` 等来源金额字段。来源金额通过报价行和汇总视图计算。

## 8. 报价状态机

```text
DRAFT
  → CALCULATED
  → PENDING_REVIEW
  → PUBLISHED
  → ACCEPTED / REJECTED
  → CONTRACTED
  → SUPERSEDED
```

规则：

- `DRAFT` 可编辑报价行。
- `CALCULATED` 必须通过服务端计价校验。
- `PENDING_REVIEW` 可按企业配置进入负责人审核。
- `PUBLISHED` 生成客户可见的不可变版本。
- `ACCEPTED/REJECTED` 记录客户确认结果。
- `CONTRACTED` 生成项目合同基线。
- 新版本发布后，旧版本标记 `SUPERSEDED`，不删除。

## 9. 项目、变更和财务闭环

### 9.1 合同基线

客户接受报价后：

```text
QuoteVersion
  → ProjectBaseline
  → ProjectStage / ProjectTask / MaterialPlan / DeliveryPlan
```

合同基线保留报价行快照，不允许随着商品目录变化而变化。

### 9.2 增减项

```text
ChangeOrder
├─ project
├─ contractBaseline
├─ changeType
├─ reason
├─ customerApproval
├─ amountDelta
├─ costDelta
└─ items

ChangeOrderItem
├─ sourceQuoteLine
├─ changeType           Add/Remove/Replace/Quantity/Price
├─ oldQuantity
├─ newQuantity
├─ oldAmount
├─ newAmount
├─ amountDelta
├─ costDelta
└─ executionAction
```

变更确认后更新：

- 合同总额。
- 项目预算。
- 施工任务。
- 材料或采购需求。
- 应收计划。
- 应付预测。

### 9.3 供应商

| 类型 | 供应关系 |
| --- | --- |
| 施工 | 劳务班组、施工队、分包商 |
| 主材 | 品牌商、经销商、工厂、仓库 |
| 软装 | 家具供应商、物流商、安装队 |
| 定制 | 定制工厂、板材商、五金商、安装队 |
| 电器 | 渠道商、品牌商、安装服务商 |
| 综合 | 服务商、费用供应商、内部团队 |

### 9.4 财务

```text
报价确认 → 应收计划 → 回款
项目执行 → 采购/工单/费用 → 应付 → 付款
项目完成 → 成本归集 → 项目利润
```

报价金额、合同金额、变更金额、已确认产值、实际成本和付款金额必须分别保存。

```text
project/task/*
project/material-plan/*
project/delivery/*

change/order/*
change/item/*

partner/partner/*
partner/item/*

finance/receivable/*
finance/payable/*
finance/payment/*

```

统一规则：

- 使用 Provider，不新增 Controller。
- 不新增 DTO、VO、Request、Response 包装类。
- 路由按领域/对象/能力命名。
- 查询必须带企业数据范围。
- 报价金额、成本和汇总只能服务端计算。

## 12. 权限边界

| 角色 | 权限 |
| --- | --- |
| 企业负责人 | 可维护项目库、套餐、价格和审批 |
| 材料员/采购 | 可维护主材、软装、电器、供应商和成本 |
| 施工负责人 | 可维护施工工艺、工序、班组和施工价格 |
| 设计师 | 可选择项目和报价，不可修改企业基础价格 |
| 门店店长 | 可审核本门店报价和折扣 |
| 项目经理 | 可查看合同基线、执行和变更，不可改客户报价历史 |
| 财务 | 可查看应收、应付、成本和利润，不可改报价快照 |

套餐和自定义报价都不能绕过 `Company`、`DataScope` 和 Provider 权限。

## 15. 验收标准

重构完成后必须满足：

1. 套餐报价和自定义报价使用同一个 `Quote`、`QuoteLine` 和计价上下文。
2. 不存在 `PackQuote`、`ConstructionQuote`、`MaterialQuote` 三套并列报价表。
3. 套餐扣减、升级、替换和自定义增项都能追溯到来源行。
4. 施工、主材、软装、定制、电器和综合全部使用同一个 `SellableItem` 根。
5. 报价发布后是快照，目录、价格、供应商变化不影响历史报价。
6. 客户接受报价后生成统一合同基线。
7. 项目增减项不覆盖原报价，只生成变更单。
8. 材料、施工、定制和安装都能关联供应商或合作方。
9. 应收、应付和项目利润可追溯到具体报价行或变更行。
10. 删除导入包后工程重新达到 `mvn -o -q -DskipTests package` 通过。

## 16. 最终判断

装得清下一阶段的正确方向不是修复导入报价代码，而是执行一次报价域重构：

```text
一个项目库
一个套餐模型
一个报价模型
一条计价链路
一条合同基线
一条变更链路
一套供应商模型
一套财务事实模型
```

套餐报价、自定义报价和混合报价都是这条统一链路的入口，不是三套独立系统。

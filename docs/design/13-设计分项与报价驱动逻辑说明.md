# 设计分项与报价驱动逻辑说明

> 目的：解释 `DesignItem` 为什么存在、它和 `CatalogItem / PackageLine / QuoteLine` 的区别，以及套餐报价、自定义报价和后续项目、变更、供应商、账务之间的完整驱动关系。  
> 结论：`DesignItem` 是“设计方案选择行”，`QuoteLine` 是“客户报价快照行”；两者字段相似，但不是重复数据。

## 1. 先用一句话理解 DesignItem

`DesignItem` 回答的问题是：

> “这套房子的这个方案，在这个区域准备用什么项目、做多少工程、预计多少钱？”

`QuoteLine` 回答的问题是：

> “客户当时收到的这份报价中，这个项目具体报了多少、成本多少、按什么公式、是否已经确认？”

`CatalogItem` 回答的问题是：

> “企业当前允许销售哪些施工、主材、软装、定制、电器和综合项目？”

三者是不同时间、不同责任面的对象。

## 2. 四层模型

```text
第一层：行业/企业项目定义
CatalogItem
  └─ ConstructionItemDetail / MaterialItemDetail / ...

第二层：套餐模板配置
PackageTemplate
  └─ PackageSection
      └─ PackageLine

第三层：具体房屋的设计方案选择
Design
  └─ DesignSpace
      └─ DesignItem

第四层：客户报价快照
Quote
  └─ QuoteLine
      └─ QuoteComponent
```

其中：

- `CatalogItem` 是长期存在、可被很多客户重复使用的企业基础资料。
- `PackageLine` 是套餐模板中的标准配置。
- `DesignItem` 是某一套房、某一套设计方案中的实际选择。
- `QuoteLine` 是某个报价版本冻结后的商务事实。

## 3. DesignItem 的准确定位

`DesignItem` 不是材料库，也不是报价单。

它承担的是“设计决策落地”：

```text
设计师选择项目
  → 选择区域
  → 填写工程量
  → 后端读取企业项目库价格和公式
  → 形成该方案的分项设计金额
```

当前 `DesignItem` 的关键字段可以按职责理解：

| 字段组 | 字段 | 作用 |
| --- | --- | --- |
| 归属 | `design` | 属于哪套设计方案 |
| 空间 | `space` | 主卧、客餐厅、厨房等，综合项目可为空 |
| 类型 | `type` | 施工、主材、软装、定制、电器、综合 |
| 分类 | `category` | 拆除、水电、瓷砖、木门等 |
| 来源 | `catalogItem` | 引用企业报价项目库 |
| 展示快照 | `name/brand/spec/unit` | 设计时选择的项目摘要 |
| 工程量 | `quantity` | 该区域实际工程量 |
| 价格 | `materialPrice/manualPrice/costPrice` | 从项目库复制的设计参考价格 |
| 规则 | `pricingMode/formula` | 企业计价方式和公式 |
| 设计结果 | `amount/cost` | 服务端计算结果 |
| 工艺 | `criterion` | 用于向客户解释工艺和标准 |
| 排序与说明 | `sort/remark/images` | 方案展示和后续谈单 |

核心原则：

- 设计师不能手工修改企业基础价格。
- `DesignItem` 的价格是从 `CatalogItem` 复制的设计参考值。
- `DesignItem.amount` 是可变的设计金额，不是最终合同金额。
- `DesignItem` 只属于一个设计方案和一个空间。

## 4. CatalogItem 与 DesignItem 的关系

假设企业项目库中有：

```text
CatalogItem
名称：瓷砖--马可波罗800*800（展厅款）
类型：Material
单位：㎡
材料价：85.60
公式：(材料单价) × 工程量
```

这条数据是所有客户、所有设计都可以使用的企业基础资料。

到了某个客户的设计方案中：

```text
DesignItem
design：联调客户现代简约方案 V2
space：客餐厅
catalogItem：马可波罗800*800
quantity：43.27㎡
materialPrice：85.60
formula：(材料单价) × 工程量
amount：3,703.91
```

这时 `DesignItem` 才表示：

> 这位客户的客餐厅方案中，实际选择了 43.27㎡ 的马可波罗瓷砖，预计金额为 3,703.91 元。

目录价格变化不会反向修改已经保存的设计选择；设计师重新编辑该设计分项时，才会重新从项目库读取最新企业价格。

## 5. 为什么不能直接让 QuoteLine 引用 CatalogItem

如果报价直接从目录生成：

```text
CatalogItem → QuoteLine
```

会缺少具体项目上下文：

- 哪个客户。
- 哪套设计方案。
- 哪个区域。
- 实际工程量是多少。
- 设计师做了哪些替换和升级。
- 客户提出了哪些特殊要求。
- 为什么报价是这个金额。

因此自定义报价必须先有设计决策：

```text
CatalogItem
  → DesignItem
      → QuoteLine
```

## 6. 为什么 QuoteLine 又不能直接继续被设计修改

报价一旦发给客户，就是客户看到的商务承诺。

如果客户确认报价后再修改 `DesignItem`：

```text
DesignItem 修改
  → QuoteLine 跟着变化
```

会发生：

- 客户看到的报价和历史报价不一致。
- 已转项目、采购和应付金额无法追溯。
- 设计师可以无意中改变客户已经确认的价格。
- 财务无法确认到底按哪个版本收钱。

因此报价必须从设计项生成快照：

```text
DesignItem
  → 报价时复制全部商务字段
  → QuoteLine
```

此后：

- 项目库变化不影响 `QuoteLine`。
- 设计项变化不影响历史 `QuoteLine`。
- 需要改价时重新生成报价版本或走增减项。

## 7. 哪些字段会从 DesignItem 复制到 QuoteLine

```text
DesignItem
├─ type
├─ category
├─ catalogItem
├─ space
├─ name
├─ brand
├─ spec
├─ unit
├─ quantity
├─ materialPrice
├─ manualPrice
├─ costPrice
├─ pricingMode
├─ amount
├─ cost
├─ formula
└─ criterion
        ↓ 生成报价快照
QuoteLine
├─ type
├─ category
├─ catalogItem
├─ designItem
├─ space
├─ 名称/品牌/规格/单位快照
├─ 数量快照
├─ 材料价/人工价/成本价快照
├─ 计价方式/公式快照
├─ 金额/成本快照
└─ 报价行角色和组件
```

`QuoteLine.designItem` 只是来源追溯，不是运行时的可变引用。项目、变更和财务计算应以 `QuoteLine` 为准。

## 8. 自定义报价的完整驱动链

```text
客户
→ 房屋信息
→ 量房
→ Design
→ DesignSpace
→ 企业报价项目库选择 CatalogItem
→ 生成 DesignItem
→ 服务端按 CatalogItem 公式计算
→ 生成 Quote
→ DesignItem 快照为 QuoteLine
→ 报价汇总
→ 客户确认
→ ProjectBaseline
```

这条链路适用于：

- 按区域逐项设计。
- 按实际尺寸计价。
- 设计师自由组合施工和主材。
- 客户要求差异较大的项目。

## 9. 套餐报价的驱动链

套餐报价不是再建立一套报价明细，而是更换报价行的来源。

```text
PackageTemplate
→ PackageSection
→ PackageLine
→ 根据房屋面积和套餐规则计算数量
→ 生成 Quote
→ PackageLine 转化为 QuoteLine
→ 客户确认
→ ProjectBaseline
```

套餐路线中的 `PackageLine` 相当于“标准设计模板行”。

例如：

```text
PackageLine
项目：马可波罗800*800
标准含量：20㎡
允许扣减：是
```

客户房屋为 118.09㎡，标准套餐为 100㎡时：

```text
比例 = 118.09 / 100
QuoteLine.quantity = 20 × 1.1809
```

最终客户看到的仍然是统一 `QuoteLine`。

## 10. 自定义方案与套餐为什么使用不同驱动入口

| 项目 | 自定义报价 | 套餐报价 |
| --- | --- | --- |
| 起始来源 | `CatalogItem` | `PackageLine` |
| 初始数量 | 设计师或量房计算 | 套餐规则和面积折算 |
| 空间结构 | 按实际区域和设计空间 | 按套餐分组，可映射区域 |
| 设计修改 | 修改 `DesignItem` | 套餐扣减、升级、替换 |
| 报价输出 | `QuoteLine` | `QuoteLine` |
| 项目输出 | 统一合同基线 | 统一合同基线 |

两条路线的差异只在报价行生成方式，最终都进入：

```text
Quote / QuoteLine / QuoteComponent
```

## 11. 混合报价的驱动方式

真实家装业务通常是混合报价：

```text
套餐基础行
+ 套餐升级行
+ 套餐替换行
- 套餐扣减行
+ 自定义 DesignItem 行
= 同一个 QuoteVersion
```

建议混合报价的处理顺序：

1. 先根据套餐模板生成套餐基础 `QuoteLine`。
2. 生成套餐调整 `QuoteLine`，标记为升级、替换或扣减。
3. 将自定义设计分项生成自定义 `QuoteLine`。
4. 所有报价行统一进入同一个报价版本。
5. 服务端统一计算折扣、税金、成本和其他费用。

## 12. 实际数据示例

当前项目库中存在真实项目：

```text
CatalogItem
名称：瓷砖--马可波罗800*800（展厅款）
类型：主材
单位：㎡
材料价：85.60
公式：(材料单价) × 工程量
```

自定义设计中：

```text
DesignItem
方案：联调客户现代简约方案 V2
区域：客餐厅
工程量：43.27㎡
设计金额：3,703.91
```

生成报价后：

```text
QuoteLine
报价：Q1789276506924
来源：DesignItem
项目：瓷砖--马可波罗800*800（展厅款）
数量：43.27㎡
材料价：85.60
金额：3,703.91
公式：(材料单价) × 工程量
角色：基础项目
```

后续企业把马可波罗材料价改成 90 元：

- `DesignItem` 编辑时可以读取新价格。
- 历史 `QuoteLine` 仍然保持 85.60 元。
- 历史报价、项目和财务不会变化。

## 13. 设计变更和报价版本

```text
方案 V1
→ 报价 Q1
→ 客户不接受
→ 修改 DesignItem
→ 生成报价 Q2

Q1 仍然保留
Q2 成为新的当前报价
```

规则：

- 修改设计时，新增或更新可变 `DesignItem`。
- 生成报价时，创建新的 `Quote` 版本或新报价快照。
- 旧 `QuoteLine` 不更新。
- 客户确认的是具体报价版本，不是某个可变设计项。

## 14. 项目、增减项、供应商和账务为什么引用 QuoteLine

报价确认后：

```text
QuoteLine
→ ProjectBaseline
→ ProjectTask / MaterialPlan / DeliveryPlan / InstallationTask
→ PurchaseOrder / WorkOrder / Expense
→ Payable / Receivable / Ledger
```

原因：

- 报价行已经冻结价格、成本和公式。
- 项目必须按客户确认的价格执行。
- 采购和应付必须能追溯到报价来源。
- 增减项必须基于原 `QuoteLine` 计算差异。
- 财务不能重新读取当前目录价格。

增减项示例：

```text
原 QuoteLine：马可波罗800*800，43.27㎡，3,703.91 元
客户改选升级砖：材料价 +20 元/㎡
ChangeOrderItem：
  sourceQuoteLine：原报价行
  changeType：Replace
  amountDelta：43.27 × 20
```

原报价不变，变更单记录差异。

## 15. 一句话理解字段“重复”

`DesignItem` 和 `QuoteLine` 都有：

```text
name
quantity
price
amount
formula
```

但含义不同：

| 字段 | DesignItem | QuoteLine |
| --- | --- | --- |
| 名称 | 设计选择摘要，可随方案调整 | 客户确认的报价名称快照 |
| 数量 | 实际设计工程量 | 报价版本冻结数量 |
| 价格 | 企业设计参考价格 | 客户报价商务价格 |
| 金额 | 设计预算金额 | 报价合同依据 |
| 公式 | 设计解释规则 | 报价版本冻结规则 |

所以这不是数据重复，而是**同一业务事实在不同阶段的版本快照**。

## 16. 最终推荐理解

```text
CatalogItem：
企业可以卖什么？

PackageLine：
套餐标准配置是什么？

DesignItem：
这套房子的这个方案准备做什么、做多少？

QuoteLine：
客户当时确认的报价是什么？

ProjectTask / MaterialPlan：
项目实际要施工、采购和交付什么？

ChangeOrderItem：
客户确认后改了什么，增减了多少钱？

Payable / Receivable：
这笔业务最终要收谁的钱、付给谁钱？
```

`DesignItem` 是设计阶段的业务事实；`QuoteLine` 是商务阶段的快照事实；项目、供应商和账务只能继续引用 `QuoteLine` 及其后续执行单据，不能反向读取可变的 `DesignItem` 或 `CatalogItem` 重新计算历史金额。

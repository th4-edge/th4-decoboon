# 装得清：以客户-房屋为根的多业务条线强闭环落地设计

> 日期：2026-09-14  
> 适用范围：`com.th4.edge.decoboon`  
> 联调账号：18660219919（设计师小林）  
> 核心结论：Customer 表示经营关系，Property 表示装修标的，所有报价、合同、项目、材料、账务单据都必须绑定 `propertyId`。

## 1. 目标架构

```text
Customer 客户
  -> Property 房屋
      -> Measure 量房
      -> Design 设计方案
          -> DesignItem 设计分项
      -> Quote 报价版本
          -> QuoteLine 报价快照
      -> ProjectContract 合同
          -> ContractLine 合同基线行
          -> ContractChange 合同变更单
      -> Project 项目
          -> ProjectStage 阶段
          -> ProjectTask 施工任务
          -> MaterialPlan 材料计划
              -> PurchaseOrder 采购订单
                  -> Payable 应付（确认下单时形成）
                  -> GoodsReceipt 到场验收（回填账期和实际成本）
      -> Receivable 应收计划
          -> Receipt 收款
      -> Settlement 结算
```

业务根不是 Customer，而是：

```text
Customer + Property
```

一个客户可以拥有多套房屋，每套房屋独立设计、报价、签约、施工、采购、账务和结算，不允许跨房屋串单。

## 2. 领域对象

| 对象 | 职责 | 是否允许修改 |
| --- | --- | --- |
| `Customer` | 客户经营关系、营销归属、客户状态 | 可修改 |
| `Property` | 装修房屋、量房和业务执行根 | 可修改基础信息 |
| `Measure` | 一次量房事实、尺寸、诉求、现场原始结构 | 可追加，不覆盖历史 |
| `Design` | 某房屋的一套设计方案 | 报价确认前可修改 |
| `DesignItem` | 设计选品、区域和工程量 | 报价确认前可修改 |
| `Quote` | 客户确认的报价版本 | 状态可推进，不直接改写快照 |
| `QuoteLine` | 报价生成时的商业快照 | 不可修改 |
| `ProjectContract` | 客户-房屋-报价之间的合同基线 | 签约后只能走变更 |
| `ContractLine` | 合同金额、成本、公式的不可变快照 | 不可修改 |
| `ContractChange` | 合同金额变更事实 | 审批后不可修改 |
| `Project` | 某个已生效合同的履约容器 | 只由履约过程推进 |
| `ProjectStage` | 施工阶段 | 项目过程推进 |
| `ProjectTask` | 施工任务 | 项目过程推进 |
| `MaterialPlan` | 合同材料行的项目预计划 | 采购过程推进 |
| `PurchaseOrder` | 按材料计划释放的采购单 | 采购过程推进 |
| `GoodsReceipt` | 材料到场和验收事实 | 不可修改 |
| `Receivable` | 合同或变更生成的应收节点 | 由收款核销 |
| `Payable` | 采购、工单或费用生成的应付 | 由付款核销 |
| `Settlement` | 项目最终收入、成本、利润闭账 | 结清后关闭 |

## 3. 客户与房屋状态

### 3.1 客户状态

```text
New
  -> Following
  -> PendingMeasure
  -> Quoted
  -> Signed
  -> Serving
  -> Finished
New/Following/... -> Lost
```

客户状态是经营漏斗汇总，不再代表某套具体房屋的执行状态。

### 3.2 房屋状态

```text
PendingMeasure
  -> Measuring
  -> Measured
  -> Designing
  -> Quoted
  -> Contracted
  -> Serving
  -> Completed
```

房屋状态是业务执行口径，设计、报价、合同、项目均由当前房屋状态驱动。

### 3.3 量房

量房记录绑定：

```text
company / store / team / owner
customer
property
designer
```

记录内容包括：

- 量房时间和状态；
- 现场照片；
- 原始结构；
- 尺寸数据；
- 客户诉求；
- 设计师结论。

量房完成后，房屋进入 `Measured`，设计师可以开始方案设计。

量房数据通过 `property/measure/save` 持久化，记录实际量房时间、原始结构、区域长宽高、客户诉求复核、现场照片和设计师结论；客户详情中的“录入量房”入口进入 `/pages/customer/measure-record`。如果房屋已经进入报价、签约或施工阶段，补录历史量房只更新最近量房事实，不允许把房屋状态回退。

## 4. 设计与报价

设计方案必须绑定 Property：

```text
Design.property
Design.customer
Design.owner
```

报价版本必须绑定同一 Property：

```text
Quote.property
Quote.customer
Quote.design
```

报价行是快照：

```text
QuoteLine
├─ source CatalogItem
├─ property
├─ space
├─ type / category
├─ name / brand / spec / unit
├─ quantity
├─ materialPrice / manualPrice
├─ pricingMode
├─ amount / cost
└─ formula
```

一旦报价被客户确认：

```text
Quote.status = Accepted
```

同房屋其他有效报价自动进入：

```text
Quote.status = Superseded
```

`Superseded` 报价：

- 不再进入设计师待推进统计；
- 不再进入有效报价金额；
- 不再生成报价通知；
- 不允许再次确认或转项目；
- 只保留历史查看。

## 5. 报价确认到合同

### 5.1 客户确认

```text
Quote.Draft
  -> Quote.Submitted
  -> Quote.Accepted
```

接受操作会锁定 Property 行，确保同一房屋并发情况下也只能确认一份报价。

### 5.2 合同创建

客户确认报价后，设计师创建合同：

```text
Quote.Accepted
  -> ProjectContract.PendingSign / Signed
```

合同保存：

- `property`
- `customer`
- `quote`
- `baselineAmount`
- `currentAmount`
- `signedAt`
- `startDate`
- `planEndDate`
- `paymentTerms`
- `ContractLine` 快照行

合同金额必须来自报价，前端不能直接填写合同金额。

### 5.3 合同状态机

```text
Draft
  -> PendingSign
  -> Signed
  -> Effective
  -> Changing
  -> Completed
  -> Settled
  -> Terminated
```

合同草稿阶段还不创建项目。只有：

```text
Contract.Effective
```

才能创建项目、材料预计划和应收计划。

## 6. 合同到项目

合同生效事件：

```text
Contract.effective
  -> Project.Preparing
  -> Quote.Converted
  -> Property.Serving
  -> Customer.Serving
  -> ReceivablePlan generated
  -> MaterialPlan generated
```

项目映射规则：

```text
ContractLine(type=Construction)
  -> ProjectStage
  -> ProjectTask

ContractLine(type=Material)
  -> MaterialPlan

ContractLine(type=CustomFurniture)
  -> 后续全屋定制交付计划

ContractLine(type=SoftFurniture)
  -> 后续软装交付计划

ContractLine(type=Appliance)
  -> 后续电器交付计划

ContractLine(type=General)
  -> 后续综合服务或费用单
```

`ProjectTask` 和 `MaterialPlan` 保存 `ContractLine` 来源，确保后续执行不受报价或目录价格变化影响。

## 7. 材料、采购和应付

材料预计划不会在签约后直接下单，正确链路为：

```text
ContractLine(Material)
  -> MaterialPlan(Planned)
  -> 按施工阶段释放
  -> PurchaseOrder(Submitted / Approved / Ordered)
  -> GoodsReceipt
  -> MaterialPlan(PartiallyArrived / Arrived)
  -> Payable(Pending)
```

采购订单绑定：

```text
company
property
project
contract
materialPlan
supplier
quantity
unitPrice
amount
expectedAt
```

到场验收绑定：

```text
property
project
purchase
materialPlan
quantity
arrivalTime
inspector
images
```

确认下单时形成材料应付；到场时自动：

- 更新采购已到场数量；
- 更新采购状态；
- 更新材料计划状态；
- 回填应付账期起算日和实际到期日；
- 按本次实到数量确认实际材料成本。

## 8. 应收、收款和结算

合同生效后生成应收计划。当前默认规则：

```text
签约款 30%
开工款 40%
竣工尾款 30%
```

应收节点必须绑定：

```text
contract
property
project
customer
dueDate
amount
```

收款必须核销具体应收节点，不能直接修改项目已收金额。

结算条件：

```text
项目已完工
应收全部收清
应付全部付清
```

满足后：

```text
Project.Settled
Contract.Settled
Customer.Finished
```

## 9. 变更单

合同生效后，金额调整不能直接修改合同，必须创建合同变更单：

```text
ContractChange.Pending
  -> Approved / Rejected
```

变更通过后：

- 更新 `ProjectContract.currentAmount`；
- 更新 `Project.contractAmount`；
- 保留原合同基线；
- 后续应收、材料、项目和应付通过关联变更事实进行追溯。

## 10. 关键不变量

1. 一个客户可以有多个房屋。
2. 一个房屋可以有多套设计。
3. 一个房屋可以有多版报价。
4. 一个房屋最多一份客户确认报价。
5. 一个房屋最多一份合同（数据库唯一键 `uk_contract_property(property_id)`）。
6. 一个报价最多一份合同（数据库唯一键 `uk_contract_quote(quote_id)`）。
7. 一个合同最多一个项目（数据库唯一键 `uk_contract_project(project_id)`）。
8. 一个项目必须绑定合同、房屋、客户。
9. 材料计划必须绑定合同和合同材料行。
10. 采购必须来源材料计划。
11. 到场必须来源采购。
12. 应收必须来源合同或变更。
13. 应付必须来源采购、工单或费用。
14. 报价确认后设计、报价和项目关键数据只能通过变更调整。

数据库强约束：

```text
db_project_contract
UNIQUE (quote_id)                  -- 一份报价只能签一份合同
UNIQUE (property_id)               -- 一套房屋只能生成一份合同
UNIQUE (project_id)                -- 一份合同只能对应一个项目

db_project
UNIQUE (com_id, property_id)       -- 一套房屋只能生成一个项目
UNIQUE (quote_id)                  -- 一份报价只能生成一个项目
```

数据库核心索引：

```text
(com_id, customer_id, property_id)
(com_id, property_id, quote_id)
(com_id, property_id, contract_id)
(com_id, property_id, project_id)
(com_id, project_id, material_plan_id)
(com_id, project_id, purchase_id)
(com_id, purchase_id, receipt_id)
(com_id, contract_id, receivable_id)
```

## 13. 强闭环判断

至少满足以下条件，业务才算完整闭环：

- 没有 Property 不能创建报价；
- 没有客户确认报价不能创建合同；
- 没有生效合同不能创建项目；
- 没有合同行不能生成项目阶段、任务和材料计划；
- 没有材料计划不能采购；
- 没有到场记录不能生成材料应付；
- 没有应收节点不能登记对应回款；
- 没有全部结清不能完成最终结算。

# 项目权限与合同变更履约落地说明

> 落地日期：2026-09-15
> 对应迭代：C0 租户隔离与主链权限封口 + C1 合同变更到履约闭环

## 1. 项目域经营归属

项目、合同及其派生履约对象统一使用以下归属快照：

```text
company  -> 所属企业
store    -> 所属门店
team     -> 所属团队
owner    -> 经营负责人
```

归属来源固定为：

```text
Property.owner/store/team/company
  -> 缺失时 Customer.owner
  -> 子对象从最近父对象继承
```

项目经理、设计师、履约专员继续通过项目参与关系获得可见性，不覆盖经营 `owner`。

## 3. 历史回填

按以下链路解析，不猜测缺失值：

```text
Project -> Property
ProjectContract -> Project -> Property
ContractLine/ContractChange/ContractChangeItem -> Contract/Project -> Property
MaterialPlan/PurchaseOrder/GoodsReceipt -> Project -> Property
ProjectStage/ProjectTask/Acceptance/TaskNode/ProjectReport -> Project -> Property
```

回填要求：

1. `Property.owner` 优先，`Customer.owner` 仅在房屋负责人为空时回退。
2. 同一企业内复制 `store/team`，禁止跨企业继承。
3. 无房屋、无负责人或链路断裂的记录进入“项目归属待确认”报告。
4. 新数据保存时由服务端重新计算，不信任前端提交的 `companyId/storeId/teamId/ownerId`。

## 4. 合同变更履约映射

客户确认仅允许 `Approved` 变更；重复确认直接返回原结果。确认事务内执行：

```text
更新合同当前金额
-> 更新项目合同金额
-> 生成/冲减应收
-> 生成或调整施工任务
-> 生成或调整材料计划
-> 重算项目成本
-> 标记 CustomerConfirmed
```

五类映射：

| 变更类型 | 未开始/未采购 | 已开始/已采购 |
| --- | --- | --- |
| 新增 | 新增变更来源任务和材料计划 | 同左 |
| 取消 | 任务转 `Cancelled`，材料计划转 `Closed` | 保留原事实并生成现场差异动态 |
| 替换 | 关闭原范围，生成完整替代任务/材料计划 | 保留原事实，生成替代执行范围 |
| 调量 | 直接调整未开始/未采购对象 | 保留原事实，生成差异对象 |
| 调价 | 直接调整未开始/未采购对象金额 | 保留原事实，生成差异对象 |

生成的执行对象通过 `change_item_id` 追溯 `ContractChangeItem`，原报价和原合同行不变。

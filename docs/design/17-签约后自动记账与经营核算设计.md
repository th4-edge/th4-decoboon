# 17 签约后自动记账与经营核算设计

> 文档状态：draft_for_review  
> 日期：2026-09-20  
> 核心卖点：报价清晰、签约后账务清晰  
> 范围：合同生效后的应收、应付、成本、收付款、资金流水、自动核校和老板经营视图  
> 边界：装得清只做企业经营管理账和业务台账，不替代法定会计总账、税务申报和审计报告

## 1. 产品判断

装得清签约后的账务不能要求财务重复录入合同、采购和收付款。正确方式是：

```text
业务动作发生
-> 系统自动形成财务事实
-> 自动核算项目经营结果
-> 自动核校不同账本是否一致
-> 老板看到收入、回款、成本、利润和风险
-> 财务只处理确认、异常和调整
```

目标不是“多一个财务页面”，而是做到：

1. 合同生效后自动建立项目收入、应收计划和成本预算；
2. 材料采购和到货自动形成承诺成本、实际成本和应付；
3. 客户收款自动核销应收并写入资金流水；
4. 供应商付款自动核销应付并写入资金流水；
5. 合同变更自动调整未来应收、预算成本和项目执行范围；
6. 每次关键写入后自动核校；
7. Boss 能按项目、门店和全公司看清经营情况。

## 2. 四本管理账

同一笔业务只写一次事实，通过不同口径形成四本账：

| 账本 | 回答的问题 | 主要对象 |
| --- | --- | --- |
| 合同与收入账 | 签了多少、变更后多少、应收多少、已收多少 | `ProjectContract`、`Receivable`、`Receipt` |
| 成本与利润账 | 预算成本多少、已承诺多少、实际发生多少、利润多少 | `ContractLine`、`PurchaseOrder`、`GoodsReceipt`、`Payable`、`Settlement` |
| 资金与现金账 | 实际收了什么、付了什么、账户余额和现金流如何 | `Receipt`、`Payment`、`Ledger` |
| 风险与核校账 | 哪些账不一致、逾期、缺成本或超过预算 | ReconciliationIssue、BusinessAlert |

不得把“已收款”当成项目收入，也不得把“已付款”当成实际成本。

## 3. 自动记账事件

所有自动记账必须以业务事件为入口。事件包含：

```text
eventId
company
project
eventType
sourceType
sourceId
idempotencyKey
occurredAt
postedAt
status
failureReason
```

状态：

```text
Pending
Posted
ReconciliationRequired
Failed
Reversed
```

首批事件和写入结果：

| 业务事件 | 自动生成/更新 | 是否写现金流水 |
| --- | --- | --- |
| 合同签署 | 合同基线、签署归档，不生成项目 | 否 |
| 合同生效 | 唯一项目、项目收入基线、应收计划、预计成本预算、合同打印归档 | 否 |
| 合同变更客户确认 | 合同当前金额、未来应收、项目预算、任务和材料范围 | 否，除非产生实际退款/收款 |
| 采购单批准 | 承诺成本、材料执行范围 | 否 |
| 材料到货/入库 | 实际材料成本、供应商应付、材料计划状态 | 否 |
| 客户收款 | 核销应收、更新待收金额、收入流水 | 是，Income |
| 供应商/班组付款 | 核销应付、更新待付金额、支出流水 | 是，Expense |
| 项目费用确认 | 项目其他成本、应付或直接成本 | 视是否付款 |
| 完工/阶段验收 | 项目进度、可结算状态、收款触发条件 | 否 |
| 项目结算关闭 | 最终收入、成本、利润和结算快照 | 否 |
| 手工调整 | 调整账务事实或冲销错误流水 | 是/视方向 |

## 4. 合同生效自动联动

合同 `Effective` 后，在同一事务中完成：

```text
锁定合同当前金额
-> 创建唯一项目
-> 建立项目收入基线
-> 按合同收款计划生成应收
-> 按合同行建立预计成本预算
-> 建立项目材料计划和施工范围
-> 生成合同打印稿归档
-> 生成交接任务
```

财务结果：

- `contract.currentAmount` 是项目当前收入基线；
- `Receivable` 是客户应收，不是现金收入；
- 合同成本快照是预计成本，不是实际成本；
- 合同未提出采购前，不生成应付；
- 合同未实际收款前，不生成资金收入。

## 5. 成本分层

项目成本必须区分四层，不能混用：

| 层级 | 含义 | 来源 | 用途 |
| --- | --- | --- | --- |
| 预计成本 | 签约时预算 | 合同行成本快照 | 项目预算和预计毛利 |
| 承诺成本 | 已下单但未到货 | 已批准采购单 | 风险占用和超预算预警 |
| 实际成本 | 已实际发生 | 到货、入库、人工、费用确认 | 动态毛利 |
| 已付金额 | 实际支付现金 | Payment | 现金流和应付余额 |

关键公式：

```text
合同预计毛利 = 当前合同金额 - 预计成本
动态毛利 = 当前合同金额 - 已确认实际成本 - 预计未发生成本
最终毛利 = 最终结算收入 - 最终实际成本
应付余额 = 应付金额 - 已付金额
```

成本不完整时：

```text
costComplete = false
grossProfit = null
grossMargin = null
```

禁止以 0 成本计算或展示利润。

## 6. 应收自动联动

合同生效和变更负责建立或调整应收计划：

```text
合同生效 -> 生成首期、进度、尾款、质保金应收
合同变更确认 -> 调整未来未收节点
阶段完成 -> 触发对应应收
```

收款时：

```text
Receipt
-> 核销一个或多个 Receivable
-> 更新 receivedAmount 和状态
-> 生成 Ledger(Income)
-> 执行自动核校
```

核心不变量：

```text
合同当前金额 = 所有有效应收节点金额合计 + 已明确释放/核销的调整项
应收已收金额 = 关联收款核销金额合计
项目已收 = 有效 Receipt 金额合计
```

具体尾差规则必须冻结，不能静默吞掉差额。

## 7. 应付自动联动

应付由真实业务义务形成：

```text
采购到货/入库 -> 材料应付
人工/班组确认 -> 工资或项目款应付
费用确认 -> 费用应付
合同退货/折让 -> 冲减应付或生成调整
```

付款时：

```text
Payment
-> 核销一个或多个 Payable
-> 更新 paidAmount 和状态
-> 生成 Ledger(Expense)
-> 执行自动核校
```

核心不变量：

```text
应付已付金额 = 关联付款核销金额合计
项目已付 = 有效 Payment 金额合计
付款不重复增加项目实际成本
```

## 8. 自动核校

自动核校不是人工月报检查，而是在每次关键记账后和月结前执行。

核校类型：

| 类型 | 检查内容 |
| --- | --- |
| 合同-应收 | 合同当前金额与有效应收计划是否平衡 |
| 应收-收款 | 应收核销金额与收款金额是否一致 |
| 应付-付款 | 应付核销金额与付款金额是否一致 |
| 流水-来源 | Ledger 是否有来源单、金额和方向是否一致 |
| 项目-成本 | 预计、承诺、实际和已付成本是否可解释 |
| 成本完整性 | 是否有应计成本缺失 |
| 预算-实际 | 实际或承诺成本是否超过合同预算阈值 |
| 项目-结算 | 完工、验收、应收和应付是否满足结算条件 |
| 时间-期间 | 是否写入已关账期间 |

结果：

```text
Matched
Warning
Mismatch
Unverifiable
```

自动核校只能发现问题，不能悄悄改金额。修正必须通过调整、冲销、补录来源或正式变更完成。

## 9. Boss 经营视图

老板首页和经营驾驶舱至少回答：

### 现金与回款

- 当前账户余额；
- 本月收入、支出和净现金流；
- 应收总额、已收、未收和逾期；
- 未来 7/30 天预计收款。

### 合同与项目

- 已签约金额；
- 变更后合同金额；
- 在建项目数和完工项目数；
- 项目当前进度；
- 项目收款比例。

### 成本与利润

- 预计成本；
- 承诺成本；
- 实际成本；
- 已付成本；
- 应付余额；
- 预计毛利、动态毛利和最终毛利；
- 成本不完整项目数量。

### 风险

- 应收到期和逾期；
- 应付到期和逾期；
- 成本超预算；
- 项目低毛利或负毛利；
- 合同应收不平衡；
- 收付款与流水不一致；
- 未归档合同、未指派人、未确认计划。

每个数字必须可以穿透到项目、单据和来源事实。

## 10. 门店和角色视图

- Boss：全公司现金、应收应付、项目利润和风险；
- 店长：本店项目经营结果和风险，不默认可编辑财务；
- PM：本人项目进度、预算占用和成本风险，成本费用字段按权限展示；
- Designer：报价成本、预计毛利和项目预算，不展开实际付款明细；
- Finance：应收应付、收付款、流水、核校问题和月结；
- Support：采购、到货、应付来源，不显示企业整体现金；
- Marketer：客户签约和回款状态摘要，不可见成本和利润。

## 11. 月结与期间锁定

```text
月度自动核校
-> 财务处理异常
-> Boss/财务确认月结
-> 锁定该期间应收、应付、Ledger 和结算快照
-> 后续修正只能新增调整或冲销
```

月结前允许：

- 期初应收应付整批重导；
- 修正未确认应收应付；
- 补录来源和付款条件。

月结后禁止：

- 修改历史收款和付款金额；
- 物理删除 Ledger；
- 无来源调整项目利润；
- 用模板新版本回写历史 PDF。

## 12. 技术边界

建议新增或强化：

```text
FinancePostingContext
FinanceReconciliationContext
AccountingPeriodContext
ProjectFinancialProjectionContext
DocumentArchiveContext
```

现有对象职责：

- `ProjectContractContext`：合同金额、变更、收款计划；
- `ProjectContext`：项目、阶段、任务、开工和成本范围；
- `ProjectCostContext`：预计、承诺、实际和完整性；
- `FinanceAccessContext`：应收应付、收付款、核销和 Ledger；
- `DocumentArchiveContext`：合同、财务单据和打印归档。

禁止：

- 自动生成借贷凭证和会计科目；
- 把付款金额直接当实际成本；
- 把应收金额直接当现金收入；
- 在多个页面重复计算不同利润；
- 自动修复异常金额而不留调整记录；
- 为每家企业复制一套不同的记账代码。

## 13. 实施顺序

### P0-1：事件与规则

- 定义业务事件和幂等键；
- 定义合同生效、变更、采购、到货、收款、付款的自动记账规则；
- 建立事件执行记录和失败重试。

### P0-2：合同生效账务联动

- 项目收入基线；
- 应收计划；
- 成本预算；
- 合同打印归档；
- 交接任务。

### P0-3：成本和应付联动

- 采购承诺成本；
- 到货实际成本；
- 材料应付；
- 付款核销和支出流水。

### P0-4：自动核校

- 合同-应收；
- 应收-收款；
- 应付-付款；
- 流水-来源；
- 成本完整性。

### P0-5：Boss 经营视图

- 现金和回款；
- 项目成本和利润；
- 风险穿透；
- 项目、门店、公司三级视图。

- 月度核校；
- 期间锁定；
- 调整和冲销；
- 历史数据迁移。

## 14. 验收场景

### 场景 A：新合同完整自动记账

```text
合同生效
-> 应收和预算自动生成
-> 采购下单形成承诺成本
-> 材料到货形成实际成本和应付
-> 收到客户款形成收入流水
-> 付出供应商款形成支出流水
-> Boss 看到合同、回款、成本和动态毛利
```

### 场景 B：合同变更

```text
合同增项确认
-> 合同当前金额更新
-> 未来应收调整
-> 项目和材料范围调整
-> 成本预算调整
-> 核校通过
```

### 场景 C：异常核校

- 合同金额与应收合计不一致；
- 应收已收金额与收款不一致；
- 应付已付金额与付款不一致；
- 收款或付款没有 Ledger；
- 实际成本缺失；
- 已关闭期间发生写入；
- 系统必须标记问题并阻止结算，不得静默修正。

## 15. 完成定义

- 合同生效后无需财务重复录入应收和预算；
- 到货后无需重复录入实际成本和应付；
- 收款付款自动核销并生成流水；
- 变更自动调整未来应收和预算；
- 每次关键写入后可自动核校；
- Boss 能看到公司、门店、项目三级经营情况；
- 所有利润口径一致，成本不完整时为空；
- 月结后历史事实不可无痕修改；
- 历史导入、正常业务和异常调整均可追溯。

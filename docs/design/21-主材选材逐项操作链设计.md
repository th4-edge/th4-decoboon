# 21 · 主材选材逐项操作链设计

> 2026-09-22 用户明确要求将 App 重构为：项目详情 → 主材清单 → 单项选材/确认/下单状态。
> 本文记录该次实现的当前工程口径；旧 `20-主材选材文本化设计.md` 的整单选材模型仅保留兼容。

## 1. 数据来源

- 主材分项直接使用合同 `ContractLine.type = Material`，不新建任务对象。
- 每条合同主材行是项目中的一个选材分项。
- `db_material_selection` 存某个主材分项的选材结果版本。
- `source_contract_line_id` 标识结果所属主材分项；空值兼容旧版整单选材记录。

## 2. 状态

选材确认状态：

```text
未创建 -> Draft -> PendingConfirm -> Confirmed
```

- 未确认版本原地保存。
- 已确认版本不覆盖，修改形成新版本。
- 客户确认沿用 `material/selection/confirm`，重复确认幂等。

下单状态从 `MaterialPlan.status` 派生：

```text
Planned/Requested/Approved -> 未下单
Ordered -> 已下单
PartiallyArrived -> 部分到场
Arrived/Closed -> 已到场
```

选材页只展示下单状态，不手工修改；下单和到场事实仍由材料计划、采购和到货链路负责。

## 3. Provider

| 路由 | 作用 |
| --- | --- |
| `material/selection/item/page` | 项目全部合同主材分项 + 最新选材结果 + 下单状态 |
| `material/selection/item/info` | 单个主材分项详情 |
| `material/selection/save` | 增加 `contractLineId`、`selectionJson`，按主材分项保存草稿或提交确认 |
| `material/selection/confirm` | 客户确认当前结果版本，保持幂等 |

## 4. App

- `subpackages/project/pages/selection.vue`：项目基本信息、双进度、主材分项清单。
- `subpackages/project/pages/selection-item.vue`：单项选材表单、客户确认、下单状态。
- `subpackages/project/pages/selection-board.vue`：企业负责人项目级汇总与分项进度。

## 5. 边界

- `selectionJson` 只用于界面回填和导出快照。
- 选材结果不改变报价、合同金额、成本、材料数量和采购金额。
- 下单状态不代表采购前置强制门禁；是否阻断采购仍需单独业务裁决。

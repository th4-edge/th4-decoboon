# 23 财务账务理念对齐与手工记账边界设计

> 状态：冻结并已实施（2026-10-06，所有待确认项已关闭）
> 决策来源：用户 2026-10-06 明确决策
> 适用范围：装得清财务域、手工记账、项目毛利与资金现金流口径
> 取代关系：本文冻结后，`2026-10-05-手工记账业务分类标准化升级方案.md` 与 `2026-10-05-手工记账内置业务分类清单.md` 中「手工记账两级业务分类树」部分不再执行，仅作历史记录
> 业务边界：装得清做企业经营台账与项目经营账，不做法定会计总账、会计科目、借贷分录和税务申报

## 1. 结论摘要

1. 手工记账的定位是**非计划内、没有业务单据来源的其他账务**，不是第二套全量记账入口。
2. 手工记账**完全禁止**登记客户工程款、材料款、工资、项目款；必须强制引导到应收/应付闭环。
3. 手工记账**允许关联项目**；手工支出关联项目即视为项目零星成本，计入项目实际成本和项目毛利。
4. 设计费、材料销售、监理服务费等非工程款收入，不进入应收或单独业务单据，允许手工记账承接；关联项目时计入项目收入与项目毛利。
5. 借款/还款、押金/退还、备用金、股东往来允许手工记账；本期**不强制**区分「损益/往来」，作为资金流水记录。
6. 房租、推广、税费等企业运营费用**不进入任何利润口径**；装得清只展示**项目毛利 + 资金现金流**，本期不提供「公司经营利润」。
7. 手工记账分类**回归文本输入**，用于描述「其他账务」；不再要求关联两级业务分类树。
8. 线上已有 64 笔手工流水**先搁置**，保留原文本、金额与关联，后续单独处理。
9. App 1.0.11 的其他升级内容保留；手工分类选择器改为文本输入的调整放到后续版本。

## 2. 背景：为什么今天的设计与整体账务理念冲突

装得清的财务域是**以项目为核心、由业务动作自动形成财务事实**：

```text
业务动作发生
-> 自动形成财务事实（应收/应付/成本）
-> 自动写资金流水 Ledger
-> 自动核算项目经营结果
-> 财务只处理确认、异常和调整
```

原设计（`08-财务域业务闭环设计` §4.5）已经明确：

> 手工记账用于银行手续费、办公费用、其他收入等无法直接归入收付款单的场景；能追溯业务合同的金额必须走对应应收/应付闭环。

上一版手工记账升级把应收/应付的业务类型原样搬进了手工分类树（工程款、首期款、进度款、材料采购、人工费用等），造成：

1. **重复入口**：同一笔工程款/材料款既可走应收/应付，也可走手工记账。
2. **现金流双记**：收款流水与手工「工程款收入」同时进入现金流，虚增收入。
3. **利润口径断裂**：手工项目成本不进入 `ProjectCostContext` 和项目毛利，导致利润虚高；手工企业费用/其他收入又不进入任何利润口径。
4. **往来被当损益**：借款、还款、押金等被统一当成收入/支出，污染现金流结构。

本文的目的，就是把手工记账重新收回到「补缺」定位。

## 3. 财务账务总理念

同一笔业务只写一次事实，通过不同口径形成四本账：

| 账本 | 回答的问题 | 事实来源 |
| --- | --- | --- |
| 合同与收入账 | 签了多少、变更后多少、应收多少、已收多少 | 合同、变更、`Receivable`、`Receipt` |
| 成本与利润账 | 预计成本、实际成本、应付、项目毛利 | 报价、采购到货、`Payable`、`Payment`、`ProjectCostContext` |
| 资金与现金账 | 实际收付、账户余额、现金流 | `Receipt`、`Payment`、`Ledger` |
| 风险与核校账 | 应收应付不一致、成本缺失、超预算 | 自动核校 |

自动记账事件链：

| 业务事件 | 自动形成 | 是否写资金流水 |
| --- | --- | --- |
| 合同生效/变更 | 项目收入基线、应收计划、成本预算 | 否 |
| 采购下单/到货 | 承诺成本、实际材料成本、材料应付 | 否 |
| 客户收款 | 应收核销、收入流水 | 是 |
| 供应商/班组付款 | 应付核销、支出流水 | 是 |
| 项目费用确认 | 项目其他成本、应付或直接成本 | 视是否付款 |
| 手工记账 | 其他账务、资金流水 | 是 |

核心原则：

- 不得把「已收款」当成项目收入，也不得把「已付款」当成实际成本；
- 能追溯合同、采购、工资、材料计划、增减项的金额，必须走来源单据；
- 手工记账只补「没有业务单据来源」的账务。

## 4. 手工记账定位与边界

### 4.1 定义

```text
手工记账 = 非计划内、无业务单据来源、无法通过应收/应付闭环自动形成的其他账务
```

手工记账写入 `Ledger(Source=Manual)`，是资金与现金账的补充，不是合同收入账、成本利润账的替代入口。

### 4.2 允许清单

| 类别 | 典型内容 | 项目/企业归属 | 是否进入项目毛利 |
| --- | --- | --- | --- |
| 项目零星成本 | 现场杂费、临时运输、垃圾清运、成品保护、设备租赁、售后维修、赶工/奖励、其他项目直接支出 | **必须关联项目** | **是**，计入项目实际成本 |
| 非工程款收入 | 设计费、材料销售、监理服务费、量房/验房服务费、补贴返利、赔偿、利息、资产处置、其他 | 关联项目时归属项目；未关联时归属企业 | **关联项目时计入项目收入与项目毛利**；未关联时只进现金流与收入台账 |
| 企业运营费用 | 房租、水电、办公、差旅、获客推广、软件服务、银行手续费、利息支出、税费、培训、其他 | 企业级 | 否 |
| 资金往来 | 借款/还款、押金/退还、备用金、代收代付、股东往来、其他 | 原则上企业级 | 否 |
| 其他 | 无法归入以上类别的零星账务 | 项目/企业按实际 | 按是否项目零星成本判断 |

### 4.3 禁止清单

| 禁止内容 | 正确入口 |
| --- | --- |
| 客户工程款：首期款、进度款、尾款、质保金、增项款、其他可追溯合同/应收的客户款项 | 应收计划 → 收款 |
| 材料款、供应商款 | 采购到货 → 应付 → 付款 |
| 工人工资 | 人工/班组应付 → 工资发放 |
| 项目款、分包款 | 项目应付 → 付款 |
| 任何可追溯采购、到货、材料计划、增减项、合同变更的金额 | 对应来源单据 |
| 法定会计凭证、会计科目、借贷分录、税务申报 | 不在装得清范围 |

### 4.4 强制引导规则

手工记账不是「什么都能记」的入口。目标交互规则：

1. 手工记账表单只提供「其他账务」用途，不提供工程款、材料款、工资、项目款选项。
2. 用户从其他入口误入，或摘要/分类明显指向工程款、材料款、工资、项目款时，系统阻断并给出应收/应付入口。
3. 同一项目、同一金额、同一日期已存在应收/应付/收付款事实时，手工记账应提示「该笔可能已在业务闭环中登记」并引导核对，不做静默通过。
4. 系统不替代财务判断；本期以「入口约束 + 明确提示 + 人工确认」为主，不做复杂自动去重。

### 4.5 分类回归文本

- 手工记账的「分类」回归自由文本输入，用于描述其他账务，例如「银行手续费」「临时保洁」「股东借款」。
- 不再要求关联两级业务分类树，不再维护手工记账内置分类，不再要求「待关联分类」。
- 自动流水（收款/付款）的分类仍由系统生成：收款取应收类型，付款取应付类型，不受手工记账回归文本的影响。
- `Ledger.category` 文本在手工流水中作为分类说明保留；在自动流水中仍是系统业务类型快照。
- 「账务用途」是用于禁止清单与归属判断的最小枚举（项目零星成本/企业费用/其他收入/资金往来/其他），不是业务分类树；分类明细仍为自由文本。

### 4.6 手工账务删除/作废规则

企业负责人（Boss）可以删除手工账务记录，采用**逻辑作废**，不做物理删除：

| 规则 | 内容 |
| --- | --- |
| 权限 | 仅企业负责人（Boss）可作废；财务、店长、普通员工不可作废 |
| 范围 | 仅 `Ledger(Source=Manual)`；自动流水（收款、付款、调整冲销）不可作废 |
| 方式 | 逻辑作废，保留原记录、金额、关联、凭证档案与审计记录 |
| 原因 | 作废必须填写原因，写入 `LedgerRevision`（作废类型） |
| 限制 | 已参与冲正重记（`correctionGroupId` 非空）的流水不可作废 |
| 查询 | 作废记录不再出现在台账、资金汇总、项目经营口径；如需审计由后台审计视图查看 |
| 影响 | 作废后现金流不再计入；若为项目零星成本或关联项目非工程款收入，项目毛利由派生计算实时恢复 |
| 历史数据 | 线上 64 笔手工流水维持搁置，不因本次能力上线自动作废 |

## 5. 账务性质与归属模型

### 5.1 三个基础维度

| 维度 | 取值 | 作用 |
| --- | --- | --- |
| 资金方向 | 收 / 支 | 只表达现金进出 |
| 账务性质 | 损益 / 往来 | 决定是否属于经营损益；本期不强制区分 |
| 归属层级 | 项目 / 企业 | 决定是否进入项目成本口径 |

### 5.2 账务性质（损益 vs 往来）

| 账务性质 | 包含内容 | 本期处理 |
| --- | --- | --- |
| 损益类 | 项目零星成本、企业费用、其他收入、其他支出 | 项目零星成本和关联项目的其他收入进入项目毛利；企业费用/未关联项目的其他收入不汇总为公司利润 |
| 往来类 | 借款/还款、押金/退还、备用金、代收代付、股东往来 | 本期不强制剔除，作为资金流水记录；不进入项目毛利 |

> 用户决策：「不必须不计入损益」。因此本期**不新增「损益/往来」字段**，不强制用户在录入时区分损益/往来；账务性质仅作为设计概念保留。未来如引入公司利润口径，往来类必须重新定义剔除规则（当前不启动）。

### 5.3 项目/企业归属

| 用途 | 项目关联 | 结果 |
| --- | --- | --- |
| 项目零星成本 | **必须关联项目** | 计入项目实际成本与项目毛利 |
| 项目零星成本 | 未关联项目 | 拒绝保存 |
| 企业费用 | 不关联项目 | 只进资金现金流与费用台账，不进项目毛利 |
| 其他收入（含非工程款收入） | 可选关联项目 | **关联项目时计入项目收入与项目毛利**；未关联时只进资金现金流与收入台账 |
| 资金往来（借款/还款/押金/备用金/股东往来） | 原则上不关联项目 | 只进资金现金流，不进项目成本 |
| 其他 | 按实际 | 不进项目毛利；需要时再单独归类 |

### 5.4 本期最小实现口径

```text
账务用途=项目零星成本 + 关联项目 -> 项目实际成本，计入项目毛利
账务用途=项目零星成本 + 未关联项目 -> 拒绝保存
账务用途=企业费用                 -> 只进现金流与费用台账
账务用途=其他收入（非工程款）+ 关联项目 -> 计入项目收入与项目毛利
账务用途=其他收入（非工程款）+ 未关联项目 -> 只进现金流与收入台账
账务用途=资金往来                 -> 只进现金流，不进项目成本
禁止用途（工程款/材料款/工资/项目款） -> 不提供入口，强制引导到应收/应付
```

## 6. 三套口径

### 6.1 项目毛利（本期提供）

```text
项目收入 = 合同当前金额（含已确认变更） + 手工关联项目的非工程款收入
项目成本 = 材料实际成本 + 人工/项目应付 + 手工项目零星成本 + 其他应计成本
项目毛利 = 项目收入 - 项目成本
项目毛利率 = 项目毛利 / 项目收入
```

规则：

- 手工零星成本只有**关联项目**且账务用途=项目零星成本时才计入项目实际成本；
- 手工非工程款收入只有**关联项目**且账务用途=其他收入时才计入项目收入；合同金额本身不因手工收入变化；
- 材料/人工/项目应付仍按采购到货、人工确认等来源累计，不重复累计；
- 任一应计成本缺失时：`costComplete=false`，`项目毛利=null`，前端显示「成本未完整」，禁止用 0 成本计算伪利润；
- 手工企业费用、未关联项目的其他收入、资金往来不进入项目毛利。

### 6.2 公司经营利润（本期不提供）

冻结结论：

- 装得清本期**不提供公司经营利润/净利润**指标；
- 房租、推广、税费等企业运营费用**不进入项目毛利**，也**不汇总为公司利润**；
- 企业运营费用只体现在资金现金流（支出）和费用台账中；
- 非工程款收入：关联项目时进入项目收入与项目毛利；未关联项目时只体现在资金现金流和收入台账中；
- 对外不得宣称装得清输出公司净利润、财务利润或税务利润。

公司利润/公司经营利润**当前不启动**，不在当前路线图内。如果未来要提供，必须另行决策并补齐：

1. 企业收入范围（是否包含项目毛利、其他收入）；
2. 企业费用确认口径（收付实现制还是权责发生制）；
3. 往来类剔除规则；
4. 期间、月结、税务口径与凭证边界。

### 6.3 资金现金流（本期提供）

```text
资金净流量 = 全部 Ledger 收入 - 全部 Ledger 支出
账户余额   = 累计 Ledger 收入 - 累计 Ledger 支出
```

规则：

- 包含自动收款、自动付款、手工记账和调整冲销；
- 手工的其他收入、企业费用、项目零星成本、资金往来都进入现金流；
- 本期不因「往来」而单独剔除现金流；
- 现金流不等于利润：即使未来出现大额借款/还款，也不能解释为经营收入或成本。

### 6.4 三者关系

| 口径 | 是否提供 | 公式/说明 | 是否含往来 |
| --- | --- | --- | --- |
| 项目毛利 | 是 | 合同当前金额 + 手工关联项目非工程款收入 - 项目成本（含手工项目零星成本） | 否 |
| 公司经营利润 | 否 | 本期不提供，企业费用不汇总为利润 | 不适用 |
| 资金现金流 | 是 | 全部 Ledger 收入 - 支出 | 是，本期不剔除 |

## 7. 手工记账目标字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 收支方向 | 是 | 收 / 支 |
| 账务用途 | 是 | 项目零星成本 / 企业费用 / 其他收入 / 资金往来 / 其他；用于约束禁止清单 |
| 分类说明 | 是 | 自由文本，描述具体其他账务，如「银行手续费」「临时保洁」 |
| 关联项目 | 项目零星成本必填；其他可选 | 决定是否进入项目成本 |
| 金额 | 是 | 大于 0 |
| 资金账户 | 是 | 银行/现金/微信/支付宝/其他 |
| 发生日期 | 是 | 业务发生日 |
| 往来对象 | 否 | 供应商/客户/个人/股东等 |
| 摘要 | 是 | 一句话说明资金用途 |
| 备注 | 否 | 凭证号、批次、补充说明 |

校验规则：

1. 账务用途不提供工程款、材料款、工资、项目款；
2. 账务用途=项目零星成本时必须关联项目；未关联项目直接拒绝保存；
3. 只有账务用途=项目零星成本的手工支出进入项目实际成本；其他用途即使关联项目也不进项目毛利；
4. 资金往来原则上不关联项目；
5. 手工非工程款收入关联项目时计入项目收入/项目毛利；未关联项目时不改变项目毛利；
6. 金额、方向、账户、日期、摘要必须完整；
7. 已存在的应收/应付/收付款事实必须给出手工重复风险提示。

## 8. 对现有实现与版本的处置建议

| 对象 | 处置 |
| --- | --- |
| 手工记账两级分类树 | 从目标设计中废弃，仅作历史记录 |
| `LedgerCategory` 与分类维护接口 | 不再作为手工记账目标能力；是否保留给其他场景另议 |

## 9. 验收标准

1. 手工记账入口明确标注「仅用于非计划内其他账务」。
2. 手工记账不提供工程款、材料款、工资、项目款选项；误入时给出应收/应付入口。
3. 手工支出关联项目时，金额进入项目实际成本，项目毛利相应减少。
4. 手工支出不关联项目时，只进入资金现金流，不改变项目毛利。
5. 手工非工程款收入关联项目时计入项目收入与项目毛利；未关联项目时只进入资金现金流与收入台账。
6. 借款/还款、押金/退还、备用金、股东往来可记录并进入现金流，不进入项目成本。
7. 不展示公司经营利润/净利润指标；企业费用不汇总为利润。
8. 项目毛利仍遵守成本完整性规则，成本缺失时返回 `null` 并显示「成本未完整」。
9. 自动收付款流水的业务类型不受手工分类改动影响。
10. 历史 64 笔手工流水不改动、不批量重算。
11. 企业负责人可作废手工流水；作废后台账、资金汇总与项目毛利不再包含该笔；财务、店长不可作废；自动流水不可作废。

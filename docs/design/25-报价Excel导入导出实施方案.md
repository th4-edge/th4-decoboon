## 3. 实施步骤（建议顺序，每步可独立验收）

### 步骤 1 · 导入模式（后端）
在既有 `QuoteWorkbookImportRequest` 上增加模式语义（**不新增 DTO**，延续实体+显式字段风格）：

```text
NEW      新建草稿：要求 quoteId 为空或指向一个可复制的来源；解析结果整体写入新草稿
OVERWRITE 覆盖当前草稿：要求 quoteId 为 Draft；以导入结果**整体替换**现有行
MERGE    合并当前草稿：要求 quoteId 为 Draft；按 itemId 匹配更新，未匹配行按规则新增
```

前置校验（三项都适用）：
- `status != Draft` → 400「已提交/已接受的报价不可导入，请改版重报或走合同变更」
- `failed > 0` → 400 + 返回逐行错误，**不落库**
- 区域不在当前设计方案 `Space` 集合内 → 该行错误（Q1 口径）

### 步骤 2 · 导出双版本（后端）
在既有 `export` 上增加版本口径：

| 版本 | 包含 | 禁止 |
| --- | --- | --- |
| **内部工作版**（设计师） | 区域/分项/工程量/公式表达式/服务端结果/销售价 | **不得出现任何 `cost*` 字段** |
| **客户版** | 正式展示字段 + 服务端金额 | 标准成本、采购价、利润、内部公式/备注 |

> 只导出**服务端正式版本**；未保存的前端预览不得进入导出。

### 步骤 3 · 前端导入向导（Web）
1. 选择 `.xlsx` → 调 `quote/workbook/import` → 展示 `ImportResult` 预览
2. 预览表：可导入/错误行分色 + 逐行 `errors[]` 文本；错误行**不可确认导入**
3. 选择模式（新建/覆盖/合并）→ 确认导入 → **服务端重算** → 重新读取 → 覆盖前端
4. 导入后核对：金额、区域、公式、行数四项与服务端一致

## 5. 边界与风险

- **不新增 DDL**：本方案所有改动都在既有实体/上下文/Provider 内完成。
- 若确认需要新增"导入批次记录"表，则属迁移 → **停止并汇报**。
- 导入模式若通过 `QuoteWorkbookImportRequest` 扩展，需确认该请求对象**不参与持久化**（当前为普通请求类）。
- 覆盖模式会**删除现有行**（业务上属替换）→ 需在确认前给出明确的二次确认文案与行数差异。

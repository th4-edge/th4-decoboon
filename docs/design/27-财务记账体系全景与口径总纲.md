## 0. 财务边界分层与红线（DEC-016）

本总纲及其全部账务口径必须服从业务智能体 `DEC-016`《财务边界分层与红线》。对外统一口径：

> 装得清管项目和钱，不管税和账。

| 边界 | 是否在本总纲内 | 说明 |
| --- | --- | --- |
| L1 必须承载 | 是 | 合同/应收/收款、采购/应付/付款、项目成本与毛利、工人工资/班组、资金台账、凭证、期初承接 |
| L2 可承载、须轻量可关停 | 是（受限） | 员工工资、公司经营利润、门店经营视图；须过五道门禁，企业可关停 |
| L3 明确不承载 | 否 | 法定会计总账/科目/借贷分录、税务申报/发票、社保公积金、完整 HR、复杂成本分摊、合并报表 |

**红线**：装得清输出的任何数字，都不能被用户误当成会计、税务或审计依据。公司经营利润统一称为「经营利润（参考）」，成本或费用不完整时返回 `null` 或「暂不可确认」，不按 0 计算。

**L2 五道门禁**：受众门禁、数据门禁、口径门禁、责任门禁、闭环门禁；任一不过则不进入研发。

详细边界见 `docs/product/2026-10-06-装得清财务边界白皮书.md`；本文与之冲突时以 `DEC-016` 和白皮书为准，并回改本文。

## 1. 总理念

装得清的账务不是「财务手工录入一套账」，而是：

```text
业务动作发生
-> 系统自动形成财务事实
-> 按不同口径形成不同账本
-> 自动核算项目经营结果
-> 自动核校账本一致性
-> 财务只处理确认、异常和调整
```

三条不可违反的原则：

1. **一笔业务只写一次事实**，不同账本只是同一事实的不同投影。
2. **已收款 ≠ 项目收入，已付款 ≠ 实际成本**。
3. **能追溯到合同、采购、人工、工资、材料计划的金额，必须走来源单据；手工记账只补没有来源的账**。

## 2. 四本管理账

| 账本 | 回答的问题 | 事实来源 | 主要对象 |
| --- | --- | --- | --- |
| 合同与收入账 | 签了多少、变更后多少、应收多少、已收多少 | 合同、变更、应收、收款 | `ProjectContract`、`Receivable`、`Receipt` |
| 成本与利润账 | 预计/承诺/实际成本多少、应付多少、项目毛利多少 | 报价、合同行、采购到货、应付、工资单、手工作废 | `ContractLine`、`PurchaseOrder`、`GoodsReceipt`、`Payable`、`Settlement` |
| 资金与现金账 | 实际收付、账户余额、现金流 | 收款、付款、手工记账 | `Receipt`、`Payment`、`Ledger` |
| 风险与核校账 | 哪些账不一致、逾期、缺成本、超预算 | 自动核校 | `ReconciliationIssue`、`BusinessAlert` |

**本次新增第五个口径（不是第五本账）**：公司经营利润。它由「项目毛利 + 非项目收入 − 企业费用」汇总，不新建资金事实。

## 3. 领域对象全景

| 对象 | 职责 | 状态 |
| --- | --- | --- |
| `ProjectContract` | 合同金额、变更、收款计划 | 既有 |
| `Receivable` | 合同节点应收：首期款、进度款、尾款、质保金、其他 | 既有 |
| `Receipt` | 客户实际收款，核销应收 | 既有 |
| `Payable` | 材料款、工人工资、项目款、供应商款、费用、**员工工资（新增）** | 扩展 |
| `Payment` | 向供应商、班组、工人、**员工（新增）**实际付款，核销应付 | 扩展 |
| `Ledger` | 不可变资金流水，来源为收款/付款/手工/调整 | 既有 |
| `Settlement` | 项目收入、成本、利润与关闭快照 | 既有 |
| `OpeningBalance` | 期初资金余额，不计入收支与利润 | 既有/承接 |
| `Worker` | 个人工人档案，工人工资凭证对方来源 | 既有 |
| **`CompensationScheme`** | 员工薪酬方案（固定工资/提成规则） | 新增 |
| **`AttendanceSummary`** | 月度考勤确认结果，工资输入 | 新增 |
| **`CommissionItem`** | 提成计提、归属、发放、冲减 | 新增 |
| **`PayrollSheet` / `PayrollItem`** | 工资单/工资项，生成员工工资应付 | 新增 |

关系：

```text
客户 -> 合同 -> 项目
  ├── 应收 Receivable -> 收款 Receipt -> Ledger(Income)
  ├── 材料计划 -> 采购单（确认下单形成材料应付 Payable）-> 到货（回填账期/实际成本）-> 付款 Payment -> Ledger(Expense)
  ├── 工人/班组 -> 工人工资应付 Payable(Salary) -> 付款 Payment -> Ledger(Expense)
  └── 员工薪酬 -> 工资单 PayrollSheet -> 员工工资应付 Payable -> 付款 Payment -> Ledger(Expense)
                     ↑ 考勤 AttendanceSummary + 提成 CommissionItem
```

## 4. 自动记账事件链

| 业务事件 | 自动形成/更新 | 是否写资金流水 |
| --- | --- | --- |
| 合同签署 | 合同基线、签署归档，不生成项目 | 否 |
| 合同生效 | 唯一项目、收入基线、应收计划、预计成本预算、合同归档 | 否 |
| 合同变更客户确认 | 合同当前金额、未来应收、预算、任务和材料范围 | 否（除非产生实际退款/收款） |
| 采购单批准 | 承诺成本、材料执行范围 | 否 |
| 材料确认下单 | 形成供应商应付（不提前确认实际成本） | 否 |
| 客户收款 | 应收核销、收入流水 | 是 `Income` |
| 供应商/班组付款 | 应付核销、支出流水 | 是 `Expense` |
| **工资单确认** | **员工工资应付、项目/企业成本** | 否 |
| **工资发放** | 应付核销、支出流水 | 是 `Expense` |
| **提成确认** | **提成应付、项目成本** | 否 |
| **提成发放** | 应付核销、支出流水 | 是 `Expense` |
| 项目费用确认 | 项目其他成本、应付或直接成本 | 视是否付款 |
| 完工/阶段验收 | 项目进度、可结算状态、收款触发条件 | 否 |
| 项目结算关闭 | 最终收入、成本、利润、结算快照 | 否 |
| 手工调整 | 调整账务事实或冲销错误流水 | 是/视方向 |

事件必须带幂等键与来源单据，重复提交不得重复记账。

## 5. 收入账（合同与应收）

```text
合同当前金额 = 原合同金额 + 已确认变更
应收计划     = 按合同收款节点分解
已收金额     = Receipt 核销合计
待收金额     = 应收金额 − 已收金额
```

规则：

- 合同生效才生成项目与应收；合同签署本身不生成项目。
- 收款必须选择应收节点，金额不得超过余额。
- 收款与应收核销、`Ledger(Income)` 同事务。
- 合同金额是项目**收入基线**，不是现金收入。
- 手工非工程款收入关联项目时计入项目收入，未关联时只进现金流与收入台账（`ALIGN-FIN-01`）。

## 6. 成本与利润账（项目）

### 6.1 成本分层

| 层级 | 含义 | 来源 | 用途 |
| --- | --- | --- | --- |
| 预计成本 | 签约时预算 | 合同行成本快照 | 预算与预计毛利 |
| 承诺成本 | 已下单未到货 | 已批准采购单 | 风险占用、超预算预警 |
| 实际成本 | 已实际发生 | 到货/入库、人工、费用、工资确认 | 动态毛利 |
| 已付金额 | 实际支付现金 | `Payment` | 现金流与应付余额 |

### 6.2 项目毛利

```text
项目收入 = 合同当前金额（含已确认变更） + 关联项目的非工程款收入
项目成本 = 材料实际成本 + 人工/班组应付 + 项目归属员工工资/提成
         + 手工项目零星成本 + 其他应计成本
项目毛利 = 项目收入 − 项目成本
项目毛利率 = 项目毛利 ÷ 项目收入
```

规则：

- 实际材料成本只在到货/入库累计；领料、损耗只流转库存，不重复累计（`ECD-002~004`）。
- 手工零星成本只有「关联项目 + 账务用途=项目零星成本」才进项目成本。
- 项目归属员工工资/提成进项目成本；企业归属不进项目毛利。
- **成本不完整时**：`costComplete=false`、`grossProfit=null`、`grossMargin=null`，前端显示「成本未完整」，禁止按 0 计算。
- 同一笔成本只能落一处，禁止项目成本与企业费用双计。

## 7. 企业费用与公司经营利润（新增）

### 7.1 v0 公式

```text
公司经营利润 = 项目毛利合计
             + 非项目其他收入（未关联项目的其他收入）
             − 企业费用（企业归属员工工资 + 房租 + 推广 + 税费 + 办公 + 其他运营）
```

### 7.2 企业费用范围

| 费用 | 是否进公司利润 | 说明 |
| --- | --- | --- |
| 企业归属员工工资（行政/财务/店长等） | 是 | 由工资单确认时计成本 |
| 房租、水电、办公 | 是 | 手工记账「企业费用」 |
| 推广、渠道/返点 | 是 | 手工记账「企业费用」 |
| 税费 | 待冻结 | 需定义含哪些税种 |
| 借款/还款、押金/退还、备用金、股东往来 | **否** | 往来类，必须剔除 |
| 项目归属工资/提成 | 否 | 已进项目毛利，避免双计 |

### 7.3 必须补齐的四件事

1. **企业收入范围**：是否含全部项目毛利 + 未关联项目其他收入。
2. **企业费用确认制**：建议统一权责发生（与「确认时计成本」一致）。
3. **往来剔除**：新增「损益/往来」判定。原 `23` §5.2 明确：引入公司利润后，往来类必须重新定义剔除规则；当前手工记账无此字段，必须先补。
4. **成本完整性传导**：任一项目成本不完整时，公司利润标记「成本未完整」，不得按 0 拼假利润。

### 7.4 对外边界

- 可以说：按「项目毛利 + 非项目收入 − 企业费用」口径展示公司经营利润，往来不计入。
- 不可说：财务净利润、税务利润、审计利润。

> 本节与 `23` §6.2 / `ALIGN-FIN-05`「公司利润不启动」冲突，用户 2026-10-06 决策启动设计，详见 `GAP-020`。

## 8. 资金与现金账

```text
资金净流量 = 全部 Ledger 收入 − 全部 Ledger 支出
账户余额   = 期初余额 + 累计收入 − 累计支出
```

规则：

- `Ledger` 不可变；手工流水仅企业负责人可逻辑作废，自动流水不可作废。
- 包含自动收款、自动付款、手工记账、工资/提成发放、调整冲销。
- 期初余额 `OpeningBalance` 不计入收入/支出，不参与利润，只作账户起始。
- 现金流 ≠ 利润：借款/还款、大额往来不得解释为经营收入或成本。
- 本期是否剔除往来由公司利润口径决定；现金流仍完整呈现。

## 9. 手工记账

### 9.1 定位

```text
手工记账 = 非计划内、无业务单据来源、无法通过应收/应付闭环自动形成的其他账务
```

### 9.2 允许用途

项目零星成本 / 企业费用 / 其他收入 / 资金往来 / 其他（自由文本分类说明）。

### 9.3 禁止清单

| 禁止内容 | 正确入口 |
| --- | --- |
| 客户工程款（首期/进度/尾款/质保金/增项） | 应收计划 → 收款 |
| 材料款、供应商款 | 采购确认下单 → 应付 → 到货回填账期/实际成本 → 付款 |
| 工人工资 | 人工/班组应付 → 工资发放 |
| **员工工资** | **工资单 → 员工工资应付 → 付款** |
| 项目款、分包款 | 项目应付 → 付款 |
| 可追溯采购、到货、材料计划、增减项、合同变更的金额 | 对应来源单据 |
| 法定会计凭证、科目、借贷分录、税务申报 | 不在装得清范围 |

### 9.4 作废规则

- 仅企业负责人可逻辑作废手工流水，不物理删除，保留审计与凭证。
- 已参与冲正重记的流水不可作废。
- 自动流水（收款、付款、工资、调整）不可作废。

## 10. 工人工资与员工工资（两条独立链路）

| 维度 | 工人工资（既有） | 员工工资（新增） |
| --- | --- | --- |
| 主体 | `Worker` / `Partner` 班组 | `Employee` |
| 应付语义 | `PayableType.Salary` | 新增员工工资语义 |
| 成本 | 项目人工成本 | 项目归属进项目成本；企业归属进企业费用 |
| 考勤 | 不适用 | 月度考勤申报 |
| 计提 | 按班组工价/工程量 | 固定工资 + 提成（签约计提 + 回款发放） |
| 发放 | 付款核销 | 工资单 → 应付 → 付款核销 |
| 凭证 | 工资发放凭证（身份证/工种/账号） | 工资条 + 按需发放凭证 |
| 禁止 | 与员工工资混算 | 与工人工资混算 |

详情见《员工工资与公司利润融入方案》。

## 11. 凭证与单据

| 单据 | 用途 | 数据来源 |
| --- | --- | --- |
| 收款单 | 客户收款留档 | `Receipt` |
| 付款单 | 供应商/班组/工人付款留档 | `Payment` |
| 工资发放凭证 | 工人个人工资套打，含身份证/工种/账号 | `Payment` + `Worker` |
| 工资条 | 员工收入明细，员工本人可见 | `PayrollItem` |
| 资金流水凭证 | 手工流水留档 | `Ledger` |
| 班组结算凭证 | 班组劳务结算 | `Payment` + `Partner` |

规则：

- 凭证是装企自用业务单据套打，**不等于会计记账凭证**（`DEC-005`）。
- 重打读同一条记录；补录工人后可按原凭证号重渲染并留痕（`REQ-BIZ-20261006-003`）。
- 模板占位符绑定业务字段，不手工覆盖金额事实。

## 12. 金额与口径约定

| 项 | 约定 |
| --- | --- |
| 精度 | `BigDecimal`，计算保留到分 |
| 金额校验 | 收款/付款 > 0；调整不得低于已收/已付 |
| 快照 vs 实时 | 合同金额、成本快照冻结；实际成本按事实累计 |
| 销售价/成本价 | 销售价与标准成本分离，成本价限 BOSS/店长/财务 |
| 缺失值 | 应计成本缺失 → `null` + 「成本未完整」，不用 0 替代 |
| 尾差 | 全企业统一四舍五入，尾差可追溯 |
| 时间口径 | 权责发生：确认时计成本；发放只动现金 |
| 期间 | 月度，月结后锁定，调整走冲销/补差 |

## 13. 状态机汇总

| 对象 | 状态 |
| --- | --- |
| 应收 | `Pending → Partial → Received`；到期未收 `Overdue` |
| 应付 | `Pending → Partial → Paid`；到期未付 `Overdue` |
| 收款/付款 | 持久事实，不可物理删除，错误走冲正 |
| 手工流水 | 可逻辑作废，保留审计 |
| 项目结算 | `Draft → Confirmed → Closed`，关闭需应收清零 + 应付清零 + 完工/验收 |
| 工资单（新） | `草稿 → 待确认 → 已确认 → 部分发放 → 已发放 → 已关闭`；未发放可作废/退回 |
| 提成（新） | `待计提 → 已计提 → 已入工资单 → 已发放 → 已关闭`；可冲减 |
| 考勤（新） | `草稿 → 待确认 → 已确认 → 已入工资单`；可申诉退回 |
| 月结 | 核校 → 确认 → 锁定期间；后续只能调整/冲销 |

## 14. 权限与数据范围

### 14.1 财务域角色

| 角色 | 范围 | 动作 |
| --- | --- | --- |
| BOSS | 全公司 | 查看、记账、建应收应付、收付款、确认/关闭结算、月结、工资确认 |
| 财务 | 全公司 | 同 BOSS 的日常操作（工资/提成核算与发放） |
| 店长 | 本店 | 只读查看财务；确认本店考勤；查看本店员工个人工资 |
| 团队负责人 | 本团队 | 待定（考勤/提成归属） |
| 普通员工 | 本人 | 仅本人工资条、本人考勤、本人提成 |
| 其他角色 | 无 | 不可访问财务 Provider |

### 14.2 强制规则

1. 企业/门店/团队/负责人只能从登录员工加载，禁止信任前端 `companyId/empId/ownerId`。
2. `@DataPermission` 管查得到什么，`@Properties`/`@ServiceProperties` 管返回什么，不可互替。
3. 分页/列表/计数由 `DataScopeRequestFilter` 统一追加范围。
4. 自定义详情/更新/删除必须用 `DataScopeContext + DataScopeSpecification`。
5. 工资敏感字段独立权限：银行卡、身份证、个税明细默认仅 BOSS/财务。
6. 越权按「不存在或无权访问」处理，不泄露他人工资/财务事实是否存在。

## 15. 风险与核校账

必须核校：

```text
合同金额 vs 应收合计
应收已收 vs 收款合计
应付已付 vs 付款合计
收款/付款 vs Ledger 来源
项目实际成本完整性
工资单确认 vs 应付/成本
工资发放 vs Ledger
已关闭期间是否发生写入
```

处理原则：**标记问题、阻止错误结算，不静默修正**；修正必须留调整记录。

---

## 16. 月结与期间锁定

```text
月度自动核校 -> 财务处理异常 -> BOSS/财务确认月结
-> 锁定该期间应收、应付、Ledger、工资单、结算快照
-> 后续修正只能新增调整或冲销
```

月结后禁止：修改历史收付款金额、物理删除 Ledger、无来源调整项目利润、用模板新版本回写历史 PDF、直接修改已确认工资单。

## 19. 核心公式汇总

| 公式 | 口径 | 缺失时 |
| --- | --- | --- |
| 合同当前金额 = 原合同 + 已确认变更 | 合同 | — |
| 应收余额 = 应收 − 已收 | 应收 | — |
| 应付余额 = 应付 − 已付 | 应付 | — |
| 项目收入 = 合同当前金额 + 关联项目非工程款收入 | 项目 | — |
| 项目成本 = 材料 + 人工 + 项目归属工资/提成 + 手工零星 + 其他应计 | 项目 | `costComplete=false` |
| 项目毛利 = 项目收入 − 项目成本 | 项目 | `null` |
| 公司经营利润 = 项目毛利合计 + 非项目收入 − 企业费用 | 公司 | 任一项目不完整则 `null` |
| 资金净流量 = 收入 − 支出 | 现金 | — |
| 账户余额 = 期初 + 净流量 | 现金 | — |
| 应发工资 = 固定工资 + 提成 + 奖金 + 补贴 | 工资 | 缺项不可确认 |
| 实发工资 = 应发 − 考勤扣款 − 社保 − 个税 − 其他 | 工资 | 缺项不可确认 |

## 20. 对外表达边界

**可以说**

- 装得清把销售价、成本价、实际成本和项目毛利分口径管理；成本不完整时提示，不用 0 成本造假利润。
- 装得清按项目毛利 + 企业费用口径展示公司经营利润，往来不计入。
- 项目人员工资/提成进项目成本，企业人员工资进企业费用。

**不可说**

- 装得清替代财务核算、审计、税务申报、个税/社保代缴。
- 系统展示的就是财务净利润/税务利润。
- 使用后利润一定提高、成本绝对准确。

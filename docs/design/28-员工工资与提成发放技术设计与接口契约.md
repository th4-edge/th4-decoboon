# 28 员工工资与提成发放技术设计与接口契约

> 实现状态：迁移 81/86/87、payroll 领域模型、薪酬/考勤、工资单确认、员工发放、提成自动释放、退款/离职/跨期负向调整、财务报表聚合、工资项/店长本店工资/薪酬工作台查询、App/Web 退款与调整页面首版已落地；定向回归和本地 E2E 通过，全量测试受工作区既有缺陷阻塞。  
> 状态：草案（供 technical review；业务口径依据 `DEC-017`、`BR-015`、`DEC-032`、`BR-028`、`ANS-BIZ-20261006-002`、`ANS-BIZ-20261007-020`、`EV-065`、`EV-069`、`EV-098`）  
> 日期：2026-10-07  
> 定位：员工工资、月度考勤、提成计提/自动释放、工资单、应付、发放、台账和成本归集的后端技术设计  
> 边界：不做法定会计总账、个税社保申报、完整 HR；不与工人工资链路混用

## 0. 结论

员工工资与提成建议**复用现有应付、付款、资金台账主干**，但必须新增员工薪酬领域对象和独立权限上下文，不能只扩展现有 `PayableType.Salary`。

推荐形态：

```text
薪酬方案 / 考勤 / 提成 / 工资单 / 工资项 / 工资条
        -> 员工工资应付 Payable(EmployeeSalary / EmployeeCommission)
        -> 员工发放 Payment(Employee)
        -> Ledger(Expense)
```

关键约束：

1. `PayableType.Salary` 保持“工人工资”语义，不修改为员工工资。
2. 新增 `EmployeeSalary`、`EmployeeCommission` 两个应付类型。
3. `Payable.property_id` 需要改为可空：企业归属员工工资没有项目/房屋。
4. `Payment` 新增 `payeeEmployee` 关联；员工付款不得关联 `worker`。
5. 员工工资成本、提成成本和工人人工成本分字段统计，不混算。
6. 工资单确认、提成计提、发放和台账写入必须有幂等键和事务边界。

## 1. 现有实现盘点与阻塞点

| 现状 | 影响 | 处理建议 |
| --- | --- | --- |
| `PayableType.Salary = 工人工资` | 不能承载员工工资 | 新增独立应付类型 |
| `Payable.property` 为 `nullable=false` | 企业归属员工工资无房屋 | 迁移为可空，并补充业务校验 |
| `Payable` 已有 `payeeEmployee` | 可用于员工收款方 | 保留，作为发薪对象 |
| `Payment` 只有 `worker`，没有员工关联 | 员工发放无法追溯 | 新增 `payeeEmployee`、`batchNo` |
| `FinanceAccessContext.requireReader` 只允许 BOSS/财务/店长 | 员工无法读取本人工资条 | 新增 `PayrollAccessContext` |
| `FinanceReportContext` 按 `PayableType` 汇总成本 | 新类型会被误归入其他费用 | 增加员工工资/提成项目和企业的独立聚合 |
| `Settlement` 当前只有 `salaryAmount` | 会把员工工资和工人工资混用 | 增加员工工资、员工提成字段 |
| 当前迁移最新编号 79 | 本设计暂定迁移 81 | 合并时按迁移编号测试最终冻结 |
| 现有 App 财务分包已有 16 页 | 不应继续堆叠员工薪酬 | 新增 `subpackages/payroll` |

### 3.1 改造现有表

```sql
-- 1. 企业工资没有房屋归属时必须允许为空
ALTER TABLE db_finance_payable
  MODIFY COLUMN property_id BIGINT NULL COMMENT '所属房屋；企业归属工资可为空';

-- 2. 应付类型增加员工工资与员工提成

ALTER TABLE db_finance_payable
  MODIFY COLUMN type VARCHAR(32) NOT NULL COMMENT '应付类型';

-- 3. 应付来源增加可追溯键
ALTER TABLE db_finance_payable
  ADD COLUMN source_type VARCHAR(32) NULL COMMENT 'PayrollItem/CommissionItem',
  ADD COLUMN source_id BIGINT NULL COMMENT '来源业务主键';
CREATE UNIQUE INDEX uk_fin_payable_company_source
  ON db_finance_payable (com_id, source_type, source_id);

-- 4. 付款增加员工与批次
ALTER TABLE db_finance_payment
  ADD COLUMN payee_emp_id BIGINT NULL COMMENT '员工收款人',
  ADD COLUMN batch_no VARCHAR(64) NULL COMMENT '发放批次号';
CREATE INDEX idx_fin_payment_company_employee
  ON db_finance_payment (com_id, payee_emp_id, paid_at, payment_id);
CREATE INDEX idx_fin_payment_company_batch
  ON db_finance_payment (com_id, batch_no, payment_id);
```

> `unique (com_id, source_type, source_id)` 只对员工工资/员工提成来源生效；历史数据的 null 不影响现有数据。

### 3.2 新增表要求

所有业务表必须：

- 含 `com_id`，联合索引最左；
- 含 `store_id`、`team_id`、`owner_id` 或 `employee_id` 以支持数据范围；
- 所有表使用雪花主键，禁止自增；
- 金额使用 `decimal(14,2)` 或与现有金额字段一致；
- 关联使用对象外键，不保存裸业务外键替代对象关系。

关键索引：

## 4. 应付、付款和台账映射

> 金额口径：员工工资应付和项目/企业成本均取工资项 `netAmount`（实发）；`grossAmount`、扣款、社保和个税仅作工资条展示。


### 4.1 应付生成

| 来源 | 应付类型 | 项目 | 房屋 | 负责人/数据归属 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 项目归属工资项 | `EmployeeSalary` | 项目 | 项目房屋或 null | 员工 | 进项目成本 |
| 企业归属工资项 | `EmployeeSalary` | null | null | 员工 | 进企业费用 |
| 项目归属提成项 | `EmployeeCommission` | 项目 | 项目房屋或 null | 员工 | 进项目成本 |
| 企业归属提成项 | `EmployeeCommission` | null | null | 员工 | 进企业费用 |

规则：

- `payeeEmployee` = 员工；
- `owner` = 员工，使员工自数据范围可读取本人应付款；
- `property` 只在项目归属时填写；
- 同一 `PayrollItem` 或 `CommissionItem` 只能生成一次应付；
- `Payable.status` 沿用现有 `Pending/Partial/Paid/Overdue/Closed`。

### 4.2 员工发放

建议新增独立 Provider，不直接把通用工人工资付款语义改复杂：

```text
finance/payment/employee/page
finance/payment/employee/info
finance/payment/employee/save
finance/payment/employee/update
```

发放规则：

- 只能核销 `EmployeeSalary`、`EmployeeCommission`；
- 同一付款批次只能是同一员工；
- `payeeEmployee` 必须与所有被核销应付的员工一致；
- `worker` 必须为空；
- 金额不得超过选中的员工应付未付合计；
- 幂等键沿用 `FinanceIdempotencyContext`；
- 同一事务写 `Payment`、`PayableSettlement` 和 `Ledger`；
- 失败重试复用同一 `idempotencyKey`，不重复写流水。

### 4.3 资金台账

员工发放使用：

```text
Ledger.source = Payment
Ledger.direction = Expense
Ledger.category = 员工工资 / 员工提成
Ledger.counterparty = 员工姓名
Ledger.project = 项目归属时填写，否则为空
```

不新建员工工资第二套流水；所有员工发放统一进入 `Ledger`。

### 5.3 提成

```text
payroll/commission/page
payroll/commission/info
payroll/commission/save
payroll/commission/build
payroll/commission/update
payroll/commission/release/page
payroll/commission/adjustment/page
payroll/commission/adjustment/save
payroll/commission/my/page
```

客户退款到提成负向调整：

```text
finance/refund/save
finance/refund/page
-> db_finance_refund
-> Ledger(Refund, Expense)
-> CommissionAdjustment(refund_id, Pending)
```

回款释放由服务端完成：

```text
累计有效回款 = 累计收款 − 累计退款/退单冲减
累计应释放提成 = min(提成金额, 提成金额 × 累计有效回款 ÷ 主合同签约额)
本次释放提成 = max(0, 累计应释放提成 − 已释放提成)
```

退款、离职、跨期负向调整：

```text
退款负向金额 = max(0, 已发提成 − 退款后累计应释放提成)
可调整上限 = 已发提成 − 已存在调整占用
下期实扣 = min(负向调整余额, 下期工资可承受金额)
```

- 调整独立入表，不修改原提成、原释放记录和已发工资。
- 客户退款先落 `ReceiptRefund`，同一收款累计退款不得超过原收款金额。
- 每条退款与原提成只允许生成一条负向调整，退款幂等键和调整唯一约束双重防重。
- 退款负向金额由累计有效回款自动重算；离职和跨期 P0 由财务手工确认抵扣金额。
- 调整金额不得超过原提成已发且未调整金额。
- 下期工资只扣减到实发不为负的范围，未抵扣部分保持 `Pending` 进入后续周期。
- 负向调整按原项目冲减员工提成成本，不转为企业费用。

### 5.4 工资单与工资条

### 5.6 工作台

工作台支持按 `period` 查询。响应除当前周期统计外，还必须返回：

- `currentPeriodHasSheet`：当前周期是否已有工资单；
- `latestSheetId/latestSheetPeriod/latestSheetStatus/latestSheetTotalNetAmount`：本企业范围内最近一次工资单投影。

当前周期没有工资单时，App 可显示最近一次工资单并一步进入详情；员工工资待发金额按选中工资周期过滤，员工提成待发金额按跨周期已释放未发事实汇总。

```text
payroll/workbench/report
```

返回待确认考勤、待确认工资单、待发放金额、待释放提成和异常数量。

## 6. 权限与数据范围

新增 `PayrollAccessContext`，不要复用 `FinanceAccessContext.requireReader`：

| 角色 | 范围 | 能力 |
| --- | --- | --- |
| BOSS | Company | 全公司薪酬、确认、发放、审计 |
| 财务 | Company | 全公司薪酬核算、制单、发放 |
| 店长 | Store | 本店考勤、本店员工工资只读，不返回敏感字段 |
| 员工本人 | Self | 本人工资条、本人提成、本人考勤 |
| 工人 | 禁止进入 | 走工人工资链路 |

BOSS 的“全公司薪酬、确认、发放、审计”是本企业全部内部岗位能力的超集。`财务制单 -> BOSS 确认 -> 财务发放`是在存在对应岗位时的职责路径，不是强制人数分离约束。只有一个 BOSS 的企业，或 BOSS 接管时，可由同一 BOSS 按顺序完成建方案、录/确认考勤、生成工资单、确认、发放和工资条发布；每一步仍须独立状态推进、独立权限校验、独立幂等键和独立审计记录。该约定同样适用于提成计提、释放查看和发放。

实现要求：

- 工资敏感字段通过 `@Properties` 白名单裁剪；
- 店长和员工视图必须使用服务端范围；
- 工资单、工资项、工资条不能直接复用通用 `finance/payable/page` 返回；
- 越权统一返回“不存在或无权访问”；
- 工资敏感字段访问和确认、发放、冲减全部写审计。

## 7. 报表与成本改造

### 7.1 `FinanceReportContext`

需要新增：

- `employeeSalaryPayableAmount`
- `employeeCommissionPayableAmount`
- `employeeSalaryCost`
- `employeeCommissionCost`
- `employeeCostComplete`

规则：

- `PayableType.EmployeeSalary/EmployeeCommission` 且有项目：进项目成本；
- 无项目：进企业费用；
- 工人工资继续用 `PayableType.Salary`，进工人人工成本；
- 项目成本不完整时仍返回 `null` 利润，不按 0 计算。

### 7.2 `Settlement`

新增字段建议：

```text
employeeSalaryAmount
employeeCommissionAmount
```

现有 `salaryAmount` 只保留工人/班组人工成本语义，不得改成员工工资汇总。

### 7.3 项目账本

项目成本增加：

- 工人/班组人工成本；
- 项目归属员工工资；
- 项目归属员工提成；
- 其他项目成本。

企业归属员工工资只进企业费用，不进项目毛利。

## 8. 事务、幂等与审计

### 8.1 工资单确认

```text
校验考勤已确认、工资项归属完整、提成状态正确
-> 锁定工资单
-> 生成员工工资应付
-> 确认项目/企业成本
-> 更新工资单状态
-> 管理侧待发状态（员工端不发布工资条）
```

必须在同一写事务内完成；重复确认按 `sheetId` 幂等返回原结果。工资单确认不等于工资条发布。

### 8.2 提成回款释放

建议在客户收款成功事务内调用 `CommissionReleaseContext.releaseForReceipt(receipt)`：

- 按主合同签约额和累计有效回款计算本次释放；
- 写 `CommissionRelease` 唯一记录；
- 生成或追加提成应付；
- 更新提成状态；
- 失败时和收款一起回滚；
- 同一 `receiptId + commissionId` 只能释放一次。

### 8.3 员工发放

- 客户端 `idempotencyKey` 全局企业内唯一；
- 同一批次只能一个员工；
- 金额不得超过员工应付未付合计；
- Payment、PayableSettlement、Ledger 同事务；
- 失败不写台账，重试复用原幂等键。

### 8.4 审计

至少记录：

- 薪酬方案变更；
- 考勤确认和退回；
- 提成计提、释放、冲减；
- 工资单确认、作废和退回；
- 员工发放；
- 工资敏感字段访问。

## 9. 测试与验收切片

### 单元/集成

- 日薪、考勤扣款、应发、实发金额；
- 多人提成比例不强制 100%，不自动补齐；
- 回款比例自动释放和退款负向调整；
- 工资项项目/企业唯一归属；
- 工资单确认、应付生成、成本写入幂等；
- 员工发放、核销、Ledger 幂等；
- 跨店、跨企业、同事工资条越权拒绝；
- 工人工资与员工工资不混算；
- 关闭 OSIV 时关联读取正确。

### 验收顺序

1. 专用测试企业、专用账号；
2. 财务生成薪酬方案和考勤；
3. BOSS 确认工资单；
4. 财务发放，核对应付、成本和台账；
5. 员工查看工资条；
6. 合同签约、回款、提成自动释放、退款下期调整；
7. 店长本店查询和跨店负例。

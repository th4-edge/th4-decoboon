# 28 收款冲正业务详细设计

> 状态：**可研发草案（核心口径可研发，权限与跨期规则待用户最终确认）**
> 日期：2026-10-20
> 适用范围：装得清 Web / App 财务域、客户收款、应收核销、资金台账、提成释放、凭证与经营指标
> 业务依据：`DEC-016`、`DEC-065`、`DEC-075`、`MET-005`、`MET-006`、`docs/design/08`、`docs/design/23`、`docs/design/27`
> 当前实现事实：`Receipt` 无冲正状态与冲正接口；`ReceiptRefund` 是“客户退款”事实，不能替代“收款冲正”；自动收款流水当前不可由现有 `finance/ledger/delete` 作废。

---

## 1. 结论

### 1.1 一句话定义

**收款冲正**用于纠正“这笔收款本来就不该存在或录错了”的情况。它不是客户退款：

- 收款冲正：没有新的客户资金流出，只是撤销原错误收款事实；
- 客户退款：客户真实收到了退回的钱，必须走 `ReceiptRefund` 并产生真实支出流水。

### 1.2 核心原则

1. **不物理删除原收款**，保留原单、原台账、原经办人；
2. **冲正必须是独立事实**，不能把原 `Receipt.amount` 改成 0；
3. **应收、台账、提成、凭证、报表在同一事务内联动**；
4. **重复提交幂等**，一张收款最多只能成功冲正一次；
5. **冲正本身不可编辑**；如需重新登记，另建新收款；
6. **收款冲正不改变合同额、项目合同额和应收节点原始金额**。

### 1.3 边界

| 场景 | 是否使用收款冲正 | 正确动作 |
| --- | --- | --- |
| 收款没有实际到账 | 是 | 冲正原收款 |
| 金额录错 | 是 | 冲正后重记正确金额 |
| 应收节点选错 | 是 | 冲正后重记到正确应收 |
| 收款账户/日期录错 | 是 | 冲正后重记 |
| 同一笔款重复登记 | 是 | 冲正重复的那一笔 |
| 客户真实退钱 | 否 | 客户退款 |
| 项目合同金额调整 | 否 | 合同变更 / 增减项 |
| 应收计划金额调整 | 否 | 应收维护 |
| 仅修改备注、附件 | 否 | 另定低风险更正规则，不走财务冲正 |

## 2. 真实业务场景

### 场景 A：误点“登记收款”

- 使用人：企业负责人
- 触发事件：客户尚未付款，负责人误把首期应收登记为已收 `22,650.00`
- 当前动作：发现错误后，从收款记录发起“收款冲正”
- 系统下一步：
  1. 原收款保留并标记“已冲正”；
  2. 生成同金额反向台账；
  3. 首期应收已收金额减回 0，状态恢复待收；
  4. 冲正原收款可能释放的提成；
  5. 汇总、项目回款、财务工作台同步刷新。
- 异常处理：存在退款、已月结或已被后续业务消费时阻断，并提示对应去向。

### 场景 B：金额录错，需要冲正后重记

- 使用人：财务
- 触发事件：应登记 `10,000.00`，实际误录为 `100,000.00`
- 当前动作：发起冲正；冲正成功后，系统引导重新登记正确收款
- 系统下一步：原单标记冲正；新收款使用新的幂等键和独立单据号；应收按净有效收款重算。
- 异常处理：重记前允许先完成冲正，不要求一次事务内强制重记，避免因忘记正确金额而卡住。

### 场景 C：客户真实退款

- 使用人：财务
- 触发事件：客户已付款，后因退单要求退回 `10,000.00`
- 当前动作：从原收款登记客户退款
- 系统下一步：生成退款事实、真实现金支出流水、提成负向调整。
- 明确规则：不得用“收款冲正”替代退款，否则会掩盖真实资金流出。

### 场景 D：跨月发现误收款

- 使用人：企业负责人
- 触发事件：本月发现上月误登记收款
- 当前动作：发起冲正
- 系统下一步：原收款继续保留在上月历史；本期生成冲正调整，累计净回款恢复正确。
- 异常处理：若该期已月结，必须按跨期调整处理，不能回写已关闭期间的原始数字。

## 3. 业务对象设计

### 3.1 `Receipt` 扩展

在现有 `Receipt` 上增加状态，不删除、不改金额：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | `ReceiptStatus` | `Active` / `Reversed`，默认 `Active` |
| `reversedAt` | DateTime | 冲正完成时间 |
| `reversedBy` | Employee | 冲正操作人 |
| `reversalReason` | String | 冲正原因快照 |
| `reversalId` | `ReceiptReversal` | 指向冲正事实，可为空 |

> 建议将 `reversalId` 做成一对一反向关联；如为避免循环依赖，也可只保留 `ReceiptReversal.receipt` 单向关联，并依靠唯一索引保证一张收款只有一次冲正。

### 3.2 新增 `ReceiptReversal`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `reversalId` | Long | 是 | 雪花主键 |
| `company/store/team/owner` | 关联 | 是/按现有规则 | 与收款相同的组织归属 |
| `receipt` | Receipt | 是 | 原收款，企业内唯一 |
| `project` | Project | 是 | 原收款项目 |
| `customer` | Customer | 是 | 原收款客户 |
| `receivable` | Receivable | 是 | 原核销应收 |
| `amount` | BigDecimal | 是 | 必须等于原收款金额，首期只支持全额冲正 |
| `reversalAt` | LocalDate | 是 | 冲正业务日期，默认当天 |
| `reasonType` | Enum | 是 | 未实际到账/金额录错/应收选错/重复登记/账户或日期错/其他 |
| `reason` | String(500) | 是 | 具体说明 |
| `operator` | Employee | 是 | 操作人 |
| `idempotencyKey` | String(128) | 是 | 企业内唯一 |
| `idempotencyFingerprint` | String(64) | 是 | 防同键不同内容 |
| `reversalLedger` | Ledger | 是 | 反向调整台账 |
| `replacementReceipt` | Receipt | 否 | 如后续重记，可建立关联 |
| `beforeSnapshot` / `afterSnapshot` | longtext | 是 | 收款/应收/台账/提成/凭证影响快照 |

### 3.3 台账设计

原 `Ledger(Income, Receipt)` 保留，不删除、不直接改金额。

新增冲正台账：

```text
direction       = Expense
source          = ReceiptReversal
sourceId        = reversalId
originalLedger  = 原收款台账
correctionGroupId = 与原收款台账共用
amount          = 原收款金额
occurredAt      = reversalAt
summary         = 收款冲正：<原摘要>
remark          = 冲正原因
```

建议新增 `LedgerSource.ReceiptReversal("收款冲正")`，避免与客户退款、手工调整混淆。

### 3.4 不等同于退款

`ReceiptRefund` 的对象语义是“真实退款”，不新增冲正字段复用：

- 冲正不生成退款记录；
- 冲正不冲减已收后又当作退款；
- 已有退款的原收款禁止再冲正；
- 已冲正的收款不得再登记退款。

## 4. 状态机

### 4.1 收款

```text
Active
  └─ 收款冲正成功 -> Reversed
```

`Reversed` 是终态，不允许恢复为 `Active`。如需重新登记，新建一条 `Receipt`。

### 4.2 冲正事实

```text
Created（事务内一次形成）
```

不提供编辑、撤销冲正。若冲正本身录错，应通过重新登记正确收款或后续专设“冲正撤销”高级能力处理，首期不做。

### 4.3 应收

冲正后按净有效收款重算：

```text
receivedAmount = Σ Active Receipt.amount（该应收）
status =
  receivedAmount = 0             -> Pending
  0 < receivedAmount < amount    -> Partial
  receivedAmount >= amount       -> Received
```

到期未收是否显示 `Overdue`，仍由现有查询/状态派生逻辑处理，不把冲正当作“逾期确认”。

## 5. 权限设计

### 5.1 建议矩阵

| 角色 | 数据范围 | 收款登记 | 收款冲正 | 说明 |
| --- | --- | --- | --- | --- |
| BOSS | 全企业 | 允许 | 允许 | 财务高危动作全企业范围 |
| StoreManager | 本店 | 允许 | 允许 | 遵循 `DEC-075` 本店高危动作口径 |
| Finance | 本店/总部 | 允许 | 默认不允许 | 防止记账人自行删除错误事实；是否放开待用户确认 |
| TeamLeader / Designer / Pm | 业务范围 | 不允许 | 不允许 | 非财务高危角色 |

> 2026-11-02 用户裁决（`DEC-099`）：BOSS/总部财务全企业、门店财务/店长本店可执行收款冲正；其他角色拒绝，跨店由服务端返回 403/404。原审计、反释放提成和凭证门禁不变。

### 5.2 数据范围

- 所有查询必须同时校验 `company + store + 项目/门店`；
- 店长不能冲正他店收款；
- 企业范围角色可跨店，但前端切换门店不等于授权；
- 禁止信任前端传入 `companyId/storeId/operatorId`。

## 6. 前置条件与阻断规则

发起冲正前必须同时满足：

1. 收款存在且状态为 `Active`；
2. 当前用户有该门店/企业的冲正权限；
3. 收款未被冲正过；
4. 收款不存在客户退款；
5. 收款未处于已关闭的月结期间，或按跨期规则生成当期调整；
6. 收款未关联已作废/不可修复的异常项目状态；
7. 目标应收仍存在，且属于同一项目、客户、企业；
8. 原收款台账存在并可定位；
9. 若已释放提成：
   - 未发放：允许反释放；
   - 已发放：必须生成下期负向调整，不在原期扣回；
10. 若已生成凭证：
    - 凭证未生成：正常冲正；
    - 已生成：作废原凭证并保留审计，允许后续重生成；
11. 若该收款参与了后续结转/历史导入锁定：提示影响范围，由 BOSS 确认。

阻断文案应给出下一步，而不是只说“操作失败”。例如：

```text
该收款已存在客户退款，不能按收款冲正处理。请从退款记录发起退款更正。
```

## 7. 主流程

### 7.1 标准冲正

```text
用户在收款记录选择“收款冲正”
-> 展示原收款、应收、台账、提成、凭证影响
-> 填写原因类型与原因
-> 二次确认“冲正”
-> 服务端加分布式锁
-> 校验权限、状态、退款、期间、凭证、提成
-> 创建 ReceiptReversal
-> Receipt 标记 Reversed
-> 冲正台账生成
-> 应收已收金额与状态重算
-> 提成反释放 / 下期负向调整
-> 原凭证作废或标记失效
-> 写审计快照
-> 提交事务、清缓存、刷新列表和汇总
```

### 7.2 冲正后重记

```text
冲正成功
-> 页面提供“重新登记正确收款”
-> 新收款独立走 finance/receipt/save
-> 如从冲正页发起，可携带 replacementReceiptId 关联
-> 新收款使用新的幂等键
```

首期建议先做“冲正”与“重新登记”两个独立动作，不把两者强行做成一个不可拆分事务。

## 8. 金额与指标口径

### 8.1 收款额

为兼容历史期间，建议拆分而不是直接把原始收款改成 0：

```text
原始收款额 = Σ Receipt.amount（按 receivedAt 归期）
收款冲正额 = Σ ReceiptReversal.amount（按 reversalAt 归期）
净回款 = 原始收款额 - 收款冲正额
```

这样：

- 原月份历史事实不被回写；
- 冲正月份体现负向调整；
- 累计净回款准确；
- 收款列表仍能追溯原收款。

### 8.2 应收

```text
应收已收金额 = Σ 该应收 Active 收款
应收待收金额 = max(应收金额 - 应收已收金额, 0)
```

### 8.3 资金台账

```text
资金净流量 = Σ Income - Σ Expense（包含 ReceiptReversal）
账户余额 = 期初余额 + 累计资金收入 - 累计资金支出
```

`ReceiptReversal` 作为独立调整行展示：

- 计入现金余额；
- 在页面单独显示为“冲正调整”；
- 不伪装成真实客户退款支出；
- 汇总页建议新增 `reversalAmount`，避免把冲正混进普通费用分析。

### 8.4 项目与合同

冲正不改变：

- 合同签约价；
- 合同当前金额；
- 项目合同金额；
- 应收计划原始金额与比例；
- 已确认合同变更金额。

### 8.5 提成

```text
冲正前有效回款 = Σ Active Receipt
冲正后有效回款 = Σ Active Receipt（排除被冲正收款）
```

- 未发放的释放金额：减少 `releasedAmount`，状态回到 `Accrued` 或对应状态；
- 已发放金额：不改历史工资，生成 `CommissionAdjustmentType.ReceiptReversal`，进入下期负向调整；
- 已关闭/已结清提成：禁止直接反写，必须走负向调整或人工审批。

### 8.6 凭证

- 原凭证保留编号与原件；
- 已生成凭证状态改为 `Void` 或写入作废修订；
- 不物理删除文件；
- 如重记新收款，重新生成新凭证；
- 收款详情显示“原凭证已因冲正失效”。

## 9. 并发与幂等

### 9.1 唯一约束

- `db_finance_receipt_reversal (com_id, receipt_id)` 唯一；
- `db_finance_receipt_reversal (com_id, idempotency_key)` 唯一；
- 一张收款最多一条冲正。

### 9.2 锁

建议在 `ReceiptReversalContext.reverse()` 外层使用：

```text
receipt-reversal:{comId}:{receiptId}
```

避免两个用户同时冲正同一笔收款。

### 9.3 重复提交

- 同 receipt + 同幂等键：返回已有冲正结果；
- 同 receipt + 不同幂等键：返回“该收款已冲正，不能重复操作”；
- 冲正成功后不清理幂等记录，防止网络重试重复生成台账。

## 10. 审计

每次冲正必须保留：

- 原收款快照；
- 原应收快照；
- 原台账快照；
- 原凭证/退款/提成关联；
- 冲正后收款、应收、台账、提成、凭证状态；
- 操作人、门店、时间、原因类型、原因、幂等键；
- 冲正后关联的新收款 ID（如有）。

审计详情建议在 Web/App 都可查看，普通业务页面不提供物理删除入口。

## 11. UI/交互设计

### 11.1 入口

- Web 收款记录：行操作 `冲正`；
- App 收款记录：进入收款详情/操作面板后提供 `收款冲正`；
- 不要把“冲正”放在登记收款主按钮旁作为高频动作；
- 不允许在退款页面用“冲正”替代退款。

### 11.2 确认弹窗

必须展示影响清单：

```text
原收款：¥22,650.00（水电验收）
项目：P1792492921137
影响：
- 应收已收将减少 ¥22,650.00
- 将生成一条冲正台账
- 可能回退未发放提成
- 已生成凭证将失效
- 此动作不可直接恢复，只会保留审计
```

按钮文案：`确认冲正`，使用危险色；取消为默认。

### 11.3 列表展示

- 状态标签：`有效` / `已冲正`；
- 已冲正行金额可保留原值，但整行弱化；
- 收款详情显示冲正人、时间、原因和关联台账；
- 汇总区拆分：
  - 原始收款额
  - 收款冲正额
  - 净回款

### 11.4 冲正后的去向

冲正完成后：

- 展示“收款已冲正”；
- 给出“重新登记正确收款”入口；
- 返回列表时刷新应收和汇总；
- 不自动创建新收款，避免在用户未确认金额时产生第二笔错误。

```text
LedgerSource.ReceiptReversal("收款冲正")
```

如果 `source` 在数据库中是 `enum`，需要迁移；如果是字符串列，只需应用层新增枚举。

### 13.4 提成调整

新增 `CommissionAdjustmentType.ReceiptReversal("收款冲正")`，用于已发放提成的下期负向调整。

## 14. 验收用例

### 14.1 正向

1. BOSS 冲正本企业收款成功；
2. 店长冲正本店收款成功；
3. 原收款状态变为 `Reversed`；
4. 原收款和原台账仍在数据库；
5. 应收已收金额准确减少，状态回到 `Pending/Partial`；
6. 冲正台账金额、方向、来源正确；
7. 汇总页原始收款额、冲正额、净回款三者可对账；
8. 项目合同额不变；
9. 无提成、无凭证时无额外错误。

### 14.2 反向

1. 财务角色冲正应拒绝；
2. 店长冲正他店收款应拒绝；
3. 已冲正收款再次冲正应拒绝；
4. 同幂等键重复请求返回同一结果；
5. 同收款不同幂等键请求返回冲突；
6. 已有退款的原收款冲正应拒绝；
7. 跨企业/不存在收款返回 404 或统一无权错误；
8. 冲正金额不等于原收款金额应拒绝；
9. 已月结且不满足跨期规则应拒绝并提示；
10. 已发放提成直接回写历史工资应拒绝。

### 14.3 指标对账

冲正 `22,650.00` 后：

```text
原始收款额：22,650.00
收款冲正额：22,650.00
净回款：0.00
应收已收：0.00
应收未收：22,650.00
现金余额影响：-22,650.00（原误收入被冲回）
```

若原收款和冲正在同一月份，月报应能清楚区分“原始收款/冲正调整”，不得只显示一个无法解释的净数。

## 16. 当前实现差异与风险

| 差异 | 影响 | 建议 |
| --- | --- | --- |
| `Receipt` 无状态字段 | 无法标记已冲正 | 增加状态列 |
| 无 `ReceiptReversal` | 只能删原单或做运维数据修正 | 新增独立事实对象 |
| `ReceiptRefund` 无应收回退 | 退款与会收款余额口径可能分离 | 冲正单独设计，不混用退款 |
| 自动台账无真冲正入口 | 直接删除会破坏审计 | 增加反向台账与 revision |
| 报表直接 Σ Receipt | 冲正后易重复/错算 | 增加冲正额和净回款口径 |
| 提成释放无收款反释放 | 误冲正可能留下已计提提成 | 增加反释放/下期调整 |
| 凭证无收款冲正联动 | 原凭证可能继续有效 | 增加凭证作废修订 |

> 说明：当前生产上曾对一笔误收款采用一次性数据修正，这是临时运维处理，不代表产品已有“收款冲正”能力；后续应通过本设计的正式 Provider 和审计链路替代。

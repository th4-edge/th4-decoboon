# 29 · 主材下单作业单设计说明

> 业务依据：`SOL-014 主材下单作业单与行业标准单据体系方案`、`OBJ-008 主材下单作业单与单据模板`、`BR-044 主材下单作业单与行业标准基线规则`、`BR-045 采购价、无价下单与结算价成本口径规则`、`SCN-021 主材下单作业单成单、到货与结算`（业务智能体，均 `draft`）。
> 事实依据：`EV-314`（麦鸿装饰真实《主材下单表》结构分析，20 张品类子单据）、`EV-315`（用户 2026-10-15 业务主张：下单可能没有价格，需区分真实价与报价成本价）。
> 口径裁决：`DEC-072` / `EV-316`（6 项）+ `DEC-073` / `EV-317`（2 项），**8 项全部裁决，`GAP-057` 已闭合**。
> 状态：**可实施稿（P0 = 瓷砖单品类打样）**；研发交接见 `T12-BIZ-20261015-003`。
> 风险提示：迁移 117 属 DDL 高风险变更，**落盘与执行前需用户确认**（备份 + 回滚 + 全量验证）。
> 日期：2026-10-15
> 定位：在既有「材料计划 → 采购 → 到货 → 应付/成本」主链之上，新增**作业单据层**（品类单据 + 模板 + 个性化配置），并补充**无价下单与结算价收敛**口径。
> 边界：不改变报价、合同、成本快照；不新增第二套事实账；不重构 `MaterialPlan` 主链语义；不做通用表单引擎。

---

## 0. 结论

1. 现有链路 `MaterialPlan → PurchaseOrder → GoodsReceipt → Payable` 是**事实账**，保持不变；缺的是**作业单据层**。
2. 新增三张表（迁移 117）：`db_material_sheet_template`（企业级单据模板）、`db_material_order_sheet`（项目级作业单）、`db_material_order_sheet_item`（作业单行）。
3. 单据与行的所有数量、金额、成本、状态**最终仍写入事实层对象**；作业单只做「聚合视图 + 编排」。
4. 价格允许缺失：`priceState = Unpriced` 时可下单、可到场；价格字段留空（**不是 0**）；成本不完整时利润必须为 `null`。
5. 打印/版式**复用现有** `DocumentTemplate`（`DocumentType.Material` + `DocumentTemplateScope.Platform/Company`），不新建打印体系。
6. 行业标准基线 = 17 个品类基线；企业个性化只在**受控白名单**内可改，事实与口径为红线。
7. **已裁决口径**（`DEC-072`）：无价下单形成暂估应付；结算按"供应商+期间（月结）"与"采购单逐单"两种方式**并存**（先后规则待定）；成本悬挂期不设上限与告警；成本偏差作为**正式能力**对老板输出；结算价**不沉淀**为供应商参考价；合同外/标配外主材**必须先走增减项**（作业单取消 `Extra` 行来源，"标配"改为行属性）；提供 **Excel 单据导出**（不要求导入）。
8. **单据边界（已裁决）**：作业单与采购单是**两个对象、两张单** —— 作业单对厂家（不带价格与账期），采购单对财务；1 张作业单 → N 张采购单。
9. **结算优先级（已裁决）**：互斥（同一采购行只允许一种结算方式计入）+ 逐单优先 + 月结兜底（期末只结算未逐单结算的差额）。
10. **P0 范围收敛**：只做**瓷砖**一类基线端到端打样，其余 16 类在 P1 铺开（见 §10）。

### 2.5 单据边界与映射契约（`DEC-073`）

**两张单，职责分离**：

```text
MaterialPlan（事实：需求量/净用量/损耗）
   ├── MaterialOrderSheet（作业单：对厂家，品类粒度，不带价与账期）
   │        └── MaterialOrderSheetItem[]（行，挂 materialPlan）
   └── PurchaseOrder（采购单：对财务，按供应商，携带价格可空 + 账期）
            └── PurchaseOrderItem[]（行，挂 materialPlan + materialOrderSheetItem）
```

| 契约 | 规则 |
| --- | --- |
| 追溯 | 每条采购明细必须能追溯到作业单行与 `MaterialPlan`；作业单行可对应 0..N 条采购明细（分供应商/分批/补货） |
| 对账 | 作业单行需求量 = Σ 采购明细下单量（允许分次）；到场量按采购明细累计 |
| 价格 | 价格、账期、供应商只写在采购单侧；作业单不带价格字段 |
| 补货 | 另起采购明细（或新采购单），**不改动原作业单行**；原单不变形 |
| 退货 | 走 `MaterialReturn` 冲减应付与已确认成本；作业单只反映"已到场/已扣减" |
| 取消 | 已下单后取消作业单，必须走采购调整或退货，不能直接抹除 |
| 一致性 | 作业单状态单向派生；`MaterialPlanStatus` 与采购/到货事实保持一致，禁止双写 |

**结算优先级（`DEC-073`）**：

1. **互斥**：同一条采购明细只允许被一种结算方式计入金额；
2. **逐单优先**：能确认单张采购单最终价时先逐单结算，提前锁定实际成本；
3. **月结兜底**：期末按"供应商 + 期间"汇总，只结算尚未逐单结算的差额，已逐单结算的行仅展示；
4. **留痕**：结算记录保留结算方式、期间、供应商、对应采购明细与金额，可回溯、可撤销（撤销走反向记录）。

## 3. 状态机与映射契约

```text
Draft(填单中) → Measuring(待测量) → Measured(已测量)
   → Submitted(已提交请购) → Pricing(财务核价) → Ordered(已下单)
   → PartiallyArrived(部分到场) → Arrived(已到场) → Settled(已结算) → Closed(已关闭)
任意态 → Cancelled(已取消，需填原因；已下单后取消必须走采购调整/退货)
```

| 作业单事件 | 事实层动作 | `MaterialPlanStatus` 影响 |
| --- | --- | --- |
| `Submitted` | 无 | 不变 |
| `Ordered` | 生成/更新 `PurchaseOrder` + `PurchaseOrderItem`；有价 → `Payable`；无价 → 暂估应付【待裁决】 | `PartiallyOrdered` / `Ordered` |
| 到场确认 | `GoodsReceipt` + 累计 `receivedQuantity` + 回填账期 | `PartiallyArrived` / `Arrived` |
| `Settled` | 回填 `settlementPrice`、修正暂估应付、重算实际成本 | 不变 |
| 退货/补货 | `MaterialReturn` / 新采购 | 按差额回退 |

**契约**：作业单状态**单向派生**，`MaterialPlanStatus` 只由采购/到货事实推进；两个状态源不得互相写入。

## 6. 金额与成本口径落点（`BR-045`）

| 概念 | 落点字段 | 规则 |
| --- | --- | --- |
| 报价成本价 P1 | `MaterialOrderSheetItem.quoteCostPrice`（只读快照）、`MaterialPlan.unitPrice/cost` | 签约冻结，不因采购变化（`DEC-MP-06`） |
| 采购价 P2 | `PurchaseOrderItem.unitPrice`、`MaterialOrderSheetItem.purchasePrice` | 可空；`priceState=Priced/Unpriced` |
| 结算价 P3 | 新增采购行字段 `settlementPrice` + 结算记录 | 唯一实际成本来源；**不沉淀**为供应商参考价（`DEC-072` 第 5 项） |
| 应付 | `Payable` | 有价下单即形成（`DEC-MP-01`）；**无价 → 暂估应付**（`estimated=true`，`amount=0`，结算回填 `settledAmount`）；结算修正留痕 |
| 结算粒度 | `Payable.period` + 采购单/行 | 月结（供应商 + 期间）与逐单**并存**；同一采购行不得被两种方式重复计入（先后规则待定） |
| 成本偏差 | 报表能力 | **正式能力**对老板输出（`DEC-072` 第 4 项）；按项目 / 品类 / 供应商维度，缺失即 `null` |
| 成本悬挂期 | — | **不设上限、不设告警**（`DEC-072` 第 3 项） |
| 实际成本 | 到货/入库累计（计价 P3 > P2） | 缺失即 `costComplete=false` → 利润 `null` |

**禁止**：0 冒充未知价；P2 改写 P1；P1 充当实际成本；未收敛展示实际毛利；无价阻断到场；非财务角色定价。

## 8. 性能与实现约束

- 列表/工作台接口：最小字段白名单 + 分页 + 条数上限；禁止返回实体全量（`rules.md` §5、`DEC-037`）。
- 汇总/进度类接口用聚合 SQL 直接算（`BR-031`）：禁止全量实体 + Java 循环、禁止循环体内查库。
- 关联读取：`@EntityGraph` / `JOIN FETCH` 预取，禁止在无事务边界的 Filter/Component 中访问 LAZY。
- 并发：不使用数据库悲观锁；如需并发保护用 `RedissonLock`（`DEC-029`）。

## 9. 验收清单

| 组 | 用例 |
| --- | --- |
| 正向 | 建单 → 测量确认 → 提交请购 → 有价下单（形成应付） → 到场 → 结算 → 成本完整、可算实际毛利 |
| 无价 | 无价下单成功（`priceState=Unpriced`、金额留空） → 可到场 → 利润为 `null` 且文案"成本待结算" → 结算后回填并收敛 |
| 反向 | 未选材行不可加入；数量超「净用量+损耗」拦截；模板白名单外字段被忽略；已下单取消必须走退货/采购调整 |
| 越权 | 跨企业/跨店/非项目参与关系一律 404；Designer/Pm 无法定价；Marketer/TeamLeader 只读 |
| 幂等 | 重复提交/重复下单不产生第二张采购单、不重复形成应付 |
| 金额边界 | 作业单不改变报价、合同、成本快照与选材文本；无价时不出现 0 成本与伪利润 |
| 暂估应付 | 无价下单 → 应付 `estimated=true` 且金额为待定态（不得为 0 冒充）→ 结算后回填 `settledAmount` 并保留暂估留痕 |
| 结算 | 月结（供应商 + 期间）与逐单结算均可登记；同一采购行不得被两种方式重复计入 |
| 成本偏差 | 预计与实际齐备时输出偏差与偏差率；任一缺失返回 `null`；按项目 / 品类 / 供应商维度可查 |
| 导出 | Excel 导出内容与导出时快照一致；模板后续升级不影响已导出文件 |
| 合同外 | 作业单无法添加 `Extra` 行；未确认的增减项不产生材料需求、不进入下单队列 |
| 版本 | 模板升级不回溯改变历史单据；单据按冻结版本呈现 |
| 性能 | 列表接口字段白名单与条数上限生效；工作台端到端 SQL ≤30 条、P95 ≤500ms（`BR-025`/`BR-031`） |

| 项 | 内容 |

## 4. 状态机与流转矩阵

```text
New ─► Contacted ─► Qualified ─► Scheduled ─► Demoed ─► Trial ─► Converted(开通租户)
         │
         ├─► Invalid（记 invalid_reason）
         └─► Dormant（30 天无进展 / 连续 3 次联系不上） ─► Contacted（复活）
```

| 流转 | 触发 | 必填 | 留痕 |
| --- | --- | --- | --- |
| New → Contacted | 运营首次联系成功 | `last_contact_at` | `LeadFollow(Contact)` |
| Contacted → Qualified/Invalid | 人工判定 | `invalid_reason`（Invalid 必填） | `LeadFollow(StageChange)` |
| Qualified → Scheduled → Demoed → Trial | 预约/演示/试用发生 | — | 同上 |
| Trial → Converted | 付费开通租户成功 | 租户 ID | 同上 |
| * → Dormant | 定时任务判定 | 触发条件快照 | `LeadFollow(StageChange)` |

## 5. 去重与幂等

1. 手机号归一化 → `dedupe_key`（规则待第 3 节第 ④ 项确认；草案：去空格/连字符 → 带 +86 → 去前导 0）。
2. 提交时查 `dedupe_key` + `status`：
   - 命中未关闭（非 `Converted`/`Invalid`/`Dormant`）→ **合并/追加跟进**，不新建；
   - 命中已关闭（`Invalid`/`Converted`/`Dormant`）→ 新建，并标 `note="历史线索重新触达"`。
3. 并发：`dedupe_key` + 状态唯一约束兜底，冲突时返回已存在线索（幂等）。
4. **历史数据兼容**：`Closed` 保留；展示层映射为 `Invalid`（若无 `Converted` 证据），并在首次维护时人工确认一次。

## 6. SLA 与定时任务

| 任务 | 判据 | 动作 |
| --- | --- | --- |
| 首响提醒 | `status=New` 且 `now - create_time > 24h`（工作日） | 通知归属人或线索池 |
| 跟进提醒 | `next_follow_at` 过期 / 3 个工作日无 `LeadFollow` | 通知 |
| 失效 | 3 次联系不上 或 30 天无进展 | `→ Dormant` |
| 保留期 | `retention_until < now` 且未转化 | 删除或匿名化 |
| 撤回 | `revoked_at` 非空 | 停止触达 + 归档 |

## 7. 权限与数据范围

- 平台运营/销售：查看/领取/转交/关闭；导出限负责人并留痕。
- **租户角色一律拒绝**（含 BOSS）；平台域 Provider 不参与租户数据范围解析。
- 平台运营**不可**访问租户客户数据（`LeadTouch`/`Customer` 属租户域）。
- 越权与跨域访问必须有自动化用例（§9）。

## 8. 隐私与合规

`consent` 提交时校验并快照；未转化 12 个月保留；支持撤回（停止触达 + 归档）；导出留痕；
不保存平台密码/Cookie/验证码，不使用群控工具（`DEC-060` 约束 5）。

## 9. 验收清单

**正向**
- [ ] 官网提交 → 落库 `source=website`；抖音提交 → `source=douyin` 且归因字段结构化落库。
- [ ] 同一手机号二次提交 → 合并到原线索并追加跟进，不产生新记录。
- [ ] 命中已关闭线索 → 新建并标记「历史线索重新触达」。
- [ ] `New → Contacted → Qualified → … → Converted` 全路径可走通，每步有 `LeadFollow`。
- [ ] `Converted` 后开通企业租户，且**不产生**租户客户记录。

**反向**
- [ ] 蜜罐非空 → 400 且不落库；`consent=false` → 400；超长字段 → 校验拒绝。
- [ ] 未登录/租户账号调用 `site/lead/page|info|update` → 拒绝。
- [ ] 状态非法跳转（如 `New → Converted`）→ 拒绝并提示。

**越权 / 跨域**
- [ ] 租户任何角色不可见 `db_site_lead` 与 `LeadFollow`。
- [ ] 平台运营不可见租户 `Customer`/`LeadTouch`。
- [ ] 导出无审计记录时拒绝。

**幂等 / 并发**
- [ ] 并发两次相同手机号提交 → 只产生一条线索。
- [ ] 两名运营同时领取 → 只有一人成功，另一人收到明确失败。

**边界 / 降级**
- [ ] SLA 定时任务在超期/失效/保留期到期时正确置位（含复活路径）。
- [ ] 抖音归因字段迁移不丢历史（迁移前有数据清洗与校验步骤）。
- [ ] 官网三字段接入顺序校验：**后端字段未落地时前端不得先行上线**。

## 10. 不做清单（P0-a）

- 不做租户侧线索池/公海（`GAP-059` L4 未裁决）。
- 不做公开短视频社区、多轨剪辑器、员工个人号自动发布、多平台矩阵（`DEC-060` P0 边界）。
- 不做平台全量数据自动读取、不做按播放量发工资/扣款。
- 不做抖音 L2 代开发（`GAP-059` L7 未裁决）。
- 不做线索自动分配算法（P0 只做人工领取/指派）。

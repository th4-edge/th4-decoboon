# docs/design — 跨端与接口设计规范

> 根目录 `AGENTS.md` 同时生效。本目录负责跨端契约和接口设计，不定义业务事实，不替代产品裁决。

## 1. 设计前置

- 业务对象、状态、权限、金额/成本和对外口径先经业务智能体裁决；设计文档只能展开已冻结事实。
- 同一能力先列出 Provider、App 调用、Web/Admin 调用、权限、状态、金额/成本、异常恢复和两端验证方式。
- 只验证一端不得写“跨端对齐”；接口失败或正式值缺失必须设计“暂不可确认”和恢复路径。

## 2. 强制规范

- 一后端多端同源：`docs/design/31-一后端多端同源架构规范.md`
- Provider 响应、白名单与懒加载：`docs/design/32-Provider接口响应序列化与懒加载安全规范.md`
- 分页、报表和计数：`docs/design/33-后端分页与聚合接口强制规范.md`
- 接口查询与业务编排：`docs/design/34-后端接口查询与业务编排强制规范.md`
- 业务对象选择器：`docs/design/35-业务对象选择器与选择结果展示规范.md`

## 3. 设计交付

- 写清使用人、触发时点、最短动作、下游消费者、数据增长、异常路径和验收。
- 接口必须分类并声明最大行数、查询链、SQL 是否随数据量增长；增长型历史独立分页。
- 选择器必须打开即展示业务数据，提供服务端搜索分页、七态、选择/清除/取消、一次性回传和服务端复核。
- 新增或改版选择器先走 `T15`；涉及表单补 `T16`；稳定单据补 `T17` 并取得 `T06/T12` 裁决。选择、清除、依赖失效和回显必须进入验收。
- 页面不得展示系统内部编号；内部 ID 只用于路由、权限、审计和接口契约。
- Web 页面设计按 Web 仓库 `src/AGENTS.md` 和 `docs/standards/**` 执行；App 页面遵循 App 仓库规范和真机证据要求。

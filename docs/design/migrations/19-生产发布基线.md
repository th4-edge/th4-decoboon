# 生产发布基线、迁移、备份与回滚 Runbook

> 本文件只提供生产操作模板。2026-09-16 已在生产 MySQL 8 完成空库基线和应用部署，但备份恢复、回滚演练和真实业务验收仍未完成。

## 1. 生产配置

生产启动必须使用 `prod` profile，并至少注入以下环境变量：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `DB_URL` | 是 | MySQL JDBC URL，必须启用与网络边界匹配的 SSL 参数 |
| `DB_USERNAME` | 是 | 最小权限数据库账号，不使用 root |
| `DB_PASSWORD` | 是 | 数据库密钥 |
| `REDIS_HOST` | 是 | Redis 主机 |
| `REDIS_PORT` | 否 | 默认 6379 |
| `REDIS_PASSWORD` | 是 | Redis 密码；无密码实例也必须显式提供空值 |
| `WECHAT_MINI_ENABLED` | 是 | 小程序登录开关 |
| `WECHAT_MINI_APP_ID` | 是 | 小程序 AppID |
| `WECHAT_MINI_APP_SECRET` | 是 | 小程序密钥 |
| `TH4_FILE_UPLOAD_DIR` | 是 | 私有文件共享目录，所有实例必须一致 |
| `TH4_FILE_PUBLIC_DIR` | 是 | 公开文件目录，必须与私有目录物理隔离 |
| `TH4_FILE_SIGNATURE_SECRET` | 是 | 多实例一致的 HMAC 密钥 |
| `TH4_PASSWORD_BOOTSTRAP_TOKEN` | 条件必填 | Web 员工首次设置密码的受控 bootstrap token；为空时首设接口拒绝请求 |
| `LOG_PATH` | 否 | 默认 `/var/log/th4-decoboon` |

若 `WECHAT_PAY_ENABLED=true`，还必须提供商户号、证书序列号、私钥、API v3 密钥、平台公钥和回调地址等支付变量。生产 profile 的 `ddl-auto=validate`，不会自动修改数据库。

## 3. 数据库迁移

### 3.1 迁移路径决策

本轮正式支持的迁移路径分为两类，默认 Runbook 不再承诺存量库自动升级：

| 路径 | 适用前提 | 允许动作 | 明确禁止 |
| --- | --- | --- | --- |
| `new_empty_database` | MySQL 8 全新空库 | 执行 `00-迁移账本.sql` 和 `01-空库基线.sql`；将 10、11、12、17、21 登记为 `BASELINE` | 对非空库执行基线；执行不完整增量链 |
| `existing_database` | 已有生产数据或既有结构 | DBA 完成表、列、索引、外键和约束审计后，使用 `adopt` 登记已审计版本 | 自动执行 `upgrade`；未审计直接补跑迁移 |

- `00-迁移账本.sql`：创建 `db_schema_migration`，记录版本、SHA-256、状态、执行人、开始/完成时间和失败信息。
- `01-空库基线.sql`：从当前 JPA 元数据生成，覆盖当前全部实体表、索引和外键，已包含 10、11、12、17、21 的最终结构。
- `10`、`11`、`12`、`17`、`21`：只作为历史版本标识和审计依据，不代表已完成存量库升级链；任何存量库差异迁移必须单独形成完整 DDL、经过 DBA/发布负责人评审并在隔离环境演练后执行。
- `18`、`19`、`20` 是发布说明，不执行 DDL。

迁移状态：

```text
RUNNING -> BASELINE（仅 01 空库基线成功后）
RUNNING -> FAILED（脚本捕获失败并写入；若账本写入本身失败，输出 CRITICAL 并阻断，人工立即修复）
BASELINE：空库基线已包含该版本，未单独执行该版本 SQL
ADOPTED：存量库经 DBA 审计后确认已具备该版本结构
CHECKSUM_DRIFT：账本 SHA-256 与当前文件不一致，必须停止并重新评审
```

### 3.2 空库初始化（正式支持）

```bash
export MYSQL_DATABASE=zqsmart
export MYSQL_CNF=/run/secrets/th4-mysql.cnf       # 权限 0600，预置 host/user/password
export MIGRATION_ACTOR=release-$(date +%Y%m%d%H%M)
export MIGRATION_LOCK_DIR=/var/lock/th4-decoboon-migration.lock

bash docs/design/migrations/run-migrations.sh.template baseline
```

`baseline` 只执行 `00-迁移账本.sql` 和 `01-空库基线.sql`，并将 10、11、12、17、21 标记为 `BASELINE`。脚本会先拒绝非空数据库。基线不得在已有业务数据的数据库执行。

### 3.3 存量数据库：DBA 审计后 adopt

`upgrade` 已从默认和自动执行路径禁用；脚本遇到 `upgrade` 会直接输出 `UPGRADE_DISABLED` 并退出，不会执行 10、11、12、17、21。已有数据或既有结构不得自动执行不完整升级链。

历史设计说明或迁移草稿中若仍出现直接执行 `10-设计转化域迁移.sql` 的提示，一律以本 Runbook 为准；该文件只保留审计线索，不能替代完整差异迁移。

DBA 必须先审计目标库的表、列、索引、外键、约束和实际数据边界，并保存审计记录。确认目标版本结构已经完整存在后，只允许登记审计结果：

```bash
export DBA_AUDIT_ID=CHG-20260915-001
bash docs/design/migrations/run-migrations.sh.template adopt 10,11,12,17,21
```

`adopt` 模式只写入 `db_schema_migration`，不执行任何 DDL。若审计发现差异，必须停止 adopt，单独制定完整差异迁移、评审、备份并在隔离 MySQL 8 环境演练后再执行；本 Runbook 不提供未完成的增量升级承诺。

Web 员工密码登录依赖 `21-用户密码登录.sql` 的凭证字段和安全日志枚举；存量库必须先审计该结构，缺失时纳入同一份完整差异迁移，再部署支持密码登录的后端版本。

### 3.4 重复执行、失败保护和校验和

- 脚本先查询 `db_schema_migration`，状态为 `SUCCESS/BASELINE/ADOPTED` 的版本可直接跳过；不会重复执行已登记版本。
- 每个被执行文件的 SHA-256 会在执行前写入账本。后续执行时若账本校验值与当前文件不一致，脚本输出 `CHECKSUM_DRIFT`、停止执行并要求重新评审；不得通过改账本绕过漂移。
- 空库基线 SQL 失败时，脚本捕获非零退出码并尝试把同一版本从 `RUNNING` 更新为 `FAILED`。如果 `FAILED` 也无法写入，会输出 `CRITICAL` 并阻止继续发布，绝不静默保留 `RUNNING` 为成功。
- 账本中存在 `RUNNING` 或 `FAILED` 时，脚本拒绝自动重跑；必须由 DBA 根据备份、实际 DDL 结果和审计记录完成人工恢复或补齐。
- MySQL DDL 自动提交，脚本不会尝试用事务回滚已经执行的 DDL。
- 所有目录变量均先通过 `realpath`/Python 规范化；危险根目录在规范化后拒绝，避免 `/var/..` 等变体绕过检查。
- 每次执行前后都保存账本查询结果、脚本输出和 SHA-256 证据作为发布证据。

### 3.5 基线重建

当前仓库已经足够从 JPA 元数据生成基线 DDL，生成过程只写文件，不连接业务数据库：

```bash
bash docs/design/migrations/generate-baseline.sh.template \
  /path/to/th4-decoboon
# Linux 优先 sha256sum；macOS/兼容环境可用 shasum -a 256
sha256sum docs/design/migrations/01-空库基线.sql 2>/dev/null || \
  shasum -a 256 docs/design/migrations/01-空库基线.sql
```

## 4. 备份

```bash
STAMP=$(date +%Y%m%d%H%M%S)
BACKUP_DIR=/backup/th4-decoboon/$STAMP
mkdir -p "$BACKUP_DIR"

mysqldump --single-transaction --routines --triggers --events \
  --set-gtid-purged=OFF --defaults-extra-file="$BACKUP_CNF" "$MYSQL_DATABASE" \
  | gzip > "$BACKUP_DIR/database.sql.gz"

tar -C "$TH4_FILE_UPLOAD_DIR" -czf "$BACKUP_DIR/upload-dir.tar.gz" .
tar -C "$TH4_FILE_PUBLIC_DIR" -czf "$BACKUP_DIR/public-dir.tar.gz" .
sha256sum "$BACKUP_DIR"/* > "$BACKUP_DIR/SHA256SUMS"
```

备份后必须执行一次恢复演练，不能只检查“文件已生成”。

## 6. 回滚

采用“新库、新目录恢复后切换”的方式，不在原生产库或原生产目录上删除、覆盖数据。

```bash
export MYSQL_CNF=/run/secrets/th4-mysql.cnf
export SOURCE_DATABASE=zqsmart
export RESTORE_DATABASE=zqsmart_rollback_20260915
export BACKUP_DIR=/backup/th4-decoboon/20260915T120000
export RESTORE_ROOT=/srv/th4-decoboon/restore
export RELEASE_ID=rollback-20260915

bash docs/design/migrations/rollback-safe.sh.template
```

脚本强制校验：

- `MYSQL_CNF`、`BACKUP_DIR`、`RESTORE_ROOT` 必须是非空绝对路径。
- 恢复库不能等于生产库，恢复库必须为空或不存在。
- `BACKUP_DIR` 和 `RESTORE_ROOT` 会先用 `realpath`/Python 规范化，再拒绝 `/`、`/Users`、`/var`、`/tmp` 等系统或危险根目录；`/var/..` 等变体不能绕过。
- 恢复目录必须位于 `RESTORE_ROOT/<RELEASE_ID>` 边界内，已存在则拒绝。
- 数据库、私有文件和公开文件备份必须存在，并通过 `SHA256SUMS` 校验。

脚本不会执行递归强制删除，不会删除旧数据库或旧文件目录。验证方式：

1. 使用输出的恢复库与恢复目录启动一个隔离实例。
2. 执行登录、项目、验收、文件和续费只读冒烟。
3. 发布负责人审批后切换 `DB_URL`、`TH4_FILE_UPLOAD_DIR`、`TH4_FILE_PUBLIC_DIR`。
4. 旧库和旧目录保留到观察期结束，由独立数据清理审批流程处理。

### 6.1 角色责任与审批矩阵

| 步骤 | 主责 | 共同责任/审批 | 必须证据 | 故障升级 |
| --- | --- | --- | --- | --- |
| 范围冻结与上线批准 | 产品负责人 | 技术负责人、发布经理 | 版本范围、排除项、上线批准记录 | 不批准则停止发布 |
| 代码与 Provider 安全预检 | 后端开发 | 技术负责人 | `mvn test` 结果、Provider 扫描 CSV/MD | 1 小时内无法修复则阻断 |
| 小程序构建与合规预检 | 前端开发 | 产品、法务 | `verify:mp-weixin`、域名/AppID/协议检查 | 正式材料缺失则阻断 |
| 密钥与配置检查 | 运维负责人 | 安全负责人、后端开发 | 密钥来源、变量清单、权限截图 | 密钥泄露立即启动轮换和事故流程 |
| 数据库备份 | DBA | 运维负责人 | 备份文件、SHA-256、恢复演练记录 | 备份校验失败则禁止迁移 |
| 空库基线或 DBA 审计 adopt | DBA | 发布经理、后端开发 | `db_schema_migration`、审计记录、脚本日志、DDL 结果 | `FAILED`/`RUNNING` 后停止发布，按备份恢复或人工修复 |
| 应用部署 | 运维负责人 | 发布经理、后端开发 | 上一/新版本 JAR、部署日志、实例清单 | 启动失败回退上一版本 |
| 发布后验证 | QA/验收角色 | 产品、开发、运维 | 冒烟、权限、文件、支付/续费证据 | P0/P1 失败立即回退 |
| 回滚 | 发布经理 | DBA、运维、技术负责人 | 恢复库/恢复目录、校验值、审批记录 | 无法验证恢复则保持旧版本 |
| 观察期关闭 | 产品负责人 | 运维、DBA、安全 | 监控报告、数据核对、遗留问题清单 | 新问题重新进入事故/变更流程 |

审批点：

- 备份完成后必须由 DBA 和发布经理双人确认备份可读、校验值一致。
- 迁移执行前必须完成代码预检、备份、迁移 SQL 评审和恢复方案评审。
- 流量切换前必须完成恢复库/恢复目录隔离冒烟，且由发布经理批准。
- 旧库和旧目录清理必须另行审批，不属于本 Runbook 的回滚步骤。

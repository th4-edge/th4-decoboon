# 小程序正式域名、协议、隐私与提审基线

> 当前文档是发布准备清单，不代表域名、主体、AppID、备案或法律文本已经完成审核。以下未知项必须作为发布阻断处理，不得用占位信息代替真实材料提交。

## 1. API 与 HTTPS

构建规则：

- 开发环境从根目录 `.env` 读取 `VITE_API_BASE`，允许本地 HTTP。
- 生产构建从 CI 或 `.env.production` 读取 `VITE_API_BASE`，必须以 `https://` 开头并以 `/` 结尾。
- `vite.config.ts` 在生产模式检测到非 HTTPS 时直接终止构建。
- 仓库内 `.env.production` 只保留 `https://api.invalid/api/` 作为安全构建占位，不得直接提审。

发布前必须替换：

```dotenv
VITE_APP_ENV=production
VITE_API_BASE=https://<已备案正式域名>/api/
VITE_AGREEMENT_VERSION=<法务确认版本号>
VITE_PRIVACY_VERSION=<法务确认版本号>
VITE_LEGAL_REVIEWED=true
VITE_LEGAL_SUBJECT=<协议与隐私责任主体>
VITE_LEGAL_CONTACT=<客服或隐私联系渠道>
```

微信公众平台需配置 request、uploadFile、downloadFile 合法域名并确认 TLS 证书链完整。

业务单据（报价打印稿等 PDF 归档）下载由后端网关 `file/private/download` 以业务域名回源对象存储，客户端不直连 OSS；因此 `downloadFile 合法域名` 只需配置业务域名（如 `decoboon.joytsing.com`），无需额外配置 `*.aliyuncs.com`。图片与附件预览仍使用 OSS 预签名地址，若真机出现同类拦截需单独评估。

## 2. AppID 与主体

- 当前 `manifest.json` 不写未知 AppID，`mp-weixin.appid` 为空，避免误用非正式身份。
- 构建产物在未配置 AppID 时使用微信开发者工具 `touristappid`，只能用于本地预览，不能提审。
- 发布前必须由小程序管理员提供正式 AppID、主体名称、营业执照、服务类目和备案信息。
- AppID、主体、备案、微信后台类目必须与实际服务一致。

已登记备案信息（2026-09-20 由小程序管理员提供）：

- 小程序备案号：`皖ICP备2021009474号-2X`
- 备案查询：[工信部备案系统](https://beian.miit.gov.cn/)
- 待核验：备案主体名称、主体证件与小程序后台主体、营业执照、服务类目一致，且备案号可在工信部系统检索到同一主体。
- 说明：本备案号属于微信小程序本体；`decoboon.joytsing.com` 等 API 域名的 ICP 备案是另一项材料，不能互相替代。

## 3. 用户协议与隐私政策

- 登录页提供可点击的《用户协议》和《隐私政策》页面。
- 协议页面当前统一显示“待法务审核”，只包含发布流程占位，不构成正式法律文本。
- 登录同意记录不再只保存布尔值，至少包含协议版本、隐私版本、同意时间、责任主体、联系方式和 App 版本。
- 同意记录独立于登录会话保存，退出登录不会抹除；协议版本更新后旧记录自动失效并要求重新同意。
- 协议或政策版本变化后，旧版本同意记录不再视为当前有效同意。
- 正式文本必须由法务确认后再替换占位内容，并设置生效日期、更新机制和用户可撤回/注销路径。

## 4. 权限与数据处理

- 当前源代码未调用 `getLocation`、`chooseLocation` 或 `openLocation`。
- 已移除 `requiredPrivateInfos: ["getLocation"]` 和 `scope.userLocation` 声明。
- 后续若重新引入定位，必须先完成业务调用、隐私目的说明、拒绝后的降级路径和微信后台权限声明。
- 当前需在正式隐私政策中核实微信身份、手机号、成员资料、客户项目资料、合同摘要、图片、验收记录和日志的处理目的、范围、保存期限、共享与删除规则。

## 6. 构建验证

```bash
cd /path/to/th4-decoboon-app
npm run verify:mp-weixin

# 检查构建产物不得使用占位域名或游客 AppID 提审
rg -n "api\\.invalid|touristappid|127\\.0\\.0\\.1|getLocation" dist/build/mp-weixin
```

普通 `verify:mp-weixin` 允许使用开发地址和待法务审核占位，只证明工程可编译、可分包，**不等于可提审构建**。

正式发布必须使用独立门禁：

```bash
npm run check:release-env
npm run build:mp-weixin:release
```

`check:release-env` 会逐项检查并在失败时输出：

- `VITE_APP_ENV=production`
- API 为 HTTPS，且不是 `api.invalid`、`.invalid`、`.test`、`.example`、localhost 或私网地址
- `manifest.json` AppID 符合 `wx` + 16 位十六进制，且不是 `touristappid` 或示例值
- 协议版本、隐私版本、责任主体、联系方式和 `VITE_LEGAL_REVIEWED=true`
- 协议、隐私、manifest 和运行配置中不存在“待法务审核”“待补充”“draft”等发布占位

当前安全占位配置预期使 `build:mp-weixin:release` 失败，直到正式 AppID、HTTPS 域名和法务材料全部替换。

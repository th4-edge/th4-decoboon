# 装得清上线前宣传数据复盘框架

> 文档编号：`REQ-20260915-ANALYTICS-FRAMEWORK`
> 责任 lane：data-review
> 上游依据：`docs/marketing/topics/装得清上线前选题规划.md`、`docs/marketing/design/装得清上线前首批视觉方案.md`、`docs/marketing/material/装得清上线前素材盘点.md`、`docs/marketing/material/素材索引.md`
> 文档定位：上线前宣传内容的周/月数据采集、口径、比对、异常判定、归因、质量治理和结论回流框架。
> 当前数据状态：`baseline_pending`
> 当前数据结论：无真实平台数据、无已确认基线、无效果结论；所有真实指标值暂记为 `—`，不得以 0、目标值、联调值或素材数量替代。

## 0. 使用边界与状态机

### 0.1 当前状态

| 状态项 | 当前值 | 含义 |
| --- | --- | --- |
| `data_status` | `baseline_pending` | 尚无真实、完整、可比较的平台数据 |
| `baseline_version` | `pending` | 基线尚未建立或冻结 |
| `metric_version` | `v1_draft` | 本框架首版口径，正式采集前需确认 |
| `tracking_status` | `pending_confirmation` | 当前未见已确认的统一埋点、短链和线索 ID 体系 |
| `content_status` | `draft/internal_draft` | 选题、脚本、封面仍处于内部审核或草案阶段 |
| `publication_status` | `pending_confirmation` | 尚无真实发布链路和平台数据输入 |
| `report_status` | `template_ready_data_pending` | 模板可使用，但不生成效果结论 |

### 0.2 数据状态定义

| 状态 | 使用条件 | 允许输出 |
| --- | --- | --- |
| `baseline_pending` | 无数据、数据不足、口径未冻结或时区未确认 | 只记录缺口和采集动作，不比较、不归因、不排名 |
| `provisional` | 有数据，但仍存在缺失、延迟更新或标签待修正 | 可写“临时事实”，必须标注覆盖率和未锁定原因 |
| `qualified` | 关键维度完整、来源可追溯、口径版本一致 | 可进入周/月比较、异常判定和假设验证 |
| `invalid_quality` | 数据缺失、重复、口径冲突或来源不可追溯 | 隔离数据，不进入结论，不通过平滑或估算补齐 |

### 0.3 三条硬规则

1. 事实、推断、假设和创意必须分开：平台导出值是事实，变化原因默认是待验证假设。
2. 渠道间不直接相加：不同平台对曝光、播放、阅读、完播和咨询的定义不同；只有口径一致且已去重时才可汇总。
3. 缺失不等于 0：无法取得的数据记为 `null` 或 `not_available`，不参与分母、比例和环比计算。

## 2. 核心指标字典

### 2.1 漏斗阶段

```text
曝光
→ 播放/阅读
→ 有效观看或读完
→ 互动
→ 点击
→ 主页访问
→ 私信/咨询
→ 有效留资
→ 演示预约
→ 试用激活
→ 转化
```

并非每个渠道都具备全部阶段。无对应阶段记为 `not_applicable`；渠道存在但没有导出值记为 `not_available`。

### 2.2 通用指标

| 指标代码 | 中文名 | 标准口径 | 计算公式/去重规则 | 主要来源 |
| --- | --- | --- | --- | --- |
| `impressions` | 曝光 | 平台或页面记录的展现次数 | 直接取来源值；不与“触达人数”混用 | 平台后台、官网统计 |
| `unique_reach` | 去重触达 | 去重用户数或触达人数 | 仅在平台明确提供时记录，不能由曝光估算 | 平台后台 |
| `plays` | 播放 | 平台定义的有效播放次数 | `sum(play_events)`；规则写入 `metric_rule_note` | 视频/直播平台 |
| `reads` | 阅读 | 图文页面被打开或阅读次数 | `sum(read_events)`；同一访问重复刷新按平台规则去重 | 公众号、官网 |
| `valid_views` | 有效观看/阅读 | 视频达到门槛或图文达到实际阅读门槛 | 视频用平台完播定义或约定观看时长；图文用读完/阅读完成定义 | 平台后台 |
| `completion_count` | 完播/读完数 | 达到渠道冻结规则的次数 | 不得把视频完播与图文读完直接相加 | 平台后台 |
| `completion_rate` | 完播率/读完率 | 达到内容完成定义的占比 | `completion_count / plays` 或 `/ reads`；分母口径必须一致 | 计算 |
| `interaction_count` | 互动总数 | 点赞、评论、分享、收藏/保存的汇总 | `likes + comments + shares + saves`；保留分项，不视为等权行为 | 平台后台 |
| `likes` | 点赞 | 平台点赞次数 | 同一内容按平台事件口径记录 | 平台后台 |
| `comments` | 评论 | 公开评论条数 | 不含私信；删除或屏蔽是否回算按平台规则记录 | 平台后台 |
| `shares` | 分享/转发 | 分享、转发或推荐次数 | 不同平台动作不可简单等权 | 平台后台 |
| `saves` | 收藏/保存 | 收藏、保存或喜欢次数 | 平台无该能力时记 `not_applicable` | 平台后台 |
| `link_clicks` | 链接点击 | 点击 CTA、短链、官网或演示入口的次数 | `sum(click_events)`；排除后台自测和机器人流量 | 短链、官网、平台后台 |
| `profile_visits` | 主页访问 | 访问账号主页、企业号主页或店铺页的次数/人数 | 按平台定义记录次数或去重人数，并写入 `metric_rule_note` | 平台后台 |
| `inquiries` | 私信/咨询 | 发起的有效对话或咨询会话数 | 私信按会话去重，不按消息条数；留言、表单咨询分别保留子类型 | 平台、私域、CRM |
| `valid_leads` | 有效留资 | 通过资格规则且取得联系意愿的独立线索数 | `count(distinct lead_id)`；必须记录有效判定人和判定时间 | CRM、人工判定 |
| `demo_bookings` | 演示预约 | 已预约演示的独立线索数 | `count(distinct lead_id where demo_booked_at is not null)` | CRM、日程系统 |
| `demo_attendances` | 演示到场 | 实际完成演示的独立线索数 | `count(distinct lead_id where demo_attended_at is not null)` | CRM |
| `trial_activations` | 试用激活 | 符合试用激活定义的企业/账号数 | `count(distinct company_id where trial_activated_at is not null)`；不使用注册数代替 | 产品后台 |
| `conversions` | 转化 | 达成本轮明确转化事件的去重数量 | `count(distinct conversion_id)`；转化事件必须在活动开始前固定 | 订单/CRM/产品后台 |
| `conversion_revenue` | 转化金额 | 已完成转订单的含税或未税金额 | 口径固定为一种；未指定币种和税额时记 `not_available` | 订单系统 |

| 指标 | 短视频 | 图文 | 直播/演示 | 官网/私域 |
| --- | --- | --- | --- | --- |

| 播放/阅读 | 播放次数 | 阅读次数 | 直播观看次数/独立观看人数 | 页面访问次数/独立访客数 |
| 完播/读完 | 完播数、完播率 | 读完数、读完率 | 不适用；改记有效到场和平均观看时长 | 不适用；可记页面滚动完成率 |
| 互动 | 点赞、评论、分享、收藏 | 点赞、在看、评论、转发 | 评论、提问、举手、演示互动 | 页面反馈、社群互动 |

| 主页访问 | 平台主页访问 | 公众号/账号主页访问 | 不适用或记演示页访问 | 官网/私域主页访问 |
| 私信/咨询 | 私信会话 | 后台留言/客服咨询 | 直播私信、演示后咨询 | 表单、企微/微信/客服会话 |
| 有效留资 | 私信转有效线索 | 留言转有效线索 | 演示预约转有效线索 | 表单/咨询转有效线索 |
| 演示预约 | 可追踪时记录 | 可追踪时记录 | 核心指标 | 核心指标 |

| 转化 | 仅在下游可追踪时记录 | 同左 | 仅在下游可追踪时记录 | 订单/CRM 确认后记录 |

### 2.4 渠道口径补充

#### 短视频

- `impressions`：平台定义的推荐曝光或展现次数。
- `plays`：平台定义的有效播放次数；若平台同时提供“曝光后播放”和“自动播放”，必须选择其一并写入规则备注。
- `completion_count`：优先使用平台“完播”口径；平台无完播时，使用冻结的观看完成门槛，且在 `metric_rule_note` 写明门槛。
- `interactions`：点赞、评论、分享、收藏分项采集；互动总数只用于同平台同指标的辅助观察。
- `link_clicks` 与 `profile_visits` 分开：主页访问不等于 CTA 点击，不能互相替代。

#### 图文

- `impressions`：平台分发或展现口径。
- `reads`：文章被打开或阅读的次数；页面刷新是否去重按平台规则记录。
- `completion_count`：仅在平台提供读完或滚动完成数据时使用；否则记 `not_available`，不用平均停留替代。
- `inquiries`：后台留言和客服咨询分类型记录；公开评论不计入私信咨询。
- 官网文章使用站点统计口径，公众号使用公众号后台口径，两者不得直接相加。

#### 直播/演示

- `impressions`：平台曝光、邀约触达或演示活动触达之和必须在 `source_system` 中拆分，不混为单一来源。
- `plays`：直播观看次数；另记 `unique_reach` 为独立观看人数。
- `valid_views`：满足冻结观看时长或有效到场规则的观看；直播不使用“完播率”。
- `inquiries`：直播私信、答疑互动和演示后咨询分别记录，咨询以会话去重。
- `demo_bookings`、`demo_attendances`、`trial_activations` 使用 `lead_id` 或 `company_id` 关联，禁止仅凭渠道汇总值推算。

#### 官网/私域

- `impressions`：页面曝光或入口触达；官网与私域来源必须分列。
- `reads`：官网页面访问量或私域内容打开量；不同系统口径不直接汇总。
- `link_clicks`：CTA 点击，按按钮/入口 ID 记录。
- `inquiries`：表单、企微、微信、社群人工咨询分别记录；机器人自动消息不计入有效咨询。
- `valid_leads`、`demo_bookings`、`trial_activations`、`conversions` 以 `lead_id`、`company_id` 或 `conversion_id` 去重。

### 2.5 核心比率公式

| 指标代码 | 公式 | 分母要求 | 缺失处理 |
| --- | --- | --- | --- |
| `completion_rate` | `completion_count / plays` 或 `/ reads` | 内容类型固定 | 分母为空或 0 时记 `not_calculable` |
| `interaction_rate` | `interaction_count / plays` 或 `/ reads` | 同渠道、同口径 | 保留分项，不跨渠道合并 |
| `click_rate` | `link_clicks / plays` 或 `/ reads` 或 `/ sessions` | 分母与渠道匹配 | 不为缺口补零 |
| `profile_visit_rate` | `profile_visits / link_clicks` | 仅可追踪主页入口时计算 | 无追踪记 `not_calculable` |
| `inquiry_rate` | `inquiries / link_clicks` | 咨询与点击可关联 | 无关联记 `not_calculable` |
| `valid_lead_rate` | `valid_leads / inquiries` | 咨询线索已去重 | 分母不可用时记 `not_calculable` |
| `demo_booking_rate` | `demo_bookings / valid_leads` | 线索 ID 可关联 | 无关联记 `not_calculable` |
| `demo_attendance_rate` | `demo_attendances / demo_bookings` | 预约 ID 可关联 | 无关联记 `not_calculable` |
| `trial_activation_rate` | `trial_activations / demo_attendances` | 仅计算已关联演示 cohort | 不可关联记 `not_calculable` |
| `lead_to_conversion_rate` | `conversions / valid_leads` | 转化事件和线索已关联 | 不可关联记 `not_calculable` |
| `trial_to_conversion_rate` | `conversions / trial_activations` | 同一企业和时间窗可关联 | 不可关联记 `not_calculable` |

## 3. 周报和月报字段、来源、时间与责任人

### 3.1 采集频率和时间

| 数据层 | 统计周期 | 采集/冻结时间 | 责任人角色 | 责任说明 |
| --- | --- | --- | --- | --- |
| 原始日表 | 自然日 | 次日 10:00 前 | 渠道运营或 `owner_pending` | 导出并锁定平台原始文件/截图 |
| 即时清理表 | 自然日 | 次日 12:00 前 | 数据复盘 lane | 校验标识、重复、缺失和异常 |
| 周报 | 周一至周日 | 次周一 14:00 冻结 | 数据复盘 lane | 生成周报，登记数据覆盖率和缺口 |
| 周报复核 | 同一周 | 次周二 12:00 前 | 渠道运营 + 数据复盘 lane | 核对来源和口径，确认是否发布 |
| 月报 | 自然月首日到末日 | 次月第 3 个工作日 14:00 冻结 | 数据复盘 lane | 合并周表并按月维度复核 |
| 月报复核 | 同一月 | 次月第 4 个工作日 12:00 前 | 营销负责人 + 产品负责人 + 数据复盘 lane | 复核回流事项和产品口径 |

所有时间统一使用 `Asia/Shanghai`。周末和节假日顺延到下一个工作日。平台延迟更新时，保留 `last_refresh_at`，不得把早取快照和晚取快照混为同一冻结版本。

### 3.2 原始事实表字段

一行表示“一个内容版本、一个渠道、一天、一个指标值”。

```csv
period_date,period_week,period_month,campaign_id,topic_id,content_version_id,content_type,channel,sub_channel,channel_post_id,audience_segment,publish_time,publish_slot,product_version,cta_id,metric_code,metric_value,metric_unit,denominator_value,metric_rule_note,source_system,source_file,source_record_id,metric_version,collected_at,data_status,coverage_status,owner,evidence_link,notes
```

字段规则：

| 字段 | 规则 |
| --- | --- |
| `metric_value` | 真实数值；不可用时留空并写 `notes`，禁止填 0 代替未知 |
| `denominator_value` | 比率计算使用的原始分母 |
| `metric_rule_note` | 平台对播放、完播、阅读、主页访问或咨询的定义 |
| `source_file` / `source_record_id` | 原始导出文件或记录 ID，支持追溯 |
| `data_status` | `baseline_pending`、`provisional`、`qualified`、`invalid_quality` |
| `coverage_status` | `complete`、`partial`、`missing`、`not_applicable` |

### 3.3 周报模板

**第一部分：范围与质量**

| 字段 | 填写内容 |
| --- | --- |

## 4. 基线期、对比期与异常判定

### 4.1 基线建立

1. 跟踪体系上线并通过一周数据质量检查后，才可选择基线候选期。
2. 周基线候选：上线后的前两个完整自然周；月基线候选：首个完整自然月。
3. 候选期内若存在内容升版、CTA 更换、渠道口径变化、产品能力变化或重大外部事件，基线顺延或拆分版本。
4. 基线的 `baseline_version` 一经冻结，记录冻结时间、数据来源、覆盖范围和变更影响。
5. 当前没有真实数据，因此保持 `baseline_pending`；不得以内部目标、联调结果或行业报告替代基线。

### 4.2 对比规则

| 报告 | 主对比 | 辅助对比 | 禁止方式 |
| --- | --- | --- | --- |
| 周报 | 当前周 vs 上一周 | 当前周 vs 最近 4 个可比周中位数 | 不对未对齐渠道、受众或产品版本做硬比较 |
| 月报 | 当前月 vs 上个月 | 当前月 vs 前 3 个可比月中位数；有数据时再做同比 | 不用单一爆款周替代月趋势 |
| 内容版本 | 新版本 vs 同选题上一版本 | 同渠道、同受众、同档期对照 | 不把不同选题直接视为同一实验 |
| 渠道 | 同内容版本跨渠道对照 | 同渠道不同内容形态对照 | 不直接相加播放、阅读和主页访问 |
| 受众 | 同渠道、同版本分受众对照 | 分角色咨询和留资质量对照 | 不用总量差异替代受众差异 |
| 转化 | 关联 cohort 的漏斗率 | 相同时间窗的试用和转化率 | 不把仅点击或注册当作付费转化 |

### 4.3 异常判定

只对 `qualified` 数据做异常判定；`baseline_pending` 和 `provisional` 只做完整性告警，不判定效果好坏。

| 级别 | 触发条件 | 处理 |
| --- | --- | --- |
| `D0 数据完整性异常` | 主键缺失、日期越界、重复记录、来源文件无法追溯、关键指标覆盖率不足 | 隔离记录，停止比率计算，登记质量问题 |
| `D1 绝对值异常` | 负数、比例超出 0-100%、去重数大于原始事件数、完成数大于播放/阅读数 | 阻断报告，回溯来源 |
| `D2 稳健异常` | 与同内容、同渠道、同受众、同档期的历史可比期相比，稳健 Z 值达到待确认阈值 | 标记 `suspect_peak`，先核验来源和口径 |
| `D3 结构性变化` | 连续两个以上周期同方向变化，且不属于数据完整性异常 | 进入归因假设，不直接下因果结论 |
| `D4 业务阈值异常` | 触发营销负责人确认的业务红线 | 由营销和数据复盘共同确认后，才可升级为经营预警 |

稳健异常建议计算：

```text
robust_z = 0.6745 × (当前值 - 可比期中位数) / 可比期 MAD
```

样本不足、MAD 为 0 或业务量很小时，不套用稳健 Z 值，改用原始事件、人工复核和绝对值门槛。业务阈值必须在上线前由营销负责人补充，本框架不预填数字。

### 4.4 归因层级与证据要求

按以下顺序排查，先排除数据问题，再讨论内容或渠道因素：

| 层级 | 要检查的问题 | 最低证据 |
| --- | --- | --- |
| L0 数据质量 | 是否缺失、重复、延迟、口径变化或来源切换 | 原始导出、采集日志、质量记录 |
| L1 内容 | 选题、标题、封面、前 3 秒、结构、CTA 或版本是否变化 | 内容版本记录、素材版本、发布时间 |
| L2 渠道 | 平台规则、分发机制、推荐量、账号状态或入口是否变化 | 渠道后台记录和平台通知 |
| L3 受众 | 受众角色、地域、兴趣或来源结构是否变化 | 受众标签、细分数据或 CRM 标签 |
| L4 发布时间 | 发布工作日、时段、档期和竞品竞争窗口是否变化 | 发布日志、档期日历 |
| L5 产品版本 | 功能、试用、注册、权益、价格或 CTA 落地页是否变化 | 产品版本和变更记录 |
| L6 外部事件 | 节假日、行业事件、平台政策、舆论或投放变化 | 外部事件日志、时间戳和来源 |

归因结论必须写成“可能因素 + 证据等级 + 验证动作”。单期相关性只能形成假设，不写成因果；跨层级原因未排除前，不得把变化直接归给某一条内容。

## 5. 数据质量规则

### 5.1 缺失

- 关键标识缺失：记录标记 `invalid_quality`，不进入周/月总量。
- 指标缺失：保留空值并写 `not_available`，禁止用 0、均值、上期值或目标值补齐。
- 必填漏斗分母缺失：对应比率记 `not_calculable`。
- 关键指标覆盖率不足、未确认渠道口径或平台数据延迟时，周/月状态保持 `provisional`；不得用有限样本生成排名和效果结论。

### 5.2 重复

- 事实表去重键：`content_version_id + channel + channel_post_id + period_date + metric_code + source_record_id`。
- 同一指标多来源时设来源优先级：平台原始导出 > 官方接口 > 人工复核录入；优先级低的数据只作核对，不重复计数。
- 线索去重使用脱敏 `lead_id`；企业试用和转化使用 `company_id` 或 `conversion_id`。
- 发现重复后保留审计记录，不直接覆盖原记录；在 `notes` 中记录合并来源和去重规则。

### 5.3 口径变化

- 任何渠道定义变化（播放、完播、阅读、主页访问、咨询等）都升级 `metric_version`。
- 新旧口径并存至少一个完整对比期，使用桥接维度；不能桥接时拆分报告并重新建立基线。
- 内容版本、CTA、落地页或产品版本变化时，不沿用旧版本作为同口径基线。
- 口径变更必须记录生效日期、变更人、影响指标和是否重建基线。

### 5.4 异常峰值

- 异常值不删除、不静默平滑；先标记 `suspect_peak` 并保留原始值。
- 检查机器人流量、海外流量、后台自测、平台推荐突变、重复导出和定时任务重跑。
- 核验通过后保留异常标记，并在报告中同时展示原始值和修正说明。
- 核验不通过时列入 `data_exclusions`，不参与比率和归因。

### 5.5 不可归因数据

- 无法关联到 `content_version_id`、`channel`、`cta_id` 或 `lead_id` 的数据进入 `unattributed` 桶。
- 不可归因数据不得按比例分摊到渠道、选题或内容，也不得用于证明某个内容有效。
- 报告必须分别展示已归因数和不可归因数；不可归因占比过高时，结论状态降为 `provisional` 或 `invalid_quality`。
- 官网直接访问、平台自然推荐、线下咨询等无法确定来源的关系，标记来源类型，不强行指定内容。

### 5.6 隐私、授权和审计

- 周/月报只保存脱敏 `lead_id`，不写手机号、微信号、客户姓名、地址或合同明细。
- 截图、录屏、PPT 和平台链接必须与 material lane 的授权、脱敏和版本记录一致。
- 每条事实记录保留 `source_system`、`source_file`、`source_record_id`、`collected_at` 和 `metric_version`。
- 撤回授权或发现素材边界变化时，相关数据标记 `withdrawn`，从对外复盘和后续归因中隔离。

## 6. 复盘结论模板

### 6.1 结论卡

```csv
finding_id,period,scope,fact,comparison_basis,change,confidence,possible_factors,alternative_explanations,verification_action,owner,due_date,decision,topic_action,material_action,content_action,design_action,cta_action,product_action,status
```

### 6.2 标准叙述结构

1. **事实**：写明周期、渠道、内容版本、指标、来源、覆盖率和数据状态。
2. **变化**：写明对比对象、绝对变化、相对变化和是否达到结构性变化；基线未建立时写 `baseline_pending`。
3. **可能因素**：按 L0-L6 层级列出候选因素，区分事实和假设。
4. **验证动作**：给出下一次对照内容、渠道隔离、素材变体、CTA 变体或数据修复动作。
5. **下一轮调整**：分别提出选题、素材、内容结构、视觉、CTA 和产品承接动作。
6. **回流目标和责任人**：指定输出给 topic-selection、material、content-writing、design 或产品团队的文件与截止时间。

### 6.3 单条结论必须回答

| 问题 | 未满足时的处理 |
| --- | --- |
| 这条结论的数据来源是什么？ | 不输出结论 |
| 口径和内容版本是什么？ | 标记 `baseline_pending` 或 `provisional` |
| 对比的是哪个基线或时期？ | 只报告事实，不做变化判断 |
| 是否排除了数据质量和渠道规则变化？ | 进入待核验，不进入效果建议 |
| 是否有替代解释？ | 没有验证动作的因果表述不得进入回流 |
| 对下一轮的动作是什么？ | 不能形成可执行动作的结论不进入决策清单 |

- 涉及产品效果、ROI、利润、返工、续费或安全性时，必须有独立产品/业务证据，不能用宣传指标替代。
- 回流给其他 lane 只形成建议或请求，不直接修改其他 lane 的文件。

- 渠道后台对播放、完播、主页访问和咨询的定义可能变化，未建立口径版本前不能跨期比较。
- 选题、脚本和封面仍为草案，正式发布版本可能改变，内容版本标识必须跟随变更。
- 线索和转换数据涉及个人信息、授权和隐私，未完成合规确认前不得进入周/月报明细。

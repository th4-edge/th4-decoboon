## 真实装企场景

### 场景一：项目经理每天重复回答进度

- 使用人：项目经理、业主、企业负责人。
- 触发事件：业主在微信里问“今天做到哪一步了”。
- 当前动作：项目经理停止手头工作，翻聊天记录、找照片、再解释一遍。
- 系统下一步：业主打开本人项目的业主端，查看当前阶段、任务、现场记录和下一步。
- 装企结果：项目经理少接一类重复询问，团队把时间留给现场处理和下一步任务。
- 异常处理：现场记录尚未同步时，只展示已经确认的进度事实，不用假照片或空模板填满。

### 场景二：阶段验收后责任说不清

- 使用人：项目经理、业主、企业负责人。
- 触发事件：阶段施工完成，业主提出整改意见。
- 当前动作：口头沟通、群内发图，整改后再靠聊天记录确认。
- 系统下一步：业主本人确认或驳回阶段验收，整改复验连续留痕；员工不得代业主确认。
- 装企结果：验收与整改有轮次、有依据，减少“上次不是这样”的口头争议。
- 异常处理：成本或费用不完整时，经营利润显示“暂不可确认”，不按 0 计算。

### 可引用事实锚点

- 客户、房屋、报价、合同、项目、履约与验收对象关系：`EV-003`、`BR-001`、`BR-002`。
- 业主查看、阶段任务、现场留证与验收整改：`SCN-003`、`SOL-006`、`DEC-015`、`BR-008`、`EV-037`、`EV-038`。

- 企业名称、Logo、服务岗位可见：`USER-DECISION-20261014-002`、`EV-323`、`BR-007`；该决策尚未升级为正式 DEC 卡，对外表述保留为原则。

### 必须保留的表达边界

- 业主端不是“全透明”：只开放本人被授权的项目事实。
- 业主端不是“所有环节审批”：阶段验收由业主本人确认或驳回，不是所有业务都由业主审批。
- 业主端不是装得清直接服务业主：装企是服务主体，装得清负责记录、协同与事实保管。
- 不承诺一定减少电话、提升利润、提高转介绍或产生确定收益。
- “24 小时客服”是老板语境的比喻，不是量化承诺；营销审计已将其标记为人工确认项，本样稿保留为修辞表达。
- 手机界面为产品界面示意，标记“界面示意”，不含真实客户名称、手机号、项目地址或金额。
- 页内未使用客户案例、收益比例、行业排名或演示数据冒充真实成效。

- 本版原则：不讲“数字化、信息化、AI、闭环、赋能、业务对象、权限矩阵”等专业词，先说老板每天遇到的麻烦

## 一页纸怎么讲

### 1. 先让老板认出现场

页面开场不介绍产品，而是直接写出老板熟悉的日常：

- 客户问：“我家今天做到哪了？”
- 项目经理说：“我找一下群里的照片。”
- 老板问：“这单到底还差什么？什么时候能收钱？”
- 财务问：“这个变更客户确认了吗？合同要不要改？”

主标题：**客户天天问，员工天天翻群，老板天天救火。**

### 2. 再讲装得清帮谁省事

- 客户少问：打开手机，看自己家。
- 员工少翻：事情跟着项目走。
- 老板少救火：哪里卡住，一眼看到。

### 3. 用“以前怎么做 / 现在少做哪一步”对比

不要求老板理解功能名称，直接用六件熟悉的事：

1. 客户问进度。
2. 报价改了又改。
3. 客户改方案。
4. 验收后整改。
5. 月底对账。
6. 这单赚不赚钱。

其中利润表达统一为：**成本没录全就显示“暂不可确认”，不拿 0 糊弄你。**

### 4. 降低开始使用的心理门槛

- 先拿一个项目试，不用全公司培训。
- 客户只看到自己家，成本、供应商价、员工资料不会给他看。
- 员工走了，项目记录还在。

## 真实装企场景

### 场景一：客户每天问进度

- 使用人：项目经理、客户、老板。
- 触发事件：客户在微信里问“今天做到哪一步了”。
- 以前：项目经理翻群、找照片、重新解释。
- 现在：客户打开自己的项目，看当前阶段、下一步和记录。
- 异常：现场记录还没同步时，只显示已经确认的进度，不用假照片填满。

### 场景二：报价改了很多版

- 使用人：设计师、老板、客户。
- 触发事件：客户连续改方案，报价文件出现“最终版”“最终版2”。
- 以前：签约时无法确认到底用了哪一版。
- 现在：每次报价都有记录，签的是哪一版能查到。
- 边界：不是承诺报价一定不出错，而是让版本和依据能追查。

### 场景三：验收后整改说不清

- 使用人：项目经理、客户、老板。
- 触发事件：阶段验收发现问题，需要整改和复验。
- 以前：口头说、群里发图，过几天找不到原话。
- 现在：客户本人确认或驳回，整改前后都有记录。
- 边界：业主只确认质量事实，不是所有业务环节都由业主审批。

## 事实与边界

### 可引用事实锚点

- 客户、房屋、报价、合同、项目、履约与验收对象关系：`EV-003`、`BR-001`、`BR-002`。
- 客户查看、阶段任务、现场留证与验收整改：`SCN-003`、`SOL-006`、`DEC-015`、`BR-008`、`EV-037`、`EV-038`。
- 材料到货、实际成本与应付归集：`SOL-002`、`EV-010`、`EV-017`。
- 财务边界“管项目和钱，不管税和账”：`DEC-016`。
- 成本不完整时利润不可确认：`EV-008`。
- 客户只看本人被授权项目；内部成本、供应商价格、员工数据和其它项目不开放：`SOL-006`、`SOL-002`、`EV-005`。

### 必须保留的表达边界

- 不把装得清说成“会计做账软件”；统一口径是管项目和钱，不管税和账。
- 不承诺一定减少电话、提升利润、提高转介绍或产生确定收益。
- 不把“客户可以看到”写成“客户审批所有环节”。
- 不把“记录完整”写成“绝对不会出错”。
- 不承诺全部替换 ERP，也不假设所有装企都适合。
- 页面没有使用客户名称、真实项目地址、真实手机号、客户案例或效果数字。
- 本版不把 AI 当卖点；在没有完成清晰、可验证的老板价值翻译前，不向低认知客户堆 AI 概念。

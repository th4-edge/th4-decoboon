## 2. 目标与范围

- 目标：关闭套餐整体闭环验收中发现的配置、生命周期、报价分组、权限和内部编号缺陷。
- 范围内：App 套餐管理/配置/选择/报价来源；后端套餐摘要、项目行幂等与报价区域投影。
- 非范围：套餐价格公式调整、合同金额、支付、权限放宽、生产数据迁移执行。
- 受影响端：App、后端。

## 3. 业务场景

1. 企业负责人创建 100㎡ 套餐，配置区域和项目行，发布 V1 并生成客户报价；后续创建 V2 时 V1 报价保持历史事实。
2. 店长维护套餐，设计师/财务/项目经理只读；非维护角色深链不得进入编辑页。
3. 套餐报价按区域快照展示，客户和员工通过客户、房屋、套餐、版本和金额识别报价，不展示内部编号。

## 4. 验收条件

| 序号 | 场景 | 预期结果 |
| --- | --- | --- |
| 1 | 套餐列表 | 已发布套餐显示真实状态、分区数和项目数；草稿/发布/历史版本动作正确 |
| 2 | 创建下一版与发布 | 已发布 V1 可创建草稿 V2，V2 发布后成为当前版本，V1 只读保留 |
| 3 | 多次选品 | 一次可添加多个不同项目；重复确认和同一分区重复项目被幂等拦截 |
| 4 | 套餐报价 | 选择客户后已选套餐保持；报价金额、税金、成本和成本完整性一致 |
| 5 | 区域投影 | 报价详情按冻结的套餐区域名称分组，并保留行级区域快照 |
| 6 | 权限 | Boss/StoreManager 可维护；其他角色按钮隐藏且深链被页面守卫阻断，服务端仍为403 |
| 7 | 内部编号 | App 不展示套餐编码、报价编号等系统内部编号 |

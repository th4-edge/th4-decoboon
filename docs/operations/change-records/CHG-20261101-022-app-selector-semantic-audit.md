## 2. 目标与范围

- 目标：对 App 全部页面做业务对象选择器语义审计，清理脚本此前未覆盖的 ActionSheet、自建员工面板、普通下拉和人员全量数组。
- 范围内：
  - 新增 `audit:selectors` 全量语义审计并纳入 App 发布校验链。
  - 量房房屋改用 `property-picker`，多套房不自动默认第一套。
  - 写汇报项目改用 `report-project-picker`，移除 ActionSheet。
  - 客户负责人/设计师、项目岗位、项目选择器设计师筛选统一接入 `employee-picker`。
  - 内容任务模板改用 `template-picker` + `content/template/page`。
  - 费用编辑分类改用 `expense-category-picker` + `expense/categories/page`。
  - 移除承办接管页用于回显的员工全量数组。
- 非范围：不修改客户、项目、合同、内容任务、费用、权限、金额或状态机业务规则；不提交真实变更。
- 受影响端：后端、App。

## 3. 业务与决策

- 是否涉及业务对象、状态、权限、金额、成本、利润、支付或数据范围：涉及项目/员工/房屋/模板/费用分类读取和回显；不改变公式与角色矩阵。
- 业务事实来源与裁决编号：`DEC-021` / `BR-019`、`BR-059` / `OBJ-010`、`DEC-095` / `BR-060`。
- 尚存 GAP 或假设置：当前租户内容模板和费用分类为 0，21/205 有数据状态使用 H5 路由夹具；未做微信真机、有数据保存和所有对象 10× 后端专项。

## 2. 目标与范围

- 目标：恢复 App 与 Web 全角色工作台的统一个人身份卡；修复首页最新动态与全部动态使用不同数据源/空状态的问题。
- 范围内：App 员工首页、Web 通用工作台首页、首页动态加载状态。
- 非范围：不改变角色权限、数据范围、动态业务定义、金额口径、Provider 路由和生产数据。
- 受影响端：App、Web。

## 3. 业务与决策

- 是否涉及业务对象、状态、权限、金额、成本、利润、支付或数据范围：涉及员工身份展示与动态读权限，不改变权限规则。
- 业务事实来源：当前登录员工；`project/report/page` 按服务端角色数据范围返回工地动态。
- 已定位根因：App 首页 Finance、Marketer 分支主动把 `reports` 清空；其他部分角色加载动态，导致同类“最新动态”在不同角色下不一致。点击“全部”进入动态页会直接调用同一 Provider，因此有数据。BOSS 的 `eventLimit=6/100` 直连接口均返回 6 条，限制参数不是根因。
- 角色覆盖：App 单首页身份卡适用于全部员工角色；Web 统一组件已接入通用工作台（BOSS/店长/业务员）以及设计师、项目经理、财务专属工作台。
- 修复原则：首页“最新动态”与全部动态必须读取同一服务端事实源，并区分加载、失败和真实空数据。

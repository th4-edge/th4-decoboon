## 2. 目标与范围

- 目标：修复财务增长列表中的上下文丢失、固定大页截断和截断列表冒充完整数据问题，保证用户能够从项目上下文进入完整资金流水，并能访问超过单页上限的薪酬、考勤和提成调整数据。
- 范围内：
  - 项目核算“资金台账”页签标明最近 12 条语义，并跳转到保留 `projectId` 的完整资金台账。
  - 独立资金台账读取 `projectId`，项目入口默认不限定当前月。
  - 提成负向调整改为服务端分页。
  - 员工工资项改为服务端分页，并保留服务端确认门禁。
  - 月度考勤改为服务端分页，显示真实总数。
  - 应收/应付选择器的状态筛选改为服务端筛选；已选对象按 ID 精确回显。
  - 财务工作台前 8/前 5 条列表不再将截断列表长度解释为总笔数。
  - 收付凭证切换门店时页码复位。
- 非范围：
  - 不修改金额、成本、利润、权限、状态机或数据范围规则。
  - 不修改主材作业单、主材结算、凭证模板版本和项目应收应付整包加载的共享 Provider 契约；另立专项，避免与现行材料热修及 App 契约冲突。
  - 不执行生产数据修改或数据库迁移。
- 受影响端：后端、Web

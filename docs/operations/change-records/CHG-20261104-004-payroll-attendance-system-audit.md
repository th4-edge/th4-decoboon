## 2. 当前目标

确认考勤业务体系在 Web、App、后端和工资单衔接中是否仍存在同类串值、状态、权限、审计和数据完整性问题，并用真实用户操作路径复现。

## 3. 非目标

- 不修改业务代码；
- 不写入生产考勤、工资单、应付或付款数据；
- 不执行历史数据回填；
- 不发布后端/Web/App；
- 不替代独立验收、业务验收或客户签字。

## 4. 已确认结果

### P0

- `ATT-01`：考勤更新接口对门店财务未执行 DataScope，门店财务可修改同企业其他门店考勤。

### P1

- `ATT-02`：Web/App 抽屉或表单内切换月份/员工时不清空考勤天数字段，已在线复现；
- `ATT-03`：状态机可被更新接口直接跳过，任意合法枚举可写入；
- `ATT-04`：已确认考勤可修改数据且不重新确认，确认人和确认时间保持旧值；
- `ATT-05`：考勤新增、修改、删除没有业务审计留痕；
- `ATT-06`：后端不校验考勤天数范围及合计关系；生产 8 月 5 人存在 27 正常 + 15 事假 > 27 应出勤；
- `ATT-07`：工资单草稿重算不清理退出方案范围的旧工资项；
- `ATT-08`：当前生产仍存在工资项已生成、考勤缺失或 Pending 的状态不一致。

### P2

- `ATT-09`：非法月份未转为业务错误；
- `ATT-10`：考勤分页在内存中全量加载；
- `ATT-11`：考勤确认缺少二次确认和恢复引导；
- `ATT-12`：快速切月/刷新存在响应乱序覆盖风险。

## 5. 验证证据

- 线上 Web 真实操作：切月保留 5/2、切员工保留 5/2；关闭重开归零；
- 生产只读数据：14 条考勤、5 名员工、7 条 InPayroll、7 条 Pending；
- 本地定向测试：8 个测试类 26 用例 0 失败；
- 缺陷现状探针：6/6 复现当前缺陷；
- Web/App type-check 和现有静态门禁通过。

完整证据见审计报告及 `raw/`、`evidence/` 目录。

## 6. 停止条件

本轮在完成 Web 真实交互复现、后端定向探针、生产只读数据核对和报告落盘后停止。未进入代码修复，避免在用户确认优先级和是否处理已发放历史数据前扩大范围。

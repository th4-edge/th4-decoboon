## 2. 目标与范围

- 目标：修复财务跨端汇总伪 0、手工应收应付类型越界和自动台账来源重复/缺失防护。
- 范围内：
  - App 应收、收款、付款汇总改用同源部门报告，失败显示暂不可确认；
  - Web/App 财务首页失败态不再以 0 伪造事实；
  - Web/App 手工应收仅允许“其他应收”，手工应付仅允许“其他应付/费用支出”；
  - 后端 Save Provider 增加同等类型门禁和负向测试；
  - 自动台账按 `com_id + source + source_id` 防重复；历史数据修复另立受控数据变更。
- 非范围：
  - 不直接修改生产/测试库历史双记或缺记数据；
  - 不改变应收应付金额公式、成本利润口径、权限范围和状态机；
  - 不发布、不提审小程序。

## 3. 业务与决策

- 业务事实来源：`BR-055`、`MET-005`、`MET-006`、`MET-002`。
- 不新增角色、状态或同义 Provider。
- App/Web 必须消费同一服务端事实；失败不得显示 0。

## 10. 复盘与沉淀

- 是否出现重复问题：是；跨端相同页面使用不同汇总 Provider，且失败态默认 0。
- 是否需要新增门禁：是；跨端汇总同源、失败态禁止伪 0、手工类型白名单、台账来源唯一性。
- 候选 `EXP`：同角色同名页面必须消费同一部门报告；未知值必须是未知，不能落为 0。
- 候选 `ANT`：用错误态默认值 0 掩盖 Provider 失败。
- 候选 `PATH`：先对齐同源 Provider，再收敛操作白名单，最后做历史数据修复。
- 后续动作与负责人：历史账务修复备份与确认、独立验收、发布门禁。负责人：codex + 用户。

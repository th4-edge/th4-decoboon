## 顺带发现的代码缺陷（建议登记）

`UserIdentityContext.identify()` 的手机号占用判断：

```java
Credentials byPhone = credentialsRepository.findFirstByPhoneOrderByCreIdDesc(normalizedPhone);  // 不按状态过滤
if (byPhone != null) {
    if (byPhone.getStatus() != UserStatus.Active)
        throw new DefinedException(new DefaultErrorCode("403", "当前用户已停用"));
    if (byPhone.getType() == CredType.Wx)
        throw new DefinedException(new DefaultErrorCode("400", "该手机号已绑定其他微信，请联系客服"));
}
```

**问题**：把账号置为 `Disabled` / `Deleted` 后，该手机号**永久无法重新注册**——用户会看到"当前用户已停用"，且没有任何自助恢复路径，只能靠运维改库（即本次操作）。本次生产变更正是因为踩了这个坑。

**建议**：手机号查询改为排除 `Deleted` 状态（`Deleted` 视为已释放），或为 `Deleted` 提供明确的"用该手机号重新注册"分支。**这是产品缺陷，不是数据问题。**

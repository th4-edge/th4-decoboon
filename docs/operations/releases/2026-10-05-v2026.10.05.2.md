## 2. 事故与根因

- 用户现象：线上将「谢玲玲首单奖励」更正后选择项目，App 提示保存失败。
- 台账：`232429385611739136`
- 项目：`232407203057762304`
- 数据库事实：`project_id` 已成功更新为项目 ID，且已写入一条 `MetadataCorrection` 修订记录，说明保存事务本身成功。
- HTTP 事实：`POST /api/finance/ledger/update` 返回 HTTP 200，但 `nginx` 响应体为 69,471 B，明显异常膨胀。
- 稳定复现：本地回归得到 `JsonMappingException: Document nesting depth (1001) exceeds the maximum allowed (1000)`。
- 根因：手工更正和冲正重记 Provider 只声明了 `Ledger` 白名单，缺少 `Project/LedgerCategory/Customer/Employee` 嵌套投影；响应序列化 `LedgerCategory.parent -> children -> parent` 无限递归。事务已提交，响应序列化失败，形成「数据已保存、App 提示失败」。
- 影响范围：仅影响 `finance/ledger/update`、`finance/ledger/correct` 在响应对象包含结构化分类节点时的响应序列化，不改变金额、分类、权限和数据库数据。

## 3. 修复内容

- 修复结果：分类节点不再返回 `parent/children` 递归关系；项目对象不再携带 `company/quote` 等无关整图。

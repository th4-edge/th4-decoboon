# 复杂业务域交付编排规范

> 适用范围：材料、合同变更、财务、项目、客户、设计、验收等需要多轮推进的业务域。  
> 目标：多轮推进，每轮从外部状态恢复，目标不丢、口径不漂、交付物可对账。  
> 执行入口：`.agents/skills/domain-delivery-orchestrator/SKILL.md`

## 1. 核心原则

1. 聊天不是记忆，文件才是记忆。
2. 一次只做一个垂直切片批次。
3. 没有业务裁决，不进入编码。
4. 没有真实页面/真机证据，不算 UI 通过。
5. 开发自测不等于独立验收。
6. 设计、蓝图、需求、代码、页面、测试、验收必须能逐项对账。
7. 小程序正式版提审和发布由用户本人完成。

## 2. 领域包

每个业务域建立一个目录：

```text
docs/product/domains/<domain>/
├── run-envelope.md
├── 00-charter.md
├── 01-scenarios.md

├── 04-requirements.md
├── 05-plan.md
├── 06-implementation.md
├── 07-ui-review.md
├── 08-acceptance.md
├── 09-release.md
├── 10-reconciliation.md
└── state.json
```

模板在 `docs/product/domains/_template/`。

## 3. 初始化与恢复

初始化：

```bash
python3 .agents/skills/domain-delivery-orchestrator/scripts/domain_state.py init \
  --domain material \
  --title "材料履约" \
  --north-star "材料计划、选材、作业单、采购、到场与结算形成可追溯闭环" \
  --owner codex
```

恢复：

```bash
python3 .agents/skills/domain-delivery-orchestrator/scripts/domain_state.py show --domain material
```

门禁前校验：

```bash
python3 .agents/skills/domain-delivery-orchestrator/scripts/domain_state.py validate --domain material --strict
```

更新阶段并留痕：

```bash
python3 .agents/skills/domain-delivery-orchestrator/scripts/domain_state.py set-phase \
  --domain material --phase BIZ_ALIGNED --batch B1 \
  --next-action "完成业务裁决" --note "T12 已收到"
```

## 4. 状态机与门禁

```text
INTAKE
→ SCENARIOS_READY
→ BIZ_ALIGNED
→ BLUEPRINT_READY
→ PLAN_READY
→ DEV_IN_PROGRESS
→ DEV_VERIFIED
→ UI_REVIEWED
→ RECONCILED
→ ACCEPTED
→ RELEASED
→ LEARNED
```

| 阶段 | 门禁 |
| --- | --- |
| INTAKE | 目标、范围、非目标、角色明确 |
| SCENARIOS_READY | 至少 2 个真实场景，含异常和系统下一步 |
| BIZ_ALIGNED | T06/T12 已形成，P0 GAP 已关闭；不得编码 |
| BLUEPRINT_READY | 对象/状态/字段/UI 绑定有业务引用或标记 gap |
| PLAN_READY | 每批为垂直切片，有退出条件、回滚和下一门禁 |
| DEV_VERIFIED | 定向测试、编译/构建、必要部署证据 |
| UI_REVIEWED | 真实页面/真机截图和交互审查 |
| RECONCILED | 本批无 UNMAPPED/STALE；设计与实现一致 |
| ACCEPTED | 独立正向/反向/越权/幂等/边界/跨端证据 |
| RELEASED | 版本、环境、回滚、冒烟、体验版/正式版边界 |
| LEARNED | 经验和反模式回写；不改业务事实 |

## 5. 和业务智能体同步

```text
T05 研发咨询
→ T06 业务答复
→ T12 业务裁决与研发交接
→ 实现与验证
→ T13 修复/学习/表达回执
```

- 业务事实只来自 `zhuangdeqing-business` 规范目录。
- 蓝图节点引用 `OBJ/SCN/BR/DEC/MET/EV`。
- 没有业务引用的内容标记 `gap`，不得作为正式口径。
- 业务知识变化后，相关蓝图和对账行标记 `stale`。
- 运行时智能体不得把 `gap/stale/draft` 当作正式规则。

## 6. 长期监督与 Run Envelope

离开电脑前先确认 `run-envelope.md`，它定义：

- 批次队列；
- 可自主决定的实现细节；
- 人工门禁；
- 质量门禁；
- 修复轮次和止损条件；
- Return Packet。

监督任务按以下循环运行：

```text
读取 run-envelope + state + reconciliation
→ 判断当前批次是否完成
→ 生成下一轮提示词
→ 执行一个批次
→ 自测 + UI 证据 + 独立验证
→ 更新 state / reconciliation
→ 无硬门禁则继续下一批
→ 命中硬门禁则停止该分支并写决策包
```

监督任务不得每批等待用户输入；只有人工门禁、预算耗尽或验收收口时才停。

查看下一轮提示词：

```bash
python3 .agents/skills/domain-delivery-orchestrator/scripts/domain_state.py next-prompt --domain material
```

## 7. 批次提示词

启动一个领域、继续一个批次、恢复上下文、业务同步和 UI 审查的模板见：

```text
.agents/skills/domain-delivery-orchestrator/references/prompts.md
```

最短使用方式：

- 新领域：说“启动 `<domain>`，先做 charter、场景和业务问题，停在 BIZ_ALIGNED 前”。
- 继续：说“继续 `<domain>` 的 `<batch>`，按 state.json 恢复，只推进这一批”。
- 恢复：说“从 `<domain>` 的 state.json 恢复，只报告不执行”。
- 审查：说“对 `<batch>` 做门禁审查，给 PASS/FAIL/BLOCKED”。

## 8. 对账

`10-reconciliation.md` 是本批交付的硬证据。每一行至少包含：

```text
REQ | 场景 | 业务规则 | 蓝图节点 | 字段/API | 页面 | 测试 | 验收 | 状态
```

有 `UNMAPPED`、`STALE`、`GAP` 或 `BLOCKED` 的行，不得宣布本批完成。

## 9. 人工保留权限

- 业务口径冲突的裁决；
- 高风险金额/成本/权限/删除/支付动作；
- 正式小程序提审和发布；
- 方向性取舍和商业决策。

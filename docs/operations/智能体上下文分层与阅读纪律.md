# 智能体上下文分层与阅读纪律

> 状态：生效
> 适用：`th4-decoboon` 后端仓库及与其直接关联的装得清研发任务
> 目标：降低每次编码的无关上下文，保留业务安全边界和可追溯事实

> 新任务的实际入口：`docs/operations/AI工作索引.md`。

## 1. 为什么分层

根 `AGENTS.md` 曾在 2026-09-24 精简到约 6,594 字符，之后因跨端、产品、验收、发布和后端规则持续追加，增长到约 15,014 字符。问题不是规则本身错误，而是所有任务都重复承担所有领域的说明，导致：

- 当前任务目标被大量历史和多端规则稀释；
- 子目录规范和业务事实源之间出现重复；
- Agent 更容易抓错重点或跳过真正相关的证据；
- 每次任务为了“保险”全文读取，Token 和响应时间不可控。

因此采用“根级硬边界 + 最近目录规范 + 事实源按需读取”。

## 2. 指令分层

| 层级 | 文件 | 职责 | 不应包含 |
| --- | --- | --- | --- |
| 项目入口 | 根 `AGENTS.md` | 跨任务优先级、硬边界、任务路由 | 完整 Provider 示例、长业务清单 |
| 实现层 | `src/main/AGENTS.md` | 后端架构、权限、实体、查询、序列化、成本 | 产品 PRD、Web/App 视觉细则 |
| 测试层 | `src/test/AGENTS.md` | 权限、契约、懒加载、分页、验证证据 | 完整编码规范 |
| 产品层 | `docs/product/AGENTS.md` | 业务裁决、场景、信息项、闭环和状态投影 | Provider 实现细节 |
| 设计层 | `docs/design/AGENTS.md` | 跨端、接口、分页、选择器和响应契约 | 业务事实裁决 |
| 事实源 | `rules.md`、业务知识库、领域 state、冻结用例 | 唯一详细事实和规则 | 重复摘要 |
| 任务状态 | `CHG-*`、`_系统/任务/当前工作.md`、领域 state | 当前范围、证据和下一步 | 长期规则、历史流水 |
| 聊天 | 当前会话 | 临时协作 | 不可替代上述事实源 |

子目录 `AGENTS.md` 与根文件同时生效，只补充当前目录特有规则。最近目录规范不得推翻根级高风险底线。

## 3. 按任务加载

### 3.1 所有任务

1. 读取根 `AGENTS.md`。
2. 读取当前路径最近的 `AGENTS.md`。
3. 用 `rg -n` 定位任务直接相关源码、文档和最近一次 `CHG-*`。
4. 不预读完整 `rules.md`、完整 worklog、历史验收或无关端源码。

### 3.2 风险路由

| 变更 | 额外读取 |
| --- | --- |
| L0 文档/文案 | 相关文档、目标页面/构建命令；不跑无关全量 |
| L1 单点修复 | 受影响 Provider/页面、对应测试类、最近发布记录 |
| L2 跨模块/跨端 | 相关设计规范、双方调用面、契约测试和跨端对账 |
| L3 权限/金额/迁移/支付/删除 | 研发章程、专项规范、备份/回滚、全量测试和用户确认 |

### 3.3 业务任务

- 先查业务事实，再读代码；不得用当前行为补业务定义。
- 没有 `T06/T12` 时，只做调研、问题登记和影响分析。
- 已有结构化 `CHG-*`、领域 state 或问题档案时，不重复全仓扫描。

### 3.4 固定读取纪律（强制）

1. 问题台账按 ID/状态查询，禁止全文读取 `registry.json`。
2. 领域包只读 `state.json`、`00-charter.md`、`10-reconciliation.md`；再按当前切片补单个业务卡或实现文件。
3. `rules.md` 只读相关章节，不全文加载。
4. Skill references 只读当前模式需要的一份。
5. 验收只读 RUN 摘要、当前用例、缺陷和关键证据。
6. 构建/监控只读失败行、结论和新增指纹。
7. 一个任务只允许一个主 Skill；业务智能体只作为事实源，不作为并行执行 Skill。

## 4. 阅读预算

| 预算项 | L0 | L1 | L2/L3 |
| --- | ---: | ---: | ---: |
| 关键文件 | ≤3 | ≤8 | 按影响面，先列清单再读 |
| 定向测试 | 不跑 | 1 次 | 相关回归，必要时全量 |
| 构建/类型检查 | 受影响端 | 1 次 | 受影响端及相关产物 |
| 同一问题推测 | 0–1 轮 | 1 轮 | 1 轮，之后进入证据分析 |

工具输出只保留：

- 失败断言、首个根因和复现命令；
- 关键 diff、接口字段和页面证据；
- 测试/构建结论与未执行项。

## 5. 新增规则的放置

新增规则前先回答“谁在什么时候需要它”：

1. 所有任务都必须遵守，且违反会造成跨域风险：放根 `AGENTS.md`，只写一句话和事实源链接。
2. 只在后端实现时相关：放 `src/main/AGENTS.md`。
3. 只在测试时相关：放 `src/test/AGENTS.md`。
4. 只在产品/业务文档时相关：放 `docs/product/AGENTS.md`。
5. 只在跨端契约设计时相关：放 `docs/design/AGENTS.md`。
6. 某技能专属流程：放对应 `SKILL.md`，不在 AGENTS 重复。
7. 具体代码示例、完整矩阵和历史细节：放 `rules.md` 或专项规范。

禁止把同一规则全文复制到多个层级；需要多处可见时只放一个 canonical 位置，其他位置给链接。

## 6. 体积阈值与复盘

建议软阈值（不作为发布硬门禁）：

- 根 `AGENTS.md`：≤8,000 字符；
- `src/main/AGENTS.md`：≤9,000 字符；
- `src/test/AGENTS.md`：≤5,000 字符；
- `docs/product/AGENTS.md`、`docs/design/AGENTS.md`：各 ≤5,000 字符。

超过阈值时先判断是否混入了示例、历史、完整矩阵或事实源副本，再执行分层，不直接扩大模型上下文。

## 7. 校验

文档变更后至少执行：

```bash
wc -m AGENTS.md src/main/AGENTS.md src/test/AGENTS.md docs/product/AGENTS.md docs/design/AGENTS.md
git diff --check
```

并确认：

- 根文件中每一个路由入口存在；
- 高风险边界没有因精简而消失；
- 详细规则只有一个 canonical 事实源；
- `CHG-*` 和 `_系统/任务/当前工作.md` 已更新；长期规则保留在工作约定，历史进入归档。

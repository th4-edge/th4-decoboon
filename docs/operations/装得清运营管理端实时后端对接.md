# 装得清运营管理端实时后端对接

> 目标：`th4-decoboon-admin` 运行后只展示 `th4-decoboon` 的真实数据库数据，不加载 mock，不回退演示数据。

## 1. 本地运行

### 1.1 启动后端

在 `后端代码/th4-decoboon`：

```bash
./run-dev.sh
```

确认：

```bash
curl -sS http://127.0.0.1:8090/api/auth/session/password-login \
  -H 'Content-Type: application/json' \
  -d '{"phone":"<平台运营手机号>","password":"<密码>"}'
```

返回 Provider envelope 并包含 token。

### 1.2 启动管理端

在 `前端代码/th4-decoboon-admin`：

```bash
npm install
npm run verify:real-api
npm run dev
```

开发环境 `.env.development`：

```env
VITE_API_BASE=/api/
VITE_ENVIRONMENT_LABEL=本地实时后端
VITE_REFRESH_INTERVAL_MS=30000
```

Vite 将 `/api/` 代理到 `http://127.0.0.1:8090`。

## 2. 生产对接

推荐管理端使用独立子域名，例如 `admin.example.com`，Nginx 配置：

```nginx
server {
    listen 443 ssl http2;
    server_name admin.example.com;

    root /opt/decoboon/admin/current;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8090/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

前端生产配置：

```env
VITE_API_BASE=/api/
VITE_ENVIRONMENT_LABEL=生产实时后端
VITE_REFRESH_INTERVAL_MS=30000
```

构建：

```bash
npm ci
npm run build
```

将 `dist/` 发布到 Nginx 根目录。

## 3. 实时数据规则

| 模块 | 数据来源 | 刷新方式 |
|---|---|---|
| 运营总览 | `platform/dashboard/info` | 首次加载 + 默认 30 秒轮询 |
| 客户企业 | `platform/tenant/page` | 查询、筛选、刷新按钮 |
| 订阅与续费 | 企业分页 + 套餐列表 + 更新 Provider | 操作后立即重新读取 |
| 套餐策略 | `platform/plan/list` | 页面加载 |
| 系统运维 | `platform/system/status` | 首次加载 + 默认 60 秒轮询 |
| 操作审计 | `platform/operation/page` | 查询、筛选、刷新按钮 |

`VITE_REFRESH_INTERVAL_MS=0` 可以关闭前端轮询，但不会产生任何演示数据。

## 4. 真实数据门禁

```bash
npm run verify:real-api
```

门禁检查：

- 是否存在 `VITE_DEMO_MODE`。
- 是否存在 mock、演示账号或演示 token。
- 是否声明全部 7 条平台 Provider 路由。
- 开发、生产、示例环境是否均配置真实 API 地址。

## 5. 后端契约校验

```bash
cd 后端代码/th4-decoboon
mvn -o -q -Dtest=ProviderSecurityAcceptanceTest,PlatformAdminAcceptanceTest test
```

通过标准：

- 平台路由全部需要登录。
- 普通企业 Boss 返回 403。
- 匿名请求返回 401。
- 平台 Boss 可以查询企业、调整订阅并生成审计。
- 系统状态接口返回真实 MySQL、Redis、JVM 和主机快照。

## 6. 故障排查

### 登录一直失败

- 确认后端运行在 `8090`。
- 确认 Nginx 的 `/api/` 已反代。
- 确认手机号已设置 BCrypt 密码凭证。
- 确认账号所属企业 `platform=true` 且角色为 Boss。

### 页面显示网络异常

- 检查 `VITE_API_BASE`。
- 检查浏览器 Network 中 `/api/platform/...` 的 HTTP 状态。
- 如果使用独立 API 域名，必须配置 CORS 和 HTTPS。

### 订阅调整失败

- 检查是否填写操作原因。
- 检查目标套餐是否上架。
- 检查恢复 Active 时服务期是否未过。
- 检查当前账号是否属于平台运营企业 Boss。

## 7. 安全要求

- 不在前端代码、构建产物或日志中放置密码。
- 初始化完成后关闭 `PLATFORM_BOOTSTRAP_ENABLED`。
- 不将平台管理端和普通租户 Web 共用同一入口。
- 不向普通租户开放 `platform/*` 路由。
- 不把服务器 SSH、数据库、Redis、OSS 和微信支付密钥展示到管理端。

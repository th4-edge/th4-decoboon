# 装得清运营管理端运行手册

> 适用应用：`th4-decoboon-admin`  
> 后端：`th4-decoboon`  
> 目标：保证运营人员能安全查询、受控调整订阅，并快速发现系统异常。

## 1. 部署拓扑

```text
浏览器
  -> Nginx / HTTPS
      -> admin 静态资源
      -> /api/ 反向代理 -> Spring Boot :8090
          -> MySQL
          -> Redis
```

管理端建议使用独立域名，例如 `admin.decoboon.example`；域名与证书必须按实际环境审批后配置。

## 2. 环境变量

管理端：

```env
VITE_API_BASE=/api/
VITE_DEMO_MODE=false
VITE_APP_VERSION=<release>
```

生产必须确认：

- `VITE_DEMO_MODE=false`
- 不提交任何 `*.local`、密钥或账号文件
- 静态资源 build 带版本号
- Nginx 将 `/api/` 代理到后端回环地址

## 3. 初始化平台运营账号

1. 执行 `24-运营管理端基础.sql`。
2. 初始化 `PlatformOrg` 和 `PlatformDepartment`。
3. 创建独立 `PlatformUser`、`PlatformDepartment` 和 BCrypt 密码。
4. 禁止复用租户 Employee/Credentials 作为平台运营账号。
5. 验收租户 Employee token 调用 `platform/tenant/page` 被用户类型校验拒绝。

## 4. 日常巡检

### 4.1 管理端检查

- 运营总览是否展示企业、订阅、回款、风险和系统告警。
- `platform/system/status` 是否返回 MySQL、Redis、应用进程。
- CPU、内存、磁盘是否超过阈值。
- 最近操作审计是否存在异常企业或异常原因。
- 企业入驻台账是否出现从未登录、7/30 日未登录、负责人手机号缺失或待服务企业。
- 完整手机号揭示是否均填写原因并形成审计；禁止批量导出完整联系方式。

### 4.2 后端只读采集

```bash
bash scripts/prod-monitor.sh collect "30 minutes ago"
```

采集后检查：

- `docs/operations/incidents/registry.json`
- 最新 incident 目录的 `triage.md`
- 错误指纹是否新出现或修复后回归

## 5. 人工订阅操作

### 续费

1. 在客户企业中确认服务状态和剩余天数。
2. 在订阅页确认合同/回款依据。
3. 选择续费天数。
4. 填写可追溯原因。
5. 执行后核对服务期、状态和审计。

### 套餐调整

1. 确认目标套餐已上架。
2. 确认客户所需模块与新套餐一致。
3. 涉及降级时先确认数据保留和历史快照。
4. 执行后核对套餐、席位、门店和模块。

### 席位/门店扩容

1. 根据真实使用率判断，不预卖未来权益。
2. 填写加购数量。
3. 与线下回款或合同同步。
4. 执行后要求企业重新登录或刷新订阅信息。

### 冻结与恢复

- 冻结前确认服务暂停原因。
- 恢复前必须确保服务期未过。
- 冻结不是删除，历史审计与业务数据必须保留。

## 6. 异常处理

### 5xx 或接口超时

1. 停止重复提交，避免重复人工调整。
2. 检查后端进程、数据库、Redis。
3. 只读采集错误日志。
4. 若确认是代码缺陷，使用受控发版；否则转人工处理。

### 资源高负载

- CPU 持续高于 80%：检查错误风暴、定时任务和异常请求。
- 内存高于 85%：检查堆、连接池和缓存。
- 磁盘高于 85%：先清理授权范围内的发布包和日志，不删除业务数据与审计数据。

### 依赖不可用

- MySQL DOWN：停止人工写操作，禁止继续调整订阅。
- Redis DOWN：先确认登录和缓存链路影响，避免重启全部服务。

## 7. 发布与回滚

发布：

```bash
bash scripts/deploy-prod.sh
```

失败自动回滚到 `/opt/decoboon/releases/.previous`。显式回滚：

```bash
bash scripts/rollback-prod.sh
```

发布前检查：

- 数据库迁移已评审并有回滚策略。
- 管理端 `VITE_DEMO_MODE=false`。
- Provider 路由总数和权限测试通过。
- 至少一名平台运营负责人可登录。

## 8. 安全规范

- 不在管理端展示服务器密码、SSH 私钥、数据库密码、微信支付密钥和 OSS AccessKey。
- 不提供 SQL 控制台和任意 Shell 执行。
- 生产账号遵循最小权限和定期轮换。
- 所有人工订阅调整必须写审计。
- 导出数据仅用于授权运营，不得外传给无关第三方。

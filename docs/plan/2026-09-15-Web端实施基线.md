# 装得清 Web 端实施基线

> 日期：2026-09-15  
> 目标目录：`../../前端代码/th4-decoboon-web`  
> 技术栈：Vite + Vue 3 + TypeScript + Element Plus + Vue Router + Pinia + Axios  
> 文档性质：在 product-planning 会话卡住时，根据当前小程序路由、角色矩阵、后端认证代码形成的可执行实施基线。

## 1. 范围与原则

- Web 端参考小程序的信息架构、业务对象和角色权限，但不复制移动端页面布局。
- 首版必须解决：User 登录、角色菜单、桌面导航、核心数据列表/详情、基础表单操作和统一错误处理。
- 服务端仍是权限事实源；Web 菜单隐藏不能替代后端数据权限。
- 业务入参与响应继续使用实体对象，禁止 DTO/VO。
- Web 首版纳入企业员工角色；业主客户暂不纳入首版，保留后续扩展。

## 2. 小程序功能盘点

当前小程序共 62 个页面，核心对象包括：

- 客户、房屋、量房记录、客户跟进。
- 设计方案、客户诉求、方案选择、谈单材料。
- 套餐、材料目录、报价、报价版本。
- 合同、项目、施工阶段、任务、日报、验收、工地相册。
- 材料采购、库存、供应链。
- 应收、收款、应付、付款、支付流水、工人工资、项目账本。
- 员工、门店、团队、邀请、离职交接。
- 订阅、门店包、席位包。
- 消息通知、经营统计、员工业绩、项目评估。

角色：

- BOSS、门店店长、团队负责人、家装顾问、设计师、项目经理、履约专员、财务。
- 业主客户仅保留小程序使用。

## 5. 首版交付等级

### A. 完整可操作

- 登录、退出、当前用户、修改密码。
- 主布局、角色菜单、路由守卫、401/403 处理。
- 经营驾驶舱基础指标和待办入口。
- 客户列表、筛选、分页、详情。
- 项目列表、筛选、分页、详情和阶段/任务读取。
- 报价列表、详情读取。
- 财务总览和应收/应付/台账读取。

### B. 页面壳 + 统一列表/详情组件

- 设计转化。
- 供应链。
- 团队、门店和企业管理。
- 订阅与权益。
- 统计报表。
- 消息中心。

### C. 明确不做

- 业主 Web 端。
- 微信扫码/OAuth 登录。
- 移动端专用拍照、定位和扫码交互。
- 自动续费、退款、发票的完整 Web 操作。
- 复杂拖拽排期和高阶数据大屏。

## 6. User 登录设计

### 6.1 登录方式

- 账号：员工手机号。
- 凭据：密码。
- 首次密码：由 BOSS/店长发起员工密码初始化或发送一次性设置凭证；不把明文密码写入日志、工单或邮件正文。
- 微信用户可在 Web 首次登录后设置密码，和现有微信身份共用同一 `Credentials`。

### 6.2 Credentials 扩展

新增字段：

- `passwordHash`：BCrypt，必须排除所有响应序列化。
- `passwordUpdatedAt`。
- `failedAttempts`。
- `lockedUntil`。
- `mustChangePassword`。

约束：

- 使用 BCrypt，不保存可逆密码。
- 登录连续失败锁定，成功后清零并刷新 `lastTime`。
- 登录、退出、改密、锁定和解锁写入 `UserSecurityLog`。
- Web token 复用 th4 `SecurityManager.sign`/`Token` 机制。
- 密码字段不得出现在 `@Properties` 白名单。

### 6.3 后端 Provider

- `auth/session/password-login`：公开，手机号 + 密码。
- `auth/session/password-change`：需登录。
- `auth/session/password-reset`：公开但受验证码/一次性凭证限制；首版可先实现受控后台重置。
- `auth/session/logout`：需登录。
- `auth/session/info`：继续作为统一会话入口。
- 现有 `auth/session/login` 微信登录保持不变。

## 7. 前端工程结构

```text
src/
  api/             Axios 实例、统一错误、各领域 API
  assets/          Logo、图标、品牌资源
  components/      PageHeader、SearchToolbar、DataTable、StatusTag、EmptyState
  layouts/         AuthLayout、WorkbenchLayout
  router/          路由、守卫、权限元数据
  stores/          session、permission、app
  styles/          Element Plus 主题变量和全局样式
  utils/           storage、formatting、query
  views/           按一级导航组织的页面
```

工程要求：

- `VITE_API_BASE` 必须配置。
- token 使用统一 storage key。
- Axios 自动附加 Authorization。
- 401 清理会话并跳转登录；403 显示无权限。
- 路由 `meta.permissions` 控制菜单和守卫；服务端仍二次校验。
- 表格统一分页、筛选、空状态和加载状态。
- 所有页面适配 1280px 及以上，最低支持 1024px。

## 8. 后端 API 映射

已有 Provider 可直接复用：客户、项目、阶段、任务、报价、财务、团队、统计、消息等现有 `page/list/info/save/update/delete` 路由。

需要在开发阶段核验并适配：

- 登录响应需要能区分 `SessionType`。
- 前端表格需要的关联字段必须通过 `@Properties/@AllowProperties` 最小返回。
- 某些路由依赖移动端语义字段，Web 侧以现有实体字段为准，不新增 DTO。
- 缺失的聚合统计接口先使用已有统计 Provider；首版不做前端拼接大量分页。

## 9. 验收标准

- `npm install`/`npm run build`/`npm run type-check` 通过。
- 登录失败、锁定、成功、退出、改密均有可复现结果。
- 四种企业角色登录后菜单不同，直接访问无权限路由被守卫和 API 双重拒绝。
- 客户、项目、报价、财务页面可以分页、筛选并打开详情。
- 控制台无未处理异常，token 不落日志，密码字段不出现在响应。
- 后端 `mvn test` 通过；新增登录测试覆盖错误密码、停用、锁定、跨企业。
- 桌面端 1440×900 和 1280×800 主要页面无横向溢出。

## 10. 实施顺序

1. 搭建 Vite/Vue3/TS/Element Plus 工程和依赖。
2. 扩展后端 Credentials、迁移、User 登录与改密。
3. 实现 Axios、Pinia、路由守卫和登录页。
4. 实现主布局、角色菜单和驾驶舱。
5. 实现客户、项目、报价、财务完整页面。
6. 其余模块按统一模板落页面壳。
7. 前后端联调、构建和独立验收。

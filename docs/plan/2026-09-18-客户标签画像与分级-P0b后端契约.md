## 三、实体契约

### 3.1 CustomerTag（标签字典）

- 表：`cust_tag`
- 继承：`AuditModel`；`@Model @Note @Entity @DataPermission @EntityListeners(SnowflakeEntityListener.class)`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `tagId` | Long | `@Id @SnowflakeId` | 标签主键 |
| `company` | Company | `@ManyToOne(LAZY)` `com_id` | 企业归属 |
| `name` | String | `@Keyword @Length(max=20)` | 标签名，企业内唯一 |
| `category` | TagCategory | `@Enumerated(STRING)` | 分类 |
| `scope` | TagScope | `@Enumerated(STRING)` | 系统 / 人工 |
| `color` | String | 可空 | 前端颜色 |
| `status` | TagStatus | `@Enumerated(STRING)` | 停用后不可再选 |
| `sort` | Integer | 默认 0 | 排序 |

索引：`(com_id, tag_id)`、`(com_id, category, status)`、唯一 `(com_id, name)`

约束：
- `scope = System` 的字典项**禁止**通过 save/update/delete 修改（服务端拒绝）。
- delete 语义为**停用（软删）**，历史关联保留。

### 3.2 CustomerTagLink（客户标签关联）

- 表：`cust_tag_link`
- 继承：`AuditModel`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `linkId` | Long | `@Id @SnowflakeId` | 主键 |
| `company` | Company | `@ManyToOne(LAZY)` `com_id` | 企业归属 |
| `customer` | Customer | `@ManyToOne(LAZY)` `cust_id` | 客户 |
| `tag` | CustomerTag | `@ManyToOne(LAZY)` `tag_id` | 标签 |
| `createdBy` | Employee | `@ManyToOne(LAZY)` `emp_id` | 打标签的人（留痕） |

索引：`(com_id, cust_id)`、`(com_id, tag_id)`、唯一 `(com_id, cust_id, tag_id)`

约束：只能绑定 `scope = Manual` 且 `status = Enabled` 的字典项；系统标签由服务端自动装配，不落关联表。

## 四、Provider 契约

路由遵循 `{域}/{对象}/{能力}`，能力名限定 `page/list/info/save/update/delete/count/enums/tree/report/unique`。

| 路由 | Request（实体） | Response | 权限 |
|---|---|---|---|
| `customer/customer-tag/page` | CustomerTag(current/size/category/status/keyword) | `Page<CustomerTag>` | 全部登录角色可读 |
| `customer/customer-tag/list` | CustomerTag(category) | `List<CustomerTag>`（仅 Enabled） | 全部登录角色可读 |
| `customer/customer-tag/save` | CustomerTag(name/category/color/sort) | CustomerTag | **BOSS / 店长** |
| `customer/customer-tag/update` | CustomerTag(tagId/name/color/sort/status) | CustomerTag | **BOSS / 店长** |
| `customer/customer-tag/delete` | CustomerTag(tagId) | CustomerTag（停用后） | **BOSS / 店长** |
| `customer/customer-tag-link/save` | CustomerTagLink(customerId/tagId) | CustomerTagLink | BOSS / 店长 / 负责人 / 指派设计师 |
| `customer/customer-tag-link/delete` | CustomerTagLink(customerId/tagId) | Boolean | 同上；**系统标签拒绝** |
| `customer/customer-portrait/save` | CustomerPortrait(customerId + P1–P10) | CustomerPortrait | BOSS / 店长 / 负责人 / 指派设计师 |
| `customer/customer/page` | 现有入参 | `Page<Customer>`（含 tags、grade.level/score） | 现有数据范围 |
| `customer/customer/info` | 现有入参 | `Customer`（含 tags、portrait、grade 全量） | 现有数据范围 |

实现要点：
- 全部继承 `Security`，当前员工 `@User` 注入；企业与归属一律从登录员工推导，**禁止信任前端 companyId/empId**。
- 自定义更新/删除必须走 `DataScopeContext + DataScopeSpecification`，禁止 `findById` 后判断。
- 响应使用 `@Properties(allow = {...})` 白名单，需补齐新增字段与 `CustomerTag` 的最小字段集。
- 列表批量装配 tags/grade，避免 N+1。

### 4.1 系统标签装配规则（只读，不落库）

| 标签 key | 判定 |
|---|---|
| `source:{source}` | `Customer.source` |
| `wechat` | `Customer.wechatAdded = true` |
| `visit:once` / `visit:multi` | `visitCount == 1` / `>= 2` |
| `measured` | 存在 `completed` 量房记录，或 `Customer.measureAt` 非空 |
| `risk:followOverdue` | `nextFollowAt < 今天` 且状态未进入 sign/construction/done/lost |
| `risk:goldenNoContact` | `createTime` 距今 ≤ 3 自然日 且 `lastFollowAt` 为空 且状态未终结 |

> 前端 P0-a 已用同一口径本地投影；后端上线后**以服务端为准**替换。

## 五、分级计算契约

### 5.1 配置来源

复用 `Company.setting`，新增 `gradeConfig`：

```json
{
  "budgetBands": { "high": 200000, "standard": 100000 },
  "thresholds": { "a": 75, "b": 50 },
  "weights": { "demand": 30, "budget": 25, "urgency": 20, "engagement": 15, "recency": 10 },
  "penalties": { "budgetUnreal": 10, "competitor": 10, "noShow": 10, "followOverdue": 5 }
}
```

未配置时使用规格默认值（Q1–Q3 已冻结）。

### 5.2 计算输入

`Customer` + `CustomerPortrait` + 量房事实（`Property/Measure`）+ `CustomerFollow`（数量与最近时间）+ 命中标签。

### 5.3 输出要求（强制）

- 必须返回 `breakdown`，每个维度给出 `weight / score / reason`。
- `level` 必须与 `score` 和阈值一致（A ≥ 75、B 50–74、C < 50）。
- `Customer.stage = lost` 时直接判 `C`。
- 分级为派生值，只读；任何接口不得接受前端直接写 `grade`。

## 八、验收标准

1. 业务员/设计师调用 `customer/customer-tag/save|update|delete` 返回 403（服务端拒绝）。
2. 系统标签（`scope=System`）无法被任何角色删除或改名。
3. 打标签幂等：重复提交不产生重复关联（唯一索引兜底）。
4. 画像 10 字段全部可空，缺失不报错、不阻断主链。
5. 分级 `level` 与 `score` 一致，且 `breakdown` 可解释；`lost` 客户恒为 C。
6. 跨企业、跨门店、跨团队、非指派员工均不可读写标签/画像；伪造 `companyId/empId` 无效。
7. 客户 A 的标签/画像不会出现在客户 B 的响应中；多房屋客户不串号。
8. `customer/customer/page` 批量装配 tags/grade 无 N+1（可用 SQL 计数验证）。

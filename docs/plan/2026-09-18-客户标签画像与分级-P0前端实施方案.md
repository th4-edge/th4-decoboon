# 客户标签 / 画像 / 分级 P0 App 实施方案

- 需求 ID：REQ-20260918-CUSTOMER-TAG-PORTRAIT-001
- 依据：`docs/plan/2026-09-18-客户标签画像与分级实施规格.md`（需求与阈值已冻结）
- 范围：App 客户模块
- 不改动：主链关系、状态机、金额/成本/利润、合同/项目逻辑、既有接口语义

## 一、分批原则：前端先行，后端字段后补

当前 `Customer` 已有：来源、阶段、预算、面积、小区、到店次数、微信、量房时间、最近跟进、下次跟进。
缺失：人工标签、画像 10 字段、A/B/C 分级。

因此拆两批，**P0-a 完全不动接口**，P0-b 依赖后端新增字段：

| 批次 | 内容 | 是否动接口 |
|---|---|---|
| P0-a | 系统标签、提醒、筛选、客户 360 与业绩页排版/交互 | ❌ 纯前端 |
| P0-b | 人工标签字典、画像 10 字段、A/B/C 自动分级 | ✅ 需后端 |

## 二、P0-a（纯前端，可立即开工）

### 2.1 系统标签（由现有字段派生）

统一在 `src/domains/experience/` 增加只读投影函数，App 使用同一口径：

| 标签 | 判定来源 | 分类 |
|---|---|---|
| 抖音 / 小红书 / 转介绍 / 老客户 / 自然到店 | `customer.source` | 来源 |
| 已加微信 | `customer.wechatAdded` | 行为 |
| 已到店 / 多次到店 | `customer.visitCount` | 行为 |
| 已量房 | `customer.measureAt` 或房屋 `latestMeasureAt` | 行为 |
| 逾期未跟进 | `nextFollowAt < 今天` 且未流失 | 风险 |
| 黄金期未首联 | `createdAt ≤3天` 且无 `lastFollowAt` | 风险 |

约束：系统标签**只读**，不可手工增删；不使用演示数据。

### 2.2 提醒（由现有字段计算）

| 编号 | 可实现性 | 说明 |
|---|---|---|
| R2 逾期未跟进 | ✅ P0-a | 现有 `nextFollowAt` 可算 |
| R3 黄金期未首联 | ✅ P0-a | 现有 `createdAt` + `lastFollowAt` |
| R4 待量房超期 | ✅ P0-a | 现有 `pendingMeasureAt` |
| R1 A 级 >3 天未跟进 | ⛔ P0-b | 依赖分级 |
| R5 A 级今日应跟进 | ⛔ P0-b | 依赖分级 |

### 2.3 客户 360（App）排版与交互

- 头部：客户名 + 阶段 + 负责人 + 系统标签行（点击标签即筛选）。
- 提醒条：命中 R2/R3/R4 时在头部下方显示（红/橙），点击跳到处理入口。
- 标签区：按分类分组（来源 / 行为 / 风险），只读。
- 业务员视角：设计、报价、合同、项目**只读**，营销信息（跟进、到店、微信、量房）为主视觉。
- 排版：减少卡片嵌套，统一 Token 与间距，无横向溢出。


## 三、P0-b（需后端字段，接口由后端 lane 实施）

### 3.1 需要后端提供的字段

| 能力 | 建议字段 | 说明 |
|---|---|---|
| 人工标签 | `tags: [{ id, name, category, source }]` | 只读返回，含系统与人工 |
| 标签字典 | `customer/tag/page|save|delete` | 仅老板/店长可写 |
| 画像 | `portrait: { decisionRole, purpose, houseCondition, startWindow, style, eco, household, payment, concerns[], competitor }` | 10 字段 |
| 分级 | `grade: { level: 'A'|'B'|'C', score, breakdown[] }` | 服务端计算，只读 |
| 提醒 | `alerts: [{ code, level, text, reason }]` | 服务端可选，前端也可自算 P0-a 部分 |

> 字段命名与最终契约以 `OBJ-001`、`BR-001` 和后端规范为准；本文只给最小建议，不做接口定稿。

### 3.2 前端接入点

- 客户 360：画像区块（10 字段，可折叠，按权限编辑）、标签区（系统+人工）、分级徽标（点击看评分明细）、提醒条（R1–R5）。
- 客户列表：分级筛选、标签多选筛选、提醒筛选。
- 权限：字典维护仅老板/店长；画像编辑=老板/店长/业务员(自己客户)/设计师(指派给自己)；分级只读。

## 四、交互细节

1. 分级徽标必须可展开"为什么"，展示各维度得分，避免业务员不信任。
2. 提醒不阻断任何动作；点击进入处理入口，不弹错误。
3. 标签点击即加入筛选条件，可多选，可一键清除。
4. 画像字段全部可空，缺失显示"未填写"，不报错、不阻断。
5. 多房屋客户切换房屋时，标签/画像/提醒不串号（按 `activePropertyId` 或客户级正确归属）。

## 五、验收标准（前端部分）

1. 系统标签由真实字段派生，无写死、无演示数据。
2. 提醒命中条件可复现、可解释，且不阻断动作。
3. 业务员不能新建/改名/删除标签字典项（P0-b 后端拒绝，前端不提供入口）。
4. 分级分数与等级一致，且展示明细（P0-b）。
5. 画像 10 字段可空，缺失不报错。
6. 多房屋切换不串标签/画像/提醒。
7. 无横向溢出；主流手机机型基本可用。
8. `npm run type-check`、`npm run build:mp-weixin`、`git diff --check` 通过。

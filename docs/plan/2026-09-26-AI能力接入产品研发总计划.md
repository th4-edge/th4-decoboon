## 3. A1 AI 经营参谋 P0 启动范围

### 3.1 目标

在 Web 企业负责人经营总览中提供 AI 经营简报，生成：

- 一句话经营现状；
- 业务、交付、资金三类事实；
- 最多三条优先行动建议；
- 成本不完整提示；
- 来源和业务下钻。

### 3.2 首个开发切片

本波次只实现“基线版经营参谋”：

1. 复用现有经营驾驶舱、财务汇总、经营预警和项目聚合；
2. 服务端组装结构化事实；
3. 通过统一 `AiBriefGenerator` 生成摘要文本；
4. 首版提供规则基线实现，真实大模型通过环境配置接入；
5. 每次生成调用 `AiUsageContext` 记录企业公共消耗；
6. Web 增加 AI 经营简报卡和来源抽屉；
7. 不做自由问答；
8. 不自动改任何业务状态。

### 3.3 为什么先做规则基线

- 无模型时也能验证数据链路、权限、页面和用量；
- 有模型时可以替换生成器，不改业务页面；
- 避免在业务口径未冻结前让模型直接决定因果；
- 保证 AI 不可用时页面仍可显示确定性事实。

### 3.4 明确不做

- 不生成净利润；
- 不预测下月收入；
- 不判断员工责任；
- 不自动指派风险；
- 不自动催收；
- 不直接写业务事实；
- 不接真实扣点。

## 4. 波次路线

## 5. 研发与协作规则

| 环节 | 负责 | 输出 |
| --- | --- | --- |
| 产品规划 | product-planning | PRD、范围、页面、状态、验收标准 |
| 业务裁决 | business agent | T06、业务条件、权限、金额和例外 |
| 开发 | development | 分支、实现、自测、迁移、交接 |
| 独立验收 | acceptance | 独立用例、证据、结论和缺陷 |
| 发布 | 发布经理 | 合并、发布、迁移、回滚和验证 |

每个研发波次必须完成：

```text
产品规格冻结
-> 业务门禁确认
-> 开发实现和自测
-> 独立验收
-> 合并 dev
-> test
-> prod
```

不得跳过独立验收直接进入生产。

## 6. 权限和安全硬边界

1. 企业、门店、团队和本人范围继续沿用现有数据权限。
2. AI 不读取权限之外的上下文。
3. AI 不自动确认报价、合同、验收、收付款、结算和利润。
4. 成本不完整时利润和毛利率为空。
5. AI 生成内容必须有来源、版本和人工确认。
6. 客户可见内容默认需要责任角色确认，AI 概念设计按 `DEC-010` 例外处理。
7. 平台成本不返回租户页面。
8. 跨租户训练继续执行授权、脱敏、隔离、撤回和审计。

## 8. 成功标准

首批成功不以“生成了多少内容”判断，而以：

1. 真实经营数据可被正确引用；
2. AI 摘要不制造无依据因果；
3. 每次调用有企业和门店归属；
4. 企业总量与门店统计可对账；
5. 页面无数据、失败、额度不足均可恢复；
6. 手工经营总览不被 AI 成功与否阻塞；
7. 独立验收可以复现所有结论。

# 装企入驻财务承接研发切片

> 状态：研发排期草案（2026-10-06）
> 来源方案：`docs/product/2026-10-06-装企入驻账务承接与账务体系对齐方案.md`
> 业务依据：`DEC-004`、`SCN-011`、`BR-010`、`SOL-005`、`MET-002`、`OBJ-001`
> 原则：现有财务核心逻辑不改；新增承接、引导、对照、对账能力

## 0. 总体结论

```text
现有应收/应付/收付款/成本/毛利/现金流公式：不动
新增：期初资金余额、期初余额的计划分解、原账口径备注、双轨对账、承接引导与说明
```

P0 目标：麦鸿这类存量装企可以完成“在跑项目 + 未结应收应付 + 期初资金 + 剩余收付款计划 + 成本完整性”的财务承接，接管后新业务按装得清标准闭环运行。

## 1. P0-1 承接六步向导与完成度投影

> 交付状态（2026-10-06）：第一段「期初资金余额」已交付（App 1.0.14）；账本摸底、完成度投影、原账口径备注、剩余收付款计划分解仍待实施。

### 目标

把现有在跑项目承接扩展为财务可独立执行的六步流程，并让 BOSS/财务看到“还差什么、哪一步异常”。

### 范围

```text
第1步 账本摸底
第2步 承接范围与接管日
第3步 期初应收
第4步 期初应付
第5步 期初资金 + 剩余收付款计划
第6步 成本完整性与角色确认
```

### 涉及对象/页面

- `CarryoverBatch` / `CarryoverProject` / `CarryoverConfirmation` / `CarryoverCostSnapshot`（已有，扩展）
- 承接首页、项目承接向导、完成度清单
- 复用 `Receivable` / `Payable`，标记 `BusinessOrigin.Carryover`

### 完成度投影（按 `rules.md` §13）

| key | label | required | 完成条件 | 异常态 |
| --- | --- | --- | --- | --- |
| `project` | 在跑项目 | 是 | 项目存在且非终态 | 暂不可确认 |
| `owner` | 责任归属 | 是 | 门店/团队/负责人明确 | 待确认，不猜 |
| `contract` | 合同基线 | 是 | 合同编号 + 金额 + 关联项目 | 仅附件无金额 → 未完成 |
| `receivable` | 期初应收 | 条件必填 | 有金额或明确“无应收” | 未确认且未标记 → 未完成 |
| `payable` | 期初应付 | 条件必填 | 有金额或明确“无应付” | 同上 |
| `cash` | 期初资金 | 是 | 账户余额已确认 | 暂不可确认 |
| `plan` | 剩余收付款计划 | 是 | 计划分解合计等于期初应收/应付 | 待补 |
| `cost` | 成本完整性 | 是 | 总额 + 完整性确认 | 不完整 → 利润为空 |

### 验收

- 每个项目独立显示完成/待确认/异常；
- 归属缺失不阻塞其他项目，但阻塞该项目“承接完成”；
- 期初应收/应付允许“明确无”，不允许空着静默通过；
- 成本不完整时利润为空；
- 首笔真实业务后锁定，只允许调整/冲正。

### 风险

- 六步流程对客户财务是新增操作负担，需要模板、说明和首月陪跑；
- 角色确认沿用现有机制，不新增权限角色。

## 2. P0-2 期初资金余额（OpeningBalance）

> 交付状态（2026-10-06）：后端对象、接口、财务汇总口径、迁移 74、测试与生产发布已完成；App 录入界面已随 P0-1 第一段交付（版本 1.0.14，业务承接 → 期初资金余额）。

### 目标

接管日各资金账户余额进入装得清，保证“期初余额 + 接管后净流量 = 当前余额”，同时不污染收入、支出和利润。

### 范围

- 新增 `OpeningBalance` 口径或账户期初字段；
- 支持多个资金账户（对公/现金/微信/支付宝/其他）；
- 展示：期初余额、接管后收入、接管后支出、当前余额。

### 关键规则

```text
期初余额不计入收入
期初余额不计入支出
期初余额不进入项目毛利
当前余额 = 期初余额 + 接管后净流量
```

### 验收

- 接管日账户余额准确；
- 当月收入/支出不包含期初余额；
- 账户余额从接管日连续；
- 多账户分别展示，企业总额可汇总。

### 风险

- 如果实现为一条 Ledger，必须在现金流报表中排除；推荐独立 `OpeningBalance`，不要混入 `Ledger` 收支。

## 3. P0-3 期初应收/应付的计划分解

### 目标

期初应收/应付是“接管日未结金额事实”；剩余收付款计划是这笔金额的**时间分解**，用于财务手动管控，不是新增一笔应收应付。

### 正确口径

```text
期初应收总额 = 接管日未收余额
剩余收款计划 = 对期初应收总额的时间分解，合计必须等于期初应收总额

期初应付总额 = 接管日未付余额
剩余付款计划 = 对期初应付总额的时间分解，合计必须等于期初应付总额
```

### 推荐实现

- 保留每个项目一条汇总 `Receivable` / `Payable`（期初余额事实）；
- 新增 `CarryoverPlanItem`（或复用的期初计划子表）：金额、计划日期、对象、备注；
- 计划合计校验：不得超过或少于期初余额（允许明确“未排期”部分，但必须标记）；
- 收款/付款仍核销期初应收/应付，不核销“计划项”。

### 验收

- 计划合计 = 期初未结余额；
- 不存在“期初应收 + 计划”重复计入；
- 后续收款/付款正常核销；
- 计划变更可追溯，首笔业务后只允许调整。

### 风险

- 这是本次承接最容易双记的地方，必须在需求和测试中明确“计划是分解，不是新增”。

## 4. P0-4 原账口径备注与对照表导出

### 目标

客户可以保留“原账科目/账本”的追溯信息，但不建立会计科目体系。

### 范围

- 承接项目、期初应收/应付、成本快照增加原账口径备注字段；
- 导出《账务承接对照表》；
- 模板包含：原账科目/原金额 → 装得清对象 → 承接方式 → 是否进经营指标 → 差异 → 确认人。

### 验收

- 备注不影响任何金额计算；
- 对照表可导出，能用于客户财务签字确认；
- 不出现“会计科目主数据/借贷分录”。

## 5. P0-5 首月双轨对账表

### 目标

首月同时看原账本与装得清，差异分类收敛后再把新业务完全交给装得清。

### 范围

- 财务手动录入原账本四个主题金额：项目未收、项目未付、资金余额、项目成本；
- 系统计算装得清金额与差异；
- 差异分类：时间、主体、含税、口径、数据缺失；
- 导出《首月双轨对账表》。

### 验收

- 四个主题可对账；
- 差异必须选择分类，不允许无原因差异；
- 对账不影响装得清金额；
- 首月末可生成对账小结。

## 8. 不做清单

- 不做会计科目、借贷分录、法定总账、税务申报；
- 不重建历史已结清收付款流水；
- 不把历史已结清数据计入经营指标；
- 不做任意格式自动科目映射；
- 不用 0 成本计算利润；
- 不为了对齐原账本修改装得清的毛利、现金流和核销公式。

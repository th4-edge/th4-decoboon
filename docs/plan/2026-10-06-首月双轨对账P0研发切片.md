# 首月双轨对账 P0 研发切片

> 状态：研发排期草案（2026-10-06）
> 来源方案：`docs/product/2026-10-06-首月双轨对账设计方案与运营手册.md`
> 业务依据：`DEC-004`、`SCN-011`、`SOL-005`、`MET-002`
> 原则：只对四个主题；原账只读对照；装得清金额只读；差异必须分类；不自动调平

## 0. 总体范围

```text
四个主题：项目未收、项目未付、资金余额、项目成本
原账侧：手工录入 / CSV 模板导入 / 附件
装得清侧：自动带出，只读
差异：自动计算 -> 分类 -> 责任人 -> 处理 -> 确认 -> 关闭
```

P0 目标：完成首月四个主题的对账、差异处理、确认关闭与导出。

## 1. P0-1 对账批次与四主题对象

### 目标

建立首月双轨对账的批次、期间、四主题明细与附件承载。

### 建议对象

| 对象 | 关键字段 |
| --- | --- |
| `CarryoverReconciliation` | reconciliationId、company、batch、asOfDate、periodStart、periodEnd、status、owner、confirmedBy、confirmedAt、closedAt |
| `CarryoverReconciliationItem` | itemId、reconciliation、theme、originalAmount、systemAmount、difference、differenceType、differenceStatus、reason、action、owner、dueDate |
| `CarryoverReconciliationAttachment` | attachmentId、reconciliation、category、fileUrl、originalName |

### 枚举

```text
Theme: Receivable / Payable / Cash / Cost
Status: Draft / Pending / DiffHandling / Confirmed / Closed
DifferenceType: Time / Entity / Tax / Scope / MissingData
DifferenceStatus: Pending / Handling / Resolved / Accepted
```

### 数据与迁移

- 新增 `carryover_reconciliation`、`carryover_reconciliation_item`、`carryover_reconciliation_attachment` 三张表；
- 首月期间默认接管日到当月最后一天；
- 历史对账结果不物理删除，关闭后只能新建调整期。

### 验收

- 同一企业同一批次只允许一个进行中的首月对账；
- 四个主题必须齐全；
- 历史已结清数据不进入对账。

## 2. P0-2 对账首页与原账金额录入

### 目标

财务可以录入四个主题的原账金额和来源附件，看到差异概览。

### 页面

- 首月双轨首页：期间、状态、四个主题卡片、差异待处理数量；
- 原账金额录入：四个主题金额、来源说明、附件上传；
- 支持 CSV 模板导入（P0 先手工录入 + 附件，P1 再做导入）。

### 接口

- `carryover/reconciliation/page`：对账批次列表；
- `carryover/reconciliation/info`：对账详情；
- `carryover/reconciliation/save`：创建/更新对账批次与原账金额；
- `carryover/reconciliation/attachment/save|page|delete`：附件。

### 验收

- 原账金额不允许空白静默通过；可明确“无此主题”；
- 原账金额不进入装得清经营指标；
- 附件可追溯。

## 3. P0-3 装得清侧金额自动带出与差异计算

### 目标

系统按四个主题自动带出装得清金额并计算差异。

### 口径

| 主题 | 装得清侧来源 |
| --- | --- |
| 项目未收 | `Receivable` 未收余额合计（期初应收 + 新应收 - 已收） |
| 项目未付 | `Payable` 未付余额合计（期初应付 + 新应付 - 已付） |
| 资金余额 | `FinanceSummary.cashBalance`（期初资金 + 接管后净流量） |
| 项目成本 | 项目实际成本合计（接管前成本快照 + 接管后材料/人工/项目/项目零星成本） |

### 规则

```text
差异 = 原账金额 - 装得清金额
差异只读计算，不允许在对账页直接改装得清金额
成本不完整时，项目毛利为空，对账表标记“成本未完整”
```

### 验收

- 四个主题金额与财务工作台/项目财务同源；
- 修改接管后业务后，对账金额可重新读取；
- 历史已结清不进指标。

## 4. P0-4 差异分类与处理

### 目标

每条差异必须分类、指定责任人、记录处理动作，形成差异清单。

### 差异分类

```text
时间差异、主体差异、含税差异、口径差异、数据缺失
```

### 处理动作

```text
补录来源、更正、冲正、继续观察、客户后续处理
```

### 页面

- 差异清单：按主题/状态/责任人筛选；
- 差异详情：原账、装得清、差异、分类、原因、动作、期限；
- 批量操作：批量指派、批量接受。

### 验收

- 未分类差异不能进入确认；
- 未处理差异不能关闭；
- 差异处理不直接修改装得清金额；
- 每条差异可追溯处理人和时间。

## 5. P0-5 完成度投影与确认关闭

### 目标

用可完成状态投影展示四个主题和差异处理完成度，财务确认、BOSS 关闭。

### 完成度投影

| key | label | required | 完成条件 | 异常态 |
| --- | --- | --- | --- | --- |
| `receivable` | 项目未收 | 是 | 原账 + 装得清 + 差异分类 | 暂不可确认 |
| `payable` | 项目未付 | 是 | 同上 | 暂不可确认 |
| `cash` | 资金余额 | 是 | 期末余额已核对 | 暂不可确认 |
| `cost` | 项目成本 | 是 | 成本金额 + 完整性 | 成本不完整 → 利润为空 |
| `difference` | 差异分类 | 是 | 每条差异有分类和责任人 | 未分类 → 不能确认 |
| `owner` | 责任确认 | 是 | 财务确认 + BOSS 确认 | 缺失 → 待确认 |

### 验收

- 完成度重新读取真实对象，不用前端本地布尔；
- 接口异常显示“暂不可确认”，保留恢复路径；
- 关闭后只能新建调整期。

## 6. P0-6 对账表导出与对账小结

### 目标

生成可签字、可留档的对账表与小结。

### 输出

1. 《首月双轨对账表》：四个主题的原账、装得清、差异、分类、处理；
2. 《差异清单》：逐条差异、责任人、期限、状态；
3. 《首月对账小结》：差异收敛情况、退出建议、遗留问题。

### 验收

- 可导出 Excel/PDF；
- 导出内容与页面同口径；
- 对账表可附原账附件；
- BOSS/财务可签字确认。

## 8. 不做清单

- 不做会计科目/借贷分录/法定总账/税务；
- 不做全科目对账；
- 不做自动调平；
- 不把历史已结清流水计入指标；
- 不用 0 成本计算利润；
- 不为对齐原账修改装得清核心口径。

## 9. 依赖与前置

- P0-1/P0-2/P0-3 已交付：承接六步主体、期初资金、账本摸底/原账备注、剩余收付款计划；
- 四主题装得清侧数据来源已存在：`Receivable`、`Payable`、`FinanceSummary.cashBalance`、项目成本汇总；
- 无新增会计口径；
- 需要用户确认首月对账的四个主题金额是“期末口径”还是“期间发生额口径”。

```text
P0-1 对账批次与四主题对象
-> P0-3 装得清侧自动带出与差异计算
-> P0-2 原账金额录入与附件

-> P0-5 完成度投影与确认关闭
-> P0-6 对账表导出与小结
-> P0-7 运营模板与培训
```

# 客户休眠状态与风险跟进排除跨端研发切片

> 日期：2026-10-08  
> 状态：业务裁决完成，研发规划完成，待进入实现  
> 业务依据：`DEC-042`、`BR-036`、`SCN-020`、`T12-BIZ-20261008-003`  
> 产品规格：`docs/product/2026-10-08-客户休眠状态与风险跟进排除-P0产品规格.md`  
> 风险级别：DDL + 权限 + 跨模块状态过滤，按高风险变更执行定向 + 全量验证

## 1. 交付目标

完成后端、App、Web 同一口径的客户休眠闭环：

- 三角色按数据范围设置和恢复；
- 原因必填、状态可审计；
- 风险和自动待办即时排除；
- 写跟进自动唤醒；
- 旧客户端兼容不误显示。

## 2. 研发切片

### B1 领域模型与迁移

- 扩展 `CustStatus`：`Dormant`；
- 扩展 `Customer` 休眠字段；
- 新增 `CustomerStatusLog` 实体、仓储和迁移；
- 历史客户不回填，字段允许空；
- 迁移脚本可重复执行并提供回滚说明。

### B2 状态动作与权限

- 新增 `customer/customer/dormant`；
- 新增 `customer/customer/resume`；
- 新增状态日志分页；
- 服务端校验角色、数据范围、原因、状态条件、量房和合同阻断；
- 分布式锁/幂等请求号控制；
- 从通用 `Customer.Save/Update` 移除状态旁路。

### B3 共享风险与工作台过滤

- `CustomerInsightContext` 提前处理 `Dormant`；
- `openStatus`、风险、主行动和经营时钟排除休眠；
- `CustomerOverviewContext`、`MyCustomerOverviewContext` 增加休眠桶和排序；
- 设计、报价、签约工作台 SQL 排除休眠客户；
- 店长、业务员、设计师和团队报表补休眠计数并排除活跃风险。

### B4 跟进自动唤醒

- 修改 `customer/customer-follow/save`；
- 对休眠客户在同一事务恢复原状态、保存跟进、写 `FollowWake` 日志；
- 恢复后重新计算风险；
- 重复提交保持幂等。

### W1 Web 契约与动作

- 更新 CRM 模型、API、阶段元数据和状态映射；
- 业务员客户页、店长客户页、企业负责人客户经营页接入动作；
- 增加休眠筛选、标签、详情和恢复；
- 所有页面读取服务端派生风险，不前端重算。

### A1 App 契约与动作

- 更新 CRM 模型、API、阶段元数据；
- 客户列表增加休眠筛选与标签；
- 客户详情增加设置/恢复动作和原因弹窗；
- 写跟进提示并承接自动唤醒。

### Q1 跨端验收

- 后端 API + DB + 日志核验；
- Web 真实浏览器；
- App 微信 DevTools；
- 三角色权限、正向、反向、边界、幂等、跨端一致性。

### R1 发布准备

- 迁移备份与回滚；
- 全量测试；
- 旧客户端兼容开关或版本门槛；
- 健康检查和核心路径冒烟；
- 生产发布前用户确认。

## 3. 建议实施顺序

```text
B1 模型/迁移
-> B2 动作/权限
-> B3 风险/统计/工作台
-> B4 自动唤醒
-> W1/A1 并行接入
-> Q1 跨端验收
-> R1 发布准备
```

B1、B2 是阻塞项；B3 契约冻结后 Web 和 App 可并行，但不得各自实现状态和风险规则。

## 7. 当前阻塞与执行注意

- 当前后端工作区存在其他 lane 未提交改动且位于 `hotfix/payroll-projections-all`，Web/App 也有未提交改动。正式编码前应先隔离本需求分支或确保变更边界，避免把休眠功能与薪酬/工作台在途改动混合提交。
- 旧客户端对未知状态存在回退到“待首联”的风险，必须采用服务开关或前端最低版本门槛。
- 生产 DDL、权限和状态迁移未执行；不得对外称功能已上线。

## 0. 目标

把 App 增减项发起从“手填金额/名称”升级为“围绕企业报价项目库和企业合同的正式变更”：

```text
新增分项
减项（部分减少 / 整项取消）
替换
```

多条明细最终形成一张 `ContractChange`，一次客户线下确认、一次审批、一次履约联动。

## 1. 范围与不做的内容

### 1.1 本期范围

- `ContractChangeItem` 目标报价项目引用与业务快照；
- 当前有效剩余工程量/金额投影；
- 待审批占用与批内重复来源处理；
- 三类动作的服务端金额计算；
- 审批后的任务、材料、应收、成本展开；
- App 逐条新增/批量录入共用草稿；
- 报价项目库选择器和工程量确认；
- App 表单统一 `jz-form-*` 规范。

### 1.2 不做

- 不删除或改写原 `QuoteLine` / `ContractLine`；
- 不新增“调价”入口；
- 不按原合同全量重算历史替换；
- 不把每条明细拆成单独审批单；
- 不用前端金额覆盖服务端差额；
- 不在迁移方案确认前执行 DDL。

## 2. 数据模型

### 2.1 来源范围与目标范围

变更的“来源 S”既可能是原合同行，也可能是此前已生效的新增/替换产生的目标范围：

```text
RangeKey =
  ContractLine(lineId)
  或
  ContractChangeItem(changeItemId, 仅新增/替换目标范围可用)
```

因此 `ContractChangeItem` 增加稳定来源引用：

- `sourceLine`：原合同行来源；
- `sourceChangeItem`：此前已生效的新增/替换目标来源；
- 二者最多只能有一个；新增分项两者均为空。

### 2.2 目标分项快照

新增/替换从启用 `CatalogItem` 选择，服务端冻结：

- 目标 `CatalogItem` 引用；
- 名称、类型、分类、品牌、系列、规格、单位；
- 计价方式、材料单价、人工单价、固定总价、公式说明；
- 施工工艺、验收标准；
- 工程量、目标金额；
- 成本单价、成本金额、成本完整性。

目标快照必须足以在审批生效后直接生成任务、材料和成本，不允许运行时再依赖可能变化或停用的报价项目库主数据。

### 2.3 来源剩余快照

每条减项/替换明细必须冻结创建时的来源剩余基线：

- 来源类型与稳定引用；
- 来源当前有效剩余工程量；
- 来源当前有效剩余金额；
- 来源当前有效单价；
- 来源基线时间/版本；
- 本次关闭工程量、关闭金额；
- 本条金额差额、成本差额、成本完整性。

- 项目成本聚合必须继续输出 `costComplete=false`，利润/毛利率为 `null`。

## 4. 当前有效剩余投影

### 4.1 权威公式

```text
Rq(S) = 初始有效量 - 已生效部分减少量 - 已生效整项取消量 - 已生效替换关闭量
Ra(S) = 当前有效剩余对应金额
Pq(S) = 待审批部分减少量 + 待审批整项取消量 + 待审批替换关闭量
Aq(S) = max(0, Rq(S) - Pq(S))
```

其中 `S` 为原合同行或已生效新增/替换目标范围。

### 4.2 实现方式

新增派生上下文 `ContractChangeRangeContext`，不新增可变的“剩余量字段”作为事实源：

- 以 `ContractLine` / 已生效 `ContractChangeItem` 为范围起点；
- 汇总已生效和待审批变更明细；
- 输出统一投影：初始量、已关闭量、待审批占用量、可变更量、当前有效单价、剩余金额、是否可确认；
- 前端只消费投影，服务端在提交和审批时重新计算。

### 4.3 需要阻断的情况

- 历史记录关系或差额无法解释；
- 来源已有其他待审批占用导致超减；
- 同一批多条明细重复超过来源剩余；
- 创建后来源基线变化；
- 目标 `CatalogItem` 停用、跨企业或不可报价；
- 项目已完工、合同关闭/终止。

## 5. 服务端动作与公式

| 用户动作 | 内部类型 | 来源 | 目标 | 差额 |
| --- | --- | --- | --- | --- |
| 新增分项 | `Add` | 无 | `CatalogItem` + 工程量 | `+目标金额` |
| 部分减少 | `Quantity` | 当前有效范围 | 无 | `-(当前有效量 - 变更后量) × 当前有效单价` |
| 整项取消 | `Remove` | 当前有效范围 | 无 | `-来源当前有效剩余金额` |
| 替换 | `Replace` | 当前有效范围 | `CatalogItem` + 工程量 | `目标金额 - 来源当前有效剩余金额` |

`Price` 不再接受新建；历史 `Price` 详情只读。

### 5.1 字段落库映射

- 新增：`oldQuantity=0`，`newQuantity=目标工程量`，`amountDelta=+目标金额`；
- 部分减少：`oldQuantity=来源当前有效量`，`newQuantity=变更后剩余量`，`amountDelta` 为负差额；
- 整项取消：`oldQuantity=来源当前有效量`，`newQuantity=0`，`amountDelta=-来源当前有效剩余金额`；
- 替换：`oldQuantity=来源当前有效量`，`newQuantity=目标工程量`，`newPrice=目标单价`，`amountDelta=目标金额-来源当前有效剩余金额`。

## 6. Provider 改造

### 6.1 `project/contract-change/batch-save`

- 统一接受三类动作的多行明细；
- 每行允许传 `sourceLineId` 或 `sourceChangeItemId`，最多一个；
- 新增/替换传 `targetCatalogItemId`、`targetQuantity`；
- 部分减少传 `reduceQuantity`；整项取消由 `changeType=Remove` 表达；
- 服务端加载来源范围、目标 `CatalogItem`，重新计算剩余、金额、成本和目标快照；
- 任一行失败整单拒绝，不产生半张变更单；
- 最终形成一张 `ContractChange`，一次审批。

### 6.2 预览 Provider

建议新增 `project/contract-change/preview`：

- 输入与 `batch-save` 相同，不落库；
- 返回每条动作的来源剩余、目标金额、本条差额、整单汇总、阻断原因和成本完整性；
- 仅用于 App 操作反馈，不作为正式提交依据。

### 6.3 审批

`project/contract-change/update` 审批通过时必须：

- 再次校验来源基线是否变化；
- 再次校验当前有效剩余和待审批占用；
- 通过后在同一事务联动合同额、应收、任务、材料、成本；
- 记录幂等结果，重复审批不重复生成履约对象。

## 7. 履约展开

`ContractChangeFulfillmentContext` 按目标快照展开：

- 新增：以目标快照生成任务/材料；不需要源合同行；
- 部分减少：调整未执行来源范围；已施工/已采购保留事实并生成差异；
- 整项取消：关闭当前有效剩余范围；
- 替换：关闭来源剩余范围，生成目标分项的任务和材料；
- 主材目标必须写目标 `CatalogItem`、品牌、规格、单位、目标成本完整性，不能沿用源合同行的目标属性；
- 应收和合同当前额使用服务端汇总差额。

## 8. App 表单设计

页面复用 `/subpackages/project/pages/change-create`。

### 8.1 模式

- 顶层 tab：`逐条新增`（默认）/ `批量录入`；
- 两种模式共享同一份本地草稿；
- 切换 tab 不丢数据；
- 最终只提交一次 `batch-save`。

### 8.2 三类动作

- 新增分项：报价项目库选择 → 工程量 → 目标摘要；
- 减项：原合同行/已生效目标范围 → 部分减少或整项取消；
- 替换：来源范围 → 报价项目库目标 → 新工程量；
- 调价：不提供新建入口。

### 8.3 控件规范

- 使用全局 `jz-form-row`、`jz-form-label`、`jz-form-input`、`jz-form-control`、`jz-form-textarea`；
- 普通表单行最小高度 `104rpx`；
- 输入/选择框最小高度 `84rpx`；
- 标签宽 `168rpx`；
- 数字输入使用 `jz-numeric-input`；
- 移除页面局部 `.cc__input`、`.cc__pick` 高度/内边距覆盖；
- 选择器统一右侧 `chevron-down` 图标，不允许不同高度。

### 8.4 状态与反馈

- 未选项目/合同：禁用；
- 来源剩余不可确认：显示阻断，不显示 0；
- 来源剩余为 0：禁止减项/替换；
- 目标成本缺失：显示“成本未完整”；
- 提交失败保留全部草稿；
- 提交成功跳详情并重新读取服务端结果。

# 凭证套打与单据模板 · 字段与占位符冻结清单

> 状态：冻结 **v2.0**
> 日期：2026-09-21
> 依据：业务智能体 `DEC-005`、`DEC-006`、`SCN-008`、`SCN-009`、`BR-006`、`BR-007`、`OBJ-002`、`OBJ-003`、`REQ-BIZ-20260921-002`
> 用途：研发实现依据。本文冻结凭证与工人档案的字段、占位符、持久对象、L2 可配置项与平台基线默认值。

> **v2.0 修订（2026-09-21）**：① 凭证**改为落库**（撤销 v1.0"不留归档"口径，便于研发交付与重打）；② 工人档案确定**独立实体 + 企业级共享**；③ 设计师不返回完整身份证号与银行账号。

## 1. 范围

**做**

- 凭证类型：收款单、付款单（工资发放凭证、材料付款凭证、班组结算凭证等模板）。
- 单据模板配置：样式 + 占位符（L1 平台行业基线 + L2 受控参数）。
- 数据来源：系统款项记录（`Receipt` / `Payment` / `Ledger`）。
- 输出：可打印 PDF，支持单笔与同类合并；**凭证落库**，支持按记录重打。
- 新依赖：个人工人档案（独立实体，项目经理维护）。

**不做**

- 会计记账凭证、会计科目、借贷分录、法定总账、税务申报口径。
- L3 自由版式/套打（不承诺预印纸像素级对位）。
- 打印与导出的订阅闸门、导出审计。

## 2. 与现有对象的关系

| 现有对象 | 本需求中的作用 | 是否改动 |
| --- | --- | --- |
| `DocumentTemplate` | 单据模板：`type` + `fieldConfig`(占位符) + `styleConfig`(样式) + `scope` + `version` | 复用，补凭证字段与样式项 |
| `DocumentProfile` | 企业抬头：`legalName` / `address` / `serviceHotline` / `bankName` / `bankAccount` / `logo` | 直接复用 |
| `DocumentType` | 已有 `Receipt`（收款单）、`Payment`（付款单） | **无需新增枚举** |
| `QuotePdfRenderer` | 报价单渲染参考实现（OpenPDF） | 作为渲染参考 |
| `Partner` | 供应商 / 劳务班组（组织级） | **不改**；工人走独立实体 |
| `Payment` | 付款事实 | 增加**可选工人关联**（个人付款） |

## 3. 凭证类型与模板

| 凭证类型（`DocumentType`） | 数据来源 | 模板示例 | 对方取义 |
| --- | --- | --- | --- |
| `Receipt` 收款单 | `Receipt` | 客户收款凭证 | 付款方（客户） |
| `Payment` 付款单 | `Payment` | 工资发放凭证、材料付款凭证、班组结算凭证 | 收款方（工人 / 班组 / 供应商） |

- 凭证名称 = 模板名称（`DocumentTemplate.name`）。
- 暂时**不新增** `DocumentType`。

## 4. 凭证号规则

凭证已**落库**，编号在**首次生成时产生并随记录持久化**，重打读取同一条记录，编号不变。

| 场景 | 规则 | 示例 |
| --- | --- | --- |
| 格式 | `PZ` + `yyyyMMddHHmmss` + 4 位序号 | `PZ20260331121705260671` |
| 唯一性 | 企业内唯一，落库唯一索引约束 | — |
| 重打 | 读取已存记录，编号不变 | — |
| 合并 | 主凭证一个编号，明细行各自保留来源单号 | — |

> 说明：v1.0 因"不留归档"要求编号必须可推导复现；本版改为落库后，**可直接采用样张的时间戳式编号**，重打一致性由"引用同一条记录"保证，不再需要哈希推导。

## 5. 合并打印规则

- 判定：**收款方/付款方 + 项目 + 款项类型** 三者全部相同才可合并；任一不同不得合并。
- 合并后一张凭证含多条明细行；抬头金额 = 各明细金额之和。
- 明细行按业务日期升序排列。
- 合并凭证的明细行保留各自**来源单号**，用于回溯到原始款项记录。

## 8. 凭证持久对象（新增，冻结）

### 8.1 凭证主表（建议 `VoucherRecord`）

| key | 说明 | 备注 |
| --- | --- | --- |
| `voucherId` | 主键 | `@Id + @SnowflakeId` |
| `company` | 所属企业 | 强制 |
| `store` / `team` / `owner` | 权限归属快照 | 继承来源款项记录 |
| `project` | 关联项目 | |
| `type` | 凭证类型 | `DocumentType`（Receipt / Payment） |
| `voucherNo` | 凭证编号 | 企业内唯一 |
| `title` | 凭证名称 | 模板名 |
| `template` / `templateVersion` | 模板引用与版本 | 模板变更不回溯 |
| `totalAmount` | 金额合计 | |
| `amountWords` | 金额大写 | |
| `partyName` | 对方名称快照 | |
| `party` | 对方引用 | 工人档案 或 `Partner` |
| `path` / `sha256` / `size` / `fileName` / `contentType` | PDF 文件 | 私有存储 |
| `generatedBy` / `generatedAt` | 生成人与时间 | |
| `status` | 状态 | 有效 / 作废（作废保留原件） |

### 8.2 凭证明细表（建议 `VoucherItem`）

| key | 说明 |
| --- | --- |
| `itemId` | 主键 |
| `company` / `voucher` | 企业 + 所属凭证 |
| `sourceType` / `sourceId` | 来源款项记录类型与 ID |
| `sourceNo` | 来源单号（快照） |
| `businessDate` / `account` / `amount` / `category` / `remark` | 明细快照 |
| `targetAccount` | 到账账户快照 |

### 8.3 索引与归属

- 必须建：`(com_id, voucher_id)`、`(com_id, voucher_no)`（唯一）、`(com_id, project_id, voucher_id)`。
- 权限维度：`(com_id, store_id, voucher_id)`、`(com_id, team_id, voucher_id)`、`(com_id, owner_id, voucher_id)`，`com_id` 最左。
- 凭证与明细均带 `company`；数据范围继承来源款项记录。

### 8.4 敏感信息处理

- **身份证号与银行账号不落库为可检索列**：仅存引用 + 名称快照，完整值出现在 PDF 文件内。
- 若确需落库（如需按身份证检索工人），只落在**工人档案**，不复制到凭证表。
- 响应按角色裁剪：非财务/BOSS 角色不返回完整敏感值。

## 10. 平台基线默认值（L1）

- 模板：平台行业基线，**零配置即可打印**。
- 字段：§6 / §7 全部启用（不适用字段除外）。
- 样式：字号 12 px、主色 `#2f7d5a`、签字栏开启、抬头显示。
- 企业没有自定义模板时直接使用基线；"恢复平台基线"一键回到本状态。

## 11. 权限

| 动作 | 角色 |
| --- | --- |
| 打印凭证 | 财务、BOSS |
| 模板配置 | BOSS、店长、财务 |

## 12. 金额大写规则

| 情况 | 规则 | 示例 |
| --- | --- | --- |
| 整元 | `X元整` | `40.00` → 肆拾元整 |
| 有角无分 | `X元Y角` | `40.50` → 肆拾元伍角 |
| 有分 | `X元Y角Z分` | `40.56` → 肆拾元伍角陆分 |
| 中间零 | 按中文习惯合并 | `1005.00` → 壹仟零伍元整 |
| 负数/冲销 | 前置"负" | `-40.00` → 负肆拾元整 |
| 金额为 0 | 拒绝生成 | 提示"凭证金额不能为 0" |

## 13. 技术落点与待研发确认

**建议落点**

- 能力路由：`document/voucher/build`（生成）与 `document/voucher/page`（凭证记录查询）；`build` / `page` 均为规范能力名。
- 复用：`DocumentTemplate`（`fieldConfig` / `styleConfig`）、`DocumentProfile`。
- 渲染：沿用 OpenPDF，参考 `QuotePdfRenderer`。
- 入参：沿用批量 Provider 模式（参考 `project/contract-change/batch-save`）：入参为款项实体 + `@AutoInject` 明细 ID 列表。
- 返回类型：**凭证记录实体**（解决 v1.0"禁止 DTO 又要返回瞬时结果"的矛盾）。

**待研发确认（1 项）**

1. **PDF 交付方式**：生成后如何给前端（内存流下载 / 私有存储 + 短期 URL）。私有文件链路已有 `FileGrant` 可参考。

**已确认**：L2 配置 JSON schema 采用平台既有 `showXxx` 布尔键 + `{primaryColor, fontSize, rowSpacing}` 样式键，逐键白名单校验（见 §17）。

## 14. 验收要点

| 类型 | 用例 |
| --- | --- |
| 正向 | 登记收款/付款 → 生成 PDF 并落库 → 打印成功 |
| 复现 | 同一凭证重复打印，**编号与文件不变**（读同一记录） |
| 合并 | 三者相同的多笔 → 一张凭证多明细行，来源单号可回溯 |
| 不合并不 | 三者任一不同 → 不允许合并 |
| 基线 | 企业未配置模板时，直接用平台基线打印 |
| 反向 | 无权限、跨企业、模板未启用、金额为 0 |
| 权限 | 凭证按数据范围可见；设计师/店长拿不到完整身份证号与账号 |
| 金额 | 大写与数字一致；负数冲销加"负" |
| 落库 | 凭证与明细均可按企业、项目、编号查询 |
| 订阅 | 订阅到期仍可打印/导出 |

## 16. 交付建议

工人档案与凭证**同批实现**：凭证个人版的身份证号、工种、到账账户依赖工人档案先行落地。

建议拆分：

1. 后端：工人档案实体 + 维护 Provider + 敏感字段裁剪。
2. 后端：凭证记录/明细实体 + 渲染器 + `document/voucher/build` 与 `page`。
3. 后端：`Payment` 增加可选工人关联。
5. 权限与脱敏验收：四角色 × 敏感字段 × 跨企业负向用例。

## 17. L2 配置 JSON schema（冻结）

`fieldConfig` 为布尔对象，键统一 `show` 前缀，服务端逐键白名单校验（`DocumentTemplateContext`）；未出现的键视为显示。

**通用键**：`showCompanyName`、`showCompanyAddress`、`showServiceHotline`

**凭证键（Receipt / Payment 均允许）**

| 分组 | 键 |
| --- | --- |
| 凭证头 | `showVoucherNo`、`showVoucherDate`、`showPartyName`、`showWorkerIdCard`、`showWorkerTrade`、`showWorkerPhone`、`showProject`、`showAmount`、`showAmountWords`、`showSignBlock` |
| 明细行 | `showDetailNo`、`showDetailDate`、`showDetailAccount`、`showDetailAmount`、`showDetailTarget`、`showDetailCategory`、`showDetailRemark` |
| 类型专有 | 收款单 `showCustomer`、`showReceivedAt`；付款单 `showPartner`、`showPaidAt` |

**样式键**：`primaryColor`（`#RRGGBB`）、`fontSize`（9–14）、`rowSpacing`（0–6）

**平台基线默认**：除 `showWorkerIdCard` / `showWorkerTrade` 在收款单默认关闭外全部开启；`showDetailCategory`、`showDetailRemark` 默认关闭。

**保存权限**：`document/template/save` 允许**企业负责人、店长、财务**保存（2026-09-21 用户确认放开）；服务端在已有企业模板上版本号自增。

## 18. 平台常用凭证模板库（内置）

平台内置**常用凭证模板**，企业可一键套用后改名保存为企业模板（服务端路由 `document/baseline/list`，基线版本 `VERSION=2`）。

| 预设编码 | 类型 | 名称 | 适用场景 | 与默认主要差异 |
| --- | --- | --- | --- | --- |
| `P-SALARY` | 付款单 | 工资发放凭证 | 发给**个人工人** | 开身份证号与工种；关款项类型与明细备注 |
| `P-LABOR` | 付款单 | 班组结算凭证 | 发给**劳务班组** | 关身份证号与工种；开到账账户与签字栏 |
| `P-SUPPLIER` | 付款单 | 材料付款凭证 | 发给**材料供应商** | 开款项类型；关身份证号与工种 |
| `P-EXPENSE` | 付款单 | 费用报销付款单 | 内部费用支出 | 开款项类型与明细备注；字段精简 |
| `R-STANDARD` | 收款单 | 客户收款收据 | 对客户开具收据 | 全字段（对方/项目/金额/大写/到账账户/签字栏） |
| `R-DEPOSIT` | 收款单 | 定金收据 | 收取定金与首期款 | 增开明细备注，突出金额与大写 |

规则：

1. 预设是**只读基线**，不落企业表；企业套用后保存即形成自己的模板版本。
2. **默认模板**取该类型第一个预设：付款单 = 工资发放凭证，收款单 = 客户收款收据。
3. 预设的字段键必须全部落在 §17 的白名单内（已有自动化用例逐条校验，防止基线自身违规）。
4. 报价单、材料计划单、合同打印稿仍各一条行业基线，不进凭证模板库。

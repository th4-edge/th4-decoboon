## 0. 结论摘要（先看这里）

### 0.1 能不能 1:1 实现？

**结构与交互层面：能，且现有技术栈可直接承接。** 原型是纯 HTML/CSS/内联 SVG，无第三方图表库依赖；目标工程为 Vue3 + TypeScript + Element Plus + ECharts 6（`th4-decoboon-web`），卡片、KPI、表格、pill、进度条、排行、热力图、里程碑、甘特条、瀑布、环形全部可 1:1 复刻。

**数据层面：不能一次到位，必须分三级。**

| 级别 | 含义 | 原型中的占比 | 处理方式 |
| --- | --- | --- | --- |
| **A · 可直接实现** | 现有 Provider 已返回所需字段，或仅需字段挑选与聚合 | 约 40% | 本批直接做 |
| **B · 需新增聚合** | 对象与字段已存在，但缺跨表/跨周期聚合 Provider 或时间戳 | 约 40% | 本批补 Provider 后做 |
| **C · 需先业务裁决或先建对象** | 与现行业务口径冲突、依赖系统中不存在的对象 | 约 20% | **禁止直接实现**，先出裁决项 |

### 0.2 已由用户决策解决的阻断项（2026-09-23）

| 决策 | 结论 | 详见 |
| --- | --- | --- |
| Web 一级导航 | 采用原型 IA，`DEC-002` 的 Web 一级导航不再约束本端 | §10.6 |
| 路由注册方式 | 不新建后端 `ViewSettingConfigure`，路由与菜单**完全前端控制** | §5.5、§14 |
| 组织维度 | 按「角色 + 门店/团队」，禁止新增部门；工长排行改为「项目经理交付准时率」 | §10.4 |
| 财务口径 | 按毛利润/毛利率，**不做净利润** | §10.1 |
| Web 工程目录 | `前端代码/th4-decoboon-web` | §1.1、§14.2 |

### 0.3 仍需裁决的 5 个阻断项

> 以下各项在本稿 §10 已给出**建议默认值**，可按默认值先实现；若业务侧有不同意见再回改。

1. **综合毛利率的口径**：`MET-002` 明确要求区分「报价时预计毛利 / 施工中动态毛利 / 结算最终毛利」，三者不得混用为同一个对外数字。原型首页「综合毛利率 32.8%」未标注口径。→ 必须标注口径，详见 §10.1。
2. **签约转化率 / 报价转化**：`MET-001` + `DEC-001` 已冻结为「最终报价接受率 + 首版报价接受率」双指标，且**当前代码实现与冻结口径不一致**。原型把「报价 98 → 签约 18」合成一条转化率，会重新引入已裁决的分母问题。→ 详见 §10.2。
3. **成本不完整态**：原型所有毛利数字都是确定值（12.4%、31.2%…）。系统规则要求 `costComplete=false` 时 `grossProfit/grossMargin` 返回 `null` 并显示「成本未完整」。→ 全部毛利字段必须带 null 态设计，详见 §11.2。
4. **组织口径**：原型出现「行政部」「物料员」「工长」。装得清角色固定 7 类，**禁止新增**重复角色，物料与采购职责已并入 `Finance`；「工长」在本系统不是角色。→ 详见 §10.4。
5. **品牌 Logo 与主色**：原型用「装」字渐变方块冒充 Logo，违反 `rules.md` §12「禁止用清/装单字方块」；原型主色为蓝色 `#3b6ef6`，与装得清品牌色 `#16A394` 不一致。→ 详见 §6.1、§6.6。

### 0.4 建议实施顺序

`P0 骨架 + 项目监管` → `P1 财务经营 + 组织效能` → `P2 业务分析 + 风险中心扩展`。详见 §16。

## 1. 文档定位与实现边界

### 1.1 这是哪个 Web 端？

原型标题为「装得清 · 企业经营管控中心」，顶栏标注「负责人视角」，一级导航 6 项（经营总览 / 业务分析 / 项目监管 / 财务经营 / 组织效能 / 风险中心）。

因此本稿定义的是：**装得清产品 Web 端（企业版）中，`Boss`（企业负责人）角色的经营管控中心**。

它与既有资产的关系：

| 已有资产 | 关系 |
| --- | --- |
| `前端代码/th4-decoboon-admin`（平台运营管理端） | **不同产品**：面向平台方跨企业运营，独立 `PlatformOrg/PlatformUser`。本稿不涉及。 |
| `前端代码/th4-decoboon-web`（**本端工作目录**，用户 2026-09-23 确认） | **本稿的实现目标工程**。该目录当前尚不存在，现有代码在 `前端代码/th4-decoboon-web【备份】`（Vue3+TS+Element Plus+ECharts6，主体为「装修获客」业务）。实施前需先把工程落到 `th4-decoboon-web`；旧获客页面按需保留。 |
| `前端代码/th4-decoboon-app`（微信小程序） | **口径与视觉同源**：同一后端、同一业务规则、同一品牌色；但交互形态不同（现场优先 vs 桌面盘点）。 |
| `后端代码/th4-decoboon`（Java 22 + Spring Boot 3.4 + th4 框架） | **唯一数据源**：Web 端只调 Provider / 通用模型服务，不自造业务逻辑。 |

### 1.2 硬边界

- **不做代码**：本稿只定义设计，实现由 development lane 承接。
- **不改口径**：任何与业务智能体知识库冲突处，只登记冲突与建议，不自行选择"更省事的版本"。
- **不新增角色**：角色固定 `Boss / StoreManager / Designer / Marketer / Pm / Finance / TeamLeader`。
- **不绕过报价链路**：所有金额类指标必须能追溯到 `Quote → ProjectContract → Project → Receivable/Payable` 主链。
- **不伪造完成态**：接口异常一律表达为「状态暂不可确认」，不得用 `0` 或空数组冒充最新事实（`rules.md` §13 / `LESSON-001`）。

### 1.3 本稿不解决的问题（明确排除）

- 其他 6 个角色的 Web 端页面设计（本稿只做 `Boss`）。
- Web 端的菜单配置后台（本端菜单为前端静态配置，无后台配置界面）。
- 移动端自适应成手机端（Web 端仅做桌面断点降级，不做手机版）。

## 2. 目标与成功标准

### 2.1 用户目标（企业负责人视角）

| 目标 | 对应原型能力 |
| --- | --- |
| 打开就知道**今天企业是否健康** | 顶栏风险预警条 + 经营总览 6 张 KPI |
| 知道**钱在哪、卡在哪** | 回款率、应收未收、账龄、现金流、逾期清单 |
| 知道**哪个项目要出事** | 项目监管：延期、毛利预警、风险分类、甘特排期 |
| 知道**谁在产出、谁在拖后腿** | 组织效能：设计师 / 销售 / 交付排行、协作链路耗时 |
| 知道**该处理什么、找谁处理** | 风险中心：分级、责任部门、责任人、时效、操作 |
| 能做**决策留痕与导出** | 导出简报 / 导出报表 / 导出绩效表 / 批量指派 |

### 2.2 成功标准（可验收）

1. 6 个一级页面全部可进入，且任一页面刷新后状态可恢复（筛选、分页、下钻返回）。
2. 所有金额、比率、天数与后端 Provider 返回值**完全一致**，前端不做二次计算（除展示格式化）。
3. 成本不完整项目在所有出现毛利的位置都显示「成本未完整」，**不出现 0% 或伪造数值**。
4. 接口失败时，受影响区块显示「状态暂不可确认 + 重试」，**不影响同页其他区块**。
5. 跨企业数据不可见：任何列表、聚合、导出、详情下钻均受服务端 `@DataPermission` 约束。
6. 任一区块可回答「这个数字从哪来」：指标卡可展开口径说明（公式 + 时间范围 + 数据截止时间）。

## 3. 场景推演（真实中小装企，先场景后设计）

> 按 `AGENTS.md` 强制要求：新功能定义实体、字段、页面、权限前必须先写清真实场景闭环。
> 目标企业画像（`DEC-001` 决策三）：合肥区域型 10–30 人、1–3 店的成长装企，年产值 800 万–5000 万，在施 3–15 个。

### 场景 A：周一早上盘点盘子（最高频，决定首页默认路径）

- **使用人**：企业负责人（老板），42 岁，习惯早上 8:30 用办公室大屏 / 笔记本看盘子。
- **触发事件**：周一上班，想在晨会前知道上周签了什么、钱收得怎么样、哪个工地要出事。
- **当前动作（无系统时）**：翻微信群、翻 Excel、逐个打电话问项目经理和财务，40 分钟凑一版口头结论。
- **系统下一步**：进入 `/boss/statistic/overview` → 顶部风险预警条直接列出 8 个客户超时未跟进等 7 类待办 → 6 张 KPI 给出月度盘子 → 「待处理风险」列表按等级排序 → 点任一行直接下钻到项目或应收详情。
- **异常处理**：
  - 若某指标数据源不可用（如应付查询失败），该 KPI 显示「状态暂不可确认」，其余 5 张正常展示，不整页报错。
  - 若本月尚无签约，KPI 显示「0 单 / 暂无数据」，不显示环比箭头（无对比基数时禁止展示 ±%）。
  - 若某项目成本不完整，首页「综合毛利率」必须标注「已排除 N 个成本未完整项目」，而不是把 null 当 0 摊平。

### 场景 B：发现工地要拖期，追责到人（高风险，决定项目监管交互）

- **使用人**：企业负责人 + 项目经理（授权后查看同一项目）。
- **触发事件**：接到业主投诉电话，说工地已经停工 3 天。
- **当前动作**：翻项目群找聊天记录，问项目经理，再找设计师确认变更是否已确认。
- **系统下一步**：进入 `/boss/project/supervision` → 切「有风险」分段 → 按「风险优先」排序找到该工地 → 卡片直接给出风险等级、风险原因、责任人（项目经理）、逾期天数、建议下一步（复用 `BusinessAlertType#nextAction()` 文案）→ 点开项目详情查阶段、验收轮次与整改清单。
- **异常处理**：
  - 风险原因无法映射到已定义 `BusinessAlertType` 时，显示「待业务确认」，操作按钮禁用但保留「查看原因」入口（`DEC-002` 冻结要求）。
  - 项目已 `Suspended`（停工）与 `Ongoing` 但逾期的语义必须区分，不能都叫「延期」。
  - 项目经理已离职或已转交时，责任人显示当前 `Project.manager`，并提示「原负责人已变更」。

### 场景 C：月底对账，回款最慢的客户先催（决定财务经营）

- **使用人**：企业负责人（兼财务，10–30 人装企常见）。
- **触发事件**：月底结账前，需要知道应收未收总额、逾期金额、账龄分布，并锁定先催哪几个客户。
- **当前动作**：翻收款登记表，按日期手工筛逾期，逐条微信催。
- **系统下一步**：进入 `/boss/finance/overview` → 「应收应付账龄」四段（0-30/31-60/61-90/90+）→ 点「90+」段直接下钻到应收明细列表 → 「催收」动作写跟进记录。
- **异常处理**：
  - 应收账龄按 `Receivable.dueDate` 与当前日期计算；`dueDate` 为空的历史数据归入「待确认账龄」单独一档，不并入 0-30 天。
  - 应付账款到期提醒按 `Payable.dueDate`，本周到期口径为「本周一 00:00 至本周日 23:59」。
  - 导出报表必须走服务端鉴权，导出内容与当前筛选一致。

### 场景 D：季度复盘，砍掉低效获客渠道（决定业务分析）

- **使用人**：企业负责人 + 市场/销售负责人。
- **触发事件**：季度经营会，发现线索不少但签不下来，要定位是渠道问题还是转化问题。
- **当前动作**：凭印象判断「线上留资质量差」，没有数据支撑。
- **系统下一步**：进入 `/boss/statistic/business` → 渠道表按签约转化率排序 → 结合漏斗（线索→到店→量房→报价→签约）定位流失环节。
- **异常处理**：
  - **获客成本字段当前无数据来源**（系统无投放费用采集），本场景默认不展示该列，详见 §10.3。
  - 报价环节的转化必须使用 `MET-001` 冻结的双指标，不能与「合同签约率」混算。
  - 渠道维度来自 `Customer.source`（枚举仅 6 值），原型里的「小区推广 / 异业合作」当前无对应枚举值，需先扩枚举或降级为「其他」，详见 §10.3。

## 4. 角色、权限与数据范围

### 4.1 角色定义

| 项 | 值 |
| --- | --- |
| 角色枚举 | `EmployeeRole.Boss`（企业负责人） |
| 数据范围 | `DataScopeType.Company` —— **本企业全部数据** |
| 登录 | 登录 Provider 继承 `Security`，当前员工由 `@User` 注入 |
| 企业归属 | 只能从登录员工加载 `company`，**禁止信任前端 `companyId`** |
| 门店筛选 | 前端可传 `storeId` 做视图筛选，**服务端必须校验该门店属于当前企业** |
| 菜单/路由来源 | **前端静态配置**（本端不做后端 `@Role`/`@View` 注册）；前端隐藏菜单**不构成权限**，接口鉴权仍全部在服务端 |

### 4.2 权限矩阵（本页范围内）

| 数据 | Boss | StoreManager | Designer / Marketer / Pm | Finance |
| --- | --- | --- | --- | --- |
| 经营总览 KPI | ✅ 全企业 | ❌ 本稿不含 | ❌ | ❌ |
| 项目监管全量 | ✅ | 仅本店 | 仅参与项目 | 仅参与项目 |
| 项目毛利 / 成本 | ✅ | ✅（本店） | ❌ 默认不可见 | ✅ |
| 组织效能（他人绩效） | ✅ | 本店 | 仅本人 | ❌ |
| 应收 / 应付明细 | ✅ | 本店 | ❌ | ✅ |
| 风险中心处置 | ✅ | 本店 | ❌ | ✅（财务类） |

> 说明：`CatalogItem.costPrice` 的可见性规则见 `AGENTS.md`「成本与利润口径」——企业负责人、店长、财务可见；设计师、业务员、项目经理默认不可见。本页作为负责人视角全量可见，但**不得把成本数据下沉到其他角色页面**。

### 4.3 服务端强权限落地要求

- 每个 Provider 必须继承 `Security` 且使用 `@User` 注入当前员工。
- 自定义详情 / 下钻必须使用 `DataScopeContext + DataScopeSpecification`，**禁止 `findById(id)` 后判断归属**。
- 列表、分页、计数由 `DataScopeRequestFilter` 依据 `CriteriaQueryAware + @DataPermission` 统一追加条件。
- 导出能力必须复用同一套数据范围条件，不得另写一套查询。
- 所有跨企业负向用例必须进入验收矩阵（§15）。

## 5. 信息架构（IA）

### 5.1 全局骨架（1:1 复刻原型）

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 顶栏 topbar  h=56  [Logo 装得清 企业版 | 负责人视角]  [搜索]  [导出简报][通知][头像] │
├─────────────────────────────────────────────────────────────────────┤
│ 风险预警条 risk-bar  h=42  ●风险预警 │ [8 个客户超时未跟进][3 份报价超 48h…]→ │
├───────┬─────────────────────────────────────────────────────────────┤
│ 左轨   │                                                             │
│ rail  │  主内容区 main（独立滚动，滚动条 8px）                        │
│ w=76  │  页面头 page-head + KPI 行 + 卡片网格 grid                    │
│ 6 项   │                                                             │
└───────┴─────────────────────────────────────────────────────────────┘
```

- 顶栏与风险条**固定不滚动**；主内容区独立滚动（原型 `body{overflow:hidden}` + `.main{overflow:auto}`）。
- 左轨 `position:sticky`，6 项 + 激活态左侧 3px 品牌色指示条。
- 页面切换为**前端路由切换**（真实实现），不是原型里的 `display:none` 切换。

### 5.2 一级导航与路由映射

| 序号 | 导航名 | 路由 path（前缀 `/boss`） | 组件文件 |
| --- | --- | --- | --- |

## 13. 性能与工程实现要点

| 项 | 要求 |
| --- | --- |
| 图表库 | ECharts 6 按需引入（`use` 注册 line/bar/pie 等模块），禁止全量 `import * as echarts` |

| 埋点 | 页面 PV、周期切换、下钻点击、导出次数、操作按钮点击（用于后续优化），埋点不得携带客户敏感信息 |

## 0. 结论摘要

1. 现有系统已经具备"材料计划行 + 采购单 + 到场验收 + 应付 + 供应商 + 成本"的骨架，但**没有"材料计划工作台"这个业务中枢**：计划行在签约立项时即被创建，与"选材确认"没有强绑定，也与"财务逐条下单"没有形成闭环。
2. 用户提出的核心诉求，本质是把现有的"计划行 → 采购单单行 → 到货才生成应付"链条，升级为：
   **选材确认/增减项确认 → 材料需求汇总 → 财务逐条下单（选供应商、选下单价、调数量）→ 确认下单 → 应付计划 → 到场确认（PM/设计师）**。
3. 主材与供应商的关联**必须落在材料业务域**，不能依赖 `CatalogItem`（报价项目库）。建议新增企业级"材料-供应商供应关系"实体，主键口径为 `(com_id, 材料标识, partner_id)`，材料标识由"目录项 + 品牌 + 规格/型号"归一化得到。
4. 一张采购单当前只能承载一条材料、一个供应商，无法支撑"财务按供应商合并下单 + 同一条材料拆多供应商"。建议引入**采购单明细行**，采购单头按供应商聚合。
5. **应付与成本口径已裁决（DEC-MP-01）**：应付在"确认下单"时形成；到货时回填账期起算日与实际到期日；**实际成本仍在到货/入库时才确认**。应付 ≠ 成本，两者不得混用。
6. 扣减项当前逻辑是"未采购才允许改数量"，无法处理"已下单/已到货后扣减"。按 DEC-MP-02，采用**负向调整计划 + 采购单调整 + 退货单**三段式；**已到货的扣减必须走退货单**，禁止用应付直接冲减。
7. **损耗（DEC-MP-04）**：瓷砖等材料必须支持采购损耗，详见 §4.5；损耗量计入下单数量与到货成本，现场领料/施工损耗只流转库存、不重复累计成本。

## 1. 现状盘点（代码事实）

### 1.1 已有对象与职责

| 对象 | 表 | 职责 | 关键事实 |
| --- | --- | --- | --- |
| `MaterialPlan` | `db_material_plan` | 项目级材料需求行 | 一合同行/一变更行生成一条；含 `quantity/unit/unitPrice/cost/requiredAt/arrivedAt/status` |
| `MaterialSelection` | `db_material_selection` | 签约后主材选材确认版本 | 文本化 + JSON 快照，客户确认后锁定；**明确不参与金额/成本/数量/采购计算** |
| `PurchaseOrder` | `db_purchase_order` | 材料采购单 | 头行一体：一个采购单只挂一条 `materialPlan`、一个供应商、一个数量单价 |
| `GoodsReceipt` | `db_goods_receipt` | 材料到场验收 | 到场后累计 `receivedQuantity`、更新计划状态、写 `unitPrice/cost` |
| `Partner` | `db_partner` | 合作方（供应商） | 有 `brands` 品牌集合、账期模式/天数/截账日 |
| `PartnerPrice` | `db_partner_price` | 合作方-目录项价格 | 按 `CatalogItem` 绑定采购价、交期、最小起订 |
| `Payable` | `db_finance_payable` | 应付款 | **当前只在到场验收时创建**，含 `payeePartner/dueDate/receiptDate/settlementMode` |
| `SupplierReturn`/`StockMovement` | `db_stock_movement` 等 | 退换货、库存流转 | 退换货按方向冲减，已有基础能力 |

### 1.2 现有链路（按代码顺序）

1. **签约立项**：`ProjectContext.appendMaterial(...)` 遍历报价 `Material` 行，直接生成 `MaterialPlan(status=Planned)`。
2. **变更确认**：客户确认后 `ContractChangeFulfillmentContext.applyMaterial(...)`：
   - `Add`/`Replace`：新建 `MaterialPlan`；
   - `Quantity`/`Price`：仅当计划状态属于 `Planned/Requested/Approved`（即未真正采购）时才允许直接改数量/单价；
   - `Remove`：关闭/取消原计划。
3. **选材**：设计师逐合同主材分项维护 `MaterialSelection` 文本，客户确认后 `status=Confirmed` 且不可原地修改，变更形成新版本。
4. **采购下单**：`project/purchase/save` 接收 `materialPlanId + supplierId + quantity + unitPrice`，把计划置为 `Requested`；`Boss/Finance` 直接自动审批为 `Approved`；`project/purchase/order` 置 `Ordered`。
5. **到场**：`goodsreceipts/save` 校验采购单已下单，累计到场数量，更新计划为 `PartiallyArrived/Arrived`，回写 `unitPrice/cost`，并**创建 `Payable`**（账期按供应商规则计算）。
6. **成本**：`rules.md` §10 明确"实际材料成本只在采购到货/入库时累计"。

### 1.3 与预期目标的差距（GAP 清单，详见 §15）

| 编号 | 差距 | 影响 |
| --- | --- | --- |
| GAP-MP-01 | 计划行在签约即生成，未与"选材确认"绑定，无"可下单"门禁 | 财务可能在选材未确认时下单 |
| GAP-MP-02 | 计划行不记录选材结果（品牌/规格/型号），采购只依赖合同行与目录项 | 下单时看不到实际选中的材料 |
| GAP-MP-03 | 主材-供应商关联只有 `Partner.brands` 粗粒度 + `CatalogItem` 级 `PartnerPrice` | 违背"不能通过报价项目库关联合作商" |
| GAP-MP-04 | 采购单头行一体，一单只能一条材料 | 无法按供应商合并下单，也无法一条材料拆多供应商 |
| GAP-MP-05 | 应付只在到场时生成 | 与"确认下单即形成应付计划"冲突 |
| GAP-MP-06 | 计划状态是单一枚举，无"部分下单"概念 | 部分下单/部分到场时状态失真 |
| GAP-MP-07 | 扣减项对已下单/已到货材料无处理路径 | 变更后采购与应付不同步 |
| GAP-MP-08 | 到场验收人未限定角色 | 与"PM/设计师确认到场"不符 |
| GAP-MP-09 | 无企业级材料计划工作台 | 财务跨项目下单缺少统一入口 |

## 2. 业务场景推演（强制：至少 2 个真实中小装企场景）

> 每个场景给出：使用人、触发事件、当前动作、系统下一步、异常处理。

### 场景 A：签约后设计师选材确认，财务逐条下单（主路径，最高频）

- **使用人**：设计师（选材）、客户（确认）、财务（下单）、项目经理（到场确认）。
- **触发事件**：合同签约完成，项目立项，项目进入主材准备阶段。
- **当前动作**：
  1. 设计师进入项目"主材选材"，对每条合同主材分项填写品牌/规格/型号/颜色/附件图片，提交客户确认；
  2. 客户在 App 或线下签字确认，`MaterialSelection.status=Confirmed`；
  3. 财务打开**材料计划工作台**，看到该项目所有"待下单"的材料需求（含选材结果快照）；
  4. 财务依次对每条材料：选择供应商 → 系统带出该供应商的最近采购价（可改）→ 确认数量（默认合同/选材数量，可微调）→ 确认下单；
  5. 系统按供应商归并生成采购单，并同步生成应付计划。
- **系统下一步**：材料计划行进入"已下单"；应付计划进入"待付款"；项目经理收到待到场提醒。
- **异常处理**：
  - 选材未确认时下单 → 直接拒绝并提示"该材料尚未完成客户选材确认"；
  - 无可用供应商价格 → 允许财务手工录入下单价并同时建立"材料-供应商供应关系"；
  - 数量与合同不一致 → 要求填写调整原因，保留调整前后快照。

### 场景 B：施工中业主加项主材，客户确认后进入下单

- **使用人**：项目经理/设计师（提出并录入）、客户（确认变更）、财务（下单）。
- **触发事件**：施工中业主追加主材（如增加一个卫生间的瓷砖、加装某品牌五金）。
- **当前动作**：项目经理在项目增减项中录入"新增/替换"主材项并提交 → 客户确认 → 系统生成新增 `MaterialPlan(sourceType=ChangeAdd)`。
- **系统下一步**：新计划行出现在材料计划工作台的"变更待下单"分组；财务与合同材料合并或单独下单。
- **异常处理**：
  - 变更未经客户确认 → 不进入待下单队列；
  - 新增材料需要新供应商 → 财务可现场新建供应商 + 供应关系，不阻塞下单。

### 场景 C：施工中业主减项，已下单材料需要冲减

- **使用人**：项目经理（发起减项）、客户（确认）、财务（执行冲减）。
- **触发事件**：业主取消某个空间的主材（如次卧不做木地板）。
- **当前动作**（本设计的关键新增）：
  1. 减项经客户确认后，系统生成**负向材料计划**（`sourceType=ChangeReduce`，数量为负或标记为冲减）；
  2. 系统判断原材料的采购状态：
     - **未下单**：直接下调原计划数量；
     - **已下单未到货**：生成采购单调整（减少原采购单明细数量），并同步减少应付计划金额；
     - **已到货**：生成退货单，冲减应付与已确认成本。
  3. 财务在工作台确认冲减结果。
- **系统下一步**：原计划数量、采购单、应付计划三者保持一致；项目成本按退货方向冲减。
- **异常处理**：
  - 供应商不同意退货 → 生成"待协商"异常态并保留原应付，人工处理；
  - 已付款部分 → 优先冲抵其他应付或转为供应商往来余额，不直接改已付款流水。

### 场景 D：一条主材拆给两个供应商

- **使用人**：财务。
- **触发事件**：某主材总需求 120㎡，A 供应商只有 80㎡现货。
- **当前动作**：财务对同一材料需求行分别向 A、B 两家下单，数量 80 + 40，单价分别录入。
- **系统下一步**：材料计划显示"部分下单→已下单"；两张采购单、两条应付计划；到场按各自采购单分别确认。
- **异常处理**：总量超过需求 → 系统按"已下单量 + 本次 > 需求数量"拦截或要求财务确认超订。

### 场景 E：材料到场，项目经理/设计师确认

- **使用人**：项目经理或设计师。
- **触发事件**：供应商直送工地或材料入仓。
- **当前动作**：PM/设计师在项目材料计划中点"到场确认"，填写到场数量、拍照、备注；系统校验必须是本项目 PM 或设计负责人。
- **系统下一步**：采购单与材料计划状态推进为"部分到场/已到场"；回填应收（应付）账期起算日与实际成本。
- **异常处理**：到场数量少于下单量 → 保持"部分到场"并保留尾量待送；与订单不符 → 拒绝确认并要求走差异记录。

### 场景 F（低频，按需展开）：材料入库后再领用

- **使用人**：财务（含履约协同）。
- **触发事件**：少数企业集中采购后按需领料。
- **当前动作**：采购交付方式选"入仓库"，到场后入库，再按项目领料。
- **系统下一步**：入库累计实际成本；领料、损耗只流转库存，**不重复累计成本**。
- **异常处理**：库存不足 → 阻断领料并提示在途数量。

## 3. 概念与对象边界澄清

| 概念 | 定义 | 关键边界 |
| --- | --- | --- |
| **材料需求行 / 材料计划行** | 项目内一条待落实的材料需求 | 来源两类：①合同选材确认 ②增减项主材。**不等于**采购单 |
| **选材确认** | 设计师对合同主材分项的最终选择，经客户确认后锁定版本 | 提供"选什么材料"的事实；**不直接产生金额与成本** |
| **材料-供应商供应关系** | 某企业某材料由某供应商供应的事实（含参考价、交期、账期） | **必须落在材料/供应链域**，不得建在报价项目库 |
| **采购单** | 财务对某供应商的正式下单凭证 | 按供应商聚合，含多条明细；确认下单即生效 |
| **采购单明细** | 采购单中的一条材料行 | 关联材料计划行，承载本次下单数量、单价、金额 |
| **应付计划** | 下单确认后形成的付款义务 | 与"实际成本"分离：应付在下单时形成，成本在到货时确认 |
| **到场确认** | PM/设计师对材料实际到场的验收 | 驱动部分到场/已到场与实际成本 |

**一句话区分**：选材回答"买什么"，供应关系回答"谁能供、大概多少钱"，材料计划回答"这条项目还差多少没落实"，采购单回答"这次向谁下、多少钱"，应付回答"欠谁多少钱"，到场确认回答"东西真的到了没有"。

## 4. 主流程与状态机

### 4.1 合同材料来源流程

```
合同签约立项
  → 按合同 Material 行生成材料计划行（status=Planned 待选材）
  → 设计师选材 → 提交客户确认
  → 客户确认（MaterialSelection.Confirmed）
  → 材料计划行派生为 ReadyToOrder（可下单）
  → 财务在材料计划工作台逐条下单（选供应商/选价/调数量）
  → 确认下单 → 采购单 + 应付计划
  → PM/设计师到场确认
  → 部分到场 / 已到场 → 回填实际成本与应付账期
```

### 4.2 增减项来源流程

```
增减项提交 → BOSS 审批 → 客户确认
  → 系统按变更行生成/调整材料计划行
     ├─ 加项 Add：新增材料计划行（sourceType=ChangeAdd）
     ├─ 替换 Replace：关闭原行 + 新增替换行
     ├─ 数量/价格 Quantity/Price：
     │    未下单 → 直接调整原行
     │    已下单 → 生成采购调整（改采购明细 + 改应付）
     └─ 减项 Remove：新增负向材料计划行（sourceType=ChangeReduce）
          ├─ 未下单 → 下调原行数量
          ├─ 已下单未到货 → 采购单调整 + 应付冲减
          └─ 已到货 → 退货单 + 应付冲减 + 成本回冲（强制走退货单，DEC-MP-02）
```

### 4.3 状态机

**材料计划行状态（建议重定义，含迁移映射）**

| 新状态 | 含义 | 进入条件 |
| --- | --- | --- |
| `Planned` | 待选材/待确认 | 合同立项生成，选材未确认 |
| `ReadyToOrder` | 可下单 | 选材客户确认 或 增减项客户确认 |
| `PartiallyOrdered` | 部分下单 | 已下单量 > 0 且 < 需求数量 |
| `Ordered` | 已下单 | 已下单量 ≥ 需求数量 |
| `PartiallyArrived` | 部分到场 | 已到场量 > 0 且 < 已下单量 |
| `Arrived` | 已到场 | 已到场量 ≥ 已下单量 |
| `Closed` | 已关闭 | 减项归零/人工关闭 |
| `Cancelled` | 已取消 | 变更取消且未产生采购事实 |

> 迁移建议：`Requested/Approved` 语义并入 `ReadyToOrder`（并保留历史数据只读），新增 `PartiallyOrdered`、`Cancelled`。

**采购单状态**（沿用）：`Draft → Submitted → Approved → Ordered → PartiallyReceived → Received`，异常 `Rejected/Cancelled/Closed`。财务/负责人下单可直接 `Ordered`。

**应付状态**（沿用）：`Pending → Partial → Paid`，逾期 `Overdue`，关闭 `Closed`。

### 4.4 状态派生规则（强制，遵循"可完成状态投影"）

- 材料计划行的 `orderedQuantity / receivedQuantity / remainingQuantity` **必须由采购单明细实时汇总派生**，禁止用人工布尔位或前端本地状态。
- 禁止在采购单 `save` 时把整条计划直接写成 `Ordered`（现有实现的问题），必须按累计下单量计算 `PartiallyOrdered/Ordered`。
- 页面重新进入、下拉刷新、跨页写入后必须重新读取，接口异常显示"状态暂不可确认"，不得用空数据伪装。

---

### 4.5 损耗设计（瓷砖等必损耗材料，DEC-MP-04）

材料损耗必须建模，且**区分两种损耗**，口径不能混：

| 类型 | 定义 | 是否计入成本 | 落点 |
| --- | --- | --- | --- |
| **采购损耗（备料损耗）** | 下单前按下单数量预留的损耗量，如瓷砖切割、排版、补砖 | **是**：随到货计入实际材料成本 | 材料计划行 `lossRate/lossQuantity`，进入下单数量 |
| **施工损耗（领料损耗）** | 到场后现场切割、破损登记 | **否**：只流转库存，不重复累计成本 | 复用 `supply/stock/loss` 现有能力 |

规则：

1. 材料需求数量 = **净用量 + 损耗量**：`quantity = netQuantity + lossQuantity`。
2. **损耗率来源 = 企业主材分类（DEC-MP-09）**：企业在"主材分类"上设置默认损耗率（如分类"瓷砖"），材料计划行按其主材分类继承；分类未设置时默认为 **0**，产品不预置行业比例。
3. 下单时财务可在损耗率基础上调整损耗量（如按整箱/整件取整），需留痕调整前后值。
4. 到场确认按**采购数量**累计实际成本；未送达的采购损耗仍保留在途。
5. 施工损耗登记（`supply/stock/loss`）只做库存流转，**不得再累加成本**（遵循 `rules.md` §10）。
6. 扣减时：**先冲减损耗量，再冲减净用量**，保证净用量优先。
7. 瓷砖等材料应支持"整箱/整件取整"提示，最终下单量仍以财务确认为准。
8. **下单量上限 = 需求数量（净用量 + 损耗量）**；超出即拦截并提示（DEC-MP-10）。确需多备料时，由财务先调整损耗量/损耗率再下单，**不另设"超订二次确认"**。

## 5. 材料计划工作台设计

### 5.1 定位

面向**财务（含履约协同）**的企业级工作台，同时服务 BOSS 总览、店长/团队负责人本范围查看、设计师/PM 项目内查看与到场确认。核心目标：把"选材确认后的材料"和"增减项主材"统一收口到一张可下单的清单。

### 5.2 信息架构

```
材料计划工作台
├── 顶部指标：待下单 / 部分下单 / 待到货 / 已延迟 / 异常
├── 视图切换
│   ├── 按项目（默认，符合"材料计划按项目单位进行"）
│   ├── 按供应商（准备下单视角）
│   └── 按材料汇总（同类材料跨项目合并，P1）
├── 待办分组
│   ├── 选材待确认（只读，指向设计师）
│   ├── 待下单（合同选材来源）
│   ├── 待下单（增减项来源）
│   ├── 在途（已下单待到货）
│   ├── 到场待确认（PM/设计师处理）
│   └── 异常（超期、超订、供应商无价格、退货待协商）
└── 下单抽屉/页
    ├── 材料信息（选材结果快照）
    ├── 选择供应商（按供应关系过滤 + 全部供应商兜底）
    ├── 选择下单价格（带出参考价，可改，留痕）
    ├── 确认调整数量（默认需求数量，可调，需原因）
    └── 确认下单（可多选后按供应商批量提交）
```

### 5.3 关键交互

1. **逐条下单**：每条材料默认独立确认；支持勾选多条后"按供应商合并下单"。
2. **供应商过滤**：优先展示"有该材料供应关系"的供应商，其次是"品牌匹配"的供应商，最后是全部有效供应商。
3. **下单价**：默认带出供应关系参考价；若手工改价，需记录来源（供应关系价/历史成交价/手工录入）。
4. **数量调整**：默认 = 需求数量 − 已下单数量；调整为非默认值时必须填原因，保存"调整前/后"快照。
5. **下单后**：即时形成应付计划并可在工作台直接跳转应付。
6. **到场确认**：PM/设计师在 App 项目内或工作台"到场待确认"中操作，需上传到场照片。

### 5.4 端侧建议

- **App（优先）**：财务移动下单、PM/设计师现场到场确认、BOSS 总览。
- **Web（P1）**：财务批量下单、跨项目对账视图。

## 6. 供应商选择与下单价格

### 6.1 供应商匹配规则（材料域，不依赖报价项目库）

> **DEC-MP-03**：供应商只能由**财务在下单时**决定；设计师只负责确认材料，不指定供应商；报价项目库不得承载主材-供应商关联。
>
> **DEC-MP-08**：**选材文本不参与供应关系匹配**。选材正文与 JSON 仅用于展示、导出和客户确认留痕，不得作为供应商匹配或采购计算的依据。

1. 材料标识归一化只使用**结构化字段**：`目录项(可空) + 品牌 + 规格/型号 + 单位`（不使用选材自由文本）。
2. 优先命中企业维护的"材料-供应商供应关系"；
3. 其次命中 `Partner.brands` 品牌匹配；
4. 最后允许选择全部有效供应商并手工录价（同时可选"建立供应关系"）。

### 6.2 供应关系维护

- 入口：供应商详情 / 材料计划下单时"维护供应关系"。
- 字段：企业、材料标识、供应商、采购价、最小起订量、交货天数、账期快照、生效/失效、启用状态。
- 唯一约束：`(com_id, 材料标识, partner_id)`。
- 与 `PartnerPrice` 的关系：`PartnerPrice` 继续服务"目录项级参考价与标准成本"，本设计新增的供应关系服务"选材后的具体材料级采购"，两者不互相替代。

### 6.3 下单价格口径

- **下单价**：本次采购的执行单价，作为采购单明细与应付金额的依据。
- **参考价**：优先供应关系价，其次 `PartnerPrice`，再次 `CatalogItem.costPrice`。
- **标准成本**：`CatalogItem.costPrice` 维持现有口径（由 Boss/店长/财务维护），签约时冻结合同成本快照。
- **实际成本**：只在到场/入库时确认，不得用下单价提前计入实际成本。

## 8. 金额、成本、应付口径

| 口径 | 定义 | 形成时点 | 备注 |
| --- | --- | --- | --- |
| 合同成本快照 | 签约时按 `CatalogItem.costPrice × 数量` 冻结 | 签约 | 不得被后续改动回溯 |
| 项目预计成本 | **以合同成本价为准**（签约合同行成本快照），不使用下单价 | 签约冻结 | DEC-MP-06；下单价只影响应付与实际成本 |
| 下单金额 | 采购单明细 `数量 × 下单价` | 确认下单 | 形成应付金额 |
| 应付 | 对供应商的资金义务 | **确认下单（DEC-MP-01）** | 下单即形成；`receiptDate/dueDate` 允许为空，到货回填 |
| 采购损耗 | `净用量 × 损耗率` 对应的数量 | 下单 | 随到货计入实际成本 |
| 实际材料成本 | 到场/入库实际发生值 | 到场/入库 | 退换货按方向冲减；施工损耗不再累加 |
| 利润 | 应收 − 成本 | 结算 | 任一应计成本缺失时 `costComplete=false`，利润 = `null` |

**关键约束**
- 应付 ≠ 成本：下单只产生应付，**不提前确认实际成本**（DEC-MP-01）。
- 预计成本口径：项目预计成本**一律取合同成本价（签约成本快照）**，与下单价无关（DEC-MP-06）；下单价只用于应付与实际成本。
- 到货回填：到场时回填 `receiptDate`，按供应商账期快照重算 `dueDate`；逾期仍按逾期口径。
- 损耗：采购损耗计入成本，施工/领料损耗只流转库存、不重复累计成本（DEC-MP-04）。
- 已到货扣减：必须走退货单再冲减应付与成本，禁止直接改应付（DEC-MP-02）。
- `costComplete=false` 时利润与毛利率必须为 `null`，前端显示"成本未完整"，禁止按 0 成本计算。
- 到场部分验收时，实际成本按实际到场数量累计。

- 成本字段：对 Designer/Marketer/Pm 一律过滤。
- 关联对象使用 `@AllowProperties` 最小白名单，禁止 `Property → Store → Team → Employee` 循环展开。
- 需求行 `status` 与派生数量必须由服务端计算，前端不得本地推断"已下单"。

## 12. 异常与边界

| 场景 | 处理 |
| --- | --- |
| 选材未确认就下单 | 拒绝，提示待客户确认 |
| 供应商无供应关系/无价格 | 允许手工录价并建立供应关系 |
| 下单量超过需求数量（净用量+损耗） | 直接拦截，提示先调整损耗量/损耗率（DEC-MP-10） |
| 部分下单/部分到场 | 状态为 Partially*，保留剩余可操作量 |
| 变更扣减已下单 | 采购调整 + 应付冲减 |
| 变更扣减已到货 | **必须走退货单** + 应付/成本回冲（DEC-MP-02），禁止直接改应付 |
| 供应商不同意退货 | 异常态"待协商"，保留原应付与在途 |
| 主材分类未设损耗率 | 继承为 0，提示财务手动录入损耗量 |
| 施工损耗登记 | 只流转库存，不重复累计成本 |
| 已付款后扣减 | 优先冲抵其他应付或转往来余额，不改历史付款 |
| 接口异常 | 显示"材料状态暂不可确认"，保留重试 |
| 重复下单/重复到场 | 幂等：按唯一键与数量校验，不重复计数 |

## 14. 分批实施建议

**P0（材料计划闭环，必须先做）**
1. `MaterialPlan` 增字段（含净用量/损耗率/损耗量）+ 状态重定义 + 迁移 51；
2. 选材确认 → 计划行 `ReadyToOrder` 门禁；
3. `MaterialSupplier` 供应关系 + 匹配 Provider；
4. `PurchaseOrderItem` 明细行，采购单按供应商聚合；
5. 财务材料计划工作台（按项目、待下单分组、逐条/批量下单）；
6. **确认下单形成应付**（DEC-MP-01）；
7. **损耗量进入下单数量与到货成本**（DEC-MP-04）；
8. 到场确认限 PM/设计师 + 账期起算日回填。

**P1（增减项与扣减）**
1. 减项负向计划（先冲损耗、再冲净用量）；
2. 已下单采购调整 + 应付冲减；
3. **已到货强制走退货单** + 应付/成本冲减（DEC-MP-02）；
4. 部分下单/部分到场状态与派生数量；
5. 超订/无价格/待协商异常态；
6. 瓷砖类整箱/整件取整提示。

**P2（效率与对账）**
1. 按材料跨项目汇总采购；
2. 供应商对账单联动；
3. 主材档案 `MaterialSpec` 归一化；
4. Web 端财务批量下单与对账视图；
5. 材料计划头-行方案评估。

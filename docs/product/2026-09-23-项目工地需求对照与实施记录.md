## 1. 本次实现细节（#2 施工任务操作权限）

| 项 | 口径 |
| --- | --- |
| 可操作角色 | 企业负责人（Boss）、店长（StoreManager）、项目经理（Pm） |
| 数据范围 | 店长受 `DataScopeType.Store` 约束：只能操作本门店项目的任务；跨门店一律 404（不泄露对象存在性） |
| 覆盖动作 | `project/task/update`（Todo→Doing→Accepting→Done 推进与证据提交）、`project/task-node/save`（施工进行/隐蔽工程/施工完成留证） |
| 未覆盖 | 阶段开工 `project/stage/update` 仍为 Boss/PM（**待确认是否同样开放给店长**） |
| 错误语义 | 非上述角色 → `403 只有企业负责人、店长或项目经理可以推进施工任务 / 确认施工节点` |

## 5. 验收建议

1. 店长账号登录后打开本门店工地：可推进任务、可做节点留证；打开非本门店工地应不可见。
2. 项目完工（`Finished`）与结算（`Settled`）后，工地增减项入口应给出明确阻断提示，且不产生变更单。
3. 成员切换：按 Q-A 裁决后补充「切换后旧负责人失去项目可见性、新负责人立即可见」的正/反向用例。
4. 计划口径：按 Q-D 裁决后补「排期反推计划 + 项目经理调整」的用例，并覆盖与合同施工计划快照的一致性。

### 6.3 仍需注意

1. 「以排期为准」在**排期任务发生变化时**生效（任务新增/修改/删除触发）；项目经理手工改项目开完工日期属于人工调整，下次排期变更会重新以排期覆盖。
2. 无排期任务的阶段仍沿用合同施工计划快照窗口（否则会出现空窗口）；如需「无任务阶段也折算工期」请另行裁决。
3. 成员切换动态为**对内动态**（`visibleToCustomer=false`），业主不可见；如需对业主公开请明确。

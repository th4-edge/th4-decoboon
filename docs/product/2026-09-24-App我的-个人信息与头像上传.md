# App「我的」· 个人信息与头像上传

```text
批次 ID: APP-PROFILE-20260924
模式: feature_iteration（账号资料）
当前状态: 已实现，待独立验收
事实来源: 工程代码 / OBJ-003 同源权限思路（头像属非敏感身份信息）/ 用户口径（2026-09-24）
主链范围: 我的 tab → 个人信息 → 头像与姓名修改
```

## 1. 业务问题

「我的」tab 原来只有一张只读名片（头像、姓名、岗位、手机号），员工无法自行修改头像和姓名；
头像来源是微信 `getUserProfile` 返回的第三方 CDN 地址，在多数新基础库下只会拿到默认灰色头像，
成员列表、项目成员和动态卡片里员工形象不可控。

## 2. 目标

1. 所有角色在「我的」都能进入统一的「个人信息」页（业主同样可见，但只读）。
2. 员工可上传头像（相册/相机）并修改姓名，保存后 App 内所有出现处即时生效。
3. 手机号、岗位、企业、门店、团队属于账号与组织事实，不在个人资料页修改。

## 3. 可编辑边界

| 字段 | 员工 | 业主 | 说明 |
| --- | --- | --- | --- |
| 头像 | 可上传 | 只读 | 员工头像写入阿里云 OSS 私有对象，通过后端公开代理供同事长期展示 |
| 姓名 | 可改（≤15 字） | 只读 | 后端 `user/user/update` 既有能力 |
| 手机号 | 只读 | 只读 | 绑定微信/账号，由认证通道维护 |
| 岗位 / 企业 / 门店 / 团队 | 只读 | — | 组织归属由企业负责人维护 |

## 4. 实现

### 4.1 App

- `pages/mine/index.vue`：名片改为可点击入口，补「查看与编辑个人信息」与右箭头；账号分组新增「个人信息」入口。
- `subpackages/account/pages/profile.vue`（新）：自定义导航 + 返回；头像卡（`open-type="chooseAvatar"`）+ 基本资料 + 组织归属只读 + 固定保存栏。
- `domains/identity/api.ts`：`updateProfile`（姓名/头像地址）与 `uploadAvatar`（multipart 上传），并把服务端返回的相对头像路径补成绝对地址。
- `domains/identity/session.ts`：`updateEmployeeProfile` 同步本地会话并持久化，保存后无需重新登录。

### 4.2 后端

- `tenant/user/service/user/user/update`：通过 `@AutoFile StreamFile avatar` 接收 multipart 头像文件；
  非空 `avatarUrl` 禁止客户端直填，显式空串表示恢复默认头像，未携带（null）保持原值。
- `tenant/user/context/AvatarContext`：校验类型（JPG/PNG/WebP）与大小（≤2MB），
  以 `avatar/{comId}/{empId}-{uuid}.{ext}` 写入阿里云 OSS 私有对象；返回 `/file/private/download?path=avatar%2F...` 稳定业务域名地址。
- `file/private/download`：对严格匹配 `avatar/{comId}/{empId}-{uuid}.{ext}` 的对象键免签名读取；其他文件仍必须通过短期签名和数据权限校验。
- `AliyunObjectStorage` / `ObjectStorage`：保持私有对象存储能力；本地 provider 继续使用 `TH4_FILE_PUBLIC_DIR` 做开发兼容。

### 4.3 为什么不用私有文件通道

私有业务文件签名有效期被强制限制在 1 小时内（`FileSignatureContext` 上限 3600 秒），
无法作为长期头像地址；头像又需要在成员/项目/动态列表被同事直接渲染。
生产 OSS 可能通过组织策略禁止对象级公共 ACL。因此头像写入私有 OSS，再由后端代理输出稳定地址，不依赖 `PutObjectAcl`；文件名由服务端 UUID 生成，不接受客户端路径。

## 5. 验收标准（待 acceptance）

1. 员工在「我的」点击名片进入个人信息页，可更换头像并修改姓名。
2. 上传非图片 / 超过 2MB 文件被拒绝并给出提示；文件名不可被客户端控制。
3. 保存后「我的」、成员列表、项目成员、动态卡片展示新头像（无需重新登录）。
4. 业主进入个人信息页为只读，无上传与保存入口。
5. 跨企业、未登录、越权调用 `user/user/update` 被拒绝。
6. 生产 `TH4_STORAGE_PROVIDER=oss`，头像对象路径为 `avatar/{comId}/`、对象保持私有，`/file/private/download?path=avatar%2F...` 稳定地址在发版和小程序重启后持续可访问。

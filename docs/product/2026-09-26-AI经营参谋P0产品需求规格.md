## 0. 结论摘要

### 0.1 本批次要做什么

在 Web 企业负责人经营总览新增一块 `AI 经营简报`，基于现有经营驾驶舱、财务汇总、经营预警和项目经营聚合，生成：

1. 一句话经营现状；
2. 业务、交付、资金三类关键事实；
3. 最多三条需要老板关注的风险及原因；
4. 成本不完整时的明确提示；
5. 每条风险的来源和下钻入口。

AI 只读、只做解释和建议，不修改金额、合同、项目、验收、收付款和风险处置。

### 0.2 为什么先做这个

- 数据来源已有，不需要先重构客户、报价和项目主链；
- BOSS 是跨对象经营判断角色，最适合验证 AI 是否真正减少盘点时间；
- 首版只读，不触碰状态机和金额写入，风险最低；
- 可为后续谈单、客户风险、回款和项目 AI 验证统一 AI 卡、来源和用量机制。

### 0.3 不在本批次

- 不做自由问答；
- 不做自动生成日报/周报并推送；
- 不做自动指派、催收、改价、调整项目状态；
- 不做跨门店预测和人员绩效判断；
- 不做自动归因结论；
- 不做净利润、行业对标或预测收入；
- 不新增经营公式，所有数值沿用现有 Provider。

## 1. 真实业务场景

### 场景一：老板周一早上盘点经营盘子

| 维度 | 内容 |
| --- | --- |
| 使用人 | 企业负责人 |
| 触发事件 | 周一早上打开 Web 经营总览，需要知道上周到现在的签约、回款、项目和风险 |
| 前置条件 | 当前身份为 BOSS；经营驾驶舱、财务汇总和经营预警至少有一个可用 |
| 当前动作 | 依次查看五张 KPI、财务健康度、风险列表，再自己判断先处理哪个 |
| 系统动作 | 生成 AI 经营简报，聚焦业务、交付、资金三类事实和最多三条行动建议 |
| 下一步 | BOSS 点击来源查看依据，或进入风险中心、财务、项目监管处理 |
| 异常 | 某数据源失败时，简报明确显示“该部分暂不可确认”，不用空值或 0 补齐 |

### 场景二：老板发现项目毛利润不可用

| 维度 | 内容 |
| --- | --- |
| 使用人 | 企业负责人 |
| 触发事件 | 经营总览显示项目毛利润不可用，但老板不知道哪个项目或哪类成本缺失 |
| 前置条件 | `BossDashboard.grossProfit.complete=false` 或 `FinanceSummary.costComplete=false` |
| 当前动作 | 让财务逐个项目排查，反复确认到底缺材料、人工、费用还是采购到货数据 |
| 系统动作 | 简报说明“成本未完整，暂不展示可靠毛利”，并列出存在成本缺口的项目数和可下钻入口 |
| 下一步 | BOSS 进入项目财务或成本缺口清单，由责任角色补齐 |
| 异常 | 无权限、无项目或数据源失败时，不能生成具体项目责任结论 |

## 2. 目标与非目标

### 2.1 目标

1. 让 BOSS 在经营总览首屏就知道当前最重要的三件事。
2. 把 KPI、财务和风险从“数字列表”变成“事实 + 原因 + 下一步”。
3. 所有 AI 结论能追溯到现有业务对象和原有 Provider。
4. 成本不完整时不产生伪毛利、伪因果或伪责任。
5. 为后续 AI 经营简报、风险代理和经营问答建立可复用契约。

### 2.2 非目标

- 不改变 `MET-001` 报价接受率、`MET-002` 项目毛利和现有财务口径。
- 不使用 AI 重新计算指标。
- 不生成净利润、预测利润、行业均值或目标完成概率。
- 不把 KPI 的高低直接解释为员工或个人责任。
- 不自动执行风险处置、付款、催收、指派和状态变化。
- 不将客户、项目或金额信息公开到其他角色和租户。

## 3. 用户与权限

### 3.1 P0 适用角色

P0 仅面向当前企业 BOSS。

| 角色 | 可见 | 可生成 | 可查看来源 | 可下钻 | 可处置 |
| --- | --- | --- | --- | --- | --- |
| BOSS | 是 | 是 | 是 | 是 | 只能进入已有业务页面 |
| 店长/团队负责人 | 否 | 否 | 否 | 否 | 后续批次评估 |
| 财务 | 否 | 否 | 否 | 否 | 使用财务页面 |
| 其他员工 | 否 | 否 | 否 | 否 | 无 |
| 业主 | 无入口 | 否 | 否 | 否 | 无 |

### 3.2 服务端权限要求

- 企业只从登录员工加载；
- 禁止信任前端传入 `companyId`、`empId` 或任意范围；
- AI 上下文只取当前企业 BOSS 有权读取的 Provider 结果；
- 每个来源对象在应用前再次校验企业范围和对象存在性；
- 跨企业、无权限和对象不存在统一返回不可见，不泄露信息。

## 4. 页面与信息架构

### 4.1 页面位置

页面：`/boss/statistic/overview`

建议结构：

```text
PageHead
-> 5 个经营 KPI
-> 成本未完整提示（已存在）
-> AI 经营简报（本批次新增）
-> 财务健康度 / 待处理风险（已存在）
```

AI 经营简报位于 KPI 和两个明细卡之间，作为“先看结论，再看明细”的过渡层。

### 4.2 首屏结构

```text
┌──────────────────────────────────────────────────────┐
│ AI 经营简报                更新于 MM-DD HH:mm          │
│ [生成简报 / 更新简报]                                │
│                                                      │
│ 一句话：本月签约额较上月增长/下降，主要风险集中在…… │
│                                                      │
│ 业务  │ 交付 │ 资金                                 │
│ 事实  │ 事实 │ 事实                                 │
│                                                      │
│ 今天建议关注：                                       │
│ 1. 风险标题 + 原因 + 责任人 + [去处理]               │
│ 2. 风险标题 + 原因 + 责任人 + [去处理]               │
│ 3. 风险标题 + 原因 + 责任人 + [去处理]               │
│                                                      │
│ [查看全部依据] [重新生成]                            │
└──────────────────────────────────────────────────────┘
```

### 4.3 三列展示

| 列 | 主要事实 | 数据来源 |
| --- | --- | --- |
| 业务 | 本月签约、环比、目标达成、在建项目 | `BossDashboard` |
| 交付 | 停工/交付风险数、高风险项目、到期项目 | `BusinessAlertReport`、`ProjectOverviewReport` |
| 资金 | 本月回款、回款率、应收未收、逾期金额 | `BossDashboard`、`FinanceSummary` |

### 4.4 行动建议区

最多三条，不强制凑满三条。

排序原则：

1. 严重风险优先；
2. 同级按到期日优先；
3. 无到期日按金额影响优先；
4. 金额相等按发现时间优先；
5. AI 不得用客户姓名、员工姓名制造羞辱性表达。

每条建议包含：

- 风险标题；
- 一句原因或现状解释；
- 业务对象；
- 责任人；
- 到期或逾期信息；
- 主按钮 `去处理`；
- 次按钮 `查看依据`。

### 4.5 来源抽屉

来源抽屉展示：

- 数据截止时间；
- 使用的 Provider 和数据对象；
- KPI 口径；
- 风险触发依据；
- 成本完整性状态；
- 生成时间、能力和版本；
- 未使用的数据或无法确认项。

来源必须展示“数据更新至”，不能只显示 AI 生成时间。

## 5. 功能需求

### F1：生成 AI 经营简报

| 项目 | 要求 |
| --- | --- |
| 入口 | 经营总览内 AI 卡 |
| 触发 | BOSS 手动点击 `生成简报`；P0 不自动后台生成 |
| 前置 | 至少一个核心数据源成功，当前身份为 BOSS |
| 输出 | 一句话摘要、业务/交付/资金三列、最多三条行动建议、成本状态 |
| 成功状态 | 显示内容和数据截止时间 |
| 失败状态 | 保留原经营总览，提供重试，不阻断手工查看 |
| 重复点击 | 生成中禁用；不产生重复任务和重复扣费 |
| 有效期 | 绑定数据截止时间和生成版本；依据变化后标记需更新 |
| 用量显示 | 生成前显示预计消耗，生成后显示实际点数和资源包扣减；企业公共不默认归总店 |

### F2：风险解释与建议

| 项目 | 要求 |
| --- | --- |
| 风险来源 | 仅使用现有四类经营预警和项目聚合风险 |
| 风险分类 | 业务、交付、资金三类；每类最多取一条进入前三 |
| 解释范围 | 只能解释现有事实，不推断人员责任和真实原因 |
| 建议动作 | 使用 `BusinessAlertType.nextAction()` 或已有业务页面动作 |
| 责任人 | 仅显示 Provider 已返回的责任人；无责任人显示“待确认” |
| 金额 | 只显示 Provider 返回金额；不生成预测金额 |
| 过期风险 | 来源日期变化后旧风险说明标记 `依据已变化` |

### F3：成本完整性诊断

| 项目 | 要求 |
| --- | --- |
| 触发 | `costComplete=false` 或 `grossProfit.complete=false` |
| 输出 | 成本未完整数量、影响的项目范围、需补类型入口 |
| 禁止 | 不用 0 成本、估算成本或行业比例计算毛利 |
| 行动 | 提供进入项目监管/财务页面的入口 |
| 文案 | 统一使用 `成本未完整，暂不展示可靠毛利` |

### F4：来源与审计

| 项目 | 要求 |
| --- | --- |
| 来源 | 记录 Provider、对象类型、对象 ID、版本和更新时间 |
| 生成 | 记录生成时间、能力版本、模型版本和触发员工 |
| 动作 | 记录查看、下钻、忽略和重新生成 |
| 数据 | 不记录不必要的客户电话、地址和附件内容 |
| 企业归属 | 每次调用记录企业，作为唯一收费主体 |
| 门店归属 | 记录业务门店、执行门店、分摊门店和归属原因；无法归属时进入企业公共 |
| 幂等结算 | 同一简报动作重复点击、网络重试和回调只形成一次有效调用与一次有效扣点 |
| 保留 | 是否持久化、保留多久和删除规则待 T06 |

### F5：下钻动作

| 行动 | 目标 |
| --- | --- |
| 查看资金风险 | `/boss/finance/overview` |
| 查看项目风险 | `/boss/project/supervision` |
| 查看全部风险 | `/boss/statistic/risk` |
| 查看业务分析 | `/boss/statistic/business` |
| 查看项目详情 | 项目监管对应项目，带 `projectId` |
| 查看应收详情 | 财务页对应应收，带 `receivableId` 或项目 ID |

跨页跳转必须携带业务 ID，禁止退回列表取第一条。

### F6：AI 用量归属

| 项目 | 要求 |
| --- | --- |
| 企业维度 | 生成经营简报属于企业级能力，必须先记录企业资源账户和调用记录 |
| 门店维度 | BOSS 未选择具体门店时归入“企业公共”，不得静默归到默认总店 |
| 业务对象 | 如果简报某个结论下钻到具体项目/门店，调用本身仍按企业级经营简报统计，不重复归属到每个业务对象 |
| 计费单位 | 调用次数与计费点数分开，点数按费率版本结算 |
| 失败重试 | 失败、超时、额度不足和重复点击不得重复扣点 |
| 展示 | 简报卡显示本次预计/实际消耗；企业资源总量和门店分布在其他资源报表查看 |

## 6. 数据输入与映射

### 6.1 输入数据源

| 数据源 | 当前能力 | 使用字段 | 准备度 |
| --- | --- | --- | --- |
| `statistic/boss/dashboard` | 已存在 | 签约、回款、毛利、在建项目 | A |
| `finance/summary/report` | 已存在 | 应收、逾期、成本完整度、紧急应收应付 | A |
| `statistic/alert/report` | 已存在 | 四类风险、级别、责任人、到期日 | A |
| `project/project/overview` | 已存在 | 项目状态、风险、阶段和进度 | B：页面当前未加载，需增加聚合调用 |
| 风险处置读侧 | 已存在 | riskId、处置状态、责任人 | B：P0 可只下钻暂不嵌入 |
| 报价接受率 | 现有报表口径需按 `MET-001` 核实 | 暂不使用 | C：不使用 |
| 组织绩效 | 现有报表 | 暂不使用 | C：本批次不判断员工 |
| 净利润 | 无可靠口径 | 不使用 | C：禁止 |

### 6.2 输入上下文包

给 AI 的数据只包含：

- 统计月份和门店范围；
- 五项 KPI 的当前值、上期值、目标、完整状态；
- 财务汇总的成本完整度、应收、逾期和紧急收付数量；
- 四类风险；
- 项目状态和风险摘要；
- 数据更新时间；
- 当前员工角色和企业范围。

不传入：

- 客户电话和地址；
- 合同正文；
- 供应商价格明细；
- 员工个人绩效判断；
- 无权限的财务明细和成本明细。

### 6.3 AI 输出逻辑

AI 只负责：

- 把确定性事实转成简洁表达；
- 按风险级别和时效排序；
- 用已有 `nextAction` 生成建议；
- 明确数据缺失和无法确认项；
- 生成用户可读的原因说明。

AI 不负责：

- 重新计算指标；
- 创建风险；
- 判断谁应被追责；
- 预测未来金额；
- 判断项目是否一定能完成。

## 7. 输出逻辑与文案规则

### 7.1 一句话摘要

必须包含：

- 统计周期；
- 至少一个确定性事实；
- 一个主要风险方向；
- 数据截止时间。

示例结构：

> 本月签约额为 X 万，较上月变化 Y%；当前主要关注点集中在逾期应收和 2 个交付风险项目，数据更新至 MM-DD。

不得生成：

> 本月经营很差，所以一定是业务员跟进不足。

### 7.2 事实表达

| 事实 | 表达 |
| --- | --- |
| 增长 | “较上月增长 X%” |
| 下降 | “较上月下降 X%” |
| 无目标 | “未设置目标” |
| 无上期数据 | “暂无可比上期” |
| 成本不完整 | “成本未完整，暂不展示可靠毛利” |
| 数据源失败 | “该部分暂不可确认” |
| 无风险 | “当前未发现已接入的预警” |

### 7.3 风险表达

AI 说明只能使用：

```text
事实：...
风险：...
建议：...
责任：...
```

不得使用：

```text
一定因为...
必然是...
责任完全在...
说明该员工...
```

### 7.4 禁止生成

- 净利润；
- 未来收入预测；
- 客户流失概率；
- 员工能力结论；
- 无证据的项目质量结论；
- 无授权客户案例；
- 承诺性服务内容；
- 行业平均对比。

## 8. 交互状态

| 状态 | 页面表现 | 可用动作 |
| --- | --- | --- |
| 功能关闭 | 不显示 AI 卡 | 无 |
| 待生成 | 显示数据截止时间和生成按钮 | 生成 |
| 生成中 | 显示进度状态，不阻塞其他页面 | 离开、返回 |
| 已生成 | 显示摘要、三列事实、行动建议 | 查看依据、下钻、更新 |
| 部分数据缺失 | 对应列显示“暂不可确认” | 重试、查看已有数据 |
| 依据已变化 | 显示 `简报依据已变化` | 更新简报 |
| 额度不足 | 说明消耗和剩余 | 购买、稍后 |
| 生成失败 | 保留页面和原数据 | 重试 |
| 无数据 | 说明尚未形成可分析经营事实 | 返回业务页面 |

## 9. 异常与恢复

| 异常 | 处理 |
| --- | --- |
| 驾驶舱接口失败 | 简报不显示经营指标结论，提示暂不可确认 |
| 财务接口失败 | 不生成资金结论，可生成业务/交付摘要，并明确缺失 |
| 风险接口失败 | 不生成行动建议，仅显示确定性 KPI |
| 项目接口失败 | 不生成项目交付解释，保留已有风险列表 |
| 成本不完整 | 毛利置空，显示成本完整度提示 |
| AI 超时 | 保留原页面，可重试，不重复计费 |
| AI 返回非法金额 | 前端不显示该金额，并记录异常 |
| 来源对象已变化 | 标记依据已变化，不继续使用旧建议 |
| 无权限 | 服务端返回不可见，不提示对象存在 |

## 12. 研发边界

### 12.1 前端

- 经营总览增加 AI 卡；
- 不改变 KPI、财务和风险卡的现有口径；
- 不把 AI 文案当作数据计算源；
- 来源和下钻必须使用真实业务 ID；
- 功能开关关闭时页面与现状一致。

### 12.2 后端

- 产品不冻结 Provider 路由和最终实体；
- 研发设计前先取得 T06，确定 AI 任务、建议、缓存、用量和应用记录；
- 上下文必须由服务端按权限构建；
- 不能在 Controller 或前端拼接企业权限上下文；
- 来源、金额和风险必须引用现有业务事实；
- 每次 AI 调用必须写入企业、门店归属、能力、资源单位、计费点数、状态和幂等键；
- 企业是收费主体，门店是统计分摊维度，经营简报未指定门店时归企业公共；
- AI 失败不得影响经营总览原接口。

### 12.3 AI 服务

- 模型输出必须是结构化字段，不接受一段自由文本直接渲染；
- 输出字段必须限量、限长度、可校验；
- 金额和 ID 由系统注入，不由模型自由生成；
- 模型不可用时可降级为规则摘要或纯页面展示；
- 模型调用和用量必须审计。

## 14. 观测指标

P0 仅内部观测，不对外宣传。

| 指标 | 定义 |
| --- | --- |
| 简报生成成功率 | 成功生成 / 有效生成请求 |
| 简报查看率 | 查看简报的 BOSS / 进入经营总览的 BOSS |
| 来源展开率 | 展开来源的简报 / 已查看简报 |
| 建议下钻率 | 下钻业务页面的建议 / 已展示建议 |
| 依据过期率 | 标记依据变化的简报 / 已生成简报 |
| 异常率 | 超时、非法金额、无依据归因 / 总生成 |
| 平均生成成本 | 模型和推理成本 / 成功生成 |

不把“生成次数”“点击次数”单独作为经营价值结论。

## 17. 结论

AI 经营参谋 P0 应先在现有经营总览上做一个可靠的“只读经营简报”，通过真实 KPI、财务和风险数据验证三件事：

1. BOSS 是否能更快找到重要问题；
2. AI 是否能正确引用业务事实且不制造伪结论；
3. 来源、权限、缓存、用量和异常机制是否可复用。

其中用量必须同时形成企业总账和门店归属，验证：

1. 企业能看到总消耗和资源包余额；
2. 门店能看到本店分摊，不重复计费；
3. 失败、重复和返还能够对账。

只有这些条件验证后，才进入自动提醒、风险处置代理、自然语言经营问答和更复杂的经营预测。

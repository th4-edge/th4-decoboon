## 0. 执行结论

P0.4 新增一个小程序页面 `/subpackages/design/pages/ai-generation`，将 AI 设计生成串成以下闭环：

```text
设计列表 / 方案详情
-> AI 效果图生成
-> 生成前条件检查
-> 发起生成（后端同时构建上下文和 Prompt 快照）
-> PromptReady / Generating 状态等待
-> DraftReady 效果图版本查看和对比
-> 设计师确认“方案封面”或“区域图片”
-> 回写 Design.coverUrl 或 Space.images
-> 只有已确认版本可作为未来正式 HTML/PDF 的输入
```

P0.4 必须成立的产品结论：

1. 设计生成入口只对可写设计方案的 BOSS、店长、团队负责人、设计师显示；后端仍是最终权限边界。
2. 没有 CAD/户型图时不得发起生成；已有 CAD 但缺少量房或区域时，只能进入明确标识的“概念探索”，不得伪装成精准共创。
3. 设计师看到的上下文必须来自后端冻结的 `contextSnapshot`，Prompt 必须来自 `promptSnapshot`，不得由前端拼接或猜测。
4. `DraftReady` 只是待筛选草稿，不得称为正式设计；`DesignerConfirmed + render.deliverable=true` 才可作为正式交付输入。
5. 当前 P0.1-P0.3 没有正式 HTML/PDF 生成 Provider。App 必须显示“正式方案文档能力尚未开放”，不得放置可用的正式 HTML/PDF 交付按钮。
6. 当前 `design/generation/info`、`update` 会向 App 返回成本、模型参数、用量、原始模型请求号和原始失败信息；这些字段必须在 development 实施 P0.4 前从对外响应裁剪，不能只靠 App 隐藏。
7. 当前 `info/page` 只有数据范围校验，没有复用 `requireDesignWriteAccess`。P0.4 上线前必须收口为与入口一致的设计写角色可读，避免 Prompt 和内部参数被其他角色直连读取。
8. `TalkBrief` 只面向设计师内部使用；BOSS、店长、团队负责人即使可查看任务和 VisualBrief/DocumentBrief，也不得取得或向业主展示 TalkBrief。
9. 本规格不设计 DTO、VO 或 Request 包装结构；Provider 继续使用 `DesignGenerationTask`、`DesignContextSnapshot`、`DesignPromptSnapshot`、`DesignRenderVersion` 等领域实体和 Provider 成员字段。

## 1. 真实业务场景

### 场景 A：单店设计师完成精准共创

| 项目 | 内容 |
| --- | --- |
| 使用人 | 12 人单店装企设计师 |
| 触发事件 | 客户完成量房，设计师已上传 CAD 并录入区域尺寸和主要诉求 |
| 当前动作 | 从方案详情点击“AI 效果图生成”，确认上下文摘要，发起精准共创 |
| 系统下一步 | 展示客户画像、量房、区域和诉求摘要；等待 Seedream 返回；提供版本查看和确认 |
| 异常处理 | 模型限流时显示可恢复提示；确认前不能进入正式交付；CAD 丢失时回到方案页重新上传 |
| 业务结果 | 设计师不再手工整理一次性提示词；确认图回写方案封面或对应区域 |

### 场景 B：6 人轻团队先看方向

| 项目 | 内容 |
| --- | --- |
| 使用人 | 兼任设计、业务和项目经理的轻团队设计师 |
| 触发事件 | 客户只有户型图片和零散诉求，量房记录或区域尺寸尚未补齐 |
| 当前动作 | 进入 AI 生成页，系统提示缺少量房或区域，只能使用概念探索 |
| 系统下一步 | 展示缺失字段和冲突，不自动补造尺寸、材料或金额；生成后明确标记“AI 概念效果” |
| 异常处理 | 设计师确认概念方向前不得作为正式设计方案或客户正式交付物 |
| 业务结果 | 先完成客户方向沟通，再回补量房事实进入精准共创 |

### 场景 C：多店设计师遇到模型失败

| 项目 | 内容 |
| --- | --- |
| 使用人 | 26 人、3 店装企设计师 |
| 触发事件 | 任务进入 `Failed`，原因是模型未配置、凭证无效、限流、服务不可用或返回无图片 |
| 当前动作 | 查看失败原因，等待后重新生成或联系管理员 |
| 系统下一步 | 将失败码映射为业务可理解文案；失败任务不自动复用；重新生成创建新任务 |
| 异常处理 | 跨门店、跨企业或伪造任务号访问不得返回任务、上下文、Prompt 或图片 |
| 业务结果 | 失败可恢复、可审计，不产生伪成功和正式交付 |

## 5. 上下文摘要页

### 5.1 数据来源

页面只展示 `design/generation/info` 返回的 `task.contextSnapshot`。解析规则如下：

- `contextJson`：唯一事实载体，前端只做只读格式化，不补值、不推断、不覆盖。
- `missingFieldsJson`：原样映射为缺失字段，不允许误显示为“已完成”。
- `conflictFlagsJson`：原样映射为冲突提示，必须与正常信息视觉区分。
- `confidence`：展示为“高/中/低”，低置信度必须提示“建议回补数据后进行精准共创”。
- `capturedAt`：展示快照采集时间。

### 5.2 展示分区

| 分区 | 可见字段 | 缺失态 | 禁止展示 |
| --- | --- | --- | --- |
| 任务信息 | 任务编号、生成模式、任务状态、创建时间 | 状态异常时显示“暂不可确认” | 模型费用、请求号 |
| 客户 | 客户名称可来自方案详情；客户面积、预算状态、客户状态 | 未关联时“客户信息待补充” | 手机号、微信号、完整地址 |
| 客户画像 | 决策角色、装修目的、房况、风格、环保、家庭结构、关注点 | 无画像时“客户画像待补充” | 推断出的敏感画像 |
| 房屋 | 小区/房屋摘要、面积、户型、状态 | 无房屋时阻断生成 | 与授权无关的地址细节 |
| 量房 | 原结构说明、量房尺寸、客户要求、设计师结论、照片数量和完成时间 | 无量房时展示缺失 | 未授权附件内容 |
| 方案 | 方案名、风格、面积、户型、设计说明、CAD/原始图摘要 | CAD 缺失时阻断 | 成本、内部备注 |
| 区域 | 区域名、类型、长宽高、面积、周长、区域说明 | 无区域时提示先补区域 | 分项成本、利润 |
| 诉求 | 诉求/排斥点、区域、品类、优先级、详情、响应状态 | 无诉求时提示补录 | 未经确认的自动推断 |
| 缺失与冲突 | 缺失字段、冲突标签、置信度 | 明确显示“不影响查看，影响精准生成”或阻断条件 | 空数组伪装全部完成 |

### 5.3 展示规则

- 缺失字段使用“待补充”标签，并给出返回方案详情或诉求页的路径。
- 冲突使用警告卡片，不用红色错误外观；仅 CAD 缺失或无户型图使用阻断态。
- 置信度为 Low 时，生成按钮默认切换为概念探索，用户显式选择精准共创前需二次确认前置风险。
- 快照一旦生成不可编辑；需要修改事实时回方案、诉求或量房页面修改后重新生成。
- 长文案使用最多 3 行折叠，展开后在卡片内完整换行；不得横向溢出。

## 6. Prompt 预览页

### 6.1 展示边界

| 输出 | 设计师可见 | 建议展示 | 禁止展示/使用 |
| --- | --- | --- | --- |
| VisualBrief | 可见 | 生成模式、上下文置信度、项目事实、量房事实、区域尺寸、必须满足、必须避免、结构约束、缺失和冲突 | 成本、供应商价、电话、微信、完整地址、原始 `contextJson` |
| TalkBrief | 仅设计师可见 | 内部讲解提纲、先讲结构再讲空间、风险和免责声明；明确标注“内部使用” | 对业主展示、价格/工期承诺、成本、内部策略外发 |
| DocumentBrief | 可见 | `meta`、`heard`、`diagnosis`、`spaces`、`materials`、`budget`、`missingFields`、`disclaimer` | 伪造材料、伪造金额、将 `UNAVAILABLE` 显示为 0 或待报价 |
| 技术字段 | 不展示 | 可在日志/后台审计查看 | `modelParametersJson`、`usageJson`、`requestId`、`costAmount`、`costCurrency`、原始 `failureMessage` |

### 6.2 VisualBrief 页面结构

1. 顶部显示“生成模式”和“上下文置信度”。
2. 使用可折叠卡片显示项目事实、量房、方案和区域尺寸。
3. “必须满足”和“必须避免”分别列出，数量为空时显示“暂无记录”，不得隐藏为空。
4. 结构约束固定展示：

```text
严格保留原户型外墙轮廓、房间数量、主要隔墙、门窗和阳台/厨卫关系。
```

5. 缺失和冲突必须展示在 Prompt 前，不能藏在二级页。
6. 原始 Prompt 仅作为“冻结文本快照”，默认折叠；不得可编辑、复制到客户文案或作为唯一业务展示。

### 6.3 TalkBrief 页面结构

- 标题固定为“设计师内部讲解提纲”。
- 第一屏必须显示免责声明：“AI 图为概念效果，正式设计、材料、工艺和金额以责任角色确认及正式报价为准。”
- 讲解顺序按后端输出，不由前端重排。
- 只允许设计师查看；BOSS、店长、团队负责人不在 App 展示 TalkBrief，后端也不得向这些角色下发 `talkPrompt`。业主不得进入任何生成页面。
- 页面不得出现“客户已确认”“可签约”等未发生状态。

### 6.4 DocumentBrief 页面结构

- `meta`：模式、置信度、模板版本。
- `heard`：客户诉求列表。
- `diagnosis`：冲突和待确认项。
- `spaces`：区域结构化摘要。
- `materials`：当前为空时显示“暂无已确认材料”；不得虚构品牌和价格。
- `budget.status=UNAVAILABLE`：显示“暂无正式报价依据，预算暂不可确认”，禁止显示 0 元。
- `missingFields/disclaimer`：必须保留。
- DocumentBrief 仅作为正式方案书的未来结构化输入，不代表已生成 HTML/PDF。

### 6.5 快照时序约束

当前 `design/generation/build` 在创建任务后立即异步生成，因此 P0.4 冻结为：

```text
上下文和 Prompt 在发起生成时冻结
-> 生成立即开始
-> App 在任务状态页展示只读快照
```

不得写成“用户先确认 Prompt，后开始生成”。如业务要求生成前二次确认，必须先新增后端准备态和明确启动能力，不能由 App 用假状态实现。

## 7. 任务状态、等待与恢复

### 7.1 P0.4 状态映射

| 后端状态 | 页面状态 | 页面动作 | 正式交付候选 |
| --- | --- | --- | --- |
| `ContextBuilding` | 准备中（兼容显示） | 自动刷新；无拆分动作 | 否 |
| `PromptReady` | 已创建，准备调用模型 | 自动轮询；可查看快照；可安全退出后恢复 | 否 |
| `Generating` | AI 生成中 | 轮询、离开页面后按 `generationId` 恢复；不显示百分比 | 否 |
| `DraftReady` | 草稿已就绪 | 查看版本、全屏预览、对比、确认封面或区域；可重新生成 | 否，确认前 |
| `DesignerConfirmed` | 设计师已确认 | 查看确认版本；可在满足规则时切换版本；回方案详情核对回写 | 仅已确认且已回写目标的版本 |
| `Failed` | 生成失败 | 按失败码给出恢复动作；重新生成创建新任务 | 否 |
| 其他后端状态 | P0 暂不展示正式入口 | 只显示“当前版本状态暂不支持操作” | 否 |

### 7.2 轮询和恢复

- 进入页面时，有 `generationId` 则调用 `design/generation/info`。
- 无 `generationId` 时调用 `design/generation/page?designId=...`，优先恢复 `PromptReady/Generating`，否则展示最近任务。
- `PromptReady/Generating` 每 2.5 秒轮询 `info`；遇到连续网络异常暂停轮询并显示“状态暂不可确认”与手动刷新。
- 页面离开不取消后端任务；重新进入按 `generationId` 或最近活动任务恢复。
- 收到 `DraftReady/DesignerConfirmed/Failed` 后停止自动轮询。
- 不得将旧状态继续展示为成功；网络失败时保留上次已知状态并标记时间。
- 重试按钮只在 `Failed` 显示；同一设计同一 `sourceDigest` 的活动任务由后端复用，失败任务不会被复用。

### 7.3 失败码文案

| `failureCode` | App 文案 | 恢复动作 |
| --- | --- | --- |
| `AI_MODEL_NOT_CONFIGURED` | AI 模型未配置，请联系管理员 | 联系管理员；提供重新检查 |
| `AI_MODEL_CREDENTIAL_INVALID` | AI 模型凭证无效或未开通 | 联系管理员；不可反复重试 |
| `AI_MODEL_RATE_LIMITED` | AI 请求过于频繁，请稍后重试 | 稍后重新生成 |
| `AI_MODEL_REQUEST_FAILED` | AI 模型请求失败 | 可重新生成 |
| `AI_MODEL_UNAVAILABLE` | AI 模型暂时不可用 | 稍后重新生成 |
| `AI_MODEL_INTERRUPTED` | AI 生成任务被中断 | 可重新生成 |
| `AI_MODEL_BAD_RESPONSE` | AI 模型未返回有效图片 | 可重新生成 |
| `AI_GENERATION_START_FAILED` | AI 生成启动失败 | 检查前置数据后重新生成 |
| `AI_GENERATION_FAILED` | AI 生成执行失败 | 可重新生成 |
| 未知失败码 | 生成失败，请稍后重试 | 手动刷新或重新生成 |

原始 `failureMessage` 不得展示。重试前提示“将再次调用 AI 模型”，但不展示模型费用或内部成本。

## 8. 效果图版本查看、对比与确认

### 8.1 版本聚合

- 当前任务的版本读取 `info.renderVersions`。
- 需要跨任务版本对比时，使用 `design/generation/page?designId=...&size=5` 获取最近任务，再对 `DraftReady/DesignerConfirmed` 任务读取 `info`。
- 每个版本必须保留 `generationId`、`renderId`、`sequence`、任务时间，确认时把所属任务的 `generationId` 一并传回。
- 只展示最近 5 个任务；更早版本显示“历史记录未展开”，不得静默截断成“没有更多”。
- 不新增或猜测图片版本；没有返回版本的区域必须显示空态。

### 8.2 版本卡片

每个版本展示：

- 图片：16:9，`aspectFit`，中性底色，不裁掉原户型结构。
- 固定标签：`AI 概念效果`。
- 版本状态：`Ready=本轮已生成`、`Confirmed=正式确认`、`Superseded=历史版本`、`Failed=生成失败`。
- 任务编号、生成模式、完成时间。
- 当前选中态和确认态不得只靠颜色区分，必须有文字标签。
- 禁止展示成本、模型用量、请求号、原始模型参数和供应商信息。

### 8.3 对比交互

- 默认横向版本条；390/430 宽度下可显示主卡和下一张的预览边，375 宽度下保持单卡可滑。
- 点击版本打开全屏图片预览；全屏页显示免责声明和“设为封面/区域”按钮。
- 至少两个可用版本时出现“双图对比”：上下叠放同一缩放比例，避免移动端横向挤压。
- 对比只做视觉差异，不做结构真实性结论；页面固定提示“结构准确性以 CAD 和责任角色现场复核为准”。
- 未确认版本永远带“AI 概念效果，不可正式交付”标签。

### 8.4 确认规则

| 场景 | 允许性 | 交互 |
| --- | --- | --- |
| `DraftReady` + `Ready` + 有图片 | 允许 | 选择目标后二次确认 |
| `DesignerConfirmed` 后切换另一版本 | 允许 | 文案为“切换正式版本”，确认后原版本同任务内变 `Superseded` |
| `PromptReady/Generating` | 禁止 | 按钮禁用并提示“效果图尚未生成完成” |
| `Failed` | 禁止 | 只显示重新生成 |
| 任务 `Shared/Locked` | 禁止 | 按钮禁用并提示“已进入不可回退阶段” |
| 版本 `Failed/Superseded` | 禁止 | 不显示确认按钮 |
| 区域目标不存在 | 禁止 | 选择区域置灰，提示先新增区域 |

确认动作：

1. 默认推荐“设为方案封面”。
2. 选择“设为区域图片”时必须选择当前方案区域。
3. 二次确认明确目标：封面会替换 `Design.coverUrl`；区域图片是追加到 `Space.images`，不覆盖原图。
4. 调用 `design/generation/update`，参数只传 `generationId`、`renderId`，封面时不传 `spaceId`。
5. 成功后重新调用 `design/scheme/info`，刷新 `coverUrl` 和区域图片。
6. 失败时保留当前页面和选择，显示服务端业务错误，不假装成功。

### 8.5 正式交付门禁

未来 HTML/PDF、客户分享或正式方案文档必须同时满足：

```text
task.status = DesignerConfirmed
and render.status = Confirmed
and render.deliverable = true
and render.imageUrl equals 当前 Design.coverUrl 或属于当前 Space.images
```

附加规则：

- 未确认版本不得进入正式 HTML/PDF 或客户可见正式方案。
- 同一设计跨任务存在多个 Confirmed 时，以当前设计事实为准，不扫描全部 `deliverable=true` 自动拼装。
- 正式文档未来必须从当前封面和已确认区域图片集取源，旧确认版本作为历史，不得重新成为当前交付页。
- TalkBrief 永不作为客户输出；DocumentBrief 只作为未来正式文档的结构化输入。
- 当前 App 显示“已确认，可作为正式方案内容”只在满足门禁时出现；没有 HTML/PDF Provider 时同时显示“正式方案文档能力尚未开放”。

## 9. 375 / 390 / 430 逻辑宽度规格

### 9.1 通用布局

- 页面使用 `100vw` 内容容器、`$jzb-page-pad` 水平内边距和 `overflow-x: hidden`。
- 底部主行动使用固定操作区，底部间距为 `calc(32rpx + $jzb-safe-bottom)`；内容区预留同等高度。
- 所有卡片 `min-width: 0`，图片、标签和文本不得撑破父级。
- 长客户名、区域名、失败文案使用 `jz-clamp-1/2/3`，展开后 `word-break: break-word`。
- 表单和确认抽屉在安全区内滚动，不遮挡底部按钮。
- 状态标签同时使用文字和图标/形状，不只依赖颜色。

### 9.2 三档宽度

| 宽度 | 结构要求 | 版本卡 | 文案与操作 |
| --- | --- | --- | --- |
| 375 | 单列布局；卡片边距紧凑；按钮可命中面积不小于 44px | 主卡约占 88%，下一张只露出边缘 | 标题最多 2 行，摘要最多 3 行，Prompt 默认折叠 |
| 390 | P0 基准宽度；上下文卡、状态卡、版本卡均为单列 | 主卡约占 76%，可明显滑动 | 保持标准字号和间距，不额外放大 |
| 430 | 利用额外空间但不增加信息密度；仍保持单列主内容 | 主卡约占 62%，可同时感知相邻版本 | 字号不放大到破坏层级；图片不拉伸超过原始比例 |

### 9.3 空态、加载和错误态

- 无 CAD/户型图：阻断卡 + “返回方案上传 CAD”主按钮。
- 无量房/区域：可概念探索卡 + “去补充量房/区域”次按钮。
- 无任务：显示生成前摘要和“开始生成”。
- 任务加载：骨架屏覆盖状态区和版本区，不展示旧任务的图片作为当前结果。
- 网络错误：错误卡、最后更新时间、重试按钮；不得显示空数组冒充“没有版本”。
- 模型失败：稳定文案、失败码对应的恢复动作、重新生成按钮。
- 快照解析失败：显示“任务数据暂不可确认”，保留返回方案和刷新入口，不展示半截 Prompt。
- 图片加载失败：显示占位图和“图片加载失败，点击重试”，不将破图当作确认图片。

## 11. 开发任务拆解与 DoD

### D1：后端 P0.4 接口收口

- DoD：定向 Provider 安全测试与字段断言通过，变更只在 P0.4 分支。

### D2：App 领域模型和 API

## 12. 验收标准

### 12.1 正向

- AC-01：完整 CAD、量房、区域、画像、诉求时，`Precise` 任务可进入 `DraftReady`，版本图可查看。
- AC-02：`DraftReady` 确认封面后，刷新方案详情显示新封面，版本状态为 `Confirmed` 且 `deliverable=true`。
- AC-03：选择区域确认后，区域图片集合增加新图，原图保留，提示明确为“追加”。
- AC-04：已有确认版本时可切换任一同任务可用版本，旧版本变 `Superseded`。
- AC-05：离开页面后任务继续，带 `generationId` 返回可恢复对应任务。

### 12.2 前置数据和模式

- AC-06：无 CAD/户型图时，后端和前端均阻断，不能创建模型调用。
- AC-07：只有部分量房/区域时，请求精准共创必须返回概念探索，并展示实际模式和原因。
- AC-08：缺失字段和冲突在页面上可见，不得静默显示“已完成”。
- AC-09：低置信度概念探索仍带“AI 概念效果，不可正式交付”标签。

### 12.3 状态和失败

- AC-10：`PromptReady`、`Generating` 显示等待态并轮询；网络中断显示“暂不可确认”，有手动重试。
- AC-11：失败码分别映射到业务文案；页面不展示原始 `failureMessage`。
- AC-12：失败任务不自动复用，点击重新生成创建新任务并保留失败历史。
- AC-13：重复点击生成且 `sourceDigest` 未变时，返回同一活动任务，不重复调用模型。

### 12.4 版本与正式门禁

- AC-14：`Ready`、`Confirmed`、`Superseded`、`Failed` 四种版本状态显示正确且不只靠颜色。
- AC-15：未确认版本不能触发正式 HTML/PDF、客户分享或“正式交付”文案。
- AC-16：已确认但未回写到当前封面/区域集合的旧版本，不得作为当前正式交付物。
- AC-17：当前无 HTML/PDF Provider 时页面只显示门禁说明，不显示可点击的正式文档按钮。

### 12.5 权限、字段和合规

- AC-18：BOSS、店长、团队负责人、设计师按数据范围通过；业务员、项目经理、财务、业主拒绝。
- AC-19：伪造 `generationId`、`renderId`、`designId`、跨企业参数返回 403/404，不泄露对象存在性或图片。
- AC-20：设计师响应无 `costAmount/costCurrency/usageJson/requestId/modelParametersJson/failureMessage/sourceDigest`。
- AC-21：业主看不到 TalkBrief、成本、供应商价、内部策略和非正式图片。
- AC-22：BOSS、店长、团队负责人响应和页面不含 TalkBrief；客户敏感信息不进入截图验收素材；正式客户文案不含内部 Prompt。

### 12.6 多机型与工程

- AC-23：375、390、430 逻辑宽度无横向溢出，底部操作不被安全区遮挡，长文案可展开。
- AC-24：空态、加载、图片失败、网络错误、快照解析失败都有恢复路径。
- AC-25：App 类型检查、构建、分包检查通过；后端 Provider 安全测试和字段断言通过。
- AC-26：App 不新增 DTO/VO；Provider 返回仍为领域实体类型或实体集合。

## 13. 开放问题

以下只能由用户或业务负责人拍板，不阻断当前 P0.4 规格落地：

1. 是否要求正式模型调用前人工逐字确认 Prompt？当前后端立即异步生成，若要求预先确认，需要新增准备态和启动能力，属于范围变更。
2. 正式 HTML/PDF 的首版模板、品牌样式和客户可编辑字段由谁负责？当前 P0.4 明确不实现。

4. 店长、团队负责人是否需要在未来单独授权下查看 TalkBrief？当前 P0.4 冻结为仅 Designer 可见。
5. 确认后是否允许在 App 中删除已回写区域图片？当前只追加，不提供删除入口。

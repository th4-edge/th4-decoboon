## 0. 一页结论

AI 资源统计必须同时回答两个不同问题：

1. **企业收多少钱**：企业是这个账单的收费主体，按 AI 调用实际消耗的计费点数结算。
2. **哪个门店用了多少**：门店是内部统计和管理维度，用于看门店 AI 消耗、能力和成本，不另建一套门店重复账单。

因此使用以下基本口径：

```text
AI 原始调用次数
-> 按能力类型换算资源单位
-> 按费率版本换算计费点数
-> 记录企业账本
-> 同时记录门店归属
-> 企业汇总 = 各门店分摊 + 企业公共未分摊
```

核心原则：

- **调用次数不等于收费单位**：一次文本调用和一次高分辨率图片生成不能都算“一次”。
- **企业汇总为收费口径**：企业资源账户和账单是唯一结算主体。
- **门店汇总为管理口径**：门店、门店公共和企业公共必须可清楚区分。
- **不重复计费**：同一幂等调用、重试和失败返还只能形成一次有效结算。
- **先结算后统计**：原始调用可实时记录，收费点数以最终结算账本为准。
- **内容最小化**：用量记录保存调用元数据，不默认保存客户提示词、图片正文和模型原始输出。

## 1. 业务目标

### 1.1 近期目标

1. 企业能查看当期 AI 调用量、成功量、失败量、资源点数和预估费用。
2. 企业能按门店查看 AI 使用分布、能力分布和业务场景。
3. AI 经营简报、客户摘要、报价检查、设计生成等能力能统一记账。
4. 失败、重试、撤销、额度和资源包有明确状态。
5. 为后续 AI 资源包销售、账单、续费和毛利分析提供可信底账。

### 1.2 后期目标

1. 企业按套餐 + AI 点数包 + 超额策略使用 AI。
2. 平台可按企业、套餐和 AI 能力计算收入、平台成本和毛利。
3. 企业可按门店、团队、员工、项目、客户和业务阶段分析 AI 使用。
4. 资源包可在到期、转入、转出和调整时保持审计。
5. 能识别高成本、低采用、高失败率和异常调用。

### 1.3 非目标

- 不按项目成交额抽成。
- 不把“AI 调用次数”直接作为销售价格。
- 不向业主展示企业 AI 成本和资源包。
- 不因调用量统计改变现有报价、成本、毛利和项目结算。
- 不用 AI 用量作为员工绩效的唯一结论。
- 不默认保存提示词、客户资料和模型输出的完整正文。

## 2. 计量对象与单位

### 2.1 六个核心量

| 名称 | 定义 | 用途 |
| --- | --- | --- |
| 请求次数 `requestCount` | 用户或系统发起一次 AI 能力的请求 | 趋势、成功率、调用量 |
| 有效调用 `validCallCount` | 进入模型执行或有效处理阶段的不重复调用 | 业务统计 |
| 成功调用 `successCount` | 返回可用结果并完成结算的调用 | 成功率和成本 |
| 资源单位 `resourceUnits` | Token、图片张数、页数、秒数、字节或文件单位 | 能力换算 |
| 计费点数 `billableUnits` | 按费率版本换算后的资源点数 | 资源包和账单 |
| 实际成本 `platformCost` | 平台调用模型、存储、转换和第三方产生的成本 | 毛利和经营 |

### 2.2 调用量与点数必须分开

```text
API 调用量用于回答：企业用了多少次、哪些能力用得多、成功率多少。
计费点数用于回答：企业用了多少资源、资源包扣多少、下一期应收多少。
```

不得把以下内容简化为同一数字：

- 一次文本摘要；
- 一次 CAD 解析；
- 一次图片生成；
- 一次视频生成；
- 一次文档 OCR；
- 一次由用户重复点击但被幂等拦截的请求。

### 2.3 能力单位建议

| 能力类型 | 原始资源单位 | 结算建议 |
| --- | --- | --- |
| 文本摘要/问答 | 输入 Token + 输出 Token | 按每 X Token 折算 1 点 |
| 文档解析/OCR | 页数、文件数、图片数 | 按每 X 页折算 1 点 |
| CAD/图纸分析 | 文件数、图纸张数、处理时长 | 按文件 + 处理档位折算 |
| 图片生成 | 图片张数、分辨率、质量档位 | 按图片和质量档位折算 |
| 图片编辑 | 原图数、输出数、编辑类型 | 按输出张数和档位折算 |
| 语音识别 | 秒数或分钟数 | 按每 X 分钟折算 |
| 文本转语音 | 字符数或秒数 | 按每 X 字符/秒折算 |
| 视频生成 | 秒数、分辨率、帧率档位 | 按视频档位和秒数折算 |
| 向量检索/知识问答 | Query 数、命中片段、模型 Token | 按检索次数 + 模型 Token 折算 |

具体 `X`、质量倍率和价格必须由费率版本冻结，不在本产品稿中写死。

## 3. 维度设计

### 3.1 企业维度

企业是唯一收费主体和资源账户主体。

企业维度记录：

- 企业 ID；
- 订阅和套餐版本；
- 套餐包含额度；
- 资源包余额；
- 本期消耗、返还和结余；
- 调用量、成功量、失败量；
- 平台成本和预估收入；
- 请求来源门店分布。

### 3.2 门店维度

门店是资源分摊和管理统计维度。

门店维度记录：

- 来源门店；
- 业务对象所属门店；
- 使用员工所属门店；
- 分摊门店；
- 门店请求次数、点数和成本；
- 门店能力分布、业务模块分布和异常率；
- 企业公共未分摊数量。

### 3.3 门店归属规则

每条 AI 调用必须形成唯一 `allocationStore`：

| 优先级 | 归属来源 | 适用场景 |
| --- | --- | --- |
| 1 | 明确的业务对象所属门店 | 客户、房屋、报价、合同、项目、验收、采购等 |
| 2 | 当前执行员工所属门店 | 通用知识助手、无业务对象的个人操作 |
| 3 | 企业公共未分摊 | BOSS 全企业操作、平台级配置或无法确定门店 |
| 4 | 禁止默认归到总店 | 只有规则明确时才可归总店，不能静默填默认店 |

同时保留：

- `businessStoreId`：业务对象门店；
- `employeeStoreId`：员工执行门店；
- `allocationStoreId`：用于门店统计的实际归属；
- `allocationReason`：归属原因和规则版本。

如果业务对象门店与员工所属门店不同，收费仍按企业汇总，门店统计以业务对象门店优先。

### 3.4 业务维度

| 维度 | 示例 | 是否用于收费 |
| --- | --- | --- |
| 业务模块 | CRM、Design、Quote、Project、Supply、Finance、Analytics、Knowledge | 统计 |
| AI 能力 | 客户摘要、报价体检、CAD 分析、日报摘要 | 计费和统计 |
| 业务场景 | 跟进、量房、设计、报价、施工、验收、催收、学习 | 统计 |
| 业务对象 | 客户、房屋、报价、合同、项目 | 审计和下钻 |
| 触发员工 | 发起员工 | 审计和团队统计 |
| 模型/供应商 | 模型和供应商能力版本 | 成本和路由 |
| 请求状态 | 成功、失败、取消、超时、重复 | 结算和异常 |
| 计费状态 | 待结算、已结算、已返还、作废 | 账单 |

## 4. 逻辑对象设计

以下为产品级逻辑对象，最终实体、字段、状态和索引需在 T06 后由技术设计冻结。

### 4.1 AI 调用记录

记录一次逻辑调用，不默认保存正文内容。

建议逻辑字段：

| 字段 | 说明 |
| --- | --- |
| `callId` | 调用唯一标识 |
| `requestId` | 上游请求标识 |
| `idempotencyKey` | 幂等键，防重复调用 |
| `company` | 企业 |
| `businessStore` | 业务对象门店快照 |
| `employeeStore` | 执行员工门店快照 |
| `allocationStore` | 最终门店归属 |
| `allocationReason` | 归属原因 |
| `employee` | 发起员工 |
| `businessModule` | 业务模块 |
| `capabilityCode` | AI 能力编码 |
| `sceneCode` | 业务场景 |
| `businessType` / `businessId` | 业务对象 |
| `provider` | 模型或服务供应方 |
| `modelCode` / `modelVersion` | 模型版本 |
| `rateCardVersion` | 费率版本 |
| `inputUnits` / `outputUnits` | 输入输出资源单位 |
| `resourceUnits` | 合并后的资源单位 |
| `billableUnits` | 计费点数 |
| `platformCost` | 平台实际成本 |
| `status` | 调用状态 |
| `billingStatus` | 结算状态 |
| `failureCode` | 失败分类 |
| `startedAt` / `completedAt` | 执行时间 |
| `retryOfCallId` | 重试来源 |
| `cancelReason` | 取消原因 |

不应默认保存：

- 完整提示词；
- 客户电话、地址、身份证；
- CAD 正文和现场图片原始地址；
- 模型原始输出；
- 供应商价格和项目成本明细。

如确有排障需要，应只保存脱敏摘要、内容指纹或受限调试引用，并设置独立权限和保留期。

### 4.2 AI 用量账本

用量账本采用追加式记录，只记录资源点数的发放、消耗、返还、调整和过期。

账本类型：

| 类型 | 含义 |
| --- | --- |
| Grant | 套餐或资源包发放 |
| Reserve | 调用前预占 |
| Consume | 成功结算并正式扣除 |
| Refund | 失败、撤销或重复返还 |
| Expire | 资源包到期失效 |
| Adjust | 人工调整，必须有原因 |
| TransferIn / TransferOut | 企业或门店间调整，是否开放待裁决 |

账本必须记录余额前值、变动值、余额后值、来源调用、企业、门店、费率版本和操作时间。

### 4.3 资源账户与资源包

资源账户：

- 企业维度的当前可用点数；
- 套餐额度、资源包额度、赠送额度和调整额度；
- 预占中的点数；
- 已消耗、已返还和已过期点数。

资源包：

- 企业；
- 产品编码和名称；
- 总量；
- 剩余量；
- 有效期；
- 适用能力范围；
- 购买订单项；
- 状态；
- 是否可滚存；
- 是否可退还。

### 4.4 AI 用量日汇总

按以下组合形成日汇总：

```text
企业 + 门店 + 业务模块 + AI 能力 + 模型 + 日期
```

汇总字段：

- 请求数；
- 有效调用数；
- 成功数；
- 失败数；
- 资源单位；
- 计费点数；
- 返还点数；
- 净计费点数；
- 平台成本；
- 平均耗时；
- 成功率。

汇总只是查询加速，最终账以原始账本为准。

### 4.5 费率版本

费率版本用于把资源单位换算为点数，必须支持历史追溯。

最低内容：

- 能力编码；
- 单位类型；
- 每点资源单位；
- 模型倍率；
- 质量或分辨率倍率；
- 成本基数；
- 生效时间和失效时间；
- 审批人和版本状态。

历史调用必须引用当时费率版本，不能让费率调整改写历史账单。

## 5. 调用和结算状态机

### 5.1 调用状态

```text
Requested
-> Validated
-> Reserved
-> Running
-> Succeeded
   -> Settled
   -> Refunded
-> Failed
   -> Released
   -> Refunded
-> Cancelled
-> Expired
-> DuplicateBlocked
```

### 5.2 计费状态

| 状态 | 含义 | 是否计入企业消耗 |
| --- | --- | --- |
| Pending | 已请求，尚未形成结算 | 否 |
| Reserved | 已预占点数 | 预占，不计净消耗 |
| Billed | 成功结算 | 是 |
| PartiallyRefunded | 部分返还 | 净额 |
| Refunded | 全额返还 | 否 |
| Void | 重复、作废或测试调用 | 否 |
| Adjusted | 人工调整 | 按调整后净额 |

### 5.3 标准结算流程

```text
收到请求
-> 校验权限和额度
-> 生成幂等键
-> 预占预计点数
-> 调用 AI
-> 获取实际资源单位
-> 按费率版本结算
-> 多退少补
-> 更新企业账本和门店统计
-> 记录日志
```

## 6. 计费公式

### 6.1 基础公式

```text
resourceUnits = 输入资源单位 + 输出资源单位

billableUnits = ceil(
  resourceUnits
  ÷ 每点资源单位
  × 模型倍率
  × 质量档位倍率
)
```

如果某能力不按资源单位，而按件计价：

```text
billableUnits = ceil(件数 × 单位点数 × 规格倍率)
```

### 6.2 净消耗公式

```text
净消耗点数 =
已结算消耗点数
- 成功返还点数
- 失败返还点数
- 撤销返还点数
+ 人工调整点数
```

### 6.3 企业汇总公式

```text
企业请求次数 = 企业内所有调用记录数

企业有效调用次数 = 企业内非重复且进入有效处理的调用数

企业净消耗点数 = 企业用量账本有效变动净额

企业本期费用 =
套餐包含额度内成本分摊
+ 超过套餐后的资源包或超额点数费用
```

### 6.4 门店汇总公式

```text
门店请求次数 = allocationStore 为该门店的调用数

门店净消耗点数 = 门店归因的账本净点数

企业已分摊点数 = 各门店净消耗点数之和

企业公共点数 = allocationStore 为“企业公共”的净点数

企业总消耗 = 企业已分摊点数 + 企业公共点数
```

门店统计必须满足：

```text
企业总消耗 = 各门店消耗 + 企业公共消耗 + 已撤销/返还的净调整
```

不得把企业总消耗直接复制给每个门店，也不得把同一调用同时归到多个门店。

## 7. 幂等、重试与返还

### 7.1 幂等键

建议幂等键由：

```text
企业 + 能力 + 业务对象 + 业务动作 + 请求指纹
```

组成。

同一用户重复点击同一动作，只能形成一个有效调用。

### 7.2 重试规则

| 场景 | 是否新调用 | 是否重新收费 |
| --- | --- | --- |
| 用户点击重试，但上游未调用成功 | 否或复用原调用 | 否 |
| 模型超时且未产生可用结果 | 新执行可复用原调用结算 | 否 |
| 模型返回可用结果，用户重新生成 | 是 | 是 |
| 用户修改输入后重新生成 | 是 | 是 |
| 网络失败但上游已成功 | 不重复执行 | 已有结算为准 |
| 重复点击被幂等拦截 | 否 | 否 |
| 调用成功但用户未采纳结果 | 是 | 默认是，需 T05 确认 |
| 调用成功后企业主动撤回和删除 | 是 | 已发生模型成本不自动退，业务退回规则待裁决 |

### 7.3 失败分类

| 失败类型 | 用户是否扣点 | 平台成本处理 |
| --- | --- | --- |
| 权限不足、输入非法 | 否 | 不计 |
| 额度不足 | 否 | 不计 |
| 模型供应商失败 | 否 | 平台内部成本 |
| 超时且无结果 | 否 | 平台内部成本 |
| 返回可用结果但格式校验失败 | 否或返还 | 平台内部成本 |
| 业务输出质量不满意 | 默认已计费 | 需申诉或调整规则 |
| 用户取消在模型执行前 | 否 | 不计 |
| 用户取消在模型执行后 | 默认已计费 | 待 T05 |

失败和返还状态必须保留原始结算记录，不能直接删除。

## 8. 资源包与结算顺序

### 8.1 建议扣减顺序

```text
赠送/试用额度
-> 当前套餐包含额度
-> 最早到期的资源包
-> 后续资源包
-> 超额策略（阻断或按规则加购）
```

是否允许负余额和是否允许继续调用，必须由 T05/T06 冻结。

### 8.2 资源包属性

- 点数总量；
- 已用、预占、剩余；
- 生效时间和到期时间；
- 适用企业和门店范围；
- 适用能力范围；
- 是否可跨期、跨门店或跨主体调整；
- 是否可退款；
- 购买订单项和支付状态；
- 来源：套餐、加购、赠送、活动、人工调整。

### 8.3 套餐与门店关系

企业是收费主体。门店包只决定企业可使用多少门店，不等于每个门店独立拥有 AI 点数。

门店统计用于：

- 门店经营分析；
- 资源使用治理；
- 发现异常调用；
- 门店负责人查看本店耗用；
- 平台为企业提供使用明细。

除非未来明确新增“门店独立资源包”，否则不在门店级重复扣费。

## 11. 异常和反向用例

1. 同一幂等请求重复提交，只记录一次有效调用。
2. 供应商失败但有两条回调，不能重复返还或重复计费。
3. 业务对象门店和员工门店不同，按业务门店优先，且保留双快照。
4. BOSS 全企业操作没有业务门店，进入企业公共，不默认归总店。
5. 企业汇总等于门店分摊与企业公共之和，不重复统计。
6. 资源包到期后不能继续扣减，错误提示清晰。
7. 费率升级后，旧调用继续使用旧费率版本。
8. 门店被关闭后，历史统计仍可查询，但不再有新调用归属。
9. 员工转店后，历史调用保留原门店快照，新调用按新门店归属。
10. 调用被撤销后，原结算保留，返还单独形成账本记录。
11. 非授权角色不能通过门店过滤看到其他门店数据。
12. 平台运营能看用量和成本，但不能读取客户正文和业务敏感内容。

## 16. T05 需要冻结的问题

1. 企业是唯一收费主体，门店仅是统计和分摊维度，是否确认。
2. 门店归属优先级，以及“企业公共未分摊”是否允许存在。
3. API 调用次数是否只作为统计，不直接作为计费单位。
4. 各能力的资源单位、每点换算和质量倍率由谁维护。
5. 成功生成但用户不采纳，是否计费。
6. 模型失败、超时、格式错误、用户取消的扣点和返还规则。
7. 套餐包含额度、赠送资源包、加购资源包和有效期。
8. 是否允许负余额、超额继续使用、自动续购和加购提醒。
9. 资源包是否允许跨门店、跨期、转出和退款。
10. 企业和门店统计的可见角色、成本可见性和导出权限。
11. 用量记录保留多久，是否允许保存脱敏提示词或输出摘要用于排障。
12. 费率版本、调价和历史账单如何保持不可变。
13. 平台成本、AI 收入和 AI 毛利率是否作为内部或对外指标。
14. 门店关闭、员工转店和企业合并时历史调用如何保留和归属。

## 17. 最终原则

AI 资源统计必须做到：

```text
企业看得清总账
门店说得清消耗
每笔调用追得到来源
每次扣点解释得了原因
失败和重复不重复收费
调价不改写历史账单
```

只有这五个条件成立，AI 资源包才可以作为成熟的订阅增值产品收费；在此之前，应只做内部统计和成本验证。

## 0. 一页结论

### 0.1 本批次目标

建立所有 AI 调用的统一底账：

```text
谁发起
-> 哪个企业
-> 哪个业务门店
-> 哪个执行门店
-> 哪个员工
-> 哪个 AI 能力
-> 哪个业务对象
-> 用了多少资源
-> 折算了多少影子点数
-> 成功、失败、重试、返还还是作废
```

同时提供：

1. 企业维度总调用量、成功率和影子点数；
2. 门店维度调用量、能力分布和分摊点位；
3. 企业公共未分摊统计；
4. 调用明细和基础对账；
5. 资源包收费前的数据准备。

### 0.2 本批次边界

本批次做：

- AI 调用记录；
- 企业、门店、员工和业务对象归属；
- 资源单位统计；
- 影子计费点数；
- 企业/门店只读报表；
- 对账和异常处理。

本批次不做：

- 不正式扣企业点数；
- 不销售 AI 资源包；
- 不出正式账单；
- 不自动续购；
- 不将门店统计用于员工绩效和处罚；
- 不展示或保存完整提示词、客户信息和项目附件正文。

## 1. 真实业务场景

### 场景一：BOSS 查看本月 AI 资源使用

| 维度 | 内容 |
| --- | --- |
| 使用人 | 企业负责人 |
| 触发事件 | 月末需要确认 AI 用了多少、集中在哪些门店和能力 |
| 前置条件 | 企业已产生 AI 调用；BOSS 有企业和全部门店统计权限 |
| 当前动作 | 没有统一统计，只能凭模型平台账单或员工反馈估算 |
| 系统动作 | 展示企业总调用、成功/失败、影子点数、能力分布和门店分布 |
| 下一步 | 下钻门店和能力明细，判断是否需要采购资源包或优化使用 |
| 异常 | 某条调用门店归属不清时进入企业公共，不归到默认总店 |

### 场景二：平台运营核对一个企业的 AI 成本

| 维度 | 内容 |
| --- | --- |
| 使用人 | 平台运营管理员 |
| 触发事件 | 企业 AI 使用增长，需要评估平台成本和未来资源包空间 |
| 前置条件 | 平台运营具有用量和平台成本权限 |
| 当前动作 | 只能在模型供应商后台按 API Key 看总成本，无法对应企业和能力 |
| 系统动作 | 按企业、门店、能力、模型展示调用量、资源单位、影子点数和平台成本 |
| 下一步 | 核算成本、发现异常、整理资源包定价依据 |
| 异常 | 平台运营不能查看客户提示词、图片正文和企业业务敏感内容 |

## 2. 目标与非目标

### 2.1 产品目标

1. 所有 AI 能力和 AI Provider 必须接入统一调用记录。
2. 每笔调用可以追溯到企业、门店、员工和业务对象。
3. 企业是统计和未来收费主体，门店是分摊和分析维度。
4. 调用次数、资源单位和影子点数分开统计。
5. 重复、失败、重试、取消和回调不会造成重复计量。
6. 企业总统计等于门店分摊加上企业公共。
7. 为后续点数结算、资源包和账单提供可对账底账。

### 2.2 非目标

- 不改变现有订阅天数、套餐价格和订单履约。
- 不改变报价、合同、项目、成本和利润。
- 不出正式账单和发票。
- 不将影子点数展示为客户应付金额。
- 不用单次调用量证明 AI 业务价值。
- 不让门店统计成为跨门店业务数据查看入口。

## 3. 产品范围

### 3.1 AI 能力接入范围

A0.1 要求以下能力在产生调用时接入统一记录：

- AI 经营简报；
- 客户跟进摘要和下一步；
- 量房/需求结构化；
- CAD/设计概念分析；
- 图片/效果图生成；
- 报价体检；
- 客户讲解稿；
- 项目/日报摘要；
- 验收证据检查；
- 选材/供应商建议；
- 财务行动建议；
- 企业知识问答；
- 后续新增的 AI 能力。

### 3.2 记录方式

建议由服务端统一 AI 调用入口或 Context 记录，不允许每个业务 Provider 自行拼一套统计。

```text
业务请求
-> 权限校验
-> 形成 AI 调用上下文
-> 记录 Requested
-> 执行 AI
-> 记录资源和结果
-> 形成影子点数
-> 更新企业/门店统计
```

## 4. 角色与权限

| 角色 | 企业总览 | 门店分布 | 员工明细 | 平台成本 | 业务对象 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| BOSS | 是 | 全部门店 | 汇总 | 默认不显示平台总成本 | 按业务权限 | 企业资源管理者 |
| 财务 | 是 | 按财务范围 | 汇总 | 可授权 | 否 | 费用和资源包管理待裁决 |
| 店长 | 本门店摘要 | 仅本门店 | 本店汇总 | 默认否 | 按业务权限 | 不能进入其他门店统计 |
| 团队负责人 | 本团队摘要 | 本团队 | 本团队 | 否 | 按业务权限 | 默认只做统计 |
| 普通员工 | 本人摘要 | 本人 | 本人 | 否 | 按业务权限 | 只看本次消耗 |
| 平台运营 | 平台聚合 | 企业/门店聚合 | 不得直达客户正文 | 是 | 不含正文 | 平台成本和套餐分析 |
| 业主 | 无 | 无 | 无 | 无 | 无 | 不感知平台成本 |

### 4.1 权限原则

- 企业 ID 只从登录员工加载；
- 门店范围必须由服务端权限裁剪；
- 平台运营不得通过用量明细读取客户提示词和业务正文；
- 成本、点数和调用量是不同字段，按角色裁剪；
- 导出必须重新校验权限，并记录导出审计。

## 5. 功能需求

### F1：AI 调用记录

每次逻辑调用形成一条原子记录。

必须记录：

- 企业；
- 业务门店；
- 执行员工门店；
- 分摊门店；
- 员工；
- 业务模块；
- AI 能力；
- 业务对象类型和 ID；
- 幂等键；
- 供应商、模型和能力版本；
- 费率版本；
- 输入资源单位；
- 输出资源单位；
- 资源单位合计；
- 影子点数；
- 实际平台成本；
- 调用状态；
- 计费影子状态；
- 开始时间、完成时间、耗时；
- 失败分类；
- 重试来源；
- 取消原因。

### F2：幂等与调用状态

同一业务动作重复提交、网络重试和供应商重放回调，只能形成一次有效调用。

状态：

```text
Requested
-> Validated
-> Reserved
-> Running
-> Succeeded / Failed / Cancelled / Expired
-> Settled / Released / Refunded / Void
```

### F3：企业维度统计

企业页展示：

- 周期内请求次数；
- 有效调用次数；
- 成功次数；
- 失败次数；
- 影子点数；
- 返还点数；
- 净影子点数；
- 成功率；
- 平均耗时；
- 平台成本；
- 资源包预估消耗。

### F4：门店维度统计

门店页展示：

- 门店名称；
- 本门店调用次数；
- 本门店成功数；
- 本门店影子点数；
- 企业总用量占比；
- 能力分布；
- 业务模块分布；
- 最近调用时间；
- 异常率；
- 平均每项目调用量。

必须单独显示企业公共，不与门店数据混合。

### F5：门店归属

归属优先级：

```text
业务对象所属门店
-> 执行员工所属门店
-> 企业公共
```

同时记录：

- `businessStoreId`；
- `employeeStoreId`；
- `allocationStoreId`；
- `allocationReason`；
- `allocationRuleVersion`。

### F6：影子计费

1. 按能力资源单位和临时费率版本计算影子点数。
2. 影子点数只用于统计和预测，不扣减资源账户。
3. 调用成功后计算影子点数。
4. 失败、重复、取消和作废不形成有效影子消耗。
5. 正式扣点条件待 T06 冻结。

### F7：对账

支持核对：

- 调用记录请求数；
- 调用状态数量；
- 影子点数总和；
- 企业总量与门店加企业公共；
- 平台成本；
- 幂等重复数量；
- 失败返还数量。

### F8：明细下钻

每个企业或门店统计可以下钻到调用列表。

明细展示：

- 时间；
- 门店/企业公共；
- 员工摘要；
- 能力；
- 业务模块；
- 业务对象摘要；
- 状态；
- 影子点数；
- 平台成本；
- 耗时；
- 重试关系；
- 幂等状态。

默认不展示提示词、图片正文和完整输出内容。

## 8. 资源单位和影子点数

### 8.1 资源单位

| 能力 | 资源单位 |
| --- | --- |
| 文本 | 输入 Token + 输出 Token |
| 图片生成 | 图片张数 + 分辨率/质量 |
| CAD/图纸 | 文件数 + 图纸张数 + 处理时长 |
| OCR/文档 | 页数 + 图片数 |
| 语音识别 | 秒/分钟 |
| 语音合成 | 字符数/秒数 |
| 视频生成 | 秒数 + 分辨率/帧率 |
| 知识检索 | 查询数 + Token |

### 8.2 影子点数公式

```text
影子点数 = ceil(
  资源单位
  ÷ 每点资源单位
  × 模型倍率
  × 质量倍率
)
```

费率未冻结时，使用固定测试费率并标记 `shadow=true`，不得展示为正式应付金额。

### 8.3 资源单位缺失

如果模型只返回自报 Token、不返回准确单位：

1. 使用可验证的估算器；
2. 在记录中标记 `estimated=true`；
3. 不与供应商真实成本混为一类；
4. 后续可对账修正，但不改写已完成正式账单。

## 9. 状态与异常

### 9.1 调用状态

| 状态 | 含义 | 是否计入有效调用 |
| --- | --- | --- |
| Requested | 已请求，未执行 | 否 |
| Validated | 已通过权限和输入校验 | 是 |
| Reserved | 已预占 | 是 |
| Running | 执行中 | 是 |
| Succeeded | 成功 | 是 |
| Failed | 失败 | 否 |
| Cancelled | 取消 | 视情况 |
| Expired | 超时 | 否 |
| DuplicateBlocked | 幂等拦截 | 否 |

### 9.2 影子计费状态

| 状态 | 含义 | 是否计入净点数 |
| --- | --- | --- |
| Pending | 未计算 | 否 |
| Calculated | 已计算 | 是（若成功） |
| Returned | 已返还 | 净额 |
| Void | 作废 | 否 |
| Adjusted | 人工调整 | 调整后 |

### 9.3 异常

| 异常 | 处理 |
| --- | --- |
| 无业务门店 | 归企业公共 |
| 业务门店和员工门店不同 | 业务门店优先，保留双快照 |
| 重复点击 | DuplicateBlocked，只记录一次 |
| 供应商失败 | Failed，不计有效影子消耗 |
| 模型返回非法单位 | 标记录异常，不计正式消耗 |
| 资源单位缺失 | 使用标记为 estimated 的估算 |
| 门店关闭 | 新调用不归该门店，历史保留 |
| 员工转店 | 新调用按新门店，历史不改 |
| 调用记录写入失败 | 不影响原业务结果，但必须进入告警队列 |
| 统计汇总失败 | 原调用记录保留，可从底账重算 |

## 10. 权限和敏感信息

### 10.1 业务数据最小化

调用记录默认不保存：

- 完整客户提示词；
- 客户姓名、电话、地址；
- CAD 正文；
- 现场图片原始地址；
- 合同正文；
- 完整财务明细；
- 模型原始输出。

### 10.2 允许保存

- 业务对象类型和 ID；
- 内容指纹；
- 脱敏摘要；
- 能力编码；
- 资源单位；
- 状态、错误码和耗时；
- 模型和费率版本。

### 10.3 导出

- 普通员工默认不能导出；
- BOSS/财务可导出企业汇总；
- 店长可导出本门店汇总，字段受控；
- 平台运营可导出平台统计，不含业务正文；
- 所有导出记录审计。

## 11. 技术实现边界

### 11.1 通用记录入口

建议由统一的 AI 调用网关或 Context 负责：

- 幂等键生成；
- 企业、门店和员工快照；
- 能力、模型和费率版本；
- 调用前记录；
- 调用后结算；
- 异常和返还；
- 统计更新。

禁止每个业务 Provider 自己写一套调用记录。

### 11.2 Provider 边界

产品建议的查询能力：

- `ai/usage/report`：企业/门店统计报表；
- `ai/usage/page`：调用明细分页；
- `ai/usage/info`：单笔调用来源和状态；
- `ai/usage/count`：未对账和异常数量。

具体接口、入参、权限和序列化由技术设计冻结，路由必须遵守 `rules.md` 能力命名规范。

### 11.3 数据库边界

- 调用记录必须保留企业归属；
- 门店统计必须保留 `allocationStore` 和原因；
- 账本和调用不可物理删除，纠错通过调整处理；
- 费用和余量以账本为准，统计汇总可重建；
- 迁移编号由 development lane 按当前最大编号申请。

### 11.4 事件与重算

调用记录写入后，统计汇总失败可以重算。

重算规则：

```text
原始调用记录
-> 重新计算资源单位
-> 重新匹配费率版本
-> 重新生成企业/门店日汇总
-> 保留重算日志和版本
```

重算不得改变已正式收费的历史账单，除非形成单独调整记录。

## 16. 结论

A0.1 的目标不是马上收费，而是先把所有 AI 调用变成可追溯的数据：

```text
每次调用有身份
每个企业有总账
每个门店有分摊
每个能力有资源单位
每次失败有原因
每笔差异可对账
```

当企业总量、门店分摊、平台成本和对账机制稳定后，再进入正式点数结算和 AI 资源包收费。

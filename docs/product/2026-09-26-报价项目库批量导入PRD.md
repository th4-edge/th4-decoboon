# 报价项目库批量导入 PRD

> 文档编号：PRD-CATALOG-IMPORT-20260926-001  
> 版本：v1.0  
> 状态：`frozen_for_development`  
> 日期：2026-09-26  
> 上游依据：`ANS-BIZ-20260926-001`、`REQ-BIZ-20260926-001`、模板 V1.0、`DEC-004`、`BR-001`、`BR-003`、`OBJ-001`、`MET-002`、`EV-008`、`EV-009`、`EV-013`、`EV-024`  
> 规划边界：只解锁报价项目库主数据导入；历史项目、合同、报价、应收应付和财务流水迁移继续暂缓

## 0. 执行结论

P0 为客户自助、标准模板优先的批量导入，不承诺任意 Excel 自动识别。

```text
下载 V1.0 模板
-> 发送到电脑微信/文件传输助手
-> 在电脑按固定表头整理
-> 发回微信聊天
-> 小程序选择 .xlsx/.csv
-> 上传并解析
-> 服务端生成暂存预览，不写正式报价项目库
-> 用户确认整批或仅合格行
-> 事务式导入 CatalogItem 及类型明细
-> 返回结果、错误清单和撤销入口
```

本期必须解决：

1. 550 条项目库能在可用时间内完成导入，不要求逐条录入。
2. 预览阶段不写正式报价项目库。
3. 空成本与明确 0 成本可区分。
4. 固定总价不误写为材料单价或人工单价。
5. 重复、错误行、部分导入和撤销都有明确且可追溯的结果。
6. 导入后的项目可立即在设计分项、套餐配置和报价选择中使用。
7. BOSS 才能发起批量导入，服务端不能依赖按钮隐藏。

## 1. 真实业务场景

### 场景 A：单店老板首次建立 550 条项目库

| 项目 | 内容 |
| --- | --- |
| 使用人 | 15 人单店装企 BOSS |
| 触发事件 | 试用装得清，原系统有约 550 条施工、主材和定制项目 |
| 当前动作 | 将原数据复制到 V1.0 模板，保存为 `.xlsx`，通过微信发回手机 |
| 系统下一步 | 解析并显示总行数、可导入、重复、错误、成本待维护数量；BOSS 确认后批量写入 |
| 异常处理 | 表头错误阻断；错误行默认不导入；可二次确认仅导入合格行；空成本标记待维护 |
| 业务结果 | BOSS 不再逐条录入；设计、套餐和报价立即能够引用项目库 |

### 场景 B：2 店装企处理重复编码和固定总价

| 项目 | 内容 |
| --- | --- |
| 使用人 | 25 人、2 店企业 BOSS |
| 触发事件 | 电脑端整理 2,000 条以内项目，其中存在重复编码、系列不同和固定总价定制柜 |
| 当前动作 | 保留原编码，固定总价项目只在“固定总价”列填写金额 |
| 系统下一步 | 编码重复阻断对应行；已有项目默认跳过；固定总价按独立字段预览和导入 |
| 异常处理 | 存在错误时默认整批不导入；BOSS 二次确认可仅导入合格行；导入结果可撤销 |
| 业务结果 | 不覆盖已有价格和工艺，固定总价进入报价后不乘工程量 |

### 场景 C：网络中断后重复上传同一文件

| 项目 | 内容 |
| --- | --- |
| 使用人 | BOSS |
| 触发事件 | 上传或等待解析时网络中断，重新选择同一个文件 |
| 当前动作 | 再次选择相同文件上传 |
| 系统下一步 | 按企业 + 文件 SHA-256 命中已有批次，返回原预览或原结果，不重复写项目 |
| 异常处理 | 上一批次为已失败、已撤销或已过期时允许创建新批次 |
| 业务结果 | 重试幂等，不产生重复报价项目 |

## 2. 范围

### 2.1 P0 必须完成

- 报价项目库维护页的“下载模板”“批量导入”“最近导入记录”。
- 微信聊天文件选择、上传进度、解析进度、失败重试。
- 解析预览、错误清单、重复清单、成本待维护统计。
- 整批确认和“仅导入合格行”二次确认。
- 批次状态、批次结果、批次撤销。
- `.xlsx` 和 UTF-8/BOM CSV。
- 单文件最多 10MB、最多 2,000 个非空数据行。
- 模板 V1.0 的 23 个字段和类型专项字段映射。
- 成本待维护、明确零成本、固定总价在项目库到报价链路的完整口径。
- 服务端 BOSS 权限、企业归属、跨企业拒绝和操作审计。

### 2.2 明确不做

- 任意原表自动识别、同义词 AI 推断和列映射编辑器。
- 多工作表合并、复杂矩阵拆行、图片内价格 OCR。
- 客户上传原表后由服务端代导入。
- 覆盖已有项目编码、名称、价格、工艺或成本。
- 预览页内逐行修改数据。
- 客户、房屋、合同、报价、项目、应收应付和财务历史数据迁移。
- V1.1 模板兼容策略。
- 短信、推送或第三方系统触发导入。

### 2.3 对外表达边界

可以说：

> 支持按 V1.0 标准模板整理报价项目库，在电脑整理后通过小程序上传、预览确认并导入；成本缺失会标记“成本待维护”，不显示假利润。

不可说：

- 任意 Excel 一键导入。
- 历史项目、合同、报价和财务数据已自动迁移。
- 空成本按 0 计算。
- 固定总价等于材料单价。

## 4. 小程序页面与流程

### 4.1 页面清单

| 页面 | 路由 | 类型 | 作用 |
| --- | --- | --- | --- |
| 报价项目库维护 | `/subpackages/quote/pages/catalog/manage` | 修改现有页 | 增加模板下载、批量导入、最近导入记录 |
| 报价项目库导入 | `/subpackages/quote/pages/catalog/import` | 新增 | 文件选择、上传、解析、预览和确认 |
| 导入结果 | `/subpackages/quote/pages/catalog/import-result` | 新增 | 结果、错误清单、批次信息和撤销 |

路由常量需加入 `src/config/index.ts`，页面需加入 `src/pages.json` 的 `subpackages/quote`，页面只调用 `domains/catalog/api.ts`。

### 4.2 入口页流转

```text
报价项目库维护
  ├─ 点击“下载模板” -> 下载 V1.0 -> 打开/分享到电脑微信或文件传输助手
  ├─ 点击“批量导入” -> 报价项目库导入页
  └─ 点击最近导入记录 -> 导入结果页
```

入口页展示：

- 模板版本、更新日期和 SHA-256 校验值。
- “模板下载”“批量导入”主入口；仅 BOSS 可见。
- 简版三步说明：电脑整理、手机选文件、确认导入。
- 最近 10 条导入批次：批次号、状态、时间、新增/部分/失败/撤销、查看结果。

### 4.3 导入页状态

```text
IDLE
-> CHOOSING_FILE
-> UPLOADING
-> PARSING
-> PREVIEW_READY
-> CONFIRMING_PARTIAL（仅存在错误行时）
-> IMPORTING
-> SUCCESS / PARTIAL_SUCCESS / FAILED
```

#### IDLE

展示：

- “先下载 V1.0 模板”按钮。
- “从微信聊天选择文件”按钮。
- 支持 `.xlsx/.csv`、最多 2,000 行、10MB。
- “不要修改表头、不要合并单元格、不要多表拼接”提示。

#### CHOOSING_FILE / UPLOADING / PARSING

- 使用 `uni.chooseMessageFile({ count: 1, type: 'file' })`。
- 客户端预检扩展名和文件大小，服务端再次强校验。
- 上传中显示文件名、进度和取消/重试入口。
- 解析中不展示“导入成功”，不写 `CatalogItem`。
- 上传或解析失败保留当前文件路径，允许重试；用户取消则返回 IDLE。

#### PREVIEW_READY

顶部文件信息：

```text
文件名 / 模板版本 / 总行数 / 导入时间
```

统计卡：

- 可导入。
- 重复跳过。
- 疑似重复。
- 错误。
- 成本待维护。

明细区：

- 可导入项前 20 条摘要：行号、类型、名称、单位、计价方式、售价、成本状态。
- 重复项前 20 条：源行、命中已有项目或文件内行。
- 错误项分页/展开：Excel/CSV 行号、项目名称、字段、原因、原值。
- 疑似重复项：源行、已有项目、系列差异；提供“跳过疑似重复（默认）”或“全部按新增导入”的批次级选择。

操作：

- 无错误：主按钮“确认导入”。
- 有错误：主按钮禁用并显示“存在错误行，不能整批导入”；若可导入数大于 0，显示次按钮“仅导入合格行”。
- “重新选择文件”返回 IDLE。
- “查看全部错误”展开分页清单。

#### CONFIRMING_PARTIAL

二次确认弹窗必须展示：

```text
将导入合格行：X
将跳过错误行：Y
将跳过重复行：Z
疑似重复行处理：跳过 N / 按新增 N
```

用户明确确认后才进入 IMPORTING。

#### SUCCESS / PARTIAL_SUCCESS / FAILED

- 成功：跳到导入结果页。
- 部分成功：跳转结果页并显示“已导入合格行，跳过异常行”。
- 失败：留在导入页显示服务端错误、批次号和“重试解析/重试导入”。
- 接口超时或未知结果：显示“导入结果暂不可确认”，不得显示空数组或伪成功；进入结果页轮询批次状态。

### 4.4 结果页

结果页展示：

- 批次号、状态、原文件、模板版本、导入时间、操作人。
- 总行数、新增、重复跳过、疑似重复跳过、错误、部分导入、成本待维护。
- 本次导入项目的查看入口。
- 错误清单和重复清单。
- “复制错误摘要”入口。
- “撤销本次导入”按钮及不可撤销原因。

结果页必须支持从“最近导入记录”重新打开，不能只在一次跳转时可见。

### 4.5 错误与恢复

| 场景 | 页面表现 | 数据要求 |
| --- | --- | --- |
| 表头错误 | 阻断解析，指出缺失/额外/变更列 | 不创建正式项目 |
| 工作表名称错误 | 阻断解析 | 不创建正式项目 |
| CSV 编码异常 | 阻断，提示 UTF-8 | 不创建正式项目 |
| 行数 > 2,000 | 阻断 | 不解析正式数据 |
| 文件 > 10MB | 阻断 | 不创建批次 |
| 公式单元格包含在数据区 | 标记错误，要求粘贴为数值 | 不采用公式结果 |
| 网络中断 | 允许重新选同文件 | 文件指纹幂等 |
| 导入线程异常 | 批次 `FAILED` | 事务回滚，不保留半批项目 |
| 结果未知 | 批次 `IMPORTING`，轮询 `info` | 禁止重复点击提交 |
| 预览过期 | 批次 `EXPIRED` | 必须重新上传 |

## 5. 模板 V1.0 冻结

### 5.1 版本与完整性

```text
文件名：报价项目库批量导入模板_v1.0.xlsx
版本：V1.0
SHA-256：0791273625f65cf6f021089d58284d17aefaab654ddadea50a67766e0f3638a9
工作表：填写说明 / 报价项目库 / 填写示例 / 选项
正式数据表：报价项目库
正式表头：第 1 行固定，共 23 列
```

解析只读取名为“报价项目库”的表；其他三种工作表仅作说明。模板版本变更必须重新发布模板、同步 SHA-256 和升级兼容策略。

### 5.2 字段映射

| # | 模板列 | 必填 | 目标字段/规则 |
| ---: | --- | --- | --- |
| 1 | 项目类型* | 是 | `CatalogItem.type`；六类枚举 |
| 2 | 项目编码 | 否 | `CatalogItem.code`；长度 ≤64；为空时由现有 `CatalogCodeContext` 生成 |
| 3 | 项目分类* | 是 | `CatalogItem.category`；施工类填写施工阶段 |
| 4 | 项目名称* | 是 | `CatalogItem.name`；长度 ≤256 |
| 5 | 品牌 | 否 | `CatalogItem.brand`；长度 ≤128 |
| 6 | 系列 | 否 | `CatalogItem.series`；长度 ≤128 |
| 7 | 规格/型号 | 否 | `CatalogItem.spec`；长度 ≤256 |
| 8 | 计量单位* | 是 | `CatalogItem.unit`；按标准别名归一 |
| 9 | 计价方式* | 是 | `CatalogItem.pricingMode`；四种枚举 |
| 10 | 材料单价（元） | 按计价方式 | `CatalogItem.materialPrice`；非负、最多两位小数 |
| 11 | 人工单价（元） | 按计价方式 | `CatalogItem.manualPrice`；非负、最多两位小数 |
| 12 | 固定总价（元） | 仅固定总价 | 独立 `fixedTotalPrice`；禁止落入材料或人工单价 |
| 13 | 标准成本单价（元） | 否 | `CatalogItem.costPrice`；空=`待维护`，0=`明确零成本` |
| 14 | 施工工期（天，仅施工） | 否 | `ConstructionItemDetail.durationDays`；非负整数 |
| 15 | 损耗率（%，仅主材，填5代表5%） | 否 | `MaterialItemDetail.lossRate`；0～100，5 表示 5% |
| 16 | 起订量（仅主材） | 否 | `MaterialItemDetail.minimumOrder`；非负数 |
| 17 | 交期（天，仅软装） | 否 | `SoftFurnitureItemDetail.leadTimeDays`；非负整数 |
| 18 | 保修月数（仅电器） | 否 | `ApplianceItemDetail.warrantyMonths`；非负整数 |
| 19 | 柜体板材（仅全屋定制） | 否 | `CustomFurnitureItemDetail.board`；长度 ≤128 |
| 20 | 台面（仅全屋定制） | 否 | `CustomFurnitureItemDetail.countertop`；长度 ≤128 |
| 21 | 施工工艺 | 否 | `CatalogItem.craft`；长文本，导入上限 4,000 字符 |
| 22 | 验收标准 | 否 | `CatalogItem.criterion`；长文本，导入上限 4,000 字符 |
| 23 | 项目说明 | 否 | `CatalogItem.description`；长文本，导入上限 4,000 字符 |

项目类型：

```text

```

计价方式：

```text
材料+人工 / 仅材料 / 仅人工 / 固定总价
```

计量单位别名：

| 模板值 | 目标 `Unit` |

| 处 | `Place` |
| 套 | `Set` |
| 户 | `House` |
| 米、m | `Metre` |
| 厘米、cm | `Centimeter` |
| 步 | `Step` |
| 樘 | `Plate` |
| 块 | `Block` |
| 根 | `Root` |
| 扇 | `Hole` |
| 台 | `Pcs` |

## 6. 校验、价格与重复规则

### 6.1 文件级校验

| 编号 | 规则 | 失败行为 |
| --- | --- | --- |
| F-01 | 扩展名 `.xlsx` 或 `.csv` | 阻断上传 |
| F-02 | 文件 ≤10MB | 阻断上传 |
| F-03 | 数据行 ≤2,000 | 阻断解析 |
| F-04 | XLSX 必须存在“报价项目库”工作表 | `FAILED` |
| F-05 | 表头必须包含 23 个标准列，不允许多余非空列 | `FAILED` |
| F-06 | 表头列名、顺序建议保持模板原样；解析按标准列名识别 | 缺失/拼写变更则阻断 |
| F-07 | 不允许正式数据区合并单元格 | 错误行/解析阻断 |
| F-08 | 数据行公式单元格不导入 | 对应行错误 |
| F-09 | 空行不计数；全为空的行忽略 | 不影响总数 |
| F-10 | 一个文件只允许一个正式数据工作表 | 额外数据表阻断 |

### 6.2 行级校验

| 编号 | 字段 | 规则 | 失败处理 |
| --- | --- | --- | --- |
| R-01 | 项目类型 | 必填，六类之一 | 错误行 |
| R-02 | 项目分类 | 必填，非空 | 错误行 |
| R-03 | 项目名称 | 必填，去首尾空格后非空 | 错误行 |
| R-04 | 计量单位 | 必填，来自枚举或标准别名 | 错误行 |
| R-05 | 计价方式 | 必填，四种之一 | 错误行 |
| R-06 | 项目编码 | 可选，≤64；同企业同类型不允许重复 | 重复跳过或编码冲突 |
| R-07 | 材料+人工 | 材料、人工均明确填写；0 可表示免费，不留空猜测 | 缺失必填价格则错误 |
| R-08 | 仅材料 | 材料必填；人工为空或 0，人工大于 0 报冲突 | 错误行 |
| R-09 | 仅人工 | 人工必填；材料为空或 0，材料大于 0 报冲突 | 错误行 |
| R-10 | 固定总价 | 固定总价必填；材料、人工必须为空 | 错误行 |
| R-11 | 普通售价空白 | 不得把空白当 0 | 错误行 |
| R-12 | 标准成本 | 空、0、正数均允许；空=待维护，0=明确零成本 | 预览统计，不阻断 |
| R-13 | 金额/价格 | 非负数、最多两位小数 | 错误行 |
| R-14 | 工期/交期/保修 | 非负整数 | 错误行 |
| R-15 | 损耗率 | 0～100，5 表示 5% | 错误行 |
| R-16 | 起订量 | 非负数 | 错误行 |
| R-17 | 类型专项字段 | 类型不匹配但非空的专项字段忽略 | 警告，不阻断 |
| R-18 | 文本长度 | 不超过目标字段上限 | 错误行 |
| R-19 | 赠送/零元 | 相关售价明确填写 0 | 允许；空白不视为 0 |

### 6.3 重复策略

去重键：

```text
有编码：企业 + 项目类型 + 项目编码
无编码：企业 + 项目类型 + 项目名称 + 品牌 + 规格/型号 + 计量单位
```

处理：

- 文件内重复：保留第一条，后续进入重复跳过，提示与第几行重复。
- 企业内已有重复：默认跳过，不覆盖价格、成本、工艺和状态。
- 同企业同类型编码存在但其他去重字段不同：编码冲突，错误行，指出已有项目。
- 系列不同但其他去重字段相同：疑似重复，不自动合并。
- 疑似重复默认跳过；用户可在批次级明确选择“全部按新增导入”。
- 同一文件重复上传：按企业 + 文件 SHA-256 命中既有批次，返回原预览或结果；不新增项目。
- 已撤销、失败或过期批次对应的文件指纹不作为命中，可新建批次。
- 不同企业的相同编码、名称和文件指纹互不影响。

## 7. 批次状态机

```text
UPLOADED
  -> PARSED
  -> PENDING_CONFIRM
  -> IMPORTING
       -> IMPORTED
       -> PARTIALLY_IMPORTED
       -> FAILED

PENDING_CONFIRM -> EXPIRED
IMPORTED / PARTIALLY_IMPORTED -> REVOKED
```

| 状态 | 用户含义 | 是否写正式项目库 | 允许动作 |
| --- | --- | --- | --- |
| `UPLOADED` | 文件已上传，等待解析 | 否 | 等待、查看上传错误 |
| `PARSED` | 行数据已解析，正在校验 | 否 | 等待、失败重试 |
| `PENDING_CONFIRM` | 预览已生成，待确认 | 否 | 整批确认、仅导入合格行、重新上传 |
| `IMPORTING` | 正在事务写入 | 进行中 | 查询，不允许重复提交 |
| `IMPORTED` | 已导入，重复项/疑似重复可能已跳过 | 是 | 查看结果、撤销 |
| `PARTIALLY_IMPORTED` | 明确选择仅导入合格行 | 是 | 查看结果、错误清单、撤销 |
| `FAILED` | 解析或导入失败 | 否，事务已回滚 | 同批次重试或重新上传 |
| `EXPIRED` | 预览超时 | 否 | 重新上传 |
| `REVOKED` | 已撤销 | 已删除本批新增项目 | 查看审计结果 |

批次字段至少包括：

```text
batchId / batchNo / company / createdBy
templateVersion / originalFilename / sourcePath / contentType
fileSize / fileSha256 / status
totalRows / readyRows / duplicateRows / suspectedDuplicateRows
errorRows / costPendingRows / importedRows / skippedRows
duplicatePolicy / partialImport
createdAt / parsedAt / confirmedAt / finishedAt / revokedAt / expireAt
```

预览批次默认 24 小时过期；过期后必须重新上传。

## 8. 成本、固定总价和下游联动

### 8.1 标准成本空白的唯一表示

- `costPrice = null`：成本待维护。
- `costPrice = 0`：明确零成本，不得显示为待维护。
- `costPrice > 0`：已维护标准成本。
- 导入预览统计 `costPendingRows`，不把待维护当错误。
- 列表和详情显示“成本待维护”；0 显示“¥0.00（明确零成本）”。
- 关联成本和利润计算必须判断 `null`，不能再使用“小于等于 0 即缺失”。
- 非授权角色不得收到 `costPrice` 或 `costPending` 字段，不能通过把 `costPrice` 置空伪装为待维护后再序列化给前端。
- 所有成本完整性判断必须只把 `null` 视为待维护；明确 0 成本对赠送/免费项目视为完整成本事实。
- 任一应计成本为待维护时，报价/套餐/项目 `costComplete=false`，毛利和毛利率返回 `null`，前端显示“成本未完整”。
- 成本待维护不新增阻断报价或合同主链的门槛；只禁止可靠利润与毛利率展示。

### 8.2 固定总价

- 固定总价使用独立字段，不能写入材料单价或人工单价。
- `pricingMode=FixedTotal` 时：
  - 固定总价必填且非负。
  - 材料单价、人工单价必须为空；持久化兼容值可以保留为 0，但不得参与售价计算。
  - 报价金额等于固定总价，不乘工程量。
  - 报价组件名称显示“固定总价”，不拆成材料/人工组件。
- 非固定总价时，固定总价必须为空。
- 套餐模板引用固定总价项目时，必须保留固定总价语义；按套餐数量换算规则计算时，不能把固定总价误读作材料单价。
- 套餐行的 `quantityFactor` 只表示包含数量或用量换算，不得再次乘以固定总价；套餐总价按比例分摊时，固定总价仍是该行的经济金额基数。
- 合同行继续以最终金额和成本快照为准，不反向修改报价项目库。

### 8.3 下游展示

| 场景 | 展示/计算 |
| --- | --- |
| 项目库列表 | 成本待维护标签；固定总价显示“固定总价，不乘工程量” |
| 项目库详情 | 售价、固定总价、成本状态分开展示 |
| 设计选材 | 可选择成本待维护项目，显示标签；金额按售价计算，利润不可确认 |
| 套餐配置 | 成本预览遇到待维护则显示“成本未完整”；固定总价不拆为材料/人工 |
| 报价生成 | 金额正常生成；成本不完整时报价 `costComplete=false` |
| 合同签约 | 沿用现有签约条件；成本快照标记完整性，不显示伪利润 |
| 合同/项目财务 | 成本不完整时利润和利润率为 `null` |

成本补齐前已经生成的报价/合同快照不自动追溯；后续新生成或明确重算的报价才使用新成本。

## 9. 撤销规则

P0 冻结为：

- 仅 `IMPORTED` 或 `PARTIALLY_IMPORTED` 可撤销。
- 必须在导入完成后的 24 小时内。
- 仅 BOSS 可操作。
- 本批所有新增 `CatalogItem` 均未被设计分项、套餐、报价、合同、任务、材料计划、库存、供货价或其他下游对象引用。
- 无引用时，在事务内删除本批新增项目和类型明细；批次保留结果并标记 `REVOKED`。
- 任意一条已被引用时，整批撤销失败，不进行部分删除；结果页提示“已被业务引用，不能撤销”。
- 已撤销批次不得再次确认；原文件重新上传时按新批次处理。
- 撤销后立刻刷新项目库、设计选择、套餐配置和导入记录，不能继续显示已删除项目。

#### `CatalogImportBatch`

- 唯一编码约束继续使用 `(com_id, type, code)`；服务端确认导入前后均需校验。

### 11.3 下游价格快照

为避免固定总价误写：

- `DesignItem` 增加独立固定总价语义或等价快照字段。

- `ProjectCostContext` 不得把空成本按 0 计算；成本不完整必须传播 `costComplete=false`。

| IM-07 | 550 条全部有效项目一次导入 | 预览总数 550；确认后新增 550；六类明细按类型写入 |
| IM-08 | 550 条包含重复、错误、成本空白和固定总价 | 统计分别准确；预览不写正式项目；确认后数量与预览一致 |

| IM-10 | 550 条导入后在设计师端选材 | 新增项目立即可按类型、分类、品牌、规格和搜索命中 |
| IM-11 | 550 条导入后打开套餐配置 | 项目可被引用；固定总价和成本待维护显示正确 |

服务端处理目标：

- 550 行上传后的解析与预览，在排除网络传输时间后 ≤15 秒。
- 2,000 行上传后的解析与预览 ≤30 秒。
- 超时或连接中断后重新查询批次状态，不重复写入。

### 14.4 成本与固定总价

### 14.5 错误、部分确认和撤销

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| IM-26 | 存在错误行直接整批导入 | 阻断，正式项目库零新增 |
| IM-27 | 仅导入合格行 | 必须二次确认；仅导入合格行；错误行和跳过行有清单 |
| IM-28 | 导入事务中途失败 | 批次 `FAILED`，已写入项目全部回滚 |
| IM-29 | 导入成功后无下游引用，24 小时内撤销 | 本批新增项目全部删除，批次 `REVOKED` |
| IM-30 | 任一新增项目已被设计方案引用 | 整批撤销失败，不删除任何项目 |
| IM-31 | 超过 24 小时撤销 | 拒绝，显示不可撤销原因 |
| IM-32 | 撤销后刷新项目库/设计/套餐/报价 | 已撤销项目不再可选；其他批次不受影响 |

### 14.6 可完成状态与审计

- 批次状态只能由服务端领域状态推导，前端不得用本地布尔决定成功。
- 统计数字必须由 `CatalogImportRow` 实际状态计算，不以接口成功推断全部完成。
- 失败/超时显示“暂不可确认”，保留批次查询和重试路径。
- 预览失败不能显示为 0 条成功。
- 所有导入、确认、撤销记录批次号、操作人、时间、数量和结果。
- 导入记录不得进入报价接受率、转化率、项目毛利等经营指标统计。
- 页面返回、下拉刷新或重新进入后必须重新读取批次和项目库事实。

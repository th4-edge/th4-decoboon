> 文档编号：PRD-CARRYOVER-20260926-001  
> 版本：v0.1  
> 状态：`ready_for_product_review`  
> 日期：2026-09-26  
> 业务依据：`DEC-011`、`SCN-011`、`BR-010`、`SOL-005`、`DEC-004`、`DEC-001`  
> 研发交接：`REQ-BIZ-20260926-002`  
> 研发设计：`docs/design/21-新装企业在跑项目承接P0设计.md`  
> 范围：只承接在跑项目，只做引导式录入；不承接已完工已结清历史，不做批量导入

## 0. 执行结论

P0 解决新装企注册后“已有项目无法继续经营”的问题。

```text
注册企业
-> 选择有在建项目
-> 业务承接首页
-> 逐个项目引导录入
-> 系统校验
-> BOSS/财务/PM确认或BOSS代确认
-> 正式承接
-> 项目进入工地和财务工作台
-> 首笔接管后业务发生后锁定
```

“承接完成”的定义不是导入了多少条数据，而是：

> 项目经理可以继续管理工地，财务可以继续处理未结款，老板可以看到当前真实经营状态，同时历史已结清事实不会污染接管后的经营指标。

## 1. 已冻结业务决策

| 编号 | 决策 |
| --- | --- |
| CARRY-DEC-01 | P0 只做引导式录入，不做在跑项目批量导入 |
| CARRY-DEC-02 | 期初财务只承接当前未结应收、未结应付 |
| CARRY-DEC-03 | 接管前成本允许只知道总额，完整性必须单独标记 |
| CARRY-DEC-04 | 责任角色未建立时允许 BOSS 代确认，必须留痕 |
| CARRY-DEC-05 | 单项目发生首笔真实业务后禁止整批撤回，只允许调整和冲正 |

## 2. 真实业务场景

### 场景 A：单店 8 个在跑项目

- 使用人：BOSS、财务、项目经理。
- 触发事件：企业首次注册，当前有 8 个项目仍在施工或验收。
- 当前处理：项目信息分散在 Excel、微信和纸质文件。
- 系统下一步：首页引导进入业务承接，逐个项目完成五步建档。
- 异常处理：1 个项目负责人不明，进入待确认，不自动分配给 BOSS。
- 业务结果：另外 7 个项目承接完成后进入项目经理和财务工作台。

### 场景 B：项目已部分收款且存在供应商欠款

- 使用人：BOSS、财务。
- 触发事件：项目合同金额 30 万元，接管前已收 18 万元，接管日未收 12 万元。
- 系统下一步：只将 12 万元登记为期初应收，供应商未付部分登记为期初应付。
- 异常处理：历史已收 18 万元没有原始依据时，只记录接管摘要和附件，不生成正常收款流水。
- 业务结果：接管后再收 5 万元，当月收入只增加 5 万元，当前未收余额变为 7 万元。

## 3. 角色与权限

| 角色 | 职责 |
| --- | --- |
| BOSS | 发起承接、确认项目范围、报价合同、归属和最终提交；必要时代确认 |
| 财务 | 确认期初应收应付、接管前成本总额及完整性 |
| 项目经理 | 确认当前状态、阶段、剩余施工和现场重点 |
| 设计师 | 按需确认报价、合同范围和有效增减项 |
| 系统 | 校验、生成基线、记录来源和审计痕迹 |

权限规则：

- 所有数据按当前企业隔离。
- 用户不能通过前端参数指定其他企业、门店、团队或负责人。
- 成本字段沿用现有成本可见范围。
- BOSS 代确认不豁免负责人缺失、金额冲突和跨企业校验。
- 代确认记录：应确认角色、实际确认人、时间、版本和确认内容摘要。

## 4. P0 范围

### 4.1 必须完成

- 注册后增加“是否有在建项目”选择。
- 首页业务承接任务卡片。
- 承接项目列表和进度。
- 单项目五步引导录入。
- 系统预览和异常提示。
- 分角色确认和 BOSS 代确认。
- 接管基线报价和合同基线。
- 在跑项目及当前工地摘要。
- 当前未结应收应付。
- 接管前成本总额和完整性。
- 项目来源标识和承接结果页。
- 项目进入现有工地和财务工作台。
- 首笔业务后的锁定与调整规则。

### 4.2 明确不做

- 在跑项目客户自助批量导入。
- 任意 Excel、CSV 字段识别和同义词推断。
- 服务侧批量承接后台。
- OCR 合同和纸质资料识别。
- 已完工且已结清项目迁移。
- 历史资金台账、收款、付款重建。
- 完整历史报价版本和报价行重建。
- 完整历史施工节点、日报和验收重建。
- 接管后整批覆盖重导。

现有“报价项目库批量导入”保持独立，不属于本 P0。

## 5. 产品入口和页面

### 5.1 注册后模式选择

位置：企业创建成功后。

问题：

> 贵公司现在是否有正在施工、验收或收尾的项目？

选项：

- 暂没有，从新项目开始；
- 有，我要承接在建项目；
- 暂不确定，稍后处理。

选择“有”时创建业务承接任务，不阻塞企业创建。

### 5.2 首页承接卡片

文案结构：

- 标题：还有 N 个在跑项目未承接；
- 说明：完成承接后，项目经理可继续管工地，财务可继续处理未结款；
- 主操作：继续承接；
- 次操作：查看说明；
- 异常态：承接数据暂不可确认，点击重试。

### 5.3 业务承接首页

展示：

- 接管日期；
- 待承接数量；
- 待确认数量；
- 已完成数量；
- 待补齐数量；
- 项目列表；
- 下一步推荐项目。

### 5.4 项目承接列表

每个项目展示：

- 项目名称；
- 客户和房屋；
- 当前阶段；
- 负责人；
- 承接状态；
- 缺失事项数量；
- 最近修改时间；
- 下一步动作。

状态只由真实对象推导：

| 状态 | 完成条件 |
| --- | --- |
| 待录入 | 尚未形成完整项目基线 |
| 待验证 | 已保存，等待系统校验 |
| 待确认 | 校验通过，等待角色确认 |
| 可承接 | 必填事实和确认完整 |
| 已承接 | 已生成正式业务基线 |
| 已续营 | 已发生接管后首笔真实业务 |
| 待修复 | 校验或确认发现问题 |

### 5.5 项目五步承接向导

#### 第一步：客户与房屋

字段：

- 客户姓名；
- 手机号；
- 房屋地址；
- 小区；
- 楼栋、房号；
- 面积；
- 房屋负责人。

规则：

- 一客户多房屋逐套建立；
- 房屋必须绑定客户；
- 地址文本不能代替房屋档案。

#### 第二步：报价与合同基线

字段：

- 合同编号；
- 合同金额；
- 当前金额；
- 签约日期；
- 开工日期；
- 原报价编号；
- 原报价单或合同附件；
- 当前有效增减项说明。

系统生成接管基线报价和合同基线。基线不得进入报价接受率和设计师待报价工作台。

#### 第三步：当前项目与工地

字段：

- 项目名称；
- 项目状态；
- 当前阶段；
- 当前进度；
- 剩余施工摘要；
- 当前主要待办；
- 当前风险或待协调事项。

规则：

- 不重建历史任务和历史验收；
- 已完成的接管前事实只保留摘要和附件；
- 项目状态使用真实项目状态，不新增第二套状态机。

#### 第四步：期初财务与成本

应收：

- 当前未收金额；
- 到期日；
- 原单号；
- 说明；
- 或明确选择“无未结应收”。

应付：

- 当前未付金额；
- 到期日；
- 收款方或供应商；
- 原单号；
- 说明；
- 或明确选择“无未结应付”。

接管前成本：

- 已发生成本总额，可空；
- 完整性：已确认完整、只知道总额、暂不确认；
- 截止日期；
- 缺失说明。

规则：

- 金额空白表示未确认，不能按 0 处理；
- 明确 0 必须由企业确认；
- 完整性未确认时利润和毛利率为空。

##### 期初财务术语与准确性交互

不同装企对财务名词的叫法不同，页面必须同时给出口径说明和行业同义词：

| 系统字段 | 通俗解释 | 可接受的其他叫法 | 计算公式 |
| --- | --- | --- | --- |
| 客户未收工程款 | 接管日客户仍欠的工程款 | 应收未收、尾款、客户欠款 | 应收总额 - 已收款合计 |
| 当前未付款 | 接管日企业仍欠供应商、工人或班组的钱 | 应付未付、供应商欠款、工资待付、项目款待付 | 应付总额 - 已付款合计 |
| 接管前已发生成本 | 项目至今已经产生的材料、人工、项目及其他成本 | 累计成本、已发生成本 | 已付成本 + 未付成本，不等于未付款 |

准确性交互：

1. 每个金额字段展示计算公式和示例。
2. 提供“无未收款”“无未付款”快捷入口，明确写入 0 并自动要求确认。
3. 当前未收超过当前合同金额时实时提示并阻断提交。
4. 接管前成本与未付款分别解释，禁止把未付余额误填为累计成本。
5. 提交承接前弹出财务数据摘要，展示合同金额、未收款、未付款、已发生成本和成本完整性。
6. 客户确认不是普通勾选，而是明确确认“以上是接管日未结余额，不是历史累计流水或未来预算”。

### 第五步：附件与提交前检查

附件类别：

- 合同；
- 报价；
- 当前工地关键照片；
- 财务依据；
- 其他承接说明。

提交前显示：

- 已完成项；
- 待确认项；
- 阻断项；
- 数据来源；
- 确认人和确认时间。

## 6. 系统校验

### 字段校验

- 必填项；
- 金额和日期格式；
- 客户、房屋、合同关系；
- 成本完整性枚举；
- 无应收/应付的显式确认。

### 业务校验

- 项目是否属于在跑范围；
- 负责人是否属于当前企业；
- 同一客户、房屋、合同是否重复；
- 报价和合同是否指向同一客户与房屋；
- 项目是否已经存在正常项目对象。

### 金额校验

- 未收、未付不能为负；
- 未结余额必须大于 0，或明确选择无余额；
- 合同金额与期初应收冲突时进入待确认；
- 成本完整性未确认时利润为空。

### 人工确认

```text
BOSS 确认项目范围和归属
-> 财务确认余额和成本
-> PM 确认工地状态
-> 系统生成可承接结果
```

角色未建立时允许 BOSS 代确认，但保留“代确认”标记。

## 9. 可完成状态投影

完成状态必须由真实承接对象和确认记录推导，禁止使用前端本地布尔值。

| key | label | required | 完成条件 | 异常态 |
| --- | --- | --- | --- | --- |
| `mode` | 入驻模式 | 是 | 企业已选择“有在建项目”并形成承接任务 | 未选择时显示待选择 |
| `scope` | 承接范围 | 是 | 项目清单已由 BOSS 确认为本次承接范围 | 接口失败显示“暂不可确认” |
| `customerProperty` | 客户与房屋 | 是 | 当前项目绑定客户和唯一具体房屋 | 关系不完整进入待补齐 |
| `owner` | 责任归属 | 是 | 经营负责人和项目经理明确 | 缺失进入待确认，禁止猜测 |
| `quoteContract` | 报价合同基线 | 是 | 合同金额、当前金额和报价/合同附件存在 | 缺金额或缺基线时阻断提交 |
| `siteBaseline` | 当前工地 | 是 | 当前状态、阶段和剩余工作摘要已确认 | 状态冲突时进入待确认 |
| `receivable` | 期初应收 | 条件必填 | 存在未收余额，或明确确认“无未结应收” | 金额未知或未确认时项目不能完成 |
| `payable` | 期初应付 | 条件必填 | 存在未付余额，或明确确认“无未结应付” | 金额未知或未确认时项目不能完成 |
| `costBaseline` | 接管前成本 | 是 | 总额和完整性状态已分别记录 | 完整性未确认时项目可承接但利润为空 |
| `confirmations` | 业务确认 | 是 | BOSS、财务、PM 对应确认存在，或存在 BOSS 代确认留痕 | 标记应确认角色和实际确认人 |
| `projectComplete` | 项目承接完成 | 是 | 以上必填项完成且正式业务对象已生成 | 任一阻断项存在时保持未完成 |
| `batchComplete` | 企业承接完成 | 条件 | 所有在范围内项目均已完成或明确排除并留痕 | 存在待确认项目时显示部分完成 |

## 10. 修复和调整

### 提交前

- 直接编辑；
- 重新选择附件；
- 修改负责人；
- 标记无未结余额；
- 暂缓项目。

### 已承接但未发生首笔业务

- 允许单项目撤回；
- 修改后重新提交；
- 调整期初金额和成本说明；
- 重新确认。

### 已发生首笔业务

- 禁止整批撤回；
- 禁止删除重建；
- 禁止覆盖期初金额；
- 财务错误走冲正；
- 期初余额错误走调整；
- 负责人错误走项目交接；
- 阶段错误走状态更正并记录原因。

其他未发生业务的项目不受影响，可以继续撤回或重新承接。

## 12. 实现方案冻结

五个实现项已按 P0 最小范围收敛：

1. 新增 `carryover` 领域承载承接任务，首页引导复用现有入驻聚合，但承接状态真源为 `CarryoverBatch` 和 `CarryoverProject`。
2. 期初余额复用现有应收、应付对象，每个项目最多一条汇总期初记录；金额等于接管日未结余额。
3. 接管前成本使用独立 `CarryoverCostSnapshot`，与接管后实际成本合并；任一段不完整时利润为空。
4. `Quote`、`ProjectContract`、`Project`、`Receivable`、`Payable` 增加 `BusinessOrigin` 来源；接管数据为 `Carryover`，存量和新业务为 `New`。
5. 首笔业务在业务事务内锁定单项目，记录首次业务类型和时间；锁定后只允许调整、更正或冲正。

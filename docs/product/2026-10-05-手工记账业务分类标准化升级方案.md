# 手工记账业务分类标准化升级方案（v1）

> - 状态：设计冻结，进入研发；内置分类名称与清单待用户最终确认
> - 日期：2026-10-05
> - 范围：App 财务工作台 → 手工记账「记一笔」、资金台账历史补关联、业务分类维护
> - 业务决策来源：用户 2026-10-05 明确指令（来源权威顺序第 1 级）
> - 关联现状：`232ff71 feat(finance): 完善资金台账分类与履约工作台`、迁移 `68-手工记账分类与更正审计.sql`
> - 业务边界：对齐 `DEC-005`，本方案管理的是**装得清经营业务分类**，不是会计科目、借贷分录、法定总账或税务口径

## 1. 背景与问题

上一版已经落地 `db_finance_ledger_category` 分类表和 `db_finance_ledger.category_id`：
每个企业首次读取分类树时懒生成内置分类，企业可追加自定义分类；手工记账可以选择分类，但仍保留自由文本输入。

线上实测与代码核对后确认四个问题：

1. **双轨口径**：`Ledger.category` 是必填文本，`categoryNode` 只是可选关联。客户端可以只填文本不选分类，导致同一含义出现「主材」「主材采购」「买材料」多种写法，无法稳定汇总。
2. **收入侧没有二级分类**：内置模板只有支出有二级，收入一级直接可选，无法按首期款/进度款/尾款等经营口径细分。
3. **历史文本无法发现和补关联**：已有手工流水保留 `category_id = null`，但台账没有「待关联」视图，客户无法系统性补齐。
4. **内置模板偏薄**：材料、人工、项目、运营、税费之外，缺少家装常见的设计收入、服务收入、获客返点、设备租赁、售后维修、社保意外险等场景口径。

## 2. 目标与非目标

### 2.1 目标

1. 每个企业内置一套「装得清家装经营分类模板 v2」，收入、支出均为**一级分组 + 二级业务分类**。
2. 手工记账的**唯一事实源是分类关联**：服务端按 `categoryNode` 推导 `category` 快照，客户端不得再提交自由文本。
3. 线上已有手工流水**一条不丢**：`category_id` 为空即「待关联业务分类」，台账可筛选、逐笔补关联。
4. 企业负责人、财务可自定义维护业务分类：新增、更名、停用/删除（逻辑停用），内置分类只读。
5. 分类变更不影响历史流水：历史关联保留，停用后仅禁止新记账选择。

### 2.2 非目标

- 不做会计科目、借贷分录、凭证分录、法定总账和税务申报口径（`DEC-005`）。
- 不把收付款自动生成流水（Receipt/Payment）纳入本期人工归类改造；其 `category` 仍是系统生成的文本快照。
- 不物理删除历史 `db_finance_ledger.category` 文本，也不做批量静默猜测映射。
- 不改造 Web 端财务只读驾驶舱；本期交互落在 App 财务工作台。

## 3. 真实业务场景闭环

### 场景 A：老板/财务记一笔支出

| 环节 | 内容 |
| --- | --- |
| 使用人 | 企业负责人（Boss）或财务（Finance） |
| 触发事件 | 发生一笔展会推广支出，需要进入资金台账 |
| 前置条件 | 已登录本企业；具备财务写权限；分类树已内置 |
| 当前动作 | 财务工作台 → 记一笔 → 支出 → 选择二级分类「运营费用 / 获客推广费」→ 金额、账户、日期、摘要 |
| 系统下一步 | 校验分类属于本企业、方向一致、为可选二级；保存手工流水并写入 `category_id`；`category` 由服务端回写为分类名称快照 |
| 异常处理 | 没有合适二级分类：现场新增自定义二级分类（挂到「运营费用」下），保存后立即选中；自定义分类仅本企业可见 |

### 场景 B：财务补关联历史流水

| 环节 | 内容 |
| --- | --- |
| 使用人 | 财务（Finance）或企业负责人（Boss） |
| 触发事件 | 打开资金台账，顶部提示「有 N 笔历史手工流水待关联业务分类」 |
| 前置条件 | 流水来源为手工记账且 `category_id` 为空；数据为当前企业可见范围 |
| 当前动作 | 进入「待关联」筛选 → 点某笔「补充分类」→ 参考原文本 → 选择二级分类 → 填写原因 → 保存 |
| 系统下一步 | 仅更新分类关联与快照，写入分类补全修订记录；金额、方向、项目、日期、摘要均不变 |
| 异常处理 | 原文本与某个二级分类完全同名时，仅作为「建议」展示，必须由人工确认，系统不静默自动映射 |

### 场景 C：自定义分类停用后的影响

| 环节 | 内容 |
| --- | --- |
| 使用人 | 企业负责人或财务 |
| 触发事件 | 某自定义分类不再使用 |
| 当前动作 | 分类管理 → 删除该分类（逻辑停用） |
| 系统下一步 | 新记账不可再选；历史流水继续显示原分类名称；自定义一级停用会连带停用其二级 |
| 异常处理 | 内置分类不可删除/停用；如确需调整口径，用自定义二级补充，不改内置编码 |

## 4. 领域模型

### 4.1 `LedgerCategory`（业务分类）

| 字段 | 含义 | 规则 |
| --- | --- | --- |
| `categoryId` | 分类主键 | 雪花 ID |
| `company` | 所属企业 | 必填，租户隔离根 |
| `parent` | 上级分类 | 二级必填；一级为空；最多两级 |
| `name` | 分类名称 | 同级 + 同方向不重名；长度 ≤ 64 |
| `direction` | 收支方向 | `Income` / `Expense`；父子方向必须一致 |
| `code` | 内置稳定编码 | 内置必填且不可变；自定义为空 |
| `builtIn` | 是否内置 | 内置只读；自定义可维护 |
| `sort` | 排序 | 同级排序，默认系统值在前、自定义在后 |
| `active` | 是否启用 | 逻辑停用，不做物理删除 |
| `createdBy` | 创建人 | 自定义分类必填 |

### 4.2 `Ledger`（资金流水）分类字段

| 字段 | 本期口径 |
| --- | --- |
| `categoryNode` | 手工记账**唯一事实源**，新记账必填，必须为可选二级分类 |
| `category` | 服务端维护的分类名称快照（历史文本也保留在此）。客户端只读；用于凭证打印、旧客户端兼容和历史回显。全量补关联完成后再评估物理清理 |
| `source` | `Manual` 且 `categoryNode = null` 判定为「待关联业务分类」 |
| `correctionGroupId` / `originalLedger` | 更正审计，不受本次分类升级影响 |

### 4.3 可选项判定

- 一级分类存在启用子分类时：**一级仅作分组，不可直接记账**。
- 二级分类、以及没有任何启用子分类的自定义一级分类：可选。
- 收支方向不一致、已停用、非本企业分类：一律按「分类不存在或无权访问」处理。

## 6. 业务规则（冻结）

| 编号 | 规则 |
| --- | --- |
| CAT-01 | 分类最多两级；一级分组、二级可记账 |
| CAT-02 | 手工记账必须选择可选二级分类，禁止自由文本入库 |
| CAT-03 | 分类方向必须与流水收支方向一致 |
| CAT-04 | 内置分类不可新增重名、不可改名、不可停用、不可删除 |
| CAT-05 | 企业负责人、财务可新增自定义二级/一级分类；同级同方向不重名 |
| CAT-06 | 分类删除为逻辑停用；停用后历史流水仍可展示，新记账不可选 |
| CAT-07 | 后端保存时企业取登录员工所属企业，禁止信任前端企业字段 |
| CAT-08 | 历史 `category_id` 为空的手工流水标记为「待关联」，不阻塞查询与凭证 |
| CAT-09 | 补关联只改分类关联与快照，写入修订记录；不自动改金额、项目、日期、摘要 |
| CAT-10 | `category` 文本快照由服务端生成，客户端传入值一律忽略 |

## 7. 标准流程与状态变化

### 7.1 记一笔

```text
进入记一笔
  -> 选择收支方向
  -> 打开业务分类树（服务端按企业懒生成内置模板）
  -> 选择可选二级分类（方向必须一致）
  -> 填写金额/账户/日期/摘要
  -> 保存：分类关联 + 快照 + 审计字段
  -> 台账/报表按 category_id 汇总
```

失败分支：金额 ≤ 0、未选分类、选了分组一级、方向不一致、跨企业分类，均返回明确错误，不产生流水。

### 7.2 自定义维护

```text
企业负责人/财务进入分类管理
  -> 新增到某一级下（二级）或新增一级
  -> 校验同级同方向重名、层级不超过两级、方向一致
  -> 保存后立即可选
  -> 更名：只改名称，历史流水保留原关联与历史快照
  -> 删除：置 active=false；一级删除连带停用其二级
```

### 7.3 历史补关联

```text
资金台账 -> 待关联业务分类（source=Manual 且 category_id is null）
  -> 选择一笔 -> 显示原分类文本作为参考
  -> 选择目标二级分类 -> 填写原因 -> 保存
  -> 更新 category_id + category 快照 + 修订记录
  -> 待关联计数减少；仍可继续下一笔
```

### 7.4 分类口径调整

- 内置分类名称由版本统一升级；企业个性化用自定义二级承载，避免改内置导致跨企业口径漂移。
- 历史关联对象不因分类停用而断开；报表按历史 `category_id` 的当前名称展示，若需保留更名前快照，以修订记录为准。

## 8. 数据与迁移

1. **不新增 DDL**：迁移 68 已提供 `category_id`、修订表和索引。
2. **存量流水不动**：已有 `category` 文本保留在列内，`category_id` 为空的手工流水进入「待关联」。
3. **内置分类增量补齐**：读取分类树时按模板幂等补齐；不删除企业自定义分类。
4. **不自动映射文本**：禁止按名称模糊匹配批量回填，避免错账；仅允许完全同名时给用户展示建议。
5. **回滚**：本次为代码级变更，回滚代码后旧版本仍可读 `category` 文本；已补关联的 `category_id` 是新增可选字段，不影响旧版本。
6. **发布门禁**：按试运营轻量规范执行定向测试 + 构建 + 必要冒烟；涉及生产数据写入前的备份/回滚说明随发布记录执行。
7. **发布顺序**：必须先具备支持 `categoryId` 的 App（与后端同批或 App 先行），再让后端强制关联；若后端需先行，需保留自由文本过渡兼容窗口，避免线上旧 App「记一笔」直接失败。

## 9. 接口契约变更

| 路由 | 变更 |
| --- | --- |
| `finance/ledger/save` | `categoryId` 必填；忽略/移除自由文本 `category`；服务端写快照 |
| `finance/ledger/update` | Boss/Finance 可仅补关联 `categoryId`；其他元数据更正仍限 Boss；写修订记录 |
| `finance/ledger/correct` | 冲正重记必须携带 `categoryId`；服务端生成快照 |
| `finance/ledger/page` | 新增 `categoryId` 精确筛选、`uncategorized=true` 待关联筛选 |
| `finance/ledger/report` | 同步新增 `categoryId` / `uncategorized`，仅影响筛选，不改变金额公式 |
| `finance/ledger-category/tree` | 返回两级树；一级有子分类时不可作为记账选项 |
| `finance/ledger-category/save|update|delete` | Boss/Finance 维护；内置只读；删除为逻辑停用 |

金额、方向和账户口径保持不变：流水金额仍为正值 + `direction` 表达收支，汇总公式 `净现金流 = 收入 - 支出`。

## 10. UI 设计

### 10.1 记一笔（手工记账）

- 业务分类改为**必选选择器**，删除自由文本输入框。
- 未选择时提示「请选择业务分类」；选择后展示「一级 / 二级」路径。
- 历史流水编辑时显示「原分类：xxx（待关联）」，作为选择参考，不自动带入。

### 10.2 业务分类选择器

- 一级分类可展开；有二级的一级**不可直接选中**，点击展开引导选择二级。
- 无二级的自定义一级可按一级选择。
- 顶部展示当前选择；历史文本以「待关联」提示展示。
- Boss/Finance 可直接新增二级分类并立即选中；自定义分类可编辑、删除；内置分类只读。

### 10.3 资金台账

- 顶部出现「有 N 笔历史手工流水待关联业务分类」横幅（仅 Boss/Finance 显示处理入口）。
- 增加「待关联」筛选；流水卡片显示「待关联」标签，点击可进入补关联。
- 未关联流水仍参与金额汇总，不因分类缺失被隐藏或计为 0。

## 12. 验收标准与测试矩阵

### 12.1 验收标准

1. 新企业首次读取分类树即得到收入/支出两套两级内置分类。
2. 手工记账不选分类无法保存；选择一级分组保存失败并提示选择二级。
3. 选择二级分类保存成功，台账按 `category_id` 精确筛选和汇总。
4. Boss/Finance 可新增自定义二级并立即用于记账；普通员工、店长不可维护。
5. 历史 `category_id` 为空的手工流水在台账显示「待关联」，可逐笔补关联，金额与项目不变，产生修订记录。
6. 分类停用后历史流水仍展示，新记账不可选。
7. 跨企业分类、方向不一致分类无法使用。
8. 修正前后金额汇总口径不变，净现金流公式不变。

| 只读角色 | 店长 | 新增分类 | 拒绝 |

| 补关联 | Finance | 只传 categoryId + reason | 关联成功、金额项目不变、有修订记录 |
| 停用分类 | Boss | 停用自定义二级 | 历史保留；新记账不可选 |
| 汇总不变 | Boss | 含未关联流水 | 金额汇总包含未关联流水，净现金流公式不变 |

## 13. 风险与回滚

| 风险 | 控制 |
| --- | --- |
| 存量文本与新分类语义不一致 | 不做静默映射；逐笔人工确认，保留历史快照 |
| 旧 App 仍提交自由文本 | 服务端忽略文本并强制 `categoryId`；旧版本保存将被明确拒绝，提示升级 |
| 内置模板调整影响存量关联 | 复用原一级 code、只增量补二级；不删除、不重建 |
| 分类停用导致历史报表缺名 | 关联对象不删除；停用仅影响可选性 |
| 回滚 | 代码可回滚；`category_id` 可选字段不强依赖，旧代码继续读 `category` 快照 |

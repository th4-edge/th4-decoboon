## 2. 定位与边界

| 做 | 不做 |
| --- | --- |
| 员工固定工资、考勤扣款、提成、实发计算 | 法定会计总账、会计科目、借贷分录 |
| 月度工资单与工资条 | 完整 HR（招聘、劳动合同、晋升、排班） |
| 考勤月度申报与确认 | 标准打卡、迟到早退、加班费 |
| 提成与签约/回款联动 | 个税代扣代缴申报、社保代缴 |
| 工资应付、发放、资金流水、项目成本归集 | 税务申报、审计报告 |
| 公司经营利润（新增设计） | 对外宣称财务净利润/税务利润 |

**核心定性：员工工资 ≠ 工人工资。**

- `PayableType.Salary` 现为「工人工资/班组劳务」，进入 `laborCost` 和项目毛利，是工人链路的成本。
- 员工工资是**企业内部成员薪酬**，必须另立语义，不得复用 `PayableType.Salary`，也不得与工人工资合并统计。

## 3. 术语与对象

### 3.1 术语定义

| 术语 | 统一含义 | 容易混淆 |
| --- | --- | --- |
| 员工 | 有系统账号的企业成员，固定 7 类角色 | 不等于工人、班组 |
| 工人 | 无系统登录账号的施工个人，企业级共享档案 | 不等于员工 |
| 固定工资 | 按月约定的底薪，不含提成、奖金 | 不等于应发工资 |
| 考勤 | 月度出勤、请假、缺勤的确认事实 | 不等于工资扣款本身 |
| 提成 | 按业绩规则计算的浮动薪酬 | 不等于项目成本或利润 |
| 应发工资 | 固定工资折算 + 提成 + 奖金 + 补贴 | 不等于实发 |
| 扣款 | 考勤扣款 + 社保个人 + 个税 + 其他扣款 | 借支冲减需单独定义 |
| 实发工资 | 应发 − 扣款，实际打款金额 | 不等于工资成本 |
| 工资单 | 某周期全员工资汇总单据 | 不等于一张应付 |
| 工资项 | 工资单内某员工的一行明细 | 不等于发放流水 |
| 计提 | 提成按规则确认，形成应付/成本 | 不等于发放 |
| 发放 | 实际打款动作 | 不等于成本确认 |

### 3.2 对象与关系（候选命名，研发前冻结）

```text
薪酬方案 CompensationScheme（员工 + 生效期 + 固定工资/提成规则）
      |
考勤记录 AttendanceRecord（日/次粒度事实）
  -> 考勤汇总 AttendanceSummary（月度确认结果，工资输入）
      |
提成明细 CommissionItem（业绩归属 + 计算过程 + 计提/发放状态）
      |
工资单 PayrollSheet（周期批次）
  -> 工资项 PayrollItem（员工级明细：固定/提成/考勤/实发）
      |
复用 Payable（员工工资应付） -> Payment（发放核销） -> Ledger（支出流水）
      |
工资条（员工可见） / 工资发放凭证（套打，按需）
```

复用对象：`Payable`、`Payment`、`Ledger`、`Project`、`Employee`、`Company`。**不新建第二套账、不新建独立资金流水。**

### 3.3 与现有模型的落差（研发必须知道）

| 现有对象 | 现状 | 缺口 |
| --- | --- | --- |
| `PayableType` | `Salary` = 工人工资 | 缺「员工工资」独立语义 |
| `Payable` | 有 `payeeEmployee` | 与工人工资语义混用 |
| `Payment` | 有 `partner`、`worker` | **缺员工关联** |
| `FinanceSummary` | 有 `salaryPayableAmount`（工人工资） | 缺员工工资与企业费用口径 |
| 权限 | `@DataPermission` 按公司/门店/团队/本人 | 缺工资敏感字段与「本人工资条」权限 |

## 4. 真实场景推演

### 场景 A：10 人装企月度固定工资 + 考勤

| 项 | 内容 |
| --- | --- |
| 使用人 | 财务（核算）、店长（确认本店考勤）、BOSS（确认工资单） |
| 触发事件 | 月末结算，设计师请假 2 天、行政迟到不计、外勤视同出勤 |
| 前置条件 | 员工已建薪酬方案；当月考勤已申报；店铺/企业月历已确认 |
| 当前动作 | 财务生成工资单草稿，系统按固定工资折算并扣考勤 |
| 系统下一步 | 草稿 → 财务复核 → BOSS 确认 → 生成员工工资应付 → 发放 → 台账 |
| 异常处理 | 考勤未确认 → 工资单标记「考勤未确认」，不可确认；员工申诉 → 退回重算 |
| 成本归属 | 项目人员归属企业则进企业费用；项目归属部分进对应项目成本 |

### 场景 B：设计师签约计提 + 回款发放提成

| 项 | 内容 |
| --- | --- |
| 使用人 | 财务（计提与发放）、BOSS（规则确认） |
| 触发事件 | 客户签约（设计师张三）→ 按签约额计提；客户回款到账 → 触发发放 |
| 前置条件 | 提成规则已配置；业绩归属明确；合同/回款事实存在 |
| 当前动作 | 系统生成提成明细，按「签约额 × 比例」计提并单独形成应付 |
| 系统下一步 | 计提确认计项目成本 → 回款后并入当月工资单或单独发放 → 核销应付 → 支出流水 |
| 异常处理 | 客户退单/退款 → 负向提成冲减；项目亏损 → 按预冻结规则处理；离职 → 按预冻结规则结清 |
| 关键约束 | 同一笔提成不得既进项目成本又进企业费用；已发放只能补差，不得改历史 |

### 场景 C：店长与员工权限边界

| 项 | 内容 |
| --- | --- |
| 使用人 | 店长、普通员工 |
| 触发事件 | 店长查看本店员工工资；员工查看本人工资条 |
| 当前动作 | 店长在门店范围查看本店员工个人工资构成；员工仅看本人工资条、提成与考勤 |
| 系统下一步 | 店长跨店访问被拒；员工访问他人被拒；敏感字段（银行账号/身份证/个税）对店长脱敏 |
| 异常处理 | 跨企业/跨门店请求按「不存在或无权访问」处理；越权写审计 |

### 场景 D：离职月折算与发放失败补发

| 项 | 内容 |
| --- | --- |
| 使用人 | 财务 |
| 触发事件 | 员工 15 日离职，当月工资按在职天数折算；发放日银行退回 |
| 当前动作 | 按在职天数计固定工资，形成工资项；发放失败保留应付未清 |
| 系统下一步 | 补发重试，核销应付，写且仅写一次资金流水 |
| 异常处理 | 已发部分错误 → 下期补差/补扣，不改历史工资单与历史发放流水 |

| 数据/动作 | BOSS | 财务 | 店长 | 团队负责人 | 员工本人 |
| --- | --- | --- | --- | --- | --- |
| 薪酬方案编辑 | ✅ | 只读 | ❌ | ❌ | ❌ |
| 全员工资单 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 本店员工个人工资 | ✅ | ✅ | ✅（仅本店） | ❌ | ❌ |
| 个人工资条 | ✅ | ✅ | ✅（涉本店） | ❌ | ✅仅本人 |
| 考勤录入/确认 | ✅ | ✅ | ✅本店 | 待定 | 只申诉 |
| 提成明细 | ✅ | ✅ | ✅本店 | 待定 | ✅仅本人 |
| 工资发放 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 公司经营利润 | ✅ | ✅ | 待定 | ❌ | ❌ |

**强制安全规则**

1. 店长仅可见登录员工所属门店内的员工工资，跨店、跨企业一律拒绝。
2. 店长不可见 BOSS、财务、其他门店员工工资；自己的工资走「本人」视图。
3. 员工仅可见本人工资条、本人提成、本人考勤，不可见同事。
4. 银行卡、身份证、个税明细等敏感字段默认仅 BOSS/财务可见，店长与本人按需脱敏（OPEN-05）。
5. 工资权限是独立于 `@DataPermission` 的敏感维度；`@Properties` 必须按角色裁剪响应字段。
6. 所有越权按「不存在或无权访问」处理，不泄露他人工资是否存在。

## 6. 状态机

### 6.1 考勤

```text
草稿 -> 待确认 -> 已确认 -> 已入工资单
                 \-> 申诉中 -> 退回重算
```

- 只有「已确认」的月汇总才能进入工资单。
- 已入工资单的考勤锁定，调整走下期补差或退回重算（需留痕）。

### 6.2 提成

```text
待计提 -> 已计提（待发放） -> 已入工资单 -> 已发放 -> 已关闭
                                  \-> 已冲减（退单/退款）
```

- 「已计提」即确认成本（OPEN-01）。
- 已发放提成不得修改，负向调整进入下期。

### 6.3 工资单

```text
草稿 -> 待确认 -> 已确认（应付已生成、成本已计） -> 部分发放 -> 已发放 -> 已关闭
   \-> 作废/退回重算（未发放）
```

**可完成状态投影（强制）**

- 「工资单已完成」只能由「应付已生成 + 发放完成 + 考勤已确认 + 提成已确认」推导，禁止前端布尔或演示数据。
- 分母区分必做项（固定工资、应发、实发）与可选项（社保、个税）。
- 新增/编辑/删除/状态变化后必须重新读取。
- 接口异常表达为「暂不可确认」并保留恢复路径，禁止用空数据伪装完成。

## 7. 金额公式与口径

### 7.1 应发与实发

```text
应发工资 = 固定工资折算 + 提成 + 奖金 + 补贴
扣款     = 考勤扣款 + 社保个人部分 + 个税 + 其他扣款
实发工资 = 应发工资 − 扣款
```

- 加班费：**不做**（用户决策）。
- 社保、个税：**字段化处理**，只做扣减，不做申报。
- 金额一律 `BigDecimal`，大于等于 0；实发可为负（需人工确认，进入下期抵扣）。

### 7.2 固定工资折算（OPEN-02）

```text
日薪 = 月固定工资 ÷ 当月应出勤天数（默认，企业可配置）
应发固定工资 = 月固定工资 − 缺勤扣款
```

备选口径：21.75 计薪天数、自然日折算。口径一经选择，同一企业内必须统一。

### 7.3 考勤扣款（OPEN-03）

```text
事假扣款 = 日薪 × 事假天数 × 事假系数（默认 1.0）
病假扣款 = 日薪 × 病假天数 × 病假系数（默认 0.5）
旷工扣款 = 日薪 × 旷工天数 × 旷工系数（默认 2.0）
```

外勤、出差、年假、调休、法定假**不扣**。系数企业可配置，缺省值只是建议。

### 7.4 提成（EMP-02 / OPEN-01）

```text
提成金额 = 提成基数 × 提成比例（或阶梯比例）
提成基数 = 签约额（计提阶段）；发放以回款到账为条件
```

- 签约计提：单独形成提成应付，确认即计成本。
- 回款发放：回款到账后核销应付、写资金流水。
- 退单/退款：生成负向提成冲减。

### 7.5 缺失值规则

- 考勤/提成/社保等应计项缺失时，工资单标记 `payrollComplete = false`，**不可确认**。
- 项目归属成本不完整时，项目毛利按 `MET-002` 返回 `null`，显示「成本未完整」。
- 禁止用 0 成本或 0 考勤计算并展示伪利润。

### 7.6 尾差

- 计算保留到分，四舍五入规则全企业统一。
- 工资单与应付、发放金额之间的尾差必须可追溯（尾差项或调整项）。

## 8. 考勤设计（服务行业口径）

装企是「项目制 + 外勤制」，标准打卡不成立。本方案采用**月度考勤申报 + 确认**。

| 维度 | 设计 |
| --- | --- |
| 周期 | 自然月 |
| 采集方式 | 员工/负责人填报，店长或财务确认；不做每日打卡 |
| 应出勤 | 企业月历/门店排班默认，月可手工调整 |
| 出勤构成 | 正常出勤、外勤（工地/客户/量房，视同出勤）、请假、缺勤 |
| 请假类型 | 事假、病假、年假、调休、婚丧产假（法定假不扣） |
| 缺勤 | 旷工 |
| 不做 | 打卡、迟到、早退、加班 |
| 影响工资 | 仅事假、病假、旷工；其余视同出勤 |
| 确认流程 | 填报 → 申诉窗口 → 店长/财务确认 → 月汇总锁定 → 进工资单 |
| 与项目关系 | 考勤只影响员工工资项，不直接进项目成本；项目成本由工资项归属决定 |

**异常**：漏报、申诉、跨月补考勤。补录默认进下月或退回重算，需留痕。

## 9. 提成设计

### 9.1 规则维度

| 维度 | 说明 |
| --- | --- |
| 适用角色 | 设计师、业务员、项目经理、店长、团队负责人 |
| 基数 | 签约额（计提）；回款额（发放条件）；备选纯回款额 |
| 比例 | 固定比例或阶梯，可按项目/套餐/来源区分 |
| 归属 | 客户/项目 → 员工；多人协作按比例分摊 |
| 计提时点 | 签约确认 |
| 发放节奏 | 回款到账后，随当月工资或单独发放 |
| 保底/封顶 | 按企业配置，默认不设 |
| 退单/退款 | 负向冲减，已发放的下期抵扣 |
| 离职 | 未发提成结清规则、后续回款是否仍提，需冻结 |

### 9.2 数据来源

- 业绩事实：合同签约、客户回款（现有 `FinanceReportContext`、`PerformanceReportContext`、`BR-005`、`MET-001`）。
- 系统目前**没有提成规则与提成金额**，需新建。
- `BR-014` 边界：能力画像/学习数据不得自动作为绩效或发钱依据，引用需单独授权披露。

### 9.3 必须冻结的规则

1. 提成基数：签约额计提 vs 纯回款额（OPEN-01）。
2. 项目亏损时是否仍计提。
3. 多人协作的归属比例。
4. 退单、退款、离职、跨期的冲减与结清规则。

## 10. 账务接入（与现有体系咬合）

### 10.1 记账时点（EMP-04）

```text
工资单确认 / 提成确认  -> 生成员工工资应付 Payable  -> 成本发生
发放                  -> Payment 核销应付         -> 写 Ledger 支出流水
```

- 「已发放」不等于成本发生；成本在确认时确认。
- 发放失败/重发不重复写流水。

### 10.2 归属与去重

| 薪酬项 | 归属 | 落账 |
| --- | --- | --- |
| 项目人员工资/提成（项目经理、设计师、销售） | 项目 | 进 `项目成本` → 影响项目毛利 |
| 行政、财务、店长、其他非项目工资 | 企业 | 进 `企业费用` → 影响公司经营利润，不进项目毛利 |

**一笔工资项只能有一个归属**：挂项目就不进企业费用，不挂项目就不进项目成本。

### 10.3 与工人工资隔离

| 维度 | 工人工资（既有） | 员工工资（本方案） |
| --- | --- | --- |
| 主体 | `Worker` / `Partner` 班组 | `Employee` |
| 语义 | `PayableType.Salary` | 新增员工工资语义 |
| 成本 | 项目人工成本 | 项目归属进项目成本；企业归属进企业费用 |
| 凭证 | 工资发放凭证（身份证/工种/账号） | 工资条 + 按需发放凭证 |
| 考勤 | 不适用 | 员工月度考勤 |

### 10.4 手工记账

- 员工工资**不得**走手工记账，必须走「工资单 → 应付」闭环。
- 借支/预支属资金往来，需单独定义冲减规则，不得混入考勤扣款。

## 11. 公司利润设计（EMP-05）

### 11.1 v0 公式（OPEN-04）

```text
公司经营利润 = 项目毛利合计（项目收入 − 项目成本，含项目归属工资/提成）
             + 非项目其他收入（未关联项目的其他收入）
             − 企业费用（企业归属员工工资 + 房租 + 推广 + 税费 + 办公 + 其他运营）
```

### 11.2 必须补充定义

1. 企业收入范围：是否含全部项目毛利 + 未关联项目其他收入。
2. 企业费用确认制：建议统一权责发生（与 EMP-04 一致）。
3. **往来剔除**：借款/还款、押金/退还、备用金、股东往来必须判别为「往来」，不参与利润。当前手工记账没有损益/往来字段，启动公司利润**必须新增该判定**，否则借款会被算成收入（原 `23` §5.2 已预警）。
4. 期间口径：月度/季度，与月结锁定一致。
5. 成本完整性传导：任一项目成本不完整时，公司利润同样显示「成本未完整」，不得按 0 拼出假利润。

### 11.3 对外表达边界

- 可以说：装得清按项目毛利 + 企业费用口径展示公司经营利润，成本不完整时提示。
- 不可说：系统输出财务净利润、税务利润、审计利润或税务申报依据。

## 14. 验收用例

**正向**

1. 固定工资 + 考勤扣款 → 工资单确认 → 应付 → 发放 → 台账与工资条一致。
2. 设计师签约计提 → 回款发放 → 提成进项目成本、发放写流水、金额可追溯。
3. 店长查看本店员工个人工资，员工查看本人工资条。

**反向**

1. 考勤未确认 → 工资单不可确认。
2. 跨店/跨企业访问工资 → 拒绝且不泄露存在性。
3. 员工访问他人工资条 → 拒绝。
4. 同一笔提成重复计提/重复发放 → 幂等拦截。
5. 已发放工资单被直接修改 → 拒绝，只能补差。

**边界**

1. 入职/离职当月折算。
2. 退单/退款负向冲减。
3. 发放失败重发不重复写流水。
4. 工人工资与员工工资不混算。
5. 成本不完整时项目毛利与公司利润均为 `null`。
6. 月结后历史事实不可无痕修改。

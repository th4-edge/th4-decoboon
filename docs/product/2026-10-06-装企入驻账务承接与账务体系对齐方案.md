# 装企入驻账务承接与账务体系对齐方案

> 状态：产品运营方案（2026-10-06）
> 适用对象：新入驻装企、存量在跑项目承接、财务实施/客户成功
> 业务依据：`DEC-004`、`SCN-011`、`BR-010`、`SOL-005`、`MET-002`、`OBJ-001`
> 关联设计：`docs/product/2026-09-26-新装企业在跑项目承接P0业务方案.md`、`docs/design/21-新装企业在跑项目承接P0设计.md`
> 边界：本方案不要求把客户原账本搬进装得清，也不承诺与客户原账本科目一一对应

## 1. 问题定义

麦鸿这类客户的问题不是“不会用系统”，而是三件事同时发生：

1. 他们已经有自己的账本、科目习惯和记账口径；
2. 他们有在跑项目，但没有完整的未来收付款计划；
3. 装得清按行业标准设计项目经营账，和他们的账本不是一套东西。

如果我们的方法是“请你按我们的科目重新整理一遍”，客户会退回原账本；如果我们承诺“完全还原你的原账本”，装得清会变成第二个会计软件，范围失控且指标失真。

所以真正要解决的是：**让客户继续用他们的会计账，同时把装得清需要的项目经营事实接进来。**

## 2. 核心判断：三本账分离

依据 `SOL-005` 的业务延续式承接方案，把客户的账务事实分成三本账：

| 账本 | 归属 | 装得清是否承载 | 说明 |
| --- | --- | --- | --- |
| 历史档案账 | 客户原有账本、Excel、纸质资料 | 只做附件/摘要，不做全量还原 | 已完工、已结清历史不进经营指标 |
| 接管基线账 | 装得清 | 承载当前未结事实 | 期初应收、期初应付、期初资金、成本快照 |
| 接管后经营账 | 装得清 | 全量承载 | 新发生的合同、采购、收付款、项目成本 |

客户只需要接受一句话：

> 装得清不替代你的会计账，只接管你“还要继续经营的那部分事实”。

## 3. 装得清是什么账、不是什么账

### 3.1 对外解释口径

装得清做的是**项目经营账 + 资金台账 + 经营核算**，不是法定会计总账。

| 装得清是 | 装得清不是 |
| --- | --- |
| 项目维度的收入、成本、毛利 | 会计科目、借贷分录、法定总账 |
| 应收应付、收付款、资金流水 | 税务申报、审计报告、发票系统 |
| 项目成本完整性与动态利润 | 客户原账本的逐笔还原 |
| 老板能看懂的项目经营结果 | 财务人员的记账软件替代品 |

### 3.2 三个不丢

入驻承接只承诺三个结果：

1. **项目不丢**：在跑项目进入工地和财务工作台，项目经理能继续管。
2. **往来不丢**：当前未收、未付进入期初应收应付，后续收付款能继续核销。
3. **现金不断**：期初资金账户余额进入资金台账，现金流从接管日连续。

不承诺：历史逐笔流水还原、历史科目映射、历史已结清数据参与经营指标。

## 4. 客户账务体系 → 装得清对象：对应方法

不做“科目对照表”，做“业务事实对照表”。客户的科目只是线索，我们要找到背后的业务事实。

### 4.1 四类对应关系

| 客户账务事实 | 装得清承载对象 | 承接方式 | 是否进经营指标 |
| --- | --- | --- | --- |
| 客户工程款、预收款、应收 | 项目合同 + 期初应收 + 后续收款 | 接管日未收余额转期初应收；后续收款走应收/收款 | 接管后发生部分进 |
| 材料款、人工、项目款、供应商应付 | 应付账款 + 付款 | 接管日未付余额转期初应付；后续付款走应付/付款 | 接管后发生部分进 |
| 已发生项目成本 | 接管前成本快照 + 项目成本完整性 | 只填总额 + 完整性确认，不还原明细 | 进入项目毛利，完整性不确认时利润为空 |
| 其他账务：房租、税费、借款、押金、备用金等 | 手工记账（其他账务） | 分类文本 + 账务用途；工程款/材料款/工资/项目款禁止手工登记 | 按账务用途决定是否进项目口径 |
| 会计科目、总账、税务 | 客户原有系统 | 不迁移 | 不进装得清 |

### 4.2 接管日期是分界线

```text
接管日之前：只承接当前未结余额和成本快照
接管日之后：所有业务按装得清标准闭环自动形成应收、应付、现金流、项目成本
```

这条线必须让客户财务明确确认，避免“历史已收款被算进本月收入”“历史已付款被算成接管后成本”。

## 5. 入驻财务承接标准流程（六步）

建议把现有在跑项目承接 P0 的财务部分，扩展为可独立执行的“财务承接六步”：

```text
第1步 账本摸底
-> 客户有哪些账本、科目、期间、资金账户、在建项目清单

第2步 范围确认
-> 哪些项目承接、接管日是哪天、哪些历史已结清不承接

第3步 期初应收
-> 每个项目接管日未收余额 + 到期日 + 来源单号

第4步 期初应付
-> 每个项目/供应商接管日未付余额 + 到期日 + 收款方

第5步 期初资金 + 剩余收付款计划
-> 资金账户期初余额
-> 未来应收计划（按合同/客户）
-> 未来应付计划（按供应商/人工/项目）

第6步 成本完整性确认
-> 接管前成本总额
-> 成本是否完整；不完整时利润为空，不按 0 计算
-> BOSS/财务/PM 确认，首笔业务后锁定
```

### 5.1 承接项目清单的完成条件

按 `rules.md` §13 可完成状态投影，建议承接清单至少包含：

| key | label | required | 完成条件 | 异常态 |
| --- | --- | --- | --- | --- |
| `project` | 在跑项目 | 是 | 项目存在且状态非终态 | 暂不可确认 |
| `owner` | 责任归属 | 是 | 门店/团队/负责人明确 | 待确认，不猜 |
| `contract` | 合同基线 | 是 | 合同编号 + 金额 + 关联项目 | 仅附件无金额 → 未完成 |
| `receivable` | 期初应收 | 条件必填 | 有金额或明确“无应收” | 未确认且未标记 → 未完成 |
| `payable` | 期初应付 | 条件必填 | 有金额或明确“无应付” | 同上 |
| `cash` | 期初资金 | 是 | 账户余额已确认 | 暂不可确认 |
| `plan` | 剩余收付款计划 | 是 | 至少一条未来收/付计划或明确“无计划” | 待补 |
| `cost` | 成本完整性 | 是 | 总额 + 完整性确认 | 不完整 → 利润为空 |

## 6. 麦鸿落地打法

### 6.1 先做三张表

1. **《麦鸿账本摸底表》**：账本名称、用途、科目、期间、期末余额、责任人。
2. **《麦鸿在建项目承接表》**：项目、合同额、已收、未收、已付、未付、账户余额、成本总额、成本完整性。
3. **《麦鸿账务承接对照表》**：原科目/原金额 → 装得清对象 → 承接方式 → 是否进经营指标 → 差异 → 确认人。

对照表示例：

| 原账科目/账本 | 原金额 | 所属项目 | 装得清对象 | 承接方式 | 是否进经营指标 | 差异说明 | 确认人 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 预收账款-XX项目 | 180,000 | XX项目 | 期初已收摘要 | 只记接管摘要，不生成收款流水 | 否 | 历史已收不进本月 | 财务 |
| 应收账款-XX项目 | 120,000 | XX项目 | 期初应收 | 接管日未收余额 | 是（后续收款） | 与合同节点可能不一致 | BOSS |
| 应付账款-材料商A | 80,000 | XX项目 | 期初应付 | 接管日未付余额 | 是（后续付款） | 账期口径差异 | 财务 |
| 管理费用 | 12,000 | 企业级 | 手工记账-企业费用 | 文本分类 + 企业费用 | 否（不进项目毛利） | 只进现金流 | 财务 |
| 其他应付款-股东 | 50,000 | 企业级 | 手工记账-资金往来 | 文本分类 + 资金往来 | 否 | 仅资金台账 | BOSS |

### 6.2 首月双轨运行

- 客户原会计账继续记（用于法务/税务/对外）。
- 装得清同步记（用于项目经营/应收应付/现金流）。
- 每周对一次差异，月末做《双轨对账表》：

| 对账主题 | 原账本金额 | 装得清金额 | 差异 | 差异原因 | 处理动作 |
| --- | ---: | ---: | ---: | --- | --- |
| 项目未收 |  |  |  | 口径/时间/主体 |  |
| 项目未付 |  |  |  |  |  |
| 资金余额 |  |  |  |  |  |
| 项目成本 |  |  |  | 完整性 |  |

- 差异只记录分类，不静默调账：
  - 时间差异（跨期、账期）
  - 主体差异（供应商/班组/个人）
  - 含税差异（含税/不含税）
  - 口径差异（合同额/已收/已结清）
  - 数据缺失（无依据、待补）
- 首月结束后再决定原账本中哪些继续保留、哪些只留给法定会计使用。

### 6.3 麦鸿的推荐节奏

```text
第0周：财务启动会 + 账本摸底 + 范围确认
第1周：在建项目逐项承接 + 期初应收应付 + 期初资金
第2周：剩余收付款计划 + 成本完整性确认 + 角色确认
第3-4周：双轨运行，新业务走装得清
第5周：首月经营对账会 + 差异收口 + 原账本定位确认
```

## 7. 引导与内容体系

### 7.1 产品内引导

| 位置 | 引导内容 |
| --- | --- |
| 注册后 | “是否有在跑项目”选择 + 财务承接任务卡片 |
| 承接首页 | 承接进度、待确认、差异待处理 |
| 承接向导 | 每一步说明“这一步在承接什么、不承接什么” |
| 应收账款 | 空状态解释“期初应收只承接接管日未收余额” |
| 应付账款 | 空状态解释“期初应付只承接接管日未付余额” |
| 资金台账 | 解释“期初余额 + 接管后流水”；历史已结清不进本月 |
| 手工记账 | 解释“只登记非计划内其他账务”；工程款/材料款/工资/项目款引导到应收应付 |
| 项目财务 | 解释“项目毛利 = 合同/手工项目收入 - 实际成本”；成本不完整时利润为空 |
| 原账口径备注 | 允许备注“此项对应原账科目 XX”，不做强制映射 |

### 7.2 交付文档

1. 《装得清财务账务体系说明》（3 分钟读懂版）：是什么账、不是什么账、三本账、三个不丢。
2. 《装企财务承接操作手册》：BOSS/财务/PM 三视角，六步流程，异常处理。
3. 《装企账务承接对照表模板》：原科目 → 装得清对象 → 承接方式 → 确认人。
4. 《首月双轨对账表模板》：原账本 vs 装得清 vs 差异。
5. 《装企财务承接 FAQ》：高频问题标准答案。
6. 《财务启动会 PPT / 培训视频》：用于驻场或线上实施。

### 7.3 FAQ（建议口径）

| 客户问题 | 建议回答 |
| --- | --- |
| 你们和用友/金蝶有什么区别？ | 他们是法定会计账；装得清是项目经营账。我们不替代他们，只把项目收入、成本、毛利、应收应付和现金流独立出来。 |
| 我们原来的会计科目要搬进去吗？ | 不需要。科目留在原系统；装得清按业务事实承接，必要时用“原账口径备注”留痕。 |
| 我们原来的预收/应收怎么对应？ | 接管日以前的已结清历史只做档案；接管日未收余额转为期初应收，后续收款走装得清。 |
| 供应商欠款怎么承接？ | 接管日未付余额转为期初应付；后续付款走应付/付款，账期和付款计划可手动补录。 |
| 为什么历史已收款不算本月收入？ | 历史已收款是接管前事实，进入会污染本月经营指标；装得清只让接管后发生的事实进经营指标。 |
| 为什么成本不完整时不显示利润？ | 成本不完整时用 0 计算会制造假利润；按 `MET-002`，利润和毛利率返回空并提示“成本未完整”。 |
| 原来的内账/外账怎么处理？ | 装得清不做内外账；原账本保留，装得清负责项目经营口径，差异通过双轨对账分类。 |
| 借款、押金、备用金怎么记？ | 手工记账选“资金往来”，只进资金台账，不影响项目毛利；将来若做公司利润需单独定义剔除规则。 |
| 剩余收付款计划为什么还要手动录？ | 接管前的合同/采购计划不完整，系统无法自动生成；先手动补齐接管日之后的计划，后续新业务自动生成。 |
| 接管后还能改吗？ | 首笔真实业务发生后锁定，只能走调整、更正或冲正，保留审计。 |

## 8. 角色分工与运营机制

| 角色 | 职责 |
| --- | --- |
| 装得清实施/客户成功 | 账本摸底、承接范围、对照表、双轨对账、培训 |
| 装企 BOSS | 确认承接范围、归属、最终金额、差异处理 |
| 装企财务 | 期初应收应付、资金余额、成本完整性、原账口径 |
| 装企 PM | 项目当前状态、剩余施工、现场重点 |
| 装得清研发 | 承接向导、期初余额、完成度投影、双轨对账导出、异常态 |

运营机制：

- 财务启动会：统一口径，明确“不搬科目、只接事实”。
- 财务专场培训：按角色讲操作，不按功能讲模块。
- 首月陪跑：每周同步，月末对账会。
- 一企一策：对照表双方确认后执行，进入实施档案。

## 9. 衡量指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 承接完成率 | 已完成承接的在跑项目 / 应承接项目 | 100% |
| 期初余额准确率 | 双轨对账无差异或差异已确认的期初数占比 | ≥ 95% |
| 双轨差异率 | 首月对账差异金额 / 对账总额 | 逐步收敛 |
| 首月对账完成率 | 首月末完成双轨对账的客户占比 | 100% |
| 财务活跃度 | 接管后财务每周登录/处理应收应付次数 | 建立基线 |
| 经营指标可用率 | 项目毛利可计算的在跑项目占比 | 随成本完整性提升 |

## 10. 边界与风险

- 不承诺与客户原账本科目一一对应；
- 不承接已完工已结清历史明细（`DEC-004`）；
- 历史导入数据不参与经营指标（`DEC-004`）；
- 归属缺失必须待确认，不猜负责人/门店/团队（`OBJ-001`）；
- 成本不完整时利润为空，不按 0 计算（`MET-002`）；
- 首笔真实业务后锁定，只允许调整/冲正；
- 公司经营利润本期不提供，企业费用与资金往来只进现金流；
- 对外不得说“装得清能替代会计总账/税务申报”。

## 11. 与现有承接设计的衔接

现有在跑项目承接 P0 已经具备：

- 在跑项目引导式录入；
- 期初应收/应付（每项目一条汇总记录）；
- 接管前成本快照与完整性；
- 分角色确认与 BOSS 代确认；
- 首笔业务锁定；
- 项目进入工地和财务工作台。

本方案建议在此基础上补：

1. 期初资金账户余额；
2. 剩余收款/付款计划手动补录；
3. 财务承接六步操作手册与对照表模板；
4. 双轨对账表与差异分类；
5. 产品内账务体系说明、空状态引导、FAQ；
6. 承接完成度投影按必做/可选/异常态展示。

## 12. 一句话结论

> 我们不是在搬客户的账本，而是在接管客户“还要继续经营的项目事实”：把未收、未付、账户余额、成本完整性和剩余收付款计划接进来，让新业务从接管日开始按装得清的标准闭环运行；客户的原会计账继续保留，双方通过双轨对账分类差异。

## 13. 现有财务逻辑影响矩阵

结论：**现有财务核心逻辑不改，承接能力主要加在“期初事实、引导、对照、对账”四层。**

| 现有对象/逻辑 | 本次承接是否改动 | 承接方式 | 红线/备注 |
| --- | --- | --- | --- |
| 项目合同、项目收入基线 | 不改 | 接管时生成合同/项目基线，标记 `BusinessOrigin.Carryover` | 历史已结清合同只做档案 |
| `Receivable` 应收 | 不改核销逻辑 | 接管日未收余额生成一条期初应收（每项目汇总） | 不重建历史收款明细 |
| `Receipt` 收款 | 不改 | 接管后发生才生成收款流水 | 历史已收不进本月收入 |
| `Payable` 应付 | 不改核销逻辑 | 接管日未付余额生成一条期初应付（每项目汇总） | 不重建历史付款明细 |
| `Payment` 付款 | 不改 | 接管后发生才生成付款流水 | 历史已付不进接管后成本 |
| `Ledger` 资金流水 | 结构不改 | 接管后业务正常写入；新增期初资金余额口径 | **期初余额不是收入/支出** |
| 现金流与账户余额 | 公式不改 | 当前余额 = 期初余额 + 接管后净流量 | 期初余额不能进本月收支 |
| `ProjectCostContext` 成本 | 不改 | 接管前成本快照继续进入成本汇总 | 完整性不确认时利润为空 |
| 项目毛利 | 不改 | 合同/关联项目收入 - 实际成本 | 成本不完整时不显示利润 |
| `Settlement` 结算 | 不改主公式 | 结算快照纳入接管前成本与手工金额 | 历史已结清不进结算 |
| 手工记账 | 不改刚上线边界 | 未结其他账务用“资金往来/其他”承接 | 工程款/材料款/工资/项目款仍禁止手工登记 |
| 公司经营利润 | 不改 | 本期仍不提供 | 企业费用/往来只进现金流 |
| 权限矩阵 | 不改 | 承接沿用 BOSS/财务/PM/设计确认 | BOSS 代确认留痕 |
| `BusinessOrigin.Carryover` | 已有，不改 | 接管生成对象统一标记 | 接管数据不参与新签/获客统计 |

### 13.1 需要新增的对象/字段

| 新增项 | 类型 | 说明 | 风险 |
| --- | --- | --- | --- |
| 期初资金余额 | 新对象或账户期初字段 | 接管日各资金账户余额 | 必须与收入/支出隔离 |
| 剩余收款计划 | 复用 `Receivable` | 接管日之后的未来应收计划，手动补录 | 不改核销 |
| 剩余付款计划 | 复用 `Payable` | 接管日之后的未来应付计划，手动补录 | 不改核销 |
| 原账口径备注 | 备注字段 | 记录“对应原账科目/账本” | 只备注，不建科目体系 |
| 双轨对账表 | 报表/导出 | 原账本 vs 装得清 vs 差异分类 | 只读，不改账 |
| 承接完成度投影 | 只读投影 | 必做/可选/完成条件/异常态 | 不改财务事实 |
| 期初应付明细拆分 | 可选扩展 | 按供应商/项目拆期初应付 | P0 不做，后续按需 |

### 13.2 三个必须冻结的口径

1. **期初资金余额**：建议新增 `OpeningBalance` 口径；不计入收入/支出，不参与利润，只作为账户起始余额。
2. **期初应收/应付粒度**：P0 每项目各一条汇总；后续如需按客户/供应商拆分，走独立期初明细，不生成历史流水。
3. **剩余收付款计划**：是对期初应收/应付的**时间分解**，不是新增应收应付；计划合计必须等于期初未结余额（或明确标记未排期部分）。
4. **历史其他账务**：已结清只做档案；未结按性质进入期初应收/应付或手工记账“资金往来”，不重建历史明细。

# 员工工资与提成使用说明书

版本：P0.1  
依据：`DEC-017`《员工工资与提成发放口径》、`BR-015`《员工工资与提成发放规则》、`DEC-032`《BOSS 全角色与一人装企经营边界》、`BR-028`《BOSS 全角色与一人装企运营规则》、`ANS-BIZ-20261006-002`、`ANS-BIZ-20261007-020`  
适用范围：装得清试运营阶段的中小装企员工工资、月度考勤、员工提成、员工发放和工资条  
不适用：工人/班组工资、社保申报、个税申报、完整 HR、法定会计总账

## 1. 先理解三条业务主线

### 1.1 员工工资

```text
薪酬方案 -> 月度考勤确认 -> 生成工资单 -> BOSS 确认
-> 生成员工实发应付 -> 财务或 BOSS 发放 -> 资金台账 -> 员工工资条可见
```

有财务岗位时按上述职责协作；只有 BOSS 或 BOSS 接管时，同一 BOSS 可按顺序完成建方案、录/确认考勤、生成、确认和发放，系统仍逐步留痕，不合并节点。

### 1.2 员工提成

```text
主合同签约 -> 财务手工计提提成 -> 客户回款
-> 按累计有效回款比例自动释放 -> 财务或 BOSS 发放 -> 提成结清
```

只有 BOSS 时，提成计提、释放查看和发放均可由同一 BOSS 依次完成；未回款不得发放，每一步独立留痕。

### 1.3 退款、离职、跨期负向调整

```text
客户退款/离职/跨期差异 -> 形成负向调整
-> 不反改已发放历史 -> 进入下期工资单抵扣 -> 抵扣完成后关闭
```

## 2. 角色与权限

| 角色 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| BOSS | 本企业全部内部岗位能力：建薪酬方案、录/确认考勤、计提提成、生成工资单、确认、员工发放、退款、负向调整和审计；单人企业可由同一 BOSS 逐步完成 | 不能冒充员工本人或业主/客户确认，不能修改已发放历史 |
| 财务 | 建薪酬方案、录/确认考勤、计提提成、生成工资单、登记退款、员工发放 | 有独立 BOSS 时，工资单最终确认由 BOSS 完成 |
| 店长 | 查看本店员工应发/扣款/实发构成，确认本店考勤 | 不能查看其他门店、银行卡、身份证、个税明细 |
| 员工本人 | 查看本人已发布工资条、本人提成、本人考勤 | 不能查看同事工资或企业工资总额 |

所有企业、门店、员工范围均由服务端根据登录身份决定，前端传入的 `companyId`、`empId`、`storeId` 不视为可信。

### 2.1 一人装企操作口径

1. BOSS 不需要邀请第二个员工，也不需要虚构“财务”“店长”“设计师”等岗位。
2. BOSS 登录后可依次完成全部内部业务节点；系统按能力放行，但仍按原状态机校验。
3. 同一 BOSS 连续制单、确认、发放时，每次操作均记录实际操作人、承担能力、动作前后状态、金额和幂等键。
4. BOSS 的工资条也按员工薪酬事实处理；如果 BOSS 同时是发薪对象，不得把个人工资混入项目材料成本或任意企业费用。
5. 业主验收确认、客户本人签认和平台运营不属于 BOSS 内部能力超集。

## 3. 前置准备

### 3.1 建立薪酬方案

使用人：财务/BOSS。

操作：

1. 进入 App「员工薪酬」或 Web「员工工资」。
2. 新建员工薪酬方案。
3. 填写员工、月固定工资、月应出勤天数、生效日期。
4. 保存后方案状态为生效。

注意：

- 同一员工同一生效日期不应重复建立方案。
- 没有有效薪酬方案的员工不会生成工资项。

### 3.2 确认月度考勤

使用人：财务或 BOSS 录入；店长、财务或 BOSS 按范围确认。

操作：

1. 进入「月度考勤」。
2. 选择工资月份；App 支持切换过往月份，从历史月份列表点击「录入」会继承该月份。
3. 选择员工后，系统按该工资月份匹配生效薪酬方案，并在录入页显示月应出勤天数。
4. 填写正常出勤、事假、病假、旷工等。
5. 保存后考勤状态为待确认；确认考勤后，需回到同月工资单重新生成草稿。

计算公式：

```text
日薪 = 月固定工资 ÷ 当月应出勤天数
事假扣款 = 日薪 × 事假天数 × 1.0
病假扣款 = 日薪 × 病假天数 × 0.5
旷工扣款 = 日薪 × 旷工天数 × 2.0
```

三个扣款系数按系统配置执行。

## 3.3 薪酬工作台周期与历史入口

薪酬工作台顶部显示当前统计周期，点击“切换周期”可选择目标月份。

- 当前周期有工资单时，摘要显示该周期的待确认考勤、工资单、发放和工资条数量；
- 当前周期没有工资单、但存在历史工资单时，工作台显示“当前周期暂无工资单”，并带出最近一次工资单的周期、状态和实发金额；
- 点击“查看最近工资单”直接进入最近一次工资单详情；
- 点击“全部工资单”进入工资单列表，查看全部历史周期。

切换周期只改变查询范围，不重新生成、不覆盖、不重算已发放工资单。

## 4. 员工工资操作

### 4.1 生成工资单

使用人：财务或 BOSS。

操作：

1. 打开 App 财务工作台。
2. 点击「员工工资」快捷入口。
3. 点击「生成」，App 会按当前选择的工资归属月份生成工资单草稿；补发过去月份时先切换到目标月份，再点击生成。
4. 系统汇总：
   - 固定工资折算；
   - 考勤扣款；
   - 提成金额；
   - 奖金、补贴；
   - 社保个人字段、个税字段和其他扣款。
5. 检查应发、扣款、实发和完整性。

状态：

```text
草稿 -> 已确认 -> 部分发放 -> 已发放 -> 已关闭
```

注意：

- 考勤未确认时不得确认工资单。
- 成本或提成归属不完整时不得按 0 伪造结果。
- 已确认或已发放的工资单不能重新生成。

### 4.2 BOSS 确认工资单

使用人：BOSS。

操作：

1. 打开工资单详情。
2. 检查每个员工的应发、扣款、实发。
3. 点击确认。

确认结果：

- 按每个工资项的 `netAmount` 生成员工实发工资应付；
- 应付类型为 `EmployeeSalary`；
- 项目归属工资计入项目成本，企业归属工资计入企业费用；
- 员工工资条此时只进入待发放状态，员工端不可见。

### 4.3 发放员工工资（财务或 BOSS）

使用人：财务或 BOSS。

操作：

1. 进入「员工发放」。
2. 选择待发工资应付。
3. 选择付款账户。
4. 填写发放日期和批次号。
5. 确认发放。

系统同时完成：

- 核销员工工资应付；
- 写员工付款事实；
- 写资金台账支出流水；
- 当同一员工全部工资项发放成功后，发布该员工工资条。

同一发放幂等键重试返回原 Payment，不重复写流水。

### 4.4 员工查看工资条

使用人：员工本人。

规则：

- 工资单确认但未实际发放时，员工端不可见。
- 实际发放成功后，员工端才可见。
- 工资条展示应发、扣款、实发构成。
- 工资条一旦发布，不因后续失败重试改写历史金额。

## 5. 员工提成操作

### 5.1 签约计提

使用人：财务或 BOSS。

操作：

1. 打开 App 财务工作台「员工提成」或 Web「员工提成」。
2. 选择员工和项目。
3. 填写主合同签约额和该员工手工比例。
4. 保存后生成提成明细和 `EmployeeCommission` 应付。

公式：

```text
提成金额 = 主合同签约额 × 该员工手工比例
```

约束：

- 提成基数只按主合同签约额，不自动纳入增项或其他收入。
- 多人协作只支持手工比例。
- 多人比例合计不强制等于 100%，不自动补齐。
- P0 默认阻断合计超过 100%。

### 5.2 回款自动释放

触发：客户收款。

公式：

```text
累计有效回款 = 累计收款 − 累计退款/退单冲减
累计应释放提成 = min(提成金额, 提成金额 × 累计有效回款 ÷ 主合同签约额)
本次释放提成 = max(0, 累计应释放提成 − 已释放提成)
```

注意：

- 提成在签约时计提。
- 回款到账后满足发放条件。
- 未回款时不能发放提成。
- 已释放但未发放部分可以是待发金额。
- 超过已释放金额的发放请求必须被阻断。

### 5.3 员工提成发放

使用人：财务或 BOSS。

操作：

1. 进入「员工发放」。
2. 选择 `EmployeeCommission` 应付。
3. 金额不得超过已释放金额和应付未付金额。
4. 确认发放。

### 5.4 多项目提成

规则：

- 同一员工跨多个项目时，可以形成多条提成明细。
- 每条提成独立归属对应项目。
- 最终在员工工资条/发放汇总中按员工合并展示。
- 一笔成本只能归项目或企业，不能重复计入。

## 6. 退款和负向调整操作

### 6.1 登记客户退款

使用人：财务或 BOSS。

入口：

- App：财务工作台 → 客户退款 → 登记退款 → 选择原收款；
- Web：财务工作台 → 客户退款 → 登记退款。

系统行为：

- 退款金额不能超过原收款可退余额；
- 写独立客户退款事实；
- 写 `Refund` 资金台账支出流水；
- 自动重算该项目累计有效回款；
- 对已发提成形成负向调整；
- 不反改原提成、原释放记录和已发工资。

示例：

```text
原提成：1308.12
退款金额：10000.00
退款后累计应释放：1108.12
负向调整：200.00
```

### 6.2 查看负向调整

入口：

- App：员工薪酬 → 负向调整；
- Web：财务工作台 → 提成负向调整。

页面显示：

- 员工和项目；
- 调整类型：退款冲减、离职调整、跨期调整；
- 状态：待下期抵扣、已入工资单、已取消；
- 应抵扣金额；
- 已抵扣金额；
- 发生日期和说明。

### 6.3 进入下期工资

规则：

- 负向调整只进入下一工资周期抵扣；
- 下期可承受金额不足时，未抵扣部分保持待下期状态；
- 工资单重建不会重复抵扣；
- 已发放历史不改写。

## 8. 常见问题

### 员工为什么看不到工资条？

先检查：

1. 工资单是否已确认；
2. 工资应付是否已实际发放；
3. 同一员工的全部工资项是否都发放完成；
4. 工资条是否已经发布。

确认但未发放、发放失败或部分发放时，员工端不可见。

### 为什么提成不能发放？

检查：

1. 客户是否已经回款；
2. 提成是否已经释放；
3. 本次金额是否超过已释放金额；
4. 应付是否已经发放。

### 退款后为什么要下期抵扣？

已发工资、已释放提成和已发提成都不能反改历史。退款形成的负向金额必须作为独立调整进入下期，并保留原始依据和调整轨迹。

### 店长为什么看不到银行卡和个税明细？

工资是敏感数据。店长只允许查看本店员工应发、扣款、实发构成；银行卡、身份证、个税明细只按企业权限返回。

## 9. 验收检查清单

- [ ] 有有效薪酬方案和已确认考勤。
- [ ] 工资单生成后可查看每个员工的项目/企业归属。
- [ ] BOSS 确认后生成实发应付，不提前发布工资条。
- [ ] 财务或 BOSS 发放后写付款和资金台账，发布工资条。
- [ ] 提成按主合同签约额计提。
- [ ] 回款按累计有效回款比例释放。
- [ ] 未回款/超释放提成发放被阻断。
- [ ] 退款生成负向调整，不反改原历史和原项目成本归属。
- [ ] 同一幂等键不重复计提、重复发放或重复调整。
- [ ] 店长、员工和跨店越权均被服务端拒绝。

## 10. 当前边界

本说明描述的是经营参考口径，不替代：

- 社保申报；
- 个税申报；
- 法定会计总账；
- 完整 HR 人事系统；
- 工人/班组工资链路。

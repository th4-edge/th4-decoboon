# 员工工资与提成发放 P0 产品规格

> 文档编号：PRODUCT-FIN-20261007-01  
> 版本：v0.1  
> 状态：`business_frozen_for_technical_review`（业务口径已冻结，技术细节待评审）  
> 依据：`DEC-017`、`BR-015`、`ANS-BIZ-20261006-002`、`EV-065`、`EV-069`、`DEC-016`、`MET-002`、`EV-008`  
> 目标：完成员工月度工资、月度考勤、提成计提/发放、工资发放、资金台账和项目/企业成本归集的 P0 闭环。

---

## 0. 结论

P0 可以进入产品规格、研发拆解和验收设计，但不得把员工工资做成完整 HR、薪酬引擎或法定会计系统。

P0 必须完成：

- 员工薪酬方案和固定工资；
- 月度考勤申报、确认和扣款；
- 手工提成明细、签约计提和按累计有效回款比例自动释放；
- 工资单、工资项、工资条；
- 员工工资应付、发放、资金台账；
- 项目成本或企业费用的唯一归属；
- 菜单级、数据级和字段级工资权限；
- 功能开关、幂等、留痕和审计。

P0 明确不做：

- 个税、社保、公积金代扣代缴或申报；
- 法定会计总账、会计科目、借贷分录和财务报表；
- 招聘、劳动合同、排班、打卡、迟到早退和绩效体系；
- 公司经营利润正式实现；
- 店长是否看门店利润；
- 自动阶梯提成、自动多人分摊和多级成本分摊；
- 银行直连代发、工资卡管理和税务稽核。

## 1. 角色与权限

| 能力 | BOSS | 财务 | 店长 | 员工本人 | 工人/班组 |

| 薪酬方案编辑 | ✅ | 只读 | ❌ | ❌ | ❌ |
| 全公司工资单 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 本店员工工资 | ✅ | ✅ | ✅（本店、可配置、留痕） | ❌ | ❌ |
| 本店考勤录入/确认 | ✅ | ✅ | ✅ | 仅本人申诉/申报 | ❌ |
| 提成明细 | ✅ | ✅ | 本店只读或按企业配置 | 仅本人 | ❌ |
| 工资单确认 | ✅ | 制单/复核 | ❌ | ❌ | ❌ |
| 工资发放 | ✅（可代操作） | ✅ | ❌ | ❌ | ❌ |
| 本人工资条 | ✅ | ✅ | ✅ | ✅ | ❌ |
| 项目/企业成本 | ✅ | ✅ | 本店只读（待产品确认） | ❌ | ❌ |

强制规则：

1. 企业、门店、团队、员工只能从登录员工加载，禁止信任前端传入的组织参数。
2. 店长只可见本店员工工资；跨店、跨企业、BOSS/财务及其他店员工不可见。
3. 店长可看应发、扣款、实发构成，不可看银行卡、身份证、个税明细。
4. 员工仅可见本人工资条、本人提成、本人考勤。
5. 工人/班组走独立的工人工资链路，不进入员工薪酬权限。
6. 越权统一返回“不存在或无权访问”，不泄露记录是否存在。
7. 工资权限独立于普通业务数据权限，响应字段必须按服务裁剪。

## 2. 两个真实场景

### 场景 A：15 人装企月度固定工资

| 项 | 内容 |
| --- | --- |
| 使用人 | 财务核算、店长确认考勤、BOSS 确认工资单 |
| 触发事件 | 月末结薪 |
| 前置条件 | 员工有薪酬方案；当月考勤申报完成；异常扣款依据已确认 |
| 当前动作 | 系统按固定工资和月度考勤生成工资单草稿 |
| 系统下一步 | 财务或 BOSS 复核 → BOSS 确认 → 生成员工工资应付并计成本 → 财务或 BOSS 发放 → 资金台账 |
| 异常处理 | 考勤未确认时不可确认工资单；员工申诉退回重算；补录按月结规则留痕 |
| 结果 | 员工看到本人工资条；店长看到本店应发/扣款/实发构成 |

### 场景 B：设计师签约计提、回款发放提成

| 项 | 内容 |
| --- | --- |
| 使用人 | 财务、BOSS、设计师 |
| 触发事件 | 主合同签约形成提成计提；客户回款形成发放条件 |
| 前置条件 | 主合同签约额存在；提成归属和手工比例已确认 |
| 当前动作 | 系统/财务形成提成明细，签约时计提并生成提成应付 |
| 系统下一步 | 回款到账后满足发放条件 → 并入工资发放批次或单独发放 → 核销应付 → 资金台账 |
| 异常处理 | 退款、离职、跨期产生负向金额进入下期，不反改已发放历史 |
| 关键约束 | 提成基数只按主合同签约额；多人手工比例合计不强制等于 100%；回款按累计有效回款比例自动释放；一笔成本只能归项目或企业 |

## 3. 业务对象

```text
CompensationScheme
  -> AttendanceRecord
  -> AttendanceSummary
  -> CommissionItem
  -> PayrollSheet
      -> PayrollItem
      -> Payslip

PayrollItem / CommissionItem
  -> Payable(EmployeeSalary / EmployeeCommission)
  -> Payment(Employee)
  -> Ledger(Expense)
```

对象职责：

| 对象 | 职责 |
| --- | --- |
| `CompensationScheme` | 员工、生效期、固定工资、提成适用规则和状态 |
| `AttendanceRecord` | 月度异常申报事实，不建立日打卡体系 |
| `AttendanceSummary` | 月度考勤确认结果，进入工资单的唯一输入 |
| `CommissionItem` | 主合同签约额、手工比例、计提、发放、冲减和归属 |
| `PayrollSheet` | 某企业某周期的工资批次 |
| `PayrollItem` | 员工+归属对象的明细行；同一员工可拆多条项目/企业明细 |
| `Payslip` | 员工本人可见的汇总工资条；实际发放完成后才发布 |
| `Payable` | 员工工资/提成应付，扩展员工工资语义 |
| `Payment` | 员工发放核销，增加员工关联 |
| `Ledger` | 员工工资/提成支出流水，不新建第二套资金账 |

关键约束：

1. 员工工资不复用 `PayableType.Salary`，必须增加独立员工工资语义。
2. `Payment` 必须可以关联 `Employee`，不能只关联工人/班组。
3. 一张工资单可以包含固定工资、提成、奖金和补贴，但提成必须保留原始 `CommissionItem` 链接。
4. 一笔 `PayrollItem` 只能归项目或归企业；同一员工跨项目时允许拆多条项目工资项，最后按员工汇总为一张工资条。
5. 同一员工的多条项目工资项各自归属对应项目，禁止在同一行做多项目混合归属。
6. 工资单确认前不得生成应付和成本；发放前不得写资金流水。

## 4. 状态机

### 4.1 薪酬方案

```text
草稿 -> 生效 -> 失效
```

- 同一员工同一时间只能有一个生效方案。
- 历史工资单引用当时方案快照，不因后续修改而回算。

### 4.2 考勤

```text
草稿 -> 待确认 -> 已确认 -> 已入工资单
               -> 申诉中 -> 退回重算
```

- 只有已确认月汇总可进入工资单。
- 已入工资单后锁定；补录按产品规则进入下月或退回重算，必须留痕。

### 4.3 提成

```text
待计提 -> 已计提（待发放） -> 已入发放批次 -> 已发放 -> 已关闭
                              -> 已冲减（退款/离职/跨期）
```

- 签约时计提并计成本。
- 回款到账后按累计有效回款比例自动释放。
- 已发放不得反改历史，负向金额进入下期。

### 4.4 工资单

```text
草稿 -> 待确认 -> 已确认（应付已生成、成本已计）
     -> 部分发放 -> 已发放 -> 已关闭
     -> 作废/退回重算（仅未发放）
```

- “已完成”必须由应付、发放、考勤和提成状态共同推导。
- 已确认或部分发放的工资单不能直接删除或改历史。

## 5. 金额公式

```text
日薪 = 月固定工资 ÷ 当月应出勤天数

事假扣款 = 日薪 × 事假天数 × 1.0（企业可配置）
病假扣款 = 日薪 × 病假天数 × 0.5（企业可配置）
旷工扣款 = 日薪 × 旷工天数 × 2.0（企业可配置）

应发工资 = 固定工资折算 + 提成 + 奖金 + 补贴
扣款 = 考勤扣款 + 社保个人字段 + 个税字段 + 其他扣款
实发工资 = 应发工资 − 扣款
```

规则：

- 提成基数只按主合同签约额，不自动纳入增项或其他收入。
- 提成比例可由财务手工填写，多人按手工比例拆条；比例合计不强制等于 100%，不自动补齐，P0 默认阻断合计超过 100% 的提交。
- 回款自动释放：

```text
累计有效回款 = 累计收款 − 累计退款/退单冲减
累计应释放提成 = min(提成金额, 提成金额 × 累计有效回款 ÷ 主合同签约额)
本次释放提成 = max(0, 累计应释放提成 − 已释放提成)
```

- 社保、个税只做扣减字段，不验证也不申报。
- 金额使用 `BigDecimal`，保留到分，统一舍入规则。
- 成本不完整或归属缺失时不可确认，不得按 0 计算。
- 负数实发必须人工确认，并进入下期抵扣。
- 员工工资应付和项目/企业成本均按实发工资计算；应发、扣款、社保和个税字段只用于工资条展示。

## 6. 核心流程

### 6.1 月度工资

1. 财务确认工资周期和当月应出勤天数。
2. 店长/财务申报并确认异常考勤。
3. 系统按固定工资和考勤扣款生成工资单草稿。
4. 财务补充奖金、补贴、社保/个税字段和归属对象。
5. 财务提交，BOSS 确认。
6. 系统生成 `Payable`，同时确认项目成本或企业费用。
7. 财务或 BOSS 发放，系统核销 `Payable` 并写 `Ledger`；单人企业由同一 BOSS 逐步完成，不得跳过确认节点。
8. 员工工资/提成实际发放成功后，员工才读取本人工资条。

### 6.2 提成

1. 主合同签约，财务或系统形成 `CommissionItem`，录入提成基数和手工比例。
2. 确认计提：生成提成 `Payable`，按唯一归属计项目成本或企业费用。
3. 客户回款，系统按累计有效回款比例自动计算本次释放金额。
4. 达到可释放金额后并入工资发放批次或单独发放。
5. 发放时核销原提成 `Payable`，写资金流水，不改历史成本。
6. 退款、离职、跨期生成负向条目，下期处理。

### Web 财务端

- 员工薪酬方案列表/详情；
- 月度考勤申报和确认；

- 店长：本店考勤确认、本店员工个人工资构成；
- 员工：本人工资条、本人提成、本人考勤和申诉入口。

## 0. 本规范要解决的四件事

1. **对外数字口径一致**：同一个业务概念，在任何页面、任何端、任何报表、任何 AI 摘要里，使用同一公式、同一数据源、同一时间口径。
2. **财务口径命名一致**：一个概念只有一个标准名称；公式不同必须换名；页面不得用两个名字指同一个数，也不得用一个名字指两个不同的数。
3. **每个对外数字都有完整口径说明**：装企看到的每个金额/比率/数量，都能点开看到定义、公式、来源、时间、范围、缺失值、负责人和更新时间。
4. **财务记账可解释、可验证**：除总纲外，单独建立财务记账口径说明和操作说明，让 BOSS/财务/研发/验收/运营都能解释“这个数从哪来、为什么是这个数、怎么核对”。

## 1. 财务边界与红线

装得清只做**项目经营账 + 资金台账 + 经营核算**，不做会计总账、会计科目、借贷分录、税务申报和审计报告。

对外统一口径：

> **装得清管项目和钱，不管税和账。**

| 边界 | 说明 |
| --- | --- |
| L1 必须承载 | 合同/应收/收款、采购/应付/付款、项目成本与毛利、工人工资、资金台账、凭证、期初承接 |
| L2 轻量可关停 | 员工工资、公司经营利润（参考）、门店经营视图；企业可关停，不阻断主链 |
| L3 不承载 | 法定会计总账/科目/借贷分录、税务申报、发票管理、社保公积金、完整 HR、复杂成本分摊、合并报表 |

**红线**：任何数字都不能被用户误当成会计、税务或审计依据。公司利润统一称「经营利润（参考）」，成本或费用不完整时返回 `null` 或「暂不可确认」，不得按 0 计算或展示伪利润。

## 2. 命名规范

### 2.1 五条命名原则

1. **一概念一名**：同一业务含义只能有一个标准名，禁止同义词在不同端各自命名。
2. **名实一致**：名称必须直接表达口径。收款单金额叫「收款额」，应收核销合计叫「已收金额」，台账收入叫「资金收入」，不得都叫「回款」。
3. **钱账分离**：合同额、收入、应收、收款、成本、应付、付款、现金流是不同概念，禁止互相替代。
4. **期间/时点标注**：同一指标有累计值和期间值时必须标注，例如「累计回款」「本月回款」；不得只写「回款」。
5. **口径不同就换名**：公式或数据源不同的两个数字，必须使用不同名称，并在口径说明里写明差异。

### 2.2 标准术语对照表（建议冻结）

| 标准名（建议） | 英文键（建议） | 定义 | 禁用/慎用别名 | 数据来源 |
| --- | --- | --- | --- | --- |
| 合同当前金额 | `contractCurrentAmount` | 原合同金额 + 已确认变更 | 合同额、签约额混用 | `ProjectContract.currentAmount` |
| 签约额 | `signedAmount` | 按签约日归月的新签合同金额（业务口径可含/不含结转，待裁决） | 合同额、合同当前金额 | `ProjectContract.signedAt/currentAmount/baselineAmount` |
| 项目合同额 | `projectContractAmount` | 项目上的合同金额汇总，用于项目账本/财务工作台 | 签约额、合同当前金额混用 | `Project.contractAmount` |
| 应收金额 | `receivableAmount` | 应收计划节点金额合计 | 收入、合同额 | `Receivable.amount` |
| 已收金额 | `receivedAmount` | 应收节点已核销的收款合计 | 收款额、回款额、收入 | `Receivable.receivedAmount` |
| 待收金额 | `outstandingAmount` | 应收金额 − 已收金额（逐条不小于 0） | 未收、欠款（可作口语） | 应收节点派生 |
| 逾期应收 | `overdueAmount` | 到期未收/状态逾期的未收余额合计 | 坏账（不使用） | 应收节点 + 到期日 |
| 收款额 | `receiptAmount` | 收款单实际金额合计（可按累计/本月） | 回款额、已收金额、收入 | `Receipt.amount` |
| 回款额 | `collectionAmount` | **待裁决**：建议专指客户实际收到的款项（Receipt 口径），按 `receivedAt` 归期 | 收款额、收入 | `Receipt` |
| 本月回款 | `monthReceiptAmount` | 本月实际收款单金额合计 | 本月收入、本月流水 | `Receipt.receivedAt` |
| 资金收入 | `monthIncome` | 本月 Ledger `Income` 合计（含收款、手工收入等） | 本月回款、营业收入 | `Ledger.direction=Income` |
| 回款率 | `collectionRate` | 已收金额 ÷ 应收金额 × 100% | 收款率、转化率 | 应收/已收 |
| 应付金额 | `payableAmount` | 应付单金额合计 | 成本、支出、合同应付 | `Payable.amount` |
| 已付金额 | `paidAmount` | 应付单已核销付款合计 | 支出、成本 | `Payable.paidAmount` |
| 待付金额 | `unpaidAmount` | 应付金额 − 已付金额（逐条不小于 0） | 未付、欠款 | 应付派生 |
| 付款额 | `paymentAmount` | 付款单实际金额合计 | 支出、成本、已付金额 | `Payment.amount` |
| 预计成本 | `estimatedCost` | 按合同行冻结成本/报价快照形成的成本 | 预算、报价 | `ContractLine.cost`、`QuoteLine.cost` |
| 实际成本 | `actualCost` | 已实际发生的项目成本（到货/入库/人工/费用/工资确认） | 支出、已付、应付 | `ProjectCostContext` |
| 项目毛利 | `grossProfit` | 项目收入 − 项目成本 | 利润、净利、现金流 | `ProjectCostContext` |
| 项目毛利率 | `grossMargin` | 项目毛利 ÷ 项目收入 × 100% | 利润率、净利率 | 项目毛利/项目收入 |
| 公司经营利润（参考） | `operatingProfit` | 项目毛利合计 + 非项目收入 − 企业费用 | 净利润、利润、税务利润 | 公司利润口径（待建设） |
| 资金支出 | `monthExpense` | 本月 Ledger `Expense` 合计 | 成本、付款、费用 | `Ledger.direction=Expense` |
| 现金流 | `monthNetCashFlowAmount` | 资金收入 − 资金支出 | 利润、毛利 | Ledger 派生 |
| 账户余额 | `cashBalance` | 期初余额 + 累计资金收入 − 累计资金支出 | 现金、存款、周转金 | `OpeningBalance` + `Ledger` |
| 期初余额 | `openingBalanceAmount` | 入驻/月结起始时点的资金余额，不计入收支和利润 | 收入、现金 | `OpeningBalance` |
| 历史归档项目 | `historicalArchiveProject` | 结转接管且已结算的项目，按归档口径排除 | 已删除、作废 | `Carryover + Settled` |
| 手工记账 | `manualLedger` | 无业务单据来源、无法通过应收应付闭环形成的其他账务 | 手工收支、内部账 | `Ledger(source=Manual)` |

### 2.3 命名禁区

1. 不得用「利润」代指「项目毛利」；「利润」只用于「经营利润（参考）」或明确限定语。
2. 不得用「回款」代指「收入」「合同额」「应收」；回款必须有期间和收款口径。
3. 不得用「成本」同时表示预计成本、实际成本、应付金额、已付金额。
4. 不得用「现金」同时表示账户余额、现金流、可用资金。
5. 不得在同一产品里对同一标签使用两个公式（当前 Web/App「本月回款」已出现）。
6. 不得对外使用「净利润」「税务利润」「会计利润」「审计利润」。

## 3. 对外数字口径说明制度

### 3.1 每个对外数字必须具备的字段

| 字段 | 要求 |
| --- | --- |
| 指标 ID | 稳定编号，例 `MET-FIN-001` |
| 标准名 | 与第 2 节命名规范一致 |
| 英文键 | 前后端统一，不得同义不同名 |
| 业务问题 | 这个数字回答老板/财务什么问题 |
| 定义 | 一句话定义，不含公式 |
| 公式 | 明确分子、分母、范围、时间、缺失值 |
| 数据来源 | 对象 + 字段 + 事实来源单据 |
| 时间口径 | 按签约日/收款日/发生日/确认日/期间 |
| 统计范围 | 企业/门店/团队/项目/项目状态；是否含结转、归档 |
| 权限 | 谁能看、谁能改、敏感字段边界 |
| 缺失值 | 返回 `null`、显示「暂不可确认」「成本未完整」等 |
| 例外 | 退款、冲销、跨期、结转、归档、月结锁定等 |
| 展示位置 | 页面/组件/报表/AI 摘要 |
| 口径说明文案 | 用户可读的一段话，页面必须可打开 |
| 状态 | `draft / approved / verified / deprecated` |
| 证据 | `EV/DEC/BR/MET` 编号 |

### 3.2 口径说明的展示要求

1. 每个对外财务数字必须有「ⓘ 口径说明」入口；至少覆盖定义、公式、来源、时间、范围、缺失值、更新时间。
2. 数字必须能下钻到来源单据或明细列表；不能只给一个孤立金额。
3. 同一数字出现在多个页面时，口径说明必须同源；如口径不同，必须换名并在说明里写差异。
4. 口径说明由服务端提供统一元数据，不允许前端各自写一段文案。
5. 口径说明变更必须走第 8 节变更流程，并保留版本与生效日期。

### 3.3 核心对外指标字典（首批）

| 指标 | 当前公式/来源 | 展示位置 | 状态 |
| --- | --- | --- | --- |
| 合同当前金额 | `currentAmount`；为零回退 `baselineAmount` | 合同、项目账本 | 当前实现，待命名冻结 |
| 签约额 | Σ `businessOrigin=New` 且 `signedAt∈月` 的合同金额 | 首页、经营驾驶舱 | 当前实现，待裁决结转口径 |

## 4. 跨页面 / 跨端口径一致性规则

### 4.1 唯一口径主源

每个指标必须指定唯一「口径主源 Provider/Context」，其他页面只能引用或基于主源派生，禁止各自重新计算。

| 口径层 | 作用 | 主源建议 |
| --- | --- | --- |
| 合同/签约口径 | 合同、签约、变更 | `project/contract`、`statistic/boss/dashboard` |
| 应收/收款口径 | 应收、已收、待收、逾期 | `finance/receivable`、`finance/receipt` |
| 应付/付款口径 | 应付、已付、待付 | `finance/payable`、`finance/payment` |
| 成本/利润口径 | 预计/实际成本、项目毛利 | `ProjectCostContext`、`FinanceReportContext` |
| 资金口径 | 收入、支出、现金流、余额 | `finance/ledger`、`OpeningBalance` |
| 公司经营利润口径 | 项目毛利 + 非项目收入 − 企业费用 | 待建设 `finance/company/report` |

### 4.2 一致性规则

1. **同名同公式**：同一标准名在任何端必须同公式、同数据源、同时间口径。
2. **同数不同名**：同一业务事实若按不同范围/时间呈现，必须换名并标注范围/时间。
3. **差异显式化**：因归档、结转、期间、权限导致数字不同，必须在页面口径说明中写明「为什么不同」。
4. **缺失值统一**：成本/费用不完整统一 `null` + 「成本未完整」；数据不可读统一「暂不可确认」；不得用 0 伪装。
5. **权限优先**：数据范围不同导致的差异不得用前端隐藏掩盖，必须服务端强制。
6. **月结锁定**：已月结期间的数字不能因新操作变化；调整走冲销/补差并标注。

## 5. 财务记账口径说明与操作说明

**单独成文**：`docs/product/2026-10-07-装得清财务记账口径与操作说明（草案）.md`。

该文档必须覆盖：

1. 装得清记账边界（是什么账、不是什么账）。

## 6. 对外展示与表达边界

### 6.1 可以说

- 装得清把销售价、成本价、实际成本和项目毛利分口径管理；成本不完整时提示「成本未完整」，不用 0 成本制造假利润。
- 装得清按「项目毛利 + 非项目收入 − 企业费用」展示经营利润（参考），往来不计入。
- 项目人员工资/提成进项目成本；企业人员工资进企业费用。
- 每个数字都可以查看口径说明和下钻到来源单据。

### 6.2 不可说

- 装得清替代财务核算、审计、税务申报、个税/社保代缴。
- 系统展示的是财务净利润/税务利润/审计利润。
- 使用后利润一定提高、成本绝对准确。
- 「回款」等于「收入」，「毛利」等于「利润」。

### 6.3 必须附条件

- 「经营利润（参考）」必须附「经营参考口径，不是净利润」。
- 「项目毛利」必须附成本完整性状态。
- 「现金余额」必须附期初口径与是否已承接。

## 7. 验证与验收清单

### 7.1 文档门禁

- [ ] 所有对外财务数字在指标字典中有卡，字段齐全。

### 7.2 数据门禁

- [ ] 同一指标在 Web/App/报表/AI 摘要中数字一致（或差异可解释）。
- [ ] 合同金额 vs 应收合计、应收已收 vs 收款合计、应付已付 vs 付款合计、收付款 vs Ledger 来源全部对平。
- [ ] 成本不完整时不显示利润，毛利率为 `null`。

- [ ] 期初承接后现金余额不再异常为负（如有真实负数需可解释）。

### 7.3 页面门禁

- [ ] 每个数字有口径说明入口。
- [ ] 每个数字可下钻到明细/单据。
- [ ] 缺失值、未设目标、无基期、成本未完整的展示文案统一。
- [ ] 权限与数据范围正确，敏感字段不外泄。

## 9. 交付物与变更流程

业务智能体裁决后应形成：

1. `DEC-*`：财务规范与数字口径一致性正式决策；
2. `BR-*`：命名规范 + 跨页面一致性规则；
3. `MET-*`：首批对外指标卡（签约额、回款额、项目毛利、财务工作台各金额、公司经营利润等）；
4. `SCN/SOP`：财务记账口径说明 + 操作说明 + 验证手册；
5. 更新 `01-知识库/07-术语/术语表.md` 与 `06-状态/场景覆盖看板.md`；
6. 回改 `docs/design/27-财务记账体系全景与口径总纲.md`，去掉「草案」状态或明确正式版引用。

变更流程：

```text
需求/代码/页面发现口径或命名问题
-> 登记 GAP 或 REQ-BIZ
-> 业务智能体裁决，形成/更新 DEC/BR/MET
-> 更新本规范与指标字典
-> 研发按新口径回改 Provider/Context/前端文案
-> 验收按口径一致性清单与线上样例验证
-> 发布后在 CHANGELOG/覆盖看板登记
```

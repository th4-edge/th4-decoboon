# 客户休眠状态与风险跟进排除 P0 产品规格

> 日期：2026-10-08  
> 状态：业务裁决完成，可研发使用，代码尚未实现  
> 业务依据：`DEC-042`、`BR-036`、`SCN-020`、`ANS-BIZ-20261008-002`  
> 研发交接：`T12-BIZ-20261008-003`  
> 适用端：后端、App、Web  
> 范围边界：签约前客户经营状态；不做项目暂停、客户自助操作和自动定时唤醒

## 1. 目标

新增客户状态 `Dormant（休眠客户）`，让业务员、店长和企业负责人能够把暂不推进的签约前客户设为休眠：

- 必须录入休眠原因；
- 休眠后不再产生客户风险、自动跟进提醒和工作台待办；
- 历史事实、金额、合同和项目数据不删除、不改变；
- 客户恢复后回到休眠前状态，重新参与风险和待办计算；
- 全程幂等、可追溯、可审计。

## 2. 状态与语义

```text
New / Following / PendingMeasure* / Quoted*
  -> Dormant
  -> Restore 到 statusBeforeDormant
```

`* PendingMeasure` 仅在没有未来量房预约时允许；`Quoted` 仅在没有待签约、已签约、已生效或待处理正式合同时允许。

禁止进入休眠的状态：

- `Signed`：合同已签，使用合同/项目机制；
- `Serving`：项目履约中；
- `Finished`：已完工；
- `Lost`：已流失，不能掩盖流失原因。

## 3. 业务规则

### 3.1 设置休眠

1. 服务端按当前登录员工解析企业和数据范围。
2. 角色必须为 `Boss`、`StoreManager` 或 `Marketer`。
3. 范围必须分别为本企业、本门店、本人负责客户。
4. 当前状态必须允许休眠。
5. 原因编码必填，选择“其他”时说明必填。
6. 校验无未来量房预约、无未结束正式合同。
7. 保存 `statusBeforeDormant`、原因、备注、操作人、时间和请求号。
8. 清空 `nextFollowAt`。
9. 状态改为 `Dormant`，写入状态日志。
10. 立即刷新风险和阶段计数。

### 3.2 恢复

- 默认恢复到 `statusBeforeDormant`。
- 恢复后可要求填写新的下次跟进时间，不得恢复旧 `nextFollowAt`。
- 如果休眠前状态不再满足当前事实，返回 409，不静默选择其他状态。
- 恢复后重新参与风险和自动待办。

### 3.3 写跟进自动唤醒

客户处于 `Dormant` 时保存跟进：

1. 校验跟进可见范围；
2. 在同一事务中恢复 `statusBeforeDormant`；
3. 保存跟进记录；
4. 写入 `FollowWake` 状态日志；
5. 刷新风险和待办。

## 5. 原因字典

| code | label | 说明 |
| --- | --- | --- |
| `PlanPostponed` | 装修计划延期 | 客户明确未来再装修 |
| `BudgetUndecided` | 预算或方案未定 | 预算/方案未成熟 |
| `DecisionPending` | 决策未确定 | 决策人未确认 |
| `CustomerRequestedPause` | 客户要求暂缓联系 | 客户主动要求 |
| `ContactUnreachable` | 长期无法有效联系 | 多次联系无有效沟通 |
| `LeadPendingVerification` | 线索待核实 | 有效性或重复性待确认 |
| `Other` | 其他 | 备注必填 |

“已选择其他公司、明确拒绝装修、确认无效”应使用 `Lost`，不得使用休眠。

## 6. 风险与统计

休眠客户必须做到：

- 不进入逾期跟进、今日跟进、近三日跟进；
- 不进入沉睡风险；
- 不进入未分配负责人风险；
- 不进入设计、报价、签约工作台自动队列；
- 不计入风险客户数和风险排序；
- 风险等级中性，下一步动作显示“恢复跟进”。

统计口径：

- 全部客户：包含休眠；
- 休眠客户数：`status = Dormant`；
- 风险客户数：只统计活跃客户；
- 阶段统计新增“休眠”桶，不并入流失；
- 历史有效跟进：已发生事实不因休眠删除。

## 7. 数据模型

### 7.1 枚举

```text
CustStatus.Dormant("休眠客户")
```

### 7.2 客户字段

- `statusBeforeDormant`
- `dormantReasonCode`
- `dormantReasonText`
- `dormantAt`
- `dormantBy`
- `restoredAt`
- `restoredBy`

### 7.3 状态日志

新增 `cust_customer_status_log`：

- `logId`
- `company`
- `customer`
- `fromStatus`
- `toStatus`
- `changeType`：`Dormant / Restore / FollowWake`
- `reasonCode`
- `reasonText`
- `operator`
- `operatorRole`
- `requestId`
- `createdAt`

建议唯一键 `(com_id, request_id)`，索引 `(com_id, cust_id, created_at desc)` 和 `(com_id, to_status, created_at)`。

## 8. API 契约

### 8.1 设置休眠

```http
POST customer/customer/dormant
```

```json
{
  "customerId": "123",
  "reasonCode": "PlanPostponed",
  "reasonText": "客户计划明年装修",
  "expectedStatus": "Following",
  "requestId": "全局唯一请求号"
}
```

### 8.2 恢复

```http
POST customer/customer/resume
```

```json
{
  "customerId": "123",
  "restoreStatus": "Following",
  "nextFollowAt": "2026-10-15T10:00:00",
  "requestId": "全局唯一请求号"
}
```

### 8.3 状态日志

```http
POST customer/customer/status-log/page
```

### 8.4 错误码

| 场景 | 返回 |
| --- | --- |
| 越权或跨范围 | 403/404 |
| 缺少原因 | 400 |
| 当前状态不允许 | 409 |
| 未来量房或正式合同阻断 | 409 |
| 重复请求 | 幂等成功 |
| 并发冲突 | 409 |

## 9. 页面要求

### Web

- 业务员客户页、店长客户页、企业负责人客户经营页增加“休眠/恢复”动作。
- 列表增加“休眠”筛选与状态标签。
- 弹窗展示风险暂停影响、原因必填和条件校验结果。
- 详情展示休眠原因、时间、操作人、原状态和恢复入口。
- 通用客户编辑不得直接修改状态。

### App

- 客户列表增加“休眠”筛选和状态标签。
- 业务员、店长、企业负责人客户详情操作面板增加“设为休眠/恢复跟进”。
- 使用受控底部弹窗录入原因。
- 休眠客户写跟进时提示将自动恢复原状态。

## 10. 非功能要求

- 状态修改与日志同事务；
- 使用客户级分布式锁或等价幂等控制，不滥用数据库锁；
- 并发设置/恢复只允许一个成功；
- 响应只返回客户端页面实际需要字段；
- 风险排除必须通过共享服务端规则，不允许 App/Web 各自推算；
- 旧客户端不支持 `Dormant` 时，禁止先产生状态，避免显示回退为“待首联”。

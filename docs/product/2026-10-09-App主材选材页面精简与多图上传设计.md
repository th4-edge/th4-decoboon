## 2. 核心口径（DEC-056）

- **门禁不取消**：合同主材下单前，仍必须存在"已选材（现场确认）"记录。
- **判定载体改写**：具备维护权限的角色在明确房屋 + 合同/项目上下文中保存选材结果，即视同满足门禁，不再要求客户系统内独立确认。
- 选材仍是文本化留档，不改变报价、合同、成本、材料计划数量、采购与库存。
- 进入采购后锁定、换材走增减项，**不变**。

## 3. 状态机

```
选材记录： 未选材 --保存--> 已选材（现场确认） --交付财务--> 已交付（可下单）
                              ↑ 进入采购前可改并形成新版本 ┘
                                        进入采购后锁定（换材走增减项）

材料计划行：Planned（待选材） --交付财务下单--> ReadyToOrder（待财务下单）--> 下单/到场
```

- 删除 `Draft`、`PendingConfirm`；新增/改名 `Selected`（已选材，现场确认）。
- 存量 `Draft`/`PendingConfirm` 需兼容迁移为 `Selected`，或保留只读，不得丢失确认事实。
- "交付财务下单"只推进到 `ReadyToOrder`，不等于下单；下单仍由财务执行（`DEC-MP-03`）。

## 4. 页面结构（线框见 §8）

**列表页 `selection.vue`**
- 顶部：项目名、合同号、房屋地址、设计师（**删除客户姓名**）。
- 进度：`已选材 x/n`、`已交付财务 x/n`（删除"客户确认"进度）。
- 筛选：`全部 / 待选材 / 已选材 / 已交付 / 已进入采购`（删除草稿、待确认）。
- 主按钮：`一键交付财务下单`（批量把"已选材未交付"推进到 `ReadyToOrder`，交付前提示未完成项数）。
- 次按钮：`材料计划`。
- 列表项：主材名 + 合同要求 + 选材结果摘要 + 状态标签 + 缩略图数（如有照片）。

**单项页 `selection-item.vue`**
- 合同要求区（分类/品牌/规格/数量，只读）。
- 选材结果区：颜色/花色、规格/型号、品牌/系列、工艺/材质、现场备注。
- 照片区：多图上传（追加/预览/删除）。
- 动作区：
  - `保存`（就地保存，状态=已选材）
  - `保存并交付`（保存 + 计划行 `Planned → ReadyToOrder`）
  - 已交付：显示"已交付财务，等待财务下单"
  - 已进入采购：锁定提示 + `去发起增减项`
- **删除**：保存草稿、提交客户确认、客户确认区、客户确认人姓名输入、客户已确认按钮。

**业主页 `owner-selection.vue`**：只读留档，展示选材结果，删除任何确认交互；照片展示为后续待办（后端已开放 `FileScope.MaterialSelection` 业主授权，页面尚未渲染）。

## 5. 字段与照片规则

- 选材字段保持引导式文本，落库 `content` + `selectionJson`，符合 `DEC-003` 文本化边界。
- 照片：
  - 复用 `src/domains/file/choose-media.ts`（`chooseImages`，单次最多 9 张，相册/相机）。
  - 支持追加、预览、删除；建议单分项上限 9 张。
  - 落 `MaterialSelection.attachments`，仅留证，不进金额/成本/数量/采购。
  - 上传失败保留已成功项与重试入口，不静默丢图。

## 6. 权限与账务

- 维护角色按 `DEC-035`：**Designer / Boss / StoreManager / Finance**；**Pm / TeamLeader / Marketer 只读**。
- **需修偏差**：App `EDIT_ROLES` 当前含 `pm/teamLeader`，与 `DEC-035` 冲突，本次一并改为上述四角色。
- 服务端按企业、房屋、项目参与关系、数据范围校验，不信任前端参数。
- 选材/交付不改变报价、合同、成本、数量、采购与库存。
- 交付后计划行出现在财务"待下单"；下单形成应付（`DEC-MP-01`）；成本缺失时 `costComplete=false`、利润 `null`，禁止伪利润。

## 7. 真实场景

**场景 1（现场确认 · 麦鸿装饰）**：设计师与客户现场逐项选定瓷砖/木门花色型号，填写 + 拍照 → 保存为"已选材（现场确认）"→ 一键交付 → 财务待下单。异常：某项已进入采购 → 锁定 + 引导增减项。

**场景 2（逐项沟通代录 · 30 人装企）**：客户微信逐项回复，设计师分次填写保存 → 全部完成后列表页一键交付；漏填项在"待选材"筛选可见，交付前提示未完成项数。

**场景 3（反向 · 已采购）**：材料已下单/已到场，设计师尝试修改 → 拒绝，文案含"发起增减项"。

## 10. 不做什么

- 不把选材拆成报价/成本/数量/采购结构化数据。
- 不由选材自动生成采购单或应付；下单仍由财务执行。
- 不让照片参与金额、成本或结算。
- 不在页面维护本地状态机。
- 不放开已进入采购的选材修改。

## 11. 验收标准

- 正向：范围内保存选材 → "已选材（现场确认）" → 单项/批量交付 → `MaterialPlan=ReadyToOrder`。
- 反向：已进入采购的分项保存/交付被拒，文案含"发起增减项"。
- 越权：Pm/TeamLeader/Marketer 写入被拒；跨企业、跨店、非项目范围被拒。
- 幂等：重复交付不重复推进状态、不产生第二版本。
- 照片：多图上传成功、可预览删除、失败可重试、不进入金额。
- 金额边界：选材/交付不改变报价、合同、成本、材料计划数量、采购与库存。
- 兼容：存量 `Draft`/`PendingConfirm` 记录不丢失、可追溯。

## 1. 员工选择器

```text
选择器名称: App 员工专用选择页
对应页面: company/pages/employee-picker
关联业务对象: Employee
唯一标识: empId
```

### 使用场景 A：离职交接

- 使用人：企业负责人。
- 触发事件：员工离职前需要把客户、房屋、项目与任务转给在职员工。
- 当前动作：打开员工选择页，排除离职员工本人，只展示在职员工。
- 系统下一步：选择结果回到离职交接页，提交服务端再次校验企业、门店和在职状态。
- 异常：无候选、接口失败、离职员工被选、跨范围员工均由前端阻断并保留恢复路径。

### 使用场景 B：施工任务负责人

- 使用人：企业负责人、店长、项目经理或任务编辑权限持有者。
- 触发事件：编辑施工任务时需要调整负责人。
- 当前动作：只允许选择 Boss、StoreManager、Pm、Designer、Marketer 中的在职员工。
- 系统下一步：保存任务时采用选中的 `Employee` 对象，服务端复核企业归属与数据范围。
- 异常：岗位不在允许集合、员工状态不是在职、接口失败时禁止静默回退。

### 统一参数

- `source=directory|payroll`：普通员工目录或薪酬目录。
- `roles=Boss,Pm,...`：允许岗位集合。
- `activeOnly=1`：只展示并允许选择在职员工。
- `excludeEmpId`：排除当前离职员工本人。
- `selectedId/selectedName/selectedMeta`：当前选择回显。
- 服务端参数：`current / size / keyword / role / status / storeId / excludeEmpId`。

## 2. 工人选择器

```text
选择器名称: App 工人选择页
对应页面: labor/pages/worker-picker
关联业务对象: Worker
唯一标识: workerId
```

### 使用场景

- 财务工资类付款需要选择发放工人，用于工资凭证的证件号、工种和银行账号栏位。
- 付款记录已生成但工人缺失时，需要补录工人并重打原工资凭证。
- 工人选择不得影响付款金额、账户、日期、应付核销、台账或项目成本。

### 展示与筛选

- 首屏展示工人姓名、工种、手机号、状态。
- 默认在职；可切换全部用于历史核对。
- 服务端搜索姓名、工种、手机号，数据库分页。
- 选择结果通过一次性通道返回，不允许来源页全量拉取工人数组。

## 3. T16 表单结果区

- 离职交接：接收人使用全宽员工卡，展示岗位、门店、团队和状态。
- 任务编辑：任务负责人使用全宽员工卡，清除后保存空负责人。
- 工资付款：填表时展示发放工人卡；未选时明确提示凭证相关栏位可稍后补录。
- 付款补录：选择工人后只更新 `Payment.worker` 并重打凭证，不修改其他付款事实。

## 4. 验收矩阵

| 类别 | 用例 | 预期 |
| --- | --- | --- |
| 正向 | 离职交接选择接收人 | 排除离职员工本人，只能选在职员工 |
| 正向 | 任务负责人选择项目经理 | 回传员工卡，保存使用 `Employee` 对象 |
| 正向 | 工资付款选择工人 | 工人卡展示姓名/工种/手机号 |
| 正向 | 付款补录工人 | 选择页返回后补录并刷新付款记录 |
| 反向 | 离职员工本人出现在候选 | 不允许，服务端 `excludeEmpId` |
| 反向 | 任务负责人岗位越界 | 候选不展示，保存服务端复核 |
| 反向 | 非在职工人 | 默认不展示；全部状态下不可冒充在职 |
| 大数据 | 超过 20 条员工/工人 | 服务端分页并加载更多 |
| 失败恢复 | 选择页接口失败 | 展示错误和重试，不清空原选择 |
| 设备 | 320/390 宽度 | 无横向溢出 |

## 1. 真实使用场景

1. 企业负责人维护套餐分区，需要从持续增长的报价项目库中选入项目；项目库超过一页时，必须通过关键词在服务端定位，而不是先拉全量再端侧过滤。
2. 负责人先选中第一批项目，再搜索另一个关键词并补选；跨搜索、跨分页的已选项必须保留，确认后一次性加入当前分区。
3. 搜索、翻页或网络失败时，页面保留当前已选项；初始加载失败显示重试，加载更多失败保留已加载数据并允许重试。

## 2. T15 选型判定

| 字段 | 结论 |
| --- | --- |
| 业务对象 | `CatalogItem` 报价项目库项目 |
| 数据概念 | 远程、独立增长、可按类型和关键词检索 |
| 控件 | 套餐配置页内的专用选品面板 `CatalogPickerSheet` |
| Provider | `catalog/item/page` |
| 主筛选 | 项目类型、服务端关键词 |
| 分页 | `current` 从 1 开始，`size=20`，供应商硬上限 50 |
| 权限 | 延续登录企业与现有项目库数据范围；不新增角色或放宽权限 |
| 返回结果 | 所选 `CatalogItem` 对象数组，一次性回传套餐配置页 |
| 服务端复核 | `pack/item/save` 仍复核模板、分区、企业范围和同区间重复项目 |
| 禁止 | `size=200`、`findAll`、全量拉取后客户端过滤、跨页选择丢失 |

## 3. 交互与七态

| 状态 | 页面表现 |
| --- | --- |
| 初始加载 | 显示加载骨架，不闪空态 |
| 有数据 | 首屏最多 20 项，显示项目名称、品牌/规格/单位、成本单价和选中态 |
| 搜索无结果 | 显示“暂无匹配项目”，保留当前已选项 |
| 初始失败 | 显示失败原因与重试，不清空已选项 |
| 加载更多 | 触底请求下一页，显示加载中 |
| 加载更多失败 | 保留已加载项，底部显示点击重试 |
| 无更多数据 | 显示总数与“已全部加载” |
| 跨页选择 | 用 `Map<itemId, CatalogItem>` 保留已选项和数量 |

## 4. T16 表单与结果确认

- 选品面板底部持续显示已选数量和“加入当前分区”主操作。
- 跨页、跨关键词已选项不因列表刷新或搜索变化丢失。
- 确认前用户可通过已选数量和当前列表选中态识别选择结果；取消单项即从 `Map` 移除。
- 确认后一次性回传所选项目，套餐配置页调用现有 `pack/item/save`；保存成功后重新读取套餐详情，以服务端事实展示项目行。
- 不允许把“已选 N 项”当作唯一业务结果；保存后必须在对应分区看到项目名称、系数、计价方式和成本完整性。

## 5. T17 判定

本批不重做套餐编辑单据结构、价格公式、分区模型或保存动作，仅替换选品入口、搜索与分页加载方式，`T17` 单据化重做为不适用。

## 6. 验收负向用例

| 用例 | 预期 |
| --- | --- |
| 请求 `size=200` | 契约门禁失败 |
| 拉取列表后客户端 `filter` | 契约门禁失败 |
| 关键词不传 `catalog/item/page` | 契约门禁失败 |
| 滚动触底不加载下一页 | 页面验收失败 |
| 搜索后跨页已选项丢失 | 页面验收失败 |
| 初始加载失败无重试 | 页面验收失败 |
| 加载更多失败清空已加载项 | 页面验收失败 |
| 重复点击确认导致重复保存 | 沿用现有确认锁与服务端重复项目拦截 |

## 7. 当前结论

- 静态契约必须具备负向夹具。
- 真实页面必须验证首屏 20 条、服务端关键词、触底分页、跨页选择、失败恢复和保存后回读。
- 本评审是开发门禁，不代替独立 `RUN-*` 验收结论。

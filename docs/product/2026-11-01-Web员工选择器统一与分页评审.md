## 1. 选择器定义

```text
选择器名称: Web 员工专用选择器
对应角色: Boss、StoreManager、Finance、Designer、Pm（按具体动作和 Provider 权限）
关联业务对象/概念: Employee
```

## 2. 真实使用场景

### 场景 A：企业负责人转交客户负责人或指派项目成员

- 使用人：企业负责人。
- 触发事件：客户原负责人离职，或项目缺少项目经理、设计师、履约支持。
- 当前动作：打开员工选择器，按岗位、门店、状态和姓名定位员工。
- 系统下一步：选择结果进入全宽员工卡；提交时服务端复核企业归属、角色、门店和项目成员规则。
- 异常处理：接口失败保留原选择；员工离职、跨店或角色不符时禁止选择并说明原因。

### 场景 B：财务或店长处理薪酬、考勤、提成和费用代填

- 使用人：财务、店长、企业负责人。
- 触发事件：新增薪酬方案、月度考勤、提成或费用归属员工。
- 当前动作：在薪酬权限范围内按门店、岗位和状态选择员工。
- 系统下一步：保存时再次校验员工企业归属、门店范围和薪酬动作权限。
- 异常处理：门店范围外的员工不返回；员工失效时提示重新选择。

### 场景 C：项目经理或设计师调整任务负责人、筛选设计运营数据

- 使用人：项目经理、设计师、店长、企业负责人。
- 触发事件：调整施工任务责任人，或查看某设计师的方案和报价。
- 当前动作：通过普通员工目录选择器按岗位、门店、状态和关键词定位。
- 系统下一步：任务保存或方案筛选使用同一员工事实。
- 异常处理：普通目录权限与薪酬目录权限分离，不能以普通目录绕过薪酬范围。

## 3. 决策维度与首屏

优先级：

1. 门店：组织定位。
2. 岗位：动作可选项由场景限制。
3. 状态：默认在职，可查看停用/离职用于历史核对；非在职不可选择。
4. 关键词：姓名或手机号精细定位。

首屏必须展示员工卡片，不允许用户先搜索才看到候选。卡片至少展示姓名、岗位、门店、团队和状态。

## 4. 布局

- Web 使用对话框选择器：顶部搜索和状态，左侧岗位/门店筛选，主区员工卡片和加载更多。
- 表单来源页面使用全宽员工卡，展示姓名、岗位、门店、团队、状态、更换和清除。
- 筛选条使用紧凑员工摘要，展示姓名、状态、岗位和门店，不占用表单高度。
- App 继续使用独立员工选择页；两端业务语义和回传结果一致。

## 5. 统一机制

- 查询参数：`current / size / keyword / role / status / storeId / empId`。
- 分页：默认 20 条，服务端硬上限 50 条。
- 多角色限制：允许逗号分隔角色集合，例如 `Boss,Pm`。
- 已选回读：使用 `empId` 单独回读，不依赖第一页候选。
- 选择结果：一次性回传 `select(value) | clear`。
- 失败：保留原选择，展示“暂不可确认”和重试。
- 上下文变化：门店、岗位、状态或搜索条件改变时重新服务端查询。
- 权限：
  - 薪酬动作使用 `payroll/employee/page`，仅 Boss/Finance/StoreManager 可访问。
  - 普通员工目录使用 `user/employee/page`，沿用既有角色矩阵。
  - 服务端最终校验，不信任前端 empId。

## 6. T16 来源页面要求

- 业务对象选择区：员工卡必须满宽。
- 短字段区：薪酬金额、日期、比例等独立输入。
- 结果区：展示已选员工、状态、门店和本次业务影响。
- 主行动区：保存或确认动作只有一个主按钮。
- 更换员工：清空依赖该员工的薪酬、考勤、提成或任务上下文。
- 清除员工：不得把其他员工的事实带入新对象。

## 7. 验收矩阵

| 类别 | 用例 | 预期 |
| --- | --- | --- |
| 正向 | Boss 按多岗位加载员工 | 服务端返回限定岗位，首屏立即可见 |
| 正向 | 选择员工后来源页回显 | 显示姓名、岗位、门店、团队、状态，不只显示“已选择员工” |
| 正向 | 已选员工不在第一页 | 通过 empId 回读成功 |
| 大数据 | 员工超过 20 人 | 默认 20 条，可加载更多，无固定 200 条 |
| 反向 | 关键词无匹配 | 区分筛选为空并提供重置 |
| 越权 | 店长请求其他门店 | 服务端拒绝 |
| 越权 | 设计师调用薪酬员工 Provider | 403 |
| 状态 | 停用/离职员工 | 可查看但不可选择，保存时服务端拒绝 |
| 失败恢复 | 员工列表接口失败 | 保留原选择，显示重试 |
| 键盘 | 打开、关闭、清除 | 焦点可见，Escape 关闭后归还触发控件 |

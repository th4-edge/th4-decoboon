# T15 / T16 · Web 员工待发应付、原收款与项目筛选评审

> 状态：依据既有业务裁决执行
> 业务依据：`DEC-021` / `BR-019`、`DEC-023` / `BR-021`、`DEC-024` / `BR-022`
> 关联变更：`CHG-20261101-017`

## 1. 员工待发应付选择器

```text
选择器名称: EmployeePayablePicker
对应角色: Boss、Finance、StoreManager（按薪酬发放权限）
关联业务对象: EmployeePayable / Payable(EmployeeSalary|EmployeeCommission)
唯一标识: payableId
```

### 使用场景

- 使用人：企业负责人或财务。
- 触发事件：员工工资单或提成已生成应付，需要登记发放。
- 当前动作：在工资单来源、员工类型和门店范围内选择待发应付。
- 系统下一步：按选中应付的待发金额发起员工发放，写付款和资金台账。
- 异常处理：没有待发应付时说明来源或门店；接口失败保留原选择；非员工工资/提成类型不返回。

### 首屏与摘要

- 首屏展示员工姓名、应付名称、工资/提成类型、期间、应付/已发/待发金额、状态。
- 必须保留工资单来源约束：工资单详情内的发放只能选择该工资单产生的应付。
- 已选应付使用全宽摘要卡，展示员工、类型、期间、金额和状态。

### 统一机制

- 参数：`current / size / keyword / storeId / sheetId / type / payableId / empId`。
- 分页：默认 20 条，服务端硬上限 50 条。
- 选择、清除、回传和服务端复核与其他专用选择器一致。

## 2. 原收款选择器

```text
选择器名称: ReceiptPicker
对应角色: Boss、Finance、StoreManager
关联业务对象: Receipt
唯一标识: receiptId
```

### 使用场景

- 使用人：企业负责人、财务或店长。
- 触发事件：客户退款需要关联原收款。
- 当前动作：按项目、客户、付款方或备注搜索有效收款。
- 系统下一步：按原收款登记退款，写退款事实、资金台账和提成负向调整。
- 异常处理：接口失败保留原选择；已冲正收款不进入候选；退款金额不得超过原收款。

### 首屏与摘要

- 首屏展示项目、客户/付款方、原收款金额、收款日期、账户和核销节点。
- 只展示有效收款；已冲正收款不得选择。
- 已选原收款使用全宽摘要卡，并在来源表单自动带入可编辑退款金额。

### 统一机制

- 参数：`current / size / keyword / status`。
- 分页：默认 20 条，服务端硬上限 50 条。
- 已选详情通过 `finance/receipt/info` 按 ID 回读。

## 3. 项目筛选中的员工维度

- `ProjectPicker` 不再全量预取设计师和项目经理列表。
- 设计师筛选使用紧凑 `EmployeePicker`，角色限定 Designer。
- 项目经理筛选使用紧凑 `EmployeePicker`，角色限定 Boss/Pm。
- 选中后项目列表重新请求 Provider，`designerId/managerId` 进入服务端查询。
- 禁止通过 200 条项目反推项目经理候选。

## 4. T16 表单要求

- 员工待发应付位于发放单据的业务上下文区，使用全宽已选卡。
- 原收款位于退款单据上下文区，使用全宽已选卡。
- 金额、账户、日期为短字段，退款金额默认从原收款带入但允许用户按业务调整。
- 结果区展示待发/退款对象和金额，最终由服务端复核。
- 选择失败不得清空原值；更换对象必须重新校验来源和依赖字段。

## 5. 验收矩阵

| 类别 | 用例 | 预期 |
| --- | --- | --- |
| 正向 | 工资单来源内选择员工应付 | 仅返回该来源应付 |
| 正向 | 提成发放选择员工提成应付 | 类型正确，待发金额正确 |
| 正向 | 退款选择有效收款 | 显示项目、客户、金额、日期、核销节点 |
| 反向 | 已冲正收款 | 不进入候选 |
| 反向 | 非员工工资/提成应付 | 不进入员工发放候选 |

| 大数据 | 超过 20 条 | 服务端分页并可加载更多 |

| 失败恢复 | 接口失败 | 保留原选择并提供重试 |
| 响应式 | 1024/1280/1440 | 无横向溢出 |

## 1. 背景与已确认事实

### 1.1 已确认修复：套餐管理页草稿不显示

2026-11-02 已确认并修复套餐管理页草稿不可见问题：

- App 套餐管理页调用 `templateManagePage`，读取企业全部状态和版本；
- 套餐报价选择器调用 `templatePickerPage`，仍只读取 `Published + currentPublished`；
- 后端 `pack/template/page` 以 `publishedOnly` 区分管理列表和报价选择器；
- App 修复提交 `11a28af`，后端修复提交 `522c74a3`，均已进入 `dev/test/prod`；
- App `1.0.81 / 181` 开发版已上传，后端发布记录为 `20261102-123251`。

本文不再重复设计该缺陷，只把“管理列表可进入详情”作为后续套餐使用闭环的前置条件。

### 1.2 用户确认的新问题

1. 已发布套餐模板在 App 套餐管理页无法查看详情，只能面对发布态卡片，无法核对套餐内容。
2. 套餐配置中的分区使用横向排列；分区较多时出现横向滚动，占用和利用不平衡。
3. 业务设计中的套餐分区属于装企，是跨套餐复用的企业主数据；进入“套餐配置 → 分区”时应默认加载企业已有分区。
4. 项目配置中的类似分项名称较多，必须显示价格信息，帮助负责人通过名称、品牌、规格和价格共同识别。
5. 项目配置列表需要按分项类型分组统计，避免所有分项混排。

## 2. 产品目标

把 App 套餐模块从“能保存和发布”补齐为“能看懂、能复用、能核对、能继续操作”：

- 负责人能打开任意已发布、历史或停用套餐查看完整只读详情；
- 企业已有分区可直接复用，新增分区进入企业分区库；
- 分区较多时使用页面宽度，不再依赖横向滚动；
- 项目行同时用名称、类型、品牌规格和价格表达业务差异；
- 项目配置列表按分项类型分组，并显示可核对的类型数量。

## 3. 真实使用场景

### 场景一：麦鸿负责人维护品质整装套餐

- 使用人：企业负责人 BOSS。
- 触发事件：企业要基于已发布 V1 创建 V2 套餐，补充主材和定制项目。
- 当前动作：负责人进入套餐配置，打开分区步骤，复用企业已有的“全屋基础、厨房、卫生间、主材、软装电器”等分区；从报价项目库添加相近名称的瓷砖项目。
- 系统下一步：默认加载当前企业分区；每个分区以全宽卡片展示名称和项目数；项目行显示材料单价、人工单价或固定总价；列表按施工、主材、定制、软装、电器、综合分组统计。
- 异常处理：分区加载失败时保留当前草稿和已选分区，显示失败原因与重试；价格缺失显示“暂不可确认”，不得显示为 0 或自动选默认价格。
- 下游影响：负责人能够区分相近项目并完成 V2 配置；V1 历史报价仍使用原快照。

### 场景二：店长复用企业分区，设计师查看已发布套餐

- 使用人：店长、设计师。
- 触发事件：店长新增“阳台改造”企业分区；设计师需要查看当前发布套餐是否包含该分区及对应项目。
- 当前动作：店长在套餐配置中新增分区并选择项目；设计师从套餐管理进入已发布套餐详情。
- 系统下一步：店长看到企业全部分区并复用；设计师看到只读详情，包括套餐基本信息、分区、项目、价格和版本，不出现编辑、发布或停用入口。
- 异常处理：分区被任一套餐项目行引用时禁止删除；已发布套餐详情加载失败时显示“暂不可确认”和重试，不复用列表摘要伪造成详情。
- 下游影响：分区名称变化只影响后续套餐版本和报价快照，不改写历史报价；非成本角色看不到成本字段。

## 4. 功能需求

### R1 · 已发布套餐模板可查看详情

#### R1.1 入口与可达状态

- 套餐管理列表中的套餐卡片主体或“查看详情”动作必须可进入只读详情。
- 可查看状态至少包括：`Draft`、`Published`、`Disabled`，以及同编码历史版本。
- 有 `view:package-template` 能力的角色均可查看；是否有编辑、发布、停用动作继续按现有权限判断。
- 内部套餐编码、模板 ID 不在 App 业务界面展示；套餐版本号 `V1/V2/V3` 作为业务识别信息展示。

#### R1.2 详情页内容

详情页使用独立只读页面，不复用可编辑页面并仅隐藏按钮。至少展示：

| 信息组 | 必展示内容 |
| --- | --- |
| 基本信息 | 套餐名称、状态、版本、标准面积、套餐牌价、默认折扣、套餐说明 |
| 金额摘要 | 折后金额；标准成本与参考毛利率仅成本权限角色可见 |
| 分区与项目 | 按企业分区或套餐分区快照分组，展示项目名称、类型、品牌、规格、单位、数量系数、计价方式和价格 |
| 生命周期 | 当前是否发布版本、发布时间/更新时间；是否停用 |
| 操作 | 返回列表；维护角色对发布版本显示“创建下一版”，对草稿显示“继续配置”，停用/历史版本只读 |

#### R1.3 详情数据边界

- 详情必须按套餐 ID 回读 `pack/template/info` 或同语义 Provider，不能只使用列表摘要。
- 项目行、分区名称、计价方式、数量系数和价格必须来自服务端事实。
- 已发布套餐不能原页修改；编辑动作只能进入“创建下一版”。
- 成本字段继续由服务端按现有角色裁剪；非成本角色响应中不得包含成本。
- 历史报价、合同和项目不因查看当前套餐详情而变化。

#### R1.4 状态与异常

- 初始加载：骨架态，不闪空态。
- 加载失败：显示“套餐详情暂不可确认”、失败原因和重试。
- 无权限：返回列表并提示无权查看，不显示空壳详情。
- 套餐不存在或跨企业：显示不可访问，不泄露对象是否存在。
- 弱网/重复进入：以最后一次服务端回读为准，不保留过期编辑态。

### R2 · 企业级套餐分区复用与全宽展示

#### R2.1 数据归属

- `PackageSection` 归属当前企业，是企业级分区主数据，不归属单个套餐模板。
- 同一企业可创建多个套餐，并复用同一批企业分区。
- 分区名称、排序和空间类型由 BOSS、店长维护；财务、设计师及其他内部角色只读。
- 本次需求不改变分区的企业归属、角色权限和价格/成本公式。

#### R2.2 默认加载与复用

- 进入“套餐配置 → 分区”时，必须默认加载当前企业已有分区，不能先从当前套餐项目行反推。
- 已有分区即使当前套餐项目数为 0，也必须展示，并可用于后续添加项目。
- 分区按 `priority` 升序稳定展示；相同优先级按名称或创建时间稳定排序。
- 新增分区保存到企业分区库，成功后立即出现在当前页面；其他套餐下次进入时也可复用。
- 重命名属于企业级修改：后续套餐和后续报价快照使用新名称；历史报价中的分区名称快照不变。
- 删除仅允许未被任何套餐项目行引用的分区；已引用分区只能停用或保留，本期不新增停用语义时直接禁止删除。

#### R2.3 展示与交互

- 分区管理不使用单行横向滚动容器。
- App 使用全宽纵向列表或自适应网格，多个分区自然换行，页面不得出现横向滚动条。
- 每个分区卡片至少展示：分区名称、当前套餐内项目数、排序/空间类型摘要、选中态，以及维护角色可见的编辑/删除动作。
- “新增分区”使用整行主入口或独立卡片，不能挤在横向标签末尾。
- 点击分区卡片即切换当前分区；当前选中态必须明显。
- 项目配置步骤复用同一套分区数据和选择状态，不得再使用横向滚动标签。
- 分区数量为 6–10 个时，首屏应能明确看到至少一个完整分区卡片和“新增”入口，并可通过纵向滚动查看全部内容。

#### R2.4 加载与保存异常

- 初始加载失败：显示企业分区加载失败与重试，不清空当前套餐和项目行。
- 新增/重命名失败：保留用户输入和当前选中分区，允许重试。
- 删除失败：说明是否被套餐引用，不只提示通用失败。
- 并发重名或并发删除：服务端返回明确冲突，页面重新回读企业分区事实。

### R3 · 项目配置显示价格

#### R3.1 列表展示

项目配置中的每个项目行必须同时展示能够区分相近项目的信息：

- 分项名称；
- 分项类型；
- 品牌、规格、单位；
- 数量系数与标准面积折算用量；
- 计价方式；
- 报价项目库中的标准销售价格信息；
- 标准成本与本行成本仅成本权限角色可见。

#### R3.2 价格口径

价格必须按报价项目库当前计价方式表达，不在前端自行拼造新售价：

| 计价方式 | 展示要求 |
| --- | --- |
| 材料+人工 | 分别显示“材料 ¥x / 人工 ¥y”；如产品后续定义标准销售单价，再由服务端统一返回 |
| 仅材料 | 显示“材料 ¥x” |
| 仅人工 | 显示“人工 ¥x” |
| 固定总价 | 显示“固定总价 ¥x”，不得伪装成按工程量单价 |

价格缺失时显示“暂不可确认”或“价格待维护”，不能显示为 0。成本待维护仍按现有“成本未完整”语义表达，不能与销售价格混淆。

#### R3.3 识别效率

- 名称相同或相近时，品牌、规格、计价方式和价格必须在同一行或同一卡片内可直接比较。
- 编辑面板继续显示项目来源与价格摘要，避免用户进入编辑后才发现选错项目。
- 内部项目 ID、项目编码不作为 App 主要识别信息。

### R4 · 项目配置按分项类型分组统计

#### R4.1 分组顺序

固定按以下业务顺序分组，空组不展示：

```text
施工 → 主材 → 定制 → 软装 → 电器 → 综合
```

分组使用服务端项目类型字段或项目行类型快照，不能通过名称关键词猜测。

#### R4.2 统计范围

- P0 统计当前选中分区的项目数，例如“主材 8 项、定制 3 项、电器 2 项”。
- 项目列表按类型分组，每个组头显示类型名称和组内项目数。
- 切换分区后，统计和分组立即按当前分区重算。
- P1 可在分区管理顶部增加整个套餐的类型汇总，但不替代当前分区统计。

#### R4.3 金额边界

本批分组统计 P0 只统计项目数量，不计算类型销售金额小计。原因是套餐采用整体牌价，项目行销售金额存在整体分摊，直接展示“主材销售额”容易被误认为独立售价。若后续需要金额统计，必须先确认分摊口径。

## 5. 权限、数据范围与快照

| 角色 | 查看详情 | 分区维护 | 套餐维护 | 成本/毛利 |
| --- | --- | --- | --- | --- |
| BOSS | 企业内全部状态 | 可维护 | 可维护 | 可见 |
| 店长 | 企业内全部状态 | 可维护 | 可维护 | 可见 |
| 设计师 | 按现有查看范围只读 | 只读 | 只读，只可使用当前发布套餐报价 | 不可见 |
| 财务 | 按现有查看范围只读 | 只读 | 只读 | 按成本权限可见 |
| 其他内部角色 | 按现有查看范围只读 | 只读 | 只读 | 不可见 |

- 企业归属、门店、员工和数据范围只能从登录员工推导，前端传参不能扩大范围。
- 分区重命名、套餐发布和报价生成均不得回写历史报价快照。
- 查看详情与创建下一版是两个动作：查看不产生业务写入，创建下一版才生成新草稿。

## 7. 验收标准

### 7.1 已发布套餐详情

- [ ] 已发布套餐从管理列表可进入详情，详情包含基本信息、分区、项目行和价格。
- [ ] 历史版本、停用版本可只读查看；已发布版本没有原地编辑入口。
- [ ] BOSS/店长可从详情创建下一版；草稿可继续配置。
- [ ] 详情只使用服务端回读事实，列表摘要不能代替项目行详情。
- [ ] 非成本角色看不到成本与毛利字段。
- [ ] 跨企业套餐 ID 不可读取。

### 7.2 企业分区与交互

- [ ] 进入分区步骤时默认显示企业已有分区，包括当前套餐尚未使用的空分区。
- [ ] 新增分区后当前套餐和其他套餐均可复用。
- [ ] 6–10 个分区时页面无横向滚动，分区卡片使用完整内容宽度并自然换行。
- [ ] 项目配置步骤同样无横向滚动，切换分区不丢当前选择。
- [ ] 已引用分区删除被拒绝并给出具体原因；历史报价快照不变。
- [ ] 分区加载失败、保存失败和并发冲突均有明确恢复路径。

### 7.3 项目价格与分组

- [ ] 每个项目行可见分项名称、类型、品牌规格、单位、计价方式和价格。
- [ ] 材料+人工、仅材料、仅人工、固定总价四类计价方式按各自口径展示。
- [ ] 相近名称项目可通过品牌、规格和价格直接区分。
- [ ] 价格缺失显示“暂不可确认”，不显示 0。
- [ ] 当前分区按施工、主材、定制、软装、电器、综合分组，组头和顶部均显示项目数。
- [ ] 分组类型来自服务端事实，不通过名称解析。
- [ ] P0 不展示类型销售金额小计，避免误用套餐分摊金额。

### 7.4 全局与异常

- [ ] App 端通过类型检查、套餐契约、构建和分包检查。
- [ ] 至少覆盖加载中、有数据、真实空态、无权限、接口失败、弱网重试和返回页面回读七态。
- [ ] 至少完成一款真实小程序页面和一款目标真机验证；未执行时只能标记待验证。
- [ ] App 与后端使用同一 `pack/template/info`、`pack/section/*`、`pack/line/*` 语义，不新增 App 专用业务规则。

## 8. 非范围

- 不修改套餐牌价、面积比例、折扣、税金、成本和毛利公式。
- 不改变 `Draft/Published/Disabled` 生命周期、发布不可变和报价快照规则。
- 不改变分区、套餐、报价项目库的角色权限矩阵。
- 不新增平台行业套餐基线或默认套餐。
- 不用前端价格汇总替代套餐整体牌价。
- 本批不在 Web/Admin 重做页面，但后续必须复用同一后端语义和字段口径。

## 9. 推荐实施顺序

## 1. 一句话定义

> **Excel 记录结果，微信群传递信息；AI 数字化经营把业务事实变成老板能理解、能判断、能行动、能回读的经营过程。**

装得清不取消 Excel，也不取代微信群沟通。它改变的是：**业务事实、经营判断和行动闭环不再由 Excel 与微信群共同承担。**

```text
Excel       = 事后表格、个人经营模型
微信群      = 即时沟通、口头协调
装得清      = 持续经营事实 + AI 理解与提醒 + 责任行动 + 结果回读
```

## 2. 老板今天如何经营

### 2.1 目标老板

- 10–30 人、1–3 家门店的成长型装企老板。
- 一人承担多个内部岗位的一人装企老板。
- 需要同时看客户、报价、项目、现金和利润，但不可能每天进入全部岗位页面。

### 2.2 Excel 和微信群为什么长期存在

它们并非落后工具，而是分别解决了两件真实事情：

| 工具 | 真实价值 | 老板为什么继续用 |
| --- | --- | --- |
| Excel | 可自由建表、计算、筛选、汇总、导出 | 能快速形成自己的经营口径，不依赖系统 |
| 微信群 | 快速通知、询问、协调、发图片和文件 | 所有人在线，响应直接，老板随时可以问 |

因此，数字化经营不能只做“另一个录入表单”。如果系统比 Excel 更难调整、比微信群更慢协同，老板就会回到原工具。

### 2.3 两者的共同缺口

| 缺口 | Excel + 微信群表现 | 对老板的影响 |
| --- | --- | --- |
| 无唯一业务事实 | 多份表、多版报价、群文件和各人记忆并存 | 不知道哪个数字可信 |
| 沟通不等于状态 | 群里说“已经安排了”，系统状态没有变化 | 需要反复确认谁真的做了 |
| 结果与过程分离 | Excel 只有结果，群聊只有过程 | 出问题后无法解释从哪里开始 |
| 风险靠人发现 | 老板追问、员工汇报、公式告警 | 容易晚发现或漏发现 |
| 无责任闭环 | @某人后没有状态回读 | 事情“说过了”但没有完成 |
| 财务二次加工 | 业务数据再抄进 Excel 汇总 | 重复录入、口径不一致、月底重算 |
| 企业记忆留不住 | 群记录难检索，经验留在个人 | 新人和交接依赖老员工 |

## 3. 什么是 AI 数字化经营

AI 数字化经营不是增加一个 AI 聊天入口，也不是让 AI 自动替老板做决定。

### 3.1 五层定义

```text
第一层：业务事实数字化
客户、房屋、报价、合同、项目、材料、收付款和成本成为连续事实

第二层：经营规则可执行
阶段、责任人、风险、下一步、成本和权限由系统和业务规则共同保障

第三层：AI 理解与解释
把分散事实转成经营变化、异常原因、影响范围和来源依据

第四层：人确认行动
老板和责任角色确认、指派、审批、推进或调整

第五层：结果回读与记忆
动作改变正式业务状态，结果被重新读取并沉淀为企业经营记忆
```

### 3.2 什么才是“AI 数字化经营”

| 不是 | 而是 |
| --- | --- |
| 一个独立 AI 聊天框 | 嵌入经营入口和业务对象的 AI 副驾 |
| 自动生成一段漂亮报告 | 基于当前业务事实解释变化、风险和下一步 |
| AI 猜测利润和原因 | 数字可追溯，来源不足时明确“暂不可确认” |
| AI 自动改价、派单、验收和付款 | AI 建议，责任角色确认，正式动作按原规则执行 |
| 把 Excel 上传给 AI 做摘要 | 业务事件持续进入系统，AI 使用有权限的实时事实 |
| 用 AI 数量衡量数字化 | 用经营判断、行动闭环和数据可信度衡量 |

### 3.3 老板购买的不是 AI，而是经营确定性

老板真正希望获得：

- 不用每天追问，也知道公司现在怎么样；
- 不用翻群和表，也知道哪一单最需要处理；
- 不用等财务月底重算，也知道钱和利润发生了什么；
- 出了问题能追到事实、责任人、影响和恢复路径；
- 公司越用越有记忆，而不是越做越依赖个人经验。

## 5. 老板一天的投影路径

### 5.1 早上：从“追问”变成“先看判断”

**Excel + 微信群**

```text
打开几张表
-> 在多个群问签约、回款、项目情况
-> 等设计、项目、财务分别回复
-> 自己拼出今天先处理什么
```

**AI 数字化经营**

```text
打开经营首屏
-> 先看今天发生了什么变化
-> 看最重要的风险与机会
-> 点开来源，确认事实
-> 选择一单直接处理
```

**装得清投影**

- 首页不是角色菜单集合，而是经营事实和待处置事项。
- 经营简报必须带数据截止时间、来源和可下钻对象。
- 风险不能只有颜色，要给出原因、责任人和下一步。
- 数据源失败显示“暂不可确认”，不显示伪零。

### 5.2 白天：从“群里安排”变成“对象内推进”

老板发现一个客户停滞、报价待确认或项目风险后：

```text
经营异常
-> 进入同一单
-> 看当前事实和上游来源
-> 完成当前唯一主行动
-> 查看下一责任人
-> 读取动作后的新状态
-> 返回继续处理下一项
```

这条路径整合的是现有客户、报价、合同、项目、材料、验收和财务能力，不新增业务链路。

### 5.3 月底：从“Excel 重算”变成“经营事实对账”

**Excel 现状**

```text
从系统或多人手中收集数据
-> 复制到多张表
-> 手工核对收款、付款、成本和利润
-> 发现差异再回群追问
-> 形成老板版经营结论
```

**AI 数字化经营**

```text
系统已形成业务事实
-> 自动投影合同、成本、资金和风险
-> AI 指出不一致和缺失来源
-> 财务处理差异
-> 老板查看同一事实和经营结论
```

替代 Excel 的关键不是导出更快，而是**老板和财务不再需要一个外部计算器才能确认经营结果**。

## 6. 装得清的老板首屏应该表达什么

老板首屏第一件事不是认识系统功能，而是判断经营：

| 区域 | 老板问题 | 展示原则 |
| --- | --- | --- |
| 今日判断 | 今天最值得关注什么 | 一到三条结论，不堆装饰指标 |
| 业务机会 | 哪一单值得推进或可能流失 | 对象、卡点、责任、下一步 |
| 交付风险 | 哪一单正在失控 | 原因、影响、责任、恢复路径 |
| 资金与利润 | 钱在哪里、利润能不能确认 | 现金、应收应付、成本完整性、利润状态 |
| 待决策 | 哪些事情等老板拍板 | 明确对象、影响和选择 |
| 数据可信度 | 哪些数据已确认、哪些失败 | 数据时间、来源、部分失败和“暂不可确认” |

首页的职责是“发现和判断”，对象工作面的职责是“看清和执行”，专业页面继续承担完整能力。

## 7. 一单对象的投影结构

任何入口进入同一单，都应看到同一套结构：

```text
对象身份
-> 当前阶段与责任人
-> 最重要变化
-> 当前风险/阻断
-> 唯一主行动
-> 报价、合同、项目、材料、验收、钱等事实摘要
-> AI 解释与来源
-> 时间线与历史证据
```

不同角色可以裁剪内容和动作，但不能改变：

- 同一客户、房屋、报价、合同和项目的业务归属；
- 同一 Provider、状态、金额和成本口径；
- 同一责任人、下一步和审计事实；
- 金额缺失、无权限、加载失败和业务阻塞的真实含义。

## 8. 装得清如何帮助老板做到

### 8.1 从“人找数据”变为“系统把事实送到人面前”

- 现有业务动作持续形成事实；
- 首页按老板关注度投影事实；
- AI 解释变化、异常和影响；
- 老板不需要记住每个功能放在哪个菜单。

### 8.2 从“群里安排”变为“对象内闭环”

- 责任、状态、动作和下一步绑定业务对象；
- 动作完成后服务端回读；
- 下一角色收到同一事实；
- 微信群继续用于沟通，但不再承担业务真相。

### 8.3 从“月底算账”变为“经营过程持续可算”

- 合同、采购、到场、收付款、成本和结算按业务事件形成；
- 财务只处理确认、异常和调整；
- 利润不完整时明确为空；
- Excel 用于导入、导出和过渡承接，不再作为正式经营计算中心。

### 8.4 从“依赖老员工”变为“经营记忆可复用”

- 对象时间线保存事实与处置过程；
- AI 可基于有权限的业务事实解释、总结和提示；
- 企业案例、标准方案和历史经验逐步成为可复用资产；
- 交接不再只靠微信群和口头记忆。

## 9. 投影表达原则

### 9.1 先说老板结果，再说系统能力

不先说“有客户、报价、项目、财务模块”，先说：

- 哪一单正在流失；
- 哪一单正在失控；
- 哪一单不赚钱；
- 今天应该先处理什么。

用户进入对象后，再自然看到支撑这些结果的完整业务能力。

### 9.2 用装企语言，不用系统语言

| 系统语言 | 老板语言 |
| --- | --- |
| 应收计划 | 这笔钱什么时候收、还差多少 |
| 成本完整性 | 这单利润现在能不能算 |
| 任务逾期 | 哪个节点拖住了交付 |
| 报价快照 | 客户确认的是哪一版 |
| 项目参与关系 | 这单现在谁负责 |
| 数据权限失败 | 暂不可确认，请联系负责人或重试 |

### 9.3 AI 只解释有来源的事实

每条 AI 结论必须能回答：

```text
结论是什么
依据来自哪里
影响哪个业务对象
谁负责
下一步是什么
数据截至什么时候
```

无法回答时不以推测补齐。

### 9.4 保留完整能力，不把投影做成缩水版

- 老板投影是默认视角，不是功能上限；
- 完整专业页面、菜单和深链继续保留；
- 投影层负责选中信息、组织叙事和突出行动；
- 用户需要深入时可以进入原有业务工作面。

## 10. 当前能力与目标投影

| 投影能力 | 当前基础 | 结论 |
| --- | --- | --- |
| 客户与一单经营视图 | 客户、房屋、跟进、量房、报价、合同已有实现 | 可投影；跨对象连续事实需真实验收 |
| 项目风险处置 | 项目、任务、验收、风险队列已有基础 | 可投影；风险链和上下文恢复待验收 |
| 现金与项目利润 | 应收、收款、应付、付款、台账、成本规则已有基础 | 可投影；成本完整性和台账守恒必须先通过 |
| AI 经营简报 | 已有产品规格，部分能力未生产验收 | 投影目标；不得写成已全面上线 |
| AI 嵌入业务副驾 | 已有总体设计和分域规划 | 投影目标；按现有 AI 门禁逐项实现 |
| 企业记忆与知识复用 | 企业能力资产有规划 | 长期投影；不得把规划当现状 |

## 11. 投影验收

### 11.1 老板认同

- 老板能用自己的经营语言复述产品价值，而不是复述菜单；
- 老板认为“这说的就是我公司的经营问题”；
- 品牌表达与真实业务能力一致，不靠夸大 AI 获得认同。

### 11.2 场景共鸣

- 至少两个真实老板能在各自场景中指出“这就是我每天遇到的问题”；
- 每个场景都能落到具体业务对象和现有能力；
- 场景不是静态插画或宣传文案，而是可以进入和操作的页面路径。

### 11.3 结果可信

- 老板能从结论下钻到事实和来源；
- AI 失败时不影响手工查看和原有业务；
- 动作完成后有服务端回读和新状态；
- App/Web 同账号同对象显示同一业务事实；
- 成本不完整不显示伪利润，数据失败不显示伪零。

### 11.4 Excel 与微信群边界

- Excel 可以继续用于导入、导出、复杂个性分析和历史承接；
- 微信群可以继续用于沟通；
- 正式客户、项目、收付款、成本和责任状态以装得清业务事实为准；
- 验收场景中，老板不再需要同时在群和表中拼接同一业务结论；
- 财务月度关账在约定范围内不需要 Excel 二次重算。

## 12. 首批需要落地的投影页

建议先形成一个可评审的三页垂直投影，而不是全面换壳：

1. **老板经营首屏**  
   今天发生了什么、最需要处理什么、公司钱和项目是否健康。

2. **一单经营工作面**  
   从客户、报价、合同、项目、材料、验收和财务事实中，形成同一单的连续经营视图。

3. **财务经营复盘/关账面**  
   老板和财务使用同一事实完成项目利润、资金、应收应付和差异核对。

这三页复用现有能力，不建立第二套业务后端，也不以角色菜单重组代替产品价值验证。

## 13. 非目标

- 不重构客户、报价、合同、项目、材料、验收和财务业务功能。
- 不删减现有角色页面和专业入口。
- 不新增 AI 专用业务事实或第二套状态机。
- 不让 AI 自动确认报价、合同、验收、收付款、结算和利润。
- 不把 Excel 和微信群描述成落后工具；它们继续承担输入、导出和沟通角色。
- 不把本文中的目标投影写成当前已上线能力。

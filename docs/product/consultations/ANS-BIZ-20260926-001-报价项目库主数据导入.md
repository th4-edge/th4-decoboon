## 3. 标准流程与状态变化

### 3.1 用户操作流程

1. 用户在报价项目库维护页点击“下载模板”。
2. 系统打开 V1.0 模板；用户通过微信将模板发送到电脑微信或文件传输助手。
3. 用户在电脑上复制、整理数据。不得修改第 1 行表头、不得合并单元格、不得把多张表拼成同一工作表。
4. 用户完成整理后，将文件发回微信聊天。
5. 用户在小程序点击“批量导入”，从微信聊天选择文件。
6. 系统上传并解析文件，生成预览，不写入报价项目库。
7. 用户查看总行数、可导入、重复、错误、成本待维护数量，以及前几行样例和错误行原因。
8. 用户确认后执行导入。若存在错误行，默认整批不导入；只有用户二次明确确认，才允许“仅导入合格行”。
9. 系统返回导入结果，记录批次和异常清单；导入成功的项目可立即在设计分项、套餐配置和报价选择中使用。

### 3.2 数据状态与写入边界

| 阶段 | 允许动作 | 禁止动作 |
| --- | --- | --- |
| 模板下载 | 生成并打开 V1.0 模板 | 在该阶段创建报价项目 |
| 文件解析 | 读取文件、识别表头、逐行校验 | 写入 `CatalogItem` |
| 预览确认 | 展示新增、重复、错误、成本待维护 | 自动覆盖已有项目或价格 |
| 导入执行 | 创建有效 `CatalogItem` 及类型明细 | 创建客户、房屋、报价、合同、项目或财务流水 |
| 导入完成 | 查看结果、错误清单、批次和撤销入口 | 将导入结果计入报价接受率、转化率、毛利等经营指标 |

### 3.3 重复与幂等

- 有项目编码时：按“企业 + 项目类型 + 项目编码”判断重复。
- 无项目编码时：按“企业 + 项目类型 + 项目名称 + 品牌 + 规格/型号 + 计量单位”判断重复。
- 系列不同的记录先作为“疑似重复”进入预览，不自动覆盖、不自动合并。
- 同一文件重复上传：按文件指纹识别，第二次默认进入“已导入”结果，不新增重复记录。
- P0 默认跳过重复项目；批量覆盖已有价格和工艺不在本次范围。

## 4. 金额/成本/指标口径

| 项目 | 口径 |
| --- | --- |
| 材料+人工 | 材料单价和人工单价均需明确填写；缺失项填 0，不能留空猜测 |
| 仅材料 | 材料单价必填；人工单价应为空或 0，不得填写大于 0 的人工价 |
| 仅人工 | 人工单价必填；材料单价应为空或 0，不得填写大于 0 的材料价 |
| 固定总价 | 只在“固定总价”计价方式下填写固定总价；材料单价和人工单价保持空 |
| 赠送/0 元 | 只有业务确认赠送时才填写 0；不确定的售价保持空白并作为错误行 |
| 标准成本 | 可以留空；空白表示“成本待维护”，0 表示明确零成本，两者不能混用 |
| 利润 | 任一应计成本缺失时必须 `costComplete=false`，利润和毛利率返回空值，禁止按 0 成本计算 |
| 经营指标 | 本次导入只形成企业主数据，不直接参与报价接受率、转化率、毛利等指标统计 |

## 6. 例外和反向用例

1. 用户修改模板表头、删除必填列或调整工作表名称时，系统必须阻断解析，不能靠列顺序猜测。
2. 同一文件重复上传不产生重复项目；同一项目编码跨企业不得互相覆盖。
3. 成本空白不得写为 0；导入前和导入后的成本完整性状态必须一致。
4. 固定总价项目中填写材料单价或人工单价时，必须提示口径冲突。
5. 售价空白不能当作 0；只有用户明确填写 0 才表示赠送或零元项目。
6. 存在错误行时不得静默跳过；如果用户选择“仅导入合格行”，必须有二次确认并显示被跳过行数。
7. 上传、解析或导入失败不得留下半套项目；重试必须幂等。
8. 导入后的项目必须立即可被设计、套餐和报价选择读取，不能形成孤立主数据。
9. 导入文件不得触发历史项目、合同、报价或财务数据写入。
10. 普通员工、设计师、项目经理不得通过文件导入获得标准成本查看权限。

- 可以说：支持按 V1.0 标准模板整理报价项目库，在电脑整理后通过小程序上传、预览确认并导入。

## 1. 总裁决

设计师 Web 报价工作空间锁定为：

> 以设计方案区域为骨架、以报价分项为行、以工程量公式为计算单元、以前端实时预览和服务端权威重算为计算机制、以结构化 `.xlsx` 导入导出为兼容通道的桌面报价工作空间。

它不是 Excel 的完整复刻：

- 兼容区域、分项、公式、表格和批量操作习惯；
- 不兼容宏、外部链接、任意函数和完整格式保真；
- 正式报价状态、版本、金额、成本和权限仍由装得清业务事实控制。

## 2. Q1：报价区域来源

**答复：P0 只使用当前设计方案中的正式 `Space` 作为报价区域。**

规则：

- 报价行必须显式绑定当前房屋设计方案下的区域 `spaceId`。
- 区域名称、排序和归属优先读取设计区域，不在报价页另建一套区域主数据。
- 未绑定区域或历史缺失区域的分项进入“综合项目/未归属区域”，必须显式展示并纳入汇总，不能静默丢弃。
- 多房屋客户必须显式选择 `propertyId`，不同房屋的区域不能混用。
- 区域小计只统计该区域内有效报价行；总价统计所有有效区域和综合项目。
- 跨区域复制分项时必须重新绑定目标区域。
- 报价内自定义区域不在 P0；如以后确需，必须新增业务裁决并明确是否回写设计区域。

例外：

- 历史报价区域缺失时保留“未归属区域”只读展示，允许在设计方案补齐区域后做数据治理。
- 套餐模板没有区域时允许进入综合项目，但必须由设计师确认归属。

## 3. Q2：公式白名单和精度

**答复：P0 只支持确定性、可校验、可服务端重算的公式子集。**

### P0 支持

- 数字、正负号、小数点；
- `+ - * /`；
- 中文/英文括号；
- 百分比 `%`；
- 同工作表单元格引用：`B12`；
- 同工作表绝对引用：`$B$12`；
- 同工作表区域范围：`B2:B8`；
- 函数：`SUM`、`ROUND`、`MIN`、`MAX`；
- 公式长度不超过 512 个字符；
- 服务端限制引用范围、计算深度和单元格数量，防止循环和性能攻击。

### P0 不支持

- 宏、VBA、脚本和外部链接；
- 跨工作簿、跨报价、跨房屋引用；
- `IF`、`VLOOKUP`、`XLOOKUP`、`INDEX`、`MATCH` 等条件/查找函数；
- 数组公式、动态数组、透视表和外部数据源；
- 合并单元格参与公式；
- 文本拼接参与金额计算；
- 任意 Excel 函数和无限递归。

如业务真实高频需求证明 `IF` 或查找函数不可缺，另行建立 P1 公式决策。

### 精度

| 类型 | 计算精度 | 展示/落库 |
| --- | --- | --- |
| 工程量 | 最多 3 位小数，计算过程不提前四舍五入 | 最多 3 位小数 |
| 销售单价/成本单价 | 2 位小数 | 2 位小数 |
| 金额、行金额、区域小计、总价 | 使用精确十进制计算 | 2 位小数 `HALF_UP` |
| 折扣/税率/比例 | 最多 4 位小数 | 按正式字段精度 |
| 公式中间值 | 保留完整十进制精度 | 不单独落库，快照保留结果 |

规则：

- `ROUND` 只在公式明确要求时执行。
- 区域小计和总价先使用各行未展示舍入的精确金额汇总，再统一按金额精度落库/展示。
- 同一行重复计算不得产生累计舍入误差。
- 公式表达式和最终计算结果都要形成快照。

### 字段兼容

- App 已使用的现有 `formula` 字段不得改变语义或数据库兼容性。
- Web 公式能力优先使用新增的兼容字段/快照承载，具体字段名由后端设计确认。
- 新增字段必须可空、可选，旧 App 不读取时不报错。
- 已提交和已接受报价保存公式和结果快照，不因主数据变化回溯改写。

## 4. Q3：Excel 导入导出兼容范围

**答复：P0 兼容结构化报价工作簿，不兼容宏和完整格式保真。**

### 支持格式

- `.xlsx`；
- 一个工作簿对应一个客户、房屋和报价草稿；
- 一个主报价明细工作表；
- 固定模板表头、区域分组和报价列；
- 基本数字、百分比和文本；
- 白名单公式；
- 行级错误和预览结果；
- 内部工作版可保留公式和计算值；
- 客户版可只导出正式展示字段，不导出成本、内部公式和内部备注。

### 导入模式

- 新建报价草稿；
- 覆盖当前报价草稿；
- 合并到当前报价草稿。

禁止：

- 导入到 `Submitted`、`Accepted`、`Converted` 报价；
- 静默跳过错误行；
- 自动执行宏或外部链接；
- 将不支持公式自动转成数值；
- 在数据行使用合并单元格。

### 错误处理

- 不支持公式：该行错误，明确提示，不自动换算；
- 区域无法匹配：该行错误并要求重新选择；
- 未知/重复项目：预览中标记冲突，逐行决定；
- 金额不一致：以服务端重算结果为准并提示差异；
- 部分失败：进入错误预览，不直接产生半套报价；
- 用户确认后只导入通过校验的行；失败行保留在导入结果中。

### 导出

- 导出当前服务端版本，不导出前端未保存预览。
- 公式列保留公式表达式，数值列保留服务端结果。
- 客户版不导出标准成本、采购价和内部利润。
- 内部工作版按角色权限导出成本字段。
- 导出的内部工作版必须可重新导入并得到一致的区域、公式和金额。
- 不承诺保留宏、条件格式、图表、透视表、复杂颜色和打印排版保真。

## 5. Q4：设计师价格编辑权限

**答复：设计师可编辑销售侧报价，不得读取或修改标准成本。**

### 可编辑

- 报价草稿中的工程量；
- 工程量公式；
- 销售侧材料单价、人工单价；
- 行级折扣/优惠；
- 固定总价行（仅当该行的正式计价模式为 `FixedTotal`）；
- 品牌、规格、备注和工艺说明（按项目库/权限范围）；
- 选择或更换报价项目来源时，必须保留原价格快照和变更痕迹。

### 不可编辑

- 标准采购成本、采购执行价、供应商历史价；
- 项目综合成本、毛利率和利润；
- 服务端计算出的正式行金额、区域小计和总价；
- 已提交、已接受、已转合同报价；
- App 已依赖的报价接口字段语义和状态机。

### 全局折扣和敏感价格

- P0 设计师可以维护行级优惠。
- 全局报价折扣、税率和最终签约价属于高影响字段，只有具备对应权限的 Boss、店长或财务可修改。
- 如果后续允许设计师使用全局折扣，必须增加角色能力、折扣区间、审批和审计规则。
- 负金额、零单价、超出授权折扣范围和历史价回写必须被服务端阻断。

## 6. Q5：前端预览与服务端重算的权威关系

**答复：前端负责即时预览，服务端负责正式计算、校验和快照。**

```text
前端编辑
-> 前端实时预览
-> 保存草稿/批量保存/导入/提交
-> 服务端权威重算
-> 返回正式金额和错误
-> 前端覆盖预览并刷新区域小计、总价、版本差异
```

规则：

- 前端不能直接提交公式计算出的金额、区域小计或总价作为正式事实。
- 正式金额、成本完整性、折扣、税费和总额以服务端结果为准。
- 前端与服务端不一致时，以服务端结果覆盖并提示“计算已按系统规则更新”。
- 保存草稿即重算；批量粘贴和 Excel 导入也必须重算。
- 提交客户前必须进行一次全量服务端重算和阻断校验。
- 提交后冻结公式、计算结果、区域、分项和金额快照。
- 修改已提交报价必须形成新版本；合同后的修改必须走合同变更。
- App 单行保存继续使用现有兼容路径；Web 新增批量保存和公式能力不能改变 App 的行为。

## 7. 冻结结果

可冻结以下产品规则：

- P0 区域只来自设计方案 `Space`；
- P0 公式采用有限白名单和统一精度；
- P0 导入导出只承诺结构化 `.xlsx` 工作簿；
- 设计师只维护销售侧报价，不可见成本；
- 前端实时预览、服务端权威重算和快照冻结；
- App 现有报价接口、状态机、金额和页面行为保持兼容。

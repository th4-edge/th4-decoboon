## 1. 业务问题

- 当前场景：合同签约并生效后系统自动立项，按合同施工计划模板快照生成施工阶段，由合同施工行和设计师排期生成施工任务；项目经理按「施工进行 / 隐蔽工程 / 施工完成」影像节点推进，阶段任务完成后提交业主验收，业主驳回则整改复验；财务按付款计划快照生成应收并核销收款。本次在本地 dev 环境用真实 Provider + 麦鸿演示项目 37 实际跑通到「提交阶段验收 / 收款 / 结算」，过程中暴露 7 项业务口径未冻结，代码已按各自理解实现。
- 用户/角色：企业负责人（Boss）、设计师（Designer）、项目经理（Pm）、财务（Finance）、业主。
- 现有处理方式：施工计划模板由平台基线（`RESIDENTIAL_STANDARD_8`/`RESIDENTIAL_SIMPLE_5`）或企业自定义模板提供；阶段验收模式（`acceptanceMode`）只在合同快照上存在，项目阶段不回传；工艺库为报价项目库的施工类目（`CatalogItem.craft` 文本），未绑定阶段与区域；阶段权重按施工任务成本占比计算；项目经理可用 `project/project/update` 重排阶段计划，重排不回写合同快照。
- 希望解决的问题：把「阶段是否需要业主验收」「工艺库与阶段/区域绑定」「阶段权重与工期/进度口径」「重排与快照一致性」「阶段计划日期维护入口」「工艺主数据形态」「取消任务是否参与验收门禁」这 7 项一次冻结，避免研发自行选择更省事的版本继续扩大偏差。

## 2. 涉及条件

- 主对象：`ContractConstructionPlan` / `ContractConstructionStage`、`ProjectStage`、`ProjectTask`、`CatalogItem`（施工类目）、`Acceptance` / `AcceptanceRound`。
- 关联对象：`ProjectContract`、`Project`、`Property`、施工区域（`SpaceType`）、`MaterialPlan`、`Receivable`、`TaskNode`。
- 当前/目标状态：阶段 `Todo/Doing/Accepting/Done`；任务 `Todo/Doing/Accepting/Done/Cancelled`；验收 `Pending/Confirmed/Rejected`。
- 组织与数据范围：Company/Store/Team/Self + 项目参与关系（`project.designer/manager/support/quote.createdBy`）。
- 权限（现状）：施工计划排期=`项目设计师 / 项目经理 / Boss`；阶段开工与影像节点=`项目经理 / Boss`；提交阶段验收=`Boss / 项目经理 / 设计师`；验收确认或驳回=`业主本人`；财务读写=`Boss / Finance`（店长只读）。
- 金额/成本/指标：阶段权重 = 阶段内施工任务成本 ÷ 全部施工任务成本；项目进度 = Σ(阶段权重×阶段进度) ÷ Σ权重；成本不完整时利润与毛利率返回 `null`。

## 4. 候选方案

1. **阶段验收模式**：A. 在 `ProjectStage` 落 `acceptanceMode`，按模板区分「无需验收 / 施工完成即通过 / 必须业主验收」；B. 一律要求业主验收，忽略模板验收模式。
2. **工艺库绑定**：A. 施工类目增加「默认阶段 + 区域白名单」，排期只能落位到允许范围；B. 维持现状（人工选择阶段与区域，关键词兜底）。
3. **阶段权重与工期**：A. 无施工行的阶段按模板工期占比参与权重（工期与进度同源）；B. 无施工行阶段权重为 0（现状），只按任务成本占比；C. 允许企业在阶段模板上直接配置权重。
4. **重排与快照一致性**：A. 项目阶段重排时同步回写合同施工计划快照（快照=最新确认版本）；B. 合同生效后禁止重排阶段计划，只能按变更流程处理；C. 快照与项目阶段各自独立，页面分别展示。
5. **阶段计划日期维护**：A. 允许项目经理/设计师在阶段上单独调整计划起止（受总工期约束）；B. 只能通过项目级重排。
6. **工艺主数据**：A. 保持 `CatalogItem.craft` 文本字段；B. 建立独立工艺主数据对象并与施工类目关联。
7. **取消任务与验收门禁**：A. `Cancelled` 任务不计入验收门禁（视为不参与）；B. 必须全部 `Done`（含取消任务）才能提交验收，取消任务需先恢复或删除。

## 5. 需要业务智能体回答

1. **G-01**：阶段是否需要业主验收由谁决定？`acceptanceMode`（无需验收 / 施工完成即通过 / 必须业主验收）是否作为项目阶段的必备字段与页面展示口径？「无需验收」阶段如何推进到 `Done`？
2. **G-02**：施工工艺（施工类目）是否必须绑定默认阶段与区域白名单？排期落位到未绑定阶段/区域时是阻断、警告还是允许？
3. **G-03**：阶段权重与工期的唯一口径是什么？无施工行的阶段（例如仅有交底/竣工保洁）是否参与项目进度加权？项目进度是否允许与计划工期脱钩？
4. **G-04**：项目阶段重排（调整开完工日期导致阶段计划变化）是否必须回写合同施工计划快照？合同生效后是否允许重排？快照与项目阶段哪一个作为对外展示与验收依据？
5. **G-05**：阶段计划日期是否可以单独维护？由谁维护（设计师/项目经理/Boss）？是否需要留痕与历史版本？
6. **G-06**：施工「工艺」最终以文本字段还是独立主数据对象承载？若为独立对象，需要哪些字段（编码、名称、单位、标准工期、关联阶段/区域、验收节点类型）？
7. **G-07（本次实测新增）**：阶段验收门禁是否排除 `Cancelled` 任务？`Cancelled → Done` 是否需要阻断？「取消」在施工计划中的语义是「不施工、不影响验收」还是「必须先恢复再验收」？

## 6. 影响与截止时间

- 影响的模块：施工计划模板与快照、项目阶段与任务排期、影像节点、阶段验收与整改、项目进度与工期、财务应收触发（阶段验收触发节点）、App 施工计划/阶段详情/验收页面。
- 不确认会阻塞什么：`ProjectStage.acceptanceMode` 落库与迁移、工艺库结构化、阶段权重口径、重排与快照一致性实现、阶段日期维护入口、施工任务与阶段验收门禁的统一验收用例；继续按现状开发会产生新的前后端口径分叉。
- 最晚决策时间：下一轮施工计划/阶段验收相关研发任务启动前。

## 1. 业务问题

- 当前场景：小程序把「业主邀请 / 员工邀请 / 注册企业」三类身份的进入方式混在一起——业主与员工共用 `pages/invite/accept.vue`（业主身份靠"是否存在 token 参数"推断），无身份用户被统一推到 `pages/company/join.vue` 手填"邀请编号或邀请链接"，且**同页下方还有"创建企业"**。
- 用户/角色：业主、拟加入企业的员工、拟注册企业的负责人（Boss）。
- 现有处理方式：业主必须有 `CustomerInvite`（token 或 inviteId）才能进入；后端 `CustomerInviteContext.requireInfo()` 已支持手机号校验但**仍必须先找到邀请记录**；企业注册无注销入口。
- 希望解决的问题：把身份判定从"页面参数"改为"**服务端业务事实**"——业主按**客户档案手机号**判定，员工按企业邀请判定，注册企业独立入口；并允许"暂不属于任何企业"的中间态存在、支持企业注销。上述改动涉及业务对象（`CustomerInvite` 去留）、身份判定依据、跨企业可见范围与注销状态机，须先由业务侧裁决。

## 2. 涉及条件

- 主对象：`Credentials`（openid + 微信授权手机号）、`CustomerInvite`、`CustomerAccess`、`Customer.telNo`、`Company`。
- 关联对象：`Project`、`Property`、`Employee`、`Invite`（员工邀请）、订阅/席位。
- 当前状态：邀请 `pending/accepted/expired/cancelled/rejected`；`CustomerAccess.status=Active`；`Company` 无终态。
- 组织与数据范围：Company/Store/Team/Self + 业主仅限本人项目（`DEC-009`）。
- 权限（现状）：业主进入 = 邀请 + 手机号一致；员工进入 = 邀请 + 手机号一致；企业注册 = 任意已登录用户；注销 = 无入口。
- 风险（研发识别，需业务确认）：**同一手机号在多家企业都有客户档案时，仅凭手机号"命中即进入"会造成跨企业串号（P0）**；建议必须让用户显式选择项目并逐项目授权。

## 3. 阻塞问题（5 项）

1. **业主进入是否仍必须邀请？** 是否接受"微信授权手机号与客户档案 `Customer.telNo` 一致即可进入该项目"，无需邀请记录？若不接受，邀请在什么条件下仍为必需？（涉及 `CustomerInvite` 是否降级为可选）
2. **同一手机号命中多家企业/多个项目**时：是否必须由业主**显式选择**并**逐项目授权**？是否允许"一次授权拿到该手机号名下全部项目"？（研发建议：必须显式选择、逐项目授权，禁止静默取第一条）
3. **业主换手机号**：原 `CustomerAccess` 是否自动失效？是否允许业主自助换绑？是否需要原手机号/企业侧确认？谁负责处理客户档案手机号变更（设计师/店长）？
4. **手机号探测防枚举**：允许的失败次数与频控窗口是多少？失败提示是否允许"该号码不属于任何装修项目"（是否算泄露企业存在性）？
5. **企业注销**：立即停用还是平台审核？存在在跑项目/未结款项/未到期订阅时的处理？数据保留期？注销后企业名称/主体能否重新注册？

## 4. 研发侧已冻结的边界（不需裁决）

- 三类身份**三个独立入口**，不做参数猜测（业主页不出现"邀请码/token"字样）。
- 注册企业页**不出现邀请码**概念。
- 允许"暂不属于任何企业"的中间态存在，下次登录重新判定，不强制注册。
- 业主身份判定**只依据微信授权手机号**，不接受前端直接传手机号；员工身份优先于业主身份。
- 业主进入**不产生任何业务事实**（不创建客户/项目）。

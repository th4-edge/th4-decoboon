## 1. 业务问题

目标客户群体主要通过 Excel 完成方案报价，设计师习惯按区域、分项和单元格公式进行工程量计算与价格维护。现有 Web 只有报价详情、单行编辑和简单的数量公式预览，不能满足“区域报价、实时计算、公式引用、导入导出、兼容 Excel 习惯”的要求。

用户已明确：

- 按区域报价；
- 已报价分项；
- 实时计算价格；
- 支持类似 Excel 单元格公式的工程量计算；
- 支持导入和导出；
- 兼容原有 Excel 操作习惯；
- Web 要用更好的交互 UI 呈现，而不是只做 Excel 的网页复制。

## 2. 涉及条件

- 主对象：Quote、QuoteGroup、QuoteLine、QuoteComponent、Space、DesignItem、CatalogItem。
- 候选工作区：按区域组织的报价工作簿投影。
- 公式：工程量、单价、行金额、区域小计、总价、优惠/扣减。
- 权限：设计师销售侧编辑；成本、采购执行价和利润按正式角色权限。
- 状态：Draft 可编辑；Submitted/Accepted/Converted 冻结；驳回后形成新版本。
- 跨端：App 现有单行报价能力和接口必须保持正常运行。
- 导入导出：`.xlsx`、模板、错误行、公式、区域和版本。
- 审计：公式、导入、导出、批量编辑、错误修正和版本快照可追溯。

## 3. 需要业务智能体回答

1. 报价区域是否只允许来自设计方案 Space？是否允许报价内自定义区域；未归属分项如何展示和汇总？
2. P0 公式白名单是什么？是否允许单元格引用、区域范围、SUM/ROUND/MIN/MAX、跨行汇总？哪些函数明确不支持？
3. Excel 导入导出的最低兼容范围是什么？公式、合并单元格、格式、打印、模板和文件大小如何界定？
4. 设计师在报价中可编辑哪些字段？数量、工程量公式、材料价、人工价、优惠、折扣、备注和固定总价分别有什么权限？
5. 实时计算、服务端重算、提交冻结和版本快照分别以哪个结果为准？导入后公式和金额如何形成历史快照？

## 4. 临时限制

- 不改变 App 现有报价接口、状态机、金额和权限。
- 不让前端直接覆盖服务端金额。
- 不支持宏、外部链接和任意 Excel 函数。
- 不把成本字段暴露给设计师。
- 业务裁决前不新增正式报价工作簿对象或通用公式引擎。

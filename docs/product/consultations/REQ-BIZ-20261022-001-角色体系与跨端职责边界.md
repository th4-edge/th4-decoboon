## 1. 业务问题

- 当前场景：材料员/履约人员归财务、App/Web 强制能力一致完整、普通员工不支持通用多岗均已由用户确认。仍需确认高风险动作主体和外部身份边界。
- 用户/角色：企业负责人、店长、团队负责人、业务员、设计师、项目经理、财务、业主；平台运营、工人、供应商作为边界主体。
- 现有处理方式：已确认七类 `EmployeeRole`；BOSS 内部能力超集；店长业务能力对齐、范围本店；财务门店/总部范围；财务客户经营对齐 BOSS/店长；材料员/履约人员与财务同一角色；普通员工不支持通用多岗。部分高风险动作主体和外部身份仍待确认。
- 希望解决的问题：在已确认材料和跨端边界的基础上，冻结“身份主体—岗位角色—数据范围—业务责任—动作能力—端职责”的关系，作为后续业务矩阵、功能矩阵、概念规则和 App/Web 对比的唯一产品底座。

## 2. 涉及条件

- 主对象：Employee、Company、Store、Team、CustomerAccess、ProjectMember。
- 关联对象：Customer、Property、Design、Quote、Contract、Project、MaterialPlan、Acceptance、Receivable、Payable、PayrollSheet、Voucher。

- 组织与数据范围：Company / Store / Team / Self / ProjectParticipation / CustomerAccess；总部财务由默认总店归属派生。
- 权限：查看、编辑、发起、确认、审批、收付、导出；页面能力键与服务端 Provider 必须同源。
- 金额/成本/指标：合同金额、应收应付、成本完整性、利润为空、工资与提成、财务高危动作、业主可见金额范围。

## 4. 候选方案

1. 材料员/履约人员已归入 `Finance`，不新增角色。
2. 普通员工不支持通用多岗，保留单主岗 + BOSS 超集 + 项目责任关系。
3. App/Web 每类能力都必须有完整业务闭环，交互可不同但不得一端缺失。
4. 业主、工人、供应商、平台运营与内部员工角色彻底分层；业主按项目授权，工人/供应商是否开放自助另行裁决。

## 5. 需要业务智能体回答（用户已确认三项后）

### 已由用户确认，不需要再回答

- 材料员/履约人员统一归到财务角色；不新增第八角色。依据 `DEC-074` 与用户 2026-10-22 再次确认。
- App/Web 每类能力的强制边界必须一致且完整；两端交互形式可不同，但能力、权限、状态、金额和异常恢复不得缺失。
- 普通员工不支持通用多岗；一个员工只有一个主岗位，BOSS 超集和项目责任关系不构成多岗位。

### 仍需回答

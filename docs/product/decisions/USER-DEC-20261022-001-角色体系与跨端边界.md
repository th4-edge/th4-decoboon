## 一、决策内容

### D1. 材料员/履约人员归财务

- 材料员、履约人员统一归入 `Finance`；
- 不新增材料员、履约专员或其他第八类员工角色；
- 历史 `ProjectSupport` 不再作为独立岗位，保留兼容映射到 `Finance`；
- 依据：`DEC-074` 与用户 2026-10-22 再次确认。

### D2. App/Web 强制能力一致且完整

- 每类强制能力在 App/Web 的边界必须一致、完整；
- 交互形式可以不同，但能力、权限、状态、金额、完成条件、错误恢复和审计必须同源；
- 不再接受“某能力只在 App”或“某能力只在 Web”作为默认豁免；
- 单端设备能力仍需在另一端提供等价业务闭环。

### D3. 普通员工不支持通用多岗

- 普通员工只有一个主岗位；
- BOSS 保留内部岗位能力超集；
- 项目设计师、项目经理、履约负责人是项目责任关系，不是员工第二岗位；
- 不新增员工多岗关系模型；
- 项目责任关系不得扩大员工主岗位的全局权限。

### D4. TeamLeader 角色冻结

- TeamLeader 作为历史兼容角色保留，不在后续产品应用中继续建设；
- 后续角色矩阵、业务矩阵、功能矩阵、App/Web 应用规划不把 TeamLeader 作为目标应用角色；
- 不再新增 TeamLeader 专属页面、入口、能力或业务流程；
- 现有 TeamLeader 账号、数据、权限和路由如何收口，进入独立问题档案和专项会话，不在此决策中推定；
- `GAP-026` 不再作为新产品应用的活跃前置裁决，转为历史兼容问题。

### D5. 供应商价格以材料下单路线为准

- 供应商价格的业务主链以材料下单路线为准；
- `PartnerPrice` 不再作为供应商价格概念和价格真源；
- 采购下单时的供应商、材料、数量、采购价和历史订单事实是价格追溯依据；
- `PartnerPrice` 的存量数据、字段兼容、标准成本同步和历史迁移由 `PI-20261022-004` 专项会话统一收口；
- 本决策不自行改写标准成本、结算价、实际成本或利润口径。

## 三、影响与处理

| 影响项 | 处理 |
| --- | --- |
| 角色矩阵 | TeamLeader 标记为冻结兼容，不纳入目标能力规划 |
| App/Web 跨端矩阵 | TeamLeader 不计入“必须双端完整”的目标范围 |
| `GAP-026` | 从活跃产品裁决转为历史兼容问题 |
| 存量 TeamLeader 账号 | 建立 `PI-20261022-002` 专项问题处理 |
| 后端枚举 | 当前不删除，避免破坏历史数据和兼容性 |
| 新需求 | 不为 TeamLeader 新增功能；如涉及存量安全，转专项会话 |

## 四、不可误解

- “冻结”不等于当前立即删除枚举或数据；
- “不考虑应用”不等于存量账号自动失效；
- 存量账号如何迁移、停用、转岗、只读或保留，需要专项业务裁决和研发验收；
- 在该裁决完成前，不得新增 TeamLeader 应用能力，也不得擅自删除历史数据。

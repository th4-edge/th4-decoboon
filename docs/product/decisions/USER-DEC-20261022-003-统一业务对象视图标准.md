## 一、决策内容

1. 报价不是孤立页面，而是所有业务对象视图规则中的一个实例；
2. 设计方案、合同、项目、计划、材料、变更、验收、财务单据等也应遵循同一规则；
3. 每个业务对象必须有唯一身份、版本、状态、事实和明细来源；
4. 不同端、不同宿主场景只允许做场景适配，不允许各自重做对象模型或重新计算；
5. 带区域/类型明细的对象支持服务端分组投影；前端只消费投影；
6. 业主端支持按类型视图查看；
7. 类型视图合并跨区域相同项目时，必须由服务端完成并保留来源行、来源区域和源数量；
8. 合同详情中的报价不做第二套嵌入明细，跳转到统一报价视图；
9. 项目端查看区域型报价明细时默认按区域；
10. PDF 打印允许用户选择按区域或按类型分组。

## 二、通用视图契约

```text
objectId + version
→ 统一对象事实
→ 统一直属明细
→ 服务端分组投影
→ 场景权限/动作/字段适配
→ App/Web/业主端/PDF 展示
```

## 三、对象族

| 对象族 | 统一对象 | 典型分组 |
| --- | --- | --- |
| 客户与房屋 | Customer / Property | 无分组或房屋列表 |
| 设计方案 | Design / DesignVersion | 区域 → 类型 → 分类 |
| 报价 | Quote | 区域 / 类型 |
| 合同 | Contract | 合同行按区域/类型；历史版本绑定 |
| 项目 | Project | 阶段/区域/类型 |
| 计划 | ProjectPlan | 阶段 → 任务 → 区域 |
| 材料 | MaterialPlan/MaterialSheet | 品类/供应商/项目/区域 |
| 变更 | ContractChange | 变更类型/区域/项目行 |
| 验收 | Acceptance/Rectification | 阶段/区域/问题类型 |
| 财务单据 | Receivable/Payable/Ledger/Voucher | 项目/类型/时间/往来方 |

## 四、强制规则

1. 同一对象跨场景必须绑定同一 `objectId + version`；
2. 宿主页只显示摘要和跳转，不复制完整明细；
3. 分组、合并和汇总必须由服务端生成；
4. 前端不得用本地循环改变正式金额、行数或分组；
5. 业主、员工、财务字段按角色服务端裁剪；
6. 成本和内部公式不进入业主投影；
7. 对象失败时显示“暂不可确认”，不得用空数组/0 伪装；
8. 合同、项目、验收等下游对象必须绑定上游版本快照；
9. PDF 使用所选分组和场景字段白名单；
10. 任何对象扩展必须先检查其统一视图契约是否仍成立。

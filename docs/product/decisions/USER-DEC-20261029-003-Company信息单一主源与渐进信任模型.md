# USER-DEC-20261029-003 · Company 信息单一主源与渐进信任模型

- 决策日期：2026-10-29
- 决策人：用户
- 状态：`APPROVED`
- 类型：企业信息架构、入驻、信任建立、占位策略
- 关联：`enterprise-brand-profile`、`PI-20261029-002`、`REQ-BIZ-20261029-001`

## 1. 用户确认

1. 先形成完整的 `Company` 信息模型。
2. 所有企业事实均从 `Company` 信息而来；其他页面、业主端、合同、单据、打印和导出只能是 Company 信息的投影或快照。
3. Company 信息必须有层次，不能做成一张平面表单。
4. 装企入驻是信任不断建立的过程：
   - 初期快速开通，保证业务可以先开展；
   - 后续通过 App/Web 的“我的 → 企业信息”持续维护和升级；
   - 信息越完整，可使用的对外展示、合同、财务和信任能力越完整。
5. 入驻初期缺失的企业信息允许使用系统占位，保证业务正常开展。
6. 占位符只用于展示和流程连续性，不能伪装成真实企业事实；法定主体、合同、凭证和对外承诺所需的关键信息未完成时必须提示、限制或阻断对应动作。

## 2. 强制约束

- `Company` 是企业信息的唯一根对象。
- `DocumentProfile` 不再作为独立企业主档；其角色应收敛为企业信息的单据投影或生成快照。
- `CustomerJourney.Vendor`、邀请卡片、业主展示、报价/合同/凭证 PDF、打印和导出均从 Company 信息或快照派生。
- 企业信息按公司级与门店级分层，不得把门店地址、项目施工地址、房屋地址混为企业地址。
- 占位符不得写入正式主档，不参与金额、成本、权限、验收或合同事实。
- 企业信息维护必须保留来源、更新时间、操作人、版本和展示范围。
- 历史合同、已发布单据和归档文件不得被当前 Company 主档更新回写。

## 3. 信任阶段

```text
快速开通
→ 基础可用
→ 对外服务准备
→ 合同/财务准备
→ 信任资料完善
→ 持续维护与版本化
```

每阶段只要求完成当前业务真正需要的信息，不用一次性长表单阻塞入驻。

## 4. 企业信息页面

统一入口：`我的 → 企业信息`。

页面不是单纯编辑表单，而是企业身份、资料完整度、缺项影响和下一步维护任务的入口。

- App：快速查看、补一项、从当前业务直接跳到缺项。
- Web：完整分组、批量维护、预览和影响范围说明。
- 保存后必须回读企业信息投影、业主展示、邀请和单据可用性。

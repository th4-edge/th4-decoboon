# USER-DEC-20261029-006 · 月度考勤应出勤天数可调整

## 决策

- 日期：2026-10-29
- 状态：已确认，待生产验证
- 来源：用户明确要求“考勤方案应出勤天数从薪酬方案带出，但应该支持修改”
- 适用端：Web 财务月度考勤、App 财务月度考勤；共用后端 Provider

## 业务口径

1. 薪酬方案仍是员工月度考勤和工资计算的前置条件。
2. 新建月度考勤时，应出勤天数默认读取该员工工资月份生效的薪酬方案。
3. 财务可在具体考勤单中修改应出勤天数，范围为 1～31 天。
4. 保存后，应出勤天数作为该月考勤快照参与工资计算，不回写薪酬方案。
5. 修改仍受现有角色、门店、企业数据范围和工资项已生成后禁止修改规则约束。

## 2026-10-30 同步

- 用户确认 App 端与 Web 端执行同一业务口径：应出勤从薪酬方案派生，允许在具体月度考勤中调整并保存为考勤快照。
- App 不再是“只读展示”；两端均不得使用 22 或其他本地默认值替代缺失的薪酬方案。

## 边界

- 不改变工资公式、考勤扣款系数、薪酬方案锁定规则和状态机。
- 不允许没有生效薪酬方案时伪造考勤事实。
- 不新增 DDL、字段或迁移。

# USER-DEC-20261029-007 · 财务角色渐进优化与菜单验收

- 决策日期：2026-10-29
- 决策人：用户
- 状态：`APPROVED`
- 类型：财务角色产品边界、迭代方式、菜单功能验收、后端改动边界
- 影响范围：`finance` domain、财务 Web 菜单、小程序财务 Tab/首页快捷入口、财务分包页面、后续研发计划与验收记录

## 1. 用户确认

1. 财务角色本次工作是**升级、优化、完善**，不是新建产品，也不是重做一套财务系统。
2. 必须保留目前已经成型的整体布局、菜单、页面职责、路由、深链、App 底部 Tab 和用户使用路径。
3. 下一步不调整后端业务逻辑。
4. 下一步工作从“按财务角色逐项验收现有菜单功能”开始，而不是先改页面或重做信息架构。
5. 菜单验收应回答：
   - 当前菜单是否属于财务角色任务；
   - 页面是否真实可用；
   - 当前功能是否完整、正确、可恢复；
   - 页面和交互是否需要最小优化；
   - 是否存在必须另行审批的后端缺口。
6. 只把验收发现转成“保持现状 / 原位优化 / 缺陷修复 / 后端缺口 / 暂不处理”五类结论。
7. 任何后端缺陷、权限、金额、成本、状态机或 Provider 逻辑问题，只登记和交接，不在本次财务 UI 升级中自行修改。
8. 小程序端遵循同一原则：保留现有底部 Tab、财务首页、快捷入口、分包页面、详情/编辑/选择器和返回路径，不新建小程序页面体系。
9. 小程序验收顺序为：角色 Tab → 财务首页 → 快捷入口 → 当前入口对应的完整任务链 → App/Web 同源核对；移动端优先高频、快捷、现场取证和即时回读，不照搬 Web 的批量表格、打印和复杂对账。

## 2. 强制约束

- 不新建财务壳层或小程序财务页面体系。
- 不删除、重命名或替换现有财务菜单、小程序底部 Tab、财务首页快捷入口和分包路由。
- 不改变现有页面路由和深链。
- 不把跨域对象复制成新的 `/finance/*` 页面。
- 不新增同义 Provider、DTO、状态、金额公式或权限。
- 不以新版原型、静态页面或“看起来更先进”为由替换现有产品。
- 每次页面优化必须先列出现状、问题证据、最小改动、回滚方式和用户验证路径。
- 先验收，后优化；未验收的菜单不进入改版。

## 3. 菜单功能验收方法

每个菜单按以下顺序验收：

```text
角色与可见性
→ 路由与页面职责
→ 真实数据与权限范围
→ 页面主要问题/主要任务
→ 当前主行动与前置条件
→ 状态、异常、失败和回读
→ App/Web 同源核对
→ 页面信息层级与交互质量
→ 最小优化建议
→ 结论与下一责任人
```

每个菜单只能给出以下结论之一：

| 结论 | 含义 | 下一步 |
| --- | --- | --- |
| `PASS` | 当前任务可成立，功能和交互无需改动 | 保留，继续下一项 |
| `OPTIMIZE` | 业务正确，但信息层级、交互或文案需原位优化 | 形成最小 UI 改造单 |
| `BUG` | 当前实现与已确认业务事实不一致 | 登记缺陷；是否修复另行确认 |
| `BACKEND_GAP` | 需要改后端逻辑/Provider/状态/金额/权限 | 只登记，不在本次修改 |
| `OUT_OF_SCOPE` | 不属于财务角色主责或不应出现在当前财务路径 | 记录归属，暂不处理 |

## 4. 当前财务角色基线

当前财务菜单以 `th4-decoboon-web/src/roles/workbenchConfig.ts` 为准，共注册 24 个菜单项，分为：

- 今日；
- 客户；
- 资金收付；
- 往来与账本；
- 凭证与归档；
- 报价与成本；
- 薪酬；
- 项目核算；
- 帮助。

上述菜单和页面是本次升级的验收对象，不以新菜单体系替代。

小程序财务角色基线：

- Finance 当前底部 Tab：`工作台 / 客户 / 财务 / 项目 / 材料计划 / 我的`；
- 财务首页：指标、逾期/临期/付款风险、财务数字口径、快捷入口、最近流水；
- 财务首页现有 5 个快捷分组、19 个快捷入口；
- `subpackages/finance` 23 个页面、`subpackages/payroll` 14 个页面、`pages/finance/index` 1 个主页面；入口、详情、编辑、选择器属于同一条任务链，不另造“菜单”。

上述内容均以原位验收、原位优化为原则。

## 5. 验收顺序

建议按财务角色的高频、资金风险和闭环优先级推进：

1. 业务工作台；
2. 待我收款、收款记录、待我付款、付款记录；
3. 客户退款、供应商往来、资金台账；
4. 费用与报销、工人工资；
5. 项目账本、收付凭证、凭证模板；
6. 薪酬工作台、薪酬方案、员工工资、员工提成、提成负向调整、本店薪酬；
7. 客户、报价、报价项目库、设计方案与报价、材料业务说明等跨域/辅助入口。

顺序可调整，但不得跳过“角色—页面—功能—回读”的验收。

## 6. 明确不做

- 不重做整体导航；
- 不新建财务页面体系；
- 不先改后端；
- 不以 UI 重构代替菜单功能验收；
- 不把“接口 200”“构建通过”“页面能打开”当作验收通过；
- 不在验收前先做大规模视觉换皮。

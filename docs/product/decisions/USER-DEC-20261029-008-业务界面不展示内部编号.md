# USER-DEC-20261029-008 · 业务界面不展示内部编号

- 决策日期：2026-10-29
- 决策人：用户
- 状态：`APPROVED`
- 业务事实：`DEC-095`、`BR-060`
- 关联：`BR-059`、`DEC-094`

## 1. 用户确认

员工编号、企业编号等内部主键不属于业务事实，不应出现在个人中心、业务列表和详情中。报价编号、合同编号、项目编号、方案编号、费用编号、凭证编号等系统生成编号，默认也不进入业务界面。

用户应通过客户名称、房屋地址、项目名称、角色、状态、金额、日期和责任人识别对象。页面不得要求用户记忆或手工输入内部编号来完成任务。

## 2. 展示边界

禁止默认展示：

- `empId`、`comId`、`customerId`、`projectId`、`quoteId`、`contractId`；
- `quoteNo`、`contractNo`、`project.no`、`scheme.no`、`expenseNo`、`voucherNo`；
- “员工编号、企业编号、报价编号、合同编号、项目编号”等字段标签；
- “搜索编号”等要求用户理解内部编码的搜索提示。

允许保留：

- 数据表主键、Provider 入参、权限校验、审计、日志、路由参数；
- 二维码内部 scene、文件命名和接口幂等键；
- 法律/监管明确要求的统一社会信用代码、法定证照号码、发票法定号码；
- 凭证套打模板中确实需要出现的凭证号码，但不在普通业务页面作为工作对象展示。

## 3. 研发落位

- Web 个人中心移除员工编号、企业编号。
- Web 项目、报价、合同、方案、费用、凭证列表和详情移除系统编号展示。
- 搜索框改为客户、房屋、项目名称、地址等人类可理解信息。
- 新增 `npm run check:identifier-exposure` 门禁并纳入 Web 构建。
- 不删除数据库字段，不改变 Provider 契约，不改变历史数据。

## 4. 验收

- 个人中心和企业信息页 DOM 中“编号/工号/单号”出现次数为 0；
- 1440、1024、390 无横向溢出；
- Web 编号门禁负向自测和正向扫描均通过；
- 用户无需知道任何编号即可完成主链识别与操作。

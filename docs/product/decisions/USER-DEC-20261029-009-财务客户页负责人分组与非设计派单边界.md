# USER-DEC-20261029-009 · 财务客户页负责人分组与非设计派单边界

- 决策日期：2026-10-29
- 决策人：用户
- 状态：`APPROVED`
- 类型：财务角色权限边界、客户页面信息架构
- 影响范围：小程序财务客户页、Web 财务客户页、客户负责人分组、设计师指派权限、客户经营聚合 Provider

## 1. 用户确认

1. 财务角色可查看和经营其数据范围内的客户。
2. 财务客户页面必须支持按客户负责人分组查看。
3. 财务不承担分配、指派或改派设计师的业务功能。
4. 负责人分组必须进入负责人的客户页面，不能只做前端本地分组。
5. 店长、企业负责人仍保留设计师指派/改派职责。

## 2. 口径调整

- 本决策仅推翻 `DEC-080` 第 4 条中“财务具备指派/改派设计承接人员能力”的部分。
- `DEC-080` 关于财务客户入口、客户数据范围、客户查看/编辑/跟进、批量录入、休眠恢复、画像和标签维护的口径继续有效。
- 财务客户数据范围继续遵循 `DEC-065`、`DEC-067`、`DEC-080`：
  - 总部财务按企业范围；
  - 门店财务按归属门店范围；
  - 不得跨企业、跨无权门店。

## 3. 页面要求

| 页面 | 财务口径 | 非财务口径 |
| --- | --- | --- |
| 小程序客户页 | 展示“按负责人查看客户”；可按负责人分组筛选；不展示“待指派设计”筛选或派单任务卡 | 店长保留待指派设计队列；Boss 保留经营分组 |
| 小程序客户详情 | 可转交客户负责人；不展示指定/改派设计师入口 | 店长、Boss 保留设计师指派/改派 |
| Web 客户页 | 可查看客户、分组与转交负责人；不展示指派设计师动作 | 店长、Boss 保留指派设计师 |
| 后端 Provider | 财务调用客户经营概览时按登录员工数据范围返回负责人分组；财务调用设计师指派 Provider 必须拒绝 | 店长、Boss、团队负责人沿用既有范围校验 |

## 4. 实现约束

- 负责人分组必须由服务端按数据范围聚合，前端不得拉取全量客户后自行拼组。
- 财务客户页不得出现“待指派设计”作为财务主任务或可点击动作。
- 财务仍可看到设计师姓名等已发生关系事实，但不得通过该事实发起派单。
- 财务权限不得通过前端隐藏代替服务端校验。

## 5. 验收要求

- 财务客户页出现全部负责人及各负责人客户数、风险数。
- 财务选择负责人后，客户列表和阶段统计按该负责人刷新。
- 财务客户页无“待指派设计”筛选、无派单提示卡、无指定设计师入口。
- 店长客户页仍显示待指派设计队列与指派入口。
- 财务直接调用 `customer/customer/handoff` 返回 403。
- App、Web、服务端口径一致。

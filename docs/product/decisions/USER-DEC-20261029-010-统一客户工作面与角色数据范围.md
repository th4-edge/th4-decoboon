# USER-DEC-20261029-010 · 统一客户工作面与角色数据范围

- 决策日期：2026-10-29
- 决策人：用户
- 状态：`APPROVED`
- 类型：客户页面统一交互、角色数据范围、后端查询效率
- 影响范围：小程序客户 Tab、Web 客户工作页、客户分页/经营概览 Provider、项目客户关系、数据库索引

## 1. 用户确认

1. 同一个产品内的客户功能不应按角色维护多套不同 UI 交互。
2. Boss、店长、财务共用同一套客户工作面：负责人分组、客户统计、搜索、阶段筛选、排序、客户卡和详情入口保持一致。
3. Boss 可查看全企业客户，并可按门店筛选；店长只能查看本店客户，页面结构与 Boss 一致。
4. 财务继续使用同一客户工作面，但在其既有企业/门店范围内查看，且不承担设计师指派。
5. 业务员只查看自己负责的客户。
6. 设计师查看“指派给自己设计的客户”和“自己作为客户负责人维护的客户”的并集。
7. 项目经理只查看归属于本人负责项目的客户。
8. 后端接口必须优先考虑效率，禁止靠前端全量拉取后分组、过滤和分页。

## 2. 角色范围矩阵

| 角色 | 客户范围 | 页面主交互 |
| --- | --- | --- |
| Boss | 全企业；可下钻门店及未归属门店 | 与店长、财务共用负责人分组客户工作面 |
| 店长 | 本门店 | 与 Boss、财务共用负责人分组客户工作面 |
| 财务 | 总部财务=企业范围；门店财务=本店范围 | 与 Boss、店长共用负责人分组客户工作面；无派单动作 |
| 业务员 | `customer.owner = 当前员工` | 本人客户跟进视图 |
| 设计师 | `customer.owner = 当前员工 OR customer.designer = 当前员工` | 本人维护与本人设计承接客户并集 |
| 项目经理 | 客户存在 `project.manager = 当前员工` 的项目关系 | 项目归属客户视图 |

## 3. 后端效率要求

- 客户列表必须在数据库完成数据范围、关键词、阶段、负责人/关系过滤和分页。
- 负责人客户数、待量房数、已签约数、阶段汇总必须在数据库聚合，不允许全量回捞客户后 Java 循环统计。
- 分页后的客户投影只批量装配当前页所需的报价、合同、标签、跟进等关联信息。
- 项目经理客户查询必须使用项目—客户关系子查询或等价 SQL，并建立 `(com_id, manager_id, project_id)` 联合索引。
- 客户索引继续以 `com_id` 最左；不得信任前端企业、门店、员工或负责人 ID。

## 4. 验收要求

- Boss、店长、财务三张客户页的核心布局和交互结构一致。
- Boss 门店切换可见且只影响本企业；店长不出现跨店切换。
- 财务客户页无“待指派设计”筛选和设计师指派入口。
- 业务员、设计师、项目经理页面分别只返回其责任关系客户。
- 关键词、阶段和负责人筛选改变后，分页总数与列表由服务端同步回读。
- 客户工作区接口不得通过全量客户实体 + Java 循环完成分组、计数或分页。

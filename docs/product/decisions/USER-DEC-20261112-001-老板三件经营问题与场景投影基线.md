# USER-DEC-20261112-001 · 老板三件经营问题与场景投影基线

- 业务依据：`CAP-001`、`SCN-002`、`SCN-003`、`SCN-012`、`SCN-016`、`SOL-002`、`MET-002`、`BR-058`、`DEC-016`、`DEC-032`

## 1. 用户确认

1. 将以下三件经营问题冻结为装得清面向老板的呈现主线和经营价值表达：
   - `OWN-P1` 客户转化：老板知道哪一单值得推进、哪一单正在丢失、为什么停、谁接下一步。
   - `OWN-P2` 项目交付：老板在损失扩大前发现项目风险，并让责任角色完成处置和恢复。
   - `OWN-P3` 经营兑现：老板和财务能解释每一单的钱、成本和利润，关键数字可回到业务来源。
2. 以“一单经营”作为产品能力的投影组织轴；不改变现有业务功能、领域边界、状态机或服务端能力。
3. 将“财务月度关账不依赖 Excel 二次重算”作为 `OWN-P3` 的正式产品验收门禁。

## 2. 冻结后的投影命题

> 同一套装企业务能力，经过面向老板的场景投影，表达为“围绕一单进行客户转化、项目交付和经营兑现”：提前发现风险、明确责任和下一步，并让所有关键数字回到同一业务事实。

“一单”是客户、房屋、报价、合同、项目、履约和财务事实的产品聚合视角，不是新增业务实体。

## 3. 决策影响

- 业务能力保持不变；市场投影决定默认入口、信息层级、业务语言、主行动顺序、场景组合、视觉表达和结果呈现。
- 老板看到的是一单经营问题和下一步，完整功能仍作为底层能力保留，不因投影而下线或缩水。
- 同一能力可以面向不同市场、角色和使用场景形成不同投影，但必须共享同一 Provider、权限、状态和金额事实。
- 现有角色菜单和专业页面继续保留兼容；投影可以重组默认入口和页面叙事，但不删除既有功能。
- 客户、项目、财务等页面必须共享同一业务事实和下一责任链，不能用多套前端投影制造多个“真相”。
- 财务验收必须覆盖项目账、资金账、应收应付、成本完整性和关账对账；仅提供财务表单和列表不构成替代 Excel。
- App、Web、业务端和服务端必须保持同 Provider、同权限、同状态、同金额语义；只验证一端不能通过。

## 4. 不授权事项

- 不新增或修改业务对象、状态机、角色、权限、金额、成本或利润公式。
- 不以“投影”为名重构业务功能、删减既有能力或重做完整信息架构。
- 不为不同市场复制第二套业务页面、接口或状态语义。
- 不自动扩大当前首发范围；首发范围调整仍需独立产品决策。
- 不直接授权编码、DDL、迁移、生产数据修复或发布。
- 不将角色菜单并集立即删除；兼容现网客户使用习惯。
- 不将本决策视为业务验收、视觉验收或跨端验收通过。

## 5. 后续动作

1. 先建立“市场需求 → 场景任务 → 现有能力 → 投影形式”的映射，不先改业务功能。
2. 投影方案必须列出使用的既有能力、入口位置、信息层级、业务语言、主行动和异常表现。
3. 同一业务动作在投影前后必须保持 Provider、状态、权限、金额和回读事实不变。
4. `OWN-P3` 的页面和财务方案必须同时提交月度关账验收脚本；Excel 只作为承接或导出工具。
5. 任何角色菜单或默认入口调整若影响现有客户使用习惯，必须另做兼容方案和用户确认。

# 合同与增减项履约 · 真实业务场景

## 场景 A：合同生效后新增卫生间防水

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 设计师发起；Boss 或本店店长审批；财务核对金额 |
| 触发事件 | 客户在施工前提出增加卫生间防水施工 |
| 前置条件 | 合同已生效、项目未完工、目标 `CatalogItem` 已启用、明细与原因完整 |
| 当前动作 | 设计师选择“新增分项”，从报价项目库选择目标、确认工程量并提交一张变更单 |
| 系统下一步 | 服务端形成 `Pending`，计算目标金额并冻结目标快照；待审批期间客户同频显示“审批中”，不显示金额 |
| 成功结果 | 企业审批通过后同一事务更新合同额、项目合同额、应收、任务、材料计划和成本；状态为“已生效”，客户可见金额 |
| 异常/恢复 | 目标成本缺失 → 成本未完整、利润 null；重复提交/审批 → 幂等；来源或审批权限变化 → 拒绝并提示重新确认 |
| 涉及对象 | ContractChange、ContractChangeItem、ProjectContract、Receivable、ProjectTask、MaterialPlan、ProjectCost、CatalogItem |
| 状态变化 | Pending → CustomerConfirmed（对外“已生效”）；驳回 → Rejected；撤回 → Cancelled |
| 金额/成本/权限 | 变更额 = +目标分项金额；成本只对 Boss/店长/财务可见 |
| 证据/来源 | SCN-004、BR-035、BR-041、DEC-055、DEC-068 |

## 场景 B：已下单瓷砖替换为另一品牌

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 设计师发起；Boss/财务审批；PM 与财务执行履约结果 |
| 触发事件 | 客户在瓷砖作业单已提交但尚未全部到场时，要求更换品牌和规格 |
| 前置条件 | 原合同行当前有效剩余可确认；目标 `CatalogItem` 启用；原材料计划/采购/到场状态可读取 |
| 当前动作 | 设计师选择“替换”，系统展示来源当前有效剩余与待审批占用，选择目标分项和工程量并提交 |
| 系统下一步 | 服务端按“目标金额 − 来源当前有效剩余金额”计算差额并冻结目标快照；审批时复核来源基线 |
| 成功结果 | 未采购部分关闭来源范围并生成目标材料计划；已采购部分保留原事实，走采购调整或已到货退货；合同额/应收/成本同步修正 |
| 异常/恢复 | 来源已被其他待审批单占用 → 阻断；审批时基线变化 → 拒绝撤回重做；历史来源无法推导 → 只能只读并阻断新变更 |
| 涉及对象 | ContractChange、ContractChangeItem、ContractLine、MaterialPlan、PurchaseOrder、GoodsReceipt、MaterialReturn、Receivable、ProjectCost |
| 状态变化 | Pending → CustomerConfirmed；原合同行不改；已采购事实保留 |
| 金额/成本/权限 | 差额 = 目标金额 − 来源当前有效剩余金额；成本缺失时利润 null |
| 证据/来源 | SCN-004、SCN-021、BR-041、BR-045、DEC-055、DEC-073 |

## 反向场景

- 越权：业务员/财务/客户不能发起；非本项目员工、跨门店、跨企业请求返回 404/403。
- 重复提交/幂等：重复提交、重复审批、重复生效不得重复生成应收、任务、材料或成本。
- 跨租户/跨项目：来源合同行、变更单、项目、目标目录项必须同企业同一项目链路。
- 数据缺失：原因、明细、目标、工程量或来源范围不完整时不得形成正式单。
- 状态不满足：合同未生效、项目完工、合同终止/关闭时不得发起新变更。
- 金额/成本不完整：合同额不得为负；目标成本缺失不得写 0，利润/毛利率必须为 null。
- 并发：两个待审批变更占用同一来源时必须可见；审批只允许一个成功，失败方不产生半套数据。

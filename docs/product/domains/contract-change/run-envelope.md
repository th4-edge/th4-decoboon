# 合同与增减项履约 · Run Envelope

## 1. 目标

- Domain：`contract-change`
- North Star：合同生效、增减项审批与合同、任务、材料、应收和成本的同源联动形成可追溯闭环。
- 目标角色：Boss、店长、财务、设计师、PM、客户（只读）、System。
- 本期范围：B0-B1 的业务事实核对、真实场景、结构化蓝图、字段字典和对账矩阵。
- 本期不做：代码修改、迁移、页面开发、生产发布、正式小程序提审。

## 3. 自主决策权限

在本域 B1 内可自主整理知识、场景、蓝图和对账；不得自行进入代码实现。

## 4. 人工门禁

遇到新业务对象/状态/角色、金额/成本/支付语义变化、DDL、迁移、生产数据删除、正式小程序发布、权限放宽时停止并写决策包。

## 5. 质量门禁

- 业务事实有 OBJ/BR/SCN/DEC/GAP 引用；
- 场景闭环；
- 蓝图节点有来源或显式标 gap；
- 实现与页面有真实证据；
- 独立验收不由实现者自批。

## 6. 预算与止损

- 每个缺陷最多修复 3 轮；
- UI 审查最多 2 轮；
- 两次无进展停止分支并写决策包；
- B1 完成后等待用户确认是否开启 B2。

## 7. Return Packet

- 已完成批次与证据；
- 未完成项、风险和待决策；
- 下一批提示词；
- 是否允许进入实现。

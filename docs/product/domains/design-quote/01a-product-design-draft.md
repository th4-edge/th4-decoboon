# 设计方案与设计报价审视 · 产品设计候选稿

> 状态：`CANDIDATE`，仅用于业务对齐，不是冻结蓝图，不代表已实现。

## 1. 定位冻结

| 对象/视图 | 定义 | 不是什么 |
| --- | --- | --- |
| 设计方案 | 客户某套房屋下的一版设计结果，包含区域、设计分项、图纸与方案状态 | 不是客户跟进记录，不是报价版本 |
| 方案计算价 | 当前设计分项销售金额的服务端汇总 | 不是正式报价，不包含报价级折扣/税费/费用 |
| 正式报价 | 从方案生成、可提交客户并形成版本的 Quote 快照 | 不是设计分项实时合计 |
| 当前报价 | 服务端按统一规则选出的当前有效或最近正式报价摘要 | 不由 App/Web 各自遍历列表猜测 |
| 设计方案审视 | BOSS/店长/财务从运营管理视角读取方案、当前报价、成本和异常的只读工作视图 | 不是审批、核价、退回或流程节点，不替代报价工作台 |

## 2. 当前现状与问题

| 端/页面 | 已有能力 | 缺口 |
| --- | --- | --- |
| App 设计工作台 | 客户、房屋、量房、方案数、诉求、停留天数 | 卡片无当前价格、报价状态和风险 |
| App 方案列表 | 已按方案关联报价并显示正式报价金额 | 无报价时只显示“待报价”，不显示方案计算价；当前报价选择逻辑在前端 |
| App 方案详情 | 区域、分项、金额和方案动作 | 金额是局部汇总，缺少与正式报价的并列视图 |
| Web 待我设计 | 客户 + 房屋队列、方案轨道、进入方案工作区 | 方案卡只有面积/空间/设计项/更新时间，无价格 |
| Web 方案工作区 | 有方案金额、报价状态、生成/继续报价 | 只对当前方案有效，无法横向审视多个设计师/房屋 |
| Web BOSS/店长 | 可进入设计相关路由 | 无“设计报价审视”列表；入口语义仍偏“待我设计” |
| Web 财务 | 可看项目与财务 | 无设计方案/报价审视入口 |
| 后端 | `design/scheme/page`、`design/scheme/info`、`quote/designer/page` | Page 无价格；当前报价依赖前端选择；成本字段未统一按角色裁剪 |

## 3. 信息架构

### App

| 角色 | 定位 | 入口 | 页面能力 |
| --- | --- | --- | --- |
| Designer | 现场执行 + 即时看价 | 现有「设计工作台」 | 卡片显示方案当前价格；进入方案后编辑/生成报价 |
| Boss | 移动端只读快速审视 | 工作台快捷入口「设计方案」 | 本企业方案列表、价格、状态、风险；点击查看只读详情 |
| StoreManager | 本店只读快速审视 | 现有「门店设计方案」 | 本店方案列表、价格、状态、风险；可进入本店方案编辑 |
| Finance | 不把 App 作为主要经营查看入口 | P2 再议 | 金额与成本横向查看更适合宽屏 Web |
| Marketer | 本人客户只读 | 客户详情已有设计关联 | 只读方案状态和报价状态，不显示成本 |
| Pm | 项目来源只读 | 项目详情关联 | 只读已选定方案/报价快照 |

### Web

| 角色 | 入口 | 页面 |
| --- | --- | --- |
| Designer | 「方案报价 → 待我设计」 | 保持执行队列；方案卡增加价格 |
| Boss | 「设计报价 → 设计方案审视」 | 全企业列表；按门店/设计师/客户/房屋/状态/风险筛选 |
| StoreManager | 「本店客户 → 设计方案审视」或「设计报价」 | 本店列表；能力同 BOSS 但数据范围限本店 |
| Finance | 「项目核算 → 设计方案与报价查看」 | 总部财务全企业、门店财务本店；只读 |
| TeamLeader | 团队经营入口 | 团队范围只读（P1） |

建议共用一个 Web 审视组件、同一服务端 Provider，按角色静态路由挂载；不要复制三套页面。

## 4. 列表设计

### 4.1 页面目标

用户打开列表后第一眼回答：

1. 当前范围内有哪些设计方案需要我看？
2. 每套方案现在值多少钱？
3. 哪套存在待补尺寸、成本未完整、客户驳回或旧报价风险？
4. 下一步是继续设计、重新报价、查看成本缺口，还是仅完成运营查看？

### 4.2 筛选与视图

顶部筛选：

- 关键词：方案名、方案编号、客户、房屋、报价编号
- 设计师
- 门店（BOSS/总部财务）
- 设计状态：设计中 / 待谈单 / 已讲解 / 已选中 / 已归档
- 报价状态：未报价 / 草稿 / 已提交 / 客户拒绝 / 客户接受 / 已转项目
- 风险：待补尺寸 / 公式待修订 / 成本未完整 / 报价需重算 / 长时间未推进
- 时间：最近更新、报价时间、客户驳回时间

默认排序：

1. 有风险且临近谈单/签约；
2. 最近更新；
3. 金额从高到低可作为可选排序，不作为默认。

### 4.3 方案卡字段

每张卡固定显示：

```text
方案名 · 编号 · V版本
客户 / 房屋 / 设计师 / 门店
设计状态 + 报价状态
主价格：当前正式报价金额；无正式报价时显示“方案计算价”
副价格：方案计算价（有正式报价时用于对比）；报价版本/时间
风险标签：待补尺寸 N / 公式待修订 N / 成本未完整 / 报价需重算 / 客户已拒绝
主行动：继续设计 / 生成报价 / 查看报价 / 查看成本缺口（按角色）
```

价格展示规则：

| 场景 | 主展示 | 辅助文案 |
| --- | --- | --- |
| 有当前正式报价 | `¥128,600.00` | `正式报价 V3 · 已提交` |
| 无正式报价，有方案分项 | `¥126,800.00` | `方案计算价 · 待生成正式报价` |
| 方案无分项 | `尚不可计算` | `还需录入区域/分项` |
| 报价客户拒绝 | `¥128,600.00` | `V3 客户已拒绝 · 待改版重报` |
| 报价需重算 | `¥126,800.00` | `方案已变更，当前报价可能过期` |

### 4.4 设计师执行卡

App 设计工作台仍以客户 + 房屋为队列，但增加：

- 当前房屋下“选中/最新方案”的名称、状态和主价格；
- 如果有多个方案，显示方案数，并在进入后使用方案轨道；
- 报价状态和是否可继续报价；
- 不显示成本、毛利。

Web 设计师 `DesignSchemeRail` 增加：

- 主价格；
- 报价状态；
- 风险条；
- 保留复制/删除，不把编辑操作搬到卡片中。

## 5. 审视详情设计

### 5.1 首屏结论区

固定显示：

- 方案名、编号、版本、设计状态；
- 客户、房屋、负责设计师、门店；
- 当前正式报价金额、报价状态、报价版本；
- 方案计算价；
- 成本完整性/毛利（仅授权角色）；
- 唯一主行动：继续设计 / 打开报价 / 返回补充资料。

### 5.2 价格与成本摘要

授权角色看到四张摘要卡：

1. 正式报价金额
2. 方案计算价
3. 预计成本
4. 毛利/毛利率（成本不完整时为“成本未完整”）

设计师只看到：

1. 正式报价金额
2. 方案计算价
3. 销售价构成
4. 报价状态/版本

### 5.3 分项审视表

按“区域 → 类型 → 组内顺序”展示：

| 列 | 说明 | 设计师 | 经营/财务 |
| --- | --- | --- | --- |
| 区域/分项 | 区域、项目名称、分类 | ✔ | ✔ |
| 工程量/公式 | 工程量、公式、来源 | ✔ | ✔ |
| 销售单价 | 材料价/人工价/固定总价结果 | ✔ | ✔ |
| 销售金额 | 当前分项金额 | ✔ | ✔ |
| 成本单价/成本金额 | 标准成本和分项成本 | ✘ | ✔ |
| 毛利/风险 | 分项毛利或成本待维护 | ✘ | ✔ |

顶部提供异常筛选：

- 待补尺寸
- 公式待修订
- 材料价/人工价缺失
- 成本待维护
- 显式 0 成本
- 报价与方案计算价差异异常（阈值待裁决）
- 设计分项与报价行差异

### 5.4 报价版本区

使用报价时间线：

```text
V1 草稿 → V2 已提交 → V3 客户拒绝 → V4 草稿（当前）
```

- 每个版本显示金额、提交/拒绝/接受时间、操作人、状态；
- 历史版本只读；
- 客户拒绝时必须能回到设计方案调整或改版重报；
- 当前报价由服务端标识，不由前端按数组顺序猜测。

### 5.5 设计上下文

按需折叠：

- 客户诉求与画像
- 量房原始区域和现场证据
- 方案区域与尺寸来源
- 效果图/CAD/原始户型
- 谈单 PPT
- 报价 PDF

## 6. 服务端读模型

### 6.1 列表读模型

建议在 `Design` 上使用只读瞬态字段，不新增 VO/DTO：

```text
designCalculatedAmount
currentQuoteId / currentQuoteNo / currentQuoteVersion / currentQuoteStatus
currentQuoteAmount
currentQuoteCostAmount
currentQuoteCostComplete
currentQuoteGrossProfit
currentQuoteGrossMargin
pendingMeasureCount
formulaRevisionNeededCount
costPendingCount
quoteOutdated
riskFlags[]
lastQuoteAt
```

- 设计师响应中清空成本/毛利字段；
- BOSS/店长/财务按数据范围返回；
- 当前报价由服务端一次查询确认；
- 列表金额通过聚合查询/子查询计算，禁止逐方案调用 `design/scheme/info`。

### 6.2 详情读模型

在 `design/scheme/info` 中增加：

- 方案计算价；
- 当前报价摘要；
- 报价版本时间线；
- 成本完整性；
- 风险计数；
- 由 `DesignCostContext` 统一裁剪敏感字段。

不得仅靠 `@Properties` 白名单决定成本是否可见；字段权限必须在业务 Context 中执行。

### 6.3 性能

- 列表聚合 SQL 目标 ≤30 条；
- 并发 P95 ≤500ms；
- 方案数增加时 SQL 条数不增长；
- 金额汇总使用数据库聚合/投影，不使用全量实体 + Java 循环求和；
- 响应只返回列表实际字段。

## 8. 分批实施

### B1：价格可见与角色入口（P0）

- 后端读模型：方案计算价、当前报价摘要、风险计数；
- 成本字段按角色裁剪；
- App 设计工作台与方案卡显示价格；
- Web `DesignSchemeRail` 显示价格；
- Web 新增 BOSS/店长/财务设计方案审视列表；
- 复用同一 Provider，按角色路由与菜单挂载。

### B2：审视详情（P0）

- 详情首屏价格/成本摘要；
- 分项审视表与异常筛选；
- 报价版本时间线；
- 成本未完整、待补尺寸、公式待修订、报价可能过期提示；
- 只读动作与进入编辑/报价的上下文跳转。

### B3：移动端经营查看（P1/P2）

- BOSS/店长 App 只读快速查看；
- Finance App 仅在业务确认后提供极简只读查看；
- 不增加审批、核价、退回或批量处理动作。

## 9. 验收标准

1. 设计师 App/Web 方案列表均能看到当前价格，且与详情一致。
2. 无正式报价时显示方案计算价，不显示“待报价=无金额”。
3. 有正式报价时以正式报价为主，方案计算价为辅助对照。
4. BOSS、店长、财务能在 2 层导航内进入设计方案审视。
5. 店长/门店财务不能跨店；BOSS/总部财务不能跨企业。
6. 设计师、业务员、项目经理响应中不出现成本和毛利。
7. 成本不完整时毛利与毛利率为 `null`，页面显示“成本未完整”。
8. 当前报价选择完全由服务端返回；前端不再自行挑选 accepted/converted 报价。
9. 客户拒绝、待补尺寸、公式待修订、方案变更后报价可能过期都有独立状态和恢复路径。
10. 列表聚合性能达标，SQL 条数不随方案数增长。
11. 审视页不产生任何新状态、待办或写动作；发现问题只能跳转既有工作面处理。

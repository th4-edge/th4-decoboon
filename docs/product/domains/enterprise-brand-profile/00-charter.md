# 装企信息与品牌投影 · 业务域章程

- Domain：`enterprise-brand-profile`
- Owner：codex
- Created：2026-10-29
- North Star：装企主体、品牌、地址、联系方式和资质在 App、Web、合同、单据导出打印及业主端保持单一主源、清晰语义、冻结快照和可追溯投影。

## 1. 业务问题

- 当前场景：装企信息已在企业资料、门店、单据资料、业主服务方投影、邀请卡片、报价/合同/凭证 PDF 和导出文件中分别出现，但字段语义、主源、快照和消费者没有形成一套完整闭环。
- 谁遇到问题：BOSS、店长、财务、设计师、项目经理、客户成功人员、业主以及打印/归档使用人。
- 当前损失/风险：
  - 企业改名、换 Logo、换地址后，不同页面和文件可能显示不同版本；
  - `Company` 与 `DocumentProfile` 同时保存法定名称、地址和 Logo，存在多主源风险；
  - 门店名称/地址与公司地址混用，客户不知道应该去哪里；
  - “地址”同时指企业办公地址、门店地址、项目施工地址和房屋地址；
  - Logo 已存储但合同/报价/凭证渲染未统一使用；
  - 地图点位和结构化地址缺失，无法稳定生成导航和服务位置；
  - 历史合同、已发单据和当前品牌之间缺少明确快照边界；
  - 企业资料完整度无法转化为对外展示、打印、导出和客户体验的完整度。
- 希望达到的结果：企业信息一次维护，按受众投影到内部、业主、合同、单据、打印和导出；当前品牌可更新，历史业务事实不被回溯改写。

## 2. 目标角色

| 角色 | 主要目标 | 关键动作 | 不负责什么 |
| --- | --- | --- | --- |
| BOSS | 维护企业法定主体、品牌、服务信息和对外展示口径 | 维护企业信息、Logo、品牌色、服务地址、联系通道、资质与展示范围 | 不代替业主确认，不修改历史合同事实 |
| StoreManager | 维护本店可授权范围内的门店名称、地址和联系协同 | 查看企业品牌，维护本店经营位置信息（待业务裁决范围） | 不修改企业法定主体和企业品牌主档 |
| Finance | 使用正确的企业抬头、税号、开户信息生成财务凭证和导出 | 查看/使用单据抬头资料，核对付款信息 | 不决定品牌表达与客户展示范围 |
| Designer/Pm/Marketer | 在合同、报价、谈单材料、邀请和业主沟通中使用同一品牌事实 | 读取并引用统一品牌投影 | 不另建企业资料副本 |
| 业主 | 知道哪家企业和哪些人在为自己服务，并能找到服务位置和联系通道 | 查看企业名称、Logo、服务区域、客服、售后、地址/地图 | 不查看内部银行、成本、员工个人号码等敏感信息 |
| 平台运营 | 保障租户隔离和系统运行 | 只读审计、订阅管控 | 不代填、不背书企业资质和品牌 |

## 3. 本期范围

- 必须做：
  1. 定义装企信息的关键概念、语义边界与稳定候选 ID；
  2. 识别主源、重复源、投影、快照和下游消费者；
  3. 覆盖企业名称、品牌名称、Logo、品牌色、服务/办公/门店地址、地图点位、客服/售后、税号、法人、资质、简介；
  4. 对账 App、Web、业主端、报价/合同/凭证 PDF、导出和打印；
  5. 形成业务裁决问题和后续垂直切片。
- 暂时不做：门店品牌独立体系、企业官网、跨企业评分、平台代认证、法定电子签章。
- 明确排除：代码修改、DDL、权限放宽、生产数据迁移、对外宣传发布和正式发版。

## 4. 主链

```text
企业主体/品牌/地址/联系信息由 BOSS 维护
→ 保存为企业主源事实
→ 按受众组装为企业信息投影
→ App/Web 企业页、业主端、邀请卡片、单据和导出消费同一投影
→ 需要法律或交易留痕时形成版本快照
→ 主档更新不回溯历史快照
→ 缺失/失败显示暂不可确认并保留恢复路径
```

## 5. 关键不变量

1. 法定企业主体、企业品牌、门店经营主体和项目施工地址不是同一个概念。
2. 一个信息项只能有一个可编辑主源；投影只读取，快照只冻结。
3. `Company` 是租户根对象，`Store` 是组织/经营位置，`DocumentProfile` 是否保留为独立主源必须业务裁决。
4. 平台品牌 Logo 与装企自有 Logo 严格分开；不得用平台 Logo 代替装企 Logo。
5. 地址必须带语义类型，至少区分企业办公/通讯地址、门店经营地址、项目施工地址、房屋地址。
6. 合同、报价、凭证、导出和打印必须在生成时使用明确版本的企业信息投影；创建后不得被主档更新回溯改写。
7. 业主可见信息以“服务主体知情权”为边界，不包含内部银行账号、成本、员工个人手机号等敏感信息。
8. 缺失企业信息时显示“暂不可确认”，不得使用平台信息或空字符串冒充装企事实。

## 6. 权限与数据范围

- BOSS：企业法定主体、品牌和展示口径的唯一维护者；按现有 `company/company/update` 权限。
- StoreManager：门店资料维护边界待业务裁决；不得修改企业主体和品牌主档。
- Finance：单据抬头与开户信息使用，不决定品牌展示。
- 业主：只读、仅本人被授权项目的服务方投影。
- 跨租户：企业资料、Logo 文件、地址和导出文件不得跨企业读取。
- 敏感字段：银行账号、法定代表人、税号等按受众裁剪；对外展示需业务裁决。

## 7. 成功指标

- 产品：企业信息维护一次后，所有目标表面按规则读取同一投影。
- 数据质量：企业主档、门店地址、单据抬头和历史快照的重复源为 0 或有明确业务理由。
- 业务结果：业主能识别服务主体、服务位置和联系通道；合同、报价、凭证和导出能正确露出装企品牌。
- 安全：跨租户、敏感字段和未授权导出为 0。

# 装企信息与品牌投影 · 关键概念图谱 v0.1

> 状态：`candidate / BIZ_TRIAGE_PENDING`  
> 性质：业务概念梳理，不是数据库设计，不是已确认字段清单。  
> 目的：为后续表单、API、合同、打印、导出和业主端投影提供统一语言。

## 1. 总原则

装企信息不是单一“企业资料”字段集合，而是六个层面的组合：

```text
企业是谁（Legal Identity）
它对外想成为谁（Brand Identity）
它在哪服务（Service Location）
客户怎么联系它（Contact Channels）
它的交易与履约凭证是什么（Document Identity）
信息在什么时间、给谁看（Projection & Snapshot）
```

核心关系：

```text
企业主体 Company
├─ 法定身份 LegalIdentity
├─ 品牌身份 BrandIdentity
├─ 对外服务信息 ServiceIdentity
├─ 地址与位置 ServiceLocation[]
├─ 资质与信任材料 Qualification[]
├─ 品牌资产 BrandAsset[]
└─ 单据抬头 DocumentIdentity
      └─ 业务单据投影 / 快照

Store
├─ 门店组织身份
├─ 门店服务地址/地图点位
└─ 门店级品牌覆盖（待裁决）

Project/Property
└─ 施工/房屋地址（与装企地址不同）
```

## 2. 关键概念定义

### 2.1 企业法定主体身份 `ENT-LEGAL-001`

回答“合同、税票、资质和对公账户所对应的法律主体是谁”。

候选信息：

- 企业法定全称
- 统一社会信用代码
- 法定代表人
- 注册地址或法定登记地址（当前未明确建模）
- 企业主体类型/状态（如适用）
- 有效期、来源与核验状态（如适用）

主源候选：企业法定主档。  
不可与品牌简称、门店名称混用。  
适用场景：合同、发票/凭证、资质、财务对公信息、法定导出。

### 2.2 企业品牌身份 `ENT-BRAND-001`

回答“客户和员工日常看到、记住的是谁”。

候选信息：

- 对客品牌名
- 企业简称
- 品牌 Logo
- 品牌色
- 品牌简介/一句话定位
- 品牌叙事主主体（企业/平台）
- 平台存证署名策略

主源候选：企业品牌配置。  
适用场景：业主端、邀请、企业展示、非法律性质的打印/导出、营销材料。  
边界：品牌名不能自动替代法定名称出现在合同主体栏。

### 2.3 品牌视觉资产 `ENT-BRAND-002`

Logo 不是普通文本字段，至少包含：

- 文件对象与访问地址
- 文件格式、宽高、透明背景、清晰度
- 上传人、上传时间、版本
- 使用范围：企业内部、业主端、单据、邀请、合同/导出
- 版权/授权声明
- 当前有效状态
- 历史版本

候选主源：企业品牌资产；`Company.logo`/`DocumentProfile.logo` 不应同时作为两个独立可编辑主源。  
平台品牌 Logo 与装企 Logo 是不同资产，不得互相兜底。

### 2.4 对外服务身份 `ENT-SERVICE-001`

回答“客户如何确认企业的服务范围和信任信息”。

候选信息：

- 服务区域
- 服务类型/业务范围
- 企业统一客服电话
- 售后专线
- 资质名称/等级/有效期（如适用）
- 一句话简介
- 对外服务承诺（必须来自企业自填自审，不得平台代填）

适用场景：业主端服务方信息、企业展示、分享页、邀请页、官网/营销素材。

### 2.5 企业地址 `ENT-LOC-001`

必须区分：

| 地址类型 | 回答的问题 | 当前可能承载 |
| --- | --- | --- |
| 法定注册地址 | 法律主体登记在哪里 | 当前未清晰建模 |
| 企业办公/通讯地址 | 客户函件、合同抬头、对外联系地址在哪里 | `Company.addr` / `DocumentProfile.address` |
| 门店经营地址 | 这家门店在哪里接待和服务客户 | `Store.addr` |
| 项目施工地址 | 这一单工程在哪里施工 | `Project.siteAddr` / `Property.address` |
| 客户房屋地址 | 业主房屋在哪里 | `Property.address` |

概念结论：一个字符串“地址”不足以支撑导航、合同、门店和业主展示。至少需要“地址语义类型 + 展示文本 + 地区 + 地图点位 + 来源/更新时间”。

### 2.6 地图点位 `ENT-LOC-002`

回答“在地图上点哪里”。

候选信息：

- 地址文本
- 行政区划
- POI/楼宇/园区
- 纬度/经度
- 坐标系与地图供应商
- 地图链接或可唤起导航的标识
- 点位来源：企业填写、地图搜索选择、历史导入
- 点位核验状态和更新时间

当前代码未发现 Company/Store 的经纬度或地图点位。  
业务上必须决定：地图点位是必填、可选还是只对部分地址类型开放；是否允许 BOSS/店长手动拖动校准。

### 2.7 联系通道 `ENT-CONTACT-001`

候选信息：

- 企业统一客服电话
- 售后专线
- 企业微信/群入口（如正式支持）
- 服务门店联系电话（是否对外待裁决）

强制边界：员工个人手机号默认不作为企业对外联系通道；业主端优先使用企业统一号码。

### 2.8 资质与能力证明 `ENT-QUAL-001`

候选信息：

- 资质名称
- 等级/范围
- 证书编号
- 有效期
- 发证机构
- 附件/证据
- 企业自填自审状态
- 平台核验状态（如未来支持）

当前 `qualification` 为文本字段，是否能承载资质文件、有效期和核验需要业务裁决。  
平台不代填、不推算、不背书。

### 2.9 单据抬头资料 `ENT-DOC-001`

回答“合同、报价、凭证、导出文件上，企业以什么身份出现”。

当前字段：

- 法定名称
- 统一社会信用代码
- 法定代表人
- 通讯地址
- 服务热线
- 开户行
- 银行账号
- Logo

关键问题：`DocumentProfile` 与 `Company` 重复保存法定名称、地址和 Logo，但两者没有同步生命周期和快照责任。  
候选结论：将其定义为“单据抬头投影/快照”，而不是第二套企业主档；若业务确需单据抬头独立维护，必须明确哪些字段可覆盖、谁维护、如何避免漂移。

### 2.10 品牌投影 `ENT-PROJ-001`

同一企业信息按受众和目标生成不同投影：

| 投影 | 目标 | 信息范围 |
| --- | --- | --- |
| 内部管理投影 | 企业资料页、工作台、邀请 | 法定信息 + 品牌 + 地址 + 联系 + 权限 |
| 业主服务投影 | 我的家、服务方、分享页 | 品牌名、Logo、品牌色、服务区域、客服/售后、资质、服务地址/地图 |
| 合同/交易投影 | 合同、财务凭证、导出文件 | 法定名称、税号、法人、地址、开户信息、Logo（按模板） |
| 营销展示投影 | 官网/宣传素材 | 品牌、Logo、简介、服务区域、授权资质；不自动包含内部信息 |

投影不产生新的业务事实；接口失败或字段缺失时必须返回明确的不可确认状态。

### 2.11 品牌快照 `ENT-SNAP-001`

回答“这份历史合同/报价/凭证当时使用的是什么企业信息”。

候选结论：

- 当前企业品牌主档可以更新；
- 已经签署或生成的正式文件必须冻结“当时的企业身份投影”；
- 快照至少包含：来源主档 ID/版本、法定名称、品牌名、Logo 资产版本、地址、联系通道、税号/资质（按文件类型）；
- 主档更新不得回溯已冻结文件；
- 重新生成必须形成新版本，不能静默覆盖旧文件。

当前已有 `DocumentRecord` 归档文件，可作为文件级快照的起点，但数据级快照和来源版本仍需裁决。

| `ENT-LOC-001` | 企业/门店地址 | Primary | 企业/门店地址主档 | 导航、合同、业主 |
| `ENT-LOC-002` | 地图点位 | Primary/Reference | 地址主档 | 导航、业主、分享 |
| `ENT-CONTACT-001` | 企业联系通道 | Primary | 企业服务配置 | 业主、分享、客服 |
| `ENT-QUAL-001` | 资质与能力证明 | Primary/Evidence | 企业资质主档 | 业主、官网、合同附件 |

## 4. 需要特别区分的词

| 当前叫法 | 必须区分成 |
| --- | --- |
| 企业名称 | 法定名称 / 对客品牌名 / 简称 / 门店名 |
| 企业地址 | 法定注册地址 / 办公通讯地址 / 门店经营地址 / 项目施工地址 / 房屋地址 |
| Logo | 平台品牌 Logo / 装企品牌 Logo / 门店 Logo（是否支持待裁决） |
| 品牌 | 企业法定主体 / 对客品牌 / 门店服务品牌 / 平台存证署名 |
| 单据抬头 | 当前企业投影 / 生成时快照 / 归档文件 |
| 服务电话 | 企业客服 / 售后专线 / 门店电话 / 员工个人电话 |
| 服务区域 | 文字服务范围 / 行政区划 / 地图覆盖区域（待裁决） |

## 5. 应用闭环原则

每个企业信息项必须回答：

```text
谁维护
→ 存在哪里
→ 当前谁读取
→ 哪个页面/文件展示
→ 展示后支持什么动作
→ 变更后哪些当前投影刷新
→ 哪些历史快照不变
→ 缺失/失败怎么表达
```

只有“有字段、有页面展示，但没有下游动作或可验证场景”的，不算形成业务闭环。

## 6. 本批概念结论

1. 装企信息应拆成法定身份、品牌身份、服务信息、地址/位置、联系通道、资质和单据投影。
2. Logo 必须被定义为品牌资产，不是一个可重复散落的字符串字段。
3. 地址必须按语义分类，地图点位是独立且可选的地址能力。
4. DocumentProfile 不应在没有边界的情况下继续充当第二套企业主档。
5. 正式合同、报价和凭证需要明确数据级品牌快照与版本。
6. 同一企业信息在 App、Web、业主端、打印和导出中必须共享一套投影规则。

## 7. 2026-10-29 用户补充后的设计收敛

用户进一步明确：

- Company 是企业事实唯一根；
- 企业信息必须分层；
- 快速入驻后通过“我的 → 企业信息”逐步完善；
- 初期缺字段允许占位，但占位不是企业事实；
- 合同、凭证和对外承诺的关键字段不能依赖占位。

据此，本域的概念设计以 `01d-company-information-complete-design-v0.2.md` 和 `01e-company-information-model-v0.2.json` 为准；本文件保留为概念基线。

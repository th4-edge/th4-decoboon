# 装企 Company 信息完整设计 v0.2

> 状态：`candidate / 待业务裁决`  
> 依据：`USER-DEC-20261029-003`、`OBJ-010`、`BR-059`、`USER-DECISION-20261014-002`  
> 性质：企业信息的概念与产品结构设计，不是数据库设计，不是最终字段白名单。  
> 核心约束：Company 是企业事实的唯一根；其他表面只能使用 Company 投影或历史快照。

## 1. 设计目标

### 1.1 快速入驻

新装企不需要一次填完整套企业档案，只需要提供业务开始所需的最小信息，系统自动建立默认总店和可用环境。

### 1.2 渐进建立信任

企业信息随着实际业务逐步完善：

```text
先能开展业务
→ 再能对业主展示
→ 再能签合同/做财务
→ 再完善品牌、资质、地图和信任资料
```

### 1.3 一次维护、多处使用

同一企业事实只维护一次，统一投影到：

- App/Web 企业信息页；
- 邀请卡片；
- 业主首页、分享页和“我的家”；
- 报价、合同、凭证；
- PDF、打印、下载和导出。

### 1.4 占位不等于事实

占位只保证流程连续和界面可理解，不得写成企业真实信息，不得进入合同主体、财务凭证或对外承诺。

## 2. Company 信息分层

```text
Company（企业事实根）
├─ A. 企业基础身份
├─ B. 法定主体身份
├─ C. 企业品牌身份
├─ D. 对外服务身份
├─ E. 地址与地图位置
├─ F. 联系通道
├─ G. 资质与信任证据
├─ H. 单据身份
├─ I. 展示与投影策略
├─ J. 门店服务身份
└─ K. 版本、完整度与快照
```

### A. 企业基础身份

用于“系统里先能用起来”，不等于完整法定身份。

- 企业展示名称
- 企业简称
- 企业状态
- 默认总店（系统自动建立）
- 企业负责人（来自 BOSS 账号）
- 入驻时间、创建时间

快速入驻最少需要“企业展示名称”；其他字段可以后续补。

### B. 法定主体身份

用于合同、税票、资质和对公资料。

- 企业法定全称
- 统一社会信用代码
- 法定代表人
- 法定注册地址
- 营业执照/主体证明证据
- 主体状态与有效期（如业务需要）

法定主体信息不能使用展示名称或平台名称替代。

### C. 企业品牌身份

用于客户识别和企业对外表达。

- 对客品牌名/企业展示名
- 品牌简称
- 企业 Logo
- 品牌色
- 一句话简介
- 品牌叙事主体（企业/平台）
- 平台存证署名策略

Logo 是品牌资产，不是普通文本字段。品牌名、法定名称和门店名称必须可区分。

### D. 对外服务身份

用于业主知情和信任建立。

- 服务区域
- 服务范围/主营业务
- 服务承诺（企业自填自审）
- 服务时间（如适用）
- 售后范围/质保说明（如适用）

服务承诺和资质信息不得由平台代填或推算。

### E. 地址与地图位置

必须按用途拆分：

- 企业注册地址
- 企业办公/通讯地址
- 门店经营地址
- 项目施工地址
- 业主房屋地址

只有企业办公地址和门店经营地址属于“装企服务位置”。项目施工地址和房屋地址属于项目/房屋事实。

每个可导航地址可以配置：

- 结构化地址
- 地图 POI/楼宇
- 经纬度与坐标系
- 地图供应商
- 导航标识
- 维护人和更新时间

### F. 联系通道

- 企业统一客服电话
- 售后专线
- 门店服务电话（是否对外待裁决）
- 企业微信/服务群入口（如正式支持）

员工个人手机号不作为企业对外联系通道；如需展示，必须另行授权。

### G. 资质与信任证据

- 资质名称
- 资质等级/范围
- 证书编号
- 有效期
- 证书附件
- 企业自填自审状态
- 平台核验状态（未来能力，不默认存在）

平台只承载和展示企业自填内容，不默认背书。

### H. 单据身份

合同、报价、凭证、导出和打印使用 Company 信息的“有效单据投影”或“生成时快照”。

候选字段：

- 法定名称
- 统一社会信用代码
- 法定代表人
- 单据地址
- 企业客服
- 开户行/账号（按单据类型）
- Logo 快照
- 单据模板署名

`DocumentProfile` 不再作为独立企业主档；应作为单据投影/快照实现。

### I. 展示与投影策略

- 面向内部：完整程度最高，但敏感字段按角色裁剪。
- 面向业主：企业品牌、服务信息、联系通道、资质摘要和地图位置。
- 面向合同/交易：法定主体、地址、税号、银行资料和 Logo（按模板）。
- 面向营销：品牌、Logo、简介、服务区域和已授权资质。
- 平台存证署名和叙事主体是策略，不是企业身份事实。

### J. 门店服务身份

门店是企业信息域内的组织与服务位置，不是新的企业主体。

- 门店名称
- 所属企业
- 默认总店/普通门店
- 门店经营地址
- 门店地图点位
- 门店服务电话（待裁决）
- 门店品牌覆盖（待裁决）

没有独立门店品牌结论前，Logo、法定主体和主品牌只来自企业级 Company 信息。

### K. 版本、完整度与快照

- 每个字段记录来源、更新人、更新时间、可见范围。
- 企业信息有展示完整度，但不把“资料百分比”直接当作外部信用评分。
- 关键业务动作生成企业信息快照。
- 历史合同、已发布报价、已生成凭证和归档文件不被当前主档更新回溯覆盖。

## 3. 渐进信任阶段

| 阶段 | 目标 | 最小信息 | 可开展业务 | 不可做 |
| --- | --- | --- | --- | --- |
| L0 快速开通 | 先进入系统 | 企业展示名称；BOSS 账号；自动默认总店 | 建客户、房屋、跟进、内部试用 | 不能把占位信息当成完整法定信息 |
| L1 基础经营 | 能推进日常业务 | 展示名称、简称、基础联系方式（可缺） | 客户、量房、设计、报价草稿、项目准备 | 对外展示可能显示“待完善” |
| L2 服务可见 | 业主能看到服务主体 | 品牌名、Logo/品牌占位、客服或恢复路径、服务区域、简介 | 邀请业主、服务方展示、分享页 | 缺少法定信息仍不能生成正式合同 |
| L3 交易可用 | 能生成正式合同/凭证 | 法定名称、税号、法人、单据地址、必要银行资料、Logo/快照策略 | 合同、报价正式文件、凭证、打印、导出 | 关键字段不能使用占位 |
| L4 信任完善 | 品牌和资质更完整 | 服务质量、资质证据、地图、售后、更多展示资料 | 更强的业主信任展示和营销素材 | 平台不代替企业做资质背书 |

阶段不是一次性强制完成的注册表单，而是由实际业务动作触发补齐。

## 4. 快速入驻设计

### 4.1 入驻最小表单

首屏只要求：

1. 企业展示名称；
2. 企业负责人账号/手机号；
3. 可选：城市、服务电话、Logo；
4. 系统自动创建默认总店。

企业展示名称可以来自注册信息，但如果未确认法定名称，状态标为 `临时/待确认`，不作为合同主体。

### 4.2 入驻后不做“大表单轰炸”

系统以“下一步需要完成什么”而不是“你还有 30 个字段没填”引导：

- 邀请员工前：提示企业展示名称和品牌资料。
- 邀请业主前：提示服务方名称、Logo、客服/恢复路径。
- 打正式报价前：提示报价抬头和可选 Logo。
- 生成合同前：提示法定名称、税号、法人、单据地址。
- 生成凭证前：提示开户行/账号等必要财务资料。
- 需要导航时：提示门店/服务地址和地图点位。

## 5. “我的 → 企业信息”页面设计

### 5.1 页面定位

不是传统资料表单，而是“企业身份工作台”：

```text
企业是谁
→ 哪些信息已经可信可用
→ 哪些信息影响什么业务
→ 下一步补什么
→ 保存后哪些对外表面会更新
```

### 5.2 页面结构

1. **企业身份头部**
   - 企业展示名、品牌 Logo/占位、状态、所属企业、最后更新
   - 当前信任阶段：快速开通 / 基础经营 / 服务可见 / 交易可用 / 信任完善

2. **资料完整度与业务影响**
   - 不用单一百分比制造焦虑
   - 显示“哪些当前可用、哪些影响业主展示、哪些影响合同/凭证”

3. **分组维护**
   - 基础信息
   - 品牌展示
   - 服务与联系
   - 地址与地图
   - 法定与单据
   - 资质与信任
   - 展示与署名
   - 门店服务信息（按数据范围）

4. **字段状态**
   - 未填写
   - 临时占位
   - 已填写待确认
   - 已确认/可对外
   - 已过期/需更新
   - 不适用（需说明）

5. **操作**
   - App：快速补充单个分组、从业务提示直达字段。
   - Web：完整分组编辑、预览业主/合同/PDF 效果、查看影响范围。

### 5.3 保存后的回读

保存企业信息后必须回读：

- 企业信息页当前值；
- 业主端服务方投影；
- 邀请卡片；
- 报价/合同/凭证预览；
- 相关下载/打印模板；
- 企业资料完整度与可用业务。

## 6. 占位策略

### 6.1 占位类型

| 类型 | 含义 | 允许进入正式文件 |
| --- | --- | --- |
| `TEXT_PLACEHOLDER` | “企业名称待完善”“服务地址待确认” | 否 |
| `BRAND_PLACEHOLDER` | 由企业简称生成的中性品牌占位，不使用平台 Logo | 否（对外正式合同/凭证不使用） |
| `HIDDEN_UNTIL_PROVIDED` | 字段不展示，保留补齐入口 | 否 |
| `BLOCK_WITH_ACTION` | 阻断当前动作并引导补齐 | 不适用 |
| `NOT_APPLICABLE` | 业务上不适用，带原因 | 可按业务放行 |

### 6.2 占位不是事实

- 占位值不写入 Company 主档的真实字段。
- 占位值不进入合同主体、金额、税号、银行资料和正式承诺。
- 投影层必须同时返回 `value`、`source`、`status`、`missingReason`、`nextAction`。
- 前端不能把占位直接显示成正式企业名称。

### 6.3 字段级占位示例

| 字段 | 缺省表现 | 是否阻断业务 |
| --- | --- | --- |
| 企业展示名 | 从快速入驻名称显示；未确认则标“待确认” | 阻断正式对外？待裁决 |
| Logo | 中性品牌占位，不使用平台 Logo | 可先开展，不进入正式合同 |
| 品牌色 | 使用系统中性色 | 不阻断 |
| 服务区域 | “服务范围待完善” | 不阻断内部；业主展示提示 |
| 客服电话 | “联系通道待完善”并给维护入口 | 业主正式展示可能阻断 |
| 服务地址 | “服务地址待确认”，不显示地图按钮 | 需要导航时阻断 |
| 法定名称/税号/法人 | “暂不可确认”，不得用展示名替代 | 合同/凭证需要时阻断 |
| 开户行/账号 | “财务资料待完善” | 涉及银行付款/凭证时阻断 |
| 资质 | “资质待补充”，不得写成“无资质” | 不阻断基础经营；对外信任展示受限 |

## 8. 资料状态与完整性

每个字段至少有四种状态：

```text
missing
placeholder
self_declared
confirmed
```

扩展状态：

```text
expired
not_applicable
blocked
```

完整性不能只看“填了几个字段”，而要看：

- 是否满足当前业务阶段；
- 是否可用于业主展示；
- 是否可用于合同；
- 是否可用于财务；
- 是否已有证据；
- 是否已过期；
- 是否有明确恢复路径。

## 9. 业务待裁决

4. 企业办公地址、门店地址、项目地址、房屋地址的字段和地图规则。

6. 客服、售后、税号、法人、开户信息和资质的受众/脱敏。
7. 每个输出表面的品牌字段白名单。
8. “我的 → 企业信息”中 BOSS 与店长的维护边界。

## 10. 2026-10-29 Logo 与品牌色默认规则

### 10.1 企业 Logo

```text
真实 Logo 资产（存在）
→ 优先展示真实资产

真实 Logo 资产（不存在）
→ 企业简称首字占位
→ 简称缺失时暂用企业展示名称首字
→ 标记“默认品牌展示”
```

- 首字占位是投影结果，不写入真实 Logo 资产。
- 正式合同/凭证如要求企业 Logo，不能把首字占位声称成已上传企业 Logo。
- 平台 Logo 与装企 Logo 严格分离。

### 10.2 企业品牌色

```text
企业自定义品牌色（已获批）
→ 使用企业色

企业未自定义
→ 使用装得清品牌主色语义 Token
→ 当前端按平台 Token 解析
```

默认品牌色不写入“已自定义品牌色”事实。后续若允许自定义，必须校验对比度、可访问性和打印颜色。

## 11. 2026-10-29 创建企业快速入驻收敛

按 `USER-DEC-20261029-005`：

- 创建企业首屏只录入负责人姓名和企业展示名称。
- 企业法定全称、地址、Logo、品牌色、服务信息、资质等全部后置到“我的 → 企业信息”。
- 负责人姓名优先使用微信昵称；不额外触发 `getUserProfile`。
- 创建成功后直接进入企业首页，自动建立默认总店。
- 已有在建项目不在创建表单中询问，入驻后从首页业务承接入口处理。
- 企业展示名称可作为临时企业标题，但正式合同/税务/银行凭证生成前必须补齐并确认法定主体信息。

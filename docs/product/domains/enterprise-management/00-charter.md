# 企业管理组织操作与审计跨端闭环 · 业务域章程

- Domain：`enterprise-management`
- Owner：`codex`
- North Star：企业、门店、员工与审计事实在 App/Web/后端同源闭环，组织调整不破坏历史归属和数据权限。
- 关联问题：`PI-20261022-005`

## 1. 业务问题

- 当前场景：BOSS 与店长需要在 App/Web 管理邀请、调岗、调店、停用、恢复、离职与交接。
- 谁遇到问题：成长型装企负责人、店长、被调整员工和企业财务。
- 当前损失/风险：双端能力不对称；跨店与角色提升边界不清；离职可能留下无主责任；审计操作人可能记错。
- 希望达到的结果：在权限范围内形成明确、可审计、可恢复的员工生命周期闭环。

## 2. 目标角色

| 角色 | 主要目标 | 关键动作 | 不负责什么 |
| --- | --- | --- | --- |
| BOSS | 管理全企业组织 | 邀请、调岗、调店、停用、恢复、离职、交接预览 | 不绕过唯一 BOSS 与席位约束 |
| 店长 | 管理本店普通员工 | 邀请本店非店长角色、本店调岗、停用、恢复、离职 | 不跨店、不操作 BOSS/店长/自己 |
| 员工 | 正确进入或退出企业 | App 接受/拒绝邀请、本人退出企业 | 不能管理组织 |
| 财务/普通员工 | 查看本人安全日志 | 本人安全与必要提醒 | 不能查看企业成员审计 |

## 3. 本期范围

- 必须做：邀请、岗位调整、门店调整、停用、恢复、离职及操作审计。
- 暂时不做：订阅 Web、完整审计页面、组织交接影响聚合页面。
- 明确排除：Team/TeamLeader 解冻、平台运营跨企业操作、金额与成本公式变化。

## 4. 主链

```text
管理员选择员工
→ 校验角色/门店/状态/席位/订阅
→ 执行生命周期动作
→ 写成员日志并保留历史归属
→ App/Web 重新读取事实
→ 异常时给出明确错误或强制离职恢复路径
```

## 5. 关键不变量

1. 登录企业、门店和角色只从当前员工加载，不信任前端 `comId/empId/storeId`。
2. Team 与 TeamLeader 冻结，仅保留历史只读事实。
3. 店长只能管理本店非 BOSS、非店长员工；跨店调整仅 BOSS。
4. `Resigned` 是终态；停用/离职立即失去企业访问；历史业务归属不回溯。
5. 成员审计必须记录实际管理员操作人，不得把目标员工写成操作人。

## 6. 金额/成本/权限边界

- 金额：本域不改变金额公式。
- 成本：本域不改变成本或利润口径。
- 权限：BOSS 全企业；店长本店；普通员工本人；TeamLeader 不可访问。
- 跨租户：跨企业对象返回 404/拒绝，不泄露存在性。

## 7. 成功指标

- 产品：App/Web 同一动作状态和错误语义一致。
- 数据质量：组织变更均有成员日志，前后值可追溯。
- 业务结果：离职不产生新的无主责任，历史归属不漂移。
- 安全：停用/离职后立即无法登录或访问企业数据。

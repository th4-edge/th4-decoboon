## 1. 目标与边界

本契约冻结企业管理在 App/Web/后端的对象、状态、动作、权限、异常和审计口径，作为 `EMG-V1~V5` 的实现依据。

覆盖：

- 企业主体、门店、Team 历史兼容；
- 员工、邀请、员工生命周期；
- 角色与数据范围；
- 订阅、席位、门店资源；
- 租户安全与成员审计。

不覆盖：

- 平台运营端跨企业运营；
- 业主端主体确认；
- Web 收银台；
- 审计导出；
- 金额、成本、利润、工资提成和凭证公式；
- `GAP-016` 未冻结的套餐价格和模块权益。

## 2. 对象与状态契约

### 2.1 Team（冻结）

| 项 | 契约 |
| --- | --- |
| 业务状态 | 冻结；不再进入新增/修改/归档/恢复生命周期 |
| 新建 | 禁止 |
| 改名/负责人/成员调整 | 禁止 |
| 新邀请/新员工分配 | 禁止 |
| 岗位/门店调整 | 不维护 Team |
| 数据权限 | 不产生任何数据权限、路由、菜单或 Provider 授权 |
| 历史数据 | 保留 Team 表、字段和历史快照；可只读解释事实 |
| 删除/清空/回填 | 本轮禁止；如需执行另立用户确认的数据任务 |
| TeamLeader | 继续冻结；不可登录、邀请、改岗或授权 |

### 2.2 Employee

```text
Active -> Suspended
Suspended -> Active
Active -> Resigned
Suspended -> Resigned
```

- `Resigned` 为终态，不提供恢复为 `Active`。
- 企业唯一 BOSS 不可停用、离职、改岗或移出企业。
- 停用/离职立即撤销企业数据访问。
- 恢复必须校验其他企业在职状态、Active 门店和企业席位；不校验 Team。
- 岗位/门店调整不自动迁移业务责任。

### 2.3 Invite

```text
Pending -> Accepted
Pending -> Cancelled
Pending -> Expired
Pending -> Rejected
```

- 邀请管理 App/Web 双端完整；接受/拒绝 App-only。
- 新邀请不得携带或写入 Team。
- 过期由服务端按 `expireTime` 判定。
- TeamLeader 不接受；Finance 的目标门店按 `DEC-081`。

### 2.4 Store

```text
Active -> Disabled
Disabled -> Active
```

- 仅 BOSS 可创建、更新、启停门店。
- 默认总店唯一且不可变更。
- 停用前不得存在在职员工或未迁移的在手业务。
- 门店容量按全部 Store 记录计数，包含已停用门店。

## 4. 动作与结果契约

### 4.1 Team 写入拒绝

以下输入必须返回 400 或明确拒绝，且不得落库：

- 新邀请携带 `teamId` 或 `teamName`；
- 成员更新携带 `teamId`；
- 接受邀请后产生新的 Team 归属；
- 任何 Team 新建/更新/归档接口被调用。

Team 历史字段允许只读返回，但不得进入活跃筛选、管理、经营入口或权限判断。

### 4.2 员工生命周期

| 动作 | 幂等要求 | 审计 |
| --- | --- | --- |
| 邀请 | 同企业同手机号存在 Pending 时返回既有邀请或明确重复提示 | 成员日志：邀请创建/取消 |
| 调岗 | 同目标重复提交不新增日志 | 成员日志：角色调整，前后值 |
| 调店 | 同目标重复提交不新增日志 | 成员日志：门店调整；跨店仅 BOSS |
| 停用 | 已停用返回明确状态错误 | 成员日志：停用 |
| 恢复 | 已 Active 返回明确状态错误 | 成员日志：恢复；校验席位 |
| 离职 | 已 Resigned 返回明确状态错误 | 成员日志：离职，原因与影响快照 |
| 交接 | 相同幂等键不重复转移 | 成员日志：交接，接收人、对象数量、前后责任 |

### 4.3 交接对象

默认影响预览：

- 客户；
- 房屋；
- 报价；
- 项目；
- 未完成任务；
- 应收。

显式交接：

| 对象 | 处理 |
| --- | --- |
| Customer | `owner` 转接收人；当前 `store` 同步接收人 |
| Property | `owner` 转接收人；当前 `store` 同步接收人 |
| Project | 勾选转移项目时 `manager` 转接收人；项目历史 store/Team 不变 |
| ProjectTask | 勾选转移项目时，未完成任务 `owner` 转接收人 |
| Quote | 不修改 `createdBy`；通过客户/项目范围继承可见性 |
| Receivable/Payable/Receipt/Payment/Voucher | 不修改历史操作人和金额；通过项目范围继承可见性 |
| Team/历史 Team 快照 | 一律不更新 |
| Notice | 历史通知不重写；新责任提醒发接收人 |

### 4.4 订阅与席位

统一服务端计算：

```text
usedSeats = count(Employee.status == Active)
          + count(Invite.status == Pending && invite.expireTime > now)

usedStores = count(Store)  // 包含默认总店和 Disabled 门店
```

规则：

- 仅 BOSS 可访问订阅、套餐、加购和订单 Provider。
- Web 提供查看、容量、订单历史和查单；本轮不新增 Web 支付。
- Web 创建待支付订单后引导 App 支付；App/Web 同订单号、同状态、同恢复路径。
- `GAP-016` 关闭前，新购/升级/降级/加购禁用，既有待支付订单可继续完成或取消。
- 订阅过期/冻结/关闭时只读，并显示续费或联系路径。

### 4.5 审计

数据来源：

- `UserSecurityLog`：登录、退出、邀请接受/拒绝、加入/退出、风控、门店启停；
- `CompanyMemberLog`：邀请管理、加入、角色/门店调整、停用、恢复、离职、交接。

可见范围：

| 角色 | 安全日志 | 成员变更日志 |
| --- | --- | --- |
| BOSS | 全企业 | 全企业 |
| 店长 | 本人 | 本店 |
| 财务/普通员工 | 本人 | 不可见 |
| TeamLeader | 不可访问 | 不可访问 |

展示字段：

- 时间、动作、结果、操作人、对象员工、原因；
- 前后角色、门店、状态；
- 脱敏手机号和 IP；
- 终端摘要；
- 不返回 `openId`、`unionId` 或身份密钥。

P0：

- Web 完整分页、筛选、脱敏；
- App 最近 20 条只读摘要；
- 不导出；
- 不自动删除；
- 不新增通用租户 OperationLog。

## 6. Provider 与错误语义

Provider 能力：

- `user/team/list`：仅保留历史只读兼容；无 Team 写 Provider。
- `user/store/{list,save,update,status}`
- `company/member/{page,info,update,suspend,resume,resign,transfer,handover}`
- `invite/invitation/{page,info,save,cancel,accept,reject}`
- `subscription/info`
- `plan/list`、`addon/list`
- `order/{create,prepay,info,page}`
- `security/security/log/page`
- `company/member/log/page`

统一错误：

- 403：角色、企业或门店范围不允许；
- 404：跨企业对象或不存在对象，避免泄露；
- 400：状态、门店、Team 冻结写入或参数不合法；
- 409：并发冲突或未完成交接；
- `SUBSCRIPTION_EXPIRED`：只读状态；
- 容量不足：明确“席位不足/门店额度不足”，不得用空数组或 0 替代；
- 部分加载失败：显示“暂不可确认”并提供重试。

## 7. 迁移与回滚边界

- Team 冻结不新增状态字段，不执行 Team 数据迁移。
- 历史 Team 数据不删除、不清空、不猜测回填。
- 无 DDL 切片仍必须有代码回退和权限回归。
- 如未来需要清理历史 Team，另立用户确认的数据迁移任务。

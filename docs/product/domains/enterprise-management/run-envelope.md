# 企业管理业务域 · 运行边界

- Domain：`enterprise-management`
- Owner：`codex`
- 当前批次：`EMG-V2`
- 当前阶段：`DEV_VERIFIED`
- 权限来源：用户已裁决 `DEC-085` / `EV-353` 与既有 `DEC-081` / `DEC-070`

## 1. 本域允许自主执行

- 按冻结契约完成单个垂直切片；
- 修改该切片直接相关的后端、App、Web 和测试；
- 运行定向测试、编译、类型检查、构建和本地运行态验证；
- 生成验收证据、交接记录和状态回填；
- 在无 DDL、无生产数据、无发布的前提下清理本地验收环境。

## 2. 人工门禁

以下事项必须停止并交用户确认：

- `Team` / `TeamLeader` 解冻或恢复任何写入口；
- 新增角色、权限放大、跨租户范围变化；
- DDL、迁移、生产数据修改或删除；
- 金额、成本、利润、支付或订阅计价语义变化；
- 生产发布、小程序正式版提审或发布；
- 将开发自测写成独立验收 `PASS`。

## 3. 批次队列

```text
EMG-V1 Team 冻结收口（已独立验收 PASS）
→ EMG-V2 员工生命周期（当前）
→ EMG-V3 组织影响与交接
→ EMG-V4 订阅 Web
→ EMG-V5 审计
→ EMG-V6 独立验收
```

## 4. 质量门禁

- 业务规则引用 `DEC-085`、`EV-353`、`DEC-081`、`DEC-070`；
- 后端定向测试与编译通过；
- App 类型检查、微信小程序构建、导航契约通过；
- Web 构建、权限与工作台门禁通过；
- 真实 App/Web 运行态证据存在；
- 对账矩阵没有本批 `UNMAPPED` / `STALE`；
- 开发结论最多为 `DEV_VERIFIED_PENDING_ACCEPTANCE`。

## 5. 返回包

每批返回必须包含：改动事实、未改事实、业务依据、验证证据、开放风险、对账结果、独立验收门禁和下一动作。

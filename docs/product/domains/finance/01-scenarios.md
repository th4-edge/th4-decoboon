# 财务经营与项目核算 · 真实业务场景

> 目标企业：10–30 人、1–3 店的成长型家装企业；总部财务与门店财务均可能存在。
> 状态：产品场景草案，用于业务对齐；不代表现有功能已验收。
> 每个场景均按“使用人 → 触发事件 → 当前动作 → 系统下一步 → 异常恢复 → 结果回读”闭环描述。

## 场景 A：总部财务早上判断“今天先处理哪三笔钱”

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 总部财务，Company 数据范围，可查看全部门店并按门店下钻 |
| 触发事件 | 早上打开财务经营台，需要判断现金安全、回款风险和付款优先级 |
| 前置条件 | 有真实合同、应收、应付、资金流水、项目成本和门户范围；数据截止时间可确认 |
| 当前动作 | 先看现金余额与近期资金缺口，再看待收逾期、待到付、成本不完整项目和异常流水；点击一条事项进入对应对象 |
| 系统下一步 | 首屏给出结论带：现金是否可覆盖近期付款、最大逾期对象、最影响利润的项目；按“回款 / 付款 / 成本缺口 / 对账异常”分组待办；每条事项显示金额、到期日、责任人、来源对象和下一步 |
| 成功结果 | 财务选择唯一主行动，例如进入某项目登记收款、调整付款顺序、催办成本补齐或处理异常流水；完成后回读台账、往来和项目状态 |
| 异常/恢复 | 汇总接口失败时保留上次成功数据并标“暂不可确认/数据截止时间”；部分门店失败时逐块标红并提供重试；成本不完整时显示“成本未完整”，不显示 0 利润；无某项数据时显示真实空态 |
| 涉及对象 | `Project`、`Receivable`、`Receipt`、`Payable`、`Payment`、`Ledger`、`ProjectCostContext`、`Risk` |
| 状态变化 | 本场景本身不强行改状态；后续动作按对应对象状态机推进 |
| 金额/成本/权限 | 所有金额来自服务端；总部财务可看全企业，门店下钻受服务端校验；高危动作按权限裁剪 |
| 证据/来源 | `SCN-015`、`SCN-016`、`BR-030`、`DEC-065`、`MET-002`、`MET-006` |

### 场景 A 任务链

```text
总部财务
→ 判断现金与经营风险
→ 经营台结论带 + 待办队列
→ 选择一笔逾期应收/到期应付/成本缺口
→ 进入项目或往来对象
→ 执行当前唯一主行动
→ 回读资金台账、往来余额、项目成本
→ 下一责任人接手或财务继续处理下一笔
```

## 场景 B：客户合同节点到期未回款，财务推动回款并处理异常

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 总部财务或门店财务；门店财务仅本店 |
| 触发事件 | 合同付款节点到期，应收未收清；项目仍在履约中 |
| 前置条件 | 合同已生效，应收节点有来源、金额、到期日；项目归属可确认 |
| 当前动作 | 在“回款队列”打开项目/客户对象，核对应收节点、已收、逾期天数、合同付款计划和项目当前阶段；联系客户后登记收款 |
| 系统下一步 | 收款保存时服务端校验来源、余额、门店和幂等；成功后核销应收、写唯一资金流水、生成业务凭证预览；回读应收状态、项目回款和资金台账 |
| 成功结果 | 应收变为部分收款或已收清，项目回款更新，凭证可打印归档；如已收清则提示财务下一步：结算准备/成本完整性检查/交接项目经理 |
| 异常/恢复 | 客户实际金额与应收不一致时不允许前端硬改余额，提示拆分、调整或走退款/冲正；重复提交返回原结果或 409；跨店/跨企业拒绝；高额或异常收款进入安全门；接口失败保留输入并可重试 |
| 涉及对象 | `ProjectContract`、`Receivable`、`Receipt`、`Ledger`、`Voucher`、`Customer`、`Project` |
| 状态变化 | `Receivable: Pending/Overdue → Partial/Received`；`Receipt: Active`；`Ledger: Income` 追加 |
| 金额/成本/权限 | 收款金额不得超过应收余额；收款≠收入；门店财务不可跨店；冲正权限不由财务自动获得；凭证金额等于收款事实 |
| 证据/来源 | `SCN-005`、`SCN-008`、`SCN-015`、`BR-050`、`BR-055`、`DEC-077`、`DEC-089` |

### 场景 B 任务链

```text
合同节点到期
→ 应收未收清
→ 财务进入客户/项目回款对象
→ 核对合同、应收、项目状态
→ 登记收款
→ 核销应收 + 资金流水 + 凭证
→ 回读项目回款与应收状态
→ 收清后交接结算准备或继续催收
```

## 场景 C：项目结算前发现成本不完整，财务组织补齐并形成项目经营结论

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 总部财务/门店财务/店长；成本敏感字段按范围可见 |
| 触发事件 | 项目进入结算准备，或者项目毛利异常、成本不完整 |
| 前置条件 | 项目存在，合同收入可确认；预计/动态/最终成本三态由服务端返回 |
| 当前动作 | 在项目核算工作面查看成本缺口来源：报价成本快照、采购到货、材料结算、人工、费用、工资归集、变更影响；按来源责任分别发起补齐 |
| 系统下一步 | 显示成本完整度、每个缺失项的来源、责任人、影响金额和下一步；成本不完整时利润/毛利率为空；补齐后重新计算三态成本并展示新旧差异 |
| 成功结果 | 成本完整度达到可结算条件，财务确认结算；形成收入、成本、利润和质保金快照；写入转账/凭证/档案并交接负责人 |
| 异常/恢复 | 历史结算已确认时不允许回写，必须新版本或调整事实；采购价不能被当作最终成本；付款不能被当作成本；缺失任何应计成本时阻断“确定利润”；接口失败显示“暂不可确认” |
| 涉及对象 | `ProjectContract`、`ContractChange`、`PurchaseOrder`、`GoodsReceipt`、`MaterialSettlement`、`Payable`、`Payroll`、`Expense`、`ProjectCostContext`、`Settlement` |
| 状态变化 | `ProjectCostContext.costComplete` 由 false → true（仅在事实补齐后）；`Settlement: Draft → Confirmed → Closed/RetentionPending` |
| 金额/成本/权限 | 预计成本取签约快照；动态成本取当前应发生事实；最终成本取结算确认；企业费用不进入项目毛利；门店财务和店长仅本店可见 |
| 证据/来源 | `MET-002`、`BR-058`、`DEC-016`、`DEC-092`、`GAP-003`、`GAP-071` |

### 场景 C 任务链

```text
项目进入结算准备
→ 财务发现成本不完整
→ 查看缺失项/责任人/影响
→ 业务责任补齐材料、人工、费用或变更事实
→ 服务端重新计算三态成本
→ 财务确认结算
→ 固化利润快照
→ 交接负责人/项目经理并归档凭证
```

## 场景 D：财务完成主材下单与结算，但不能把采购价、付款当成本

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 财务（材料员与财务同一角色），本店/企业范围按门店归属 |
| 触发事件 | 设计师已交付选材；材料计划进入 `ReadyToOrder`；供应商与价格待财务确认 |
| 前置条件 | 材料计划、选材结果、合同范围、客户确认和供应商主数据可确认；来源对象可访问 |
| 当前动作 | 在材料下单工作面选择供应商、确认价格/数量/交期，生成采购/应付；材料到场后按结算规则确认实际材料成本；异常退换货进入冲减 |
| 系统下一步 | 下单形成应付而非直接成本；无价下单形成暂估应付；到场/结算后更新实际成本；付款只核销应付和写资金流水，不重复计成本；结算后重新计算项目成本完整性 |
| 成功结果 | 供应商应付、采购到货、结算成本、付款流水和项目成本可追溯；项目成本完整性提高；供应商往来可核对 |
| 异常/恢复 | 供应商缺失禁止自由文本建单；无价/价格异常必须显式暂估并后补；退换货必须冲减原事实；跨店材料/应付拒绝；付款超应付拒绝；接口失败保留已选对象和输入 |
| 涉及对象 | `MaterialPlan`、`MaterialSelection`、`MaterialOrderSheet`、`PurchaseOrder`、`GoodsReceipt`、`MaterialSettlement`、`Payable`、`Payment`、`Partner`、`MaterialSupplier`、`ProjectCostContext` |
| 状态变化 | `MaterialPlan/Sheet` 按既有状态机推进；`Payable: Pending/Partial/Paid`；实际成本按到场/结算事实更新 |
| 金额/成本/权限 | 供应商与价格由财务决定；采购价是应付口径，不等于最终成本；实际材料成本只在到场/结算累计；财务可维护供应商主数据但需审计 |
| 证据/来源 | `DEC-008`、`DEC-073`、`DEC-074`、`DEC-084`、`BR-009`、`BR-045`、`BR-054`、`SCN-005` |

## 场景 E：门店财务月度核对费用、薪酬与资金，向总部财务交接经营异常

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 门店财务；总部财务按需查看全企业；店长只读本店薪酬构成 |
| 触发事件 | 月末关账前，需要核对费用报销、工资/提成发放、资金流水和项目成本；发现无法归属或异常事项 |
| 前置条件 | 费用审批、工资单状态、发放记录、资金台账和门店范围可确认 |
| 当前动作 | 进入“费用与薪酬”工作面，按状态处理待审批/待付款/待发放事项；核对工资条可见性、提成负数调整、费用项目/企业归属和重复付款 |
| 系统下一步 | 费用批准后形成唯一费用事实；工资单由 BOSS 最终确认后财务可发放；发放只核销应付并写流水；负向提成进入下期工资单抵扣；无法归属的费用进入待确认，不猜测项目/门店 |
| 成功结果 | 月末费用、薪酬和资金流水闭环；工资发放完成才生成员工可见工资条；总部财务只看到可解释的差异和待决策问题 |
| 异常/恢复 | 未确认工资单不可发放；已发放不得反改，只能下期调整；门店财务不能跨店；店长不能确认/作废/发放；接口失败保留筛选和输入；真实空态与失败态区分 |
| 涉及对象 | `Expense`、`ExpenseCategory`、`ExpenseAttachment`、`PayrollSheet`、`PayrollItem`、`CommissionAdjustment`、`Payable`、`Payment`、`Payslip`、`Ledger` |
| 状态变化 | `Expense: Submitted → Approved/Returned`；`PayrollSheet: Draft/Pending → Confirmed → Paid`；`Payslip: pendingPayment → published` |
| 金额/成本/权限 | 费用归属唯一；工资确认/作废/退回仅 BOSS；财务复核/发放；店长只读薪酬构成；成本不完整不得确认利润 |
| 证据/来源 | `BR-015`、`BR-038`、`BR-039`、`BR-057`、`DEC-091`、`DEC-093` |

## 场景 F：财务通过客户与报价经营支持业务开展，但不复制业务域页面

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 总部财务/门店财务（按 DEC-079/080 拥有客户经营和报价项目库维护权限） |
| 触发事件 | 业务员或设计师提交客户、报价项目库维护需求；需要核对客户回款风险、报价成本和合同付款计划 |
| 前置条件 | 财务有当前企业/门店客户经营权限；报价项目库维护权限按 DEC-079；财务可见成本但不得改正式报价规则 |
| 当前动作 | 从财务经营台或共享客户对象进入客户经营页；进入报价项目库维护标准成本；在报价/合同对象查看财务投影（付款计划、应收、成本完整性） |
| 系统下一步 | 客户、报价、合同仍由各自领域工作面承载；财务配置的能力只改变动作权限和字段投影，不生成 `/finance/customers`、`/finance/quotes` 的第二套业务页面 |
| 成功结果 | 财务完成客户维护、报价项目库维护、合同付款计划核对和回款风险标记；设计师/业务员继续使用同一客户/报价对象 |
| 异常/恢复 | 财务不能做客户物理删除、企业治理、报价规则变更或合同客户确认；跨店拒绝；接口失败显示原业务页面错误态；成本字段按权限裁剪 |
| 涉及对象 | `Customer`、`Property`、`Quote`、`QuoteLine`、`ProjectContract`、`ContractPaymentPlan`、`CatalogItem` |
| 状态变化 | 按客户、报价、合同各自既有状态机；财务不改写客户/报价状态机 |
| 金额/成本/权限 | 财务可维护标准成本和客户经营；不替代设计师报价；合同金额、应收计划和成本快照按事实来源 |
| 证据/来源 | `DEC-079`、`DEC-080`、`DEC-084`、`BR-052`、`DEC-086` |

## 反向场景

| 场景 | 预期结果 |
| --- | --- |
| 门店财务请求跨店项目或全企业合计 | 403/404，不返回空数组伪装 |
| 财务执行收款冲正、手工流水作废/更正/冲正重记 | 拒绝；仅 BOSS 全企业、店长本店 |
| 店长确认、作废、退回重算工资单 | 拒绝；仅 BOSS |
| 店长或门店财务发放他店工资 | 拒绝 |
| 同一应收/应付/收款/付款重复提交 | 服务端幂等返回原结果或 409，不重复记账 |
| 用付款代替成本、用收款代替收入、用采购价代替最终材料成本 | 业务口径错误，页面不得暗示为确定事实 |
| 成本不完整时显示 0 利润或伪毛利率 | 验收失败 |
| 发票附件被当成开票完成/发票管理 | 验收失败；只允许附件/号码元数据，具体按业务裁决 |
| 手工登记合同节点应收、材料/工资应付 | 拒绝，必须走来源单据 |
| 财务从 `/finance/quotes`、`/finance/material-ordering` 维护第二套业务对象 | 架构/对账失败；应复用原业务域页面 |
| 接口失败显示空列表、0 金额或旧余额 | 验收失败，显示“暂不可确认”及恢复路径 |
| 已确认/已关闭结算被无痕回写 | 拒绝；生成新版本或调整事实 |

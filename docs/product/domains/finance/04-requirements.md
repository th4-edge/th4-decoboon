## 2. 非功能要求

### 2.1 性能

- 财务经营台/列表/账本接口必须使用服务端分页和聚合 SQL；
- 首屏并发 P95 目标 ≤500ms（在真实数据规模和测量前提下）；未测量不得先优化；
- 列表/账本不得全量加载实体后 Java 循环求和；
- 10× 数据量下 SQL 条数不得增长；
- 响应体按角色和页面裁剪，最小字段白名单，避免把实体全图带入列表。

### 2.2 数据可信

- 所有派生金额带 `asOf`、范围、口径版本和数据完整性；
- 成本不完整、账龄待确认、历史门店为空、接口失败必须显式；
- 不使用缓存旧值伪装最新事实；
- 历史快照不可被当前主数据回写。

### 2.3 安全与审计

- 跨租户、跨店、越权返回 403/404；
- 高危动作必须有二次确认、原因、影响预览、幂等键和审计；
- 财务页面不能通过深链、导出或选择器绕过数据范围；
- 金额/成本敏感字段由服务端裁剪。

### 2.4 可访问性与交互

- 可键盘完成主链；
- 焦点可见并正确归还；
- 状态同时使用文字、颜色和图标/形状；
- 动效只用于状态/空间连续性，不循环装饰；
- 触控目标 ≥24×24px；
- 支持 `prefers-reduced-motion`。

### 2.5 跨端一致性

- App/Web/Admin 如果出现同一能力，必须同一 Provider、同状态、同金额、同权限、同错误和同回读；
- Web 专属差异只允许批量、对比、键盘、打印、密度和导出；
- App 专属差异只允许现场拍照、扫码、移动审批、快速登记等端侧能力。

## 4. 明确不做

- 不生成 `/finance/*` 下的客户、报价、合同、项目、材料、薪酬第二套 CRUD/详情页；
- 本轮不修改后端 Java 业务逻辑、Provider、实体、状态机、权限、金额/成本/利润或 DDL；
- 不新建财务壳层，不删除、重命名或替换现有菜单、路由和深链；
- 不新增财务专属同义 Provider；
- 不新增或改名财务业务状态；
- 不在未冻结前显示公司/门店经营利润确定金额；
- 不做发票管理、税务、法定会计、完整 HR；
- 不以指标卡、图表墙或菜单卡片替代财务判断和行动；
- 不把开发自测、构建通过或接口 200 当作 UI/业务验收。

# FM-02「客户」菜单首轮验收记录

- 日期：2026-10-29
- 验收角色：总部财务（Finance，默认总店，Company 数据范围）
- 页面：`/workbench/customers`
- 当前组件：`src/views/workbench/StoreCustomerView.vue`
- 实际浏览器：Web `127.0.0.1:8081`，真实 Finance 登录态
- 本轮边界：只读验收 + 本地真实路由守卫验证；未修改后端、页面、权限或业务数据
- 验收结论：`BUG`，并伴随页面模型 `OPTIMIZE`

## 1. 用户提出的产品事实

用户期望：

> 财务点击「客户」进入的应是和设计师相同的客户对象工作面，只是角色投影不同。

该判断与客户域对象模型一致：

- 客户是同一个 `Customer`；
- 房屋是同一组 `Property`；
- 跟进、诉求、阶段、负责人、设计师是同一组事实；
- 财务、设计师、BOSS、店长为不同角色；
- 角色差异应体现在数据范围、默认筛选、字段裁剪、主行动和回读，不应复制第二个客户对象页。

## 2. 当前代码事实

| 维度 | 财务 | 设计师 | 结论 |
| --- | --- | --- | --- |
| 菜单路由 | `/workbench/customers` | `/designer/customers` | 两个路由 |
| 页面组件 | `StoreCustomerView.vue` | `DesignerCustomersView.vue` | 不是同一工作面 |
| 页面形态 | 顶部标题 + 搜索 + 客户表格 + 行操作 | 左侧客户/房屋队列 + 中间客户房屋工作面 + 右侧状态动作 | 交互模型不同 |
| 列表数据 | `customer/customer/page` | `customer/customer/page` + 设计任务聚合 | 部分共用 Provider |
| 客户详情 | 当前页无完整客户对象工作面 | 选中客户后加载客户、房屋、跟进、方案 | 财务缺少对象连续工作面 |
| 财务动作 | 转交负责人、指派设计师、标记/恢复流失 | 跟进、安排量房、客户诉求、设计方案、完整档案等 | 能力被拆在两套页面 |
| 角色投影 | 顶部按 Company/Store 切换“全部客户/本店客户” | 默认是“待我设计/本店设计方案” | 投影规则不同且不完整 |

## 3. 已确认的明确缺陷

### FM-02-BUG-01：财务「查看方案」进入无权访问

`StoreCustomerView.vue` 的 `openDesign` 固定跳转：

```text
/designer/customers?customerId=...
```

但 Finance 的路由集合只装载：

```text
workbenchArea(L.wbStoreCustomers, ...)
designerArea(L.dsCatalog)
```

没有装载 `designer/customers`。

真实浏览器验证：

```text
Finance -> /designer/customers
-> /forbidden
-> “无权访问该页面”
```

因此当前财务客户列表的“查看方案”是一个明确死路。

### FM-02-BUG-02：总部财务页面标题投影不一致

真实浏览器中，总部财务（全公司范围）页面同时出现：

- 浏览器标题：`本店客户 | 昭青装饰`
- 面包屑：`财务工作台 / 本店客户`
- 页面 H1：`全部客户 全部门店`
- 页眉说明：按门店维度查看全企业客户

同一页面存在“本店客户”和“全部客户”两套语义，说明路由 meta 与页面角色投影没有统一。

### FM-02-OPT-01：财务客户页面缺少对象连续工作面

当前财务页面是表格 + 行操作：

- 只能看到客户、阶段、负责人、设计师、预算；
- 没有客户/房屋对象上下文；
- 没有客户 360、跟进记录、诉求、方案和历史关联；
- 没有完整客户档案入口；
- 客户操作被割裂为行内弹窗。

设计师页面已经具备客户、房屋、方案、跟进和诉求的对象工作面结构。财务不应再维护一套简化表格作为主工作面。

### FM-02-OPT-02：DEC-080 的财务客户能力未被同一页面完整承接

当前财务入口主要承接：

- 转交负责人；
- 指派设计师；
- 标记/恢复流失；
- 查客户基础表格。

DEC-080 已确认财务与 BOSS/店长对齐的能力还包括：

- 客户查看、新增/编辑；
- 跟进；
- 记录微信/到店；
- 预约量房；
- 批量录入；
- 休眠/恢复；
- 客户画像与标签维护。

这些能力没有在同一个财务客户工作面形成连续入口，部分依赖其他路由或不可达页面。

## 4. 正确升级方向

### 4.1 不是新建第二个客户页面

不新增 `/finance/customers`，也不新建一套财务专用客户组件。

### 4.2 保留现有路由与菜单

- 财务菜单继续保留「客户」和现有 `/workbench/customers` 深链；
- 设计师继续保留 `/designer/customers`；
- 两个路由最终挂载同一个客户对象工作面组件，仅按角色做投影。

### 4.3 角色投影内容

| 投影维度 | 设计师投影 | 财务投影 |
| --- | --- | --- |
| 默认队列 | 待我设计 / 本店设计方案 | 负责范围内的全部客户，按风险/待跟进/签约/项目状态筛选 |
| 对象上下文 | 客户 + 房屋 + 方案 + 量房 + 诉求 | 客户 + 房屋 + 当前阶段 + 负责人/设计师 + 跟进 + 关联项目/合同/报价摘要 |
| 默认主行动 | 推进设计、量房、方案 | 跟进、维护客户、转交、指派、查看项目与回款风险 |
| 只读/隐藏 | 财务成本、利润 | 设计编辑、方案编辑中不属于财务职责的专业动作 |
| 数据范围 | Self/Store 按既有权限 | 总部财务 Company；门店财务 Store |
| 术语 | 待我设计、方案报价 | 客户经营、客户风险、回款风险、项目关联 |

### 4.4 兼容要求

- 保留现有 `customerId` / `activeCustomerId` 深链；
- 保留当前财务客户菜单路径；
- 保留现有客户、房屋、跟进、转交、指派、流失等 Provider；
- 不新增后端接口；
- 不改变客户、房屋、项目、合同状态机；
- 先做页面组件复用和角色投影，不先做视觉换肤。

## 2. 验收单位

### 2.1 入口级验收

以财务用户实际能看见的入口为验收单位：

1. 底部 Tab；
2. 财务首页；
3. 财务首页快捷入口；
4. 从项目/材料/客户等 Tab 进入的财务相关动作。

### 2.2 任务链验收

每个入口都要按真实任务链验收：

```text
入口
→ 当前页面
→ 必要对象选择/编辑页
→ 提交/保存/确认
→ 反馈
→ 回读上级列表或对象
→ 返回路径
```

例如“登记收款”不是只验收 `entry.vue`，而是验收：

```text
财务首页 → 登记收款
→ 选择项目
→ 选择应收节点
→ 填写金额/账户/日期
→ 保存
→ 回到收款记录/财务首页
→ 回读应收余额、收款记录、资金台账
```

## 3. 验收结论口径

| 结论 | 含义 | 本阶段允许的处理 |
| --- | --- | --- |
| `PENDING` | 尚未按真实财务角色和设备验收 | 继续验收 |
| `PASS` | 当前入口和任务链可完成，保留 | 不做无意义改动 |
| `OPTIMIZE` | 业务正确，但移动端信息层级、文案、触控、反馈或状态表达需原位优化 | 最小前端优化 |
| `BUG` | 当前实现与已确认业务事实/契约不一致 | 登记缺陷，是否修复另行确认 |
| `APP_GAP` | App 缺少某个已确认业务能力，是否需要在移动端承载待确认 | 登记，不直接新建页面 |
| `BACKEND_GAP` | 需要 Provider、状态、权限、金额/成本/利润或后端逻辑调整 | 只登记，本阶段不改 |
| `OUT_OF_SCOPE` | 属于 Web 深度能力或非财务移动端主责 | 记录边界，不在 App 强行补齐 |
| `BLOCKED` | 缺真实账号、数据、权限、设备或业务裁决 | 记录恢复路径 |

## 7. 小程序端验收重点

App 与 Web 同源，但移动端验收不从“功能一样多”出发，而从真实移动场景出发：

### 7.1 必须成立

- 单手完成高频收付款、费用提交、审批和回读；
- 项目、应收、应付、供应商等对象选择不默认第一条；
- 失败保留输入，不因网络失败丢金额、图片或备注；
- 提交中不可重复点击；
- 成功后明确回到哪里、更新了哪个余额/状态/台账；
- 返回后保留来源列表、筛选和对象上下文；
- 底部安全区、键盘遮挡、长列表、大金额、长名称和空数据可处理；
- 图片/相册/拍照只用于当前业务证据，不伪造事实；
- 正式数据缺失显示“暂不可确认”，不用 0 或空数组伪装。

### 7.2 不强行复制 Web

以下能力优先由 Web 承载，App 不因“Web 有”就新增页面：

- 大规模筛选与批量对账；
- 多列并排比较；
- 批量凭证/批量打印；
- 复杂模板编辑；
- 深度的跨项目、跨门店经营分析；
- 长表单的完整字段编辑。

App 发现这些需求时，先判断是否属于 `OUT_OF_SCOPE`、`APP_GAP`，由用户决定是否纳入后续移动端范围，不在本次验收中直接新建。

## 8. 入口验收最低证据

| 维度 | 证据 |
| --- | --- |
| Tab/入口 | 当前角色可见性、入口路径、返回路径 |
| 真实任务 | 从入口到任务完成、反馈、回读和交接 |
| 真实数据 | 当前测试企业/门店/角色/Provider 返回 |
| 七态 | 正常、加载、空、失败、无权限、长内容、极端值 |
| 表单 | 必填、金额、日期、对象选择、附件、失败保留 |
| 权限 | 本店/全企业、跨店、跨租户、财务/BOSS/店长差异 |
| 一致性 | App/Web 同 Provider、同状态、同金额、同权限、同错误 |
| 设备 | 目标微信开发者工具/真机尺寸、安全区、键盘、滚动 |
| 视觉 | 真实截图；视觉桥预检 + 人工/更强视觉模型复核 |
| 交互 | 主行动、点击反馈、提交中、重复提交、返回、深链 |

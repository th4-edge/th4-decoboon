# 客户页面业务能力清单 v0.1

- 日期：2026-10-29
- 状态：`DRAFT_FOR_RULE_REVIEW`
- 目标：先冻结客户页面必须具备的业务能力，再讨论页面结构和视觉设计
- 定位：客户页面不是“待我设计”页，也不是客户 CRUD 页，而是**全员客户查询 + 客户业务关系入口 + 角色动作投影 + 内部协同锚点**
- 约束：不调整后端逻辑；本清单中的“能力”不等于当前已有页面；能力落地必须复用现有 Provider，缺口单独登记

## 1. 客户页面的第一性定位

客户页面要同时承担三件事：

```text
1. 所有内部角色都能查询客户
2. 查到一个客户后，能看清该客户当前发生了什么
3. 根据当前角色、数据范围、客户关系和业务状态，进入下一步动作或查看协同信息
```

可用公式表示：

```text
客户页面
=
全员客户查询
+ 客户主档
+ 多房屋关系
+ 客户业务链
+ 当前角色动作投影
+ 内部协同与交接
+ 数据可信与状态恢复
```

客户是装企内部围绕同一个家庭/决策主体进行信息同频、业务协同和下一步交接的统一业务锚点。

## 2. 客户页面与角色任务页面的边界

### 2.1 客户页面应承载

- 客户查询与识别；
- 客户主档；
- 客户与房屋关系；
- 跟进、微信、到店、休眠、流失等客户生命周期事实；
- 客户关联的设计、报价、合同、项目、验收、付款等业务链摘要；
- 当前用户对客户的业务关系；
- 当前用户可执行的客户动作；
- 当前主行动、阻断原因和下一责任人；
- 客户协作时间线与交接信息。

### 2.2 客户页面不应承载

- `待我设计`、`待我跟进`、`待我签约`等角色队列本身；
- 设计方案编辑器；
- 报价编辑器；
- 合同编辑器；
- 项目工地执行工作台；
- 财务收付款、凭证、结算操作台；
- 验收整改工作台。

这些页面是客户业务链的**关联目的地**，不是客户页面本体。客户页面可以展示摘要、状态、责任人和入口，但不能复制它们的专业工作面。

## 3. 两个参考面的职责

### 3.1 小程序企业负责人客户 Tab

参考价值：

1. 全员可见的客户查询入口；
2. 按客户阶段、跟进状态、负责人、门店范围筛选；
3. 客户卡片同时展示身份、阶段、负责人、设计师、风险、最近/下次跟进、当前业务金额、项目和下一步；
4. 负责人分组让管理者从“人”的维度查看客户经营；
5. 搜索结果直接进入客户详情。

不直接复制的部分：

- Boss 的统计分析和负责人分组属于企业负责人角色投影，不应原样复制给所有角色；店长应有同口径的本店统计和本店负责人分组。
- `我的客户`、`本店客户`、`全部客户` 的角色语义必须通过投影解决，不能每个角色重写一套；
- 客户卡片不能代替客户业务链工作面。

### 3.2 Web 设计师客户与设计页面

参考价值：

1. 客户 → 房屋 → 当前业务对象的连续性；
2. 一个客户可有多套房屋，房屋可切换；
3. URL 保留 `customerId + activePropertyId + schemeId` 等对象锚点；
4. 动作围绕当前选中对象，而非围绕整页；
5. 筛选、选择、刷新后保持上下文；
6. 右侧动作与当前状态关联，不是通用按钮堆。

不直接复制的部分：

- “待设计房屋”是设计任务队列，不是客户主页面；
- 设计方案创建与设计分项是设计专业工作台，不是客户操作；
- 财务、项目经理、业务员不应默认进入设计任务队列。

### 3.3 Web 客户 360

参考价值：

1. 客户身份条、阶段、负责人、设计师、画像、流失和档案信息；
2. 多房屋卡片与“当前房屋”切换；
3. 房屋关联页签：诉求、方案、报价、合同、项目、量房、付款；
4. 付款信息按权限裁剪，设计师只能看合同付款条款或提示不可确认；
5. 跟进时间轴；
6. 当前主行动和业务状态引导。

不直接复制的部分：

- 客户 360 当前偏设计师查看，需补充财务、项目经理、业务员的角色投影；
- 不能在客户页面直接编辑所有关联业务对象；
- 需要将“查看关联业务”和“执行当前角色动作”分开。

## 5. 角色投影原则

### 5.1 全员共同能力

所有内部角色都具备：

- 客户查询；
- 客户身份识别；
- 客户主档摘要；
- 多房屋关系；
- 当前阶段/责任人/更新时间；
- 被授权的业务链查看；
- 当前用户与客户的关系提示；
- 只读协同模式。

### 5.2 角色动作差异

动作不是由角色静态枚举，而是由：

```text
角色能力
+ 数据范围
+ 客户/房屋/项目关系
+ 当前状态
+ 前置条件
+ 阻断条件
```

共同决定。

| 角色 | 查询后默认关注 | 典型主行动 | 典型只读信息 |
| --- | --- | --- | --- |
| 业务员 | 跟进、量房、客户转化 | 写跟进/预约量房 | 设计、报价、项目 |
| 设计师 | 房屋、量房、设计、报价 | 进入设计/推进方案 | 合同、项目、财务摘要 |
| 项目经理 | 项目、施工、验收 | 进入工地/推进阶段 | 设计、报价、合同 |
| 财务 | 合同、项目、应收、成本 | 查看应收/登记收款/核对成本 | 设计、施工细节 |
| 店长 | 本店客户全链、责任分配 | 转交/指派/处理本店阻断 | 全业务链本店范围 |
| BOSS | 全企业客户经营和风险 | 处理跨角色阻断/经营决策 | 企业范围全链 |

## 6. 页面信息层级建议

客户页面首屏必须优先回答：

```text
这是谁？
和我是什么关系？
当前发生了什么？
现在该做什么？
做完交给谁？
```

建议三层：

### L1：客户身份与当前结论

- 客户姓名、联系方式、阶段、门店；
- 当前负责人、设计师、项目经理；
- 当前风险/阻断；
- 当前主行动；
- 数据更新时间。

### L2：客户对象与业务关系

- 客户画像、标签、跟进状态；
- 当前房屋列表；
- 当前房屋的量房、方案、报价、合同、项目、验收、付款摘要；
- 当前责任人和下一步。

### L3：完整档案与历史

- 客户档案；
- 完整跟进时间轴；
- 房屋历史；
- 关联业务对象完整列表；
- 流失/恢复、交接和审计历史。

## 7. 参考设计取舍

| 参考 | 采用的模式 | 不直接采用 |
| --- | --- | --- |
| App BOSS 客户 Tab | 全员查询、阶段/跟进筛选、负责人分组、客户卡片含下一步 | Boss 经营 KPI 全量搬到所有角色 |
| Web Designer Customers | 客户/房屋切换、当前业务对象上下文、URL 锚点、动作逻辑 | 三栏布局本身；“待设计房屋”作为客户页默认队列 |
| Web Customer 360 | 客户身份条、多房屋、业务链页签、跟进时间轴、权限裁剪 | 把客户页变成所有专业工作台的集合 |

## 8. 明确不做

- 不把客户页面设计成新的“菜单目录”；
- 不在客户页面复制设计方案、报价、合同、项目、财务工作台；
- 不要求所有角色看到同一套客户字段；
- 不把所有动作都变成按钮墙；
- 不让客户查询依赖“我的客户”或“本店客户”单一入口；
- 不用前端推断当前可执行动作；
- 不用 0、空数组或隐藏入口伪装无权限/失败；
- 不在本阶段改后端 Provider 或业务规则。

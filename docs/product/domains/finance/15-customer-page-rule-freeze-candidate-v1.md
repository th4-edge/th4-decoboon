- 依据：`14-customer-page-business-capability-list-v0.1.md`、`13-customer-page-inventory-web-app-v0.1.md`、`USER-DEC-20261029-007`

## 1. 冻结原则

### R1 客户页面首先是全员客户查询入口

所有内部角色都可以查询客户，但查询范围仍受现有租户、组织、数据范围和敏感字段权限约束。

```text
可查询 ≠ 可查看全部字段
可查询 ≠ 可操作客户
可查看业务链 ≠ 可修改业务对象
```

### R2 客户页面不是角色任务页

客户页面以 `Customer` 为中心；`待我设计`、`待我跟进`、`待我签约`等属于角色任务工作面，不是客户页面本体。

### R3 客户主对象唯一，业务链共享

同一企业内部，客户、房屋、跟进、设计、报价、合同、项目、财务等对象使用同一业务事实和同一 Provider；不同角色只改变默认筛选、字段可见、动作能力和交接提示，不复制对象页面。

### R4 客户是多房屋、多业务链的业务锚点

客户可以有多套房屋；每套房屋可以关联量房、设计、报价、合同、项目和验收等业务链。客户页面必须支持：

```text
Customer
├─ Property A
│  ├─ Measure
│  ├─ DesignScheme
│  ├─ Quote
│  ├─ Contract
│  ├─ Project
│  └─ Payment/Receipt
└─ Property B
   └─ ...
```

### R5 查询结果必须说明“我与客户的关系”

每个客户查询结果至少能回答：

- 我为什么能查到这个客户；
- 我是负责人、设计师、项目经理、财务协同人，还是只读协同；
- 当前责任人是谁；
- 当前阶段是什么；
- 当前下一步是什么；
- 当前是否有需要我处理的动作。

### R6 有操作能力的人看到下一步，无操作能力的人看到协同信息

有客户操作能力时：

```text
客户定位
→ 当前状态
→ 当前主行动
→ 阻断原因
→ 动作结果回读
→ 下一责任人
```

无客户操作能力时：

```text
客户定位
→ 客户摘要
→ 被授权业务链
→ 当前责任人和更新时间
→ 只读进入相关专业工作面
```

不显示不可执行的假按钮，不以空数组代替无权限。

### R7 客户页面不复制专业工作面

客户页面可以展示关联业务摘要和入口，但以下操作仍在各自专业工作面完成：

- 设计方案编辑；
- 报价编辑；
- 合同签约/变更；
- 项目施工管理；
- 验收整改；
- 财务收付款、台账、结算和凭证。

客户页面负责：

- 找到对象；
- 理解关系；
- 看清状态和责任人；
- 进入正确的下一步；
- 完成后回读客户与业务链状态。

### R8 当前可用动作由服务端能力投影决定

动作不能仅由前端角色枚举决定，必须综合：

```text
角色能力
+ 数据范围
+ 客户归属/项目关系
+ 当前客户/房屋/业务对象状态
+ 前置条件
+ 阻断条件
```

客户页面只负责展示服务端给出的动作、原因和回读结果。

### R9 保留现有产品路径

- 保留财务现有「客户」菜单和 `/workbench/customers` 深链；
- 不新建 `/finance/customers`；
- 不重做整体导航；
- 客户页面优化采用原位升级；
- 现有客户、房屋、跟进、转交、指派、流失等 Provider 优先复用；
- 本阶段不调整后端业务逻辑、权限、金额、成本、状态机或 DDL。

### R10 Web 与小程序同事实、不同布局

- 小程序：适合高频查询、快速识别、轻量动作和移动协同；
- Web：适合多客户对比、多对象上下文、批量查看、长业务链和深度操作；
- 两端共享同一客户、房屋、业务链事实、权限和错误语义。

### R11 客户页面必须覆盖七类状态

正常、加载、空、失败、无权限、长内容、极端值。

### R12 客户查询结果必须可恢复

切换客户、切换房屋、进入关联业务、返回和刷新后，客户上下文必须可恢复；不能返回后重新搜索，也不能丢失当前房屋。

## 2. 财务角色客户页面的目标

### 2.1 一句话目标

> 财务打开客户页面，既能查询客户，也能围绕该客户查看合同、项目、应收和经营协同信息；当有财务动作时直接进入下一步，没有动作时作为跨角色业务协同的只读窗口。

### 2.2 财务页面的两个模式

| 模式 | 适用情况 | 页面输出 |
| --- | --- | --- |
| 财务操作模式 | 财务对当前客户/业务对象有可执行动作 | 当前主行动、金额/风险摘要、阻断原因、完成后回读 |
| 财务协同模式 | 财务只能查看或当前无财务待办 | 客户主档、房屋、合同/项目/收付款摘要、当前责任人和下一步 |

## 3. 财务客户页面的建议结构

### 3.1 首屏

```text
客户范围：全部门店 / 本店
搜索：客户姓名 / 手机号 / 小区
轻量筛选：全部客户 / 有财务业务 / 应收关注 / 逾期收款 / 已签约项目
```

首屏不复制 Boss 的经营指标卡墙。财务客户页面的第一任务是**客户查询**，不是经营总览。

### 3.2 左侧：客户结果队列

客户结果卡至少包括：

- 客户姓名；
- 手机号脱敏；
- 小区/地址；
- 客户阶段；
- 负责人、设计师；
- 是否有合同/项目；
- 应收、待收、逾期摘要；
- 下次跟进/最近跟进；
- 当前风险或下一步。

财务客户卡不抢占整个页面；搜索和对象定位应优先。

### 3.3 中间：客户对象工作面

客户身份区：

- 客户姓名、手机号、来源、等级；
- 当前阶段；
- 归属门店；
- 负责人、设计师、项目经理；
- 最近跟进、下次跟进；
- 风险/流失/休眠状态。

房屋区：

- 多房屋选择；
- 房屋状态；
- 每套房屋关联的方案、报价、合同、项目、验收、收付款计数。

财务关注区：

- 合同金额/状态；
- 应收、已收、待收、逾期；
- 项目状态与项目经理；
- 当前收付款节点；
- 成本完整性或利润仅在权限和口径允许时展示；
- 当前财务责任人与下一步。

业务链区：

- 量房；
- 设计；
- 报价；
- 合同；
- 项目/工地；
- 验收；
- 收付款。

业务链以摘要、状态、责任人和入口为主，不在客户页复制专业工作台。

### 3.4 右侧：下一步与可用动作

右侧只突出一个当前主行动，例如：

- 查看应收；
- 登记收款；
- 核对合同/项目关联；
- 查看项目财务；
- 维护客户资料；
- 转交负责人/指派设计师（如财务有该动作权限）。

其他动作放入“更多客户操作”或“更多业务协同”。

右侧必须同时说明：

```text
为什么现在做
当前状态
前置条件是否满足
阻断原因
完成后回读什么
下一责任人
```

### 3.5 只读协同展示

当财务当前没有可执行动作：

```text
当前无财务待办
+ 最近更新时间
+ 当前业务阶段
+ 当前责任人
+ 可查看的业务链
+ 进入相关专业工作面的权限入口
```

不能用“按钮置灰一片”表达无操作能力，也不能把只读用户引导到不可用页面。

## 4. 财务角色动作投影

| 当前客户状态 | 财务首要关注 | 建议主行动 | 其他信息 |
| --- | --- | --- | --- |
| 未签约 | 客户跟进、量房、方案、报价状态 | 查看客户资料/关联报价 | 设计、报价、跟进 |
| 已签约未立项 | 合同生效、应收计划、项目立项 | 查看合同/应收计划 | 合同、项目阻断 |
| 项目在途、应收正常 | 合同、项目、收付款正常 | 查看项目财务/下一个收款节点 | 设计、施工摘要 |
| 存在逾期应收 | 逾期金额、责任人、合同节点 | 登记收款/查看应收 | 台账、凭证 |
| 完成收款 | 应收核销、凭证、后续结算 | 查看应收/凭证 | 项目成本、结算 |
| 客户流失/休眠 | 原因、恢复路径、历史业务影响 | 查看流失/恢复信息 | 历史合同/项目 |
| 客户资料不完整 | 是否影响合同/付款/开票流程 | 维护客户资料（如权限允许） | 关联业务链 |

动作是否显示和是否可点击，以服务端能力投影和既有业务规则为准，不在本文件新增权限。

## 5. 参考设计的采用方式

### 小程序企业负责人客户 Tab

采用：

- 查询优先；
- 阶段/跟进/负责人筛选；
- 客户卡信息密度；
- 风险、负责人、设计师、最近/下次跟进；
- 下一步在客户卡中可见。

不采用：

- Boss 指标卡作为财务客户页首屏主体；
- 负责人分组作为所有角色的默认布局。

### Web 设计师客户与设计页面

采用：

- 左侧对象定位、中间客户/房屋上下文、右侧动作引导；
- 客户与房屋切换；
- URL 锚点；
- 返回和刷新保持上下文。

不采用：

- “待设计房屋”作为财务客户页左侧队列；
- 设计任务队列和方案编辑作为客户页主体。

### Web 客户 360

采用：

- 客户身份条；
- 多房屋；
- 业务链页签；
- 跟进时间轴；
- 权限裁剪；
- 当前主行动。

不采用：

- 所有业务对象都在客户页面直接编辑；
- 单一设计师视角。

## 6. 需要用户验证的关键判断

1. 财务客户页是否定位为“全员客户查询 + 财务协同窗口”，而不是“财务经营驾驶舱”？
2. 财务左侧默认队列是否以“全部客户/有财务业务/应收关注/逾期”为主，而不是复制 Boss 的负责人经营分组？
3. 财务中间区是否以客户身份、房屋、合同/项目/应收摘要为主，不显示完整设计方案、报价编辑和施工工作台？
4. 财务右侧是否只突出一个当前财务动作，同时保留客户维护、转交/指派等次级动作？
5. 财务无当前动作时，是否显示“当前无财务待办 + 当前责任人和可查看业务链”，而不是空页面或大量禁用按钮？
6. Web 是否采用三栏对象工作面，小程序是否采用客户卡列表 + 客户详情页，而两端共享同一客户业务链？
7. 是否确认本阶段只复用现有 Provider，不新增后端逻辑，不新建 `/finance/customers`，保留现有 `/workbench/customers`？

## 7. 本轮不做

- 不修改当前后端代码；
- 不新增客户字段、接口、状态或权限；
- 不修改现有 `/workbench/customers` 路由；
- 不开始完整页面视觉设计；
- 不替换全站导航；
- 不把客户页面做成所有专业工作台的集合。

## 1. 本轮修正

用户评审指出：

1. 客户卡上的“顾问”与小程序不一致，应统一为“客户负责人”；
2. 点击客户详情后信息不完整，应形成与小程序客户详情一致的客户 360；
3. Web 可用展示区域更大，不能继续使用窄抽屉和单列堆叠，应按信息关系重新排版。

## 2. 小程序设计逻辑对齐

小程序客户详情的阅读顺序为：

```text
客户身份与标签
→ 客户负责人 / 负责设计师
→ 沟通动作
→ 当前业务阶段与主行动
→ 装修房屋
→ 客户资料
→ 内容来源
→ 客户画像
→ 跟进记录
```

Web 客户 360 按同一任务顺序转译，并利用横向空间组织为：

```text
客户身份条与主要沟通动作
→ 责任关系 / 下次跟进 / 当前下一步
→ 客户业务阶段轨道
→ 主栏：装修房屋 → 当前房屋业务链 → 房屋关联信息 → 跟进记录
→ 侧栏：客户资料 → 客户画像 → 低频客户动作
```

## 3. 客户卡修正

- “顾问”统一改为“客户负责人”；
- “负责设计师”与“项目”保持独立；
- 客户卡仍以客户自身信息为主，财务合同/项目/待收/逾期保持低权重上下文。

## 4. 客户 360 能力

### 4.1 客户身份与协同

- 姓名、阶段、等级、风险；
- 电话、来源、最近跟进；
- 客户标签；
- 客户负责人、负责设计师；
- 下次跟进与当前下一步；
- 打电话、复制号码、写跟进。

### 4.2 客户业务阶段

固定七段：

```text
到店 → 跟进 → 量房 → 设计 → 报价 → 签约 → 项目
```

按客户阶段与当前房屋既有事实投影，不在前端新增业务状态。

### 4.3 多房屋

- 展示全部装修房屋；
- 明确当前选中房屋；
- 显示地址、面积、户型、最近量房；
- 切换房屋后，房屋关联信息随之切换；
- 支持新增与编辑房屋。

### 4.4 房屋关联信息

七个关联页签：

1. 需求/禁忌；
2. 设计方案；
3. 报价版本；
4. 合同；
5. 项目；
6. 量房记录；
7. 收款计划。

每个页签只展示当前房屋的数据；缺失时显示空态，不以假数据补齐。收款数据按现有角色权限返回，无权限时明确不可查看。

### 4.5 客户资料与画像

- 来源、意向小区、房屋面积、预算、等级、到店次数、详细地址、备注；
- 客户画像使用现有唯一展示映射；
- 未填写画像时显示明确空态。

### 4.6 跟进时间轴

- 客户级事实，不随房屋切换；
- 展示跟进内容、方式、员工、时间和下次跟进；
- 写跟进沿用现有客户跟进 Provider。

### 4.7 内容来源

- 复用 App 既有 `content/lead-touch/list` Provider；
- 展示内容任务、归因员工、归因方式、置信度和触达时间；
- 明确区分主归因与辅助触点；
- 接口失败时显示“内容来源暂不可确认”，不伪装为空。

## 5. 宽幅布局

- 1440：客户 360 宽度 1240px，主栏 + 320px 侧栏；
- 1280：自适应宽幅，主栏 + 侧栏；
- 1024：客户 360 宽度 992px，主栏约 608px + 280px 侧栏；
- 1024 与 1440 均无横向溢出；
- 所有按钮保持“图标 + 文字”，关闭按钮使用带可读名称的图标。

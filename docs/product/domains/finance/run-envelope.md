## 1. 目标

- Domain：`finance`
- North Star：以财务角色为经营控制面，统一项目资金、成本利润、往来核校与业务协同，形成可复用、可追溯、可交接的财务工作台体系
- 目标角色：总部财务、门店财务、BOSS、店长；其他角色参与费用、薪酬和业务交接
- 本期范围：基于现有产品逐项验收 Web 24 个 Finance 菜单及小程序 6 个财务角色 Tab、财务首页、19 个快捷入口和对应任务链；不做新建式重构
- 本期不做：后端业务逻辑/Provider/状态/权限/金额/成本/利润/DDL 修改、财务页面整体重做、导航重构、独立验收、发布

## 3. 自主决策权限

当前仅允许自行决定：

- 文档结构和技术性排版；
- 已有事实的归纳、交叉引用和证据归档；
- 只读代码/页面盘点；
- UI 基线的取证方法；
- 不改变业务事实的组件复用建议草案。

## 4. 人工门禁

遇到以下情况必须停止并写入决策包：

- 新业务对象、状态、角色或数据范围；
- 任何后端业务逻辑、Provider、金额/成本/利润、权限或 DDL 调整；
- 金额、成本、利润、权限、支付语义变化；
- DDL、迁移、生产数据删除；
- 正式小程序提审与发布；
- 密钥、生产配置、对外消息；
- 财务职责边界、导航和页面归属的最终取舍；
- 公司/门店经营利润或发票边界的正式口径。

## 5. 质量门禁

- 业务事实均引用 `DEC/BR/SCN/OBJ/MET/EV`；
- 业务未对齐前不进入编码；
- UI 必须有最新真实渲染证据；
- 七态与八维视觉评审完成；
- App/Web 同源字段、权限、状态、金额和回读对账；
- 没有 `UNMAPPED/STALE` 才能声称本批完成；
- 开发自测不得冒充独立验收。

## 6. 预算与止损

- 每个缺陷最多修复轮次：2（技术问题）；业务问题不循环试错
- UI 审查最多轮次：3（含最终复核）
- 同指标连续无改善停止次数：2
- 最大自主批次：当前 0（未授权编码）
- 无进展时处理：记录阻塞，等待 T06/用户决策

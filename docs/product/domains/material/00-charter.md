# 材料履约与材料业务助手 · 业务域章程

- Domain：`material`
- Owner：codex
- North Star：材料计划、选材、作业单、采购、到场与结算形成可追溯闭环，并提供可解释、可校核的业务助手。

## 1. 业务问题

装得清的材料链横跨合同材料行、选材、作业单、采购、到场、库存、应付、结算和增减项。不同角色只看到自己那一格，容易出现：

- 把材料计划、作业单、采购单混成同一个对象；
- 不知道“提交请购”“财务下单”“确认到场”分别由谁做；
- 不知道测量日期、配送日期、要求到场、实际到场的区别；
- 作业单有项目/来源计划/价格语义缺失时无法追溯；
- 增减项发生后不知道该改计划、采购还是生成退货；
- 无价采购、暂估应付、成本不完整和利润 null 的关系难以理解。

本域不仅交付材料业务，还交付一套能解释材料业务、校核数据、诊断异常的业务助手。

## 2. 目标角色

| 角色 | 主要目标 | 关键动作 | 不负责什么 |
| --- | --- | --- | --- |
| Boss / StoreManager | 看材料闭环、风险和资金结果 | 审批、超集操作、配置/供应商决策 | 不代替项目经理现场确认 |
| Finance | 下单、应付、结算、成本收敛 | 选供应商、填价格/账期、确认到场后账期、结算 | 不决定设计师选材内容 |
| Designer | 选材、建品类作业单、提交请购 | 现场选材、建单、测量/时间确认、提交 | 不决定供应商和采购价格 |
| PM | 测量、时间、到场、催货 | 现场测量、确认到场、异常反馈 | 不选择供应商、不决定价格 |
| Supplier / Dealer | 接收作业单、生产/备货、送货、对账 | 对账、送货、配合退货/补货 | 不直接修改系统状态 |
| Customer / Owner | 确认选材、查看自己项目 | 线下/现场确认、只读查看 | 不查看企业内部成本和供应商价格 |
| System | 维持事实、状态、权限、账务 | 生成计划、门禁、状态派生、应付/成本写入 | 不自行发明业务规则 |

## 3. 本期范围

### 必须做

- 材料计划、选材、作业单、采购、到场、结算、退货的主链在 App 内真实闭环；
- 标准业务蓝图、企业配置蓝图、项目实时投影；
- App/Web 的业务说明、字段解释、项目业务体检；
- 只读材料业务助手：解释、数据校核、异常诊断、下一步引导；
- 材料业务助手上下文入口：在项目、作业单、采购/结算上下文提供统一单轮“问材料”，复用同一只读运行时；
- 真实页面/真机证据、独立验证和对账矩阵。

### App 单端闭环（2026-10-17 用户裁决）

- App 是材料下单的唯一业务入口；Web 不作为材料下单/结算的必经节点。
- 唯一路线：`MaterialPlan → MaterialOrderSheet → 提交请购 → App 下单 → PurchaseOrder → GoodsReceipt → MaterialSettlement`。
- 旧“材料计划直接采购”路线从 App 产品面下线，后端直接创建采购单入口同步收口。
- 角色：Designer 建单/提交，PM 测量/到场，Finance/Boss/StoreManager 在 App 下单与结算。

### 首版切片

首版以 **瓷砖 P0** 跑通材料链与材料助手；其他主材品类沿用模板和规则，不在首版一次性铺满。

### 明确不做

- 不新增业务规则或改变金额/成本口径；
- 不实现自动审批、自动付款、自动删除、自动改权限；
- 不做正式小程序提审和发布；
- 不在未裁决前实现“测量字段全品类必填”；
- 不把作业单取消扩展为已下单采购的撤销；已进入采购必须走调整或退货；
- 不把当前 HTML 蓝图复制成每个模块的静态页面。

## 4. 主链

```text
合同材料行
→ MaterialPlan（需求/损耗/状态/要求到场）
→ MaterialSelection（选材现场确认）
→ MaterialOrderSheet（品类作业单：位置/尺寸/测量/配送/安装）
→ 提交请购
→ PurchaseOrder（供应商、价格、账期、应付）
→ GoodsReceipt（实际到场、账期起算、实际成本）
→ MaterialSettlement（P3 结算价、成本收敛）
→ 退货/往来余额/增减项联动
```

## 5. 关键不变量

1. 材料计划是需求事实；作业单只编排；采购单才产生价格、账期和应付。
2. 1 张作业单可以对应 N 张采购单。
3. 作业单对厂家，不带价格、账期和成本；打印/导出不出现价格类字段。
4. 合同选材来源的计划行进采购前必须有 Selected 选材记录；进入采购后锁定，换材走增减项。
5. 下单量不得超过净用量 + 损耗；减项先冲损耗，再冲净用量。
6. 下单即形成应付；无价形成暂估应付；到场只回填账期和实际成本，不新增应付。
7. 实际成本以 P3 结算价为唯一来源；P2 可暂估计价；P1 只用于预计成本和偏差。
8. 任一应计成本缺失时 `costComplete=false`，利润和毛利率必须为 `null`。
9. 增减项按状态走计划冲减、采购调整或退货；不得直接改应付而不留退货记录。
10. 所有数据范围来自登录员工和项目参与关系，禁止信任前端 companyId/empId/projectId 作为权限依据。

## 6. 金额/成本/权限边界

- P1 报价成本价：报价/合同快照，只用于预计成本；
- P2 采购价：财务/采购下单，形成应付和暂估成本；
- P3 结算价：财务/供应商对账，实际成本唯一来源，不写回供应商参考价；
- 成本价和供应商价格只对 Boss/StoreManager/Finance 可见；
- 材料作业单、选材、采购、到场的权限按项目参与关系和企业/门店/团队范围校验；
- 业务助手沿用当前用户权限，不得扩大数据范围。

## 7. 成功指标

- 产品：项目材料业务体检可见率、下一步点击率、蓝图使用率；
- 数据质量：缺选材、缺测量、缺供应商、缺价格、超量、成本不完整等问题的发现率；
- 业务结果：错误下单/错误结算减少，材料闭环处理时间下降；
- 安全：越权数据访问 0，金额/成本计算错误 0，高风险写入 0；
- 交付：无 UNMAPPED/STALE，真实 UI 证据完整，独立验证 PASS。

## 9. App 单端闭环裁决（2026-10-17）

用户明确裁决：

1. 材料下单统一走主材作业单，不再保留“材料计划直接采购”路线；
2. App 必须完成从作业单建单、请购、下单、应付、到场到材料结算/成本完整的闭环；
3. Web 不作为接管端或必经节点；
4. 历史采购单只读保留，不删除历史事实。

本裁决以用户书面确认为最高权威，与 `SCN-021`、`OBJ-008`、`BR-044`、`BR-045`、`DEC-072`、`DEC-073`、`DEC-074` 一致。

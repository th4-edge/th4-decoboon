# 材料域 UX 回归 · 从业务说明书改回工作台

- 状态：U1/U2/U3 已完成（UI_REVIEWED，自测）；下一步 U4
- 触发：用户 2026-10-18 明确指出“Web/App 解释太多、技术语言太多、设计师/财务用不好最基本功能”
- 性质：前端信息架构与交互回归；不改业务对象、状态、权限、金额/成本/结算语义，不新增 DDL
- 事实依据：既有 `00-charter.md`、`03-blueprint.json`、`04-requirements.md`、`07-ui-review.md`、`08-acceptance.md`、`10-reconciliation.md`
- 关键判断：蓝图是产品方向的母版，不是一线用户的日常工作台；功能验收 PASS 不等于可用性验收 PASS

## 1. 回归原则

1. 一屏只回答三个问题：我现在在哪、还差什么、点哪里继续。
2. 一个页面只有一个主行动；其他动作降级。
3. 业务规则解释默认折叠到“为什么”，不占首屏。
4. 设计师/PM 首屏不出现价格、成本、利润、结算口径。
5. 技术语言不进入首屏：`Provider`、`confidence`、`null`、`priceState`、`CHK-*`、`commit`、`审计`。
6. 先改主流程页面，不改后端业务事实；需要新增字段或绑定对象时单独开批次。

## 3. U1 页面契约

```text
页面：App 主材作业单详情
角色：Designer/PM/Boss/StoreManager/Finance
打开时机：从项目材料、待办或工作台进入某张作业单
唯一主行动：
  - Designer/Boss/StoreManager 且可提交：提交请购
  - Finance/Boss/StoreManager 且待下单：去下单
  - PM 且可测量：保存现场信息
首屏三问：
  1. 我现在在哪？ -> 单号 + 状态 + 项目
  2. 还差什么？ -> 必填现场字段与待下单行数
  3. 点哪里继续？ -> 唯一主按钮
解释：时间口径/作业单边界折叠到“为什么这样填？”
```

## 4. U1 具体改动

- 移除首屏大段“这张单怎么继续”说明卡；
- 顶部保留紧凑状态卡：单号、状态、项目、测量/配送/安装日期；
- 增加“下一步”卡：还差哪些必填项、待下单行数、当前等待谁；
- 测量/配送/安装字段直接放在下一步卡内；Designer 点“提交请购”时自动保存现场字段再提交；
- 设计师/PM 不显示价格状态、成本、利润、结算信息；
- 底部只保留一个主按钮；导出、编辑降为次要动作；
- “时间口径/作业单不带价格”折叠到“为什么这样填？”；
- 保留材料明细与现有权限、状态、接口不变。

## 5. 不做

- 不修改 `material/sheet/submit|measure|order` 的业务语义；
- 不修改金额/成本/利润/结算口径；
- 不新增数据库字段或迁移；
- 不删除蓝图与助手，只调整入口和首屏权重。

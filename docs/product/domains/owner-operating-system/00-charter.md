# 装企负责人经营管理体系 · 业务域章程

- Domain：`owner-operating-system`
- Owner：codex
- Created：2026-10-28
- 状态：产品梳理与概念设计（非生产实现）
- North Star：以负责人视角统一多端能力，沿客户经营主链看清业务推进、经营结果、运营标准和组织效能，并能从观测点直接进入处置。

## 1. 业务问题

负责人当前面对的不是“功能不够”，而是跨客户、报价、合同、项目、材料、财务和组织之后，难以在同一个经营视角下回答五个问题：

1. 今天企业最需要我处理什么？
2. 哪个客户、合同或项目正在停住，为什么停、责任人是谁？
3. 本月签约、回款、应付和项目毛利处于什么状态，哪些数字尚不可确认？
4. 企业的报价、套餐、计划、凭证和主数据标准是否已经支撑一线执行？
5. 员工、门店、角色、邀请、权限和审计是否支撑当前经营规模？

本域要建立“负责人经营管理全景”：

```text
业务推进
×
企业经营
×
运营工具
×
组织管理
×
App / 微信小程序 / Web
×
观测点 → 对象 → 处置 → 回读
```

## 2. 目标角色

| 角色 | 主要目标 | 关键动作 | 不负责什么 |
| --- | --- | --- | --- |
| 企业负责人 BOSS | 看清企业全盘并推动关键事项闭环 | 看经营事实、识别异常、审批、指派、推进、复盘 | 不能冒充业主/客户确认，不取得平台运营权限 |
| 一人装企 BOSS | 在同一个人下完成内部多岗位连续闭环 | 切换岗位视角，按状态逐步执行并留痕 | 不得合并状态节点、跳过金额/权限校验或伪造操作主体 |
| 多门店 BOSS | 看全企业并按门店收窄观察 | 门店对比、跨店指派、公司目标与门店目标分层查看 | 不把门店目标自动相加为公司目标 |
| 店长（对照角色） | 复用同一业务能力处理本店经营 | 本店客户、项目、财务、组织与经营分析 | 不拥有企业治理、跨店、公司利润和订阅能力 |

## 3. 本期范围

### 必须做

- 以负责人视角重构一级信息架构：业务推进、企业经营、运营工具、组织管理。
- 盘点负责人在各业务阶段的观测点和可执行下一步。
- 明确 App、微信小程序、Web 的职责分工及同一事实回读要求。
- 输出可交互高保真 HTML 概念原型，覆盖桌面 Web 与移动端壳层。
- 输出业务推进流程图：阶段、对象、负责人、进入条件、观测点、风险、下一步和异常。
- 对未确认的指标和口径展示“暂不可确认”，不伪装为默认值。

### 暂时不做

- 不新增业务对象、状态机、角色、数据范围或金额公式。
- 不把四维分类直接写成后端菜单或权限模型。
- 不实现生产 App/Web 页面，不新增 Provider，不执行 DDL。
- 不把概念原型的演示数据当成生产数据或对外能力承诺。
- 不冻结公司经营利润、门店经营利润和总部费用分摊公式。

### 明确排除

- 业主、工人、供应商自助端。
- 平台 Admin 运营端。
- 法定会计、税务申报和审计口径。
- 小程序正式提审与发布。

## 4. 主链

```text
负责人进入经营全景
→ 选择业务推进 / 企业经营 / 运营工具 / 组织管理
→ 先从服务端事实读取经营结论与异常
→ 定位客户、合同、项目、资金或组织对象
→ 查看观测点、阻断原因、责任人和允许动作
→ 在 App/小程序/Web 中执行当前唯一主行动
→ 回读对象状态、风险、金额、待办和时间线
→ 返回原队列或进入下一项
```

## 5. 关键不变量

1. 同一业务能力只有一个 Provider，App、微信小程序、Web 只允许壳层与交互密度不同。
2. 正式业务值只能来自服务端；缺失、失败或未确认时显示“暂不可确认”，并用 0、22、空数组或前端常量兜底均为禁止项。
3. 负责人可以执行企业内部岗位能力超集，但状态机仍逐步推进，每步记录动作人、能力、前后状态和时间。
4. 业主/客户确认、合同签认等外部主体动作不能由 BOSS 冒充。
5. 项目成本不完整时，项目毛利和毛利率必须为空并显示“成本未完整”。
6. 公司/门店经营利润在公式冻结前只显示观测位和“口径待确认”，不得展示确定金额。
7. 风险队列必须保留筛选、位置和对象上下文，动作完成后显式进入下一项，不自动切换。
8. 运营工具属于企业标准层，修改影响未来业务，但不得回溯改写历史单据。
9. 组织管理按企业、门店、员工、角色、邀请、权限和审计建模，不新增重复岗位角色；TeamLeader 仅历史兼容。
10. 负责人视角不是“全部页面入口堆叠”，而是“经营结论 → 异常观测 → 当前处置 → 结果回读”。

## 6. 金额、成本、权限边界

- 金额：签约额、回款额、应收、应付、合同额按各自对象和期间口径展示，不能互相替代。
- 成本：项目成本统一通过 `ProjectCostContext`；成本不完整时利润为 `null`。
- 利润：项目毛利可引用 `MET-002`；公司/门店经营利润只能标为参考且当前口径待冻结。
- 权限：BOSS 数据范围为 Company；可按门店筛选，但筛选不是新增授权。
- 越权：跨企业、跨门店或无项目参与关系的访问必须被服务端阻断，禁止用空数据伪装无权限。
- 模板：App 中报价项目库维护仅限 BOSS/店长/财务；其他角色只读且成本字段由服务端裁剪。

## 7. 成功指标

### 产品体验

- 负责人在 30 秒内回答“今天最需要处理的三件事”。
- 从一个观测点进入对象并完成处置后，能回到原队列位置。
- 同一风险在 Web 与移动端显示同一对象、状态、责任人和金额口径。

### 数据质量

- 所有指标必须显示数据更新时间、口径和缺失态。
- 未确认的利润、分摊或观测阈值必须显式标注，不得默认成功。
- App、微信小程序、Web 读取同一 Provider 事实，差异有明确记录。

### 业务结果

- 首轮只验证认知和任务闭环，不用原型推断效率、利润或转化率提升。
- 客户、项目、合同、资金和组织关键风险能够从负责人视角被定位和分派。

### 安全

- 越权、跨租户、成本泄露、外部确认冒名和前端伪造企业身份均不得出现。
- 概念原型不得包含真实账号、密钥、客户隐私或生产数据。

## 8. 未决业务问题

| 问题 | 需要的裁决 | 影响 | 当前状态 |
| --- | --- | --- | --- |
| 微信小程序是否作为独立负责人壳层，还是与 App 共用同一移动端产品定位 | 用户产品决策 / 业务智能体同步 | 影响三端信息架构和导航 | OPEN |
| 负责人观测阈值（如跟进超期、报价停留、项目延期）是否按企业配置 | 业务裁决 | 影响风险队列和告警 | OPEN |
| 公司/门店经营利润公式与费用分摊 | `MET-007/011`、`GAP-070` | 影响企业经营页金额展示 | BLOCKED，不显示确定金额 |
| `运营工具`是否作为正式一级产品名称 | 产品命名与业务矩阵裁决 | 影响 IA 和菜单 | OPEN，本原型按用户指定名称展示 |

## 9. 业务事实引用

- OBJ：客户、房屋、设计方案、报价、合同、项目、项目阶段、材料计划、应收、应付、收付款、台账、员工、门店、邀请。
- SCN：`SCN-001`～`SCN-022`，重点 `SCN-016` 负责人风险队列。
- BR：`BR-001`、`BR-002`、`BR-028`、`BR-030`、`BR-037`、`BR-049`。
- DEC：`DEC-032`、`DEC-034`、`DEC-067`、`DEC-075`、`DEC-076`、`DEC-080`、`DEC-085`。
- MET：`MET-001`、`MET-002`、`MET-004`、`MET-005`；`MET-007/011` 仅草案。
- GAP：`GAP-003`、`GAP-047`、`GAP-070`，以及本域新增的跨端壳层与阈值问题。

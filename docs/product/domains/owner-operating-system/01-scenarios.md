# 装企负责人经营管理体系 · 真实业务场景

> 所有企业、人物、金额和项目均为合成数据。场景用于定义负责人视角，不用于对外承诺。

## 场景 A：三门店负责人早晨经营盘点

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 企业负责人王总，经营 3 家门店，员工约 28 人 |
| 触发事件 | 08:40 到办公室，打开 Web 经营管控中心，准备处理今天最影响经营结果的事项 |
| 前置条件 | 企业、门店、员工有效；客户、合同、项目、应收和成本事实已落入系统 |
| 当前动作 | 先看公司本月签约、回款、应收逾期和成本完整项目毛利；再查看 A 店一个延期项目、B 店一笔首期款逾期、C 店两份待决策报价 |
| 系统下一步 | 风险条按“金额影响、逾期时间、责任人、可恢复动作”排序；点击 A 店项目进入对象工作面，并保持原风险队列位置 |
| 成功结果 | 王总完成项目延期指派和首期款催收分派，回读责任人、状态、最近动作和时间线；回到队列继续下一项 |
| 异常/恢复 | 项目成本不完整时毛利显示“成本未完整”；因权限无法查看某员工工资时，不显示 0，而是暂不可确认并说明范围；跨店筛选只改变观察范围，不改变 Company 权限 |
| 涉及对象 | Company、Store、Customer、Quote、Contract、Project、Receivable、ProjectCostContext、Employee |
| 状态变化 | 风险项从待处置→已指派；项目保持施工中，但责任人/下一步动作更新；应收计划状态不回写为已收 |
| 金额/成本/权限 | 签约额、回款额、应收和项目毛利分开；成本不完整禁止利润；BOSS 全企业范围，门店筛选不是授权 |
| 证据/来源 | `BR-028`、`BR-030`、`SCN-016`、`DEC-067`、`MET-002`、`MET-004`、`MET-005` |

## 场景 B：一人装企负责人连续完成一单

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 企业负责人李总，公司只有 1 人，同时承担业务、设计、项目、财务工作 |
| 触发事件 | 新客户咨询一套 105㎡住宅，希望当天完成量房并尽快出报价 |
| 前置条件 | 企业已开通；客户和房屋可建档；报价项目库和模板可用 |
| 当前动作 | 李总在移动端登记客户和房屋，切到设计视角完成量房与方案，再切到报价/合同视角提交报价、登记合同；项目启动后再切到项目经理视角推进任务，最后切到财务视角登记收款 |
| 系统下一步 | 系统提示当前岗位视角、允许动作和下一状态；每个动作单独留痕，不因同一人操作而跳过报价接受、合同生效、项目立项等节点 |
| 成功结果 | 从客户到项目、合同、收款形成同一条可追溯链路；李总可在负责人首页看到签约、回款、项目风险和成本完整性 |
| 异常/恢复 | 未完成成本快照时不能展示确定毛利；项目未生效时不能提前开工；业主阶段验收必须由业主确认或按正式代登记规则处理 |
| 涉及对象 | Customer、Property、Design、Quote、Contract、Project、Task、Receivable、Receipt、ProjectCostContext |
| 状态变化 | 客户新登记→量房→设计→报价→合同生效→项目立项→施工→验收→收款，节点逐步推进 |
| 金额/成本/权限 | BOSS 具备内部岗位能力超集；不得代替业主确认；报价/合同/财务事实仍按原状态机和金额口径 |
| 证据/来源 | `DEC-032`、`BR-028`、`BR-030`、`CAP-004`、`CAP-005` |

## 场景 C：负责人手机上处理现场阻断

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 企业负责人赵总，外出途中使用 App/微信小程序 |
| 触发事件 | 收到“A 项目材料未到场、阶段任务可能延期、合同变更待审批”的通知 |
| 前置条件 | 通知对象属于当前企业；负责人具备审批或查看权限；移动端已登录 |
| 当前动作 | 在移动端查看风险卡、项目身份条、延期原因、当前责任人和变更金额；直接在移动端审批变更，或转交项目经理补充证据 |
| 系统下一步 | 显示唯一主行动；涉及金额/成本/权限的高风险动作进入确认门；动作成功后回读项目阶段、任务、变更状态和应收/成本影响 |
| 成功结果 | 负责人在现场完成关键决策，Web 端打开同一项目时看到相同状态和审批记录 |
| 异常/恢复 | 弱网或接口失败显示暂不可确认和重试；审批冲突提示重新读取；无权限时说明范围，不把失败伪装为空列表 |
| 涉及对象 | Project、ProjectStage、Task、MaterialPlan、ContractChange、Notification、Audit |
| 状态变化 | 变更从待审批→已批准/退回；项目阶段不自动完成，待现场任务和验收事实推进 |
| 金额/成本/权限 | 变更审批只改变变更状态和后续重算触发，不等于自动收款或成本完成；成本完整性保持原规则 |
| 证据/来源 | `BR-028`、`BR-030`、`SCN-016`、`CAP-004`、`CAP-005` |

## 反向场景

- 越权：店长访问他店客户；普通员工查看全公司利润；非维护角色调用报价项目库写接口。
- 重复提交/幂等：付款审批、合同变更审批、风险指派重复提交不得产生重复事实。
- 跨租户/跨项目：伪造 companyId、项目 ID 或深链接不得越过服务端数据范围。
- 数据缺失：观测点金额、责任人、状态无法确认时显示“暂不可确认”，并提供重新加载或联系负责人。
- 状态不满足：未生效合同不能建项目；未完成报价不能直接签约；未到达阶段不能提前验收。
- 金额/成本不完整：成本未完整时项目毛利、毛利率为空；经营利润公式未冻结时不显示确定金额。
- 外部主体：BOSS 不能冒充业主确认、合同签认或客户验收。
- 跨端：App、微信小程序、Web 对同一对象必须显示同一状态、金额和下一步；只验证一端不得标记跨端通过。

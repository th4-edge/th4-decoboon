# 装企负责人经营管理体系 · 业务智能体同步

## 1. 同步方式

本文件直接消费装得清业务智能体的已批准知识卡，不复制第二套业务事实。

- 试点角色：企业负责人 BOSS
- 期间：2026-10-28
- 目标：将负责人能力按用户指定的 `业务推进 / 企业经营 / 运营工具 / 组织管理` 四维重新组织，并落成高保真概念原型
- 性质：信息架构与产品表达能力梳理，不新增业务对象、状态、角色或金额公式

## 2. 已确认事实

| 事实 | 结论 | 来源 |
| --- | --- | --- |
| BOSS 能力 | BOSS 是本企业全部内部岗位能力超集，Company 数据范围，可按门店收窄观察 | `BR-028`、`DEC-032`、`DEC-067` |
| 一人装企 | 同一 BOSS 可连续执行内部岗位节点，但状态机逐节点推进并逐步留痕 | `DEC-032`、`BR-030` |
| 外部主体 | BOSS 不能代替业主/客户确认、合同签认或验收 | `DEC-032` |
| 工作台 | 必须按角色、触发事件、对象和状态组织；默认回答“需要我处理什么” | `BR-030`、`CAP-005` |
| 对象工作空间 | 负责人从风险队列进入客户/项目对象，动作后回读关联事实并保留上下文 | `SCN-016`、`CAP-004` |
| App 经营工具 | BOSS/店长/财务可维护报价项目库；BOSS/店长可维护套餐、付款计划、施工计划模板；其他角色只读且成本裁剪 | `BR-037`、`DEC-044`、`DEC-079` |
| 月度目标 | 公司目标与门店目标分层保存和展示，不自动相加 | `BR-049` |
| 项目毛利 | 预计/动态/最终三态不混用，任一成本不完整则毛利与毛利率为 `null` | `MET-002` |
| 报价接受率 | 最终报价接受率与首版报价接受率双指标，不把待决策报价放入分母 | `MET-001` |
| 签约额/回款额 | 分别按各自事实统计，不得互相替代 | `MET-004`、`MET-005` |
| 角色治理 | 固定岗位角色，不因组织管理新增重复角色；TeamLeader 仅历史兼容 | `BR-028`、`DEC-085` |

## 3. 四维能力映射

| 负责人维度 | 业务层 | 核心问题 | 主要能力 | 事实来源 |
| --- | --- | --- | --- | --- |
| 业务推进 | BIZ | 这一单推进到哪里，哪里在停，下一步是什么 | 客户、房屋、量房、设计、报价、合同、项目、材料、变更、验收、整改 | `CAP-006` A1～A11、`SCN-001`～`SCN-010` |
| 企业经营 | FIN | 钱、成本、利润和经营目标现在是什么状态 | 应收、收款、应付、付款、台账、项目毛利、签约额、回款额、月度目标 | `MET-001/002/004/005`、`BR-049` |
| 运营工具 | EOP | 企业用什么标准支撑未来业务 | 报价项目库、套餐模板、付款计划模板、施工计划模板、合同/凭证模板、材料与供应商主数据 | `BR-037`、业务架构 EOP |
| 组织管理 | EMG | 谁属于企业、在哪家店、能做什么、是否可审计 | 企业主体、门店、员工、邀请、岗位角色、数据范围、审计、订阅边界 | `BR-028`、`DEC-075/085` |

## 4. 负责人观测模型

每个观测点必须同时具备：

```text
观测事实
+ 数据时间
+ 业务范围
+ 对象锚点
+ 责任人
+ 风险/异常原因
+ 允许动作
+ 处置后回读
```

禁止只有数字没有对象、只有告警没有责任人、只有入口没有下一步。

## 6. 可以进入概念原型的内容

- 四个负责人维度及其能力地图。
- 业务推进阶段、对象、观测点、责任人和下一步。
- App / 微信小程序 / Web 的职责差异和同源要求。
- 示例性经营事实、风险队列和对象处置流。
- 对利润、阈值和独立小程序壳层显式标注待确认。

## 7. 不可以进入概念原型的内容

- 新增业务状态、角色或权限。
- 把公司/门店经营利润草案写成确定口径。
- 把演示数字写成真实产品数据。
- 把站内提醒、材料到场或项目变更说成自动完成。
- 用前端默认 0、空数组或本地常量替代 Provider 事实。

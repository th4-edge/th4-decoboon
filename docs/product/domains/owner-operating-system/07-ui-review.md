# 装企负责人经营管理体系 · 概念原型 UI 评审

## 评审边界

- 对象：`docs/product/prototypes/owner-operating-system/index.html`
- 结论类型：概念原型 UI/交互评审
- 不是：生产 UI 验收、业务验收、独立验收或发布结论
- 证据目录：`docs/acceptance/runs/20261028-owner-operating-system-prototype/screenshots/`

## D1 设计意图

| 问题 | 结论 |
| --- | --- |
| 页面类型 | 负责人经营决策页 + 风险行动队列 + 业务推进观测图 + 企业管理页面 |
| 谁在什么状态下打开 | 企业负责人每天查看经营结果、异常、资金、组织与待处置事项 |
| 第一答案 | 今天最需要处理什么，为什么，谁负责，下一步是什么 |
| 唯一主行动 | 从当前观测点进入对象处置并回读事实 |
| 信息优先级 | 经营结论 → 风险对象 → 阶段观测 → 业务明细 |
| 与 App 差异 | Web 强调全局、批量、配置和深度分析；App 强调移动处置、审批与快速回读 |
| 与小程序差异 | 小程序仅作为轻量提醒与最短动作入口，独立壳层仍待确认 |

## 构图模板

- Web：经营管控中心壳层；左侧维度导航 + 顶部范围/搜索 + 负责人观测条 + 决策页/流程页/专业页。
- App：移动工作台；今日判断 → 风险队列 → 经营指标 → 阶段观测 → 固定底部导航。
- 微信小程序：轻量经营简报 → 待办 → 观测点 → 回 Web 继续处理。

## 状态清单

| 状态 | 原型表达 |
| --- | --- |
| 正常 | 服务端事实可读、责任人和下一步明确 |
| 加载 | 生产实现需骨架屏；本静态原型不模拟网络加载 |
| 失败 | 生产实现需“暂不可确认 + 重试”；项目成本抽屉演示缺失态 |
| 真实为空 | 不使用 0 伪装；保留“暂无”表达方案 |
| 无权限 | 跨店/跨租户不展示对象；生产需 403/404 + 可理解说明 |
| 会话过期 | 生产需返回登录并保留对象回跳 |
| 长内容/极端值 | 表格可滚动，手机壳层内部滚动；KPI 使用省略与完整事实入口 |
| 成本不完整 | 项目毛利显示“成本未完整”，不显示 0 |
| 利润口径未冻结 | 显示“口径待确认”，不显示确定金额 |

## 第一轮渲染与修正

| 问题 | 修正 |
| --- | --- |
| 外层层级高度超出 1000px 视口约 20px | 收紧缩放高度，外层不再产生无意义滚动 |
| 部分辅助文字小于 12px | 提升正文、标签、表格、移动端卡片字阶 |
| 浅灰辅助色与表面背景对比不足 | 加深中性辅助色，提高对比度 |
| 移动端预览被页面外框撑高 | 390×844 下手机壳层固定为可用视口高度，内容在手机内部滚动 |
| 四维能力只在菜单出现，整体认知不够直接 | 经营总览增加四维能力地图 |

## 第二轮渲染与检查

- 1440×1000：五页切换正常，Web 页面无横向溢出。
- 1024×900：侧栏折叠，主内容宽度 902px，无页面级横向溢出。
- 390×844：App 手机壳层 366×770，底部导航固定且在视口内；内容内部滚动。
- 微信小程序：轻量入口可切换五类内容。
- 风险抽屉：可打开、可用 Esc 关闭，显示对象事实、负责人判断、回读项和事实边界。
- 焦点：键盘 Tab 首次落在 Web 切换按钮，3px 可见焦点环。
- 控制台：0 error / 0 warning。

## 量规评分

| 维度 | 分数 | 依据 |
| --- | --- | --- |
| C1 视觉一致性 | 4 | 品牌绿、状态色、圆角、间距和字阶统一 |
| C2 信息层级 | 4 | 今日判断、风险对象、观测点、明细四层清楚 |
| C3 对齐与留白 | 3.5 | 卡片和表格统一栅格，信息密度高但分区明确 |
| C4 状态完整性 | 3.5 | 已覆盖成本缺失、利润待确认、无权限说明和失败边界；静态原型未模拟全部网络态 |
| C5 交互清晰度 | 4 | 五维切换、阶段选择、对象抽屉、下一动作和回读项明确 |
| C6 数据可读性 | 3.5 | 金额按口径分列，表格在 1024 可横向滚动；极端值需生产态继续验证 |
| C7 可访问性 | 3.5 | 语义按钮、可见焦点、文字+颜色状态、减少动效；尚未做屏幕阅读器实测 |
| C8 跨端与适配 | 3.5 | Web/App/小程序三档成立；小程序独立边界仍是产品缺口 |

平均：3.69 / 4。达到概念原型评审线，不等于生产 UI 验收通过。

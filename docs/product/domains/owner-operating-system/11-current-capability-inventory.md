> 性质：现状能力清单，不是页面重绘、不是生产能力承诺、不是独立验收结论。

## 1. 结论

本轮共梳理 **62 个能力组**：

| 维度 | 能力组 |
| --- | ---: |
| 业务推进 | 23 |
| 企业经营 | 18 |
| 运营工具 | 9 |
| 组织管理 | 9 |
| 横向支撑 | 3 |

按生产成熟度：

| 状态 | 数量 | 含义 |
| --- | ---: | --- |
| A | 41 | 生产可见主能力 |
| B | 18 | 部分覆盖/单端/只读/跨端待对账 |
| C | 1 | 后端或后台有，负责人前端入口不完整 |
| D | 1 | 未上线/设计中 |
| G | 1 | 口径或高风险阻塞 |

一句话判断：

```text
装得清已经向负责人提供了“从客户到项目、材料、收付款、工资、组织和经营分析”的大部分内部经营能力，
且 BOSS 在权限上是内部岗位能力超集；
但产品呈现仍是“Web 经营管控中心 + 移动端经营工作台 + 专业工作台组合”，
并不是一套已经完整收口的“企业经营管理操作系统”。
```

其中最强的部分是全业务链的专业操作能力；相对薄弱的是：

1. 负责人视角的经营口径统一；
2. 企业费用/报销与企业经营利润；
3. 多门店经营治理；
4. 售后、质保、复购；
5. 跨端入口与信息密度的一致性；
6. 把“有 Provider”变成“负责人能直接理解和触发”。

## 2. 状态口径

- **A**：生产可见主能力：生产分支存在明确入口/Provider，不等于已做独立全链验收
- **B**：部分覆盖：只覆盖单端、只读、局部入口、后端已具备但前端不完整，或跨端口径仍需对账
- **C**：后端/后台能力：Provider存在，但生产前端未见明确负责人入口
- **D**：未上线/设计中：尚未进入当前生产能力范围
- **G**：口径或高风险缺口：能力存在但正式展示/使用仍受业务裁决阻塞

> “A”只代表生产分支存在明确入口或 Provider，**不代表已做完整独立验收**。  
> “App/小程序”按当前同一套 uni-app 移动端事实盘点，不能将同一端能力重复算成两套产品能力。

## 3. 四维能力总览

### 3.1 业务推进

负责人实际可以沿：

```text
客户 → 房屋 → 量房 → 设计 → 报价 → 合同 → 项目 → 施工 → 材料 → 变更 → 验收/整改 → 收付款 → 交付
```

完成大部分内部岗位动作。BOSS 可以一人连续执行，但业务状态机仍需逐步推进并留痕。

### 3.2 企业经营

负责人可以看：

- 签约额、回款额、应收、应付、资金台账；
- 项目成本、成本完整性与项目毛利；
- 工资、提成、考勤、工人工资；
- 经营漏斗、报价转化、渠道、区域和订单结构；
- 风险预警、经营目标、组织效能和员工排行；
- 门店范围下钻与未归属门店提示。

但**公司/门店经营利润、企业费用分摊、非项目收入与税务利润**仍未形成可正式展示的冻结口径。

### 3.3 运营工具

负责人可维护报价项目库、套餐模板、付款/施工计划模板、设计模板、合同/凭证模板、材料/供应商主数据和品牌对外信息。  
这些属于“企业标准层”，影响未来业务，不回溯历史单据。

### 3.4 组织管理

负责人可管理企业、门店、成员、邀请、调岗调店、停用/恢复/离职、客户交接、订阅席位和部分审计。  
组织能力按固定岗位角色与 Company/Store/Team/Self 范围运行，不通过新增部门或重复角色解决权限问题。

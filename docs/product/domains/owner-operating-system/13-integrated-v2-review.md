# 负责人经营管理整合版 V2 · 交互设计评审

## 设计命题

在不削弱 BOSS 全业务链能力的前提下，把负责人从“超级操作员”拉回“经营者”。

结论模型：

```text
权限能力层：BOSS 是企业内部岗位能力超集
经营观测层：负责人默认看结果、风险、目标、标准和组织
执行工作面层：需要亲自处理时，在当前对象内切换岗位执行方式
```

## 页面结构

| 层级 | 页面 | 负责人问题 |
| --- | --- | --- |
| 经营总览 | 今日判断、风险、经营指标、业务停留点 | 今天先看什么？ |
| 业务推进 | 客户到交付八阶段、观测点、当前对象 | 哪里停住，谁负责，下一步是什么？ |
| 企业经营 | 签约、回款、应收应付、成本、目标、风险 | 经营结果是否健康？ |
| 运营标准 | 报价库、套餐、计划、模板、主数据 | 企业用什么标准支撑下一单？ |
| 组织管理 | 企业、门店、员工、邀请、交接、权限、审计 | 谁在什么范围做什么？ |

## 交互创新点

1. **不铺角色菜单**：一级导航固定五个经营维度。
2. **对象内亲自处理**：从当前业务对象打开执行抽屉，再选择业务员、设计师、项目经理、财务或店长方式。
3. **身份与工作视图分离**：切换到岗位执行方式时，BOSS 身份、Company 数据范围和审计主体都不变。
4. **生产能力可追溯**：点击能力 chip/工具卡，打开该能力的生产状态、Web/移动端覆盖、对象、Provider、观测点和缺口说明。
5. **利润缺失态显式表达**：成本不完整时不显示毛利，经营利润显示口径待确认。
6. **移动端不复制 Web**：移动端只保留经营判断、风险处置、经营事实和快速回读。

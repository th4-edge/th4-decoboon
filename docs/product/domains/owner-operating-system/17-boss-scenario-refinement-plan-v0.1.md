# 企业负责人 · 现有产品场景细化与功能核验计划 v0.1

> 日期：2026-10-29  
> 依据：`USER-DEC-20261029-001`、`USER-DEC-20261022-001`、`BR-028`、`BR-030`  
> 基线：本地集成版 1.0.73  
> 状态：`PLAN_READY / NO_UI_REDESIGN`  
> 性质：在现有 App/Web 上做场景细化、功能核验和增量补强；不更换导航，不重做产品壳层。

## 1. 产品定位

### App

- 手机端高频、快速、时效优先。
- 主要解决：即时查看、提醒响应、轻量确认、现场记录、快速回读。
- 继续使用现有五 Tab：`工作台 / 客户 / 项目 / 财务 / 我的`。
- 不给负责人增加一套新的移动端一级信息架构。

### Web

- 电脑端低频、完整、深度优先。
- 主要解决：跨对象比较、批量处理、复杂编辑、财务对账、组织与标准治理。
- 继续使用现有角色菜单、专业工作台和深链。
- 不以“经营大屏”替换现有可用页面。

## 2. 负责人首批真实场景

### A. 移动端 · 每日经营巡检（高频）

| 项 | 内容 |
| --- | --- |
| 使用人 | 企业负责人 |
| 触发 | 早上或外出途中打开 App |
| 目标 | 3 分钟内判断今天是否需要亲自介入 |
| 现有路径 | BOSS 工作台 → 经营指标/风险项目/经营动态 → 对应客户、项目或财务页面 |
| 要验证 | 指标是否同源；风险是否有原因、责任人、下一步；失败是否可恢复；返回是否保留上下文 |
| 允许改动 | 原位补充判断文案、风险入口、空/失败/无权限态；不更换底部 Tab |
| 成功结果 | 负责人能快速确认 1–3 个需要关注的对象并进入处理 |

### B. 移动端 · 风险提醒即时处理（高频）

| 项 | 内容 |
| --- | --- |
| 触发 | 收到应收逾期、材料延迟、变更待决策或项目风险提醒 |
| 目标 | 打开通知后直接进入当前对象和既有业务动作 |
| 现有路径 | 消息通知 → 项目/客户/财务对象 → 原业务页面 |
| 要验证 | 通知对象是否存在；权限是否正确；状态是否最新；动作后是否回读 |
| 允许改动 | 优化通知到对象的锚点、返回路径、状态摘要；不引入新的对象工作台 |
| 成功结果 | 从通知到完成轻量处理无需重新搜索对象 |

### C. Web · 周度经营对账（低频、复杂）

| 项 | 内容 |
| --- | --- |
| 触发 | 负责人每周核对签约、回款、应收、项目成本和风险 |
| 目标 | 发现异常、定位对象、分派或进入财务/项目页面处理 |
| 现有路径 | 现有经营分析/财务工作台/项目页面 |
| 要验证 | 期间口径、门店范围、成本完整性、异常对象下钻、金额回读 |
| 允许改动 | 补字段、补说明、补下钻、补筛选、补异常态；不替换现有页面 |
| 成功结果 | 负责人能从结果指标下钻到具体项目或单据并看到同一口径 |

### D. Web · 跨项目风险与责任检查（低频、复杂）

| 项 | 内容 |
| --- | --- |
| 触发 | 多项目并行时需要看延期、材料、变更、验收和资金风险 |
| 目标 | 比较多个项目，按责任人和风险类型筛选并进入现有页面处置 |
| 现有路径 | 风险队列、项目列表、项目详情、财务页面 |
| 要验证 | 风险排序、责任人、金额、项目状态和处置权限 |
| 允许改动 | 增强现有列表、筛选、排序和下钻；不新建第二套项目工作台 |
| 成功结果 | 负责人能在一个现有页面完成比较并进入原业务处置路径 |

## 3. 功能核验矩阵

每个场景按以下行核验：

| 维度 | 必须回答 | 证据 |
| --- | --- | --- |
| 入口 | 用户从哪里进入，是否符合现有习惯 | 页面截图、路由 |
| 对象 | 是否携带客户/项目/单据锚点 | URL、页面状态 |
| 数据 | 字段、金额、状态、更新时间是否同源 | Provider、API 响应 |
| 权限 | BOSS/财务/店长/门店范围是否正确 | 跨端/跨范围用例 |
| 动作 | 当前允许动作是否唯一、明确 | 页面按钮、服务端校验 |
| 异常 | 空、失败、无权限、冲突如何恢复 | 七态证据 |
| 回读 | 动作后对象、风险、金额、待办是否刷新 | reload 证据 |
| 价值 | 是否减少查找、判断、重复录入或交接 | 场景走查 |
| 兼容 | 原导航、返回、筛选、深链是否保留 | 回归用例 |

## 4. 本轮不做什么

- 不重命名现有 App 五 Tab。
- 不替换现有 Web 左侧导航。
- 不把所有角色能力合并成新的负责人五域壳层。
- 不做以视觉展示为主的交互换皮。
- 不在没有真实场景证据时加减业务字段。
- 不改变权限、金额、成本、状态机或 DDL。
- 不把探索原型作为生产实施基线。

## 5. 核验输出

首批完成后输出：

1. 每个场景的现状路径和页面证据；
2. 能力“可用 / 部分可用 / 不可用 / 暂不可确认”；
3. 问题清单，按 `阻塞业务 / 影响判断 / 体验优化` 分类；
4. 最小增量改造建议；
5. App/Web 同源矩阵；
6. 回归与真实用户验证计划。

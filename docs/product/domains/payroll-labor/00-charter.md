# 员工薪酬与薪资经营 · 业务域章程

- Domain：`payroll-labor`
- Owner：codex
- Created：2026-10-21
- North Star：财务按方案A完成员工薪酬日常操作，BOSS保留最终确认与高风险动作，薪酬方案、考勤、提成、工资单、应付、发放和工资条形成可追溯闭环。

## 1. 业务问题

- 当前场景：10～30 人家装企业由财务按月维护薪酬方案、考勤和提成，生成工资单，BOSS 最终确认后由财务发放。
- 谁遇到问题：企业财务、BOSS、店长和员工本人。
- 当前损失/风险：
  - Web 财务页只覆盖部分动作，薪酬方案缺少完整列表、编辑、停用和删除入口；
  - Web 新增薪酬方案没有提交服务端必填的月应出勤天数，按现有契约会失败；
  - 工资单确认仍被提成完整性阻断，违反工资与提成解耦规则；
  - 财务无法在同一条 Web 工资单链路上完成复核、退回和状态查看；
  - 前端确认按钮权限与后端角色门禁不一致，存在“看得到但点不了”的体验与权限风险。
- 希望达到的结果：财务可在 Web 完成方案 A 授权内的全部日常操作；BOSS 只在最终确认和高风险动作上介入；每一步金额、权限、状态和审计可追溯。

## 2. 目标角色

| 角色 | 主要目标 | 关键动作 | 不负责什么 |
| --- | --- | --- | --- |
| 财务 | 准确完成日常薪酬制单、复核和发放 | 维护薪酬方案、考勤、提成；生成工资单；提交确认；发放；处理可恢复异常 | 不最终确认工资单，不删除草稿，不做高风险作废 |
| BOSS | 对工资结果承担最终责任 | 最终确认、草稿删除、高风险作废与异常处置 | 不替代财务完成日常录入和发放，除非单人企业按顺序操作 |
| 店长 | 查看本店薪酬与考勤构成 | 按既有规则查看、确认考勤；跨店操作拒绝 | 不获得财务未授权的高风险动作；确认/作废边界继续受既有缺口约束 |
| 员工本人 | 确认本人工资结果 | 查看本人已发放工资条、本人考勤和提成 | 不查看他人薪酬、全员工资单和财务明细 |

## 3. 本期范围

- 必须做：
  - 固化方案 A：财务日常操作，BOSS 最终确认、草稿删除和高风险作废；
  - 修复 Web 薪酬方案、考勤、工资单链路中的现有阻断；
  - 补齐财务日常操作所需的列表、编辑、状态和可恢复路径；
  - 保证工资与提成独立结算，负向调整仅在下期工资抵扣；
  - 保证薪酬方案、考勤、工资单、应付、发放、工资条金额与状态一致；
  - 保持 App 与 Web 能力键及后端角色校验一致，不允许形成只能换端完成的闭环断点。
- 暂时不做：
  - 个税、社保、公积金申报和代缴；
  - 银行代发接口和完整 HR 入转调离；
  - 已发放工资历史重算或覆盖；
  - 报价项目库价格维护，归入报价域独立批次。
- 明确排除：
  - 以 `Payable(Salary)` 冒充工人工资或员工工资；
  - 用前端本地计算替代服务端工资、提成、应付和台账结果；
  - 给财务扩权到 BOSS 最终确认或草稿物理删除。

## 4. 主链

```text
财务维护薪酬方案
→ 财务/店长录入并确认月度考勤
→ 财务计提提成，回款触发释放
→ 财务生成工资单草稿并复核
→ 财务提交待确认
→ BOSS 最终确认，生成员工工资应付并计成本
→ 财务发放，核销应付并写资金台账
→ 发放完成后工资条对员工本人可见
→ 退款/离职/跨期形成负向调整，进入下期抵扣
```

## 5. 关键不变量

1. 工资单金额、提成释放、应付和台账金额只能由服务端事实推导，前端不得自行计算正式金额。
2. 方案 A 下工资单最终确认仅 BOSS；财务可制单、复核、提交确认和发放，但不可最终确认、删除草稿或执行高风险作废。
3. 工资与提成独立结算；提成未结清只作提示，不阻断工资确认。
4. 已确认、已发放和已关闭的工资历史不可静默覆盖；异常通过下期调整或受控反向流程处理。
5. 企业、门店、员工数据范围由登录员工在服务端解析，跨企业、跨店、员工访问他人必须拒绝。
6. 任一应计成本缺失时不得计算伪利润；本次薪资改造不得以 0 成本作为未知值。

## 6. 金额/成本/权限边界

- 金额：工资项、扣款、实发、应付、发放、台账和工资条全部以服务端结果为准，口径引用 `BR-015`、`BR-038`。
- 成本：工资单确认时形成员工工资应付并进入成本事实；应付不等于付款，发放不等于重复计成本。
- 权限：沿用 `Finance`、`Boss`、`StoreManager`、员工本人固定角色；不新增重复角色。
- 数据范围：总部财务按企业范围，门店财务按归属门店；店长限本店；员工本人只见本人。
- 高风险动作：最终确认、草稿物理删除、作废、已确认后反向处理必须保留 BOSS 或另行裁决的审批责任。
- 审计：每个节点记录操作人、对象、动作、前后状态、金额、企业/门店范围、时间和幂等键。

## 7. 成功指标

- 产品：财务在 Web 可完成方案 A 内全部日常动作，无需因页面缺失切换到其他端。
- 数据质量：工资单、工资项、应付、发放、台账和工资条金额一致；重复确认/发放不产生重复财务事实。
- 业务结果：BOSS 只在最终确认和高风险动作介入；财务异常有明确修复路径。
- 安全：跨企业、跨店、跨员工访问测试全部拒绝；成本/薪资敏感字段不越权返回。

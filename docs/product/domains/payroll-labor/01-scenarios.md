# 员工薪酬与薪资经营 · 真实业务场景

## 场景 A：财务完成 10 月工资制单并交由 BOSS 确认

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 某 12 人家装企业总部财务小王；BOSS 李总 |
| 触发事件 | 2026 年 10 月工资周期开始结算，员工考勤和提成已具备结算条件 |
| 前置条件 | 员工存在有效薪酬方案；财务有企业范围权限；工资月份未关闭；相关员工考勤可确认 |
| 当前动作 | 财务核对薪酬方案，补录或修正月度考勤，计提本月提成，生成工资单草稿并逐项核对应发、扣款和实发 |
| 系统下一步 | 服务端按薪酬方案、考勤、提成和调整计算工资项；财务复核后提交待确认；BOSS 最终确认，服务端生成员工工资应付并准备工资条 |
| 成功结果 | BOSS 确认成功；财务看到已确认工资单和应付；员工工资应付金额与工资项合计一致 |
| 异常/恢复 | 薪酬方案失效或缺失时提示先补方案；考勤未确认时阻止提交并给出考勤入口；工资项为空或实发为负时显示原因和修复路径；提成未结清只提示，不阻断 |
| 涉及对象 | CompensationScheme、AttendanceSummary、CommissionItem、PayrollSheet、PayrollItem、Payable、Payslip |
| 状态变化 | 方案 Active；考勤 Pending → Confirmed；工资单 Draft → Pending → Confirmed；工资项 Draft → Confirmed |
| 金额/成本/权限 | 财务可制单、复核、提交确认；最终确认仅 BOSS；金额以服务端为准；总部财务企业范围 |
| 证据/来源 | `BR-015`、`BR-038`、`DEC-046`、`DEC-047`；用户 2026-10-21 方案 A 裁决 |

## 场景 B：财务发现考勤录入错误，在工资确认前修正并重建草稿

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 某 20 人家装企业门店财务小陈 |
| 触发事件 | 工资单草稿生成后，财务发现一名设计师的病假天数录错，尚未提交 BOSS 确认 |
| 前置条件 | 工资单为 Draft；对应考勤尚未进入工资单正式事实，或允许按受控流程退回重算；操作人在本店数据范围 |
| 当前动作 | 财务打开月度考勤，修改病假/事假等异常天数，确认考勤后重新生成该周期工资单草稿并核对差额 |
| 系统下一步 | 服务端重新读取确认后的考勤和薪酬方案，重建未确认工资项并重算应发、扣款、实发；旧草稿结果不形成应付和工资条事实 |
| 成功结果 | 修正后的工资单金额正确；操作留痕；财务可继续提交 BOSS 最终确认 |
| 异常/恢复 | 若工资单已确认或已形成应付/支付事实，系统拒绝直接修改并提示走退回、反向或下期调整；跨店员工返回无权访问；重复重建保持幂等 |
| 涉及对象 | AttendanceSummary、PayrollSheet、PayrollItem、CompensationScheme |
| 状态变化 | 考勤 Confirmed；工资单 Draft 重算后仍为 Draft；确认后不得直接重建 |
| 金额/成本/权限 | 门店财务仅本店；服务端重算；不得修改已确认/已发放历史；修正前后差异可见 |
| 证据/来源 | `BR-015`、`BR-038`；`GAP-060` 仅影响店长边界，不扩大门店财务权限 |

## 反向场景

- 越权：财务调用 `payroll/sheet/update` 最终确认工资单必须 403；门店财务访问他店员工、考勤、工资单必须 404/403。
- 重复提交/幂等：重复确认不重复生成应付和工资条；重复发放不重复写付款、核销和台账；工资单重复重建不产生重复工资项。
- 跨租户/跨项目：跨企业员工、项目、工资单和提成不可见；提成项目必须属于登录人可见范围。
- 数据缺失：无有效薪酬方案、考勤未确认、工资项为空、实发为负时阻断并给出可执行下一步。
- 状态不满足：已确认工资单不可直接改考勤或删除；已发放工资不可回写历史；已支付提成只能下期负向调整。
- 金额/成本不完整：工资应付、发放、台账和工资条必须同额；任何成本未知不得用 0 冒充已完整。

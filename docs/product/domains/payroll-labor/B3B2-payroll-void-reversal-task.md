# B3B2 · 工资单作废与反向应付/成本研发任务

## 状态

- 批次：`B3B2`
- 变更级别：L3（状态机、金额、成本、删除/作废、DDL）
- 业务裁决：`DEC-093`、`DEC-043`、`T12-BIZ-20261023-002`
- 编码授权：未授权
- DDL/迁移：必须先设计并获用户确认
- 当前门禁：`BLOCKED_DDL_AND_VERSION_DESIGN`

## 目标

在保留工资单历史可追溯的前提下，实现 BOSS 对 Draft/Pending/Confirmed 未支付工资单的受控作废，以及对应的反向财务事实。

## 业务边界

1. 作废仅 BOSS；
2. Draft/Pending 可作废；Draft 无任何财务事实时可物理删除；
3. Confirmed 未支付只能先反向员工工资应付和原确认成本再作废；
4. PartialPaid/Paid/Closed 禁止作废；
5. 作废原因必填；保留原状态、金额、操作人、时间、反向金额和幂等键；
6. 工资条在发放完成后才对员工可见，作废后不得可见；
7. 重复作废不得重复反向应付或成本。

## 编码前必须完成

- 现有 `db_payroll_sheet` 的 `company + period` 唯一约束与作废版本关系设计；
- 工资单/工资项/应付/成本/工资条反向字段与幂等键设计；
- DDL、历史数据兼容、备份和回滚方案；
- 用户对 DDL 与生产发布边界的确认；
- 反向应付/成本的真实 SQL 与事务边界测试。

## 不做

- 不物理删除 Pending 及以上工资单；
- 不回滚已发放工资；
- 不修改已发放历史，不允许 PartialPaid/Paid/Closed 作废；
- 不将提成应付或工资条未实现字段冒充为已完成。

## 验收

- Draft/Pending 作废和原因留痕；
- Confirmed 未支付反向应付/成本后作废；
- PartialPaid/Paid/Closed 全部拒绝；
- 重复作废幂等；
- 作废后工资条不可见；
- 迁移/回滚/备份与跨企业、跨店、员工越权证据齐备。

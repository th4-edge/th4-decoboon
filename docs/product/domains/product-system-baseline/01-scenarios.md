# 装得清产品体系基线 · 真实业务场景

本文件验证角色基线是否覆盖真实装企工作，而不是只覆盖菜单。所有场景为合成数据，业务事实以 `zhuangdeqing-business` 编号为准。

## 场景 A：成长型单店，六岗位协同完成一单

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 企业负责人张伟、店长王敏、业务员李娜、设计师陈晨、项目经理赵强、财务吴濛 |
| 触发事件 | 客户咨询一套 118㎡ 住宅，企业希望从客户登记推进到签约、施工、材料、验收和回款 |
| 前置条件 | 企业已开通；门店、团队、员工和角色有效；客户明确房屋；报价与合同主数据可用 |
| 当前动作 | 业务员登记客户并预约量房；设计师完成量房、设计和报价；店长复核签约；项目经理接收项目并推进施工；财务登记收付款；业主确认阶段验收 |
| 系统下一步 | 每个角色只看到本岗位待办和当前对象；完成后系统生成下游对象、责任人和下一步；同一事实在 App/Web 回读一致 |
| 成功结果 | 客户、房屋、设计、报价、合同、项目、材料、验收、应收和成本形成可追溯链路 |
| 异常/恢复 | 业务员请假时客户转交；设计师变更时方案和报价归属留痕；项目经理被替换时项目成员和待办同步；跨门店操作被拒 |
| 涉及对象 | Customer、Property、Measure、Requirement、Scheme、Quote、Contract、Project、MaterialPlan、Acceptance、Receivable、Receipt、ProjectCostContext |
| 状态变化 | 客户新登记→跟进→已量房→已设计→已报价→已签约；合同待签→已签→已生效；项目待开工→施工中→验收中→已完工 |
| 金额/成本/权限 | 业务员不确认签约；设计师不确认生效；财务按门店范围收付款；BOSS 可全链路代办但不得代业主确认；成本不完整时利润为空 |
| 证据/来源 | `CAP-006`、`BR-001`、`BR-002`、`BR-028`、`DEC-065`、`DEC-075`、`DEC-080` |

## 场景 B：三门店企业，负责人看全局、店长看本店、财务按归属分层

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | BOSS、A 店店长、B 店店长、总部财务、A 店财务、跨店项目经理 |
| 触发事件 | 企业新增第二、第三家门店，需要同时管理客户、项目、资金和组织 |
| 前置条件 | 多门店能力已开通；员工归属明确；总部财务归属默认总店；项目成员关系有效 |
| 当前动作 | BOSS 按门店筛选全企业；店长处理本店客户和项目；总部财务看全企业汇总；门店财务只看本店；项目经理只处理参与项目 |
| 系统下一步 | 跨店合计只对 BOSS/总部财务开放；门店角色传入其他门店参数时返回 403/404；项目参与关系不覆盖经营负责人 |
| 成功结果 | 数据范围、门店筛选和经营责任人一致；不同角色看到同一门店数字时不出现口径差 |
| 异常/恢复 | 店长请求他店客户被拒；门店财务收到他店应收查询失败；项目经理尝试修改非参与项目失败；员工调店后历史事实不回溯 |
| 涉及对象 | Company、Store、Team、Employee、Customer、Contract、Project、Receivable、Ledger、BusinessTarget |
| 状态变化 | 无业务状态跨越，重点验证范围切换、查询与写入边界 |
| 金额/成本/权限 | 门店财务不获得财务高危动作；店长仅本店高危动作；总部财务不自动获得工资单确认；BOSS 保留企业治理 |
| 证据/来源 | `DEC-065`、`DEC-067`、`DEC-075`、`DEC-076`、`DEC-080`、`GAP-046` |

## 场景 C：一人装企，BOSS 连续承担多个岗位

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | BOSS 同时承担业务员、设计师、项目经理和财务工作 |
| 触发事件 | 小微企业没有专职团队，需要一个人完成从获客到收款 |
| 前置条件 | BOSS 账号有效；企业范围可用；业务对象状态和必填信息完整 |
| 当前动作 | BOSS 登记客户、量房、设计、报价、发起并确认合同、接项目、采购、验收申请、收付款、结算 |
| 系统下一步 | 系统按能力超集放行内部动作，但状态机仍逐步推进；每步记录动作人、动作、状态和时间；外部确认不能被 BOSS 身份替代 |
| 成功结果 | 一人也能形成完整、可审计的业务和账务事实链 |
| 异常/恢复 | 漏填报价基线时阻断签约；未生效合同不能建项目；成本不完整时利润为空；业主验收必须由业主本人或按正式代登记规则处理 |
| 涉及对象 | Customer、Property、Design、Quote、Contract、Project、Purchase、Receivable、Payment、Payroll、OwnerAccess |
| 状态变化 | 与正常主链相同，不允许因同一人操作而合并或跳过节点 |
| 金额/成本/权限 | BOSS 内部能力超集；企业范围；不能替代业主/客户确认；外部主体能力不并入 |
| 证据/来源 | `BR-028`、`DEC-032`、`DEC-015` |

## 场景 D：业主多项目授权与撤销

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 业主、企业负责人、项目经理 |
| 触发事件 | 同一业主先后有两套房屋项目，需要分别授权查看和验收 |
| 前置条件 | 客户档案存在；每个项目有独立项目码或邀请授权；授权状态有效 |
| 当前动作 | 业主通过项目授权进入本人项目；企业员工只查看项目事实；授权撤销后不得继续访问 |
| 系统下一步 | 业主只能看到被授权的项目；多项目之间不串数据；验收确认必须绑定具体项目、阶段和轮次 |
| 成功结果 | 业主看到的是企业当前真实进度、材料、变更、验收和付款事实，而不是企业内部的成本、利润或员工信息 |
| 异常/恢复 | 授权撤销后旧链接失效；项目不匹配返回无权限；跨企业邀请失败；员工预览不能生成业主确认事实 |
| 涉及对象 | Customer、CustomerAccess、Project、Acceptance、AcceptanceRound、Notice |
| 状态变化 | 授权 active→revoked；验收待确认→确认/驳回；员工预览不改变业务状态 |
| 金额/成本/权限 | 业主可见合同金额与应收事实，不可见内部成本、利润和供应商执行价；确认动作只属于业主主体 |
| 证据/来源 | `OBJ-001`、`DEC-009`、`DEC-015`、`DEC-074`、`GAP-055`、`GAP-056` |

## 反向场景

- 越权：业务员访问他店客户；设计师替 BOSS 确认合同生效；财务确认工资单；店长访问他店台账；项目经理修改非参与项目。
- 重复提交/幂等：重复签约、重复生效、重复收款、重复付款、重复生成工资单和重复验收确认。
- 跨租户/跨项目：同一微信账号绑定不同企业；同一客户多房屋项目串链；业主项目授权跨企业复用。
- 数据缺失：客户地址存在但房屋档案缺失；合同无报价基线；项目无明确房屋；成本存在缺失应计项。
- 状态不满足：未接受报价进入合同；未生效合同创建项目；未完成整改直接确认验收。
- 金额/成本不完整：报价成本快照缺失；采购未到货却计入实际成本；利润以 0 成本计算；工资与提成重复发放。

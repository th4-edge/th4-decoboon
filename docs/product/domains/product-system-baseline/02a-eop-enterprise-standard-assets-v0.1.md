# B2A-1 企业运营标准资产矩阵 v0.1

> 范围：报价项目库/成本标准、套餐模板、付款计划模板、施工计划模板、单据与凭证模板。
> 不包含：供应商/材料主数据、经营目标与指标字典、设计模版方案库；这些进入后续 EOP 切片。
> 状态：`draft`，用于业务结构对账，不是新业务规则。

## 一、本切片解决的问题

企业运营层最容易混淆的是：

- 报价项目库是不是“报价”？
- 套餐模板和客户套餐报价有什么区别？
- 付款计划模板和应收计划是什么关系？
- 施工计划模板和项目施工计划是什么关系？
- 凭证模板是财务凭证还是打印版式？
- 这些资产是否有版本、发布、停用和历史快照？

本切片只处理“企业标准资产本身”，不展开客户报价、合同、项目、应收等业务实例。

## 二、统一分层

```text
平台基线（可选）
→ 企业标准资产/模板
→ 业务引用
→ 业务快照
→ 财务事实
```

企业运营资产必须明确：

| 属性 | 业务含义 |
| --- | --- |
| 来源 | 平台基线、企业自建、历史迁移 |
| 状态 | 草稿、启用/发布、停用 |
| 版本 | 是否可追溯、何时递增 |
| 默认 | 是否作为新建业务的默认选择 |
| 引用保护 | 已被业务使用后能否删除或修改 |
| 快照 | 业务实例是否冻结当时的名称、价格、节点和配置 |
| 端覆盖 | App/Web 是否都有完整查看与维护闭环 |

## 三、五类标准资产对照

| 能力 | 当前对象 | 当前状态模型 | 版本模型 | 默认/启停 | 历史保护 | 主要维护角色 | App | Web |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 报价项目库/成本标准 | CatalogItem | `active=true/false` | 无显式版本字段 | 启停；无默认 | 被引用禁止删除；报价行保存价格、成本、公式等快照字段 | BOSS、店长、财务 | 有维护 | 有维护 |
| 套餐模板 | PackageTemplate + PackageLine | 无状态字段 | 无版本字段 | 无启停、无默认、无发布 | 客户报价行会保存金额/成本等快照，但套餐模板本身无版本来源 | BOSS、店长；财务只读且可见成本 | 有维护 | 未找到管理页 |
| 付款计划模板 | 平台基线 + CompanyPaymentPlan | Draft/Enabled/Disabled | 版本字段；编辑已启用模板时版本+1 | 支持默认；仅启用可设默认 | 合同复制节点并记录来源 code/version | BOSS、店长 | 有维护 | 未找到管理页 |
| 施工计划模板 | 平台基线 + CompanyConstructionPlan | Draft/Enabled/Disabled | 版本字段；编辑已启用模板时版本+1 | 支持默认；仅启用可设默认 | 合同复制阶段并记录来源 code/version | BOSS、店长 | 有维护 | 未找到管理页 |
| 单据/凭证模板 | 平台预设 + DocumentTemplate + DocumentTemplateVersion | 版本状态 Draft/Published/Disabled；模板有当前发布版本 | 不可变版本历史；发布时形成版本 | 发布/停用 | DocumentRecord/VoucherRecord 绑定 templateVersion | BOSS、店长、财务 | 有维护 | 有维护 |

## 四、逐项分析

### EOP-01 报价项目库/成本标准

**定位**

企业级可售项目与标准成本主数据，不是客户报价单。

**已具备**

- 统一覆盖施工、主材、软装、定制、电器、综合项目；
- 支持材料+人工、仅材料、仅人工、固定总价等计价方式；
- 支持销售价、标准成本、公式、工艺、规格、品牌和分类；
- 支持批量导入、停用、删除保护；
- 被报价、设计、套餐、任务、材料计划等引用时禁止物理删除；
- 报价行会快照价格、成本、公式、工艺等关键业务事实；
- 服务端对成本做角色裁剪。

**当前问题**

1. 没有显式版本号，业务快照虽然保存了值，但无法直接回答“这条报价来自报价项目库哪个版本”。
2. 名称中同时存在“报价项目库”“材料库”“统一家装材料库”等不同称呼，容易与客户报价、材料主数据混淆。
3. 销售价、标准成本、供应商采购价、结算价是不同口径，但页面和对象层仍需统一术语。
4. 已被引用禁止物理删除、未引用可删除，与“发布版本不可变”模型不同；是否足以保护历史需要业务确认。

### EOP-02 套餐模板

**定位**

企业级套餐产品定义，不是客户套餐报价。

**已具备**

- 套餐名称、面积、牌价、折扣、成本；
- 套餐分区、项目行、数量系数、包含/扣减/升级/替换；
- 客户报价可从套餐模板生成报价行；
- 报价行保存金额、成本、品牌、规格、数量等快照；
- 成本对设计师、业务员、项目经理等服务端裁剪。

**当前问题**

1. `PackageTemplate` 没有状态、版本、发布、启停和默认标识。
2. 模板更新直接覆盖当前记录，没有历史版本可查。
3. 客户报价虽然保存快照值，但没有套餐模板版本来源，难以追溯“来自哪个套餐版本”。
4. 套餐模板维护权限为 BOSS/店长，财务只可查看成本；与报价项目库财务可维护的口径不同。
5. Web 未找到套餐模板管理入口，App 有完整管理页，违反“App/Web 能力一致且完整”。
6. 平台基线、企业套餐、客户套餐报价三层关系未在 UI 和命名中稳定呈现。

### EOP-03 付款计划模板

**定位**

企业级默认收款节点标准，不是合同付款计划、应收计划或实际收款。

**已具备**

- 平台基线与公司自定义模板；
- Draft/Enabled/Disabled；
- 版本、来源基线 code/version、默认模板；
- 比例合计 100%、节点数量、触发阶段等校验；
- 合同签约时复制为企业合同快照，记录来源 code/version；
- 历史合同不随企业模板修改而回溯。

**当前问题**

1. 当前写权限为 BOSS/店长，财务只读；财务是否应维护需继续按业务口径确认。
2. Web 未找到付款计划模板管理入口，App 有管理页。
3. 设计文档与当前代码在维护角色描述上存在历史差异，以当前正式决策为准。
4. 模板修改后版本+1，但节点历史是否保留完整旧版本需通过测试/数据证据确认。

### EOP-04 施工计划模板

**定位**

企业级标准施工阶段与工期，不是项目实际施工计划。

**已具备**

- 平台基线与公司自定义模板；
- Draft/Enabled/Disabled；
- 版本、来源基线 code/version、默认模板；
- 阶段编码唯一、工期范围、总工期、验收方式；
- 合同签约复制阶段和工期，记录来源 code/version；
- 历史合同、项目计划不随模板修改回溯。

**当前问题**

1. 当前写权限为 BOSS/店长；PM 是否参与维护需业务确认。
2. Web 未找到施工计划模板管理入口，App 有管理页。
3. 企业模板、合同施工计划、项目阶段/任务三层对象在页面上的命名和导航仍需统一。
4. 合同变更、项目排期是否可以从模板外新增阶段，需要与 BIZ 项目域对账。

### EOP-05 单据与凭证模板

**定位**

企业业务/原始单据的版式与字段模板，不是法定会计记账凭证。

**已具备**

- 平台行业预设、企业复制/自建；
- 不可变版本、发布、停用；
- 当前发布版本、版本历史、发布人和时间；
- 历史单据绑定模板版本；
- 覆盖报价、材料、收款、付款、合同等业务类型；
- 报销、差旅、工资、退款、质保金等预设只代表单据版式；
- App/Web 均有管理入口；
- BOSS/店长/财务可维护。

**当前问题**

1. “凭证模板”容易被理解为会计记账凭证，需要稳定对外说明为“业务/原始凭证模板”。
2. 报销模板存在，不等于报销申请/审批/付款业务闭环存在；不得混用。
3. 模板字段变化与历史单据展示需要用真实记录验证版本回读。
4. 平台预设、企业模板、业务单据三层关系需在信息架构中继续明确。

## 五、横向结构问题

### EOP-X01：生命周期不统一

| 资产 | 生命周期完整度 |
| --- | --- |
| 报价项目库 | 有启停、有引用删除保护，无显式版本 |
| 套餐模板 | 无状态、无版本、无发布/停用/默认 |
| 付款计划模板 | 状态、版本、默认、合同快照完整度较高 |
| 施工计划模板 | 状态、版本、默认、合同快照完整度较高 |
| 单据/凭证模板 | 不可变版本、发布/停用、历史版本绑定完整度最高 |

结论：企业运营资产目前没有统一生命周期标准，套餐模板是最明显短板。

### EOP-X02：跨端能力不一致

App 有：
- 报价项目库；
- 套餐模板；
- 付款计划模板；
- 施工计划模板；
- 凭证模板。

Web 有：
- 报价项目库；
- 凭证模板；
- 未找到套餐模板、付款计划模板、施工计划模板管理页。

按用户 2026-10-22“App/Web 强制能力一致且完整”的裁决，这三类模板需要补齐 Web 管理能力或明确裁决为不再维护的企业运营例外。

### EOP-X03：企业标准角色不统一

当前维护角色：

| 资产 | BOSS | 店长 | 财务 | 其他内部角色 |
| --- | --- | --- | --- | --- |
| 报价项目库 | 维护 | 维护 | 维护 | 只读 |
| 套餐模板 | 维护 | 维护 | 只读、可见成本 | 只读 |
| 付款计划模板 | 维护 | 维护 | 只读 | 只读 |
| 施工计划模板 | 维护 | 维护 | 只读 | 只读 |
| 单据/凭证模板 | 维护 | 维护 | 维护 | 受入口/字段限制 |

需要业务确认：这是按资产类型有意分工，还是历史演进造成的不一致。

### EOP-X04：平台基线与企业的边界不统一

- 付款/施工计划：平台基线 + 企业复制 + 合同快照；
- 单据模板：平台预设 + 企业复制 + 单据版本；
- 报价项目库：当前以企业数据为主，平台是否存在行业基线需确认；
- 套餐模板：当前只有企业套餐，平台是否有行业套餐基线需确认。

### EOP-X05：命名与导航分散

同一类“企业标准资产”分散在：
- App：`我的 → 经营工具`、`财务`、模板页面；
- Web：设计师/财务菜单、凭证模板；
- 后端：catalog、pack、plan、document 四个域。

目前没有统一的“企业运营/经营标准”入口和目录结构。

## 六、建议的目标模型（待裁决）

### 6.1 统一资产元数据

所有企业标准资产建议具备：

```text
id
company
code
name
scope: Platform | Company | Store（若未来支持）
source: Baseline | Company | Migration
status: Draft | Published | Disabled
version
publishedAt
publishedBy
defaultFlag（适用时）
usedBy（引用计数或引用摘要）
```

### 6.2 统一生命周期

```text
草稿
→ 发布/启用
→ 业务引用
→ 修改产生新版本
→ 旧业务继续引用旧快照
→ 停用
→ 未引用才允许删除
```

### 6.3 统一业务快照

所有业务实例至少记录：

```text
sourceId
sourceCode
sourceVersion
snapshotContent
```

不能只保存业务结果，不保留来源和版本。

### 6.4 统一跨端

企业标准资产的查看与维护必须在 App/Web 都有完整业务闭环；交互可不同，但能力不得单端缺失。

## 七、待业务裁决问题

1. 套餐模板是否必须补状态、版本、发布/停用和默认能力？
2. 套餐模板、付款计划模板、施工计划模板是否必须补 Web 管理端？
3. 企业标准资产的维护角色是否统一为 BOSS/店长，财务仅在价格/成本/单据类资产中维护，还是应按资产分别定义？
4. 报价项目库是否需要显式版本；若不需要，如何用快照值和引用保护满足追溯？
5. 套餐模板是否需要平台行业基线，还是只允许企业自建？
6. “报价项目库/成本库/材料库”的正式产品名称和对外术语如何统一？
7. 设计模版方案库是否纳入 EOP 企业运营资产，还是归入 BIZ 设计业务？

## 八、结论

```text
企业运营资产已存在：是
业务价值已体现：是
生命周期统一：否
版本治理统一：否
App/Web 能力完整一致：否
角色所有权统一：否
业务事实已完全冻结：否
```

当前最优先的结构问题不是新增功能，而是：

1. 把企业运营资产作为同一产品层统一管理；
2. 补齐套餐模板的状态/版本/快照；
3. 补齐三类模板的 Web 管理闭环；
4. 明确各类资产由谁维护；
5. 统一企业标准与客户业务单据的命名和导航。

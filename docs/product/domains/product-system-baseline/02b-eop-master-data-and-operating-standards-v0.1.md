# B2A-2 企业主数据、经营标准与设计模版边界 v0.1

> 范围：供应商/材料主数据、经营目标与指标字典、设计模版方案库。
> 状态：`draft + user-confirmed supplier price direction`。2026-10-22 用户确认：供应商价格以材料下单路线为准，`PartnerPrice` 不再作为价格概念和价格真源。
> 前置：`02-business-operation-architecture-v0.1.md`、`02a-eop-enterprise-standard-assets-v0.1.md`。

## 一、本切片解决的问题

1. 供应商档案、供应商采购价、材料供应关系和材料分类分别属于哪一层？
2. 采购单、到货、退货为什么不属于企业运营主数据？
3. 经营目标是指标、计划还是财务事实？
4. 指标字典由谁定义，是否允许企业修改？
5. 设计模版方案库到底属于企业运营资产还是业务运营设计实例？
6. 这些能力在 App/Web 和角色权限上是否完整一致？

## 二、总体分类结论

| 能力 | 业务层 | 类型 | 说明 |
| --- | --- | --- | --- |
| Partner 合作方 | EOP 企业运营 | 主数据 | 供应商、工厂、劳务班组、安装、物流、其他服务商 |
| PartnerPrice 合作方价格 | 历史兼容 | 待收口 | 用户已确认不再作为供应商价格概念和价格真源；仅保留存量与迁移问题 |
| MaterialSupplier 材料供应关系 | EOP 企业运营 | 主数据 | 结构化材料标识与供应商关系；当前与 PartnerPrice 有字段重叠 |
| MaterialCategory 主材分类 | EOP 企业运营 | 主数据 | 企业级分类与默认损耗率 |
| 采购单/到货/退货/库存 | BIZ 业务运营 | 真实业务事实 | 项目采购与履约，不属于主数据 |
| BusinessTarget 月度经营目标 | EOP 企业运营 | 经营计划事实 | 公司/门店月度目标值，不是指标定义 |
| MetricDefinition 指标字典 | EOP 企业运营 | 口径标准 | 指标的公式、范围、时间口径和缺失值规则 |
| DesignTemplate 设计模版方案库 | EOP 企业运营 | 可复用标准/模板 | 企业/门店/个人三级模版；无价格，只引用报价项目库 |
| Design 设计方案 | BIZ 业务运营 | 真实业务实例 | 从客户、房屋、模版实例化后形成实际方案 |

## 三、EOP-06 供应商与材料主数据

### 3.1 当前对象

| 对象 | 当前定位 | 关键字段/规则 |
| --- | --- | --- |
| Partner | 统一合作方 | 类型：供应商、定制工厂、劳务班组、安装班组、物流、其他服务商；状态 Active/Disabled；品牌集合；税号、账期模式、账期天数、截账日、银行信息 |
| PartnerPrice | 合作方-报价项目库价格 | 采购价、人工/班组价、最小起订量、交货天数、账期、生效/失效日期、启停 |
| MaterialSupplier | 材料-供应商供应关系 | 结构化 materialKey、CatalogItem 可空、品牌/规格/型号/单位、参考采购价、MOQ、交期、账期、生效区间 |
| MaterialCategory | 主材分类 | 企业级分类、默认损耗率、排序、启停 |

### 3.2 当前链路

```text
Partner 合作方
→ 材料计划/材料下单
→ 选择供应商、材料、数量、采购价
→ 采购单/到货/结算
→ 实际成本
```

供应商价格以材料下单产生的采购事实为准，不再以 PartnerPrice 作为新价格真源。

```text
MaterialSupplier 材料供应关系
→ 按 materialKey 匹配供应商
→ 无匹配时按 Partner.brands 品牌兜底
→ 兜底价读取 PartnerPrice
```

### 3.3 已具备

- 合作方与项目库均按企业隔离；
- 合作方有启停、账期和品牌信息；
- PartnerPrice 有生效期、启停、采购价/人工价和标准成本同步；
- MaterialSupplier 支持多供应商、结构化材料标识、品牌兜底；
- 维护角色主要为 BOSS、店长、财务；
- 采购单/到货/结算等业务事实不混入主数据。

### 3.4 当前结构问题

1. **供应商主数据缺少正式业务对象卡**：`CAP-006`/`GAP-058 G5` 明确供应商主数据仍为业务知识空白或缺口；`PartnerPrice` 已按用户裁决退出新价格主链。
2. **PartnerPrice 与 MaterialSupplier 字段重叠**：`PartnerPrice` 不再作为供应商价格概念；`MaterialSupplier` 和材料下单采购事实如何承接价格、交期和账期仍需专项冻结。
3. **材料身份表达不统一**：PartnerPrice 直接绑定 CatalogItem；MaterialSupplier 使用结构化 materialKey，也可绑定 CatalogItem，但允许 CatalogItem 为空。
4. **供应商页面命名混用**：合作方、供应商、材料供应商、供应商往来、供应商采购价等概念在代码和菜单中并存。
5. **Web 缺少完整供应商主数据维护**：Web 有供应商往来台账和材料下单输入框；App 有供应关系、采购价和供应商选择页。
6. **Web 材料下单仍使用供应商名称文本输入**：输入提示“需已在合作方建档”，但没有像 App 一样使用供应商专用选择器。
7. **采购执行价和标准成本口径复杂**：PartnerPrice、MaterialSupplier.purchasePrice、CatalogItem.costPrice、采购单价格和结算价必须严格分层，不能互相覆盖。

## 四、EOP-07 经营目标与指标字典

### 4.1 当前对象

| 对象 | 当前定位 | 当前能力 |
| --- | --- | --- |
| BusinessTarget | 公司/门店月度目标 | 签约额、回款额、毛利、在建项目数；公司目标 store 为空；门店目标绑定 store |
| MetricDefinition | 指标口径说明 | key、名称、定义、公式、来源、时间范围、数据范围、包含/排除、缺失值、示例、状态 |
| 指标查询 | 只读字典 | 通过 `statistic/metric/dictionary` 返回 |
| 目标查询/保存 | BOSS/店长 | `statistic/target/info`、`statistic/target/save` |

### 4.2 已具备

- 公司目标和门店目标分开存储，不自动相加；
- 店长锁定本店目标，BOSS 可读取/保存公司或指定门店目标；
- 目标包含签约、回款、毛利和在建项目数；
- 指标字典描述了公式、时间范围、数据范围、包含/排除和缺失值；
- App/Web 都有经营目标和指标解释的展示入口。

### 4.3 当前问题

1. **经营目标和指标字典属于两种不同性质**：一个是月度计划值，一个是口径标准，不应都简单归为“指标”。
2. **目标维护权限仅 BOSS/店长**：财务可见经营指标但不能维护目标，是否符合企业实际需要待裁决。
3. **目标值是否允许财务/团队负责人参与**尚未形成统一矩阵。
4. **指标字典是代码内的只读定义**，不是企业可维护的数据；企业若要自定义指标或目标维度，需要新模型。
5. **目标毛利依赖成本完整性**，成本不完整时的目标/达成口径必须继续遵守 `MET-002` 和成本完整性规则。
6. **同名指标跨端展示和公式仍有历史差异**，例如“本月回款”等口径历史冲突需要专项对账，不在本文件自行修正。

## 五、EOP-08 设计模版方案库

### 5.1 当前对象与生命周期

| 维度 | 当前实现 |
| --- | --- |
| 对象 | DesignTemplate、DesignTemplateVersion、DesignTemplateRoom、DesignTemplateItem |
| 归属 | Personal / Store / Company |
| 状态 | Draft / Published / Disabled |
| 版本 | 有版本；发布后不可变；修改生成新版本 |
| 价格 | 不承载任何价格字段，只引用 CatalogItem |
| 实例化 | 生成真实 Design/空间/分项，实例化即快照 |
| 权限 | 企业/门店级 BOSS、店长；个人级本人；设计师可建个人级 |
| Web | 有方案模版库、编辑、发布、停用、复制、实例化 |
| App | 按 `DEC-050` 当前无入口，仅 Web |
| AI | 可生成草稿，不能直接发布或生成正式报价 |

### 5.2 分类判断

从业务性质看，设计模版方案库属于 **EOP 企业运营**：

```text
企业/门店/个人可复用标准
→ 区域骨架、分项、公式
→ 实例化为具体房屋的 Design
```

但它有个人级归属，和普通企业模板不完全相同；企业级、门店级和个人级应分别展示来源与权限。

### 5.3 当前边界冲突

`DEC-050` 明确“本期只在 Web 建设，App 不提供入口（含只读）”。

后续用户已裁决“App/Web 每类能力必须一致且完整”。两者直接冲突：

- 如果设计模版属于强制能力，App 必须补完整闭环；
- 如果设计模版属于专业 Web 工具，需要重新明确 App 例外；
- 不得用“Web 主端”直接解释，因为用户已取消默认单端豁免。

## 六、角色与 App/Web 对照

| 能力 | 主要维护角色 | App | Web | 判断 |
| --- | --- | --- | --- | --- |
| 合作方档案 | BOSS、店长、财务 | 部分维护 | 未找到完整维护页 | 跨端不完整 |
| 合作方采购价 | BOSS、店长、财务 | 有维护 | 未找到完整维护页 | 跨端不完整 |
| 材料供应关系 | BOSS、店长、财务 | 有部分 | 未找到完整维护页 | 跨端不完整 |
| 主材分类/损耗率 | BOSS、店长、财务 | 部分 | 部分 | 需继续对账 |
| 月度经营目标 | BOSS、店长 | 有 | 有 | 角色范围待确认 |
| 指标字典 | 系统/平台标准 | 只读解释 | 只读解释 | 代码定义，非企业可编辑 |
| 设计模版方案库 | BOSS、店长、设计师本人 | 无入口 | 有 | 与最新跨端裁决冲突 |

## 七、建议的目标边界

```text
EOP 企业运营
├── 合作方主数据
├── 合作方价格/供应关系
├── 材料分类与默认损耗率
├── 经营目标计划
├── 指标口径标准
└── 设计模版方案库

BIZ 业务运营
├── 客户/房屋
├── 设计方案
├── 材料计划/采购/到货/退货
├── 项目施工/验收
└── 业务实例快照

FIN 财务运营
├── 应收/应付
├── 收付款/台账
├── 实际成本/利润
├── 薪酬/费用
└── 凭证
```

## 八、待业务裁决问题

1. 合作方主数据是否以 Partner 为唯一对象？MaterialSupplier 应作为唯一供应关系，还是仍保留其他供应关系模型？
2. 材料下单路线中的采购价、交期、账期如何回写到供应关系和标准成本？PartnerPrice 存量字段如何废弃和迁移？
3. 供应商/合作方主数据是否必须提供 Web 完整维护页？Web 下单是否必须改用供应商选择器？
4. 经营目标是否只由 BOSS/店长维护，财务是否参与目标设定或只查看？
5. 指标字典是否只由平台维护，企业是否允许自定义指标？
6. 设计模版方案库正式归入 EOP 还是 BIZ？在最新 App/Web 一致裁决下，App 是否必须补入口，还是形成明确例外？
7. 设计模版个人级、门店级、企业级三类资产的可见/复制/停用规则是否已完整冻结？

## 九、结论

```text
供应商/材料主数据：已实现但业务口径未完全成体系
经营目标：已实现，分类与权责需澄清
指标字典：有口径标准，但为代码定义
设计模版方案库：业务规则较完整，跨端边界冲突
App/Web 一致性：供应商主数据和设计模版均未闭合
```

下一步不应直接开发，而应先通过专项会话完成上述业务裁决，再分别形成供应商主数据、经营目标/指标、设计模版跨端三个研发切片。

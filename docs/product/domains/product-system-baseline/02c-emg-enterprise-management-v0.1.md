# B2B 企业管理矩阵 v0.1

> 范围：企业主体、品牌、门店、团队、员工、邀请、角色与数据范围、订阅席位、安全审计。
> 状态：`draft`，用于企业管理层对账。
> 前置：`02-business-operation-architecture-v0.1.md`。

## 一、企业管理层定义

企业管理回答：

```text
谁代表企业？
企业有哪些门店和团队？
谁属于哪个组织？
谁可以邀请、停用、调岗、调店、离职和交接？
企业当前购买了什么订阅、使用了多少席位和门店？
谁能查看组织与安全审计？
```

企业管理不承载客户、项目、采购、财务等业务事实。

## 三、关键对象与边界

### 3.1 Company

- 企业主体与对外服务信息；
- 企业信息由 BOSS 维护；
- App/Web 均有维护入口；
- 对外客服电话不得使用员工个人手机号；
- 企业品牌和署名信息来自企业自身配置，平台不代填。

### 3.2 Store

- 企业内一级组织归属；
- 客户、报价、合同、项目、财务单据和员工均带门店归属；
- 门店启停仅 BOSS；
- 默认总店是总部财务和门店范围派生的重要锚点；
- 默认总店调整与门店列表候选问题已进入 `PI-20261022-001`，不在本文件重复裁决。

### 3.3 Team

- Team 必须有 leader、store、company；
- 团队负责人角色已冻结；
- 当前团队主要由邀请 TeamLeader 时创建或在邀请时指定团队；
- 当前没有独立 `team/save`、`team/update` Provider；
- TeamLeader 冻结后，团队是否继续作为活跃组织能力、谁创建和维护团队，是新的边界问题。

### 3.4 Employee 与 Invite

- 员工只有单一主岗位；
- 财务账号必须归属门店；总部财务为默认总店财务；
- App 有成员列表、详情、岗位调整、停用、恢复、注销、交接；
- Web 有部分邀请、财务调店和组织效能；
- 后端支持 `company/member/update`、suspend、resume、resign、transfer、handover；
- 前端尚未把完整员工生命周期统一到双端。

### 3.5 Subscription

- 订阅主体是企业；
- 门店数和席位数是套餐容量；
- 企业版所有业务模块不因套餐差异而拆模块；
- App 有订阅、套餐、订单与门店资源展示；
- Web 当前未找到对应企业订阅页；
- 平台运营端是独立跨企业管理系统，不应与租户 BOSS 订阅页混为一体。

### 3.6 Audit

- 后端存在安全日志、成员日志和操作日志能力；
- 当前 App/Web 未找到完整审计查询入口；
- 哪些角色能看哪些日志、日志字段如何脱敏、是否双端必须，需要专项裁决。

## 五、当前结构问题

### EMG-X01：TeamLeader 冻结后团队生命周期未重新定义

Team 依赖 leader，而新 Team 主要通过邀请 TeamLeader 创建。TeamLeader 冻结后：

- 是否允许新团队存在？
- 团队是否继续作为组织能力？
- 店长/BOSS 如何在 Web/App 维护团队？
- TeamLeader 存量团队如何处理？

必须专项裁决。

### EMG-X02：员工生命周期跨端不对称

App 有较完整的员工管理流程，Web 只有部分邀请和财务调店。按“两端一致且完整”要求，需要明确哪些操作双端必须，哪些因现场/电脑端特性采用不同交互但保持完整闭环。

### EMG-X03：门店管理入口不完整

后端有创建、启停门店能力，但前端完整入口待盘。默认总店调整和总部财务范围问题已在 `PI-20261022-001`。

### EMG-X04：订阅仅企业侧 App 可见

Web 未找到完整订阅页。企业 BOSS 在电脑端无法查看和管理订阅资源，和企业管理场景不完整。

### EMG-X05：安全审计没有产品化展示

后端日志存在，但没有明确的 App/Web 审计查询入口和角色可见矩阵。组织变更、邀请、停用、离职和权限调整需要可追溯展示。

### EMG-X06：组织调整与历史业务归属的影响提示不足

调岗、调店、停用、离职和交接会影响：
- 数据范围；
- 待办与风险；
- 客户/项目归属；
- 财务范围；
- 通知接收。

页面需要明确提示和交接结果，而不能只修改员工字段。

## 六、建议的目标边界

```text
BOSS
- 企业主体、订阅、门店、默认总店、角色治理、全公司审计

店长
- 本店员工邀请/管理、团队维护（若团队继续保留）、本店审计子集

员工
- 查看本人身份、组织、角色和必要审计提示

平台运营
- 独立运营端，不进入租户业务页面
```

## 七、待业务裁决问题

1. TeamLeader 冻结后，Team 是否继续作为活跃组织能力？Team 的创建、改名、负责人、成员调整由谁完成？
2. 员工邀请、调岗、调店、停用、恢复、离职、交接中，哪些是 App/Web 双端必须能力？
3. BOSS 邀请财务必须显式选择目标门店已在 Web/App 部分出现，是否适用于所有角色？
4. 门店新建、启停、默认总店调整是否全部进入 BOSS 企业管理页？
5. 企业订阅与席位是否必须在 Web 提供完整查看和管理入口？
6. 安全审计在 App/Web 的角色可见范围、字段和交互如何定义？

## 八、结论

```text
企业主体管理：已实现且双端基本一致
门店管理：后端有，前端待收口
团队管理：受 TeamLeader 冻结影响，生命周期不清
员工管理：App 较完整，Web 不完整
订阅管理：App 有，Web 缺
安全审计：后端有，产品入口缺
```

企业管理应作为一个专项闭环处理，而不是在角色矩阵里继续加列。

## 一、结论先行

1. **装得清财务是“项目经营账 + 资金台账 + 经营核算”，不是法定总账。** 对外边界仍是“管项目和钱，不管税和账”；凭证是业务单据套打，不是会计记账凭证。`[业务 DEC-016 / DEC-005]`

2. **四本管理账必须共用同一事实源。**
   - 合同与收入账：合同、变更、应收、收款；
   - 成本与利润账：报价成本、采购/到货/结算、应付、工资；
   - 资金与现金账：收款、付款、退款、冲正、手工流水；
   - 风险与核校账：逾期、缺口、成本不完整、跨账不一致。  
   `[业务 财务总纲] [代码 Receivable / Payable / Ledger / Settlement]`

3. **应收不是收入，应付不是成本，付款不是成本。**
   - 合同生效生成应收计划；
   - 收款核销应收并写资金流水；
   - 采购下单形成应付；
   - 到场/结算形成实际材料成本；
   - 付款只核销应付并写资金流水。  
   `[业务 DEC-MP-01 / DEC-016]`

4. **财务门店范围已形成一套派生模型。** 只有一个 `Finance` 角色：
   - 默认总店财务 → Company；
   - 普通门店财务 → Store；
   - 店长本店记账写权限与门店财务接近，但不获得 BOSS 专属高危动作。  
   `[业务 DEC-065 / DEC-075 / DEC-081]`

5. **当前财务主链已有较完整实现，但存在三类结构性风险：**
   - 部分按 ID 写入的应收、应付、付款、退款、结算和凭证路径未统一执行门店数据范围，存在同企业跨店写入风险；
   - 项目成本与实际毛利仍混用 P1 预计成本、P2 采购价、P3 结算价，代码中的 `actualCost/costComplete/profit` 语义与最新 `BR-045` 存在冲突；
   - 企业费用只有 `PayableType.Expense`、手工企业费用和报销模板，没有独立的费用申请、报销、审批、付款和归集对象。

6. **App/Web 财务能力大体对齐，但高危动作和历史承接仍有差集。**
   - App 有收款冲正，Web 当前无入口；
   - Web 财务写按钮允许店长生成凭证，但后端 `document/voucher/build` 只允许 BOSS/财务；
   - 账龄报表有后端 Provider，App/Web 均未接页面；
   - 期初资金 App 有完整页面，Web 仅有 API/摘要，缺独立页面；
   - 报销闭环双端均缺失。  
   `[页面] [代码]`

### 2.1 对象职责

| 对象 | 事实职责 | 不承担 |
| --- | --- | --- |
| `Receivable` | 客户在何时应收多少钱 | 实际到账、收入确认、会计核算 |
| `Receipt` | 某一应收节点实际收到的钱 | 项目最终收入、发票、会计收入 |
| `ReceiptRefund` | 按原收款退回客户的钱 | 收款冲正、供应商退款 |
| `ReceiptReversal` | 原收款登记错误或未实际到账的全额冲正 | 客户真实退款 |
| `Payable` | 企业何时应向谁付款 | 实际付款、项目成本、会计负债 |
| `Payment` | 实际向应付对象支付的钱 | 成本发生、费用确认 |
| `PayableSettlement` | 一笔付款核销哪些应付 | 会计凭证 |
| `Ledger` | 实际资金流入/流出或手工补账 | 应收应付余额本身 |
| `Settlement` | 项目收入、成本、利润和关闭快照 | 公司总账 |
| `PayrollSheet` | 某月员工工资计算与确认结果 | 银行代发、个税申报 |
| `VoucherRecord` | 收付款等业务事实的打印载体 | 法定会计记账凭证 |
| `OpeningBalance` | 接管日账户起始余额 | 收入、支出、利润 |

## 三、业务事实 → 财务事实主链

### 3.1 合同与应收

```text
合同签约/生效
→ 合同付款计划快照
→ 应收计划 Receivable
→ 到期未收 Overdue
→ 收款 Receipt
→ 累计已收 / 状态刷新
→ Ledger(Income)
```

当前规则：

- 合同生效时生成应收计划；
- 应收状态：`Pending → Partial → Received`，到期未收进入 `Overdue`；
- 收款金额必须大于 0，且不得超过应收余额；
- 收款必须绑定项目、应收、客户和资金账户；
- 收款成功后同步累计 `receivedAmount` 并写且只写一次资金流水；
- 收款幂等键在租户内唯一，重复网络请求不得重复核销或写流水。  
  `[代码 Receivable / Receipt Save / FinanceAccessContext]`

### 3.2 收款冲正与客户退款

两者不是同一事实：

```text
收款冲正：原收款登记错误/未到账 → Receipt.Reversed → 反向 Ledger → 恢复应收
客户退款：原收款真实有效 → ReceiptRefund → Ledger(Expense) → 形成净回款冲减
```

当前规则：

- 收款冲正仅 BOSS 全企业、店长本店；财务不自动获得；
- 首批只允许全额冲正；
- 原收款有退款、有效凭证或已发放提成时禁止冲正；
- 冲正后写 `ReceiptReversal`、反向台账、恢复应收、反释放未发放提成；
- 客户退款按原收款追溯，金额不得超过可退余额；
- 退款写资金支出并触发提成负向调整；
- 退款与冲正均要求幂等。  
  `[业务 BR-050 / DEC-077] [代码 ReceiptReversalContext / ReceiptRefundContext]`

### 3.3 应付与付款

```text
材料下单 / 工人工资 / 项目款 / 费用
→ 应付 Payable
→ 付款 Payment
→ 应付核销 PayableSettlement[]
→ Ledger(Expense)
```

当前规则：

- 应付类型包括：材料款、工人工资、员工工资、员工提成、项目款、供应商款、费用支出、其他；
- 付款金额不得大于所选应付待付合计；
- 一笔付款可核销同一供应商/对象的多张应付，但必须有核销明细；
- 付款后刷新应付状态并写资金流水；
- 付款只有失败/重试，不可物理删除；
- 应付调整不得低于已付金额。  
  `[代码 Payable / Payment / PayableSettlement]`

### 3.4 资金台账

`Ledger` 是资金流水的统一归集处：

| 来源 | 方向 | 说明 |
| --- | --- | --- |
| `Receipt` | Income | 客户实际收款 |
| `Refund` | Expense | 客户退款 |
| `Payment` | Expense | 供应商/员工/工人等实际付款 |
| `ReceiptReversal` | Expense | 原收款冲正 |
| `Manual` | Income/Expense | 无来源单据的补账 |
| `Adjustment` | Income/Expense | 调整冲销 |

手工记账边界：

- 只补“没有来源单据”的账；
- 禁止手工登记客户工程款、材料款、工人工资、项目款等已有闭环事项；
- 账务用途固定为：项目零星成本、企业费用、其他收入、资金往来、其他；
- 项目零星成本必须关联项目，计入项目实际成本；
- 关联项目其他收入计入项目收入；
- 资金往来不进入项目毛利或公司经营利润；
- 作废、更正、冲正重记只允许 BOSS 或店长本店，且保留修订轨迹。  
  `[业务 DEC-016 / 财务总纲 / BR-034] [代码 ManualLedgerContext / Ledger Update/Delete]`

## 四、项目成本、利润与结算

### 4.1 三种价格与成本事实

| 代号 | 名称 | 来源 | 用途 | 当前风险 |
| --- | --- | --- | --- | --- |
| P1 | 报价成本价 | 合同/报价成本快照 | 预计成本 | 当前代码会回退到 `actualCost` |
| P2 | 采购执行价 | 采购单/明细 | 应付、暂估成本 | 到货时先按 P2 计成本 |
| P3 | 结算价 | 结算确认 | 实际材料成本唯一最终来源 | 结算后修正应付与实际成本 |

业务正式规则：

```text
预计成本 = P1 汇总
实际材料成本 = P3（已结算）> P2（已定价）> 成本不完整
P1 不得进入实际成本
任一应计成本缺失 → costComplete=false → 毛利/毛利率=null
```

当前代码事实：

- `ProjectCostContext.contractActualCost` 在缺少 P2/P3 时回退合同成本、报价成本或目录成本；
- `ProjectCostContext.actualCost` 在缺少实际成本时回退当前标准成本或预计成本；
- 没有采购记录时，不因“尚未采购”自动标记成本不完整；
- 财务项目报告使用 `max(ProjectCostContext.actualCost, Σ应付成本)` 作为项目总成本；
- 这使 P1、预计成本、采购价、应付金额和实际成本在不同项目状态下可能混入同一个 `actualCost/profitAmount`。  
  `[业务 BR-045 / DEC-072 / MET-002] [代码 ProjectCostContext / FinanceReportContext]`

**结论：** 当前代码不能直接证明满足“P1 不进入实际成本、实际毛利只在应计成本齐备后输出”的最新业务规则。已登记 `PI-20261022-017`。

### 4.2 项目结算

```text
Draft（待确认）
→ Confirmed（已确认）
→ Closed（已关闭）
→ RetentionPending / RetentionReleased（质保金路径）
```

当前规则：

- 项目必须处于 `Accepting` 或 `Finished` 才可确认结算；
- 关闭结算要求应收、应付全部结清；
- 有质保金时关闭后进入 `RetentionPending`，释放后进入 `RetentionReleased`；
- 关闭结算后项目进入 `Settled`；
- 成本不完整时结算利润和毛利率必须为空；
- 已关闭结算不得直接反改，如需调整走新流程。  
  `[代码 Settlement / finance settlement Update / FinanceReportContext]`

待确认：

- 结算金额与当前合同额、变更、扣款、奖励、质保金的最终公式；
- 结算关闭与项目关闭、合同关闭、质保到期的关系；
- 成本不完整时是否允许确认结算、是否允许关闭；
- 已确认但未关闭的结算如何重算和留痕。  
  部分已进入 B2E 对账，成本语义问题转 `PI-20261022-017`。

## 五、员工薪酬与提成

### 5.1 主链

```text
薪酬方案
→ 月度考勤
→ 提成计提/回款释放
→ 工资单草稿
→ BOSS 确认
→ 员工工资/提成应付并计成本
→ 发放 Payment
→ 资金台账
→ 工资条对本人可见
→ 关闭
```

业务规则：

- 工资单确认最终动作人仅 BOSS；财务制单、复核和发放；
- 财务不能确认工资单；
- 考勤未确认、工资项为空、实发为负时禁止确认；
- 提成未结清不阻断工资确认，因工资与提成已解耦；
- 工资与提成均按实发金额形成应付和成本；
- 项目/企业成本归属唯一，禁止重复计成本；
- 工资条在发放完成后才对本人可见；
- 草稿且无财务事实仅 BOSS 可删除；非草稿只能作废/退回重算；
- 已发放工资不得回改，退款/离职/跨期走下期负向调整；
- 敏感字段服务端裁剪。  
  `[业务 DEC-017 / DEC-043 / DEC-046 / DEC-047 / BR-038]`

当前实现：

- 薪酬方案、考勤、提成、工资单、工资项、应付、付款、工资条均有对象与 Provider；
- App/Web 均有薪酬闭环入口；
- 2026-10-21 员工薪酬 B1 已完成独立验收 PASS，覆盖 Web CRUD、App 精度、三角色权限和三档视口。  
  `[代码 payroll/*] [验收 20261021-payroll-b1-independent]`

## 六、凭证与单据

### 6.1 凭证能力定位

```text
Ledger 来源事实
→ 选择同项目/对方/款项类型的有效流水
→ 绑定模板版本
→ 生成 PDF
→ 凭证记录 VoucherRecord + 明细 VoucherItem
→ 重打读取同一记录并累计打印记录
```

当前规则：

- 凭证是业务单据套打，不是会计记账凭证；
- 金额只取来源流水，不二次计算；
- 合并条件：收款方/付款方 + 项目 + 款项类型相同；
- 模板有不可变发布版本；
- 重打不新建金额事实，保留打印记录与修订轨迹；
- 历史模板升级不重写已归档 PDF；
- 客户版不展示内部成本；
- 凭证可见范围按财务数据范围裁剪。  
  `[业务 DEC-005 / DEC-020 / BR-006 / BR-018] [代码 VoucherContext / DocumentTemplate*]`

## 八、历史承接与期初

```text
承接批次
→ 在跑项目范围确认
→ 期初应收/应付
→ 期初资金账户余额
→ 接管前成本快照
→ 当前工地确认
```

当前规则：

- 期初应收、应付、成本必须确认；
- 期初资金按账户和接管日保存，不计入收入/支出/利润；
- 首次业务发生后承接项目锁定，不能撤回，只能调整或冲正；
- 双轨对账只记录差异，不直接改金额。

## 九、角色与数据范围

### 9.1 财务角色

| 角色 | 数据范围 | 主要动作 |
| --- | --- | --- |
| BOSS | 全企业 | 全部财务动作、工资确认、结算关闭、作废/更正/冲正 |

## 十四、验收最低要求

### 应收与收款

- 合同金额、应收合计、已收、未收、逾期可对账；
- 收款不得超应收余额，重复提交幂等；
- 收款冲正与客户退款边界不可混用；
- 退款后净回款、应收余额、提成调整一致；
- 资金台账与收款/退款/冲正来源一一对应；
- 跨企业、跨门店、非项目权限拒绝。

### 应付与付款

- 采购、工资、费用、项目款来源可追溯；
- 应付、已付、未付、逾期可对账；
- 一笔付款多笔核销有明细且总额准确；
- 付款不得超应付余额，重复付款幂等；
- 付款只写一次资金流水，不重复计成本；
- 跨企业、跨门店、非财务/店长权限拒绝。

### 成本与利润

- P1、P2、P3 不混用；
- 预计毛利、动态毛利、最终毛利有明确展示名称和可用条件；
- 成本缺失时 `costComplete=false`，利润与毛利率为空；
- 项目卡片、项目账本、结算和驾驶舱金额一致；
- 历史快照不回写；
- 真实数据多状态样本可对账。

### 薪酬与凭证

- 工资单 BOSS 确认，财务不得确认；
- 发放工资条才可见；
- 工资、提成、应付、付款、台账金额一致；
- 凭证金额只取来源流水，模板版本可追溯；
- 重打不重复生成金额事实；
- 店长/财务/总部财务/BOSS 凭证权限与门店范围一致。

### 企业费用与报销（若裁决纳入）

- 申请、审批、付款、凭证、归集完整；
- 费用归属唯一，不重复进项目成本或企业费用；
- 票据附件和审批留痕可回读；
- 手工企业费用与独立报销边界不混用；
- App/Web 能力边界一致。

## 十五、结论

B2E 表明装得清的财务骨架已经成立：

```text
合同 → 应收 → 收款/退款/冲正 → 台账
采购/工资/费用 → 应付 → 付款 → 台账
项目成本 → 项目结算 → 毛利
员工薪酬 → 工资单 → 应付/付款 → 工资条
收付款 → 凭证模板 → PDF 归档
期初资金 + 历史承接 → 接管后经营
```

但当前还不能说财务体系已经完整：

```text
主链有对象，但部分写路径缺门店范围
成本有数字，但预计/实际/结算口径仍混用
凭证有生成，但高危动作跨端不一致
费用已有对象与业务边界裁决，但代码/页面/独立验收尚未完成
```

因此下一批结论不是立即改代码，而是：

```text
PI-20261022-016 → 财务写入与门店/高危动作裁决（已取得）
PI-20261022-017 → 成本与实际毛利口径裁决（BIZ_DECIDED，待 COST-D1 授权）
PI-20261022-018 → 企业费用/报销对象与闭环裁决（已取得）
```

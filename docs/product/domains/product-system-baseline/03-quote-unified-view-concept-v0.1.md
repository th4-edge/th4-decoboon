# 报价统一视图概念与契约 v0.1

> 日期：2026-10-22
> 状态：产品概念分析 + 待研发会话消费的协调契约。
> 用户方向：无论 App、Web、业主端、项目、合同、客户钻取还是报价入口，同一报价必须是统一视图；必须支持按区域、按类型查看，交互参考 Web 设计师报价工作台。

## 一、概念定义

“报价统一视图”不是所有端使用同一个页面布局，而是：

```text
同一个 quoteId + version
→ 同一组报价事实
→ 同一组行项目
→ 同一套区域/类型分组语义
→ 同一套金额、状态和缺失值口径
→ 不同场景只改变上下文、权限、动作和展示密度
```

允许的场景差异只有：

- 标题和返回路径；
- 宿主对象上下文，例如客户、项目、合同；
- 可执行动作，例如编辑、提交、签约、打印；
- 可见字段，例如成本仅 BOSS/店长/财务可见；
- 交互密度，例如 Web 三栏表格、App 单列卡片；
- 是否可切换版本。

不允许的场景差异：

- 同一版本报价显示不同总额或不同明细；
- 一个入口按区域、另一个入口按类型后无法对齐；
- 合同/项目显示“最新报价”而不是绑定合同接受的版本；
- 前端自行合并、重算或改变报价行数量；
- 成本、公式、供应商执行价等内部字段泄漏给业主；
- 接口失败时用空数组或 0 伪装“无报价”。

## 二、统一报价核心模型

统一视图至少包含以下事实。

### 2.1 报价头

| 字段组 | 内容 |
| --- | --- |
| 身份 | quoteId、报价编号、标题、version、status |
| 来源 | 客户、房屋、设计方案、套餐模板、业务来源 |
| 时间 | 创建、提交、接受、驳回、转项目时间 |
| 金额 | subtotal、设计费、管理费、折扣、税率、税额、total/subtotal、金额口径说明 |
| 成本 | cost、costComplete（仅成本可见角色） |
| 责任 | 报价负责人、门店、团队 |
| 状态 | 当前状态、下一步、阻断原因、可执行动作 |

### 2.2 报价行

| 字段组 | 内容 |
| --- | --- |
| 身份 | 行 ID、来源 CatalogItem/DesignItem/PackageLine 引用 |
| 空间 | 区域 Space、区域名称、未归属时“综合项目” |
| 分类 | ItemType、业务分类 category、项目名称、品牌、系列、规格、单位 |
| 数量 | quantity、quantityFormula、是否需要补尺寸 |
| 价格 | pricingMode、销售单价、材料价、人工价、固定总价 |
| 金额 | amount、折扣金额、行角色、是否包含、设计差异类型/状态 |
| 内部 | cost、components、内部公式、成本完整性（按角色裁剪） |
| 展示 | craft、criterion、排序、备注/说明（按场景裁剪） |

### 2.3 分组投影

统一报价必须同时可生成两种分组，但只返回允许的一个或两个投影：

#### REGION：按区域

```text
区域/空间
→ 该区域的报价行
→ 区域小计
```

规则：

- 未关联空间的行统一进入“综合项目”；
- 区域按稳定顺序排列，不能随请求或浏览器排序变化；
- 区域小计只汇总行金额，不负责重算报价总额；
- 业主、报价工作台、合同、项目默认优先使用此视图。

#### TYPE：按类型

```text
ItemType（施工/主材/软装/定制/电器/综合）
→ 业务分类 category
→ 该分类的报价行
```

规则：

- 类型是分层维度，不只做扁平标签；
- 同一类型下再按分类分组；
- 默认保留原区域来源和行 ID；
- 如需把跨区域相同项目合并，只能由服务端生成合并投影，并返回 sourceLineIds、sourceRegionNames、sourceCount；前端不得自行合并后冒充原始行；
- 合并投影的行数量、数量合计、金额合计必须可回溯到原始行。

### 2.4 版本

- 每个场景必须绑定明确的 `quoteId + version`；
- 合同必须绑定客户已接受的那一版，不得自动展示最新版；
- 项目必须绑定合同来源报价版本；
- 业主端只能显示被授权项目对应的已接受/当前有效报价；
- 客户 360 和报价工作台可以显示版本轨，但必须明确当前版本与历史版本；
- 同一版本在 App/Web/业主端必须使用同一快照事实，不读取实时主数据改写历史。

## 三、统一场景适配器

| 场景 | 模式 | 默认分组 | 可执行动作 | 字段边界 |
| --- | --- | --- | --- | --- |
| 设计师报价工作台 | EDIT | REGION，可切 TYPE | 编辑、保存、提交、版本切换、导出 | 设计师不可见成本；可见公式和设计差异 |
| 报价列表/工作台卡片 | SUMMARY | 不展开完整行 | 进入统一视图 | 只返回列表摘要 |
| 客户 360 报价 Tab | READ | REGION，可切 TYPE | 进入报价工作台或只读详情 | 按当前角色裁剪 |
| 项目详情中的报价 | READ | TYPE 或 REGION 可切 | 打开同一报价只读视图 | 项目上下文，成本按角色 |
| 合同交接/合同详情 | READ | REGION 默认 | 查看接受版本、生成合同/打印 | 合同绑定报价版本，不显示最新替代版 |
| 业主报价页 | OWNER_READ | REGION 默认，可切 TYPE（若裁决支持） | 查看、返回项目 | 仅销售价、税金、总额，不含成本和内部公式 |
| 员工业主预览 | OWNER_PREVIEW | 同业主 | 不得产生业主确认或修改 | 与业主真实会话同业务区，仅安全层不同 |
| 报价 PDF/打印 | PRINT | REGION 默认 | 打印/重打 | 客户版不含成本、公式、供应商价格 |

场景适配器只能改变外层，不得重新定义报价行和分组。

## 四、Web 设计工作台可复用原则

参考 Web 设计师报价工作台的核心交互：

1. 三栏对象工作面：版本轨 | 报价表 | 报价决策；
2. 区域分组的表格行、区域小计、折叠和公式栏；
3. 版本切换和版本差异；
4. 服务端金额、前端只编辑输入和展示；
5. 唯一主行动按报价状态变化；
6. 键盘、批量、Excel 导入导出等 Web 效率能力；
7. 失焦、保存、错误和回读状态明确。

统一视图应把“报价核心表”抽成可复用能力，但不同场景不必强制三栏。App/业主端使用响应式适配层，数据仍来自同一投影。

## 五、当前实现差异

| 入口/投影 | 当前行为 | 问题 |
| --- | --- | --- |
| `QuoteViewContext.apply` | 返回完整 items、regionGroups、constructionGroups、materialGroups、otherGroups | 是当前最接近统一视图的后端实现 |
| `QuoteViewContext.applyManagerView` | 删除 items 和 regionGroups，只保留类型/分类组 | 项目经理失去区域视图，与统一概念冲突 |
| `quote/info` | 返回完整分组、成本字段 | 角色/场景裁剪依赖 `@Properties`，字段契约和 designer info 不完全一致 |
| `quote/designer/info` | 返回完整分组，成本被裁剪 | 设计师视图与通用视图字段白名单不同 |
| App 报价详情 | 前端支持区域/类型切换；类型视图前端合并相同行 | 前端自行合并，和服务端分组可能不一致 |
| Web 报价工作台 | 只使用 regionGroups，三栏表格按区域 | 没有类型视图，和用户要求不一致 |
| 业主旅程 `CustomerJourneyContext` | 自建 `PriceGroup/PriceRow`，按区域、字符串金额 | 第二套分组模型，未复用 QuoteGroup |
| 业主报价页 | 使用 journey priceGroups，只显示区域 | 没有统一类型视图，字段与内部报价模型不同 |
| 客户 360 | 报价 Tab 主要展示版本/摘要和跳转 | 未统一嵌入同一报价核心视图 |
| 项目/合同 | 主要展示报价摘要与跳转 | 必须在打开后绑定同一版本和同一视图 |
| 报价 PDF | 独立渲染 | 需消费同一分组/字段快照，不能另算 |

## 六、当前必须解决的冲突

### QV-X01：区域视图被项目经理视图删除

统一视图必须保留区域维度，项目经理可以选择类型视图，但不能因为角色不同而丢失区域事实。

### QV-X02：类型视图存在两套语义

- 后端按 construction/material/other 分组；
- App 前端按 ItemType+category 再做合并；
- 业主旅程只按区域；
- Web 工作台没有类型视图。

需要统一为服务端 `REGION` 和 `TYPE` 两种投影。

### QV-X03：客户旅程是独立报价模型

`CustomerJourney.PriceGroup/PriceRow` 与 `QuoteGroup/QuoteLine` 字段、类型、金额格式和分组逻辑不同。长期应共用同一核心投影，只在业主字段白名单和文案层适配。

### QV-X04：合同/项目可能展示“摘要”而非同一版本

所有从合同或项目进入的报价必须明确携带 quoteId 和 version；合同必须锁定已接受版本。

### QV-X05：前端重算与合并

App 类型视图当前在客户端合并相同行并重算展示数量和金额。统一后，合并结果必须由服务端投影给出，前端只负责显示。

### QV-X06：成本/公式边界必须统一

- 成本不是每个人都可见；
- 业主只可见销售价；
- 报价工作台可见成本和内部公式的人员不同；
- 场景适配器不能通过两份投影各自决定字段。

## 七、统一验收标准

对同一个 `quoteId + version`：

1. 所有入口看到的报价编号、版本、状态、客户、房屋、金额和明细行一致；
2. 区域视图与类型视图来自同一批原始行；
3. 两种视图的行数、数量合计、金额合计可互相解释；
4. 服务端返回的组小计不被前端重新计算；
5. 合同和项目显示的报价必须绑定合同接受的版本；
6. App/Web/业主端的销售价、税额、总额一致；
7. 成本、公式、供应商价格对无权限角色完全不返回；
8. 同一报价的版本轨和当前版本标识一致；
9. 接口失败显示“暂不可确认”，不显示为空报价；
10. 页面交互可以因设备不同而不同，但核心事实和可执行动作边界一致。

建议新增契约测试：

```text
同一 quoteId + version
→ quote/info
→ quote/designer/info
→ project/manager/quote/info
→ customer journey quote
→ owner quote projection
断言核心销售字段、行 ID、区域分组、类型分组、版本、总额一致
```

## 八、建议的落地顺序

1. 先冻结统一报价投影契约和场景适配规则；
2. 后端以 `QuoteViewContext` 为唯一分组来源，补 REGION/TYPE 双投影；
3. 客户旅程、项目、合同、业主端改为消费同一投影；
4. App 报价详情移除客户端合并作为正式逻辑，改为服务端 TYPE 投影；
5. Web 报价工作台增加 REGION/TYPE 切换；
6. 统一业主字段白名单和成本裁剪；
7. 最后再做各场景页面适配和真实 UI 验收。

## 九、2026-10-22 用户已确认

| 问题 | 已确认口径 |
| --- | --- |
| 业主端类型视图 | 支持 |
| 类型视图跨区域相同项目 | 合并，但必须由服务端完成并保留来源行/区域 |
| 合同详情中的报价 | 跳转统一报价视图，不嵌入第二套明细 |
| 项目端默认视图 | 区域 |
| PDF 分组 | 允许用户选择按区域或按类型打印 |

## 十、结论

```text
统一报价：必须有单一事实源和单一分组投影
区域视图：必须保留
类型视图：必须正式支持
Web 工作台：现有表格和版本交互可复用
App/业主：使用响应式适配，不得再造报价模型
合同/项目/客户：只能绑定同一 quoteId + version
```

这份契约应先交给现有报价修复会话消费，禁止各页面分别修改后再对账。报价只是统一业务对象视图的一个实例，通用规则见 `04-unified-business-object-view-standard-v0.1.md`。

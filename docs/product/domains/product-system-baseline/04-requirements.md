## 非功能要求

- 性能：本批为文档与只读盘点，不产生运行时性能影响。
- 可访问性：矩阵表在 Markdown 阅读器中保持列宽可读；后续转 HTML 时需提供横向滚动和表头固定。
- 异常恢复：每个结论标注来源、状态和待裁决项；业务答复缺失时保持 `pending`，不得自行补规则。
- 审计/幂等：后续角色或权限变更必须记录变更人、前后值、影响范围和回滚点。
- 跨端一致性：同一角色、同一对象和同一动作在 App/Web 的能力、数据范围、金额口径和错误态必须可对账；强制能力不得一端缺失。

## 明确不做

- 不新增第八员工角色。
- 不修改 `EmployeeRole`、`DataScope`、Provider 校验、菜单、路由、页面或数据库。
- 不把候选缺陷直接转成代码任务。
- 不对外宣称已形成正式角色权限矩阵。
- 不替代专项会话裁决 TeamLeader 存量收口、`GAP-060` 等未决口径。

### U1 非功能与异常要求

- 服务端是唯一分组来源；前端只展示，不重算。
- 同一 `quoteId + version` 的 REGION/TYPE 行集合必须来自同一份原始明细。
- 区域为空进入“综合项目”；不得猜区域。
- 原始金额缺失显示“暂不可确认”，不得静默按单价乘数量补齐。
- 任何部分读取失败显示“暂不可确认/部分事实暂不可确认”，保留恢复路径。
- 跨企业、跨门店、跨项目、伪造版本和分组参数全部阻断。
- 成本、内部公式、供应商执行价和 `acceptedBy` 按角色和场景裁剪。
- U1 默认无 DDL；PDF 分组元数据暂由文件内容和文件名承载。

### U1 明确不做

- 不修改后端、App、Web 代码或 DDL。
- 不改变金额、成本、利润、权限和状态机。
- 不新增直接签约来源字段或统计隔离。
- 不补历史区域、不重算历史报价。
- 不把契约评审通过表述为 UI 或生产验收通过。

### 非功能与异常要求

- App/Web 同权限、同状态、同金额、同异常恢复；接口失败显示“暂不可确认”。
- 费用提交、审批、应付创建、付款、凭证生成均需幂等。
- 跨企业、跨店、跨项目、非本人访问返回 403/404，不得以空数组伪装。
- 审批通过后金额/归属/附件不可直接修改；已付款后只能冲正/负向调整。
- D1/D2 DDL、权限和金额/成本语义需用户确认并走 L3 门禁。
- 没有真实 App/Web 页面和独立验收证据前，不得标记 UI 或业务闭环通过。

### 明确不做

- 不做预算/额度、多级审批、金额阈值和支出前预申请。
- 不做发票查验、认证、税额、进项抵扣和发票台账。
- 不做复杂成本分摊、总部公共费用分摊和经营利润正式上线。
- 不自动迁移存量手工流水或 `Payable(Expense)`。

# 统一业务对象视图标准 v0.1

> 日期：2026-10-22
> 状态：用户已确认方向，作为跨业务对象的产品架构标准。
> 适用：客户、房屋、设计方案、报价、合同、项目、计划、材料、变更、验收、财务单据等所有业务对象。

## 一、核心原则

```text
一个对象
+ 一个明确版本
+ 一组同源事实
+ 一组同源明细
+ 服务端分组投影
+ 场景适配
```

统一视图解决的是“同一业务对象在所有入口是否说同一件事”，不是强制所有页面采用同一种布局。

## 二、统一视图模型

每个业务对象至少需要定义：

| 层 | 内容 |
| --- | --- |
| 身份 | 对象 ID、编号、所属企业/门店/团队、来源 |
| 版本 | 当前版本、历史版本、生效/冻结版本 |
| 状态 | 状态、状态名、下一步、阻断原因 |
| 事实 | 金额、数量、日期、责任人、上下游关系 |
| 明细 | 明细行或子对象及其稳定 ID |
| 分组 | 区域、类型、阶段、分类等投影 |
| 权限 | 可见字段、可执行动作、数据范围 |
| 场景 | 业主、项目、合同、客户、工作台、PDF |

宿主对象的详情页只能展示该对象的摘要和跳转入口，不能复制一套会漂移的完整明细。

## 三、分组投影规则

### 3.1 通用分组

- `REGION`：按空间/区域；
- `TYPE`：按业务类型；
- `PHASE`：按项目阶段；
- `CATEGORY`：按业务分类；
- 具体对象可组合使用，但必须显式命名，不允许前端猜测。

### 3.2 区域视图

```text
区域/空间
→ 明细行
→ 区域小计
```

规则：

- 未归属行进入“综合项目”或对象定义的等价分组；
- 排序由服务端稳定生成；
- 区域小计只汇总明细行金额，不重新定义对象总额。

### 3.3 类型视图与跨区域合并

用户已确认：业主端和类型视图支持跨区域相同项目合并。

允许合并的前提：

1. 服务端执行；
2. 只合并业务身份相同的明细；
3. 保留 sourceLineIds、sourceRegionIds、sourceRegionNames、sourceCount；
4. 合并后数量/金额只是展示投影，原始明细仍可展开查看；
5. 合并规则和字段参与合并的条件必须由对象专项冻结；
6. 前端不得自行决定“看起来一样”就合并。

报价类型视图的建议合并键：

```text
ItemType
+ category
+ name
+ brand
+ series/spec
+ unit
+ pricingMode
+ sale unit price
+ role
+ difference type/status
+ included
+ craft/criterion
```

最终合并键由报价修复会话通过 T05/T06/T12 冻结。

## 四、场景适配规则

| 场景 | 统一视图职责 | 允许的差异 |
| --- | --- | --- |
| 员工工作台 | 进入对象工作区 | 队列、批量、键盘、编辑能力 |
| 客户 360 | 看对象摘要和版本 | 客户上下文、跨对象跳转 |
| 项目详情 | 看项目关联对象摘要 | 项目上下文、返回路径 |
| 合同详情 | 看合同自身；报价等引用对象跳转 | 不复制报价完整明细 |
| 业主端 | 只读查看业务事实 | 销售字段白名单、区域/类型视图 |
| 员工预览 | 与业主同业务区 | 水印、预览标识、安全层 |
| PDF | 打印当前对象 | 选择分组、客户字段白名单 |
| API/导出 | 返回同一事实 | 场景字段裁剪、权限过滤 |

## 五、对象落地矩阵

| 对象 | 统一视图 | 默认分组 | 场景跳转 | 备注 |
| --- | --- | --- | --- | --- |
| 设计方案 | Design + DesignVersion | 区域 | 客户/项目跳转统一设计视图 | 分项不含价格 |
| 报价 | Quote + version | 区域；项目端默认区域 | 合同/项目/客户跳转统一报价视图 | 业主支持区域/类型，类型跨区域合并，PDF可选分组 |
| 合同 | Contract + version | 合同行/区域/类型 | 报价、项目跳转合同统一视图 | 合同详情不嵌入第二套报价明细 |
| 项目 | Project | 阶段 | 合同/客户/业主跳转项目视图 | 关联计划和验收跳转 |
| 计划 | ProjectPlan + version | 阶段 → 任务/区域 | 项目跳转计划视图 | 模板不在此视图展示 |
| 材料 | MaterialPlan/Sheet | 品类/供应商/项目/区域 | 项目/财务跳转材料视图 | 成本/采购价按角色裁剪 |
| 变更 | ContractChange | 变更类型/区域 | 项目/合同跳转变更视图 | 金额与生效状态同源 |
| 验收 | Acceptance + round | 阶段/区域 | 项目/业主跳转验收视图 | 业主只读/确认边界 |
| 财务单据 | Receivable/Payable/Ledger/Voucher | 项目/类型/时间 | 项目/财务跳转统一单据视图 | 金额、来源、核销同源 |

## 六、禁止模式

1. 宿主页面直接复制对象完整明细；
2. 一个入口按区域、另一个入口按类型却没有统一投影；
3. 前端根据名称、价格或“看起来相同”自行合并；
4. 合同/项目自动取最新报价而不是绑定版本；
5. 业主端显示成本、毛利、内部公式或供应商执行价；
6. 页面把失败显示为空数据；
7. PDF 自行使用另一套分组逻辑；
8. 新增业务对象时只做页面，不定义统一视图和场景适配。

## 七、验收标准

对任意业务对象、任意 `objectId + version`：

1. 所有场景返回的核心事实一致；
2. 明细行 ID 和版本一致；
3. 区域/类型/阶段分组来自服务端；
4. 类型合并结果可回溯原始行和来源区域；
5. 场景只改变字段、动作和密度；
6. 契约测试覆盖 App、Web、业主端、项目、合同和 PDF；
7. 所有跳转都保留对象 ID、版本和来源场景；
8. 页面失败和部分数据状态可恢复；
9. 角色无权限字段完全不返回；
10. 历史对象不受当前模板、主数据或最新版本影响。

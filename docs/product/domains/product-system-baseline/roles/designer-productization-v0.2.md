## 3. 目标信息架构

### App

```text
工作台 / 客户 / 签单 / 项目 / 我的
```

- 客户：我的客户、待我跟进、待我量房、客户诉求、内容线索；
- 签单：待我量房、待我设计、待我谈单、待我签约；报价历史从待我谈单上下文进入，不占一级菜单；

- 我的：业绩、资料库、设置。

### Web

```text
业务工作台
客户经营
签单中心
项目协同
资料与档案
经营与工具
```

资料与档案包含：报价项目库、方案模版、套餐、施工方案、施工计划模板、工人档案。报价历史从待我谈单进入，合同档案从项目详情进入，均不占一级菜单。

## 5. D1A 项目内合同档案

最终决策：合同档案不是全局菜单，也不是独立一级能力，而是项目子资源。

- 入口：项目工地 → 选择项目 → 合同档案；
- Web 路由：`/designer/projects/:projectId/contract`；
- App 继续使用项目详情 → 合同履约档案；
- 合同档案只读展示合同基线、金额、付款计划、施工计划、合同范围和变更历史；
- 不提供登记收款、修改合同、确认签约/生效等合同页内写动作；
- 报价、变更、选材、应收等从各自工作面进入，不在合同档案中伪装成合同动作；
- 详情复用 `project/contract/info`、`project/contract-line/page`、`project/contract-change/page`；
- 不再使用全局 `project/contract/page` 检索，不保留合同档案一级菜单。

## 6. 后续批次硬边界

- D2 只调整 App 信息架构，不新增同义业务 Provider；
- D3 合同详情复用项目合同事实，不复制合同对象；
- D4 只读资料库不得出现编辑/删除/发布动作；
- D5 主材下单只展示财务履约状态，不开放采购单；
- App 设计方案模版保持 `DEFERRED_BY_USER`；
- 所有批次继续使用服务端分页、Dormant 排除和同一数据范围。

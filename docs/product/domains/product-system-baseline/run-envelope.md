# 装得清产品体系基线 · Run Envelope（自主运行授权包）

> 本包只授权只读盘点和文档沉淀。角色、权限、金额、成本和外部身份变更必须经过业务裁决与用户确认。

## 1. 目标

- Domain：`product-system-baseline`
- North Star：以角色、业务域、功能、对象概念和跨端展示的同源基线，支撑产品持续扩展、变更影响识别与规则一致性
- 目标角色：7 类内部员工角色、业主/客户、平台运营；工人与供应商暂作为被管理对象纳入边界盘点
- 本期范围：角色分类、角色矩阵、业务主链责任、功能能力、对象概念规则、App/Web 展示一致性
- 本期不做：新增角色、扩权、业务状态机变更、金额/成本口径变更、DDL、生产发布、正式小程序提审/发布

## 3. 自主决策权限

当前只允许自行决定：

- 盘点方法、表格结构、证据命名和文档组织；
- 在已确认业务卡范围内整理候选矩阵；
- 读取与任务直接相关的 App/Web/后端代码和文档；
- 登记 `GAP`、候选缺陷和待确认项；
- 形成 T05 问题和后续批次提示词。

## 4. 人工门禁

遇到以下情况必须停止该分支并写入决策包：

- 新业务角色、角色合并/拆分或一人多岗模型；
- 数据范围、权限、审批主体、收付主体和业主确认主体变化；
- 金额、成本、利润、工资、提成和凭证语义变化；
- 新业务对象、状态机或对外可见字段变化；
- DDL、迁移、生产数据删除、生产发布；
- 正式小程序提审与发布；
- 对外能力承诺或营销表达。

## 5. 质量门禁

- 业务结论必须引用 `SCN/BR/DEC/GAP/EV`；
- 代码事实、页面事实和业务事实必须分级标注；
- 角色矩阵必须区分身份、岗位、范围、责任和能力；
- 跨端对比必须有真实路由/页面证据；
- 没有业务裁决时保持 `candidate/pending`；
- 不允许用页面现状替代正式规则。

## 6. 预算与止损

- 每个批次只解决一个垂直切片；
- 同一问题最多做一轮补充推断，缺少高权威来源即登记 T05；
- 角色或权限口径无裁决时停止编码分支，继续只读盘点；
- 连续两个批次没有新增证据时，停止扩张并重新收敛范围；
- B0 完成后停在 `SCENARIOS_READY → BIZ_ALIGNED` 门禁。

## 7. Return Packet

回来后必须提供：

- 已完成批次与文档证据；
- 已确认口径、候选判断和未决项；
- 受影响角色/对象/页面/Provider；
- 需要业务智能体或用户裁决的问题；
- 下一步提示词；
- 是否可以进入下一阶段。

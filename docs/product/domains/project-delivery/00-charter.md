# 项目施工履约与进度 · 业务域章程

- Domain：`project-delivery`
- Owner：codex
- Created：2026-10-17
- North Star：合同施工范围通过阶段、任务、排期、节点留证和进度投影形成可追溯的履约闭环，不脱离合同或已生效变更独立造任务。

## 1. 业务问题

- 当前场景：合同生效并立项后，设计意图必须进入阶段、施工任务和排期，由项目经理在现场推进并留证。
- 谁遇到问题：设计师负责把合同施工行解释为可执行任务；PM 负责开工、节点和现场；Boss/店长负责项目、人员和风险；业主只读查看。
- 当前损失/风险：施工任务可从企业工艺库手工新增而脱离合同范围；合同基准完工日与排期日期被混用；阶段计划存在两套算法；现场汇报角色和取消任务门禁未统一。
- 希望达到的结果：任务来源唯一、工期层次清晰、排期可追溯、节点证据完整、阶段/项目进度同源，合同外施工必须先走增减项。

## 2. 目标角色

| 角色 | 主要目标 | 关键动作 | 不负责什么 |
| --- | --- | --- | --- |
| 设计师 | 让合同施工范围可执行 | 从合同/报价施工行选择任务，参与排期 | 不从企业工艺库造合同外任务 |
| 项目经理 | 推进现场并留下证据 | 接单、开工、节点留证、日报、阶段完工 | 不改合同金额、不绕过验收 |
| Boss | 控制项目经营结果 | 立项承接、指定 PM、查看进度/偏差 | 不替代 PM 现场留证 |
| 店长 | 管理本店履约 | 本店项目、人员、偏差处置 | 不跨店操作 |
| 业主 | 了解本人项目进度 | 只读查看进度、动态和验收节点 | 不修改任务和内部备注 |
| System | 维持计划与进度事实 | 生成基准阶段/任务、投影预计完工、识别偏差 | 不让排期静默改写合同基准 |

## 3. 本期范围

- 必须做：合同施工行 → 项目阶段 → 施工任务 → 排期 → 节点留证 → 阶段/项目进度 → 计划偏差。
- 暂时不做：报价阶段清单修订、增减项审批本身、阶段验收整改的独立业务域。
- 明确排除：手工任务、企业工艺库直接下发、以排期静默覆盖合同基准完工日、自动验收。

## 4. 主链

```text
合同生效
→ 立项并生成项目阶段
→ Boss/店长指定项目经理
→ 从合同/报价施工行生成待排期任务
→ 设计/PM/Boss 排期
→ PM 开工、隐蔽、完工节点留证
→ 阶段完成并进入验收
→ 项目进度/预计完工投影
→ 超窗生成计划偏差并处置
```

## 5. 关键不变量

1. 排期任务唯一来源 = 本项目合同/报价施工行；合同外施工必须先走增减项。
2. 不存在手工任务；`ProjectTask` 必须有合同行或已生效变更项来源。
3. 合同基准完工日锁定；任务排期只产生动态预计完工日。
4. 阶段计划由排期驱动时必须与合同基准层次区分，不能无痕回写承诺日期。
5. 未指定 PM、未具备开工条件、量房未完成时不得开工。
6. 节点证据必须与项目、任务、节点关联；隐蔽工程未确认不能推进完成。
7. 空阶段必须区分“本项不涉及”和“应有任务但缺失”。
8. 计划偏差必须留痕，客户原因走合同工期变更，不由 PM 静默顺延。

## 6. 金额/成本/权限边界

- 金额：任务销售价/成本来自合同行或已生效变更快照。
- 成本：成本缺失时 `costComplete=false`，利润/毛利率为 null。
- 权限：设计师/PM/Boss 在数据范围内排期；PM 现场留证；Boss/店长指定 PM；业主只读。
- 跨租户/数据范围：项目、任务、阶段、证据继承项目归属；非参与员工不可访问。

## 7. 成功指标

- 产品：有来源任务覆盖率、节点证据完整率、阶段按时完成率。
- 数据质量：无来源任务数 0、合同基准/预计完工混用 0、超窗未生成偏差 0。
- 业务结果：计划偏差可解释率、项目按期交付率。
- 安全：跨企业/跨项目越权 0，重复开工/重复节点 0。

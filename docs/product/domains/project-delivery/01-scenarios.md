# 项目施工履约与进度 · 真实业务场景

## 场景 A：正常新签项目从合同施工行到阶段验收

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 设计师排期；Boss/店长指定 PM；PM 执行；业主只读 |
| 触发事件 | 合同生效，项目立项并生成标准施工阶段 |
| 前置条件 | 客户/房屋/报价/合同有效；合同施工行存在；量房完成；PM 已指定；开工日期明确 |
| 当前动作 | 设计师从本项目合同施工行选择阶段、区域、数量和计划起止，PM 接收任务 |
| 系统下一步 | 任务写入合同行来源、金额/成本快照；阶段计划由任务排期驱动；超窗生成计划偏差 |
| 成功结果 | PM 完成开工、隐蔽、完工节点并留证；阶段完成后进入验收；项目进度和预计完工同源更新 |
| 异常/恢复 | 未指定 PM、量房未完成、无合同施工行、合同外任务、节点证据缺失均阻断并给出恢复路径 |
| 涉及对象 | Project、ProjectStage、ProjectTask、TaskNode、ProjectReport、ProjectPlanDeviation |
| 状态变化 | Stage Todo→Doing→Accepting；Task Todo→Doing→Accepting→Done |
| 金额/成本/权限 | 任务金额/成本来自合同行；PM/设计师不可见成本明细（按既有角色边界） |
| 证据/来源 | SCN-003、BR-002、DEC-048、DEC-049、DEC-051 |

## 场景 B：增减项生效后生成新增施工任务

| 项 | 内容 |
| --- | --- |
| 使用人/角色 | 设计师发起变更；企业审批；系统生成任务；PM 排期执行 |
| 触发事件 | 合同变更审批通过并生效，新增施工内容 |
| 前置条件 | 合同变更已生效，目标施工行快照完整，阶段存在或可恢复 |
| 当前动作 | 系统从已生效变更项生成施工任务，不允许从企业工艺库手工补录 |
| 系统下一步 | 任务继承目标金额/成本快照；如阶段原为“本项不涉及”则自动恢复为未开始；进入待排期 |
| 成功结果 | 新增任务与原合同任务同源管理，节点留证和阶段验收正常推进 |
| 异常/恢复 | 变更未生效、目标缺失、来源不可追溯时阻断；不得伪造任务或 0 成本 |
| 涉及对象 | ContractChangeItem、ProjectTask、ProjectStage、TaskNode、ProjectCost |
| 状态变化 | ProjectTask 新建 Todo；Stage NotApplicable→Todo |
| 金额/成本/权限 | 任务金额/成本来自已生效变更目标快照；成本缺失时利润 null |
| 证据/来源 | DEC-049、DEC-057、DEC-055、BR-041 |

## 反向场景

- 越权：非项目参与员工、跨门店、跨企业不得查看或推进项目。
- 重复提交/幂等：重复开工、重复节点提交、重复排期不得产生重复任务或证据。
- 跨租户/跨项目：任务、阶段、节点、证据必须同项目同企业链路。
- 数据缺失：无合同行来源、无区域/单位、无计划日期时不得形成正式排期。
- 状态不满足：未指定 PM、量房未完成、阶段不在可开工状态时阻断。
- 金额/成本不完整：成本缺失不得写 0，项目利润保持 null。
- 合同外施工：必须先走增减项，不得通过企业工艺库直接新增。

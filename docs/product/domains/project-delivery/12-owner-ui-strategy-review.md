# 业主端产品化 UI · 战略复盘与当前不足

- 日期：2026-10-21
- 来源会话：`探索装得清业主端分享引流`（`01a136fd-c819-7643-bb7d-48845523b8eb`）
- 审查对象：`OWNER-UI-V1` 当前微信开发者工具实现
- 结论：完成的是“业主可读的产品骨架”，尚未完成“业主愿意主动使用的情绪价值产品”

## 1. 会话中的原始设计意图

### 1.1 不是装企 ERP 的业主皮肤

会话明确否定：

> 当前业主端仍是最传统的管理系统呈现，需要转换成业主视角，同时不违反装修事实。

业主端不是把量房、报价、合同、材料、施工、验收这些内部对象缩小后搬到手机上。
它首先要回答：

- 我家现在怎么样？
- 接下来会发生什么？
- 有没有需要我做的事？
- 出了事谁负责、证据在哪里？
- 这段经历是否值得记住和分享？

### 1.2 两种能力，不是一套功能

用户明确要求保留原有业务 Tab，同时增加中央凸起入口：

- **业务能力**：我的家、进度、我的钱、家档案，负责事实、进度、证据与服务。
- **价值能力**：中央装修历程，负责画面、记忆、情绪、感受、音乐与分享。

两种能力必须形成视觉和叙事上的两个世界：

- 业务能力 = 清晰、可信、有掌控感。
- 价值能力 = 唯美、沉浸、可回忆、愿意分享。

中央入口不是第五个普通 Tab，而是装得清区别于装企 ERP 的核心价值入口。

### 1.3 业主需要的是“站在我这边”的数字保镖

会话中业主的核心诉求包括：

- 亲友能自己看进度，不再天天催我。
- 工期或材料延期时，有态度、有补救计划。
- 验收能拒绝，问题能留证，不只是“通过”。
- 项目经理不处理时，有升级通道和处理时限。
- 预算、增项、延期赔偿要能看懂。
- 材料颜色、型号、到场事实能长期回看。
- 隐蔽工程、质保、维修要有后路。
- 完工后能形成真实的避坑总结和装修记忆。

这说明业主端的产品角色不是“替装企展示管理成果”，而是：

> 让业主在漫长的装修过程中，获得证据、底气、选择权、掌控感、安全感和被认真对待的感觉。

### 1.4 分享是结果，不是目的

会话明确区分三种诉求：

- A. 帮装企获得口碑与转介绍：成立。
- B. 拿装企业主素材替装得清获客：不成立。
- C. 借业主流量做平台品牌曝光：不是当前必要动作。

因此分享设计的顺序必须是：

```text
业主先觉得“这段记录值得给家人看/值得纪念”
→ 自然分享给家人和邻居
→ 装企身份随内容被看见
→ 形成本地口碑与转介绍
```

不能反过来为了引流而要求业主发内容。

### 1.5 装企身份是信任，不是广告

- 业务能力侧需要企业、项目经理、设计师等“为我服务的人”。
- 这部分不是企业宣传册，而是责任人与服务关系。
- 对外分享内容必须自然携带装企身份，但平台角色是记录存证与保管，不抢装企服务主体。
- 累计案例数、泛化业绩不应塞进业主服务界面；与本小区、本户型相关的信息更有价值。

## 2. 当前 OWNER-UI-V1 做对了什么

- 四主 Tab + 中央装修历程的骨架已经落地。
- 首页不再显示员工身份卡和经营指标。
- 装修事实来自真实 journey，没有伪造未来计划和金额。
- 进度页能按真实施工阶段展示节点与现场记录。
- 我的钱使用应付/已付/待付口径。
- 家档案已具备八类档案索引。
- 服务团队和企业名称已进入业主视图。
- 员工预览仍保持只读、水印和项目范围限制。

这些是继续演进的基础，但只能算“业务能力的业主化包装”。

## 3. 当前不足

### 3.1 产品本体仍是“管理系统投影”

当前首页最显眼的结构仍是：

- 当前阶段和进度。
- 八类记录卡。
- 服务人员。
- 接下来施工节点。

它优化了视觉，但没有改变底层问题：页面仍按内部业务对象组织。

典型文案仍是：

- `合同 C1791842081135`
- `材料计划 1 项，已到场 0 项`
- `已完成 0 个阶段验收`
- `6/8 已完成阶段`

这些是管理台账语言，不是业主语言。业主想知道的是：

- 我家现在正常吗？
- 下一步什么时候发生？
- 这件事影响我入住吗？
- 需要我做什么？
- 出问题谁负责？

### 3.2 情绪价值没有进入产品结构

当前深色 Hero、品牌色和柔和卡片提供了“气质”，但没有形成情绪闭环。

真正缺失的是：

- 装修阶段中的关键情绪节点：开工、隐蔽工程完成、瓷砖到场、竣工验收。
- 面对延期、整改、超支时的态度表达和恢复路径。
- 家庭共同参与感。
- 对业主耐心和焦虑的体谅。
- 从“施工现场”到“未来生活”的画面感。

当前页面仍然主要在告诉业主“系统里有什么”，而不是让业主感到“有人认真对待我的家”。

### 3.3 中央“装修历程”仍是换肤后的业务长列表

价值能力目前只是深色背景 + 业务 section 列表：

- 量房、设计、报价、合同、材料、施工、验收、付款依次排列。
- 内容完整，但没有故事线、节奏、主次和画面。
- 没有说明“哪一天最值得记住”。
- 没有照片叙事、里程碑、数字滚动、时间聚焦、情绪文案。
- 没有形成愿意主动分享的成品内容。

这还不是会话中要求的产品：

> 装修经历、曾经画面、入驻感受、记忆、感受、画面、音乐。

### 3.4 首屏没有回答“未来与我”

当前首屏回答的是“当前阶段 + 是否待办”。

会话里业主更关心：

- 接下来 7 天会发生什么。
- 谁会来我家。
- 是否需要我到场。
- 这件事是否正常。
- 如果延期，谁负责、怎么补。

当前只有在下方出现“接下来的施工节点”，且只有日期和业务状态，没有“人、是否到场、影响、承诺”。

### 3.5 服务团队只有名字，没有服务关系

当前团队卡显示“姓名 + 岗位”，例如设计师、业务员。

业主真正需要知道：

- 他在我家负责什么。
- 出哪类问题应该找谁。
- 他为我家的哪些事实签过字、留过证。
- 中途是否换人，谁什么时候接手。
- 哪些联系方式可以公开，统一客服在哪里。

只显示姓名和岗位，无法建立“出事找谁”的信任。

### 3.6 我的钱还只是付款计划

当前页面能显示应付、已付、待付和下一节点，这是有用的基础事实。

但会话中的业主诉求更进一步：

- 总落地成本会不会超。
- 哪些是合同内，哪些是后续自购。
- 当前增项为什么发生。
- 延期是否有合同责任。
- 下一笔钱为什么现在要付。

当前仍是财务节点阅读，不是“我是否安全、是否被多收”的掌控体验。

### 3.7 家档案目前只是目录

当前“家档案”是 8 个业务入口的索引。

真正的家档案应当承载：

- 隐蔽工程图与可追溯位置。
- 材料型号、颜色、批次和到场记录。
- 验收证据与问题整改历史。
- 质保起算与售后路径。
- 入住后维修需要的关键资料。
- 装修前后的画面与家庭记忆。

当前档案能“查到业务记录”，但还不能成为业主愿意长期保留的资产。

### 3.8 分享与装企名片没有形成产品链路

当前中央历程只包含基础分享入口，尚缺：

- 高质量、可自豪转发的家庭装修卡片。
- 不含隐私但能自然携带装企身份的分享视图。
- 亲友打开后“看懂这一户的故事”，而不是阅读业务 section。
- 从亲友观看到咨询装企的自然承接。
- 业主对分享范围、金额、房号和照片的明确控制。

分享仍是一个功能，不是产品的情绪出口。

### 3.9 视觉层级仍偏 SaaS 信息面板

当前设计已经比旧版整洁，但整体仍是：

- 深色 Hero
- 白色卡片网格
- 图标 + 标题 + 状态
- 业务时间线

这是高质量的后台信息移动化，不是专为住宅、家庭、生活阶段设计的界面语言。

下一步需要把“家”的语义加入视觉：

- 空间与时间，而不是模块与字段。
- 人的痕迹与照片，而不是只有状态标签。
- 关键时刻的仪式感，而不是所有卡片同权重。
- 安静的留白与节奏，而不是持续堆叠信息。

### 3.10 员工预览与真实业主体验仍有边界差异

员工预览需要安全横幅和水印，这是必要的。

但当前视觉评估容易把“员工侧预览安全层”误当成业主真实首屏，从而高估完成度。

后续 UI 验收必须同时区分：

- 业主真实会话。
- 员工只读预览。
- 亲友免登录分享。

三种视图要同源但各有明确边界，不能互相冒充。

## 4. 下一轮设计原则

1. **先回答业主的问题，再展示系统对象。**
2. **每个首屏只制造一个主情绪和一个主行动。**
3. **业务能力负责可信，价值能力负责感动，二者不能混成一套卡片。**
4. **证据只在需要建立信任和安全时出现，不把所有业务字段前置。**
5. **分享必须由业主的骄傲、安心或记忆驱动，不能由装企获客驱动。**
6. **装企身份自然出现，平台定位为记录与保管，不抢服务主体。**
7. **没有事实源的内容不做，尤其不能伪造未来计划、质保和评分。**
8. **员工预览只读，不代替业主确认。**

## 5. 建议的下一批

### OWNER-EMOTION-01：我的家 · 未来 7 天与情绪首屏

- 业务裁决未来计划可见口径。
- 首屏改为“我家现在怎么样 + 接下来会发生什么 + 是否需要我到场”。
- 引入延期/整改时的态度文案与恢复路径，但必须来自真实状态。

### OWNER-STORY-01：装修历程 · 真正的价值能力

- 时间轴代替业务 section 列表。
- 关键里程碑、施工现场、人物承诺、照片和家庭记忆。
- 动态节奏、沉浸首屏、可关闭的环境音乐作为后续增强。
- 最终产出可分享的“这一户的装修故事”。

### OWNER-TRUST-01：人、企业、证据与档案

- 服务团队从“姓名岗位”升级为“责任关系”。
- 装企名片进入业务侧与分享链路。
- 隐蔽工程、材料档案、质保与售后形成长期家档案。

### OWNER-CONTROL-01：钱与安全感

- 从付款计划升级为业主可控的花费视图。
- 在业务裁决后补足合同内、变更、自购、延期责任等口径。

## 6. 审查结论

当前版本是合格的**产品骨架第一版**，但不能称为业主端设计目标已经完成。

真正需要继续补的不是更多卡片，而是：

> 让业主感到“这个产品站在我这边”，并且在关键节点给他确定感、安全感和值得纪念的画面。

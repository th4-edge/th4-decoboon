## 1. 产品命题

业主端不是装企 ERP 的移动投影，而是：

> 一份始终站在业主这一侧、可读懂、可追溯、可长期保存的家装事实与家庭记忆。

产品分为两层：

| 能力 | 页面 | 目标 |
| --- | --- | --- |
| 业务能力 | 我的家、进度、我的钱、家档案 | 让业主知道发生了什么、下一步是什么、谁负责、证据在哪里 |
| 价值能力 | 中央装修历程 | 把真实过程组织成可回看、可分享、值得记住的故事 |

详情页不是“补充弹层”，而是五类关键业务事实的正式落地：

1. 报价详情
2. 合同详情
3. 选材详情
4. 材料计划详情
5. 增减项详情

## 2. 统一体验原则

1. **先回答问题，再展示字段。** 每页先回答“现在是什么状态、和我有什么关系”。
2. **一页一个视觉主行动。** 查看原件/明细是主行动，提问和反馈降为次行动。
3. **事实层用浅色纸张。** 合同、金额、签字、附件必须有稳定、安静、可核对的阅读环境。
4. **深色只属于历程。** 首页照片 Hero 和进度状态卡允许局部深色，但完整暗色世界只保留给装修历程。
5. **同源不是同文案，而是同页面组件树。** 业主端与员工预览复用同一页面、同一组件、同一数据投影。
6. **预览只增加安全层。** 横幅、水印、只读与分享关闭允许存在，不另做一套预览页面或预览卡片。
7. **没有事实就明确空态。** 不补造附件、登记人、照片、版本或金额。

## 4. 设计系统

### 4.1 Owner Token

Owner 子品牌 Token 必须集中维护在 `src/uni.scss`，页面不得再写裸色值。

| Token | 值 | 用途 |
| --- | --- | --- |
| `$owner-ink` | `#17231F` | 主文字 |
| `$owner-ink-2` | `#34443E` | 次级文字 |
| `$owner-muted` | `#60716B` | 辅助文字，满足纸色背景对比度 |
| `$owner-paper` | `#F4F1E9` | 页面底色 |
| `$owner-card` | `#FFFDF8` | 业务卡片 |
| `$owner-forest` | `#0D2B25` | 品牌深色、历程底色 |
| `$owner-moss` | `#247263` | 正向动作与已形成状态 |
| `$owner-mint` | `#DFF2EB` | 正向浅底 |
| `$owner-copper` | `#96542F` | 金额变化、关键强调 |
| `$owner-copper-soft` | `#F2DFCF` | 强调浅底 |
| `$owner-line` | `rgba(23,35,31,.09)` | 分隔线 |
| `$owner-danger` | `#B9574D` | 风险与阻断 |

### 4.2 字体层级

| 层级 | 建议字号 | 用途 |
| --- | --- | --- |
| Display | 60rpx / 30px | 页面主标题、关键金额 |
| H1 | 46rpx / 23px | 详情页标题 |
| H2 | 38rpx / 19px | 区块标题 |
| Body | 26–28rpx / 13–14px | 正文 |
| Meta | 24rpx / 12px | 时间、来源、备注 |
| Kicker | 22rpx / 11px | 英文/辅助标签，仅作辅助 |

禁止正文低于 24rpx（12px）；金额、状态、日期不得只靠低对比度颜色表达。

### 4.3 间距与形状

| Token | 值 | 用途 |
| --- | --- | --- |
| `$owner-page-pad` | `32rpx` | 标准左右安全边距 |
| `$owner-section-gap` | `52rpx` | 区块间距 |
| `$owner-card-gap` | `28rpx` | 卡片间距 |
| `$owner-radius-card` | `40rpx` | 主卡片 |
| `$owner-radius-small` | `24rpx` | 事实格、附件行 |
| 触控高度 | `≥88rpx` | 所有按钮和可点卡片 |

内容轨必须统一为 `32 / 718 / 686rpx`（以 750rpx 设计宽度计），章节标题和子卡片同宽。

### 4.4 明暗主题

- 业务页面：暖纸色底 + 米白卡片。
- 首页：照片 Hero 使用深色遮罩承载情绪，进入内容后立即回到浅色。
- 进度概览：允许一张深森林状态卡。
- 详情页：全部使用浅色单据样式，不再使用深绿 Hero。
- 装修历程：唯一完整暗色世界，使用暖深绿 `#173B33` 系，不使用近黑科技色。

## 5. 组件体系

新增或重构以下 Owner 组件：

| 组件 | 职责 |
| --- | --- |
| `OwnerPageShell` | 统一页面底色、安全边距、预览横幅、水印、底栏避让 |
| `OwnerFactHero` | 项目态/单据态统一 Hero |
| `OwnerSection` | 章节标题、说明、内容槽、可选右侧动作 |
| `OwnerFactGrid` | 两列/三列事实格，统一金额、日期、状态格式 |
| `OwnerRecordMeta` | 登记方、登记人、时间、来源 |
| `OwnerSignoffCard` | 线下确认 / 记录型 / 审批生效 / 业主本人确认四种语义 |
| `OwnerDocumentList` | 附件、原件、证据列表 |
| `OwnerTimeline` | 材料、变更、验收历史 |
| `OwnerEmptyState` | 真实为空、部分同步、接口失败三种空态 |
| `OwnerTabBar` | 五槽业主导航，中央历程凸起 |

组件规则：

- 所有页面使用 `JzIcon`，禁止 emoji 和字符箭头。
- 所有主卡圆角、颜色、字号来自 Token。
- 同一业务事实在不同页面必须使用同一格式化函数。
- 预览层不得复制任何业务卡片。

## 6. 五类详情页规范

### 6.1 报价详情

- 单据 Hero：报价编号、当前版本、金额、状态、线下确认时间。
- 版本条：V1/V2/V3，清楚标识当前版本。
- 报价构成：空间分组，默认收起，可展开逐项明细。
- 本次差异：新增、减少、金额变化。
- 登记来源：客户线下确认，员工登记；没有登记事实时显示“登记信息待同步”。
- 附件：报价单、线下确认材料。
- 主行动：查看完整报价单。
- 次行动：对报价有疑问。

### 6.2 合同详情

- 单据 Hero：合同编号、合同金额、状态、签约/生效日期。
- 关键事实：原金额、当前金额、已生效变更、计划工期。
- 服务主体与项目范围。
- 付款节点：只展示业主应付口径。
- 线下签署与员工登记事实。
- 合同正文与附件。
- 主行动：查看合同正文。

### 6.3 选材详情

- 版本、选材状态、覆盖主材数量。
- 每类主材：品牌、系列、型号、花色、规格、空间、图片。
- 线下确认：客户线下选择，设计师登记。
- 明确“选材确认 ≠ 材料到场”。
- 链接到材料计划详情。

### 6.4 材料计划详情

- 状态计数：计划、已下单、已到场。
- 材料明细：名称、品牌、规格、数量、要求到场、实际到场。
- 记录型说明：材料到场不需要业主确认，也不代表质量验收。
- 现场素材存在时展示图片/视频；没有时明确空态。
- 主行动：查看材料到场记录。
- 次行动：对材料有疑问。

### 6.5 增减项详情

- 审批中：只显示事项和状态，不显示金额。
- 已生效：显示原因、明细、金额、发起人与生效时间。
- 金额联动：签约金额 + 生效变更 = 当前合同金额。
- 不展示内部审批意见、成本和内部备注。
- 明确：增减项属于企业审批生效后同频，不建模业主在线确认。
- 次行动：提出异议。

## 7. 业主与员工预览一致性

### 7.1 完全一致的业务 UI

以下必须完全一致：

- 页面路由
- 页面组件树
- 数据投影
- 组件尺寸、颜色、字号、间距
- 空态、错误态、加载态
- 金额、状态、日期格式化
- 详情页展开/收起状态

### 7.2 允许的唯一差异

员工预览额外增加：

- `OwnerPreviewBanner`
- `OwnerPreviewWatermark`
- 分享菜单关闭
- 业主写动作隐藏或禁用
- 返回员工项目入口

这些安全层不得改变业务内容的内部结构，也不得另做预览专用卡片。

## 8. 状态设计

| 状态 | 表现 |
| --- | --- |
| Loading | 骨架保持页面构图，不显示空白页 |
| Empty | 说明“尚未形成”，并说明什么时候会出现 |
| Partial | 展示已同步事实，列出未同步字段 |
| Error | 说明暂不可确认，保留重试和返回 |
| Readonly | 预览模式显示横幅/水印，业务内容不变 |
| Long content | 页面可滚动，章节可折叠，底部安全留白 |
| Offline | 保留最近一次已加载事实，顶部提示“数据可能不是最新” |
| Permission | 不泄露项目是否存在；返回项目列表 |

## 9. 业务确认语义

| 业务 | 语义 | 业主端表现 |
| --- | --- | --- |
| 报价 | 客户线下确认，员工登记 | 显示“线下确认/登记人/时间”，不提供在线确认 |
| 合同 | 客户线下签署，员工登记生效 | 显示合同事实与签署登记，不提供在线重签 |
| 选材 | 客户线下确认，设计师登记 | 显示选材版本与登记来源 |
| 材料到场 | 装企执行记录 | 只读展示，不设置确认按钮 |
| 增减项 | 企业审批生效后同频 | 只读展示变更结果，不建模业主在线确认 |
| 阶段验收 | 业主本人确认 | 仅此业务提供业主本人确认/驳回 |

## 10. 非目标

- 不新增业务状态机。
- 不新增业主自助确认对象。
- 不让员工代替业主验收。
- 不把预览水印视为防截图承诺。
- 不添加成本、利润、供应商价、内部审批意见。
- 不为真实为空的数据生成演示素材。
- 不做 Web 预览入口。

## 11. 设计验收

- 390×844、375×812、430×932 三档画布。
- 标准内容轨一致，无双重 gutter。
- 正文 ≥12px；元信息 ≥11px。
- 所有页面无横向溢出。
- 详情导航不被微信胶囊遮挡。
- 业主真实会话与员工预览截图中：除安全层外，业务区像素级布局一致。
- 业主与预览使用同一页面路由、同一 Canvas、同一数据格式化结果。

# 项目施工履约与进度 · Run Envelope

## 1. 目标

- Domain：`project-delivery`
- North Star：合同施工范围通过阶段、任务、排期、节点留证和进度投影形成可追溯的履约闭环。
- 目标角色：Boss、店长、设计师、PM、业主（只读）、System。
- 本期范围：B0-B1 业务事实、场景、蓝图、字段字典与对账矩阵；用户于 2026-10-22 继续指令后授权 `PROJ-STATE-D1`。
- `PROJ-STATE-D1` 范围：阶段验收模式继承、迁移、Provider 回读和 App/Web 展示；不含 D2-D5。
- 本期不做：三模式完成分流、停复工业务动作、生产迁移/发布、正式小程序提审。

## 3. 自主决策权限

B1 内可自主整理知识、场景、蓝图和对账。`PROJ-STATE-D1` 仅允许验收模式继承与回读的最小实现；D2-D5 仍需后续明确授权。

## 4. 人工门禁

新业务对象/状态/角色、金额/成本/支付语义变化、DDL、迁移、生产数据删除、正式小程序发布、权限放宽时停止并写决策包。`PROJ-STATE-D1` 的字段迁移仅允许在当前 H2/dev 环境验证；生产执行必须另行确认。

## 5. 质量门禁

- 业务事实有 OBJ/BR/SCN/DEC/GAP 引用；
- 场景闭环；
- 蓝图节点有来源或显式 gap；
- 实现与页面有真实证据；
- 独立验收不由实现者自批。

## 6. 预算与止损

- 每个缺陷最多修复 3 轮；
- UI 审查最多 2 轮；
- 两次无进展停止分支并写决策包；
- B1 完成后等待用户确认是否进入 B2。

## 7. Return Packet

- 已完成批次与证据；
- 未完成项、风险和待决策；
- 下一批提示词；
- 是否允许进入实现。

# 项目施工履约与进度 · Run Envelope

## 1. 目标

- Domain：`project-delivery`
- North Star：合同施工范围通过阶段、任务、排期、节点留证和进度投影形成可追溯的履约闭环。
- 目标角色：Boss、店长、设计师、PM、业主（只读）、System。
- 本期范围：B0-B1 业务事实、场景、蓝图、字段字典与对账矩阵。
- 本期不做：代码修改、迁移、页面开发、生产发布、正式小程序提审。

## 2. 批次队列

| 批次 | 垂直切片 | 允许执行 | 退出条件 | 状态 |
| --- | --- | --- | --- | --- |
| B1 | 业务对齐 + 初始蓝图 | 只读知识卡/代码，写领域包 | `BIZ_ALIGNED` + `BLUEPRINT_READY` | IN_PROGRESS |
| B2 | 任务来源与排期收敛 | 经用户确认且材料域释放 | `DEV_VERIFIED` | PENDING |
| B3 | 节点留证与进度投影 | 经用户确认且材料域释放 | `UI_REVIEWED` | PENDING |
| B4 | 独立验收 | 独立角色 | `ACCEPTED` 建议 | PENDING |
| B5 | 发布准备 | 体验版/灰度 | `RELEASED` 或决策包 | PENDING |

## 3. 自主决策权限

B1 内可自主整理知识、场景、蓝图和对账；不得进入代码实现。B2 以后需材料域释放代码租约和用户确认。

## 4. 人工门禁

新业务对象/状态/角色、金额/成本/支付语义变化、DDL、迁移、生产数据删除、正式小程序发布、权限放宽时停止并写决策包。

## 5. 质量门禁

- 业务事实有 OBJ/BR/SCN/DEC/GAP 引用；
- 场景闭环；
- 蓝图节点有来源或显式 gap；
- 实现与页面有真实证据；
- 独立验收不由实现者自批。

## 6. 预算与止损

- 每个缺陷最多修复 3 轮；
- UI 审查最多 2 轮；
- 两次无进展停止分支并写决策包；
- B1 完成后等待用户确认是否进入 B2。

## 7. Return Packet

- 已完成批次与证据；
- 未完成项、风险和待决策；
- 下一批提示词；
- 是否允许进入实现。

## 8. 授权确认

- 授权人：用户
- 授权时间：2026-10-17
- 授权范围：仅 B0-B1 业务域初始化与业务对齐
- 备注：实现和发布需要用户再次确认。

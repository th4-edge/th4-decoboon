## 一、问题摘要

报价项目库/成本标准、套餐模板、付款计划模板、施工计划模板、单据/凭证模板都属于企业运营标准资产，但当前生命周期、版本、平台基线、业务快照、维护角色和 App/Web 覆盖不统一。

已核实的结构性差异：

1. 套餐模板没有状态、版本、发布/停用和默认能力，修改直接覆盖当前记录；
2. 付款计划、施工计划模板有状态/版本/默认和平台基线来源，但启用后编辑原地递增版本，不保留旧版本内容；
3. 报价项目库有 active 启停和引用删除保护，无显式版本或平台基线；
4. 单据/凭证模板已有较完整的不可变版本和历史实例绑定；
5. App 有五类资产管理入口，Web 仅找到报价项目库和凭证模板，套餐/付款计划/施工计划管理页缺失；
6. 同类资产分散在 catalog/pack/plan/document 四个后端域和不同菜单，缺少统一产品层。

### 已冻结且不再重复裁决的口径

- `DEC-044` / `DEC-075` / `DEC-079` / `BR-037`：报价项目库由 BOSS、店长、财务维护；套餐、付款计划、施工计划模板由 BOSS、店长维护，财务与其他内部角色只读；单据/凭证模板由 BOSS、店长、财务维护。
- 用户 2026-10-22 裁决：App/Web 每类能力强制边界一致且完整；两端交互可不同，但能力、权限、状态、金额和异常恢复不得单端缺失。
- `DEC-020` / `BR-018` / `OBJ-004`：凭证模板采用平台基础模板只读、企业复制、发布不可变版本、历史凭证绑定版本和快照。
- `DEC-048`：施工计划模板标准总工期是模板声明值，阶段 `defaultDays` 是相对权重；合同基准计划锁定，任务排期不静默回溯。

## 三、影响

- 企业无法用统一方式理解“经营标准资产”的状态、版本与生效边界；
- 套餐模板修改后无法说明历史报价来自哪个模板版本；
- 付款/施工模板的“版本号”不能还原旧版本内容，审计证据依赖合同快照是否完整；
- 电脑端无法维护套餐、付款计划、施工计划模板，违反已冻结的 App/Web 完整能力边界；
- 平台基线与企业的边界不统一，后续迁移、升级和企业复制容易产生静默回溯；
- 同类资产分散在多个领域和菜单，增加学习与维护成本。

## 四、临时处理

专项裁决完成前：

1. 不新增或重构模板生命周期；
2. 不改变现有维护角色；
3. 不删除历史模板或业务快照；
4. 不把套餐模板直接改造成新版本模型；
5. Web 缺失能力记录为问题，不以“App 为主”解释豁免；
6. 不修改代码、权限、DDL 或金额语义。

### 5.1 冻结口径

| 资产 | 正式生命周期 | 版本/修订 | 新建业务可用 | 历史与删除 |
| --- | --- | --- | --- | --- |
| 报价项目库 | `Active/Inactive` | 不发布版本；每次有效变更递增 revision，保存不可变变更审计；下游保存 sourceRevision 与业务值快照 | Active | 未引用可删；已引用只能停用；历史金额/成本不回算 |
| 套餐模板 | `Draft/Published/Disabled` | 发布版本不可变并永久保留；报价绑定 templateId/code/version | Published | 草稿可删；停用只阻止新报价；历史报价/合同/项目不受影响 |
| 付款计划模板 | `Draft/Enabled/Disabled` | 启用版本不可变并永久保留；合同保存来源版本和完整节点快照 | Enabled | 草稿可删；启用后只能停用并保留版本；企业内最多一个已启用默认 |
| 施工计划模板 | `Draft/Enabled/Disabled` | 启用版本不可变并永久保留；合同保存来源版本和完整阶段快照；总工期以声明值为准，阶段 defaultDays 仅相对权重 | Enabled | 同付款计划模板；不得用阶段汇总覆盖 `totalDays` |
| 单据/凭证模板 | `Draft/Published/Disabled` | 维持不可变版本；历史实例绑定模板版本、数据快照和文件快照 | Published | 草稿可删；发布版本永久保留；停用不影响历史读取/重打 |

统一底层模型：

```text
资产头（企业范围、当前状态）
-> 版本或修订（发布/启用后不可变；主数据至少保留修订与审计）
-> 业务引用
-> 业务实例快照
-> 历史事实
```

平台基线只适用于付款计划、施工计划、单据/凭证模板。企业副本保留来源编码和版本，但平台升级不得自动同步；只能提示升级，由企业显式创建新版本并发布。报价项目库和套餐模板本期仅企业自建。

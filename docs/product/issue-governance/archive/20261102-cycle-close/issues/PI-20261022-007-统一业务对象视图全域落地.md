## 一、问题摘要

当前各业务对象存在不同页面、不同投影、不同字段和不同分组逻辑。报价问题只是最先暴露的实例，设计方案、合同、项目、计划、材料、变更、验收和财务单据也可能出现同类分裂。

## 二、已确认原则

- 同一对象必须绑定同一 `objectId + version`；
- 不同场景只做上下文、权限、动作和展示密度适配；
- 宿主页只显示摘要和跳转，不复制完整明细；
- 明细分组由服务端生成；
- 区域/类型/阶段等分组必须显式、稳定、可回溯；
- 业主端支持类型视图；
- 类型视图可合并跨区域相同项，但必须服务端执行并保留源行/区域；
- 合同详情中的报价跳转统一报价视图；
- 项目端默认区域视图；
- PDF 可选择分组打印。

## 三、临时处理

在各对象专项冻结前：

1. 不新增第二套对象投影；
2. 不在前端自行合并或重算；
3. 不在宿主页面复制完整明细；
4. 新增页面必须引用统一视图契约；
5. 报价先由现有修复会话落地，其他对象按域推进。

## 五、验收最低要求

- 同一对象版本在不同场景事实一致；
- 明细 ID、分组和金额可由服务端回溯；
- 前端无本地重算/合并；
- 业主字段和内部字段隔离；
- 合同/项目跳转保留版本和来源；
- App/Web/PDF 消费同一契约；
- 真实页面和契约测试通过。

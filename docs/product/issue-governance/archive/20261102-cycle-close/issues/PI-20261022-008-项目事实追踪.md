## 一、问题摘要

当前项目页、业主旅程和各业务对象页面各自加载不同事实，项目没有统一的事实节点和关系模型。需要把项目作为事实索引根，串联量房、设计、报价、合同、增减项、选材、材料、施工、验收、财务和售后事实。

## 二、已确认原则

- 项目视图是事实追踪主入口；
- 事实摘要 + 来源 + 版本 + 状态 + 关系 + 跳转；
- 不复制统一对象完整明细；
- 业主端看到授权子集；
- 历史版本和当前有效版本明确；
- 事实缺失、过期和冲突必须显示；
- App/Web 项目事实集合可对账。

## 三、临时处理

专项裁决前：

1. 不新增项目事实聚合模型；
2. 不在项目页复制设计方案、报价、合同或选材完整明细；
3. 不让项目页直接取各对象“最新版本”替代绑定版本；
4. 不修改现有项目状态、金额或权限；
5. 先完成统一对象视图和事实链契约。

## 四、T05 待裁决问题

1. 项目事实链按业务发生时间还是系统记录时间排序？
2. 默认展示全部阶段、已发生阶段还是当前阶段？
3. 业主端是否展示售后/质保/复购事实？
4. 事实完整度如何定义和展示？
5. 各事实节点可展示哪些摘要字段？
6. 项目事实链是否使用独立领域投影模型？
7. 事实链查询的性能、分页和缓存边界？

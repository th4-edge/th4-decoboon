## 一、问题摘要

客户、房屋、量房分别有真实对象和 Provider，但缺少统一的“客户 → 多房屋 → 量房 → 原始区域”事实链。客户生命周期状态与页面销售阶段、量房设计师/实际执行人/实测录入人、房屋面积/量房尺寸/区域实测面积之间也需要统一展示口径。内容获客已于 2026-10-22 搁置，转入 `PI-20261022-012`。

## 二、已确认事实

- LeadTouch 是租户内容归因，不是平台官网/抖音销售线索；
- Customer 支持多房屋；
- Property 是设计、报价、合同和项目的唯一业务根；
- MeasureRegion 实测值只有 Measured 来源可进入工程量；
- 长/宽是量房快照，不能推算面积/周长；
- CustStatus 是客户生命周期状态；
- App/Web 强制能力应一致且完整。

## 三、临时处理

专项裁决前：

1. 不新增客户/房屋/量房第二套状态或事实模型；
2. 不从客户地址或第一条房屋兜底；
3. 不把模板参考值、历史估算值或长宽推算面积作为实测事实；
4. 不在 Web 内容缺口上以“App 主端”解释豁免；
5. 不修改客户、房屋、量房权限和金额规则。

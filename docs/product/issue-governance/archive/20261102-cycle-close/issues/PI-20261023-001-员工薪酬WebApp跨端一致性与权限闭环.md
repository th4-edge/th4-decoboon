## 问题摘要

员工薪酬域已存在薪酬方案、考勤、提成、工资单、应付、发放和工资条能力，但 Web、App、后端 Provider 与业务规则没有形成同一跨端能力契约：

- Web 月度考勤未从薪酬方案带出应出勤；
- Web 考勤缺少编辑、删除和部分异常字段；
- Web 工资单缺少草稿删除、完整工资项构成和确认确认框；
- Web 错误复用通用财务权限，可能给店长展示不可执行的制单、确认或发放按钮；
- 后端仍有提成阻断工资确认的回归代码；
- 考勤详情缺少店长门店范围校验；
- 工资单复核、作废、批量发放等能力两端均未完成。

## 当前代码事实

1. `FinanceAttendanceDrawer.vue` 将 `scheduledDays`、`normalDays` 固定初始化成 `22`，选择员工只更新姓名。
2. App `attendance-edit.vue` 已调用 `compensationForMonth`，只读展示方案应出勤，并支持已有考勤回填。
3. Web `financeApi` 未封装 `compensation/info`、`attendance/info|delete`、`sheet/info|delete`。
4. Web 员工工资、提成和工作台使用 `useFinanceAccess`，不是薪酬能力矩阵。
5. `PayrollSettlementContext.confirm` 仍包含 `commissionComplete=false` 时拒绝确认的代码。
6. `attendance/summary/info` 仅校验企业与记录存在，未统一应用店长门店范围。
7. `attendance/summary/save|delete` 后端使用 `requireEditor`，只允许 BOSS/Finance，与 `BR-038` 的店长本店考勤能力不一致。

## 业务影响

- 财务无法信任考勤页显示的应出勤天数；
- 历史月份补录和修正缺少恢复路径；
- 页面显示值与数据库快照值不一致；
- 店长可能看到不能执行的动作，或执行本不应开放的动作；
- 提成未结清时工资单可能仍被后端阻断；
- 同企业跨店读取考勤详情存在数据范围风险。

## 已裁决口径

- 应出勤天数按员工和工资月份匹配薪酬方案，考勤保存时写入快照；
- 考勤新增、编辑、删除和确认允许 BOSS、Finance、StoreManager；店长限本店；
- 薪酬方案、提成计提、工资单生成仅 BOSS、Finance；
- 工资单最终确认和草稿删除仅 BOSS；
- 提成未结清只提示，不阻断工资确认；
- App/Web 同一能力必须同源、同状态、同权限、同恢复路径；
- 店长员工发放权限与店长工资单确认/作废边界继续按 `GAP-060` 和支付权限待决项处理。

## 一、问题摘要

企业负责人在权限上是内部岗位能力超集，但当前 Web 默认首页仍是通用工作台卡片集合，且 BOSS 清单中混入“本店经营结果 / 店长查看本店”卡片；独立经营总览页面存在于路由中，却没有明确菜单入口。

App 负责人首页已经显示经营指标、风险项目和经营动态，Web 首页和经营分析则呈现另一套信息结构。结果是同一 BOSS 在 App/Web 打开后没有共同的“今天最重要的事实 + 风险 + 下一步”首屏模型。

本问题不删除负责人专业能力，也不新增角色、权限、状态或金额公式。目标是把负责人默认入口收口为“经营总览 → 业务对象 → 亲自处理”。

## 三、业务影响

1. BOSS 首次进入 Web 可能看到店长语义入口，角色认知错误。
2. 负责人三秒内无法稳定回答“今天先看什么、先处理什么”。
3. App/Web 同一角色使用不同首屏事实，跨端回读和验收缺少统一基准。
4. 岗位菜单并集让负责人把时间花在找入口，而不是判断和处置。
5. 接口失败被空数组/空对象吞掉时，负责人可能把“暂不可确认”误认为“业务正常或无数据”。
6. 继续在现有三套首屏上叠加页面，会扩大导航、字段和状态对账成本。

## 四、临时处理

在 `BOS-D01～D04` 确认和生产切片完成前：

- 不修改负责人权限、金额、成本、利润、状态机或 DDL。
- 不删除现有岗位页面和深链。
- 不新增负责人专用同义 Provider。
- 不把 `GAP-070` 未冻结的利润或费用分摊展示为确定金额。
- 不把现有原型、静态页面或本地 1.0.73 当作已验收上线能力。
- 只允许继续字段对账、产品决策、静态设计和 Provider 映射。

## 七、验收最低要求

- BOSS Web 默认首页不存在店长语义卡片。
- 同账号、同企业下 App/Web 首屏展示同一组负责人事实和同一数据日期。
- 签约额、回款额、项目毛利、在建项目、风险对象数量均可追溯到同一 Provider 字段。
- 成本不完整时毛利显示“成本未完整”，不显示 0 或伪利润。
- 接口失败、无权限、真实空态分别可见，不以空数组伪装。
- 风险对象能进入现有处置工作面，返回后保留筛选和对象上下文。
- Web 1440/1280/1024 与 App 目标设备真实渲染、截图、构建与类型检查通过。
- 独立验收前不得标记完成。

## 九、2026-10-29 用户反馈与方案收敛

用户指出高保真稿与当前上线产品差异过大，需优先考虑现有客户的使用习惯。

纠偏口径：

- 高保真五域经营台仅作方向探索，不作为默认生产方案。
- 保留现有 Web 菜单、工作台入口、专业页面、深链和 App 底部 Tab。
- 首个生产候选改为 `BOS-C1 兼容式经营总览`：
  1. 修正 BOSS 首页店长语义卡片；
  2. 在现有首页内增加“今日经营判断 + 风险对象”；
  3. Web 复用 App 已在使用的 `statistic/boss/workbench`；
  4. 风险对象进入现有风险队列或业务页面；
  5. 不改变主导航、页面职责和常用操作路径。
- 只有当真实客户走查证明现有 IA 无法承载负责人任务时，才重新评估信息架构重构。

# PI-20261029-006 · 已绑定微信重复请求手机号授权

| 项 | 内容 |
| --- | --- |
| 问题 ID | `PI-20261029-006` |
| 当前状态 | `CLOSED / ADMIN_CYCLE_RESET`（不代表已验收或已解决） |
| 严重级别 | P1 |
| 发现日期 | 2026-10-29 |
| 来源 | 用户反馈“已经授权微信信息，为什么每次登录都需要授权手机号码” |
| 所属领域 | 微信登录、身份凭证、账号恢复 |
| 变更记录 | `CHG-20261029-011-login-phone-authorization-once` |

## 根因

后端 `auth/session/login` 已支持按微信 `openid` 命中既有 `Credentials`，命中后直接签发会话，不需要 `phoneCode`。

但 App 登录页首屏始终使用 `open-type="getPhoneNumber"`，没有先执行仅携带微信 `code` 的身份识别。因此即使凭证已经存在，微信仍会在每次点击时弹出手机号授权，后端也持续收到多余的 `phoneCode=true`。

开发日志证据：

| 时间 | 命中既有凭证 | 带 phoneCode | 结论 |
| --- | --- | --- | --- |
| 2026-10-29 14:16:54 | 否 | 是 | 首次绑定，手机号授权必要 |
| 2026-10-29 14:41:38 | 是 | 是 | 已绑定，仍重复请求手机号，前端多余 |
| 2026-10-29 14:54:26 | 是 | 否 | 修复后复用微信凭证，不再请求手机号 |

## 业务与平台边界

- 手机号与微信账号的绑定关系只建立一次，由 `Credentials` 持久化。
- 微信 `getPhoneNumber` 不是永久静默权限，每次主动调用都需要用户点击并确认。
- 已绑定用户必须先使用 `uni.login` 获取微信 `code`，由后端按 `openid` 恢复凭证。
- 只有后端返回 `PHONE_REQUIRED` 时，页面才切换到手机号授权步骤。
- 不新增账号合并、换绑手机号或跨微信授权规则。

## 处理

1. 登录页默认展示“身份快捷登录”，首次点击只执行微信身份识别。
2. 已绑定用户直接恢复员工或业主会话，不出现手机号授权。
3. 服务端返回 `PHONE_REQUIRED` 后，页面才展示“授权手机号并登录”。
4. 保留协议勾选、员工身份门禁和业主项目授权边界。
5. 新增契约门禁，防止后续再次把 `getPhoneNumber` 放回登录首屏主按钮。

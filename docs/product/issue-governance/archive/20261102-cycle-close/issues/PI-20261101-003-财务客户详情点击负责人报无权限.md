## 问题摘要

财务账号进入 Web 客户详情 `王芳（造数5100）`，点击“客户负责人”后，页面提示“当前账号无权执行该操作”，负责人选择框为空。

业务决策 `USER-DEC-20261029-009` 明确：

- 财务可查看、经营其数据范围内的客户；
- Web/小程序客户详情可转交客户负责人；
- 财务不承担设计师指派/改派；
- 财务权限不得以隐藏前端代替服务端校验。

## 根因

客户详情打开负责人转交框时会调用：

```text
user/employee/page
```

该 Provider 仅允许 Boss、店长、设计师、PM，未允许 Finance，因此返回 403：

```json
{"success":false,"errorCode":{"code":"403","message":"当前账号无权执行该操作"}}
```

客户负责人实际更新 Provider `customer/customer/update` 与 `CustomerContext.resolveAssignableOwner` 已允许 Finance，并按企业/门店数据范围校验。缺陷是候选员工目录的权限与客户转交权限不一致。

## 修复

- `user/employee/page` 加入 Finance；
- 候选人范围与登录财务的数据范围同源：
  - 总部财务：企业范围；
  - 门店财务：本门店范围；
- 店长仍为本门店；Marketer 等其他角色仍返回403；
- 未开放设计师指派或改派权限；
- App客户详情移除“按当前门店二次过滤”逻辑，直接信任后端按登录财务范围返回的候选。

## 验证

- 财务调用 `user/employee/page`：200，9名企业候选；
- 店长调用：200，8名本店候选；
- 业务员调用：仍403；
- 财务 Web 客户详情点击“客户负责人”：不再报错，选择框出现9名候选人；
- 选择现任负责人“审计业务”并提交：页面提示“已转交客户负责人”，客户DB归属仍为原负责人，无业务副作用；
- 定向测试、后端构建、App type-check/build、客户管理契约和 Provider 响应契约检查通过。

## 未完成

- App 已移除本地门店二次过滤，dev 构建已更新，Provider已实测返回9名企业候选；仍需用户在真机/开发者工具手工点击确认一次；

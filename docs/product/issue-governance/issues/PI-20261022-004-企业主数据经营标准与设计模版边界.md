## 一、问题摘要

企业运营层还存在三组未收口边界：

1. 用户已于 2026-10-22 裁决：`CatalogItem.costPrice` 始终人工维护；采购下单价格只形成应付事实；`PartnerPrice` 供应商材料价格退场。旧设计中的“采购价回写标准成本”已撤销；
2. 经营目标与指标字典一个是计划事实、一个是口径标准，需要明确权责和分类；
3. 设计模版方案库原 Web-only 裁决已被用户双端完整裁决覆盖，App 当前仍无入口，需补完整闭环。

## 二、当前事实

### 供应商/材料主数据

- **正式前提（`EV-346` / `EV-354`）**：`CatalogItem.costPrice` 由人工录入维护；采购价只形成应付；`PartnerPrice` 供应商材料价格停止新增和使用。
- `Partner` 是统一合作方，覆盖供应商、工厂、劳务、安装、物流、服务商；
- `MaterialSupplier` 以 `materialKey` 维护材料—供应商关系，当前保存采购价、MOQ、交期、账期和有效期；
- `PartnerPrice` 仍保存采购价/人工价、MOQ、交期、账期和有效期，但供应商材料价格部分已进入退场和迁移范围；
- `PartnerPriceContext` 当前仍把有效 `PartnerPrice` 的最低采购成本同步到 `CatalogItem.costPrice`，与 `EV-354` 冲突；
- `PartnerPrice` 仍被品牌兜底参考价、采购执行价来源识别和劳务结算读取；业务裁决已明确材料价退场、`laborPrice` 暂保留只读兼容；
- 业务已裁决：采购价 P2 只形成应付，不自动写回 `CatalogItem.costPrice`；`MaterialSupplier.purchasePrice` 不由下单回写、不参与成本价，代码仍待改造；
- Web 有供应商往来台账和材料下单，但没有完整合作方主数据维护页；
- App 有供应商协作、采购价、供应关系等页面；
- Web 材料下单当前使用供应商名称文本输入，而非合作方选择器。

### 经营目标与指标字典

- BusinessTarget 是公司/门店月度计划值，含签约、回款、毛利、在建项目数；
- MetricDefinition 是公式、范围、时间和缺失值的口径标准；
- 目标维护仅 BOSS/店长；
- 指标字典为代码内只读定义，不是企业自定义数据。

### 设计模版方案库

- 归属 Personal / Store / Company；
- 有 Draft / Published / Disabled 和不可变版本；
- 不承载价格，只引用 CatalogItem；
- 实例化生成真实 Design，实例化即快照；
- Web 有完整管理；App 当前无入口；
- 业务已裁决：用户 2026-10-22 双端完整裁决覆盖设计模版，`DEC-050` Web-only 条款由 `DEC-084` 取代，App 待补完整闭环。

## 三、影响

- 旧供应商价格模型仍与正式口径冲突，存在采购价自动覆盖成本价、PartnerPrice 残留使用和劳务价格误删风险；
- Web 用户可能通过自由文本选择供应商，绕过主数据约束；
- 设计模版已裁决为 App/Web 双端完整，但 App 当前无入口，形成明确研发缺口；
- 经营目标与指标口径可能被混为同一类规则；
- App/Web 主数据能力不一致，影响企业运营标准化。

## 四、临时处理

研发实施前继续遵守：

1. 不新增供应商主数据对象或价格字段；
2. 不改变 `PartnerPrice`、`MaterialSupplier`、`CatalogItem.costPrice` 的现有计算与同步逻辑，不新增回写；
3. 不删除或清空 `PartnerPrice` 存量字段/数据，不把 Web 自由文本供应商直接升级为主数据真源；
4. 不新增或删除设计模版 App 入口；
5. 不新增企业自定义指标或改变现有指标公式。

## 五、T05 问题与业务裁决（已取得）

`REQ-BIZ-20261022-005` 已由 `ANS-BIZ-20261022-005` v2 答复，正式决策为 `DEC-084`。用户新增 `EV-354` 后，原“采购价回写标准成本”方案已撤销。

### 最新五个阻塞问题与裁决

1. **PartnerPrice 供应商价格退场**：`PartnerPrice.purchasePrice` 停止新增和业务读取；存量保留只读兼容并做引用盘点；不迁移为新的价格表，采购单/采购明细本身就是采购价历史；最终删除另行确认。
2. **MaterialSupplier 价格字段**：`MaterialSupplier.purchasePrice` 不由下单回写，不参与 `CatalogItem.costPrice`，作为历史字段只读/待退场；采购价展示改从采购单/采购明细读取并标注“采购价（应付口径）”。
3. **供应商主数据与 Web/App 选择器**：供应商主数据是 App/Web 强制双端能力；Web 必须补合作方和材料供应关系维护；下单新增/编辑必须使用 `supplierId` 选择器，自由文本仅历史兼容。
4. **经营目标与指标字典**：`BusinessTarget` 仅公司/门店计划事实，BOSS/店长维护、财务只读、无团队/个人目标；`MetricDefinition` 仅平台维护，企业不可自定义，内部角色可读相关说明但数值仍按数据权限裁剪。
5. **设计模版跨端边界**：用户双端完整裁决覆盖 `DesignTemplate`，App 必须补齐查看、新建/编辑、发布、停用、复制、实例化和异常恢复，交互可不同但事实同源。

### 成本边界（不可违反）

- `CatalogItem.costPrice` 是人工录入和维护的成本价，不从其他价格自动获取。
- 采购执行价 P2 只形成应付/暂估应付事实，不自动覆盖成本价。
- 本专项不新增采购价回写成本、不新增供应关系价格历史表、不修改实际成本/结算/利润公式。
- `PartnerPrice.laborPrice` 仍供现有劳务结算只读使用，必须独立裁决后再迁移或删除。

## 七、验收最低要求

### 供应商/材料主数据

- 人工维护的 `CatalogItem.costPrice` 不因采购下单、到货或结算自动改变；
- 采购执行价只形成应付/暂估应付事实，不被显示为成本价；
- `PartnerPrice.purchasePrice` 停止新增/读取，存量只读兼容，历史引用可核对；
- `MaterialSupplier.purchasePrice` 不由下单回写、不参与成本价；
- `PartnerPrice.laborPrice` 与劳务结算的保留/迁移边界按裁决验证；
- 无价下单、分批下单、退货和结算不错误改写成本或历史；
- 新订单只能引用当前企业有效合作方；自由文本不得静默创建或绕过主数据；
- 停用合作方不得新建采购或供应关系，历史采购、应付和报表保持可读；
- 跨企业、跨门店、非项目参与和非授权角色请求被服务端拒绝。

### 经营目标与指标字典

- 公司目标与门店目标分层、唯一性和数据范围正确，不自动相加；
- 财务及其他角色按裁决完成正向与越权验证；
- 指标说明与取数 Provider 同源，目标值不冒充指标口径或实际结果；
- 平台口径变更可追溯，历史目标与历史经营结果不被静默重算。

### 设计模版跨端与历史快照

- App/Web 动作矩阵与裁决一致，未授权角色和跨企业/跨门店请求被拒绝；
- 发布版本不可变；停用/删除不影响历史报价；
- 同一房屋 + 同一模版版本实例化幂等，实例化后修改模版不改变历史区域、分项和金额；
- 成本、采购价、供应商历史价与毛利在设计师响应中由服务端裁剪。

### 通用门禁

- App/Web 同一事实、状态、金额、完成条件和错误恢复同源；
- 真实页面/真机/接口证据完整；开发自测不得冒充独立验收；
- 涉及迁移、金额/成本或权限的切片必须有备份、回滚点和全量/核心回归。

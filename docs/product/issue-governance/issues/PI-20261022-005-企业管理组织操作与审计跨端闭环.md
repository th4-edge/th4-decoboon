## 一、问题摘要

企业管理的后端能力相对完整，但前端呈明显不对称：

- App 偏员工生命周期，并已有团队列表和订阅页；
- Web 偏组织效能，只有部分邀请、成员列表和财务调店；
- 安全审计只有后端查询 Provider，双端都没有明确产品入口；
- TeamLeader 冻结后，Team 的创建和维护路径实际断裂；
- 组织调整对手上客户、项目、任务、应收和通知的影响缺少统一提示与交接口径。

本问题不能只通过补几个 Web 页面解决。用户已裁决 Team 冻结；员工生命周期双端范围、订阅支付路径、席位占用公式和审计可见范围已由 `DEC-085` 冻结。

## 二、已确认的正式口径

1. `DEC-082`：TeamLeader 仅保留历史数据兼容，不可邀请、不可改岗、不可登录、不可授权；App/Web 不装载 TeamLeader 业务入口；历史归属不自动改写。
2. `DEC-081`：企业有且仅有一个默认总店，默认总店不可切换；BOSS 邀请财务必须显式选门店；店长仅可邀请本店财务；仅 BOSS 可跨店调整财务；调店不回溯历史业务门店。
3. `DEC-075` / `BR-028`：BOSS 是企业内部能力超集；店长在本店范围内对齐业务能力；订阅、套餐、席位、门店包、门店增删、企业主体、企业负责人转让和角色治理仅 BOSS。
4. `DEC-070`：组织变动不回溯客户、报价、合同、项目、财务单据的历史门店快照；未归属门店记录必须显式标注。
5. `DEC-032` / `BR-028`：同一人连续执行制单、确认、发放等节点仍须逐步留痕，不得合并成一个不可追溯动作。
6. 本轮不改变销售价、标准成本、利润、应收应付、工资提成和凭证金额公式。
7. 订阅商品价格与模块权益仍受 `GAP-016` 冲突约束；在冻结前不得把当前套餐矩阵写成正式商业承诺，也不得覆盖现有套餐版本快照。

### 2.1 业务裁决结果（`DEC-085`）

- 用户明确裁决 Team 冻结：Team 与 TeamLeader 一并冻结，Team 仅保留历史表、字段和快照，不新建、不维护、不分配、不产生数据权限或经营入口。
- 员工邀请管理、岗位/门店调整、停用/恢复、离职和交接在权限范围内要求 App/Web 双端完整；邀请接受/拒绝和本人退出企业为 App-only 例外；Team 不参与。
- 仅改岗位/门店不自动迁移责任；显式交接只转客户/房屋 owner、项目 manager 和未完成任务 owner 等当前责任指针，历史创建人、财务事实、门店/Team 快照不回溯。
- 订阅仅 BOSS；Web 补齐查看、容量、订单和查单，本轮不新增 Web 支付；`GAP-016` 关闭前暂停新购/升级/降级/加购。
- P0 审计聚合安全日志与成员日志，不新增通用租户 OperationLog；BOSS 全企业、店长本店成员 + 本人安全、财务/员工本人安全；Web 完整查询、App 最近 20 条、不导出。

## 四、缺陷/缺口

1. `EMG-GAP-01`：Team 已冻结；剩余风险是历史 Team 字段、旧深链接和服务端 Team 写入必须持续拒绝。
2. `EMG-GAP-02`：员工生命周期动作矩阵已冻结；`EMG-V2` 已实现邀请、调岗、调店、停用、恢复和离职，独立验收 `PENDING`；交接仍归 `EMG-V3`。
3. `EMG-GAP-03`：普通员工调店已由 `EMG-V2` 在 BOSS 范围产品化；店长仍不可调店，Team 调整不支持。
4. `EMG-GAP-04`：组织调整对客户、房屋、报价、项目、任务、应收、通知和待办的影响没有统一影响矩阵。
5. `EMG-GAP-05`：订阅只有 App 完整入口，Web 缺查看/订单/支付/查单闭环；席位展示与邀请占用口径不一致。
6. `EMG-GAP-06`：安全审计无产品入口、无角色可见矩阵、无双端字段和脱敏口径；现有安全日志查询也不等于全企业审计。
7. `EMG-GAP-07`：`EMG-V1` 已移除 TeamLeader 邀请选项、Team 管理/经营入口；独立验收 PASS。
8. `EMG-GAP-08`：组织调整缺少统一的接收人通知、影响预览、原因和幂等证据。

## 五、影响

- 电脑端无法完成完整员工生命周期管理；
- BOSS 需切换端才能管理订阅和资源；
- 组织调整可能造成责任悬空、待办丢失、客户/项目归属与门店范围不一致；
- TeamLeader 冻结后，团队组织可能继续退化为不可维护的僵尸数据；
- 安全审计无法从产品界面核查，组织变更难以形成可追溯证据；
- 前端存在“可见但不可用”的冻结角色入口和团队入口，容易误导操作人。

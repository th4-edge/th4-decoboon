## 一、问题摘要

同一报价在不同入口存在多套投影：

- `QuoteViewContext` 完整区域/类型分组；
- 项目经理视图删除区域；
- App 类型视图前端合并；
- Web 报价工作台只按区域；
- 业主旅程自建 PriceGroup；
- 合同/项目/客户钻取主要显示摘要或不同字段。

如果其他会话只修单页，会加剧跨端和跨场景分裂。

## 二、统一目标

```text
同一 quoteId + version
→ 同一报价事实
→ 同一行项目
→ 同一区域/类型分组
→ 场景只改变上下文、权限、动作和密度
```

## 三、临时处理

现有修复会话开始前：

1. 不单独修改报价展示组件或分组字段；
2. 不新增新的报价 DTO/客户端合并逻辑；
3. 不让合同/项目显示未绑定版本的“最新报价”；
4. 不继续扩展业主旅程 PriceGroup 的第二套模型；
5. 先在现有会话中提交 T05 并消费统一视图契约。

## 四、用户已确认与剩余 T05

已确认：

1. 业主端支持按类型查看；
2. 类型视图合并跨区域相同项目；
3. 合同详情中的报价跳转统一报价视图；
4. 项目端默认区域视图；
5. PDF 允许选择区域/类型分组打印。

仍需 T05/T06/T12：

1. 类型视图合并键的最终字段；
2. 合并后 quantity/amount/sourceCount/sourceRegion 的展示和回读；
3. 合同/项目/业主场景的字段和动作白名单；
4. PDF 分组选择的页面入口和客户版字段。

## 五、验收最低要求

- 同一 quoteId + version 的销售事实和行 ID 跨入口一致；
- 区域/类型双视图可互相解释；
- 合同/项目绑定报价版本；
- App/Web/业主端销售金额一致；
- 成本和内部公式按角色裁剪；
- 前端不重算金额、不自行合并；
- 真实页面和契约测试通过。

## 一、问题摘要

当前 App 已具备较完整的项目履约操作面：施工排期、阶段开工、任务推进、三类节点留证、现场日报、主材作业单新建/编辑/测量/提交/取消、财务下单、采购到场、结算和退货查看。Web 则以项目查看、PM 任务推进、验收提交和财务下单/结算为主，缺少多类强制写能力。

同时，主材作业单定义了 `Settled/Closed` 状态，但结算事实没有推进这两个状态；已到货扣减目前主要依赖合同减项自动生成退货单，破损、错发、少发、补发等非合同减项场景没有冻结独立业务路径。这些问题不能通过单端补页面解决，必须先冻结对象状态和跨端能力边界。

### 2.2 作业单状态断点

- `MaterialSheetStatus` 定义完整：
  `Draft → Measuring → Measured → Submitted → Pricing → PartiallyOrdered → Ordered → PartiallyArrived → Arrived → Settled → Closed`；
- 实际代码会创建、提交、下单、部分到场和到场；
- 未发现结算 Provider 将作业单推进到 `Settled`，也未发现关闭 Provider 推进到 `Closed`；
- 价格状态可以由采购/结算投影为 `Settled`，但单据生命周期状态仍停留在 `Arrived`，两个“结算完成”语义可能不一致；
- `Pricing` 没有有效写入路径；
- `PurchaseOrderItem` 仅关联 `MaterialPlan`，未显式关联作业单行，不能可靠证明多作业单/多行场景的采购归属；
- 结算明细允许小于到场数量，但同一采购明细只能成功结算一次，部分数量会把整条明细锁定为 `Settled`。

### 2.3 价格边界

- 业务决策要求作业单不带价格、账期和成本，价格与供应商决策在采购单侧；
- 当前作业单行仍保存 `quoteCostPrice/purchasePrice/settlementPrice/priceState` 投影；
- 服务端读取时按采购/结算事实聚合，Designer/PM 响应已裁剪商业字段；
- 这些字段仍须冻结为只读投影，不能由前端写入或成为第二套计价事实；
- App 仍存在 PartnerPrice 页面和后端路由，Web 主材下单仍以自由文本供应商名称为入口，已由 `PI-20261022-004` 跟踪。

### 2.4 退货/补发

- 已到货合同减项会生成 `MaterialReturn`，并冲减应付、成本和库存；
- `material/return` 当前只有分页 Provider，没有独立创建/确认/取消入口；
- 破损、错发、少发、色差、补发等非合同减项异常当前没有独立单据和状态机；
- 业务口径已由 `DEC-088/BR-054` 冻结：允许独立 `MaterialAdjustmentOrder`、部分数量、供应商确认和无损退货；业主不确认，只读影响摘要。

## 三、业务影响

- 设计师/项目经理在 Web 无法完成施工排期和现场证据链，只能回 App；
- 财务/PM/设计师在 Web 无法完成作业单维护和到场确认，跨端职责不一致；
- 作业单到场后无法进入已结算/已关闭，列表和后续动作状态不准确；
- 采购价投影若被视为真实价格，会破坏作业单与采购单的边界；
- 非合同减项退换货只能绕开系统或误走合同变更，影响应付、成本和库存；
- 供应商自由文本与 PartnerPrice 并存，导致主数据与价格来源双轨。

## 四、已冻结处理口径

1. App/Web 强制能力按动作一致完整；设备输入方式可不同，Web 必须有文件上传等等价闭环。
2. 施工排期、节点留证、现场日报、作业单全生命周期和到场确认均需双端完整；日报发布限 PM + BOSS/本店店长。
3. 作业单 `Pricing` 退出新流转；`Settled` 由有效到场与未撤销结算覆盖推导，不等待应付付清或项目结算。
4. `Closed` 在 `Settled` 后显式关闭，且无未结采购、到场、异常处置、价差和配送/安装事项。
5. 价格投影只允许服务端只读生成，不能写入、计入单位价格或参与结算/成本/利润。
6. 破损、错发、少发、色差、补发、换货和无合同减项退货统一走 `MaterialAdjustmentOrder`。
7. 退货/补发/换货复用 `MaterialReturn/GoodsReceipt/StockMovement/Payable/PartnerCredit`，不建第二套账。
8. 供应商新写入只接受 `supplierId` 选择器；主数据实现归 `PI-20261022-004`。
9. 项目事实追踪拆为作业单、采购、到场、异常处置、结算五个独立节点族，接入 `PI-20261022-010`。
10. 本次裁决不等于代码完成或验收通过；DDL、权限、金额/成本/库存联动切片实施前仍需用户确认。

### 5.1 作业单状态公式

```text
有效下单量 = 当前有效采购明细数量
有效到场量 = 累计到场 - 已确认退货/拒收 + 已确认补发到场
有效结算量 = 未撤销结算明细累计数量
```

- `PartiallyOrdered`：有有效采购，但作业单需求未全部被采购覆盖。
- `Ordered`：作业单需求全部被有效采购覆盖。
- `PartiallyArrived`：有有效到场，但未满足全部到场/异常终态。
- `Arrived`：有效到场满足有效下单量，或差额已有终态处置。
- `Settled`：每条有效采购明细的有效结算量覆盖有效到场量，退货/补发/换货/价差已处理，价格完整。
- `Closed`：`Settled` 后显式关闭，且无未结采购、到场、异常、价差和配送/安装事项。
- `Pricing`：仅历史兼容，不再写入。

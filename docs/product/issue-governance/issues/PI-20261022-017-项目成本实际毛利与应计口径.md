## 一、问题摘要

最新业务规则明确区分：

```text
P1 报价成本价 = 预计成本
P2 采购价 = 应付/暂估成本
P3 结算价 = 实际材料成本唯一最终来源
P1 不得进入实际成本
任一应计成本缺失 → costComplete=false → 利润/毛利率=null
```

当前代码中，`ProjectCostContext.actualCost` 在缺少实际成本时会回退合同成本、报价成本或目录成本；没有采购记录时还可能保持 `costComplete=true`。财务项目报告又把 `ProjectCostContext.actualCost` 与应付汇总取较大值作为总成本，而不是按“实际材料 + 人工/班组 + 员工工资/提成 + 其他应计成本”分类汇总。

这使项目卡片、项目账本、结算快照和驾驶舱可能把预计成本、采购价、应付金额、实际成本混在同一字段或同一利润口径里，存在展示伪利润或错误利润的风险。

## 二、当前代码事实

- `ProjectCostContext.contractActualCost`：优先实际成本，其次合同冻结成本、报价快照成本、目录成本、预计回退值；
- `ProjectCostContext.actualCost`：优先 `QuoteLine.actualCost`，否则使用目录成本或预计成本；
- `hasIncompletePurchaseCoverage`：没有关联采购时返回 `false`，不会仅因“尚未采购/尚未到货”标记不完整；
- `FinanceReportContext.totalCost` / `FinanceProjectLedgerContext.totalCost`：使用 `max(ProjectCostContext.actualCost, Σ应付成本)`；
- 成本完整性 `costComplete` 主要来自 `ProjectCostContext.incompleteItemCount`，没有显式区分预计成本、实际成本、结算成本和未发生成本；
- 项目报告同时存在 `estimatedCost`、`actualCost`、`totalCost`、`profitAmount`、`grossProfit`、`grossMargin` 多个字段，但语义和展示条件未完全统一。

## 三、业务影响

- 未采购或未到货时，P1 可能被显示为实际成本；
- 实际毛利可能在没有 P2/P3 的情况下被输出；
- 不同成本类别采用总值 `max`，可能在部分成本实际发生、部分仍为预计时错算；
- 项目卡片、项目账本、结算和驾驶舱可能出现不同利润数字；
- 用户可能把预计毛利误当成最终经营结果，违反“管项目和钱，不做假利润”的红线；
- 历史承接成本和当前实际成本叠加时，完整性判断会更复杂。

## 四、临时处理

专项裁决前：

1. 不调整成本公式或字段名称；
2. 不把 `ProjectCostContext.actualCost` 直接解释为业务上的“实际成本”；
3. 不新增第二套利润计算；
4. 不在前端用 P1/P2/P3自行拼利润；
5. 成本不完整时继续显示 `null/成本未完整`，不得用 0 兜底；
6. 不修改历史已确认结算快照。

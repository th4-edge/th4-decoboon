## 一、问题摘要

当前系统有：

- `PayableType.Expense` 费用支出应付；
- `LedgerManualPurpose.CompanyExpense` 手工企业费用；
- `DocumentTemplateBaseline` 中的费用报销付款单、差旅费报销单模板；
- `Settlement.expenseAmount` 费用分摊字段。

但这些只覆盖“费用记一笔”和“打印一张凭证”，没有独立的费用申请/报销业务对象、审批状态机、票据附件、付款核销和成本归集闭环。用户要求 B2E 覆盖企业费用/报销，不能把模板存在当成业务闭环。

## 二、当前代码事实

### 2.1 已有能力

- 手工流水可选择企业费用用途；
- 费用可以形成 `Payable(Expense)`，再通过 `Payment` 付款；
- 单据模板预设有费用报销付款单、差旅费报销单；
- 项目结算模型存在费用分摊字段；
- 资金台账可以按企业费用分类统计。

### 2.2 缺失能力

- 无 `ExpenseRequest` / `Reimbursement` 主对象；
- 无员工提交、票据/附件、审批、驳回、退回、重提、付款、关闭状态；
- 无费用分类、门店/项目/企业归属、预算/额度、费用说明的结构化规则；
- 无“报销模板 → 报销单 → 审批 → 应付/付款 → 凭证”的对象链；
- 无企业费用与项目零星成本的统一边界；
- App/Web 均无独立费用/报销页面。

## 三、业务影响

- 企业费用和项目成本容易混记；
- 员工垫付、差旅、项目零星费用无法形成可追踪审批链；
- 报销模板只能打印，不能证明费用业务成立；
- 费用付款和项目成本归集缺少来源；
- 公司经营利润（参考）缺少可靠的企业费用来源；
- App/Web 财务矩阵无法解释“为什么有模板却没有报销闭环”。

## 四、临时处理

专项裁决前：

1. 不新增费用申请/报销表和状态机；
2. 不把 `Payable(Expense)` 当作完整报销单；
3. 不把报销模板当作业务事实；
4. 不将企业费用自动计入项目毛利；
5. 不扩展成本分摊和公司经营利润正式口径；
6. 手工企业费用继续按现有边界使用，但不对外宣称报销闭环已支持。

## 七、验收最低要求

- 费用申请/报销与手工流水、应付费用、模板打印边界清楚；
- 一张报销单可追溯到提交人、票据、审批、付款和凭证；
- 金额、归属、期间、项目/门店/企业分类可对账；
- 财务不能自审自付，或按正式裁决执行；
- 项目零星费用只进对应项目成本，企业费用不误入项目毛利；
- 报销模板版本与历史 PDF 可回读；
- App/Web 同一费用事实、状态、金额和下一步一致；
- 跨企业、跨门店、越权、重复提交、重复付款被拒绝；
- 真实页面、真机/浏览器、接口和独立验收证据齐备。

## 一、问题摘要

装企信息已经存在于企业资料、门店、业主服务方投影和单据抬头中，但同名信息存在多套承载：

- `Company.title/name/logo/addr` 与 `DocumentProfile.legalName/address/logo` 重复；
- 业主端使用 `Company/Setting` 实时投影，PDF 使用 `DocumentProfile`，二者没有统一快照边界；
- 企业 Logo 已存储，但 App 业主首页使用平台 Logo，PDF 未统一使用企业 Logo；
- 地址同时表示企业办公地址、门店地址、项目施工地址和房屋地址；
- 未发现地图经纬度/点位，无法形成稳定导航；
- `DocumentProfile` 有独立写接口，但前端未发现完整维护入口和消费链。

## 二、业务影响

- 企业换 Logo/地址/名称后，不同页面和文件可能显示不同版本；
- 历史合同、报价和凭证有被当前主档回溯影响的风险；
- 业主无法清楚知道服务主体、服务门店和前往位置；
- 装企品牌在合同、打印、导出和业主端露出不一致；
- 财务税号、法人、开户信息可能在不同来源漂移；
- 企业实际品牌与法定主体不一致时缺少明确兼容规则。

## 三、临时处理

- 不新增企业信息字段、不修改权限、不修改 PDF/导出/业主投影。
- 不把平台 Logo 当作装企 Logo。
- 不在当前主档和 `DocumentProfile` 之间静默同步。
- 历史文件继续按归档文件读取，不使用当前主档回写。
- 只允许继续概念梳理、代码映射、业务咨询和最小影响分析。

- App/Web 企业信息页按“基础身份 / 企业品牌 / 对外服务信息 / 对外署名”分组；

- 品牌色采用安全预设，默认使用装得清品牌语义主色；
- 员工邀请、业主首页和业主分享页使用同一企业品牌组件；

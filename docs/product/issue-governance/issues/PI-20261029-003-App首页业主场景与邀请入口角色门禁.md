## 一、问题摘要

1. 游客首页只按装企内部四类能力介绍，缺少业主端这一重要使用场景。
2. 登录页首次登录存在“先静默微信登录、失败后再手机号授权”的额外步骤。
3. 员工邀请和业主邀请额外调用 `getUserProfile`，产生不必要的微信资料授权。
4. 未加入企业页图标底色和图标风格不一致，员工卡片还存在无实际动作的展开点击。
5. 邀请上下文可能在登录/未加入企业页丢失，导致已邀请员工或业主落到通用未加入企业页。

## 二、本次调整

- 游客首页增加业主专属入口、场景说明和“我是业主，进入我的家”行动。
- 企业入口文案改为“企业负责人 / 员工登录”。
- 登录页原先从首次点击开始直接使用手机号授权主行动；该方案已被 `CHG-20261029-011` 修正，当前口径为先识别已绑定的微信身份，仅首次绑定请求手机号。
- 员工和业主邀请不再请求微信昵称/头像，使用邀请中的姓名与手机号核对。
- 新增邀请上下文存储 `jzb_invite_intent_v1`：
  - 员工邀请 → 员工邀请确认页；
  - 业主邀请 → 业主进入页；
  - 未加入企业页读到邀请上下文时直接分流，不继续展示身份选择。
- 未加入企业页统一图标底色、大小和描边图标风格，移除员工卡片无动作展开。
- 员工接受邀请后进入企业首页；业主接受邀请后进入业主首页。

## 三、当前事实

- 微信隐私弹窗是平台侧授权机制，首次使用时仍由微信展示；本次不再额外请求个人资料。
- 手机号授权仍需要用户点击一次，微信不允许静默获取手机号。
- 邀请页仍保留必要确认，不自动替用户接受邀请。
- 未执行的正式小程序审核发布仍由用户本人完成。

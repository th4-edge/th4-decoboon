## 一、问题事实

App 项目财务页把 `paymentRate` 展示为“成本 25%”。该字段公式实际为：

```text
paymentRate = paidAmount / payableAmount = ¥500 / ¥2,000 = 25%
```

项目实际成本为 ¥800，预计成本为 ¥1,760，且 `costComplete=false`。将付款核销进度标成“成本”会让用户误以为成本只发生了 25%，与项目成本和成本完整性事实冲突。

Web 财务工作台另有两张关注卡使用“应收与逾期 / 应付与到期”，但显示值是 `urgentReceivables.length / urgentPayables.length`，容易被理解为全部应收应付笔数。

## 二、修复

- App 项目页：“成本 25%”改为“付款进度 25%”；
- Web 财务工作台：“应收与逾期”改为“需关注应收”；“应付与到期”改为“需关注应付”；
- 不改变 `paymentRate` 公式、金额、应付核销或成本完整性逻辑。

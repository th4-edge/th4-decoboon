## 二、规则判断

- `DEC-055 / CC-05`：原 `QuoteLine` / `ContractLine` 不改，已施工/采购事实保留；但成本完整性与利润必须基于当前有效业务范围。
- `BR-058`：最终成本必须来源完整；不能因已取消范围永远无法完整。
- `DEC-092`：`Draft` 展示动态/预计；`Confirmed` 必须 `finalCostComplete=true`。
- 因此当前实现属于成本完整性分母未按有效剩余投影计算，而不是需要修改业务规则。

## 三、影响

- 任一完全减项的材料会持续制造 `Missing`，即使项目已无采购义务。
- 项目最终成本可能永远不完整，结算无法确认/关闭，利润始终为空。
- 影响同一项目卡片、合同工作面、财务工作台、项目账本、结算和 Boss 驾驶舱。

## 四、修复门禁

1. 在 `ProjectCostContext` 计算材料完整性分母前，按当前有效剩余应用已生效 `Remove / Quantity / Replace` 快照：
   - 数量为 0 的有效减项不得计入材料缺失；
   - 部分减少只保留剩余数量要求；
   - 已发生采购/到场/退货仍按事实流转，不得删除历史。
2. 不得改写原合同行、报价行或历史成本快照。
3. 不得把有效减项成本差额直接当实际成本，也不得用 P1 回填实际成本。
4. 人工/工资/费用缺失仍单独阻断最终成本，不能借减项修复绕过。
5. 覆盖：
   - 整项 Remove；
   - 部分 Quantity；
   - Replace 原范围关闭 + 新目标范围；
   - 已采购后减项/退货；
   - 重复审批、并发剩余占用；
   - 跨页面/App/Web 同源金额与完整性。

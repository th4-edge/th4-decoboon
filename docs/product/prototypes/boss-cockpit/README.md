## D1 页面意图冻结

| 项目 | 结论 |
|---|---|
| 页面类型 | BOSS 决策工作台 |
| 目标角色 | 企业负责人（全部门店范围） |
| 角色职责 | 判断经营是否在轨、发现影响结果的风险、把问题交给正确责任人 |
| 结果指标 | 签约额、净回款、项目成本完整性、经营利润参考、待处理事项 |
| 触发事件 | 每日经营判断 / 月度经营复盘 |
| 用户打开页面的第一个问题 | 本月经营是否在轨？今天先处理哪几件事？ |
| 三秒结论 | 签约在轨，回款和成本完整性需要先处理 |
| 唯一主行动 | 处理 6 项待办 |
| 任务链 | 进入驾驶舱 → 看判断 → 选待办 → 查对象/责任人 → 进入处理队列 → 回读结果 |
| Web 提升点 | 多门店对比、趋势对照、风险并行处理、导出经营简报 |

## 页面结构

1. **经营判断带**：签约、回款、成本完整性、待办数量。
2. **经营结果**：一个连续指标区，不再拆成四张独立 KPI 卡片。
3. **趋势**：标题直接表达经营结论，图表只做证据。
4. **经营结构**：门店结果 / 经营漏斗 / 报价转化三个页签，只展示一个工作面。
5. **待我处理**：按业务影响排序，直接连接对象、责任人与动作。
6. **需要关注**：只保留三条与经营结果相关的提醒。

## 专业评审后的调整

- 移除 BOSS 驾驶舱中的 2.5D 模块：它没有减少 BOSS 的判断步骤，属于负担设计。
- 删除英文 eyebrow、装饰圆环、状态药丸堆叠和“数据诚实优先”等设计说明文案。
- 将四张 KPI 卡片合并为一个连续结果区。
- 将门店/漏斗/报价从纵向堆叠改为页签，使页面只保留一个当前工作面。
- 把“状态预览/演示数据”控件移入 `?debug=1`，正常产品界面不展示。
- 页面文案只服务操作和判断，设计理由进入 README 与评审记录。

## 数据与业务边界

本页面为演示数据原型，数字用于验证信息结构和交互，不代表真实经营结果。

正式实现优先消费：

- `statistic/boss/business/report`
- `statistic/organization/report`
- `statistic/store/report`
- `statistic/target/info`
- `statistic/store/profit/report`

口径边界：

- 签约额按签约日归月。
- 净回款为收款减去收款冲正，按收款/冲正日期归期。
- 经营利润参考在成本不完整或口径未冻结时显示“暂不可确认”，不按 0 计算。
- 公司目标与门店目标分开展示，不自动相加。
- 演示门店、客户与责任人均为虚构数据。

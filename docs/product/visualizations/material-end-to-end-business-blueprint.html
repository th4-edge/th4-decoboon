从合同材料行到现场、采购与结算的一张全景图

材料计划负责“需要什么”，主材下单作业单负责“按品类怎么向厂家下单”，采购单负责“向谁买、什么价、形成多少应付”，到场与结算负责“是否真的到、最终成本是多少”。增减项则从合同变化反向驱动材料需求、采购调整、退货和账务。

05

两种“现场确认”

不要把“选材现场确认”和“材料到场确认”混为一件事。

一前一后，责任不同

选材现场确认 购买前

设计师/授权维护人与客户在房屋现场确认颜色、规格、型号、工艺等，系统保存为选材记录；当前口径是“保存即已选材”，交付财务后计划行进入可下单。

01
现场事实颜色、规格、品牌/系列、工艺、备注、照片；以文本/JSON 保存，不反向改报价、合同或成本。
02
门禁合同选材来源的材料计划行，必须存在 Selected 选材记录；进入采购后锁定，换材必须走增减项。
03
交付不等于下单`deliver=true` 只把 Planned 推进为 ReadyToOrder；供应商、价格、数量仍由财务下单时确定。
04
异常未选材、已采购、跨企业/非项目参与人保存均被拒绝；已确认后再次保存会生成新版本。

材料到场确认 采购后

项目经理或设计负责人确认实际到场数量与日期。应付不是到货才产生；到货只回填账期起算、实际到场数量和实际成本。

01
到场数量可部分到场；数量不得超过该采购明细的剩余可到场量；多明细采购单必须指定明细。
02
到场日期`arrivedAt` 是实际到场日期，不是系统确认动作时间；页面当前只填日期，传入为当天 00:00:00。
03
账务联动回填应付账期起算日/到期日；直送不动库存，入仓同步库存与流水；实际成本按到货数量累计。
04
异常破损/少发/错发/色差保留到场事实，后续走补发、退货或扣款差异；无价不阻断到场。
06

增减项与材料联动

同一笔变更，按材料当前处于哪一层，走完全不同的处理路径。

审批通过即生效
合同变更审批通过 → ContractChangeFulfillmentContext.apply()

增项 Add

生成新的材料需求计划行，来源为 ChangeAdd，状态 ReadyToOrder。

  • 继续走选材/作业单/采购
  • 不直接改原合同材料行

替换 Replace

未采购的原计划可关闭并生成替代需求；已采购则保留原事实，生成替代计划。

  • 原计划已采购：原物退货/调整
  • 新计划重新走采购

数量 / 价格变更

调整现有材料计划；数量减少时进入三段式扣减；价格变更更新计划口径，不覆盖采购/结算历史。

  • 未下单：先冲损耗，再冲净用量
  • 已下单：调整采购明细与应付差额

减项 Remove

按材料当前状态处理，绝不直接改应付而不留退货记录。

  • 未下单：直接冲减计划
  • 已下单未到：调整采购明细/应付
  • 已到货：生成退货单并冲减成本
A
计划层：直接冲减先冲损耗量，再冲净用量；不产生退货单，适用于尚未下单的部分。
B
采购层：调整采购明细减少采购数量与金额，按差额下调同一采购单的应付；采购单状态重新汇总。
C
到场层：退货冲减生成 MaterialReturn，回退到场量、冲减实际成本与应付；入仓材料同步库存退回。
D
往来层：余额兜底本单应付不够冲减时，先冲同供应商其他应付；仍有余额转 PartnerCredit 往来余额。
↳替换不是“覆盖原记录”，而是“保留原事实 + 新增替代需求”；历史单据和账务必须可追溯。
07

价格与账务口径

同一份材料有三个价格事实，不能用 0 或预计成本冒充实际成本。

成本完整性门禁
P1 · QUOTE COST

报价成本价

报价/合同行的成本快照，用于预计成本和偏差；签约后冻结，不进入实际成本。

P2 · PURCHASE PRICE

采购价

财务/采购对供应商的下单价；可调整，是应付金额和暂估成本依据。

P3 · SETTLEMENT PRICE

结算价

对账后最终真实价；实际成本的唯一计价来源，不写回供应商参考价。

下单即形成应付有价：应付 = Σ(数量 × P2) 无价：暂估应付，金额待定，estimated = true
实际成本收敛实际材料成本 = Σ(到场数量 × P3) P3 未知时按 P2 暂估；仍缺失则 costComplete = false
利润门禁costComplete = false → 实际毛利 / 毛利率 = null → 页面显示“成本待结算”
结算互斥同一采购明细只能结算一次 逐单优先 → 月结只结算未逐单结算的差额 撤销后释放明细，允许重新结算
↳到场的账务作用：到场不新增应付，只回填应付账期起算日/到期日、确认实际到场量并累计实际成本。应付金额由下单和结算负责。
08

状态机

计划状态和作业单状态是两条线，单向映射，禁止双写。

状态由事实派生

MaterialPlan · 需求/履约状态

由采购与到场事实派生。

Planned 待选材ReadyToOrder 可下单PartiallyOrdered 部分下单Ordered 已下单PartiallyArrived 部分到场Arrived 已到场Closed / Cancelled
↳Requested / Approved 是历史兼容状态，不再作为新数据主链。

MaterialOrderSheet · 单据/编排状态

只编排，不替代事实层状态。

Draft 填单中Measuring 待测量Measured 已测量Submitted 已提交请购Pricing 财务核价Ordered 已下单PartiallyArrived 部分到场Arrived 已到场Settled 已结算Closed / Cancelled
↳已下单后取消必须走退货或采购调整；换材走增减项。

PurchaseOrder / Receipt

采购单按明细汇总，到场记录不新增应付。

SubmittedApprovedOrderedPartiallyReceivedReceivedRejected / Cancelled
↳GoodsReceipt 是到场事实；入仓才产生库存/流水，直送不产生库存。

10

当前实现边界

这份蓝图以已裁决业务口径为主，同时明确当前代码还没有完全对齐的地方。

上线前需关注
P0 · 入口

App 作业单没有正常业务入口

当前只存在路由和页面间跳转，没有从项目详情/工作台调用 `P.materialSheet` 的入口；普通用户无法自然进入。

P0 · 语义

Excel “下单时间”实际是建单时间

`MaterialSheetExportContext` 使用 `sheet.createTime`；它既不是请购时间，也不是财务采购下单时间。

P1 · 模板

测量字段没有按品类模板驱动

详情页对所有可编辑作业单显示测量卡片；没有按 Tile / Curtain / CustomCabinet 的字段显隐与必填配置。

P1 · 门禁

测量日期不是提交请购的强制条件

提交请购当前主要校验选材和数量；如果某品类要求测量必填，需要在提交前增加模板级门禁。

P1 · 取消

作业单缺少独立取消 Provider

状态机定义了 Cancelled，但当前没有 `material/sheet/cancel` 路由；提交后取消/重开路径需要产品裁决。

已对齐

采购价 / 结算价 / 成本完整性

P2 形成应付，P3 收敛实际成本；无价不写 0，costComplete=false 时利润为 null。

术语对齐

销售、实施、产品、研发说同一个词时，应该指向同一个对象。

材料计划MaterialPlan
项目级需求事实，回答“需要什么、多少、什么时候要”。
选材记录MaterialSelection
现场确认结果，文本/JSON/图片；不等于结构化采购明细。
主材下单作业单MaterialOrderSheet
按品类对厂家的作业单据，1 张可对 N 张采购单。
采购单PurchaseOrder
对供应商的交易单据，携带价格、账期和应付。
经销商 / 供应商Partner
当前统一建模为合作方；Supplier / Factory 等用类型区分。
材料供应关系MaterialSupplier
材料—合作方的供货关系、参考价、起订量、交期。
到场记录GoodsReceipt
实际到场数量/日期/照片；不等于采购下单。
退货单MaterialReturn
已到货减项的统一冲减载体，冲应付/成本/库存。
结算价settlementPrice
最终实际成本唯一来源；不写回供应商参考价。

# 装企财务承接操作手册

> 读者：装得清实施/客户成功、装企 BOSS、财务、项目经理
> 适用：有在跑项目、希望把当前未结业务接进装得清的新入驻装企
> 原则：不搬科目、不重建历史明细、只接当前未结事实

## 1. 角色分工

| 角色 | 职责 |
| --- | --- |
| 装得清实施/客户成功 | 主持启动会、摸底、对照表、双轨对账、培训、首月陪跑 |
| 装企 BOSS | 确认承接范围、归属、金额、最终提交、差异处理 |
| 装企财务 | 期初应收应付、期初资金、成本完整性、原账口径、日常记账 |
| 装企项目经理 | 项目当前状态、剩余施工、现场重点、成本情况 |
| 装企设计师 | 按需确认报价、合同范围、有效增减项 |

## 2. 前置条件

- 企业已注册，BOSS 账号有效，默认总店已建立；
- 已确认哪些项目属于在跑范围；
- 能明确接管日期；
- 对项目负责人、合同金额、当前状态有可确认的信息来源；
- 没有来源的信息进入待确认，不猜测。

## 3. 六步承接标准流程

### 第 1 步：账本摸底

**使用人**：实施 + 装企财务  
**工具**：`templates/01-账本摸底表模板.csv`

要摸清：

- 客户有哪些账本：内账、外账、项目账、资金账；
- 使用什么系统/工具：用友、金蝶、Excel、纸质；
- 科目/分类体系、期间、期末余额；
- 资金账户有哪些、各自余额；
- 谁负责、哪些数据能确认、哪些数据缺失。

**完成标准**：账本清单、资金账户清单、责任人清单明确；缺失项已标记“待确认”。

### 第 2 步：承接范围与接管日

**使用人**：BOSS + 实施  
**工具**：`templates/02-在建项目承接表模板.csv`

要明确：

- 本次承接哪些在跑项目；
- 哪些已完工已结清项目只做档案；
- 接管日期是哪一天；
- 每个项目的负责人、当前阶段、剩余施工。

**完成标准**：项目范围、接管日、责任归属三方确认；归属缺失进入待确认，不自动分配。

### 第 3 步：期初应收

**使用人**：财务  
**工具**：`templates/02-在建项目承接表模板.csv`

口径：

```text
期初应收 = 接管日项目未收余额
```

操作要点：

- 每个项目登记一条期初应收汇总；
- 填未收金额、到期日、原账来源单号/备注；
- 如果项目明确“无应收”，必须显式标记，不能空着；
- 接管日以前的已收款只做摘要/附件，不生成收款流水。

**完成标准**：每个项目“有金额”或“明确无应收”；未确认项进入待补清单。

### 第 4 步：期初应付

**使用人**：财务  
**工具**：`templates/02-在建项目承接表模板.csv`

口径：

```text
期初应付 = 接管日项目未付余额
```

操作要点：

- 每个项目登记一条期初应付汇总；
- 填未付金额、到期日、收款方、原账来源单号/备注；
- 如果明确“无应付”，必须显式标记；
- 接管日以前的已付款只做摘要/附件，不生成付款流水，也不计入接管后成本。

**完成标准**：每个项目“有金额”或“明确无应付”。

### 第 5 步：期初资金 + 剩余收付款计划

**使用人**：财务 + BOSS  
**工具**：`templates/05-期初资金账户表模板.csv`、`templates/04-首月双轨对账表模板.csv`

#### 5.1 期初资金余额

- 按资金账户登记接管日余额：对公、现金、微信、支付宝、其他；
- 期初余额只作为账户起始余额；
- **期初余额不计入收入、不计入支出、不进入利润**；
- 账户余额公式：`当前余额 = 期初余额 + 接管后净流量`。

#### 5.2 剩余收付款计划

- 是对第 3/4 步期初应收应付的**时间分解**，不是新增一笔应收应付；
- 计划合计必须等于期初应收/应付总额；
- 允许“未排期”部分，但必须标记；
- 收款/付款仍核销期初应收/应付，不核销“计划项”。

**完成标准**：期初资金账户余额已确认；剩余计划合计与期初余额一致或有明确未排期标记。

### 第 6 步：成本完整性与角色确认

**使用人**：财务 + BOSS + PM（必要时设计师）  
**工具**：`templates/02-在建项目承接表模板.csv`

操作要点：

- 登记接管前成本总额；
- 确认成本是否完整；
- 成本不完整时，项目毛利显示为空，并提示“成本未完整”，不得按 0 计算；
- BOSS、财务、PM 分别确认；角色未建立时允许 BOSS 代确认并留痕；
- 项目发生首笔真实业务后锁定，只允许调整、更正或冲正。

**完成标准**：成本总额与完整性已确认；所需角色确认完成；项目可正式承接。

## 4. 首月双轨运行

**使用人**：财务 + 实施  
**工具**：`templates/04-首月双轨对账表模板.csv`

| 周期 | 动作 |
| --- | --- |
| 第 1 周 | 完成六步承接，开始双轨记录 |
| 每周 | 对四个主题：项目未收、项目未付、资金余额、项目成本 |
| 第 4 周 | 生成首月对账小结，差异分类收口 |
| 第 5 周 | 经营对账会，确认哪些继续用原账本、哪些完全走装得清 |

差异只分类记录，不静默调账：

- 时间差异：跨期、账期；
- 主体差异：供应商/班组/个人；
- 含税差异：含税/不含税；
- 口径差异：合同额/已收/已结清；
- 数据缺失：无依据、待补。

## 5. 接管后日常规则

| 场景 | 操作 |
| --- | --- |
| 客户收款 | 走应收/收款，自动核销期初应收 |
| 供应商/工人付款 | 走应付/付款，自动核销期初应付 |
| 材料采购 | 走采购到货，形成实际成本和应付 |
| 房租、税费、办公费 | 手工记账 → 企业费用，只进现金流 |
| 借款、还款、押金、备用金 | 手工记账 → 资金往来，只进现金流 |
| 项目零星支出 | 手工记账 → 项目零星成本，必须关联项目，计入项目毛利 |
| 设计费、材料销售、服务费 | 手工记账 → 其他收入；关联项目时计入项目收入与毛利 |

禁止在手工记账登记：客户工程款、材料款、工资、项目款；系统会引导到应收/应付。

## 6. 常见异常处理

| 异常 | 处理 |
| --- | --- |
| 项目负责人不明确 | 待确认，不自动分配 BOSS |
| 一个客户多套房屋 | 必须逐套确认，禁止用第一套兜底 |
| 只有纸质合同 | 先建项目 + 上传扫描件；合同金额标记待确认 |
| 未收/未付金额无法确认 | 允许暂缺，该项目标记未完成，进入待补清单 |
| 原账科目无法对应 | 记录在“原账口径备注”，不强行建科目 |
| 成本只知道总额 | 登记总额 + 标记完整性，利润置空 |
| 重复提交同一项目 | 按企业 + 项目业务键幂等，进入编辑而非新建 |

## 7. 完成标准（承接完成定义）

> 项目经理可以继续管理工地，财务可以继续处理未结款，老板可以看到当前真实经营状态，同时历史已结清事实不会污染接管后的经营指标。

# 装得清 · 供应商协作业务设计与操作手册

> 版本：P0  
> 更新时间：2026-09-18  
> 适用对象：中小家装企业、门店、材料员、项目经理、财务和企业负责人

## 1. 设计结论

中小装企与材料商的合作不是完整 ERP，而是下面这条最短业务链：

```text
微信询价
  → 确定供应商和当前采购价
  → 项目按需下单
  → 供应商直送工地
  → 现场确认到货和异常
  → 自动形成项目实际成本与供应商应付
  → 月底按供应商对账付款
```

系统必须优先服务这条链路。库存、批次、领料、复杂审批和供应商门户属于后续能力，不应成为首次使用门槛。

老板真正需要回答的三个问题：

1. 这个项目还缺什么材料，应该找谁买？
2. 这家材料商现在多少钱、多久到、最少买多少？
3. 哪些货已经到场，月底应该付给供应商多少钱？

## 2. 角色与职责

| 角色 | 主要动作 | 可见范围 |
| --- | --- | --- |
| 企业负责人 BOSS | 确认供应商、采购价、异常采购、供应商结算 | 全企业供应商、成本、毛利、应付 |
| 店长 StoreManager | 确认门店项目采购、催货和供应商协同 | 门店项目、门店供应商协作数据 |
| 材料员 ProjectSupport | 询价、下单、催货、到场确认、异常登记 | 委派项目、供应商执行价、数量和到货 |
| 项目经理 PM | 提交材料需求、确认到场数量和质量异常 | 自己负责项目，不默认查看供应商利润口径 |
| 财务 Finance | 应付确认、月结对账、付款和差异处理 | 全企业应付、付款、供应商往来 |
| 设计师/业务员 | 查看材料、影响客户方案和报价 | 只查看允许的销售信息和方案状态 |

### 采购执行价权限说明

当前规则将采购价限制为 BOSS、店长、财务可见，但实际业务中材料员通常需要看到供应商执行价才能下单和催货。

推荐将权限拆成两个层次：

- `采购执行价`：材料员可看，用于询价、下单、催货和到货核对。
- `项目成本/毛利/其他供应商报价`：只有 BOSS、店长、财务可见。

是否向材料员开放采购执行价，应由 BOSS 配置。不能通过前端隐藏代替服务端权限。

## 3. 六个核心实际场景

### 场景 A：询价和选择供应商

**真实动作**

材料商在微信里发来报价：

> 马可波罗 CH12811，750×1500 柔光砖，68 元/片，500 片起订，7 天到货，月结 25 日。

老板或材料员比较两三家后，选择一家作为当前合作供应商。

**系统必须记录**

- 供应商
- 报价项目
- 采购价
- 单位
- 起订量
- 交期
- 默认账期
- 更新日期

**系统不应强制**

- 每次录入都填写生效日期和失效日期
- 建立多个价格本
- 填写复杂税率和运费规则
- 必须上传正式报价单

**操作结果**

报价项目库直接维护标准成本价；BOSS、店长、材料员和财务可维护，设计师、业务员和项目经理默认不可见。

---

### 场景 B：项目需要采购材料

**真实动作**

项目经理或材料员打开项目材料计划，发起采购：

> 湖畔云庐项目，瓷砖 600 片，供应商 A，68 元/片，9 月 25 日送到工地。

**系统必须支持**

- 从材料计划生成采购单
- 自动带出项目、房屋和报价项目
- 选择供应商
- 显示该供应商当前采购价
- 修改本次采购数量和实际执行价
- 指定预计到场日期
- 选择“直送工地”或“入仓库”

**默认路径**

`供应商直送工地`

只有用户明确选择“入仓库”时，才进入仓库、库存和批次流程。

**采购单状态**

```text
待确认 → 已下单 → 部分到货 → 已到货 → 已结清
```

审批、驳回、取消作为动作存在，不要求在每次采购中展示全部状态节点。

---

### 场景 C：供应商发货和现场到货

**真实动作**

供应商将材料送到工地。项目经理或材料员现场确认：

> 订 600 片，实际到 598 片，其中 2 片破损，需要补发。

**系统必须支持**

- 确认到场数量
- 确认实际到场日期
- 上传现场照片
- 记录少发、破损、错发、色差
- 选择补发、退回、扣款或后续处理
- 支持部分到货
- 到货后自动形成实际材料成本

**默认结果**

- 直送工地：不新增仓库库存，直接形成项目实际成本。
- 入仓库：增加仓库库存，后续领料。
- 两种方式都可以形成供应商应付。

---

### 场景 D：月底对账和付款

**真实动作**

月底，财务按供应商汇总所有到货单，与供应商微信账单核对：

- 本月采购金额
- 已到货金额
- 已付款金额
- 未付余额
- 差异和扣款

**系统必须支持**

- 按供应商汇总采购和到货
- 自动生成应付
- 按供应商账期计算到期日
- 支持收货后天数和每月固定对账日
- 支持一笔付款冲抵该供应商多张应付单

**系统不应强制**

- 每张采购单都单独生成一次对账
- 供应商必须登录系统确认
- 所有采购都走线上支付

---

### 场景 E：价格变化、补货和退换货

**真实动作**

- 供应商通知涨价。
- 项目临时补货。
- 材料破损需要补发或退供应商。
- 色差需要换货。

**系统必须支持**

- 记录采购价历史
- 提示受影响项目和报价
- 补货使用当前有效价格
- 到货异常进入待处理
- 退货按金额冲减项目实际成本和供应商应付

**系统不应强制**

- 每次价格变化都重新创建供应商
- 退换货必须走新的完整采购流程
- 差异直接覆盖原始到货记录

---

### 场景 F：全屋定制和施工班组

**全屋定制**

```text
定金 → 复尺 → 生产下单 → 到货安装 → 尾款
```

**施工班组**

```text
施工任务 → 工程量确认 → 班组结算 → 应付
```

它们共享供应商、价格和应付模型，但不应被强制套用普通材料的库存逻辑。

## 4. P0 功能范围

### P0-1 供应商协作首页

展示：

- 待采购材料计划
- 进行中采购单
- 待到货采购单
- 到货异常
- 供应商未付金额
- 最近采购价变化

用户可以从首页直接进入采购、到货和对账。

### P0-2 供应商与品牌关系

- 报价项目直接维护标准成本价
- 供应商按品牌关联，如“马可波罗”关联可选供应商
- 同一品牌下多个报价项目共享供应商匹配
- 采购单保存本次执行价和供应商

### P0-3 项目采购单

- 从材料计划创建
- 默认直送工地
- 支持选择供应商
- 自动带出当前标准成本作为参考
- 支持修改本次执行价
- 支持待确认、已下单、部分到货、已到货和已结清
- 企业负责人和财务创建采购单时可直接确认，其他角色提交后进入审批

### P0-4 到货确认

- 支持部分到货
- 记录数量和异常
- 支持现场照片
- 自动生成实际成本和应付
- 直送默认不进入库存

### P0-5 供应商应付和月结

- 按供应商汇总应付
- 自动计算到期日
- 支持付款冲抵多张应付
- 支持差异备注和扣款记录

### P0-6 操作说明

系统内每个页面提供一行业务提示：

- 当前处在什么业务节点
- 下一步应该做什么
- 什么情况下需要财务或老板处理
- 哪些字段是可选的高级设置

## 6. 详细业务操作说明

### 6.1 企业负责人：首次建立供应商合作

1. 在报价项目库直接维护标准成本价。
2. 进入“供应商协作”新增供应商。
3. 填写供应商名称、联系人、电话和默认账期。
4. 选择主类型，例如“材料供应商”或“劳务班组”。
5. 在供应商下关联品牌，如马可波罗、东鹏。
6. 不需要为每个报价项目逐项建立采购价。
7. 采购时按报价项目品牌匹配供应商。

### 6.2 材料员：项目采购下单

1. 打开“供应商协作 → 项目采购”。
2. 选择待采购材料计划。
3. 查看项目、供应商、数量和要求到场日期。
4. 选择供应商。
5. 系统自动带出当前采购价。
6. 如果本次实际价格不同，修改本次执行价。
7. 选择“直送工地”或“入仓库”，默认直送工地。
8. 确认预计到场日期。
9. 提交采购单。
10. 将采购单摘要复制或转发给供应商。

### 6.3 项目经理：现场到货确认

1. 打开“供应商协作 → 待到货”。
2. 选择采购单。
3. 填写实际到场数量。
4. 选择到货结果：正常、少发、破损、错发、色差。
5. 上传现场照片。
6. 填写异常说明。
7. 提交到货。
8. 系统自动更新材料计划和采购单状态。
9. 如果是直送工地，系统不新增仓库库存。
10. 系统自动生成供应商应付。

### 6.4 财务：月结对账和付款

1. 打开“供应商协作 → 供应商往来”。
2. 选择供应商。
3. 查看本月采购、到货、应付和已付款。
4. 与供应商账单核对。
5. 核对无误后确认应付。
6. 登记付款。
7. 一笔付款可以冲抵该供应商多张应付单。
8. 差异项填写备注，不覆盖原始到货和应付记录。

### 6.5 企业负责人：处理价格变化

1. 打开供应商或报价项目。
2. 查看当前采购价和价格历史。
3. 录入新采购价。
4. 系统显示受影响项目和报价。
5. 对已签约项目，评估毛利变化。
6. 对未签约报价，更新报价成本参考。
7. 对已下单采购，保留原订单执行价。

## 7. 必做与禁止事项

### 必做

- 项目采购必须能追溯到材料计划和报价来源。
- 直送工地和入库必须明确区分。
- 到货必须支持部分到货和异常记录。
- 到货后必须能形成实际成本和应付。
- 成本可见性必须由服务端控制。
- 所有创建、审批、到货和付款写操作必须可追溯。

### 禁止

- 禁止把仓库库存作为所有采购的必经环节。
- 禁止让用户为了下单先维护完整仓库、批次和税率。
- 禁止直接覆盖原始采购价、到货数量和应付金额。
- 禁止让材料员通过前端猜测采购执行价。
- 禁止把项目成本或毛利暴露给无权限角色。
- 禁止在前端重试时生成重复采购单或重复应付。

## 8. 验收标准

### 业务闭环

- [ ] 从材料计划可以创建采购单。
- [ ] 采购单可以默认直送工地。
- [ ] 采购单可以选择入仓库。
- [ ] 支持部分到货。
- [ ] 到货后自动更新采购单和材料计划。
- [ ] 直送不生成库存。
- [ ] 入库生成库存。
- [ ] 到货后自动生成应付。
- [ ] 应付按供应商账期计算到期日。
- [ ] 付款支持冲抵多张应付。

### 权限

- [ ] BOSS、店长、材料员和财务可以维护报价项目标准成本。
- [ ] 设计师、业务员和项目经理看不到标准成本。
- [ ] 材料员看不到项目利润和其他供应商历史报价。
- [ ] 材料员是否可看采购执行价由权限配置决定。
- [ ] 跨企业供应商和采购单不可访问。

### 操作体验

- [ ] 首次下单不需要填写有效期、税率和批次。
- [ ] 项目采购在 3 分钟内可以完成。
- [ ] 现场到货在 1 分钟内可以完成。
- [ ] 财务可以按供应商查看未付余额。
- [ ] 每个页面都有下一步业务提示。

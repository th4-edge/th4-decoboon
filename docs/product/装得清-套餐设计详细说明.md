# 装得清套餐设计详细说明

> 适用对象：企业负责人、店长、设计师、财务和实施人员  
> 核心定位：帮助企业把常用整装方案沉淀成可复用套餐，并稳定生成客户报价  
> 当前载体：App「我的 -> 套餐模板」  
> 关联设计：`docs/design/03-套餐报价域设计说明.md`、`docs/design/12-报价体系重构总设计.md`

## 1. 一句话理解套餐

套餐不是客户最终报价，而是企业预先配置好的一套“标准报价模板”。

```text
套餐模板
→ 选择客户和房屋
→ 输入实际计价面积
→ 系统按面积、牌价和折扣折算
→ 形成报价草稿
→ 设计师处理扣减、升级、替换和增项
→ 提交客户确认
→ 接受后进入合同和项目
```

企业负责人需要重点理解：

- 套餐模板负责“企业经营标准”，可以长期复用。
- 客户报价负责“本次客户事实”，生成后必须保存快照。
- 后续修改套餐模板，不能回写已经生成的客户报价。
- 套餐报价和设计方案报价可以共用报价内核，但当前是两个入口。

## 2. 为什么需要套餐

中小装企经常遇到以下问题：

1. 每个设计师都用自己的 Excel 报价，项目和材料口径不一致。
2. 同一套餐不同客户报出的价格逻辑不同，老板无法复核。
3. 新设计师不会组价，签单依赖个别老员工。
4. 套餐名称相同，但施工、主材、品牌和数量范围不明确。
5. 客户改材料、减项目或升级品牌后，报价历史无法追溯。

套餐要解决的不是“简单写一个总价”，而是把以下经营规则固定下来：

- 套餐按多大标准面积设计。
- 标准面积对应多少牌价。
- 默认折扣是多少。
- 套餐包含哪些分区和项目。
- 每个项目的数量换算系数是多少。
- 哪些项目允许扣减。
- 项目成本如何计算。
- 客户改项目时如何形成报价差异。

## 3. 套餐与相关对象的区别

| 对象 | 企业版理解 | 是否属于客户事实 | 是否允许修改 |
| --- | --- | --- | --- |
| 报价项目库 `CatalogItem` | 企业能卖什么、标准销售价和成本价 | 否 | 企业持续维护 |
| 套餐模板 `PackageTemplate` | 企业预设的一套标准整装方案 | 否 | 负责人可维护 |
| 套餐分区 `PackageSection` | 套餐里的空间或业务分组 | 否 | 负责人可维护 |
| 套餐项目行 `PackageLine` | 某套餐在某分区里包含的标准项目 | 否 | 负责人可维护 |
| 客户报价 `Quote` | 某客户、某房屋本次报价 | 是 | Draft 可调整，提交后锁定 |
| 报价行 `QuoteLine` | 本次报价的项目、数量、金额和成本快照 | 是 | 仅 Draft 可调整 |

关键词：

- **模板**：企业标准，可复用。
- **报价**：客户事实，必须留痕。
- **快照**：报价生成时冻结的数量、价格和成本。

## 4. 套餐和设计方案是什么关系

当前有两类报价路线：

### 4.1 套餐报价

```text
客户 + 房屋 + 套餐模板 + 实际计价面积
→ 套餐报价草稿
```

特点：

- 不一定要求先完成设计方案。
- 按套餐标准内容生成基础报价。
- 适合套餐标准化程度较高的装企。
- 当前套餐项目行不会自动映射到设计方案的客厅、主卧、厨房等区域。

### 4.2 设计方案报价

```text
设计方案区域 + 设计分项
→ 设计报价草稿
```

特点：

- 必须从 `Ready/Presented/Selected` 的完成方案生成。
- 项目直接来自设计方案的施工、材料、软装、定制、电器等分项。
- 客户报价可以按区域查看。

### 4.3 混合报价

设计师可在设计方案的“确认报价”页选择套餐，形成：

```text
套餐基础 + 套餐调整 + 自定义增项
→ 一份统一报价
```

系统会以套餐为基础行，自动匹配设计方案的区域和分项，形成 `PackageOnly / DesignOnly / QuantityChanged / Upgrade / Replace` 等差异。设计师确认、忽略或调整全部差异后，才能提交客户。

## 5. 企业负责人配置前先定六件事

### 5.1 先定套餐标准面积

标准面积是套餐牌价的基准面积。

例如：

```text
标准面积 = 100㎡
套餐牌价 = 158,000 元
```

这表示企业配置的是一套“100㎡标准套餐”。客户房屋 118㎡时，系统按 1.18 倍折算。

### 5.2 先定套餐牌价

`套餐牌价`必须理解为折前价。

不是：

```text
套餐牌价 = 已经打完折的成交价
```

而是：

```text
套餐牌价 × 面积比例 × 折扣 = 折后套餐金额
```

如果企业习惯直接报“成交一口价”，应先换算成折前牌价再录入，否则会重复折扣。

### 5.3 先定默认折扣

默认折扣是企业标准报价折扣。

示例：

- `100`：不打折。
- `95`：按 95% 报价。
- `90`：按九折报价。

生成客户报价时可以调整本次折扣，但套餐模板中的默认折扣仍用于快速报价。

### 5.4 先定套餐分区

推荐按企业实际讲解习惯设置，例如：

- 全屋基础。
- 客厅餐厅。
- 厨房。
- 卫生间。
- 卧室。
- 主材区。
- 软装电器。

当前套餐分区是套餐自己的分组，不等同于设计方案的 Space。

### 5.5 先定包含项目和数量系数

每个套餐项目行来自报价项目库。

需要明确：

- 选择什么报价项目。
- 数量换算系数是多少。
- 使用哪种计价方式。
- 默认是否包含。
- 是否允许客户扣减。
- 升级、替换、差价如何解释。

### 5.6 先定成本口径

套餐标准成本来自报价项目库中的成本单价。

```text
套餐标准成本
= Σ（报价项目成本单价 × 数量换算系数）
```

成本不完整的项目不应被当作零成本使用，否则会形成虚假毛利。

## 6. 套餐核心字段说明

### 6.1 套餐模板 PackageTemplate

| 字段 | 业务含义 | 建议 |
| --- | --- | --- |
| 套餐名称 | 对外识别名称 | 如“品质整装 100㎡套餐” |
| 标准面积 | 套餐牌价对应的基准面积 | 必须大于 0 |
| 套餐牌价 | 标准面积对应的折前价格 | 不含本次客户折扣 |
| 默认折扣 | 套餐默认报价折扣 | 1 表示不打折 |
| 标准成本 | 所有套餐项目行成本合计 | 系统自动计算 |
| 套餐分区 | 套餐项目分组 | 建议 3–8 个，不宜过细 |
| 套餐项目行 | 实际包含内容 | 来自报价项目库 |
| 套餐说明 | 适用范围、排除项和口径说明 | 建议写清楚 |

### 6.2 套餐分区 PackageSection

| 字段 | 含义 |
| --- | --- |
| 分区名称 | 如厨房、卫生间、主材区 |
| 空间类型 | 可选，用于标记分区适用的空间类型 |
| 可删减数 | 套餐内允许扣减的控制参考 |
| 优先级 | 控制展示顺序 |

### 6.3 套餐项目行 PackageLine

| 字段 | 含义 | 业务要求 |
| --- | --- | --- |
| 所属套餐 | 该行属于哪个套餐模板 | 必填 |
| 所属分区 | 该行在套餐中的分组 | 必填 |
| 报价项目 | 从报价项目库选择的销售项目 | 必填且必须有效 |
| 项目名称 | 默认继承报价项目名称 | 可调整展示名 |
| 品牌/规格/单位 | 套餐内标准配置 | 应与企业销售口径一致 |
| 数量系数 | 标准套餐下的基准数量 | 必须大于 0 |
| 计价方式 | 材料+人工、仅材料、仅人工、固定总价 | 默认继承报价项目 |
| 默认包含 | 生成套餐报价时是否默认包含 | 一般设为是 |
| 允许扣减 | 客户可减少该项目时是否允许扣减 | 高风险项目谨慎开放 |
| 规则说明 | 升级、替换、差价解释 | 用于设计师和客户沟通 |

### 6.4 套餐差价项 PackageTemplateItem / PackageRule

这两个对象用于更细的套餐差价和规则扩展，例如：

- 某空间标准升级差价。
- 某项目品牌替换差价。
- 超出标准配置后的加价标准。

当前模型已具备基础能力，但完整自动化规则匹配仍在后续阶段。现阶段应把规则写清楚，并在报价 Draft 中由设计师选择实际替换项目。

## 7. 两个真实企业场景

### 场景一：标准整装套餐快速报价

企业背景：

- 10–30 人装企。
- 常用“品质整装套餐”面向 100㎡左右新房。
- 设计师希望 10 分钟内形成首版报价。

操作：

1. 套餐名称为“品质整装 100㎡套餐”。
2. 标准面积填写 100㎡。
3. 套餐牌价填写企业折前报价。
4. 默认折扣填写 90%。
5. 建立“全屋基础、厨房、卫生间、主材、软装电器”分区。
6. 从报价项目库选择施工、主材、定制和电器项目。
7. 设置数量系数。
8. 保存套餐并检查标准成本。
9. 给 118㎡房屋报价，系统自动按 1.18 倍折算。
10. 生成 Draft 后处理客户不需要的项目和升级项目。
11. 提交客户确认。

### 场景二：套餐基础上做扣减、升级和增项

客户情况：

- 选择基础套餐。
- 不需要其中一个基础材料项目。
- 将普通瓷砖升级为品牌瓷砖。
- 增加中央空调。

操作：

1. 生成套餐报价 Draft。
2. 选择“扣减”处理不需要的基础项目。
3. 选择“升级”或“替换”，选择品牌瓷砖并填写数量。
4. 系统扣减原基础项目金额，再追加新项目金额，差额进入报价。
5. 选择“增项”，追加中央空调。
6. 系统重新计算小计、折扣、税金、金额和成本。
7. 客户确认后提交，报价进入锁定快照。

## 8. 企业负责人 App 配置步骤

入口：

```text
App -> 我的 -> 套餐模板
```

### 第一步：新建套餐

填写：

- 套餐名称。
- 标准面积。
- 套餐牌价。
- 默认折扣。

点击“创建套餐”。

### 第二步：建立套餐分区

点击“新增分区”，输入：

- 全屋基础。
- 厨房。
- 卫生间。
- 主材区。
- 软装电器。

分区不应照搬完整 ERP 结构，应优先按客户讲解顺序组织。

### 第三步：从报价项目库添加项目行

选择：

- 套餐分区。
- 项目类型：施工、主材、定制、软装、电器、综合。
- 具体报价项目。
- 数量系数。
- 计价方式。
- 是否默认包含。
- 是否允许扣减。
- 升级/替换/差价规则说明。

系统显示本行标准成本。

### 第四步：检查套餐标准成本

页面底部显示：

```text
套餐标准成本 = Σ项目成本
```

企业负责人应重点检查：

- 是否有遗漏项目。
- 是否有成本为零或明显异常的项目。
- 数量系数是否符合标准面积。
- 品牌和规格是否与销售承诺一致。

### 第五步：保存并形成模板快照

保存后，该套餐可以作为后续客户报价的来源。

之后修改套餐模板：

- 影响未来新报价。
- 不影响已经生成的客户报价。

## 9. 套餐金额和成本计算

### 9.1 面积比例

```text
面积比例 = 实际计价面积 ÷ 套餐标准面积
```

### 9.2 套餐牌价金额

```text
套餐折前金额 = 套餐牌价 × 面积比例
```

### 9.3 折后金额与税金

```text
折后金额 = 套餐折前金额 × 折扣
税金 = 折后金额 × 税率
报价合计 = 折后金额 + 税金
```

当前系统默认税率为 5%，最终以企业实际税务口径为准。

### 9.4 套餐成本

```text
套餐标准成本 = Σ（项目成本单价 × 数量系数）
客户报价成本 = 套餐标准成本 × 面积比例
```

### 9.5 套餐项目行数量

```text
客户报价行数量 = 数量系数 × 面积比例
```

### 9.6 项目行金额分摊

当套餐采用整体牌价报价时，系统按项目成本占比分摊套餐金额。

企业负责人不需要手工计算分摊金额，但应理解：

- 套餐总价来自企业录入的牌价、面积和折扣。
- 项目行金额是总价在项目之间的解释。
- 项目成本用于分析利润，不作为客户报价的直接售价。

## 10. 如何应用套餐生成客户报价

### 10.1 从报价列表生成套餐报价

入口：

```text
App -> 方案报价 -> 新建报价 -> 套餐报价
```

必须选择：

- 客户。
- 客户房屋。
- 套餐模板。
- 实际计价面积。
- 本次折扣。

多房屋客户必须明确选择本次报价的房屋，不能依赖默认房屋静默绑定。

### 10.2 生成结果是 Draft

套餐不会直接生成合同，也不会直接生成项目。

```text
套餐模板 -> 客户报价 Draft -> 调整 -> 提交客户
```

### 10.3 提交前的调整

套餐报价 Draft 支持：

| 动作 | 业务含义 | 金额影响 |
| --- | --- | --- |
| 扣减 | 客户不需要原套餐项目 | 减少原项目金额 |
| 升级 | 将标准项目升级为更高配置 | 扣原项目、加新项目，形成净差价 |
| 替换 | 将原项目替换为其他项目 | 扣原项目、加新项目，形成净差价 |
| 增项 | 增加原套餐之外的项目 | 追加新项目金额 |

每次调整后，系统重新计算：

- 折前小计。
- 折扣。
- 税金。
- 报价合计。
- 报价成本。

### 10.4 提交后不可修改

提交客户后，报价进入快照状态。

- 不能继续调整报价行。
- 客户接受后进入合同。
- 客户驳回后原报价保持只读。
- 需要改价时，基于原报价生成新的 Draft 版本。

## 11. 报价状态与版本

### 11.1 状态机

```text
Draft
  -> Submitted
      -> Accepted
          -> Converted
      -> Rejected
```

### 11.2 版本规则

- 套餐报价版本按“同一客户 + 同一套餐模板”递增。
- 自定义设计报价版本按同一设计方案递增。
- 版本号用于区分历史报价，不允许覆盖旧版本。

### 11.3 驳回后的处理

驳回不是删除。

```text
原报价 Rejected
→ 保留历史
→ 基于原报价生成新 Draft
→ 调整设计或套餐项目
→ 重新提交
```

这保证客户看到的每一版报价都可以追溯。

## 12. 权限和数据范围

### 企业负责人 BOSS

- 创建套餐模板。
- 修改套餐基本信息。
- 维护套餐分区和项目行。
- 查看标准成本。
- 使用套餐报价。

### 店长、团队负责人、设计师

- 可以查看和使用当前企业套餐。
- 可以基于套餐生成客户报价 Draft。
- 可以执行套餐扣减、升级、替换和增项。
- 不能直接修改企业套餐模板，除非另行授权。

### 财务

- 可查看报价和成本相关数据。
- 不应通过报价页面修改套餐模板。

### 数据范围

- 套餐模板归属企业。
- 套餐报价必须绑定当前企业可见的客户和房屋。
- 前端传入企业、负责人和归属不能直接作为最终事实。

## 13. 企业套餐设计建议

### 13.1 套餐不要做得过多

建议首版控制在 3–5 套：

- 基础整装。
- 品质整装。
- 高配整装。
- 局部空间套餐。
- 特殊客群套餐。

套餐过多会导致：

- 设计师不知道该选哪套。
- 维护成本增加。
- 报价口径容易分叉。

### 13.2 分区按客户理解组织

客户更容易理解：

```text
全屋基础
厨房
卫生间
主材
软装电器
```

而不是：

```text
施工分类
材料分类
工艺分类
综合费用
其他杂项
```

### 13.3 扣减项要谨慎开放

不建议把所有项目都设为“允许扣减”。

建议：

- 可量化、可替代的项目允许扣减。
- 影响整体质量或施工闭环的项目不允许直接扣减。
- 高风险项目必须走说明或审批。

### 13.4 套餐名称要说清楚适用范围

推荐：

```text
品质整装 100㎡套餐
现代简约基础包
旧房全改 90㎡套餐
```

不推荐：

```text
豪华套餐
高端套餐
全包套餐
```

后者无法说明面积、配置和范围。

## 14. 常见错误

| 错误做法 | 后果 | 正确做法 |
| --- | --- | --- |
| 把成交一口价填成套餐牌价 | 重复折扣 | 先换算折前牌价 |
| 套餐不标标准面积 | 无法按客户面积折算 | 必须填写标准面积 |
| 项目数量系数随意填写 | 报价结构和成本失真 | 根据企业标准面积校准 |
| 所有项目都允许扣减 | 报价失去底线 | 只开放可量化项目 |
| 套餐修改后期待历史报价变化 | 破坏快照 | 新报价使用新模板，历史不变 |
| 一个客户多套房不选房屋 | 报价绑定错误 | 必须明确选择房屋 |
| 提交后直接改报价行 | 客户确认事实被覆盖 | 驳回后生成新版本 |
| 套餐没有说明排除项 | 客户理解偏差 | 写明不含内容和边界 |

## 15. 套餐报价示例

套餐配置：

```text
套餐名称：品质整装 100㎡套餐
标准面积：100㎡
套餐牌价：158,000 元
默认折扣：90%
标准成本：105,000 元
```

客户房屋：

```text
实际计价面积：118㎡
本次折扣：90%
```

计算：

```text
面积比例 = 118 ÷ 100 = 1.18

套餐折前金额 = 158,000 × 1.18 = 186,440 元
折后金额 = 186,440 × 90% = 167,796 元
税金 = 167,796 × 5% = 8,389.80 元
报价合计 = 176,185.80 元

客户报价成本 = 105,000 × 1.18 = 123,900 元
参考毛利 = 167,796 - 123,900 = 43,896 元
```

注意：

- 参考毛利是否含税，应以企业财务口径为准。
- 税金只是系统默认计算，具体税率和开票口径以企业为准。
- 如果客户扣减或升级项目，最终金额会以 Draft 调整后的结果为准。

## 16. 套餐验收清单

企业负责人配置完成后，应至少检查：

- [ ] 套餐名称、标准面积、牌价、折扣均正确。
- [ ] 套餐至少有一个分区。
- [ ] 套餐项目行来自有效报价项目库。
- [ ] 项目数量系数符合标准面积。
- [ ] 包含和不允许扣减项设置正确。
- [ ] 标准成本没有明显异常。
- [ ] 使用单套房屋客户生成套餐报价成功。
- [ ] 使用多套房屋客户时必须明确选择房屋。
- [ ] 套餐报价生成后状态为 Draft。
- [ ] 扣减、升级、替换和增项后金额重新计算。
- [ ] 提交客户后报价行不可调整。
- [ ] 客户驳回后可以生成新版本。
- [ ] 修改套餐模板后历史报价不变。

## 17. 当前实现边界

当前已具备：

- 套餐模板基本信息。
- 套餐分区。
- 套餐项目行。
- 报价项目库选择。
- 数量系数。
- 计价方式。
- 默认包含和允许扣减。
- 套餐标准成本预览。
- 套餐报价 Draft。
- 扣减、升级、替换和增项。
- 套餐报价版本。
- 驳回报价新版本重报。

当前已具备：

- 设计方案同时关联 `Design` 和 `PackageTemplate` 生成 `Hybrid` 报价。
- 套餐行与设计分项按报价项目、空间类型、分类和名称匹配。
- `QuoteLine` 保存差异类型、确认状态、`designItem` 和 `packageLine` 来源。
- 待确认差异未处理完时禁止提交客户。
- 报价头记录 `costComplete`；成本缺失或全部为 0 时显示“成本未完整”。

当前仍有限制：

- 套餐和设计方案区域尚未自动映射。
- 套餐项目行目前按企业模板组织，不会自动识别“主卧、次卧、厨房”等设计布局。
- 升级和替换当前使用“扣原基础项目 + 加新项目”的净差价模型。
- 品牌、规格之间的自动差价公式匹配尚未完全配置化。
- 自动匹配无法确认时会保留为待确认差异，仍需设计师人工判断。
- 套餐模板的停用、归档和更细的版本管理还需继续补充。

## 18. 负责人快速操作卡

```text
1. 我的 -> 套餐模板 -> 新建套餐
2. 填名称、标准面积、牌价、默认折扣
3. 新增套餐分区
4. 从报价项目库添加项目行
5. 设置数量系数、计价方式、包含、可扣减
6. 填写升级/替换/差价规则说明
7. 检查标准成本
8. 保存套餐
9. 方案报价 -> 新建报价 -> 套餐报价
10. 选择客户、房屋、套餐、计价面积和折扣
11. 生成 Draft
12. 调整扣减、升级、替换和增项
13. 提交客户确认
14. 客户接受后进入合同
15. 客户驳回后基于原报价新建版本
```

## 19. 常见问题

### 套餐模板修改后，旧报价会变吗？

不会。旧报价保存的是生成时的快照。

### 一个客户可以生成多份套餐报价吗？

可以，但在最终成交前只能有一份有效确认报价。客户接受某一份后，同房屋的其他草稿、已提交或已接受报价会被标记为已被替代。

### 套餐报价是否可以没有设计方案？

可以。套餐报价可以只绑定客户、房屋、套餐模板和计价面积。

### 套餐报价是否按设计区域展示？

套餐项目行当前按套餐分区展示。套餐分区不是设计方案的房间区域。

### 客户驳回后可以直接修改原报价吗？

不可以。原报价保持只读历史，应生成新的 Draft 版本。

### 套餐成本为什么和材料采购成本不完全一样？

套餐标准成本来自报价项目库成本单价和数量系数，用于报价参考。采购到货成本是项目实际发生成本，两者属于不同口径。

### 能不能只填套餐总价，不配置项目？

不建议。只有总价会导致客户无法理解钱花在哪里，也无法计算成本、调整项目和追溯历史。

# TP-20261101-V0.1 签约后工地不乱 · 核心全链路测试计划

## 1. 目标

验证一个真实签约项目从合同生效、项目接住、施工推进、材料到场、阶段验收，到收款与成本回读，在员工角色、App、Web、业主端和后端之间保持同一业务事实。

## 2. 范围

### 覆盖

- 客户与房屋；
- 量房、设计、报价；
- 合同签约、生效、项目立项；
- 合同变更；
- 项目阶段、任务、现场留证；
- 材料选材、作业单、采购、到场；
- 阶段验收、驳回、整改、复验；
- 应收、收款、应付、付款、成本完整性、结算草稿；
- 角色权限、跨租户、工作台正确引导、内部编号隐藏。

### 非范围

- 薪酬、工资单与提成完整闭环；
- 企业治理、订阅、平台运营；
- 品牌资产、内容获客和营销发布；
- 真实微信支付、电子签、短信、真实业主确认、正式小程序发布。

## 3. 环境与角色

使用 `local-fixture` 当前昭青科技数据集。角色至少包括 Boss、StoreManager、Marketer、Designer、Pm、Finance、Owner。Owner 的高风险确认使用受控人工或匹配身份，不由员工代填。

## 4. 进入条件

1. 后端、Web、小程序构建可用；
2. 测试企业、账号、阶段和财务夹具可用；
3. 用例库通过 `test_assets.py validate`；
4. oracle lock 与当前业务知识库版本一致；
5. 清库/写操作有备份或回滚路径；
6. 本次运行的代码提交和制品版本已记录。

## 5. 退出条件

- P0 用例全部通过；
- P1 无未接受阻断；
- 核心主链在 Web 与 App/业主端完成声明范围验证；
- 权限、金额、成本、状态和跨端对账均有证据；
- 未覆盖项和残余风险明确；
- 结论只能是 `PASS/CONDITIONAL_PASS/FAIL/BLOCKED`。

## 6. 执行批次

| 批次 | 内容 | 产出 |
| --- | --- | --- |
| `B0` | 环境、账号、数据、oracle lock 预检 | preflight |
| `B1` | 客户、量房、设计、报价、合同 | run evidence |
| `B2` | 项目、材料、验收 | run evidence |
| `B3` | 财务、权限、跨端对账 | run evidence |
| `B4` | 工作台、恢复、异常和回归 | run evidence + final report |

## 7. 风险

- 业主身份不可用会使业主确认用例 `BLOCKED`，不得由员工替代；
- 成本不完整时利润必须为空，结算确认必须被阻断；
- 跨端只验证一端时只能标 `PARTIAL`；
- 当前工作树包含大量既有未提交变更，执行报告必须记录实际提交和制品哈希。

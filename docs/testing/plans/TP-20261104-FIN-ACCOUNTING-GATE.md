# TP-20261104-FIN-ACCOUNTING-GATE · 财务账务专项测试计划

## 1. 目标

以工资单/考勤锁定缺陷为种子，验证财务账务域在真实角色、多状态、多端、并发和失败恢复下，不产生越权、重复账、金额错误、伪成本利润或不可恢复状态。

## 2. 范围

### 覆盖

- 月度考勤与工资单状态机；
- 工资单、工资项、员工工资应付、发放、工资条；
- 应收、收款、退款、收款冲正；
- 应付、付款、费用；
- 材料到应付和成本；
- 项目成本、利润与结算；
- 资金台账、凭证、财务汇总；
- Web/App/API/DB 同源；
- 权限、门店范围、租户范围；
- 幂等、并发、失败恢复、审计和历史调整。

### 非范围

- 法定税务申报、完整会计总账、银行真实代发；
- 未冻结的业务规则；
- 生产真实客户资金；
- 用员工账号代替业主或人工验收；
- 把修复前证据当作修复后通过证据。

## 3. 环境

| 跑道 | 用途 | 写入 |
| --- | --- | --- |
| `local-fixture` | 状态组合、破坏性、并发、金额边界 | 允许，可重置 |
| `prod-twin` | 受控测试企业完整闭环 | 当次授权 |
| `prod-readonly` | 麦鸿真实形态、入口、权限和页面参照 | 禁止 |
| `prod-controlled-write` | 白名单测试租户最终验证 | 单独审批 |

## 4. 角色

- BOSS；
- 总部财务；
- 门店财务；
- 店长；
- 员工本人；
- 项目经理/设计师作为上游事实提供者；
- 跨企业/跨门店负向账号。

## 5. 执行阶段

| 阶段 | 内容 | 通过条件 |
| --- | --- | --- |
| FG0 | 业务规则、提交、制品、账号、夹具、备份 | oracle 和制品一致 |
| FG1 | 状态机、权限、金额、幂等、审计不变量 | P0 全部通过 |
| FG2 | Web/App 真实页面旅程 | 页面、API、DB 回读一致 |
| FG3 | 跨角色、跨门店、跨端 | 同事实同状态同动作 |
| FG4 | 应付/付款/成本/台账/凭证/报表对账 | 金额和计数守恒 |
| FG5 | 历史数据和恢复 | 差异清零或有批准调整方案 |

## 6. 执行批次

### B1 工资单与考勤

- 未确认考勤阻断生成；
- 生成后 InPayroll；
- Pending 防重建；
- Draft 删除恢复；
- 直接状态绕过；
- 确认后修改；
- 跨店范围；
- 切月/切员工表单；
- Web/App 枚举；
- 重算清理旧工资项。

### B2 工资财务结果

- 工资单确认只生成一次应付；
- 应付金额等于工资项汇总；
- 付款幂等；
- 台账和工资条；
- 已发历史不得反改；
- 下期负向调整。

### B3 通用收付与往来

- 应收、收款、退款、冲正；
- 应付、付款、费用；
- 重复付款；
- 资金台账；
- 凭证可用性和审计。

### B4 材料、成本和结算

- 下单、到场、应付、付款；
- 退货、换货、部分到场；
- 成本不完整；
- 利润为空；
- 结算阻断或通过。

### B5 跨端和真实角色

- BOSS、总部财务、门店财务、店长、员工；
- App/Web/API 同源；
- 页面动作和依赖 Provider 同权；
- 失败、弱网、重复点击、旧页面。

## 7. 用例库

机器可读用例：`docs/testing/cases/finance-accounting-gate-v0.1.json`。

用例必须满足：

- 有业务规则 ID；
- 有对象、夹具、前置状态和明确禁止结果；
- 页面用例有页面目标；
- 有 Provider 路由；
- 有页面/API/DB/账务证据要求；
- P0 不允许 `BLOCKED` 后进入发布。

## 8. 进入条件

1. 业务知识库 oracle 已冻结；
2. 后端、Web、App 提交和制品已记录；
3. 测试企业、角色和数据夹具可用；
4. `python3 docs/testing/scripts/finance_gate.py validate` 通过；
5. 写操作有备份/恢复路径；
6. 生产只读或受控写入边界已确认。

## 9. 退出条件

- P0 100% 通过；
- P1 无未接受阻断；
- FG4 账务对账无不平项；
- Web/App/Provider/DB 同源；
- 并发和失败恢复有证据；
- 未覆盖项、GAP、残余风险明确；
- 独立验收结论由非修复者给出。

## 10. 停止条件

- 任一 P0 失败；
- 发现新的越权或重复账；
- 账务金额不守恒；
- 需要用生产真实资金或已发放历史做实验；
- 业务规则冲突未裁决；
- 执行环境、账号或回滚能力不可用。

# src/test — 后端测试规范

> 根目录 `AGENTS.md` 同时生效。测试必须验证业务规则和技术契约，不得从当前实现反推正确业务事实。

## 1. 测什么

- 业务条件矩阵：正向、反向、越权、重复、边界、历史快照和失败恢复。
- 权限：企业、门店、团队、本人范围；跨租户、越权 ID、缺失登录态。
- 金额/成本/利润：缺失成本时 `costComplete=false`，利润和毛利率为 `null`，禁止用 0 伪装事实。
- 接口：真实 JSON 字段、状态、责任人、派生字段和同源口径。
- 查询：分页上限、同筛选列表与报表计数一致、10× 数据量、响应行数和 P95。
- 写操作：幂等、并发锁边界、一次批量加载/校验/写入和副作用隔离。

## 2. 必守边界

- 涉及 LAZY 关联的测试显式设置 `spring.jpa.open-in-view=false`，测试方法不加 `@Transactional`。
- 禁止用临时 `EAGER`、`@JsonIgnore` 或只跑 dev 配置让测试变绿。
- 只读事务及其间接调用链不得调用悲观锁仓储；并发写使用 `RedissonLock`，测试不得引入数据库业务锁替代。
- 报表不能只断言 Service 返回值；必须验证聚合 SQL、行数上限和同筛选对账。
- 页面、Provider、日志只能用于核验业务事实；独立验收预期必须来自冻结用例和业务事实源。

## 3. 执行纪律

- L0/L1 先跑最相关测试类和编译；只有 L2/L3、批量发布或用户明确要求才跑全量。
- 编译日志默认只看 `tail -50`；失败时保留首个根因、失败断言和复现命令。
- Provider 响应改动运行 `python3 scripts/audit-provider-response-contract.py --check`；规则自测使用 `--self-test`。
- 路由、权限或安全注册改动补 `ProviderSecurityAcceptanceTest` 或对应专项安全测试。
- 测试结果写清命令、用例数、失败数和未执行原因；不得把“开发自测通过”写成“独立验收通过”。

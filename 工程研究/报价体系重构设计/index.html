01 重构背景与问题定义

当前 decoboon 工程中，材料、施工主数据、设计方案与报价业务存在成体系的重叠（6 组重复），且新增的 dr.design 报价体系与旧体系并行，工程结构已影响后续开发。

重叠点重复双方后果
R1 枚举双轨CatalogType(bim) ↔ QuoteItemType(trade)，枚举值 1:1 重复，需双向 mapping 桥接改一个忘一个，桥接代码膨胀
R2 计价双轨Price/PriceType/PriceContext ↔ PricingMode/QuoteCalcContext，两套计价引擎计价口径分叉风险
R3 明细同构DesignItem ↔ QuoteItem，近 30 字段逐字段复制，已出现字段漂移（costPrice）每加字段同步两处
R4 主数据双轨Construction/Material(旧) ↔ CatalogItem(新统一库)迁移桥接 fromXxx 持续维护
R5 分类四套Modular / Category / GiftGroup / 字符串分类分类语义各说各话
R6 报价双入口QuoteContext.create(Design) ↔ create(GiftPack)，QuoteItem 挂 5 路来源前端需判断分项来源，展现歧义
重构目标：保留「套餐报价」与「自定义报价」两条业务路线（这是家装行业的真实业务需求），但让两条路线都建立在同一份企业主数据基石之上；报价单采用装修行业真实结构（套餐 + 主材 + 施工 − 扣减 + 其他 + 设计费 + 管理费 + 税金），输出统一、无歧义。

02 目标架构：单基石 · 双路线 · 单快照

三层架构：基石层唯一可信源；组合层承载两条报价路线；快照层输出统一报价单。任何报价明细的价格、名称、数量均从基石复制为不可变快照。

③ 快照层 · 报价单（不可变，输出统一结构）
Quotation 报价单（8 类金额分列） PackQuote 套餐报价 PackItemDeductQuote 扣减 ConstructionQuote 施工报价 MaterialQuote 主材报价 UpgradeQuote 增值报价
▲ 生成快照 ▲
② 组合层 · 两条报价路线（引用基石分项 + 数量）
路线 B · 套餐报价
GiftPack 套餐模板 = GiftGroup 分组 + GiftItem 分项（引用基石 + 标准量 + 差项公式），企业一次维护
路线 A · 自定义报价
Scheme 方案 = Building + spaces，设计分项 = 基石引用 + 空间 + 数量，设计师按需组合
▲ 引用 ▲
① 基石层 · 企业主数据（唯一可信源）
CatalogItem 统一主数据 六类：施工 / 主材 / 软装 / 电器 / 综合 / 全屋定制 价格模型 materialPrice / manualPrice / costPrice + PricingMode 分类：字符串 + CatalogTree Unit / SpaceType 公共枚举
消除歧义的关键：所有组合（设计分项、套餐分项）只引用 CatalogItem 一个来源；所有报价明细只保存复制下来的快照字段；前端展示无需再判断「分项从哪来、价格信谁」。

03 实体模型设计（四层）

以 dr.design 报价模型为蓝图、CatalogItem 统一库为基石，合并两套体系后的目标实体模型。

① 基石层（bim 域）

实体说明关键字段 / 调整
CatalogItem企业统一主数据，覆盖六类分项type(CatalogType) / category / brand / spec / unit / pricingMode / materialPrice / manualPrice / costPrice / formula / craft；收编旧 construction/material 的 const_id/mat_id 溯源列
Upgrade增值项主数据（套餐/自定义报价的升级加价项）名称 / 计价方式 / 价格（从 dr.account.cost 并入 bim）
CatalogTree分类树视图（非实体）由 category 字符串 + type 聚合生成
下线Construction / Material / Modular / Category / GiftGroup(旧) / Price / PriceType / UpgradeMethod/Mode/Type仅作迁移期读源，新代码不再引用

② 套餐组合层（bim.pack 域重构）

实体说明关键字段 / 调整
GiftPack套餐模板price 定价 / discount 折扣 / 参考面积 / 状态
GiftGroup套餐分组（空间维度展示）name / icon / spaceTypes / priority（从旧分类语义剥离，专用于套餐分组）
GiftItem套餐分项（改引 CatalogItem）引用 CatalogItem + standard 标准量 + unit；删除 Map<Construction, measure> / Map<Material, measure> 双路引用
GiftFormula差项计价公式standard（标准量）/ price（差项单价）/ remark——套餐超出标准部分按此计价

③ 设计组合层（design 域重构）

实体说明关键字段 / 调整
Scheme设计方案（替代旧 Design）building + designer + spaces + cupboard + cads + vr + tips
SchemeItem设计分项（替代旧 DesignItem）引用 CatalogItem + space + quantity；删除 construction/material 直连与 QuoteItemType 依赖，类型统一用 CatalogType
Space方案区域type(SpaceType) / name / length / width / area / perimeter

④ 报价快照层（quotation 域，新 dr.design 蓝图）

实体说明关键字段
Quotation报价单主档building / scheme / giftPack(可空) + 8 类金额分列 + cost + rmb + sign + designer
PackQuote套餐报价快照giftPack + packAmount + measureAmount(差项合价) + deductAmount + amount + measureItems(Map<GiftPackItem, PackMeasureQuote>)
PackMeasureQuote差项计价结果price / standard / calculated / measure / amount / tip
PackItemDeductQuote套餐分项扣减快照giftPack + giftGroup + giftItem + 引用 CatalogItem 明细 + 金额
ConstructionQuote施工报价快照引用 CatalogItem(type=施工) + unit + price 快照 + measure + amount + upgradeQuotes
MaterialQuote主材报价快照同上（type=主材）
QuoteTemplate设计师自定义报价模板常用分项组合（GiftGroup × CatalogItem），快速生成自定义报价
快照原则：报价明细的 name/brand/spec/unit/price 全部在报价生成时从 CatalogItem 复制落库；之后基石改价不追溯既有报价。所有金额字段为 @LogicField，由计算器服务端重算。

04 业务路线 B · 套餐报价（企业预置 → 客户套餐）

企业先维护套餐模板；客户量房后，按方案实际面积对套餐分项计价（差项/扣减/增项），最终输出统一报价单。

1
企业维护套餐模板GiftPack（定价/折扣）+ GiftGroup（分组）+ GiftItem（引用 CatalogItem + 标准量 + 差项公式）——基石分项被套餐引用，价格口径唯一
2
客户量房 → 创建方案 Scheme记录 Building 各空间（类型 + 面积），作为套餐差项计价的依据
3
创建报价单 Quotation选择 building + scheme + giftPack；预置套餐定价，其余金额归零
4
生成套餐报价 PackQuote（自动）packAmount = 套餐定价；遍历差项公式，按 spaceTypes 匹配区域、按 Unit.Area/Count 计算实际量，超出 standard 部分计价；人工可修正差项实际量
5
套餐扣减客户不要某分项 → PackItemDeductQuote：按分项标准量 × 折扣计算扣减金额；可调整单施工/主材项的扣减量（差价更新）
6
套餐外增项添加施工/主材报价（从 CatalogItem 选）→ ConstructionQuote / MaterialQuote：复制主数据价格快照，唯一性校验（同报价单同分组同分项唯一）
7
整单重算（事件驱动）套餐变化 → PackQuoteEvent → QuotationCalculator 整单重算；报价单金额 = 套餐 + 主材 + 施工 − 扣减 + 其他 + 设计费(5%) + 管理费(8%) + 税金
8
输出与签约报价单展示 8 类金额分列 + 大写金额 + 成本；客户确认 → sign 签约 → 转项目

05 业务路线 A · 自定义报价（设计师按需组合）

设计师从企业基石直接组合分项形成方案，方案确认后自动落为报价明细——适合非套餐客户的个性化报价。

1
从基石选分项设计师从 CatalogItem 统一库按类型/分类/品牌筛选，选择施工、主材、软装、电器、综合或全屋定制分项；价格/公式/工艺全部来自基石，不落自定义价
2
组装方案 Scheme分项归属空间（区域）并指定数量 → 设计分项 SchemeItem；可关联图纸、效果图、橱柜面积
3
创建报价单 Quotation选择 building + scheme（不选套餐）
4
分项自动落明细方案分项按 type 自动生成 ConstructionQuote（施工）或 MaterialQuote（主材）等明细，复制基石价格快照
5
补充费用与增项添加其他费用、税金；可随时从基石补加分项
6
整单重算与输出QuotationCalculator 重算：施工/主材明细金额 + 设计费 + 管理费 + 税金 → 统一报价单
7
签约转项目客户确认 → sign → 转项目履约
两条路线关系：自定义报价可先基于 QuoteTemplate（设计师常用分项组合模板）快速生成，再增删调整；套餐报价的「增项」本质就是自定义报价能力，两条路线在同一报价单上可叠加。

06 金额计算规则（统一口径）

全链路唯一计价引擎：明细计算器 + 套餐计算器 + 整单计算器；报价金额永远由服务端计算，前端只读。

明细金额 = measureAmount（按计价方式算工程量） + upgradeAmount（增值项）
measureAmount = calculate(price, pricingMode, measure) —— 材料+人工 / 仅材料 / 仅人工 / 固定总价
套餐差项 = Σ [ (实际量 − standard) × 差项单价 ]，非面积项金额不为负
套餐报价 = 套餐定价 + 差项合价 − 扣减合价
扣减金额 = Σ [ 分项标准量 × 单价 × 折扣 ]（施工 + 主材）
报价总额 = 套餐报价 + 主材报价 + 施工报价 − 扣减 + 其他费用 + 设计费 + 管理费 + 税金
设计费 / 管理费 = (基础合计) × designRate(默认5%) / manageRate(默认8%)（可配置）
成本 = Σ costPrice × 数量（套餐部分 + 明细部分 − 扣减部分）
环节触发方式说明
明细计价quote 保存时从 CatalogItem 复制 price 快照后立即计算 measureAmount
套餐计价PackQuote 保存 / 差项调整packAmount + measureAmount − deductAmount，发 PackQuoteEvent
整单重算ResponseFilter 收口所有返回 Quotation 的 Provider 响应前自动调用 QuotationCalculator
事件联动PackQuoteEvent → 监听套餐变化自动重算整单，金额一致性由服务端保证

07 状态机与权限模型

报价单状态收敛为一条主线；权限沿用 th4 四级数据权限，报价按设计师归属审计。

报价单状态机

拟稿 Draft→ 已提交 Submitted→ 已接受 Accepted（客户同步签约）→ 已转项目 Converted ｜ 驳回 Rejected（可回到拟稿）
  • 拟稿/编辑：设计师本人（auditField = designer）
  • 提交/接受：企业内按角色（BOSS/店长/团队/本人四级）
  • 已接受报价锁定明细，不可再增删分项；已转项目后报价只读

权限设计

对象权限机制
Quotation / Scheme / 各明细实现 Record<Employee>，auditor = designer；查询走 @DataPermission（company/store/team/designer 维度），自定义 Provider 用 DataScopeSpecification，禁止 findById 裸查
CatalogItem / GiftPack企业级主数据：BOSS 可维护，员工只读引用；修改走通用 service/update + @ModelUpdateInject 归属保护
金额字段全部 @LogicField，前端传入被忽略；保存/更新 Provider 只接受数量与费用类输入

08 落地分期计划

按「先立基石、再建双路、后迁存量、终清旧轨」的顺序推进，每期可独立上线。

P0 基建
包结构规范 + 依赖就位
统一包名与目录（消除 dr 目录/包名不一致）；决策主数据域归属；公共枚举（CatalogType/PricingMode/Unit/SpaceType）迁入 bim.configure，删除 QuoteItemType 及双向 mapping 桥接
P1 基石统一
主数据并轨
CatalogItem 为唯一主数据；Construction/Material/Modular/Category 存量幂等迁移（沿用 const_id/mat_id 溯源），旧实体置只读；价格体系统一为 PricingMode + materialPrice/manualPrice/costPrice，废弃 Price/PriceType/PriceContext
P2 套餐重构
套餐模板落基
GiftItem 改引 CatalogItem（删除 Map<Construction/Material, measure>）；GiftGroup 收敛为套餐分组语义；差项公式 GiftFormula 标准化
P3 报价落地
新报价模型上线
Quotation + 四类明细实体 + 计算器/事件/ResponseFilter 收口；新增 dr/design/quotation 系列路由；Scheme/SchemeItem 替代旧 Design/DesignItem；前端切换新接口
P4 旧轨下线
存量迁移与删除
存量 Quote/QuoteItem 按来源分拆为 Quotation 明细；旧 trade/quote、DesignItem 双来源、QuoteItem 五路关联下线；数据校验与对账后删除旧表
上线原则：P1–P3 期间新旧接口并存（新写旧读），P4 一次性切换；每一期结束都保证「报表口径一致、金额可对账」。

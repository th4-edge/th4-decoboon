02

邀请注册全流程与权限矩阵

6 个角色账号全部通过"老板生成邀请 → 被邀请人访问邀请链接 → 填写姓名/手机号/密码 → 确认加入团队 → 自动登录对应角色工作台"的系统流程完成注册，注册结果与数据库核验一致（db_tenant_invite 全部 Accepted，db_tenant_employee 归属正确）。

邀请注册流程（实测全通）

  1. 老板登录 → 首页入口「邀请成员」进入 /pages/team/invite；
  2. 选择角色（6 宫格：团队长/店长/设计/经理/顾问/财务），填写手机号 → 生成一次性邀请（32 位 hex 令牌，绑定手机号，有效期 7 天）；
  3. 被邀请人访问 /#/pages/auth/invite?token=… → 令牌自动带入（只读）→ 填写姓名、手机号、密码、确认密码；
  4. 确认加入团队 → 服务端校验令牌/手机号/密码一致性 → 创建员工与登录凭证 → 自动登录进入对应角色工作台；
  5. 数据库同步写入 db_tenant_invite(Accepted)、db_tenant_employee、db_tenant_credentials，短信日志落 th4_sms_log。

团队负责人邀请需绑定已有团队（自动成为队长）或新建团队；注册成功后自动具备对应角色的菜单与数据范围。

权限边界实测结论

  • 角色即数据范围：顾问 0 客户 / 店长 4 客户 / 团队长 2 成员 / 老板全企业——四级范围（企业·门店·团队·个人）在后端查询层生效，非前端隐藏。
  • 财务隔离到位：团队长、项目经理进入财务页呈现「只读视图」，金额掩码为 "–"（快速入口仍展示但不可操作）。
  • 角色专业化：顾问独有"黄金营销时段"分层，店长独有"设计调度"，项目经理以交付质量指标为核心——指标口径与角色职责强绑定。

  • 菜单级控制不一致：团队长仍可见"财务快捷入口"8 项图标（虽只读），未做角色级菜单裁剪，入口与能力割裂。
  • 新账号空态运营缺位：各新角色工作台全 0 指标 + 空态文案，但缺少"下一步建议动作"（如"去登记第一位客户"），新人引导弱。

实测缺陷清单（6 项，含 4 项存量 + 2 项本次新发现）

全部缺陷均来自真实操作复现，标注严重度与修复建议。

高

邀请成员页默认团队参数错误，非负责人角色邀请被阻断

/pages/team/invite · identityApi.createInvite

界面生成邀请时默认携带团队 ID（teamId 默认选中首个团队"全案一组"），后端校验"团队必须属于当前门店"失败，报错「团队不属于当前门店」。实测团队 store_id 与老板门店完全一致（1789096143706777093），后端接口直接调用（不带 teamId / 带正确 teamId）均成功——确认是前端默认值传参 bug，非后端逻辑问题。本次 5 个角色邀请被迫以接口方式绕过界面完成。

修复：非团队长角色提交时 teamId 置 undefined（仅 needsTeam 时传值），或修复团队默认值初始化时机。
高

金额符号双币符 bug（¥¥）

工作台/经营概览/业绩面板（顾问、设计师、团队长、店长）

多个角色首页金额显示为 "¥¥97,012"、"¥¥0"，而财务模块显示单 "¥"。货币符号渲染重复，影响专业形象与数据可读性。已在四个角色工作台复现。

修复：金额格式化组件统一去重（formatMoney 与静态字符串拼接重复注入 ¥）。
中

报价详情首次加载报"报价不存在"（刷新后恢复）

报价详情页 · 时序竞态（上轮设计师实测复现）

首次进入报价详情偶发报错，下拉刷新后数据正常——详情接口与报价列表状态初始化存在竞态，用户会误以为数据丢失。

修复：详情页 onLoad 参数传递与接口加载顺序解耦，增加 loading 兜底。

设计转化列表返回不刷新

设计转化页 · onShow 未重载（上轮实测复现）

从方案页返回设计转化列表，新生成的设计/报价不出现，需手动下拉刷新——onShow 生命周期未重新拉取数据。

新增分项弹窗项目库空白

中

注册表单密码键盘输入抖动

/pages/auth/invite 注册页 · 受控组件

密码/确认密码键盘逐键输入偶发字符错位/追加（实测首次提交报"两次密码输入不一致"，重试即成功）。与登录页手机号输入问题同源（uni-app 受控组件对程序化输入兼容差）。

修复：密码框支持粘贴/自动填充；弱化前端"两次一致"硬校验，改由服务端统一校验并给出明确错误字段。

评价口径说明

上述 6 项缺陷中，报价详情竞态、转化列表不刷新、新增分项项目库空白为上一轮设计师身份全模块实测复现；本次新增邀请页团队参数 bug 与注册密码输入抖动 2 项。整体判断：缺陷集中在 交互时序与表单兼容 层，业务模型与权限链路未见功能性错误。

06

客观评价：优点与不足

基于 8 账号 × 40+ 页面的实测体验，从业务逻辑、页面交互、操作便捷三个维度给出评价。

做得好的（7 项）

  • 角色-驾驶舱设计成立：8 角色 8 套首页指标与入口，角色代入感强，"登录即知自己今天该干什么"。
  • 业务闭环完整：客户（获客/跟进/量房）→ 设计（方案/转化）→ 报价（套餐+自定义同池）→ 项目（履约/验收）→ 财务（应收应付闭环）→ 组织（邀请/团队/调度）六域贯通，数据同源。
  • 报价体系已按重构落库：catalog_item（537 条六类）、quote/quote_line/quote_line_components、pack_template 等统一模型存在，套餐与自定义报价共用报价池，与重构设计一致。
  • 数据权限四级生效：企业/门店/团队/个人数据范围实测隔离正确，财务页只读掩码、跨角色不可越权。
  • 运营化细节到位：店长「需要关注」待办带处置建议、"黄金营销时段"自动分层、逾期客户标红提示——非纯工具而是带经营建议。
  • 空态与引导完整：客户空态提供"登记客户"CTA、项目空态提供"新建项目"入口，无裸空页面。
  • 邀请-注册-登录一键流：邀请令牌绑定手机号一次性使用，注册成功自动登录对应角色，零二次登录成本；短信日志可追溯。

不足与可优化（7 项）

  • 移动端表单兼容性差：受控输入框对键盘/程序化输入错位（登录、注册密码均复现），真机与模拟器表现不一致，是当前最大体验风险。
  • 只读权限语义缺失：无权限场景用 "-"/0 代替"无权限查看"，信息误导；菜单入口未按角色裁剪。
  • 跨页数据刷新不一致：部分列表 onShow 不重载（转化列表），依赖手动刷新，存在数据过期感知。
  • 新账号冷启动引导弱：全 0 工作台缺少"下一步动作"建议，新人无法快速理解第一件该做的事。
  • 流程状态可见性不足：报价"草稿/待确认/已接受/已转项目"等状态在店长/团队长侧缺少流转动作入口（如"催办""驳回"联动）。
  • 双 ¥ 等显示层问题未收敛：金额符号、金额 "-" 与 0 的混用缺乏统一格式化规范。
  • 角色覆盖不全：邀请页仅 6 角色，监理/采购/仓管有角色枚举但无邀请入口，工程施工闭环的角色支撑不完整。

总体判断：装得清已覆盖装企"获客-设计-报价-签约-履约-财务"经营主闭环的 7/8 主线，行业专业度在同类 SaaS 中处于中上；最薄弱的环节是供应链执行与变更结算——恰好是装企利润与客诉的高发区。

可拓展板块 A：供应链与成本域（P0）

  • 采购全链：采购单（按报价行/项目汇总）→ 审批 → 到货入库 → 领料出库 → 损耗/退换归集，回写 QuoteLine 成本组件。
  • 供应商门户：供应商档案、报价单、对账单、付款计划——Partner 域（重构设计已规划）。
  • 库存与预警：主材库存、安全库存、临期预警，与 catalog_item 联动。
  • 班组劳务：劳务班组档案、工价本、进度款按工序结算——与工人工资模块打通。

可拓展板块 B：变更与结算域（P0）

  • 变更单全流程：增项/减项/替换/数量/价格五类变更 → 审批 → 生成变更报价 → 客户确认 → 同步预算与应收。
  • 竣工结算：合同价 + 变更 + 扣款/奖励 → 结算单 → 质保金（3%-5% 留档）→ 质保到期释放。
  • 签证留证：变更现场照片/签认单电子化，与现场汇报打通，争议可回溯。

可拓展板块 C：经营决策域（P1）

  • 老板驾驶舱：签约额/回款/毛利/在建数四联看板 + 目标达成率 + 同比环比。
  • 项目利润核算：合同收入 - 材料成本 - 人工成本 - 费用分摊 = 单项目毛利（现仅有合同额无毛利）。
  • 人员绩效：设计师转化率、顾问签约率、PM 准时交付率/验收通过率自动考核报表。
  • 经营预警：逾期应收、停工风险、材料超领、变更率异常自动预警。

可拓展板块 D：客户与业主域（P1）

  • 业主端（邀请页已预留）：工地进度、验收节点、施工留证、消息通知的业主小程序/公众号。
  • 口碑转介绍：完工后评价、老带新线索、案例沉淀（图片/视频）→ 反哺获客。
  • 质保售后：质保期内报修工单、派单、处理记录、满意度回访。

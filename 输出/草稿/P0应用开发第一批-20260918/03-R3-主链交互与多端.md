# R3 主链交互与多端

## 1. 设计主张

使用者从工作台、客户、房屋、报价、合同和项目详情进入同一主链。首屏固定回答：

```text
当前处于什么阶段
谁负责，多久未推进
下一步是什么
为什么不能继续
完成后会写回什么对象、状态、金额和通知
```

## 3. App 信息架构冻结建议

- 首页只保留本角色今日必须做的 1 个主行动和分组待办。
- 客户详情按当前阶段只展示主行动，不把跟进、量房、设计、报价同时平铺。
- 房屋是量房、设计、报价和项目的固定上下文，不允许无房屋继续。
- 两端渠道枚举、状态文案、金额单位和错误提示必须来自同一契约。

## 4. 下一动作规则草案

| 当前事实 | 推荐动作 | 禁止动作 |
| --- | --- | --- |
| 客户 New/待首联 | 首次跟进 | 量房、设计、报价 |
| 客户 Following 且无房屋 | 建立房屋 | 量房 |
| 客户 Following/PendingMeasure 且有房屋 | 约定量房 | 跳过房屋 |
| 房屋已量房且无设计师 | 指定设计师 | 直接新建报价 |
| 设计师已接手且无量房结果 | 完成量房记录 | 生成报价 |
| 设计分项已齐 | 生成报价快照 | 直接签合同 |
| 报价 Submitted | 登记客户决策 | 合同/项目 |
| 报价 Accepted | 生成合同并登记签约价 | 直接项目 |
| 合同 PendingSign | 签约 | 项目 |
| 合同 Signed | 生效 | 再次签约 |
| 合同 Effective | 查看唯一项目 | 重复立项 |

服务端负责推导状态和权限。本规则若需要新增“下一动作”字段或接口，先由 product-planning 定契约，不能由各页面自行判断。

## 5. 实测交互问题

### UI-P0-001 新客户首屏动作错误

- 证据截图：`evidence/web-customer-new-1280.png`
- 现状：客户 `待首联`，无跟进记录，首个主按钮是“约定量房”。
- 要求：先显示“写一条跟进”；量房动作只有满足前置状态和房屋条件后才出现。

### UI-P0-002 合同页没有签约价调整语义

- 证据截图：`evidence/web-contract-effective-1280.png`
- 现状：只有合同基线和当前合同金额，没有原报价、调整额、原因与确认。
- 要求：签约前必须让业务人员能够解释“为什么合同金额和报价不同”。

### UI-P1-003 财务页仍展示伪利润

- 证据截图：`evidence/web-finance-overview-1280.png`
- 现状：材料应付 ¥1,600，成本为 0，利润 ¥48,400，毛利率 97%。
- 要求：成本不完整时显示 null/成本未完整，不出现可用于经营判断的利润值。

### UI-P2-004 角色工作台近期业务为空

- 现象：Boss、店长、团队负责人、财务工作台指标有数据，但“近期业务/项目”多处显示暂无可展示数据。
- 影响：工作台的第一屏无法告诉角色“现在先处理哪一条”。
- 要求：补统一待办/最近业务查询，空状态只能在真实无数据时出现。

# 第一批 P0 验收与用例清单

## 1. 环境与数据

- 租户：T-A 单店 12 人、T-B 三店 26 人、T-C 小团队 6 人。
- 角色：Boss、StoreManager、TeamLeader、Marketer、Designer、Pm、ProjectSupport、Finance。
- 数据必须全部为合成数据；跨租户对象互相不可见。
- App：微信开发者工具真机/模拟器 375、390、430。

## 2. 正向用例

### ACC-P0-001 建团

Boss 邀请 Marketer、Designer、Pm、Finance，员工接受后复制企业、门店、团队和角色；席位只占用一次。

### ACC-P0-002 客户到房屋

Marketer 登记客户，记录首次跟进，新增房屋，预约量房，Designer 录入量房结果；客户/房屋/量房状态同步且不自动建房。

### ACC-P0-003 报价自定义销售价

Designer 从项目库选择至少 3 个分项，其中 1 个修改销售价并填写原因；系统保存标准价和自定义价快照；报价金额由服务端重算；导出 Excel 包含价格来源和调整原因。

### ACC-P0-004 报价拒绝与版本

客户拒绝首版报价；Designer 修改后生成新版本；旧版本标记 Superseded，历史金额和价格来源不变。

### ACC-P0-005 报价接受到签约

客户接受最终报价后客户状态仍为待签约；Boss 生成合同，调整签约价并填写原因，合同保存原报价金额、调整额和最终金额；签约、生效后只生成一个项目。

### ACC-P0-006 直接签约补录

Boss 录入线下合同、成本和范围，系统生成“直接签约补录”基线报价，随后合同签约、生效、项目创建；补录报价不进入首版报价接受率。

### ACC-P0-007 主链下一动作

App 在客户/房屋/报价/合同/项目各状态显示相同下一步；未满足前置条件时不显示不可执行动作。

## 3. 反向与权限用例

- 未完成首次跟进：不能约定量房。
- 无房屋或伪造其他客户房屋：量房失败。
- 同一房屋已有其他 Accepted/Converted 报价：新报价确认失败。
- 未接受报价：不能创建合同。
- 未生效合同：不能创建项目。
- 同一合同重复生效、同一报价重复立项：不产生第二个项目/应收基线。
- 普通员工、店长、团队负责人对公司范围报价：不能通过合同/项目创建接口读取或创建。
- 伪造 `companyId/storeId/teamId/ownerId`：服务端忽略或拒绝。
- 变更负价导致合同金额 < 0：拒绝。
- 成本不完整：利润、毛利率为 null，不显示 0 或伪利润。
- App 发送未知客户来源：拒绝，不静默变成其他。

## 4. 金额对账

| 事实 | 报价 | 合同 | 项目 | 财务 |
| --- | ---: | ---: | ---: | ---: |
| 标准销售价合计 | A | A | A | A |
| 自定义价调整 | B | B | B | B |
| 签约价调整 | - | C | C | C |
| 当前合同金额 | - | 基线+C+已确认变更 | 同合同 | 同合同 |
| 成本完整 | 有快照 | 有快照 | 可追溯 | 若不完整利润 null |

所有对账页必须显示同一快照时间和来源。

## 5. UI 验收

- 375/390/430 App 页面无横向滚动、文字遮挡、底部 CTA 被安全区覆盖。

## 6. 验收门禁

以下任一未满足则 `BLOCK`：

- 同企业跨范围创建/读取仍可绕过。
- 房屋自动创建仍存在。
- 报价接受提前把客户标记为已签约。
- 签约价调整无原因/快照。
- 成本不完整仍输出利润。
- 跨租户正向/反向证据缺失。

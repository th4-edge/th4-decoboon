### DEV-P0-002 禁止由客户地址自动创建房屋

涉及：

- `customer/customer/measure`
- `customer/customer/handoff`
- `PropertyContext.ensureForCustomer` 的调用点。

要求：

- 约定量房必须传 `propertyId`，且该房屋属于当前客户和当前数据范围。
- 禁止在量房、指定设计师等业务动作中隐式建房。
- 客户地址只作为客户档案信息，不作为房屋存在证明。
- 无房屋时返回可操作错误：先建立房屋档案。

验收：

- `propertyId=null` 返回 400。
- 伪造其他客户房屋返回 404/400。
- 成功后不新增额外房屋记录。
- UI 无房屋时只显示“建立房屋档案”。

### DEV-P0-003 量房状态门禁

涉及：

- `customer/customer/measure`
- App 客户详情的同等动作规则。

要求：

- New/待首联不得直接约定量房。
- 首次有效跟进后进入 Following，之后才允许建立房屋和预约量房。
- 只允许 Following、PendingMeasure 进入量房；已完成、已签约、履约中、已完工、流失不可重复预约。
- 下一步动作优先按客户状态判断，不先以房屋存在判断量房。

验收：

- 新客户、无跟进：显示并只允许“写跟进”。
- Following 无房屋：只允许“建立房屋”。
- Following 有房屋：允许“约定量房”。
- New 调用量房接口失败。

### DEV-P0-004 客户状态不提前签约

涉及：

- `QuoteContext.accept`
- `ProjectContractContext.createFromQuote`
- `project/contract/update`
- `ProjectContext.createProjectForContract`

要求：

- 报价接受：Quote=Accepted，Customer 保持 Quoted/已报价。
- 合同首次登记为已签（`signedAt != null` 或签约动作）：Customer=Signed。
- 合同生效：Customer=Serving；项目创建继续要求 Effective 合同。
- 不允许合同未签约就显示已签约。

验收：

- `Submitted -> Accepted` 后客户状态仍为 Quoted。
- `PendingSign -> Signed` 后客户状态 Signed。
- `Signed -> Effective` 后客户状态 Serving。
- 任一失败事务不留下部分状态。

### DEV-P0-006 成本不完整不得生成伪利润

涉及：

- `ProjectCostContext.summarize`
- `FinanceReportContext.project/summary` 的现有完整性逻辑

要求：

- 合同时有历史报价但没有报价分项，且项目成本为 0 时，必须视为成本不完整，不能把 0 当完整成本。
- 无可核算分项时 `incompleteItemCount >= 1`。
- `costComplete=false` 时利润、毛利率为 null。
- 前端统一显示“成本未完整”，不能显示 0 或接近合同额的伪利润。

验收：

- `YS-PRJ-001` 场景不再显示 ¥48,400/97%。
- 有完整报价分项成本时正常计算。
- 部分采购应付存在但项目成本完整时不重复累计成本。

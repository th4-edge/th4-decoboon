## 1. 修分享落地页强制登录缺陷（亲友只读通道）

### 1.1 缺陷确认

| 位置 | 现状 |
| --- | --- |
| `app/src/composables/share.ts` | 注释明确要求分享 path「必须是对方未登录也能打开的小程序路径」 |
| `app/src/subpackages/project/pages/journey.vue` | `onLoad` 首句 `if (!isLoggedIn()) { redirectToLogin(); return }` |
| 结论 | 分享出去的链接，家人/好友点开**直接跳登录**，功能实际不可用 |

### 1.2 设计

**分为两个对象**（避免同一对象下 `info` 语义冲突）：

| 对象 | 用途 | 鉴权 |
| --- | --- | --- |
| `ProjectShareLink` | 业主管理自己生成的分享链接 | **需登录**（继承 `Security`） |
| `ShareView`（投影） | 游客凭 token 查看脱敏内容 | **免登录** |

> 免登录先例：`site/lead/submit`（`public interface Submit extends Provider<SiteLead, SiteLead> {`，**不继承 `Security`**）。

### 1.3 数据模型

`ProjectShareLink`（表 `db_customer_project_share_link`）

| 字段 | 说明 |
| --- | --- |
| shareId（`@Id`+`@SnowflakeId`） | 主键 |
| company / project / customer | 归属链（`@ManyToOne(fetch = LAZY)`） |
| token | 随机串（UUID 去横线），唯一索引 |
| scope | Enum：`Family` / `Friend` |
| showAmount | Boolean，默认 `false` |
| status | Enum：`Active` / `Revoked` / `Expired` |
| expireAt / createdBy / createTime | 时效与留痕 |

**scope 差异（脱敏白名单）**

| 内容 | Family（家人） | Friend（好友/邻居） |
| --- | --- | --- |
| 进度 / 阶段 / 照片 / 未来安排 | ✔ | ✔ |
| 金额（应付/已付/待付） | 按 `showAmount` | ✗ |
| 房屋地址 | 完整 | **仅小区 + 楼栋**（不含房号） |
| 企业名片入口 | ✔ | ✔（转介绍主入口） |
| 客户姓名 / 电话 | ✗ | ✗ |

### 1.5 接口契约

| 路由 | 能力 | 鉴权 | 入参 | 出参 |
| --- | --- | --- | --- | --- |
| `customer/sharelink/save` | save | 需登录（业主本人） | `projectId`、`scope`、`showAmount`、`expireDays` | `ProjectShareLink` |
| `customer/sharelink/page` | page | 需登录（业主本人） | `projectId` | `Page<ProjectShareLink>` |
| `customer/sharelink/update` | update | 需登录（业主本人） | `shareId`、`status=Revoked` | `ProjectShareLink` |
| **`customer/shareview/info`** | info | **免登录** | `token` | **`ShareJourneyView`**（投影） |

**`ShareJourneyView`** 沿用 `CustomerJourney` 先例（`customer/model/CustomerJourney.java` 为**非表投影类**，仅 `@Note`）：

```java
@Note("亲友只读视图")
public class ShareJourneyView {
    @Note("项目名称")      private String projectName;
    @Note("小区与楼栋")    private String community;      // 脱敏：不含房号
    @Note("整体进度")      private Integer progress;
    @Note("当前阶段")      private String currentStageName;
    @Note("现场照片"),      private List<Media> photos;    // 不含金额、姓名、电话
    @Note("下一段安排")    private List<Plan> upcoming;
    @Note("服务方")        private Vendor vendor;          // 装企名 + Logo + 品牌色
    @Note("数据时间")      private LocalDateTime asOf;
}
```

**业务规则**

1. `token` 无效 / 已撤销 / 已过期 → 返回 404 与「这次观看已结束」文案，不泄漏项目是否存在。
2. `scope = Friend` 时**强制**不返回金额与房号（与 `showAmount` 无关）。
3. 撤销后立即失效（不缓存）。
4. 生成上限：每项目并发有效链接 ≤ 5，超出提示先撤销旧的。
5. 默认有效期 30 天（对齐 `CustomerInvite.expireTime` 惯例）。

## 16. L3 门禁：全量测试（2026-10-15）

### 16.1 全量测试第一次跑：**157 个 Spring 上下文错误**

定向测试全绿的情况下，全量测试暴露出应用**启动直接失败**：

```text
IllegalStateException: 发现未显式声明 Security 的业务路由：
customer/shareview/info -> ...customer.service.shareview.info.support.Info
    at com.th4.edge.decoboon.common.configure.ProviderSecurityValidator.run
```

**这是框架治理按设计生效**：`ProviderSecurityValidator` 在启动时校验
——业务 Provider 必须显式继承 `Security`，**免登录路由只能来自显式白名单 `PUBLIC_ROUTES`**。

### 18.2 🔴 事故：迁移 116 漏建审计列，导致生产启动崩溃循环

**现象**：部署后 nginx 502，服务反复重启（restart counter 递增），每次启动约 22 秒后 `status=1` 退出。

**根因**（日志原文）：

```text
Schema-validation: missing column [update_date] in table [cust_project_share_link]
```

`ProjectShareLink` 继承 `AuditModel`，**必须同时具备 `create_*` 与 `update_*` 两组审计列**；
我在 116 里只写了 `create_*`，漏了 10 个 `update_*`。生产是 `ddl-auto: validate`，于是**启动即失败**。

**止损**：对照既有 `cust_customer_invite` 表，用 `ALTER TABLE` 补齐 10 个 `update_*` 列 → 重启 → 服务恢复。

**复盘：为什么测试没拦住？**
- 本地/测试环境用 H2 + `ddl-auto: create-drop`，**由 Hibernate 从实体建表**，所以"实体缺什么列"根本不会暴露；
- 全量测试 780 项全绿，但它们跑在 H2 上，**没有一处校验"手写 DDL 与实体是否一致"**；
- 真正的一致性检查是**生产启动时的 `validate`**——而那是最后一道，代价最高。

**这类缺陷的通用特征**：*手写 DDL 与 ORM 实体之间的偏差，只在 `validate` 环境暴露*。

**已修**：迁移文件 116 同步补齐 10 列，避免新环境重演。

# 业主端五类详情页 · 高保真设计评审

- 日期：2026-10-21
- 范围：报价、合同、选材、材料计划、增减项
- 证据：`shots-polish/`、`shots-real-polish/`（含全部主界面与详情页长图）
- 结论：高保真结构与交互可进入产品确认；不代表微信小程序已开发或业务验收通过

## 1. 设计意图冻结

| 详情页 | 页面类型 | 谁在什么状态下打开 | 第一个答案 | 唯一主行动 | 信息优先级 |
| --- | --- | --- | --- | --- | --- |
| 报价 | 业务单据详情 | 业主想核对版本和金额 | 当前是哪一版、总价多少、为什么变 | 查看完整报价单 | 当前版本 → 空间/逐项构成 → 差异 → 线下登记 → 附件 |
| 合同 | 业务单据详情 | 业主想确认合同和付款 | 合同是否生效、当前金额与义务是什么 | 查看合同正文 | 当前金额 → 主体/范围/工期 → 付款节点 → 线下签署 → 附件 |
| 选材 | 选择结果详情 | 业主想回看选了什么 | 品牌、花色、规格和空间是否正确 | 查看选材清单 | 当前版本 → 四类主材 → 线下确认 → 选材/到场边界 |
| 材料计划 | 履约记录详情 | 业主想知道材料什么时候来 | 哪些已下单、哪些到场、有没有记录 | 查看到场记录 | 状态计数 → 材料明细 → 到场时间线/影像 → 规则 |
| 增减项 | 变更结果详情 | 业主想知道钱为什么变 | 哪些审批中、哪些已生效、影响多少 | 查看变更单据 | 变更规则 → 审批中 → 已生效 → 合同联动 → 留痕 |

五页均面向业主，不承担装企审批、建单或内部备注功能。主行动只有一个，疑问反馈全部降为次行动。

## 3. 两轮渲染—批判—修正

### 第一轮

渲染证据：改版前五页截图 + DOM 检查。

发现：

1. 详情页顶部导航位于微信状态栏/胶囊层下方，返回到标题会与全局导航重叠。
2. 正文大量辅助信息只有 7.5–8.5px，手机阅读压力大。
3. 合同页存在一个多余的闭合 `div`，导致后续三个详情页脱离 `.viewport` 滚动容器。
4. 增减项曾使用“客户线下签认”表述，与已冻结口径冲突。正确口径是企业审批生效、业主端只读同频。
5. “完整页面”仍以摘要为主，报价逐项、合同付款节点、选材规格、材料时间线不足。
6. 真实数据态的确认页使用了丰富内容态的虚构记录，与“当前无记录”冲突。

### 第二轮

修正：

1. 详情导航下移到微信胶囊下方，`sticky` 滚动时保持可见。
2. 详情页正文、金额、状态、来源、时间统一提升到可读字号。
3. 修复合同页 DOM 结构，五个详情页全部回到 `.viewport`。
4. 增减项改为发起、审批、生效、同频四段事实，不提供确认按钮。
5. 补齐五类详情页的业务内容、附件预览、来源说明和跨页联动。
6. 真实数据态的确认页改为诚实空态。
7. 支持 `#quote` 等深链、返回来源页和 `detail-mode` 导航。

再渲染结果：

- 丰富内容态五页：无 JavaScript error、无页面横向溢出、详情导航与胶囊不重叠。
- 真实数据态五页：同一导航和布局成立；无内容字段保持明确空态。
- 返回路径：从家档案进入详情后可回到家档案。
- 文档预览：报价单预览层成功打开，读取到 5 条文档摘要行。
- 增减项：页面没有把变更呈现为“线下签认/客户已确认”的记录或按钮；相关文案只用于说明系统不建模该动作。
- 真实确认页：为空态，不再出现“业主已在小程序确认”的假记录。

## 4. 第三轮 · 全局排版与主题收敛

用户反馈：多个页面设计细节粗糙、宽度不一致、效果不整齐、排版错乱，并质疑深色主题是否合适。

审查发现：

1. 主页面大量辅助文字仍为 8–10px，视觉上像缩小版桌面稿。
2. `.section` 已有 16px 外边距，内部报价卡、阶段卡、变更卡和档案网格又重复内缩 16px，形成“双重边距”。
3. 部分区块标题对齐父级，内容卡却再窄 32px，产生明显错位。
4. 首页、进度概览、详情 Hero 和装修历程同时使用深绿色，暗色承载了过多层级，导致“哪里才是情绪高潮”不清晰。
5. 部分弱文字色在纸色背景上的对比度不足 4.5:1。

本轮修正：

- 建立统一内容轨：标准卡片、章节标题和主要区块均对齐 `16 / 374 / 358`。
- 清除章节内部重复 gutter，让标题与子卡片同宽。
- 正文提升至 12.5–13px，元信息不低于 11px，并拉开行高。
- 统一主要卡片圆角为 20px，按钮最小高度 44px，关键点击区域更完整。
- 将弱文字与铜色强调色调整为符合 AA 对比度的色阶。
- 详情页改为温暖的纸质单据风格；深色只保留给“装修历程”的沉浸叙事，并改成暖深绿而非近黑科技色。
- `装修历程` 的节点改为暖深绿卡片，提升正文、日期、引语和导航可读性。
- 增加详情页入口：首页选材任务和个人钱增减项都可以进入对应详情页。

再渲染结果：

- 主界面与五类详情页所有标准内容卡均为 `358px` 内容宽度，无双重 gutter。
- 390×844 画布无横向溢出。
- 详情页顶部导航与微信胶囊不重叠。
- 全部页面无 JavaScript error。
- 可见正文与元信息不再使用 7.5–10px 的小字；仅图标字形保留较小尺寸。
- 当前深色面积仅集中在首页照片 Hero、进度概览卡和装修历程，详情页恢复浅色阅读。

## 6. 未解决项

1. 真实接口未返回报价逐项、合同正文、线下登记人、选材和材料计划明细，需后端投影补齐。
2. 微信开发者工具中的真实小程序页面尚未按本高保真实现。
3. 加载、失败、无权限、会话过期需在 App 组件层统一接入。
4. 附件预览当前为高保真演示文档，未接真实文件服务。
5. 实时麦鸿数据需要有效只读测试账号或 token；当前真实态使用已保存的验收快照。

## 一、命题

现在的业主端 = **管理系统的业主投影**：按业务对象组织（量房/设计/报价/合同/增减项/材料/施工/验收/付款），
回答的是「**已经发生了什么**」。

要转成业主视角，就要按业主此刻的心理组织，回答四个问题：

| 业主的问 | 现状 | 本原型的回答 |
| --- | --- | --- |
| 接下来会发生什么 | 空 | 未来 7 天逐日安排 + 谁上门 + **要不要我到场** |
| 这正常吗 | 只有裸进度数字 | 与计划持平/快慢几天 + 风险透明（材料晚 1 天说明不影响完工） |
| 我能做什么 | 只有确认验收 + 提意见（后端 `collectActions` 仅 3 个 action） | 待办可执行、验收逐项、整改复验、主动发起诉求 |
| 装完之后呢 | 项目结束即归零 | 隐蔽工程 / 主材清单 / 质保 / 凭证 → **家的档案** |

## 二、逐项交互改造（原型里可直接点出来）

## 四、不越界的边界（本次刻意守住）

1. **不出现**成本、利润、供应商价、内部预警、内部沟通。
2. 金额一律换算成业主口径：应付 / 已付 / 待付。
3. 增减项**审批通过后才生效**，文案写明"请您确认后再执行"（对齐 `DEC-068`）。
4. 业主确认权归业主本人，原型里也没有"员工代确认"路径。
5. **质保期从竣工验收日起算**，项目未竣工时显示"待生效"，没有编造已生效日期。
6. 演示数据在页面外显式标注，不冒充真实项目。

## 五、需要业务裁决的空白（编码前必须冻结）

1. **未来计划对业主的可见口径**：只给已确定计划 / 给计划+标注可能调整 / 只给今天明天。（原型按"计划 + 可能调整说明"呈现，待裁决）
2. **验收点清单的来源**：这 6 项由谁维护——企业自定义模板、行业基础模板、还是项目现场生成？（`BR-018` 企业自定义模板体系可参考）
3. **业主发起诉求的对象复用**：复用既有 `Requirement`（提交诉求 → 设计师确认）还是新增通道；适用范围与是否必然形成增减项。
4. **整改复验入口的落点**：复用 `BR-008` 同一验收单追加轮次，还是独立复验动作。
5. **家档案的保留期与权属**：项目结束、企业停止订阅、业主换装企之后，档案归谁、保留多久。
6. **隐蔽工程归档的强制点**：是否作为阶段验收的必要条件（不归档不能进下一阶段）。

## 七、v1.1 增补：装修历程（第三个时间视角）

前两轮做的是「**现在**」（我在哪）和「**接下来**」（会发生什么）。业主还缺第三个视角：**「我走过来经历了什么」**。

### 7.1 关键判断：这不是新数据，是新的"读法"

历程的每一个节点都已经在库里——`CustomerJourneyContext` 的 10 个 section（量房/设计/报价/合同/增减项/材料/施工/验收/付款/意见）
本身就是一条从量房到交付的事实链。缺的不是对象，是**把事实链翻译成时间轴叙事**。

所以装修历程**不新增业务对象**，是既有事实的第三种投影。

### 7.2 起点为什么是"首次量房"，不是"接触"

业务边界（已用代码确认）：

- 业主 journey 对 `CustomerFollow`（跟进员工 / 跟进方式 / 跟进内容 / 下次跟进时间）的引用数为 **0**——
  咨询、跟进、销售备注属于**企业内部事实**，本来就不对客户开放。
- 所以历程起点应锚在业主真实参与的第一个装修事实：**首次量房**。
- 未签约客户看到的是"我的咨询进度"，不是"装修历程"。
- 原型页脚如实写明：历程从第一次量房开始，更早的咨询沟通属于企业内部信息。

### 7.3 过去的三种价值，权限完全不同

| 层次 | 内容 | 谁会看 | 风险 |
| --- | --- | --- | --- |
| **凭证价值**（理性） | 我确认过什么、改过什么、花了多少 | 业主自己 | 极低——自己的数据 |
| **纪念价值**（情感） | 从空房到家的过程、曾经画面 | 业主自己 + 家人（家庭共用视图） | 低——素材可能含他人肖像 |
| **表达价值**（社交） | 入住感受、新家照片 | 对外 | **高——必须走 `OBJ-006` / `BR-042` 三层授权** |

### 7.4 落进原型的两条硬边界

1. **授权默认关闭**：装修纪念册 / 入驻感受卡明确写「默认只有你自己和家人能看见，我们不会拿它对外用；
   以后要是想放到案例里，会单独再问你一次」——对齐 `BR-042`「装得清宣传默认关闭，逐条授权」。
2. **未竣工不假装可用**：纪念册与入驻感受显示为"未解锁"，并写明竣工日（12-19）解锁，没有编造已生效状态。

### 7.5 位置：**不占用 Tab**

底部 Tab 保持原样不变，仍是四个：**我的家 / 进度 / 我的钱 / 家档案**。

装修历程页（`p-story`）作为**独立页面**存在，暂不挂 Tab，可通过 `index.html#p-story` 直达查看；
等确定它该放在哪里（独立 Tab / 我的家里的入口 / 家档案的子页 / 交付时单独触达）再接线，不先动导航结构。

页面结构：顶部小结（16 天 / 3-8 阶段 / 与计划持平）→ **走过的路**（正序时间轴，含照片与你确认过的印记）
→ **接下来**（计划节点，弱化处理）→ **曾经的画面**（按月照片墙）→ **装修纪念与回忆**（纪念册 / 入驻感受 / 随时记一笔）。

### 7.6 新增待裁决

7. **「你确认过 / 你提过问题」这类业主参与印记**是否作为历程的必显项（它同时是信任证据，也是责任留痕）。
8. **纪念册的生成时点与范围**：竣工自动生成 / 业主手动触发；是否包含报价与合同金额（涉及家庭内部隐私）。
9. **入驻感受的归属**：内容归业主还是装企；业主删除后装企侧是否同步失效。

## 八、v1.2：双能力结构 —— 业务能力 + 价值能力

### 8.1 结构

业主端提供**两种能力**，互不侵入：

```text
┌─────────────────────────────────────────────┐
│  业务能力（管"事"）                          │
│  我的家 · 进度 · [历程] · 我的钱 · 家档案      │
│  = 浅色信息层：事实、状态、待办、金额          │
├─────────────────────────────────────────────┤
│  价值能力（管"感"）                          │
│  底部 Tab **最中间凸起按钮** → 装修历程        │
│  = 暗色记忆层：历程 / 画面 / 记忆 / 感受       │
└─────────────────────────────────────────────┘
```

- **业务能力 4 个 Tab 的内容一字未改**，只在 Tab 栏中间新增一个凸起入口。
- Tab 顺序：`我的家 | 进度 | 【历程·凸起】 | 我的钱 | 家档案`。
- 价值能力是**另一个世界**：暗色、沉浸、动态、有音乐，进入后连状态栏和 Tab 栏都跟着变暗。

### 8.2 价值能力做了什么

| 手法 | 实现 |
| --- | --- |
| 沉浸开场 | 深色渐变 + 两团缓慢漂移的光晕（19s / 23s）+ 14 颗上浮光尘 |
| 数字滚动 | 「16 天 / 26 张 / 3 阶段」进入视口时从 0 滚到目标值（1100ms 缓出） |
| 滚动揭示 | IntersectionObserver 逐条淡入上移，带 90ms 错峰 |
| 照片呼吸 | 揭示时照片从 `scale(1.14)` 缓慢回到 1（1.5s 缓出） |
| 当下脉冲 | 时间轴"今天"节点带扩散光环，2.4s 循环 |
| 环境音乐 | **Web Audio 现场合成**，无任何音频文件（见下） |
| 音乐开关 | 右上角圆形按钮，开启后有呼吸光环 |

### 8.3 音乐怎么做的（重要）

**没有引入任何外部音频文件**——用 Web Audio API 现场合成一段环境音乐：

- 4 个和弦循环（Gmaj7 类色彩：`[-5,0,4,7] / [-3,2,5,9] / [0,4,7,11] / [-1,4,7,12]`），
  每个 9 秒、11 秒淡入淡出，相互交叠；
- 每个和弦 4 个振荡器（基音 sine + 三个 triangle），峰值音量按声部衰减；
- 低通滤波（1500Hz）+ 0.45s 反馈延迟，制造空间感；
- 随机间隔（约 62% 概率）落一枚高八度五声音阶"铃音"；
- 总输出电平约 0.18，**很轻**，不抢注意力。

为什么这样做：
1. 不需要联网、不依赖版权音频，原型可离线打开；
2. 小程序端对应能力就是 `wx.createInnerAudioContext()` 播放一条 BGM，这里先验证"有没有音乐"的体验差别。

行为约定：
- 进入历程页**自动开启**（Tab 点击本身是用户手势，浏览器允许出声）；
- 离开历程页自动淡出；
- 用户手动关掉后，本轮不再自动开启。

### 8.4 截图模式（`!shot`）

无头浏览器会把 CSS 动画/过渡冻结在起始帧（`.page` 停在 `opacity:.4`，`.rv` 停在 `opacity:0`），
导致截图发灰、内容缺失。因此新增标记：

- `index.html#p-home!shot` —— 冻结动效并揭示全部元素后截图
- `index.html#p-story!tall` —— 把手机拉成 4300px 长图
- 两者可叠加：`#p-story!tall!shot`

真实浏览器里不加标记，动效照常播放。

## 九、v1.3：对外门面 —— 装企名片（`p-visit`）

### 9.1 为什么必须有

`src/manifest.json` 里小程序名就是「装得清」，微信客户端顶部、关于页、分享卡片都会带出平台名。
**业主第一次进入就必然知道装得清**——所以不要再试图隐藏，而要重新定义装得清的角色。

在这之上还缺一块：**业主把内容推给好友时，好友看到的是业主的工地，看不到装企是谁、也无法联系。**
转介绍链路断在这里。抖音 L2 已定义的核心功能正是「品牌/案例 → 预约量房」，**微信端完全没有**。

### 9.2 页面结构

`#p-visit`，由历程页「分享给好友 / 看看装企名片」进入；**不占 Tab、不显示 Tab 栏**（`data-nobar="1"`）。
顶部保留装得清导航栏——**故意不隐藏**，如实呈现"容器归装得清"这一现实。

```text
① 分享卡片预览  微信 5:4 样式：「朋友家的装修实录」+ 装企 Logo + 装得清记录存证角标
② 品牌头        Logo + 企业名 + 定位 + 服务区域（用企业品牌色）
③ 这家的情况    已完工 / 在施工地 / 质保年限 + 「由企业自填并审核发布，平台不代填、不推算、不背书」
④ 做的活        案例列表 + 「已获业主书面授权 · 已脱敏」+ BR-014 六条件说明
⑤ 你朋友家这一段  进入脱敏的装修历程（业主授权公开）
⑥ 服务与保障    主营 / 施工标准 / 质保 / 联系方式
⑦ 页脚          「本页内容由 栖岸装饰 提供并审核发布 / 记录存证与保管 · 装得清」
```

### 9.3 页面上刻意做的三处门禁演示

1. 数字旁标注**"企业自填并审核发布，平台不代填、不推算、不背书"**（对齐 `BR-014`）。
2. 每条案例带**"已获业主书面授权 · 已脱敏"**标记，并列出六条件（禁止把业主项目自动变成案例）。
3. 展示"业主授权公开的部分"，并声明**不含金额、联系方式与家庭成员信息**。

### 9.4 名字说明

演示装企使用**虚构名称「栖岸装饰」**，避免对真实合作装企产生不实陈述。

## 十、v1.4：业务能力侧植入「人」与「企业」

### 10.1 原则

**业务能力侧植入的是「人」，不是「宣传」。** 对外门面（名片页）负责拉新，业务能力侧负责服务。

### 10.2 现状缺口（已核代码）

- 业主 journey 里只有零散姓名（`量房设计师`、`整改责任人`、报告落款人）
- **没有"我的服务团队"概念**
- `ProjectMember` 对象**存在**，但**未投影给业主**
- 业主可见的员工字段仅 `Employee.getName()` —— 无头像、无岗位、无联系方式

**业主在整个过程里看不到"在跟谁打交道"。**

### 10.3 落点

| 位置 | 内容 |
| --- | --- |
| 首页「管我这件事的人」 | 横滑人卡：头像 + 姓名 + 岗位 + 一句话职责 + 联系他（4 人） |
| 责任人详情（遮罩页 `s-person`） | 从业年限 / 服务户数 / 擅长 / 服务承诺 + **「他为您家做了什么」**（来自既有 journey 事实） |
| 家档案「我的服务团队」 | 全部服务过的人（含施工班组）6 人 + 谁做了哪一段 |
| 家档案「服务方」 | 企业 Logo/名称/简介/联系方式 + 与本户相关的业绩 |

### 10.4 页面里刻的三处纪律

1. 人卡下方写明：**"中途换人我们会在这里告诉你"**。
2. 责任人详情标注：**"以上信息由 栖岸装饰 自行填写并审核。平台不推算、不评分、不与其它公司比较。"**
3. 服务方业绩只放**与本户相关**的（本小区 12 户 / 同户型 7 户），**不放"累计 386 户"这类泛泛宣传**——
   业主在已成交阶段关心的是"你懂不懂我这个小区、这个户型"，不是"你有多大"。

### 10.5 待裁决

- 员工在业主端露出的信息范围（姓名 / 头像 / **个人电话** / 从业年限 / 服务户数）
- 项目经理/设计师**换人的主动通知与留痕机制**（现在完全没有）

| ④ | 我的**确认与签认** | 家档案 → `p-confirm` | 倒序 8 条 + **两类标记（"我确认" / "已签认"）** + 金额显示开关 + "记录不可修改，也不可删除"。**2026-10-14 修正**：只有阶段验收是业主在小程序里确认的，报价/合同/增减项是线下签认后由装企登记（对齐 `DEC-015`、`USER-DECISION-20261014-004`） |
| ⑤ | 360 全景隐蔽工程 | 家档案 → 隐蔽工程 → `s-pano` | **可拖动全景**（按住左右转一圈）+ 房间切换 + 拍摄人/时间/验收条件 |
| ⑥ | 一键投诉 | 家档案 → `s-complaint` | 提交后显示 **48h 倒计时 + 四步进度**；明确"你看得到的 / 你看不到的" |

### 11.1 每一项里都埋了业务门禁

- 漏项自查：**"不会自动加进你的报价"**
- 材料到场：**"不需要你确认，也不会因为没有确认而影响施工；核对是项目经理和材料员的职责"** + **"到场记录不等于质量验收"**
- 全景：**"记录的是当时的现场事实，不代替质量验收"**
- 投诉：**"你会看到处理进度、承诺时限、倒计时；你不会看到企业内部的处理与考核记录"**

这些不是装饰文案，是把 `ANS-BIZ-20261014-002` 的裁决**画在界面上**——业主和装企都看得见边界在哪。

### 11.2 不出现的东西（同样重要）

- 业主端**不出现**整洁度评级、工人评分、跨企业对比
- 投诉页**不出现**任何人被扣分或处罚
- 材料到场**不出现**"验收通过"字样
- 材料到场**不出现**任何确认按钮与倒计时（`USER-DECISION-20261014-003`）
- 确认记录页**不出现**"我亲手确认过报价/合同"这类表述（`DEC-015` 禁止把代登记伪装为客户自助确认）

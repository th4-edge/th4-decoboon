## 1. 结论

本轮裁决可支持开发立即修复以下 P0：量房角色分离、PM 量房可见性与开工、阶段开工幂等、业主独立确认、收款幂等、财务成本完整性统一、结算状态投影。

合同签约/生效的最终角色矩阵、线下业主代录策略和人工材料计划补录仍缺少正式业务决策，保持 `BLOCKED`，开发不得用“当前页面能点”反推权限。

## 3. 标准流程与状态变化

### 3.1 量房与设计师

```text
客户建档 -> 房屋建立 -> 约定量房
-> 如有设计师：由设计师完成量房并记录 measure.designer
-> 如无设计师：由业务员/现任有量房权限的人预约；
   完成前必须先由老板/店长/团队负责人指定设计师；
-> 量房 Completed -> 设计节点仍为“待指定/待设计”，不得自动完成设计
```

规则：

- `Measure.designer` 只表达量房责任人/设计师事实，不得把“当前操作人”无条件写成设计师。
- 若产品需要保留“实际量房执行人”，应新增明确的执行人语义，不与设计师混用。
- 量房完成后 PM 应通过项目参与关系获得只读量房事实，量房可见性不能阻碍开工。

### 3.2 项目开工

```text
合同 Effective -> 项目 Preparing -> PM/项目参与读取量房和施工计划
-> 补齐项目经理、工期、量房事实
-> 阶段 Todo -> Doing -> 任务施工 -> 阶段 Accepting
```

- 开工重复请求不得重复生成动态，重复推进应返回同一最终事实或明确的已处理结果。
- 量房可见性由项目参与关系补充；前端 readiness 不是权限事实源，不能单独阻断合法角色。

### 3.3 业主验收

```text
阶段任务完成 -> PM/BOSS 提交阶段验收和证据
-> 验收单 Pending -> 业主本人通过授权会话确认
-> 阶段 Done -> 项目按全部阶段结果进入 Finished
```

- Boss/Pm/Designer 可以提交验收和证据，但不能扮演业主完成最终确认。
- 业主未确认时阶段不得通过正常路径完成。
- 线下代录不属于已确认规则；在用户正式决策前应失败关闭。

### 3.4 合同与项目

- 报价必须已被客户接受。
- 合同必须绑定报价，只有 `Effective` 合同可创建项目。
- `Signed` 与 `Effective` 是两个独立状态，重复签约/生效不得创建多个合同或项目。
- 现行产品能力矩阵只有 Boss 拥有 `contract:write`；Designer 不得仅因页面能点击而获得签约/生效权。若店长/财务需要该能力，应由产品规划另行授权并补充验收。
- 合同签署、生效的角色边界定为 `BLOCKED`，等待用户或产品负责人确认；在确认前采用最小权限失败关闭。

## 4. 金额、指标和口径

- 报价金额和成本由服务端计算并快照，前端不能覆盖。
- 项目预计成本优先合同成本快照，其次报价快照，再其次明确可用的标准成本；缺失即为不完整。
- `costComplete=false` 时：`grossProfit=null`、`grossMargin=null`，所有视图显示“成本未完整”。
- `Finished` 表示施工和阶段验收完成，不等于应收/应付/结算已关闭。
- `Settlement.Confirmed` 表示财务确认当前结算快照，可保留已明确的未收/未付余额；`Closed` 才是最终财务关闭，要求应收和应付清。
- `Project.Settled` 只能由结算关闭路径产生。项目 Finished 与 Settled 不得混用。
- 收款、付款和采购必须具备幂等键；重复请求不得重复生成单据、台账、应收核销、应付核销或成本。

## 5. 例外和反向用例

- 无设计师：允许预约，不允许由业务员把 `Measure.designer` 写成自己；量房完成前要求指派设计师。
- 量房完成但项目未配置 PM：可保留量房事实，PM 可见性由项目参与关系补足。
- 阶段开工：请求失败不能已修改数据库；重复开工不能重复写动态。
- 业主未登录：只能准备验收，不能确认；员工确认必须失败。
- 同一收款幂等键重复提交：返回原收款，不新增收款和资金台账。
- 成本不完整：所有利润视图显示成本未完整，不显示 0 或历史伪利润。
- 未收清/未付清：可生成或确认结算快照，不可关闭结算。
- 人工材料计划补录：在正式规则前不得开放，防止绕过报价、任务和采购来源。

## 6. 文档、实现与验收差异

- 当前实现与 SCN-001 冲突：量房完成会把当前用户当设计师。
- 当前实现与 SCN-003 冲突：PM 可以通过非业主身份确认业主验收；阶段开工可能已提交但返回失败。
- 当前实现与 BR-002 冲突风险：Designer 页面可操作合同签约/生效，但角色能力矩阵未授予 `contract:write`。
- 当前实现与 GAP-003/SOL-002 冲突：财务汇总和项目利润对同一项目返回不同的成本完整性结论。
- 当前实现与 SCN-005 冲突风险：材料计划缺少明确的人工补录来源，收款没有幂等键。

## 7. 给各智能体的建议

- 产品规划：补充合同签署/生效角色决策、人工材料计划补录来源、业主线下代录策略；不要把当前页面动作当业务事实。
- 开发：先修 P0，按“角色 × 数据范围 × 状态 × 幂等”实现；权限拒绝必须返回明确错误码。
- 验收：覆盖跨企业、跨门店、跨团队、跨项目参与、重复提交、重复确认、成本不完整和未收未付。
- 市场/内容：本答复不代表能力已验收；不得宣称全链路、利润、业主验收或防重已上线。

## 8. 对外表达边界

- 可以说：主链对象和状态已经存在，正在按真实业务条件修复闭环。
- 不可说：全链路已验收、业主确认真实闭环、利润口径全端一致、资金已经防重。
- 必须附条件：所有结论限于本轮本地测试环境和对应证据。

## 1. 首次入驻完成口径

首页“开始使用装得清”是 Boss 首次可用性引导，不是完整业务经营进度。

- 必做分母固定为 3 项：报价项目库、标准成本价、第一个客户及房屋。
- 邀请成员和供应商品牌关系为可选步骤；完成后只显示可选步骤已完成，不改变必做分母。
- 企业、默认总店、Boss 在注册时自动形成，是引导运行前置条件，不作为可操作步骤占用分母。
- 第一份报价、签约和项目立项属于后续业务里程碑，不纳入首次入驻完成判定。
- 只有按状态表从真实领域对象推导的完成项才可显示“已完成”；接口成功、页面打开、本地布尔值都不能作为完成事实。

### 2.1 供应商步骤冻结结论

供应商步骤以“有效材料供应商 + 至少一个关联品牌”为完成谓词；只有供应商主数据、没有品牌关系时不算完成。

该步骤仍是可选步骤：

- 不阻止首次入驻完成。
- 不计入 `3 个必做项` 的分子或分母。
- 必做项全部完成后，即使供应商可选步骤未完成，首页仍可显示首次入驻完成。
- 文案必须明确“需要采购时再维护”，避免用户理解为必须先建供应商才能维护成本价或开始报价。

### 2.2 首个报价、签约里程碑

报价项目库、成本价和客户/房屋完成后，Boss 已具备开始第一份报价的条件。首份报价、客户接受、合同签约和项目立项继续由对象主线和业务状态驱动，不用于回写首次入驻进度。

## 3. 进度与下一步算法

```text
required_steps = [catalog, cost, customer]
completed_required = count(step.done === true for step in required_steps)
progress = completed_required / 3
next_required = required_steps 中第一个 done !== true 的步骤
optional_completed = partner / member 的独立展示状态
```

- 未知状态使用 `unknown`，不能折叠为 `false` 后展示确定未完成，也不能折叠为 `true`。
- 可选步骤完成不修改 `completed_required`、分母 `3` 或 `next_required`。
- 删除、停用或回退业务对象后，下次刷新必须重新计算并允许已完成回退为未完成。
- 页面重复进入、重复 `onShow`、下拉刷新必须幂等，不得叠加计数或重复推进下一步。

## 5. 产品或开发不得使用的方式

- 禁止 `done: false`、演示对象、静态布尔值或本地“我已阅读”代替领域事实。
- 禁止只在组件首次 `mounted` 读取一次会变化的完成状态。
- 禁止用接口成功响应当作业务对象已完成。
- 禁止把可选步骤计入必做分母或阻塞下一步。
- 禁止以列表首屏数量代替全量计数，除非能证明该谓词在首屏范围内必然成立。
- 禁止页面截图、`type-check` 或构建通过替代业务状态迁移验收。

## 6. 防复发流程

以下规则同时适用于首次入驻、实施清单、待办、资料完整度、节点进度、审批进度和质量检查清单：

1. 产品规划在编码前必须冻结 `key / label / required / source_provider / completion_predicate / count / refresh_triggers / next_action / 异常态`。
2. 开发实现必须直接消费领域对象；任何完成状态必须能够反向指向 Provider、对象、字段和谓词。
3. 验收必须至少覆盖初始态、动作成功返回、动作失败/接口异常、可选完成、必做未完成、删除回退和重复进入。
4. 跨页面动作成功后，返回首页必须刷新；不能依赖用户杀进程或冷启动才能看到状态变化。
5. 必做/可选必须同时体现在文案、分母、下一步和验收矩阵中。
6. 新增或修改状态契约时，先更新本文件，再改实现；不得先写页面壳或静态占位。

## 8. 报价项目库、供应商与签约成本核心规则

- 报价项目库先于供应商维护，标准成本直接维护在报价项目。
- 成本价可由 Boss、店长、材料/履约、财务维护；设计师、业务员默认不可见。
- 供应商品牌关系按品牌匹配材料下单，不要求逐项供应商采购价。
- 报价阶段成本仅作参考；合同签约时按当前报价项目成本和行数量计算并冻结。
- 成本不完整时利润和毛利率为空，前端显示“成本未完整”。
